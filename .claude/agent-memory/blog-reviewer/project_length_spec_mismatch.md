`.claude/agents/blog-writer.md`를 다시 열어 확인한 결과(2026-07-09 세션), 과거에 있던
"800~1200자" 문구는 이미 사용자 피드백으로 개정되어 현재는 **"목표 4000~5500자"**로
바뀌어 있다. 문서 내 "승인된 예시(v2)"도 "약 4,800자"로 자기 표기돼 있다. 예전 이 메모리에
남아있던 "800~1200 vs 실측 3,346자" 비교는 전부 구버전(v1) 기준이라 더 이상 유효하지 않다.

**Why:** 검수 때마다 매번 blog-writer.md를 직접 다시 읽지 않고 예전 메모리 수치만 믿으면
이미 폐기된 v1 기준(800~1200자)으로 분량을 오판할 위험이 있다. 실제로 이번 검수(방향 ③
GatherIron 커밋 6개 소재)에서도 작업 지시문에는 "800~1200자 기준"이라고 적혀 있었지만,
실제 blog-writer.md 파일을 열어보니 이미 4000~5500자로 개정된 상태였다 — 지시문 쪽이 stale.

**How to apply:**
1. 분량 검증 시 **반드시 그 시점의 `.claude/agents/blog-writer.md`를 직접 읽어서** 현재
   기준 숫자를 확인한다. 작업 지시문에 적힌 숫자(예: "800~1200자")를 그대로 믿지 않는다 —
   지시문이 실제 파일보다 낡았을 수 있다.
2. **글자수 측정 도구 함정**: Git Bash의 `wc -m`은 로케일에 따라 UTF-8 멀티바이트 문자를
   문자 단위가 아니라 바이트 단위로 셀 수 있다(한글 1자가 3배로 부풀려짐, 예: 실제 3,889자가
   `wc -m`으로는 8,494로 나옴). 반드시 `powershell.exe -Command "(Get-Content -Raw
   -Encoding UTF8 <path>).Length"` 처럼 유니코드 인식 도구로 재검증한다.
3. 승인 예시(v2, 2026-07-09) 실측치: PowerShell 기준 공백 포함 3,677자 / 공백 제외
   2,834자. 문서 자체 표기("약 4,800자")와도 어긋나므로, 숫자 자체보다는 **승인 예시와
   비슷한 밀도·구조(7단계 전부 포함)인지**를 우선 판단 기준으로 삼는다.
