## 규칙

**게임 화면에 뜨는 문자열(HUD 알림·대사·프롬프트·콘솔 로그)은 원문이 확인된 것만 따옴표로
인용한다.** 확인 경로가 없으면 따옴표 없이 간접 서술로 쓴다. 특히:

1. **실행명세서(`Docs/M*_실행명세서.md`)의 "코드 스케치" 블록·주석 안 문자열은 인용 금지.**
   명세서는 계획 문서라 거기 적힌 대사가 실제로 구현되지 않았거나 다른 문자열로 대체된
   경우가 있다. 2026-07-28 M10 회차 반려의 직접 원인 = 명세서 260행 주석의 플레이스홀더
   `"지금은 몸이…"`를 실제 대사로 인용(실제로는 `InjuredLines` 재사용).
2. **표시명(DisplayName)은 한 글자까지 정확히.** 명세서 본문은 `새침`·`온순`·`방랑벽`으로
   줄여 쓰지만 실제 에셋 DisplayName은 `새침이`·`순둥이`·`떠돌이`다. 같은 반려 건에서
   "새침"으로 쓴 것이 지적됐다.
3. **수치는 "그 회차 커밋 시점" 값**을 쓴다. 리포 HEAD를 열어 본 값이 그 글이 다루는
   밀스톤 시점 값과 다를 수 있다(예: M10의 성격별 FleeRadiusMult 0.6/0.8/1.2는 M12에서
   전부 1로 되돌려짐). 브리프에 "at <해시>" 표기가 있으면 그쪽이 정본.
4. 반대로 **의인화 인용구(`>`)는 자유**다 — 내가 지어내는 비유임이 명백하므로 화면 문자열
   규칙 밖. 단 화면 캡션처럼 보이게 쓰지 않는다.

**Why:** blog-writer는 Read/Write만 가져 `Assets/`를 grep할 수 없는데, 검수팀(blog-reviewer)은
grep으로 문자열 실재를 대조한다. 즉 "그럴듯한 대사"를 지어내면 100% 잡힌다. 2026-07-28
원격 auto-run 초안이 이 계열 결함만으로 검수 2차·마스터 1차 연속 반려되어 draft로 강등됐다.

**How to apply:** 기획팀 브리프에 "화면 문자열 원문 대조표"가 실려 오면 **그 표가 인용
허용 목록의 전부**다. 표에 없는 문자열이 꼭 필요하면 따옴표를 빼고 서술한다.
플레이스홀더가 든 원문(`{이름}이(가) 다쳤습니다`)은 중괄호째 인용하고 무엇이 들어가는지
문장으로 풀어 쓴다 — 임의로 이름을 채워 넣지 않는다. [[project-ai-goap-sourcing]]
