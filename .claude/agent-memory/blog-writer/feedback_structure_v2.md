## 현재 기준 요약 (2026-07-30 갱신)

- 구조 = 7단계 (아래 v2 개정 내용 그대로).
- **분량 = 4,000~45,000자, `wc -m` 기준** — 2026-07-30 사용자 지시로 상한이 15,000 → 45,000
  으로 재확대됐다(이력: 5,500 → 15,000(07-16) → 45,000(07-30). 이유 = 개발이 진행될수록
  한 회차 내용이 많아짐). 아래 "v2로 개정된 기준"의 4,000~5,500은 **옛 값이니 인용하지 말 것**.
  소재가 풍부하면(밀스톤 A~G 통짜 등) 수만 자도 정상. 🚨 단 **상한은 허용치이지 목표가
  아니다 — 상한 채우기용 늘리기는 반려**(사용자가 확대 지시하며 재차 강조).
- **인트로는 최근 3편과 자구가 겹치면 안 된다.** 2026-07-28 반려 사유 중 하나가
  "07-22·07-24·07-26 세 편의 첫 문단 1·2·4번 문장이 자구까지 동일"이었다. 지시서의
  "승인된 예시" 인트로 문단은 **복사 금지 구역**이고, 1인칭 도입이라는 브랜드 톤만
  유지한 채 진입 각도(장면 묘사 / 결과 선언 / 질문형 / 메타 예고 등)를 매번 바꾼다.
  GOAP 설명에 쓰는 예시 명령("집을 지어라"·"밭을 갈아라" 등)도 최근 3편과 중복 금지.
- 인용 정확성은 [[feedback-quote-accuracy]]가 별도로 관리한다.

## 인트로 중복 방지 대장 (쓸 때마다 갱신)

| 2026-08-04 (M13) | 실패한 믿음 + 자기 회상 인용 | 다친 사람을 돌봐라 |

지시서가 제시한 네 각도(장면/결과 숫자/실패한 가정/질문)는 08-02~08-06에서 이미 다 쓰였다 —
5번째 각도를 직접 만들어야 할 때가 있다(08-08 = 타임스탬프 진입). 다음 회차는 위 4행과
겹치지 않게 고르고, 이 표에 한 줄 추가할 것.

## 🚨 분량 계측 함정 — `wc -m`이 바이트를 셀 수 있다 (2026-07-28)

**이 환경의 Git Bash `wc -m`은 한국어 텍스트에서 글자수가 아니라 바이트 수를 돌려준다**
(한글 1자 = UTF-8 3바이트). 실제 글자수는 PowerShell `(Get-Content -Raw file).Length`로 센다.

- 2026-07-28 M10 초안: `wc -m` = 23,351 (바이트) / 실제 글자수 = **10,080** (밴드 한가운데).
- 이 숫자를 글자수로 오인해 "상한 8,000자 초과"로 판단, 13,000~14,000자 목표로 축약을 한
  차례 수행했다가 전량 복구했다. 그대로 갔으면 6,000자 아래로 떨어져 하한에 근접했을 것.
- **분량이 밴드를 크게 벗어났다는 통보를 받으면, 축약 전에 계측 방식(바이트냐 글자수냐)을
  먼저 되물을 것.** 3배 가까이 어긋난 숫자는 계측 오류를 먼저 의심한다.

**어림 감각**: 내 문단당 200자 어림은 정확했다(추정 12,000 vs 실측 10,080). 이 감각을 유지하고,
Bash가 없어 직접 계측은 못 하므로 최종 숫자는 오케스트레이터에게 받되 맹신하지 않는다.

**원본 보존**: 축약·재작성 지시를 받으면 덮어쓰기 전에 원본을 Read해 대화에 남겨 둘 것 —
이번 복구가 가능했던 유일한 이유다.

## "AI와 함께 푼 장면" 섹션을 쓰는 법

이 프로젝트는 실제로 Claude Code로 개발 중 (Docs/CLAUDE.md 존재, 커밋에
"Co-Authored-By: Claude" 표기 다수). 이 사실에 기반해 쓰되, **대화 내용을 지어내지 않는다.**
"이런 판단이 필요할 때 AI와 함께 확인해가며 진행했다" 정도의 사실 기반 서술로 그친다.
CLAUDE.md의 "작업 프로토콜" 절(명세에 없는 판단은 구현하지 말고 질문/이슈로 남긴다)이
이 섹션을 뒷받침하는 좋은 근거 — 실제 규칙 문서 인용은 안전하고 구체적이다.

## "의외의 디테일" 섹션을 쓰는 법

작업 자체보다 "작업이 끝난 뒤 실전에서 증명된 순간"이나 "재밌는 부수 효과"를 찾는다.
이번 회차에서는 project memory(project_planning_deadlock_diagnosis.md)의 "실전 검증"
기록 — M3 커밋 직후 실제 로그에 찍힌 `ByReason=[Plan=3,Res=0,Path=0,Pre=0]` — 이
정확히 이 역할을 했다. **주의**: 이 로그는 아직 미해결로 남아있는 GatherIron 이슈에서
나온 것인데, 미해결 이슈 자체를 끌어오지 않고 "관측 도구가 실전에서 즉시 값을 증명했다"는
완결된 장면으로만 잘라서 썼다 — 사실관계 원칙(미해결 이슈 언급 금지)과 배치되지 않게
스코프를 좁히는 요령.

**Why:** 사용자가 같은 소재로 v1 초안을 승인 없이 바로 재작성 지시함 — v1 승인은
그 시점 기준이었고, 이후 구조 자체가 개정될 수 있다는 뜻. 새 세션에서도 이 파일이
최신 기준인지 먼저 확인할 것 (추가 개정이 있었는지 사용자에게 물어봐도 됨).

**How to apply:** 앞으로 이 프로젝트의 블로그 글은 기본적으로 v2 구조(7단계)를 따른다.
[[project-ai-goap-sourcing]]에 정리한 방식으로 사실을 먼저 확인한 뒤 쓴다.
