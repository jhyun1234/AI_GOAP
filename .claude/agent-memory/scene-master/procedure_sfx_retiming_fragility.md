# 효과음 `delayMs` 는 `timed.json` 에 매달려 있다 — tts 를 다시 돌리면 전부 무효

**Why:** `delayMs` 는 자막 시작 기준 오프셋이라 안전해 **보인다**. 그런데 그 값을 정한 것은
그림의 `cue` 창(= 그 줄의 `dur`)이고, **`cue` 를 안 쓰고 샷 로컬 시각 `t` 로 도는 그림**은
앞줄들의 길이 합에 통째로 매달린다. ep02s S8 `tripwire.js` 가 그 사례 —
걸림은 `u = frac(t/5.2) ∈ [0.57,0.85)` 라 샷 안 2.964s 에 고정인데, `at1` 의 위치는
`S8 line0 의 dur`(2,640ms)이 정한다. 즉 `delayMs = 2964 − 2640 = 324`.
line0 이 1ms 늘면 소리가 1ms 어긋난다. 게다가 소리는 걸림 시작 **1ms 뒤**에 착지해
**이른 쪽 여유가 사실상 0** 이다(늦은 쪽은 1.3초).

**How to apply:**
- 효과음이 붙은 회차는 **대본을 안 고쳤으면 `tts.mjs` 를 절대 다시 돌리지 않는다.**
  돌렸다면 `delayMs` 6개를 전부 재역산하고 다시 판정한다.
- 반대로 **대본을 고쳤으면 `tts` 재실행이 필수**이고(→ [[verdict_ep02s_redo]] 의 timed.json 사고),
  그때는 효과음도 같이 다시 계산해야 한다. 두 규칙은 짝이다.
- 판정 때 각 소리의 **양쪽 여유**를 적어 둘 것. "맞다"만 쓰면 다음 사람이 이 취약함을 못 본다.
- 효과음만 얹는 재작업에도 **전체 재렌더가 유일한 길**이다 — `render.mjs` 에 소리만 다시
  만드는 경로가 없다(`buildTrack` 이 프레임 추출과 같은 실행 안). 그림이 안 바뀌었으므로
  **결과 길이가 이전과 달라지면 그 자체가 이상 신호**다.
