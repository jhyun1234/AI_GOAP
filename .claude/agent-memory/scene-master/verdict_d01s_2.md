# `d01s-2` = **APPROVED (조건 해소 · 최종 무조건)** (2026-08-11 · dNNs 파일럿 2편 중 2편 · 마스터 반려 0 · 누적 1)

> ✅ **결말**: 이행 조건(카드 비우기)은 **사용자 중간 리뷰가 엔진 개정을 승인**하면서 상위 결정으로 대체됐다.
> `engine.js` 에 `outro.nextKind` 가 들어갔고, 이 편은 `next` **복원 + `nextKind:"item"`** →
> 카드 실물 = **「다음 항목 · …」**. 판정서 말미 「추기」 참조.
> 🔑 **차선(이행 조건)을 요구할 때 최선(제안)을 같은 문서에 적어 둔 것이 값을 했다** — 사람 리뷰가
> 예정된 구간(파일럿·중간 리뷰)에서는 **둘을 함께 올리는 형태가 옳다.** 제안이 없었으면 이 편은
> 카드 한 줄을 영구히 잃은 채 나갔다.
> 🔴 **통보가 「기록용·회신 불요」여도 내 승인분의 렌더 산출이 바뀌었으면 다시 본다** — 게이트 2회 재실행 ·
> 스틸 재렌더 · 자막/`timed.json` 무변경 대조 · **파급은 `grep -rl "nextKind" episodes/*/scene.json` +
> `git diff --stat` 로 증명**(보유 회차 1편 = 나머지 44편 출력 바이트 동일. **스틸 세 장보다 강한 증명**).
> 파일럿 S1 채점 불변 — 게이트 3종(`check`·`render`·`sfx`)은 여전히 무변경이고, 엔진 개정은
> **파일럿 통과용 수정이 아니라 파일럿의 산출**이다.

판정서 = `tools/scene-video/episodes/d01s-2/notes/verdict.md`

**Why:** 커밋 직송(dNNs) 트랙의 첫 완주 판정이고, 여기서 정한 것이 이후 모든 dNNs 의 기본값이 된다.
**How to apply:** 다음 dNNs(`d02s`~) 판정 때 이 파일을 먼저 연다. 연속극·롱폼에는 §2·§4만 걸린다.

## 1. 🔴 화면 한 줄이 트랙 규약을 배신하는 유형 — 엔진 하드코딩

`engine/engine.js:321` = `` `다음 편 · ${ocNext}` `` (하드코딩). ADR-D-3 은 dNNs 가
**다음 회차를 예고하지 않는다**고 정했다(사유: *다음 소재를 모르는 트랙*).
음성은 「다음**은**」(항목형), `nextpeek` 라벨도 「다음 항목」인데 **카드만 「다음 편」**이었다.

**판정 = 이행 조건(렌더 전) `outro.next = ""`.** 근거 넷:
① 조문의 실질(뒷받침 못 하는 단정)을 어긴다 ② **이번엔 실제로 거짓이 될 공산이 크다**
(미발행 대기 14편 + 다음 후보가 `ep17s`) ③ **작성팀이 고칠 수 있는 필드**라 「기계 파생이라 못 고친다」
선례(형제 라벨 수치)가 적용 안 된다 ④ `SO.source` 자신이 「가리키는 것은 다음 편이 아니다」라고 적어 놓았다.

🔑 **대가는 복제본으로 미리 실측하고 요구했다** — `episodes/d01s2m` 에 `outro.next=""` 로 복제 →
`check.mjs` **전부 통과**(「다음 편 예고 있음」은 **음성 자막**으로 만족) → 스틸 1장 확인 → 복제본 삭제.
**「비우라」고 요구하기 전에 비운 판이 green 인지 내가 먼저 봤다.** 이행 요구는 이렇게 낸다.

🔧 **엔진 개정 제안**(실행은 코디네이터 → 사용자) — **형제 판정서를 대조하고 제안을 고쳤다**:
처음엔 `scene.track === 'dNNs'` 분기를 쓰려 했는데, [[verdict-d01s-1]] 을 열어 보니
`d01s-1` 의 `outro.next` 는 **형제 편**을 가리켜 「다음 편 ·」이 **참**이었다(그 편은 이 자리 지적 없이 APPROVED —
**누락이 아니라 그 편에선 문제가 아니었다**). **트랙으로 가르면 형제가 되레 틀어진다.**
→ 최종 제안 = **`outro.nextKind: 'episode'(기본) | 'item'`** 로 가른다. 기본값이라 기존 44편 무변경.
🔑 **가르는 축은 「어느 트랙인가」가 아니라 「그 필드가 무엇을 가리키는가」였다.**
🔗 형제의 `ADR-D-3` 개정 제안(①진짜 미래=예정형 / ②닫힌 사건=단정형 허용)과 **한 묶음으로** 올릴 것 —
합치면 **중간 편 = 단정형 + 「다음 편」 / 마지막 편 = 예정형 + 「다음 항목」** 으로 규약이 닫힌다.

## 2. 🔴 dNNs 고유 재검 항목 = 「창 밖 커밋이 이 편의 화면을 낡게 하는가」

원문이 **살아 있는 로그 파일**이라 **같은 파일의 뒤쪽 커밋이 앞쪽 사건의 수를 낡게 만든다.**
이 편은 15:03 커밋(시야 10→7 · 부화 15→10 · 회수 20→14)이 원장 커버(14:40:55) **밖**인데도 읽고,
**반경 수치를 화면·자막에서 전부 뺀 뒤 「관계」만 그렸다**(7<10 참 · 7<14−5 참 → 안 낡는다).
🔑 판정법: **원장 커버 밖이라 「내 원문이 아니다」로 끝내지 말고 「내 화면이 그것 때문에 낡는가」를 물어라.**
(`lf02` 교훈 *영상이 만드는 사이에 낡는다* 의 dNNs 첫 선제 적용.)
⚠️ 원문의 **사슬 표기**(`시야 < 부화 < 회수−배회`)는 새 값에서 **10 < 9 = 거짓**이 된다 —
로그 717행의 **부등식 둘** 표기로 인용해야 안 깨진다. 「사슬로 눌러 쓴 줄」은 값이 바뀌면 먼저 죽는다.

## 3. 🔴 브리프의 「이 회차는 …」 진술이 편 경계를 넘으면 오배치가 난다

검수 반려 ②(blurb 이 「해결 설계도 사람」)의 뿌리는 작성팀이 아니라 **브리프 §9 머리 문장**
(*"결함을 찾고 해결을 설계한 것은 전부 사용자"*)이었다. 표의 각 행은 전부 원문에 있는데,
**「해결 설계」 행은 W5R = 형제 편의 문장**이고 이 편 사건(14:38)에서 로그가 준 것은 **발견뿐**(697행).
🔑 `ep13s-2` 의 **슬롯 결합**(수는 실재, 주어가 다름)이 **문장 층에서** 난 것.
**분할 회차에서는 브리프의 회차 단위 진술을 편 단위로 쪼개서 대조하라.**
