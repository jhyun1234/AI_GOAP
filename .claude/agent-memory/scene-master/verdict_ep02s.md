# ep02s = APPROVED (2026-07-30)

## 판정
APPROVED. 무인 실행 파이프라인의 첫 완주. 마스터 반려 0회.

## 반려 이력
- 작성 1차: 총 길이 83.6초 초과 + S1 원문 없는 대사 3종 + cue 인덱스 초과 4곳
- 작성 2차: S3 wardline 6종 성격 이름 중 3개(성실·겁많음·쾌활) 원문 미명시
- 작성 3차: PASS
- 마스터: APPROVED

## 이번 편의 새 패턴

**렌더 계층 화이트리스트로 "원문에 있는 것만 화면에 나간다" 규칙을 지켰다.**
scene.json 은 그대로 두고 `kinds/wardline.js` 안에서 `KNOWN` set 으로 필터.
scene 데이터는 원문의 6종 존재(Random.Range(1,7))를 반영해 6개 유지, 화면 표시만
원문 근거 있는 3개로 제한하고 나머지는 `···` 익명 자리로.

**Why:** "6칸 존재는 원문 근거 있지만 이름 6개는 3개만 원문 근거" 라는 조각난
정직성을 데이터 계층에서 표현하기 어렵다. 렌더가 걸러 주는 편이 정직.

**How to apply:** 앞으로 원문이 "N종 존재" 만 말하고 이름은 일부만 주는 상황에서
쓸 수 있는 패턴. 단 화면에 나가는 문자열 전수를 원문에서 grep 하는 검증 절차와
함께 써야 실효.

## 편향 재발 = 3차 컷의 원인

작성팀 2차 컷의 자체 검토("수치 정직성" 절)가 숫자만 대조하고 문자열은 안 대조함.
1차 반려 사유 2(원문 없는 대사)와 같은 종류 위반이 다른 자리(성격 이름)에서 재발.

**교훈**: 자체 검토 규칙이 "숫자"에 고정되면 같은 종류의 위반이 문자열에서 재발한다.
검수팀 리뷰 절차에 이미 [[review_method_recycling_check]] 같은 그림 대조가 있는
것처럼, **화면에 나가는 문자열 전수 grep** 이 별도 절차로 필요. 다음 회차 검수팀
프롬프트에 반영 여지.

## 잔존 리스크 (다음 회차 정리 대상)

`ep02s/kinds/blank.js`, `ep02s/kinds/scoped.js` 두 파일이 scene.json 미참조 상태로
잔존. check.mjs 는 참조된 kind 만 검사하므로 판정에는 영향 없지만, **회차 폴더에
"안 쓴 그림"이 남는 관행이 굳으면 다음 회차에서 그걸 참고해 돌려막기 유혹**.
다음 회차 검수팀에 "회차 폴더의 미참조 kind 는 반려 사유" 규칙 추가 여부 검토.
