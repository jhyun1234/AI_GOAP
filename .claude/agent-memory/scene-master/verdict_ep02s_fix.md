# ep02s 부분 재작업 = APPROVED (2026-07-30)

렌더까지 간 뒤 `check.mjs` 14종 중 `좌우 가장자리 잘림 없음` 한 항목만 실패해
검수→작성으로 돌린 건. 산출은 `-fix` 접미사로 남기고 1차 기록은 안 덮음
(`review-fix.md` / `writer-fix.md` / `verdict-fix.md`). 마스터 반려 누계 변동 없음(0회).

## 이번에 쓴 판정 절차 — 부분 재작업 전용

**Why:** 새 회차 심사(4조건 전수)를 그대로 돌리면 과잉이고, 반대로 `check.mjs` 초록만
보면 그게 바로 이 항목이 추가된 원인(잘린 채 13종 통과)을 반복한다.

**How to apply:** 대본 무변경 국소 수정에는 이 4단계를 쓴다.

1. **범위를 두 경로로 독립 확인.** `git status` 의 `A ` vs `AM` 로 unstaged 변경 전수 +
   파일 mtime 을 1차 `verdict.md` mtime 과 비교. 둘 다 맞아야 "대본 안 건드림"을 인정.
2. **`fillText` 인자 전수 grep.** diff 만 보면 "추가된 리터럴 없음"까지밖에 못 본다.
   `substring|slice|substr` 도 같이 grep — **긴 문자열을 잘라 폭 문제를 회피하는 것**이
   이 자리의 대표 사고다. 인자가 전부 `spec`/`scene` 에서 오면 통과.
3. **`scene.json` 의 `checks` 키 존재 여부를 직접 본다.** 통과 출력에
   `(선언 예외: …)` 꼬리표가 없는지도 같이 확인 — 예외 선언으로 도망갔는지 판별.
4. **수정된 샷의 `reads` 를 스틸로 검증.** 수정 전후 동작이 바뀐 구간에 스틸을 3~5장
   찍어 시간순으로 늘어놓고 reads 문장을 한 구절씩 대조. 전체 렌더는 안 돌린다.

## 이번 판정의 쟁점과 결론 — "밀어내기 → 흐려지며 사라지기"

S10 `reads` = "두 표식이 옆으로 밀려나고 그 자리에 새 표식이 앉는다".
작성팀이 **화면 밖까지 밀어내기**를 **170px 이동 후 alpha 0** 으로 바꿈.

**결론: reads 훼손 아님.** 근거 = ①이동 92 CSS px = 캔버스 폭(352)의 26% · 표식 한 장
폭(96)에 맞먹어 "밀려남"이 눈에 보인다 ②`reads` 가 요구하는 **복수성**("두 사건의 표식")이
1차 컷에서는 두 장이 포개져 이미 깨져 있었고 이 수정이 **회복**시켰다 ③끝까지 밀어내면
잘림이 되돌아오므로 두 제약을 동시에 만족하는 유일한 해다.

**How to apply:** 화면 밖 퇴장을 소멸로 바꾸는 처방이 올라오면, "밀려남"의 성립 여부를
**이동 거리 ÷ 캔버스 폭**(체감 기준 ~25% 이상)과 **요소 자체 폭 대비**로 재고,
스틸 2장을 나란히 놓아 확인한다. **화면 이탈 여부 자체는 판정 기준이 아니다.**

## 이번에 확인한 좋은 판단 3가지 (다음 회차에서도 이렇게)

- **예외 선언을 안 골랐다.** `check.mjs:186-206` 좌우 검사는 *바로 이 회차 S4 사고*
  때문에 생겼다. 같은 회차에서 `checks.edge` 로 무력화하면 다음 회차가 선례로 인용한다.
- **조건부 레버를 미리 안 썼다.** 검수 처방의 "재실행에서 아슬아슬하면 `easeOut` 로"를
  조건 성립 전에 쓰면 근거 없는 연출 변경이 된다.
- **범위 밖(미사용 `mono` import 등)을 안 건드렸다.** 보고만 하고 다음 클린업으로.
