## 🔑 이 회차가 만든 판정법 3

**① 「N px 여유면 충분한가」는 계산으로 답하지 않는다 — 최악 위상을 특정해 그 프레임을 렌더하고 픽셀을 센다.**
검수가 `spread` 집↔곁불 최악 **1.95px**(125°)을 냈다(내 독립 재계산과 소수점까지 일치).
그런데 「1.95 가 충분한가」는 그 수로는 못 정한다 — 그 수는 **글로우 공칭 반경까지 다 인정한 하한**이다.
최악 위상을 식에서 풀어(`hp=1` → 불꽃 h 20·글로우 7, `lit=1` → `s0≥1.55`, 125°는 i=0 → `t=2.0196`
→ **절대 26.113s**) 스틸을 뽑고 세었더니 **혼합 픽셀 0 · 흰↔강조색 최소 9.91 CSS px**(5배).
**Why:** 좌표 감사는 「닿나」를 묻고 픽셀은 「보이나」를 묻는다. 둘은 5배 차이가 난다.
**How to apply:** 여유가 2px 아래로 내려온 자리는 **반드시** 최악 위상 프레임을 렌더해 확인.
재사용할 스캐너 = 픽셀을 흰(채도<0.12)·강조색(G최대 & R<0.35G)·혼합으로 가르고 BFS 로 최소거리.
승인 회차 통제군 = 본문 샷 **혼합 0 · 최소 3.3~20.7 CSS px**(공용 인트로 `S0` 만 예외로 0.36px).

**② `latch` 는 `seed` 로 안 갈린다. 개성은 `dur` 에 있다.** — 옛 메모 정정
`sfx.mjs:73-84` 의 몸통은 **340/680Hz 고정 + `dur` 이 정하는 포락선**이고, `seed` 가 만지는
`click` 은 `exp(−260t)` 라 **210ms 중 앞 15ms** 뿐이다.
전수 300쌍 분포 **0.637~0.841**(공지된 돌려막기 `ep02s↔ep03s` 0.9976 제외).
`ep14s-2·-3·-4` 가 **`dur` 을 0.21 로 똑같이** 쓰고 seed 만 갈랐더니 상호 **0.79~0.80**.
🔑 `ep13s-3` 의 **thud/`freq` 기본 150** 과 **같은 병**이다 — 원인이 회차가 아니라 kind 설계다.
**How to apply:** ⓐ 옛 규칙 「latch 에 고유 seed 필수」는 **필요조건일 뿐이다**(0.9976→0.83 까지만
내린다). `dur` 도 갈라라. ⓑ **kind 단위로도 세라** — `ep12s-1` 의 「세 편 연속 같은 **짝**」
규칙은 이 형태를 못 잡는다(최근 6편 중 **5편이 latch**인데 짝은 다 달랐다).
ⓒ 이번엔 **통과**시켰다(0.8309 = 300쌍 중 5위, 2~4위가 이미 승인된 14-2·14-3·lf02).

**③ 주석의 좌표는 「경로냐 획 바깥이냐」를 적어야 한다.** 「`lineWidth/2` 를 더해라」로는 안 낫는다.
검수가 「작성팀이 `lineWidth/2 = 1.5px` 를 일관되게 안 더한다」를 다섯 곳에서 잡았다(①③⑤ 재현 ✅).
🔴 **그 처방(「수만 고치고 kind 머리에 한 줄」)이 ④ 에서 안 통했다** — 수만 고치면
「0.12px 뜬다」가 되는데 **0.12px 은 「뜬다」가 아니라 「닿는다」**다.
🔑 진짜 병은 빼먹은 게 아니라 **기준이 안 적힌 것**이다 — `ep14s-3/scan.js` 는 포함해서 적었고
`ep14s-2/everyrow.js`·`ep14s-4/tether.js` 는 안 적었는데 **문법이 똑같아** 아무도 못 갈랐다.
**How to apply:** kind 머리에 「이 파일의 좌표는 **획 바깥** 기준. 경로 좌표는 `(경로)` 표시」.
