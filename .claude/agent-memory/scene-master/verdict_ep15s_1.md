# `ep15s-1` = 🟢 APPROVED (2026-08-10) · 누적 반려 1회(검수 1차) · 마스터 반려 0

M12 성격 축 · **5편 분할 = 채널 최다**. 판정서 = `tools/scene-video/episodes/ep15s-1/notes/verdict.md`.

**Why:** 이 편은 `ADR-V25-15②`(라벨 읽는 창)의 **기준점이 층마다 다르게 읽히고 있다**는 것을
드러냈다. 그 혼선 하나가 한 라운드를 통째로 잡아먹었고(존재하지 않는 「여유 0.02초」),
동시에 **측정 하나를 구조적으로 없앴다**(오타 한 글자).

**How to apply:** 아래는 다음 회차 판정에서 바로 쓴다.

## 🔴 1. 라벨·사건 시각의 **정본 기준점은 「줄」이다. 낱말은 강화판이다**

`.claude/agents/scene-reviewer.md` §5 의 **±20프레임 = 0.67초**는
*"그 사건을 부르는 **자막의 발화 구간** 안에 드는가"* 다. 그 수를 낳은 사고(`ep00i` `runmark`)도
**사건이 다른 자막 위에서 터진** 형태였다 — 줄을 건너뛴 것이지 낱말을 앞지른 것이 아니다.

🔑 **이유가 화면에 있다 — 자막은 두 줄을 한꺼번에 띄운다.** `ep15s-1` `19.4s` 스틸에서
아래 자막 「여섯이 다 값을 가진 건 / **하나였고요.**」가 **이미 다 떠 있는데** 그 위에
「겨울 비축 1개뿐」이 앉는다. **시청자는 그 낱말을 이미 읽고 있다** → 같은 줄 안에서는
라벨이 발화보다 먼저 떠도 **스포일러가 성립하지 않는다.**

⚠️ **그러므로 「낱말보다 N초 이르다」만으로 반려하지 마라.** 먼저 **줄을 벗어났는지**를 봐라.
`ep15s-1` 에서 낱말 기준으로 재면 ⑤가 1.25초 · ⑥이 0.81~1.02초 · ⑩이 1.19초 「초과」인데
**셋 다 자기 줄 안**이라 통과였다.

## 🔴 2. 「기준점 삼분」 = 조건부 수용 (`ep15s-1` 신설 규약)

작성팀 제안: **진입 라벨 → 자막 시작 / 리빌 → 낱말 발화 / 페이오프 라벨 → 그림**.
받아들였다. 근거 — ⓐ정본이 이미 줄 기준이라 삼분은 **자율 강화**다 ⓑ페이오프 라벨을 낱말에
묶으면 **「자막 길이의 23% 안에서 완성」**(`ep08s-3` 반려 회피)과 정면 충돌한다
ⓒ작성팀이 충돌 자리(1.19초)를 **숨기지 않고 적었다** — 그것이 신뢰 근거다.

**조건 셋:**
1. 정본은 **줄**이라고 못박는다. 낱말은 강화판.
2. **삼분을 쓰는 편은 화면 글자를 세 통에 전수 배정해 적는다.** 미배정이 있으면 그 편은
   삼분을 근거로 못 쓴다(`ep15s-1` 은 ⑤⑥이 미배정이었다).
3. 박는 자리는 **`scene-reviewer.md` §5 먼저**(그 문단이 「자막의 발화 구간」과 「그 낱말」을
   한 문단에서 섞어 쓰는 것이 혼선의 원인). ADR-V25-15② 는 그다음.
   ⚠️ **문안은 마스터가 안 정한다** — ADR 개정은 관측+사유 기재가 필요하고 사용자·코디네이터 몫.

## 🔴 3. 오타 한 글자가 측정 하나를 없앴다 — 분류표는 **값과 대조**해서 읽어라

`notes` 가 *"진입 라벨 … 아래 **①④⑥**이 전부 이 상태다(α0.6 = ts 0.15~0.17)"* 라고 썼는데
⑥의 α0.6 은 같은 노트 아래쪽에서 **`since(1) 0.555`** 다. ts 0.145 인 것은 **⑦**이다.
→ ⑥이 「진입 라벨」 통에 잘못 들어갔고, 진입 라벨은 정의상 낱말과 안 견주므로
**「하나」를 잴 이유가 사라졌다.**

🔑 **분류 문장을 읽을 때 그 항목의 수치를 옆에 놓고 대조하라.** 「①④⑥」처럼 번호만 나열된
줄은 눈으로 통과한다. 이 파이프라인에서 **분류 오타가 측정 누락으로 번진 첫 사례**다.

## 🔴 4. 검수의 확인 스틸이 **낡은 것이었다** (첫 적발)

`kinds/*.js` 최종 수정 **19:45 / 19:39** vs 검수가 근거로 든 스틸 **19:20~19:24**.
= **검수는 마지막 수정 이전 화면으로 「고쳐졌다」고 썼다.** 결과적으로 틀리지 않았지만
**절차로는 무효**다.

🔑 **판정 첫 손은 `ls -la --time-style=+%H:%M kinds build/stills`** — mtime 비교가 스틸 열기보다 싸다.
낡았으면 `node tools/scene-video/render.mjs <ep> --still t1,t2,…` 로 **직접 다시 뽑는다**.
⚠️ **스틸 시각 산수**: 샷 경계에 **`SHOT_TAIL 0.35`가 샷마다 붙는다.** 줄 시작 합만으로
시각을 잡으면 샷 하나마다 0.35씩 밀린다(내가 처음에 3초 어긋났다).

## 🔴 5. 어절 실측 = 검수 값을 **먼저 재현**한 뒤에 안 잰 자리를 잰다

5ms hop · 20ms 창 RMS 포락선. `ep15s-1` 에서 검수 9개 중 5개를 재현(「열다섯」1.924 ·
「백여든」0.822 · 「줄로」2.325 · 「서른여섯」1.904 · 「겨울」0.441) → 방법이 맞다는 것을
확인한 뒤 **안 잰 둘**을 쟀다: 「셋뿐」 **2.065** · 「하나」 **1.34~1.55**.
🔑 **어절 경계는 무음(peak 대비 ≤0.03)과 폐쇄음 갭에서 잡는다** — 「하나였고요」의 `였고`
폐쇄가 0.10초 무음을 만들어 거꾸로 세는 앵커가 된다. 음절 배분만으로 잡으면 폭이 남는다.
🔴 **`dur` 에 후행 무음이 0.36~0.53초 들어 있다**(ep15s-1 5개 wav 실측) — 글자 수 균등 배분은
**반드시 뒤로 밀린다**(최대 0.72초). 부호가 일정하지 않아 **보정 계수를 만들 수 없다. 재라.**

## 🔴 6. 화면 글자 전수 목록에 **`outro.source` 를 더한다**

`ep15s-1` 에서 **「축」이 화면에 1회** 있었다 — `outro.source` = 「M12 성격 축」(아웃트로 카드).
검수 「등장 0회」·작성팀 「전수 열두 종류」가 **둘 다 캔버스만 센 것**이었고,
**내 기억의 전수 목록조차 이 슬롯을 이름으로 안 부르고 있었다.**

🔴 **갱신된 전수 = `lines.text` + `lines.say` + `spec` 문자열 + `fillText` 리터럴 + `hud.*`
+ `hook` + `outro.source` + `outro.part` + `outro.next` + `outro.siblings`.**
`ep15s-1` 기준 **57개**. 스크립트로 뽑아 금칙 낱말을 정규식으로 훑어라(부분 문자열 오탐 주의 —
「겨울 비**축**」이 걸린다).

**통과시킨 사유**(선례로 쓸 때 그대로 인용할 것): `outro.source` 는 `ep04s-1` 부터
**밀스톤 이름을 그대로 넣는 슬롯**이고 「」 안의 출처 이름이라 설명 하중이 0이다.
⚠️ **이 슬롯이 기술어를 문 것은 처음**이다. 다섯 편 공통이라 바꾼다면 동시다 — 사용자 판단 재료.

## 참고치 (다음 편이 인용해도 되는 것 / 안 되는 것)

- 🟢 **인용해도 된다**: `drop` 최대 |상관| **0.7974**(기본 480→120 쌍과) — 판정선 0.85 아래.
  `sweep` seed 257 · dur 0.66 = **0.0184**. 피크 drop 0.118 · sweep 0.159(천장 0.46, 경고 0건).
- 🟢 **파이프라인 잔존 결함**: `ep02s/S5` ↔ `lf02/S2` **drop 상관 1.0000**(둘 다 dur 0.28 +
  기본 from/to). **발행된 두 편이 같은 소리**다. `thud` 기본 `freq` 150 몰림과 같은 형태.
- 🔴 **인용 금지 1**: 「읽는 창 **1.60초**로 통과했다」(⑦ 「손으로 180칸」 8자, 승인 회차 새 최솟값).
  짧은 이유는 **두 제약이 서로를 밀어서**(더 두면 ⑧과 겹쳐 좌우 역순이 되돌아온다)이지
  1.6초가 충분해서가 아니다. 참고 하한은 여전히 `ep14s-3` **2.34초**.
- 🔴 **인용 금지 2**: 「담화표지 0개가 통과했다」. 통과 사유의 **무게 순서가 다르다** —
  작성팀 1순위였던 「37.45초면 경고가 켜진다」는 **약한 사유**다(경고는 게이트 실패가 아니고
  `ep14s-1` 37.3 · `ep14s-4` 37.5 가 경고를 달고 발행됐다). **결정적 사유는
  「반려 수정 라운드에서 자막을 고치면 `timed.json` → 라벨 창 표 → `delayMs` 가 줄줄이 무효」**다.
  선례 카운트: ep10s~ep15s 19편 중 **4편이 0개**(ep11s · ep12s-2 · ep14s-4 · ep15s-1).
- 🔴 **인용 금지 3**: 「⑨ 램프를 옮겨 반려를 면했다」. **옛 램프(α0.6 = 0.471)도 0.67 안이었다** —
  여유를 넓힌 개선이지 결함 수리가 아니다.

## 코디네이터 사슬 끊김 (2회째 · 박제)

검수 판정서 §3-2 의 어절 실측 **9개** 중 **5개만** 작성팀에 전달됐다. 작성팀이 「판정서를 직접
읽으라」는 지시를 지켜 본문을 열어 나머지 넷을 찾았고, 그중 **「백여든」·「줄로」는 ⑦의 읽는 창
판정에 직접 쓰였다.**
🔑 **교훈은 「요약하지 마라」가 아니라 「셀 수 있는 것은 개수를 함께 넘겨라」다** —
「§3-2 에 실측 **9건**」 한 줄이면 5건만 받은 쪽이 즉시 알아챈다.
🟢 자진 신고는 파이프라인이 도는 신호로 기록한다 — 안 적었으면 나도 못 봤다.
