ep12s(블로그 13편 · M9 공간과 재해)를 **3편으로 분할**해 브리프 작성 (2026-08-08).
산출 = `.staging/01_planner_brief.md` + `episodes/ep12s/notes/planner.md` + `ep12s-1/-2/-3/notes/planner.md`.
`schedule.json`: `order` 의 `ep12s` 한 줄을 `ep12s-1`·`-2`·`-3` 으로 치환 + `sources["ep12s"].split=3` + `note`.
**막 전환 없음** — ep11s·ep12s 둘 다 4막(막이 바뀐 건 ep11s).

**🔑 새 판단 잣대: 「원문이 스스로 요약한 결과물 수」를 사건 수로 쓰지 않는다.**
이 글은 머리말에서 *"결과물은 셋"*(구역 · 재해 · 「식량 N일치」 HUD)이라고 못 박는데,
그 셋으로 세면 **구역(ZoneService)과 재해 선반(DisasterSO)이 편이 된다 — 둘 다 ①어긋난 상태가 없다.**
구역은 원문이 직접 *"나쁘진 않았지만 그냥 습관이지 규칙은 아니었습니다"* 라고 써 실패가 0이고(유형 ②+③),
재해 선반은 아예 없던 것을 만든 것이다(유형 ②). **결과물 목록은 사건 목록이 아니다.**

**세운 사건 셋** (전부 세 조각 + 본문 20초 확보):
1. `ep12s-1` 「조리식 20개」가 주민 **10명** 시절 숫자 → 주민 **4명**인데 그대로 → `FoodDaysLeft`(며칠 버티나)
2. `ep12s-2` 1년 돌려 겨울 잔량 **40**(기준 **30**) → 네 군데 조임 + 계절 레시피 → **짝인 요리 발동 조건이 어긋남**
3. `ep12s-3` 코드 **0줄**로 넣은 홍수가 「작물 **0개** 소실」 → 원인은 앞 편의 재파종 잠금 → 밭 시설을 부수는 재해로

**흡수한 것**: 이탈 오탐(진단 로그 먼저) — 세 조각이 다 있으나 **결론이 12-3과 같은 계열**
("증상 쪽을 뒤지면 못 찾는다", 유형 ④) + 결말이 "버그가 없었다"라 25초 편의 마지막 3초가 죽는다.
상대 목표 절대값 오해 · 정원 제한 · 관개수로 목표 끄기 · 비용표 한 줄 = 곁가지.

**순서를 못 바꾼 이유(인과 잠금)**: `ep12s-2` 의 첫 조정이 *"밭 재파종을 **식량 일수**로 잠갔다"* 라
`ep12s-1`(FoodDaysLeft) 뒤여야 하고, 그 잠금이 `ep12s-3`(홍수 0개)의 원인이다. C→D→E 고정.
그래서 **ep11s 의 `outro.next`(「12편 · 마을에 처음으로 재해가 생깁니다」)를 12-1편이 지지 못한다** —
브리프에 「첫 줄에서 이어받는 예시 문장」까지 적었다(*"재해를 내리기 전에 이상한 걸 찾았습니다.
겨울 목표가 조리식 20개."*). 실물 재해는 12-2·12-3 이 낸다.

**수치 사정**: 원문 10,271자, `<table>`/`<pre>`/`<svg>` **전부 0개**(오염 0). 수치 문장이 풍부하고
전후 대비 쌍이 넷(10명→4명 / 20개→3일치 / 30→40 / 코드 0줄→작물 0개).
🔴 **HTML 주석 0개 = `selected_commits_range` 없음 → 커밋 수 사용 불가**(ep11s 와 같음. 두 회차 연속).
🔑 「밸런스를 **네 번** 고쳤다」는 이 글엔 서수(첫째~넷째)로만 있고 그 표현은 **다음 글(ep13s 원문)**
첫 문단에 있다 — 저자 본인의 회고라 사실이며, 브리프에 근거 파일까지 적었다.
