`check.mjs` 통과는 통과의 근거가 아니다. 실제로 결함이 나온 자리는 아래 넷이고,
매 회차 이 넷을 손으로 본다.

**Why:** ep00s 1차 검수(2026-07-29)에서 check.mjs 는 🔴 0건·⚠ 1건으로 통과를 냈는데,
사람이 프레임을 뽑아 보니 반려급 결함이 넷 나왔다. 기계 점검 11종은 "규칙을 지켰나"만 본다.

**How to apply:**

1. **`checks` 키가 실제로 읽히는 키인가.** `check.mjs` 는 `checks.palette` 와 `checks.edge`
   **둘만** 읽는다(파일 안 `paletteSkip`/`edgeSkip` 두 줄). 다른 이름은 조용히 무시되면서
   씬 노트에는 "예외를 선언했다"고 남는다 — 선언한 척이 되고 다음 회차가 그 선례를 베낀다.
   실제로 먹었는지는 check.mjs 출력의 `(선언 예외: S5=…)` 문구로 확인된다. 안 찍히면 안 먹은 것.
   정보성 메모는 `checks` 가 아니라 `notes` 자리다.

2. **좌우·위 가장자리.** check.mjs 는 **아래 가장자리만** 본다. 스프링 오버슈트가 붙는
   요소(`bars` 의 note 도장, `metrics` 카드)는 좌우로 넘친다. 무대 폭은 392px(CSS) 고정이고
   `bars` note 는 40px×spring 이라 **한글 3자를 넘으면 잘린다**(ep01s "50배"=3자 안전 / ep00s
   "여섯 중 넷"=5자 잘림). 검사법은 캔버스 0열·W-1열의 알파를 프레임마다 세는 것.

3. **막대·카드 등장 순서가 나레이션 순서와 같은가.** `bars.js` 는 `keys=['b','a']` 로
   **왼쪽에 b** 를 그린다(주석: "대본이 큰 값을 먼저 말한다"). 대본이 작은 값을 먼저 말하는
   회차에서 a/b 를 그대로 두면 왼쪽 열이 몇 초 동안 **"0"** 을 띄운 채 남는다 —
   화면이 원문과 반대되는 수치를 말하는 시간이 생긴다.

4. **화면이 자막을 그대로 옮겨 적지 않았는가.** `plan`·`term` 처럼 라벨이 주인공인 kind 는
   자막과 같은 문자열을 카드로 늘어놓기 쉽다. 그 샷은 정보 증가량이 0이다.
   판단 기준은 kind 가 아니라 **"화면 문자열이 원문에만 있고 자막에는 없는 것인가"**.

5. 🔴 **캔버스 안에서 글자 위에 글자가 얹히지 않았는가.** 게이트는 **잘림만** 본다 —
   겹침은 잘림이 아니라서 `좌우/아래 가장자리 잘림 없음` 이 통과한 채로 나간다.
   lf02 1차(2026-08-09)에서 kind 9개를 스틸로 떠 봤더니 **다섯이 겹쳤다**
   (`ledger` 값이 라벨을 통째로 덮음 · `identity` 헤드라인이 라벨을 덮음 ·
   `decay` 축 라벨끼리 `DAY 13AY` · `handoff` 문구 셋이 한 자리 · `mechanisms` 는
   **엔진 HUD 챕터 칩 아래**로 들어감).
   - 검사법: `node render.mjs <ep> --still <각 캔버스 샷 시각>` → 눈으로. 임시 타이밍
     역산은 [[review-method-wide-longform]] 4번.
   - 산술로도 잡힌다 — **행 높이 vs (라벨 baseline, 값 baseline, 폰트 크기)** 를 코드에서
     계산해 보면 된다(`ledger.js` 는 rowH 35px 에 10px 라벨 + 20px 값을 4px 간격에 겹쳐 그렸다).
   - **캔버스 우상단은 쓰면 안 되는 자리다**(wide). 엔진 HUD 가 우측 46%·top 3% 를 덮으므로
     `x = w − M` 기준으로 그린 라벨은 칩에 잠긴다. 나머지 kind 처럼 `x = M` 좌측 정렬이 안전.
   - 🔴 **글자를 덮는 것은 글자만이 아니다.** lf02 2차(2026-08-09)에서 다섯 자리가 더 나왔는데
     범인은 **연속 모션 점**(`humanonly` r5 점이 카드 라벨 baseline 을 21.8초 내내 지남) ·
     **막대·프레임 획**(`costfloor` 의 `MIN COST` 가 막대 3px 획 관통 · `blindspot` 머리 라벨이
     흰 프레임에 아래 절반 잘림) · **점선**(`decay` 의 `-50% / DAY` 끝 글자) · **표식**
     (`handraise` 추천 ▼가 라벨 끝 두 글자) 이었다. **전부 같은 색**이라 팔레트 게이트가 구조적으로
     못 본다 → [[review-method-same-color-and-clip-seam]].
   - 🔴 **한 kind 당 최소 3시점(초·중·말)을 떠라.** cue 로 나중에 나타나는 라벨은 첫 스틸에
     없다 — lf02 1차가 `costfloor` 를 20s 한 장만 보고 「겹침 0」이라 적었는데
     `MIN COST` 는 `cue(4)` 뒤에 뜬다(오판). `spec.phase` 가 있으면 **phase 마다** 따로 뜬다.
   - 🔴 **「N종 고치고 나머지는 작성팀이 훑어라」로 넘기지 마라.** 작성팀 환경에 크로미움이
     없으면 물리적으로 불가능하다(lf02 writer 가 두 차수 연속 그렇게 적었다). **캔버스 kind
     전부를 검수가 뜬다** — `render.mjs <ep> --still a,b,c,…` 는 한 배치에 10~15장이고
     20종이면 3배치·약 2분이다.
   - 🔴 **가로선·가로 막대가 값 라벨의 「위쪽 획」만 먹는 자리는 세 검수가 다 놓쳤다.**
     lf02 3차(2026-08-09)에서 `costfloor` phase 1 의 CookMeal 막대 값 라벨 `6` 이 게이트
     막대(`yOf(8)`, lineWidth 6)에 **위쪽 2.4px** 을 먹혀 바닥 고리만 남아 **`o` 로 읽혔다.**
     글자가 「사라지지」 않고 **다른 글자로 읽히는** 형태라 눈으로 훑을 때 그냥 지나간다.
     **산수 한 줄로 전수 검사하라** — `라벨 baseline − 글자높이 < 선 y + lineWidth/2` 이면 잘림
     (mono 10px 이면 글자높이 ≈ 7px). 값이 클수록 라벨이 올라가는 막대 차트에서
     **기준선·게이트선의 값과 가까운 막대**가 항상 후보다.
   - 🔑 **직전 차수 스틸을 `stills-2nd` 처럼 복사해 보존하라.** 새로 찾은 결함이
     「이번 개정이 만든 회귀」인지 「원래 있었는데 놓친 것」인지는 **같은 초 스틸의 픽셀 합
     비교**로 1분 만에 갈린다. 등급 판정(반려 vs 정정)이 여기서 갈린다.
   - 🔴 **모션 면적을 키우라는 처방은 「아래 가장자리 잘림」을 낳는다.** lf02 2차에서
     `ledger` 의 세로 이동 띠가 `by = lerp(y0−10, h−22, k)` + `height = rowH−6` 이라
     `k=1` 에서 캔버스를 7.6px 넘어 **기계 fail(1673px)** 이 됐다. 처방을 낼 때
     **「띠 끝이 상자 안에 남는가」를 같이 적는다.** x 축 이동은 안전, **y 축 이동만 위험**.
