**「N개가 차례로 켜진다/사라진다」를 `진행도 × N − 순번` 꼴로 짠 kind 는, 진행도가 1.0 에서
클램프되는 순간 **양 끝 원소 하나가 안 닫힌다.** 끝 상태를 반드시 식으로 풀고 스틸로 확인해라.**

**Why:** `ep15s-4` S4(`twoasks.js`)에서 실제로 났다 — 착지 그림이

```js
const gone = keep ? 0 : ease(clamp((clearK * ORDER.length - rank) / 1.6));  // clearK = clamp(...) → 최대 1.0
```

이었는데 `rank` 최댓값이 `N−1` 이라 마지막 원소의 인자가 `(N − (N−1)) / 1.6 = 0.625` 에서 멈춘다.
`ease(0.625) = 0.684` → **`grow` 0.316 으로 얼어붙어 샷 끝까지 남았다.** 이 편의 페이오프가
「넘치던 것이 **하나만** 남는다」인데 화면에는 **둘**이 있었고, 남은 쪽은 사라지다 만 크기라
연출이 아니라 고장으로 읽혔다. `reads`·`notes` 셋과 kind 머리 주석이 전부 「하나만 남는다」로
적혀 있었고 좌표 여유 계산의 전제(「유일하게 남은 것이라 옆 칸 겹침 없다」)까지 같이 깨졌다.

🔴 **게이트는 전부 통과한다** — 결정성·정적·팔레트·가장자리 어느 것도 「의도한 끝 상태와 다르다」를
못 본다. 픽셀 변화량으로도 못 잡는다(작은 요소가 계속 숨 쉬고 있어 오히려 정적 검사에 유리하다).

**How to apply:**
1. kind 에서 **개수가 시간의 함수인 식**을 찾는다(`prog − n` · `clearK*N − rank` · `k/0.8 × N` 꼴).
2. **진행 변수의 최댓값을 대입해** 첫 원소와 마지막 원소의 값을 손으로 낸다. 램프 폭(위 예의
   `/1.6`)이 있으면 **인자가 그 폭을 넘어서는지**가 관건이다 — 안 넘으면 안 닫힌다.
3. 대칭으로 **시작 쪽도** 본다(`prog − n` 은 `n = 0` 이 `t = 0` 에 이미 켜져 있을 수 있다).
4. 반대로 몇 초 남는지도 계산해 **그 상태가 화면에 얼마나 오래 서 있는지** 적는다
   (`ep15s-4` 는 1.8초 = 착지 그림 전부였다).
5. 🔴 **확인 사살은 스틸이다** — `render.mjs <ep> --still <abs초>` 로 **샷이 끝나기 직전** 프레임을
   뜬다. 아무 프레임이나 뜨면 전이 중이라 안 보인다. abs 시각은 `timed.json` 으로
   [[review_method_shot_timing]] 대로 계산한다(`dur` 은 `pauseAfter` 포함 · 샷마다 `SHOT_TAIL` 0.35).
6. 처방은 램프에 여유를 주는 것이다 — `clearK * (N + 램프폭)` 처럼. **고친 뒤 `--fps 30` 재실행과
   스틸 재확인까지 요구해라**(낡은 스틸로 수리를 확인한 사고가 있다 → [[review_method_self_report_is_not_evidence]]).

🔑 이 검사는 [[feedback_review_blind_spots]] 의 「기계가 못 보는 자리」에 하나를 더한다 —
**끝 상태(terminal state)는 아무 게이트도 안 본다. `reads` 가 주장하는 끝 그림과 식이 내는 끝 그림을
직접 대조하는 사람이 없으면 그대로 나간다.**
