`check.mjs` 의 `좌우 가장자리 잘림 없음` 이 걸렸을 때, **눈대중으로 판정하지 않는다.**
다섯 단계로 산술 확정한다.

**Why:** ep02s 무인 실행(2026-07-30)에서 S4·S10 두 샷이 함께 걸렸는데, 눈으로는 둘 다
"글자가 잘렸다"로 보였다. 실제로는 S4 는 33.05px 초과가 3.27초 서 있는 진짜 잘림,
S10 은 잘림(0.24초)보다 **두 표식이 서로 들이받아 글자가 포개지는 것**(1.06초)이 본체였다.
같은 실패 메시지 뒤에 다른 병이 있었고, 숫자를 재고서야 갈렸다.

**How to apply:**

1. **폭은 엔진 안에서 잰다.** `openEngine` 으로 페이지를 띄우고 `measureText` 를 부른다.
   node 에서 추정하면 안 된다(폰트가 다르다). 검산법: *화면에 남은 폭* 과
   *잘린 채 보이는 문자열의 폭* 이 일치하면 진단이 확정된다 —
   ep02s S4 는 352−220.45 = **131.55** 와 `GOAP 목표 : HungerLe` 의 **131.60** 이 맞아떨어졌다.
   스틸의 글자 시작 픽셀을 CSS 로 역산해 한 번 더 대조한다(image x = 55 + cssX × 2.7551).
   캔버스 실측: CSS **352 × 307.08**, device **970 × 846**, dpr 2.7551.

2. **접촉 y 좌표로 범인을 특정한다.** 프레임마다 바깥 2열의 알파뿐 아니라
   **y 범위와 좌/우 구분**을 같이 센다. "S4 우 4px, y 666~669 device" 하나로
   *캔버스 안의 다른 모든 요소는 무죄* 가 증명되고, 그 라벨만 고치면 0% 가 된다는
   예측이 선다. 좌/우를 안 나누면 "밀려나는 옛 표식"과 "들어오는 새 카드"가 한 숫자로 섞인다.
   `check.mjs` 는 5fps 라 샷당 샘플이 ~17개뿐 — **30fps 로 다시 재야** 구간이 보인다
   (한 프레임이 5.9%p 라 문턱 25% 근처는 샘플링 잡음에 흔들린다).

3. **`checks.edge` 선언 기준.** 문턱 25%(`check.mjs:269-275`)는
   "잘린 글자는 몇 초씩 서 있고 쓸고 지나가는 그림은 스친다"로 잡은 값이다.
   선언은 **진입·퇴장 모션(상자·도형이 화면을 가로지름)** 에만 쓴다.
   **글자가 잘리는 것에는 절대 안 쓴다** — 좌우 검사 자체가 ep02s S4 의
   `HungerLevel → HungerLe` 사고 때문에 생겼고(`check.mjs:186-206`), 같은 회차에서
   그 검사를 무력화하는 선언을 남기면 다음 회차가 그 선례를 베낀다.
   판단이 애매하면 기준은 가장자리가 아니라 **그 샷의 `reads` 가 아직 성립하는가** 다.

4. **자주 나오는 근본 원인 세 가지.**
   - *폭 제한을 박스에만 걸고 글자에는 안 걸음.* `gw = min(textW+18, bw+8)` 식으로 박스만
     막으면 글자가 박스를 뚫고 나가 캔버스에서 잘린다. 박스는 글자를 감싸고,
     **가운데 정렬 기준점을 `clamp` 로 캔버스 안에 넣는다**(글로우 blur 만큼 여백을 더 준다).
   - *여러 장이 출발 간격과 도착 간격이 달라 서로 들이받음.* 이동 거리를 같게 하면
     간격이 유지된다.
   - *퇴장 투명도의 최솟값이 0 이 아님.* 요소가 안 사라진 채 캔버스 경계에 잘려 나간다 —
     경계가 지워 주는 건 연출이 아니라 미완성이다.

5. **한글 섞인 문자열을 `mono` 로 찍었는지 같이 본다.** SceneMono 에 한글이 없어
   시스템 폴백으로 떨어지고(머신마다 다름 = 무인 렌더 재현성 위험), 폭도 커진다
   (같은 문자열이 mono 164.60 vs disp 138.72). 기계 판정법: `'목표'` 를
   `700 11px SceneMono` 와 `700 11px "__NoSuchFont__"` 로 재서 같으면 폴백이다
   (ep02s S4 실측 둘 다 26.00). `lib.js:45-48` 이 이미 금지한 자리다.

**대본을 못 건드리는 수정 지시일 때**: 처방은 폰트 패밀리·박스 폭·정렬 기준점·
이동거리·투명도만 바꾼다. 폰트를 줄여 맞추려 하기 전에 **정렬 기준점을 옮기는 쪽**을 먼저
본다 — ep02s S4 는 막대 중심(302.75) 기준으로는 98.5px 밖에 못 쓰지만, 기준점을 캔버스
안으로 당기면 320px 을 쓸 수 있어 폰트를 오히려 키울 수도 있었다.
