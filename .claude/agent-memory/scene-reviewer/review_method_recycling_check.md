# 돌려막기는 이름이 아니라 장치로 판정한다

kind 이름이 하나도 안 겹쳐도 돌려막기일 수 있다. 대조할 것은 **장치**다 —
출발점·갈래 수·값이 실물화되는 방식·강조 대상·캡션 문자열과 그 렌더 방식.
배치만 바꾼 것(평행 배열 → 방사형)은 다른 그림이 아니다.

**꼭 하는 두 가지:**

1. **앞 회차 `kinds/*.js` 주석을 읽는다.** 주석이 이 회차를 이름으로 지목하고 있으면
   그게 곧 경계선이다. 실제 사례 = `ep00s/kinds/channels.js:11` 이
   *"ep01s S1B 가 같은 로그를 카드 그리드로 이미 썼고"* 라며 ep01s 를 피해 설계됐다고
   적어 뒀다. 그런데 ep01s 재제작이 카드 그리드를 버리고 네 갈래 쪽으로 옮겨와
   0편이 확보해 둔 간격을 써 버렸다.
2. **기각 사유표의 논증이 앞 회차 주석의 논증과 같은 문장인지 본다.** 같은 논증을
   다시 세우면 같은 계열의 답에 도착한다. ep01s writer.md 의 `metrics` 기각 사유
   ("비교가 아니라 한 방향으로만 몰렸다")가 channels.js 주석과 사실상 같은 문장이었다.

**참작 사유도 같이 적는다.** 원문 둘이 같은 로그·같은 개념을 실었으면 내용 겹침은
강제된 것이라 작성팀 잘못이 아니다. 반려하되 "그릇 선택은 자유였다"로 범위를 좁혀야
작성팀이 대본까지 흔들지 않는다.

**Why:** 사용자가 공용 kind 라이브러리를 없애고 그림을 회차 소유로 바꾼 이유가
*"각 블로그 글의 개성에 맞게끔 매번 새롭게"* 다. 이름만 갈아끼운 재설계는 그 목적을 못 채운다.

**How to apply:** 매 회차 검수의 돌려막기 항목에서 옛 kind(git 으로 복원) + 직전 회차
`episodes/*/kinds/` 를 전부 읽고 표로 대조한다. writer 의 "안 겹친다" 주장은 근거
없이 통과시키지 않는다 — 실제로 한 번 틀렸다([[ep01s-rework-review]]).
