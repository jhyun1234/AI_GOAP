효과음 `delayMs` 는 **두 축으로 따로 검산한다.** 하나만 보면 틀린다.

**Why:** ep02s 효과음 검수(2026-07-31)에서 여섯 개 전부를 다시 풀어 보니, 그림 정렬은
`cue` 역산으로 나오지만 *"나레이션이 이때 무슨 말을 하는가"* 는 그 식으로 안 나온다.
`timed.json` 의 `dur` 에는 TTS wav 의 **선행 무음 360~540ms · 후행 무음 500~700ms** 가
통째로 들어 있다. 즉 `line.t` 는 자막이 뜨는 시각이지 말이 시작하는 시각이 아니다.
이걸 안 재면 "이 소리가 말을 먹는가"도 "이때 그 단어를 발음하는가"도 판정할 수 없다.

**How to apply:**

① **그림 축** — `cue(i, lead, span)` = `clamp((ts−a)/(b−a))`, `a = lᵢ.t−lead`,
`b = lᵢ.t + lᵢ.dur×span` (`engine/engine.js:240-245`). `lᵢ.dur` 는 발화+pauseAfter
(`engine.js:156`). 효과음은 `line.t + delayMs` 에 놓인다(`render.mjs:111`) — 그림과 **같은 기준선**.
```
c = (delayMs/1000 + lead) / (lead + dur×span)
delayMs = (c × 창 − lead) × 1000
```
`ease` 는 smoothstep 이라 `ease(c)=0.5 ⇔ c=0.5`. **이중 이징**(`lerp(a,b,ease(ak))` 에
`ak` 가 이미 `ease(cue(...))`)을 흘리지 말 것 — nextnote·wardline 이 그렇다.
🔴 `cue` 를 안 쓰고 `frac(t/CYCLE)` 로 도는 그림이 있다(tripwire). 그런 샷은 **샷 안 절대시각**
으로 풀고 자막 시작 시각과 대조해야 한다. 자막 인덱스만 보면 절대 못 잡는다.

② **말 축** — 줄별 wav(`timed.json` 의 `file`)를 20ms 창 RMS 로 훑어 말 시작·끝을 재고,
소리 시각의 단기 RMS 를 직접 잰다. 판정 기준은 나레이션 **평균** RMS(ep02s 0.051)가 아니라
**그 순간의 값**이다 — 유성 구간은 0.11~0.15 라 평균과 비교하면 소리에 부당하게 불리하다.
말이 쉬는 골이나 말 시작 직전 무음에 떨어진 소리는 마스킹이 0 이고, 그게 가장 좋은 자리다.

🔴 **②-b 어절 시각을 「`dur` ÷ 글자 수」로 배분한 주장은 그 자리에서 기각한다.** `dur` 은
선행 무음 0.29~0.46 + 실제 발화 + **후행 무음 0.44~0.57** 이라, 배분값은 시작을 최대 0.46초
이르게·끝을 최대 0.57초 늦게 본다(`ep15s-1` 실측 오차 **0.72초**, 한도 0.67초를 넘는다).
작성팀 `notes` 가 그 방식을 쓰면 **라벨 등장·`delayMs` 판정 근거가 통째로 무효**다.
재는 법 = 20ms 창 · 10ms hop · 문턱 = 피크 RMS 10% · 90ms 이하 틈 병합 → **발화 구간 목록**.
한국어 TTS 는 절 경계에 100ms 안팎의 쉼을 넣으므로 이 목록이 곧 어절 묶음이다
(`ep15s-4` S4: 「무엇을 짓는지는 안 보고」 0.39~1.80 / 「누가 바쁜지만 봤어요」 1.90~3.09).
🟢 **사건을 `since(i)` 위에 세운 회차는 이 오차에 면역**이다 — 그걸 먼저 확인하면 대부분 끝난다.

③ `sfx.mjs` 의 `synth(kind, opt)` 를 씬의 실제 인자로 **직접 돌려** 길이·피크·RMS·영교차
주파수를 잰다. 같은 kind 가 두 번 나올 때 "성격이 갈렸나"는 이 숫자로만 판정할 수 있다.

`check.mjs` 에는 효과음 항목이 **없다** — 기계가 아무 증거도 안 준다. 위 셋이 증거 전부다.

## 🔴 발화 개시는 **20ms RMS 포락선**으로 재고, 어절 시각은 **`dur` 배분으로 절대 구하지 마라**

**Why:** `ep15s-1` 검수(2026-08-10)가 작성팀의 어절 시각표를 wav 와 대조해 **최대 0.72초** 오차를
찾았다. 원인은 하나 — **`dur` 에 후행 무음이 들어 있다.** `ep15s-5` 열 줄을 재 보니
**후행 무음이 0.496~0.555초(평균 0.52 · `dur` 의 12~21%)로 예외 없이 붙어 있었다.**
즉 「글자 수로 균등 배분」은 **모든 회차에서 구조적으로 틀린다.**
(선행 무음도 0.28~0.51로 줄마다 다르다 — 앞뒤 양쪽에서 어긋난다.)

**How to apply:**
- **발화 개시·끝**: 20ms 창 RMS 포락선을 만들고 **피크의 8%**(≈ −22dB)를 넘는 첫/마지막 창.
  원표본 절대치 6% 문턱과 비교했더니 차이가 **최대 15ms** 라, 급하면 원표본도 쓸 수 있다.
  🔑 **어느 쪽이든 「wav 를 열었다」는 사실이 핵심**이다 — 배분값과는 0.7초까지 갈린다.
- **줄 안 절 경계**(어느 낱말이 언제 나오나)는 **내부 무음 길이 순위**로 뜬다.
  쉼표는 다른 지점보다 확연히 길다(ep15s-5 S3[1]: 쉼표 **0.200초** vs 나머지 0.06~0.12초).
  🔴 **짧은 dip(0.06~0.12초)은 파열음이지 절 경계가 아니다** — 그걸로 낱말 위치를 주장하지 마라.
  검산은 글자 수 × 회차 실측 자당 시간으로 **맞는지만** 본다(단독 근거로는 쓰지 않는다).
- **`since()` 위에 세운 사건은 이 오차에 면역**이다(원점이 줄 시작이라). 어절 위치에 기댄
  `delayMs` 를 보면 **소리를 옮기지 말고 줄을 잘라** 그 낱말이 줄 머리에 오게 하라(ep15s-5 S2 선례).
- 🔴 **검수인 내가 낸 배분값이 작성팀 파일로 번진 사례가 있다**(`ep15s-2`). 1차 리포트에서
  어절 시각을 `dur` 위에 배분해 냈더니 작성팀이 그 수를 `sfx.why`·`notes` 에 **출처까지 밝히고**
  옮겨 적었고, 3차에서 포락선으로 다시 재니 여덟 개 중 다섯이 **최대 0.45초** 어긋나 있었다.
  🔑 **내 리포트의 수는 다음 라운드에 파일이 된다** — 배분값을 리포트에 쓰지 마라.
- 🔑 **교차 검증이 싸다**: 「발화 구간 위 음절 균등 배분」과 「35ms 이상 무음 간극」 두 방법이
  `ep15s-2` 에서 **10~42ms 안에 일치**했다(간극이 예측 위치에 정확히 앉는다 —
  「구십오」 모형 1.598 ↔ 간극 1.545~**1.580**). 둘을 같이 내면 판정이 흔들리지 않는다.
  ⚠️ 다만 낱말 **안**에도 간극이 생긴다(고집\|쟁이 1.110~1.185) — 간극을 무조건 어절 경계로 읽지 마라.
- 🔴 **무음 간극이 없는 자리는 「자음 랜드마크」로 짚어라 — 이게 가장 센 방법이다.**
  한국어 TTS 는 낱말 사이에 쉼을 **안 넣는 경우가 많아** 간극법이 침묵한다. 그때는
  5ms hop 으로 **저역 RMS(폐쇄음 골)** 와 **고역 에너지(마찰·파열음)** 를 따로 떠서
  아는 자모 배열과 맞춘다. 고역 = `x[n] − x[n−1]` 차분의 RMS 면 충분하다.
  ㅅ·ㅆ·ㅈ·ㅊ·ㅍ·ㅌ 은 고역 버스트로, ㄱ·ㅂ·ㄷ 받침/초성은 20~80ms 저역 골로 뜬다.
  실측(`ep15s-3` wav01 「성격이 목수를 마을 밖으로 내보냈어요」): 고역 버스트가 **딱 하나**
  (2.611~2.701) = 「목**수**」의 ㅅ, 그 앞 골 2.551 = 「목」의 ㄱ, 앞 골 2.145 = 「격」의 ㄱ,
  뒤 골 3.122·3.232 = 「밖」의 ㅂ·ㄲ → **네 랜드마크가 서로를 검산해 「목수」 = 2.47~2.78초**
  로 확정된다. 균등배분값(2.37~2.79)과 0.10초 차이인데, 그 0.10초가 판정선 근처에서 갈린다.
  🔑 **랜드마크 위치를 「발화 구간 위 균등배분 예측 음절 번호」와 대조하면 오정렬이 바로 보인다**
  (버스트 0.717 → 예측 4.0번째 = 「수」 ✅). 둘이 어긋나면 랜드마크 해석이 틀린 것이다.
- 🔴 **내가 이 규칙을 갖고도 두 번 어겼다**(`ep15s-3` 1·2차). 한 줄(wav01)은 말 끝을 재 놓고
  다른 줄(wav03)은 `dur` 끝까지 말한다고 보고 배분해 **어절이 0.15~0.36초 밀렸다.**
  🔑 **줄마다 재라 — 한 줄을 쟀다고 회차를 잰 것이 아니다.** 열 줄 전부의 후행 무음을
  표로 뽑는 데 스크립트 하나면 된다(`ep15s-3`: 열 줄 전부 0.46~0.57초).
- 🟡 **목록이 말보다 얼마나 앞서는가는 「절 단위」로 재라.** ep15s-5 S3 의 칸 셋은 `since(1)` 1.19 에
  다 켜지는데 열거 절은 1.76 에 시작한다 — **묶음으로 0.57초 = 한도 0.67초 안**(낱개로 보면
  0.6/1.5/2.0초). 같은 내용을 먼저 보여주고 읽어 주는 것은 정상 어법이라 통과시켰다.
