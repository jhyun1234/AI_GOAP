승인(APPROVED)을 받은 회차를 다시 작업할 때, **자막(`text`/`say`)·샷 구성·수치는 그대로 두는
것이 기본**이다. 새 그림이 더 나은 순서를 실제로 요구할 때만 고치고, 고쳤으면 `notes` 에 사유를 쓴다.

**Why:** 2026-07-29 `ep00s` 재작업 지시가 명시적으로 이렇게 왔다 — "대본은 살아 있다.
검수·마스터 승인까지 통과했다. **버릴 것은 그림이다.**" 대본은 이미 사실관계 대조·말투 규칙·
콜드 오픈·열린 고리 판정을 전부 통과한 자산이고, 그림 문제 때문에 그걸 다시 흔들면
승인 절차를 처음부터 다시 태우게 된다. 실제로 ep00s 2차에서 자막 27줄을 한 글자도 안 바꾸고
`kind`·`spec`·`reads`·`notes` 만 갈아 끼웠다.

**How to apply:**
- 재작업 지시가 오면 먼저 물어야 할 것: *무엇이 반려됐나 — 대본인가 그림인가.*
  그림이면 `scene.json` 의 `lines` 블록은 손대지 않는다.
- 단, **`excluded` 는 다시 본다.** 1차에서 "그림이 서지 않는다"는 사유로 버린 대목은
  대개 그림이 없었던 게 아니라 **그릇이 없었던 것**이다. 새 kind 를 만들면 되살아나는 경우가 많다
  (ep00s 에서 두 건이 그렇게 돌아왔다: 거짓 전파 2종 → 쌓는 블록의 라벨,
  EditMode 테스트 2종 → 검문소의 문).
- 되살렸으면 `excluded` 에서 지우지 말고 "🟢 되살림"으로 남겨 **왜 1차 사유가 틀렸는지**를 적는다.
  (예외 — 반려 사유 자체가 무효로 확정된 경우엔 항목을 배열에서 **빼라**는 지시가 올 수 있다.
  ep02s 재작업이 그랬다: "60초 상한"이라는 문자열을 사유로 남기지 말 것.)

## 얼음이 깨지는 조건 — 사유가 무효로 확정됐을 때

2026-07-30 `ep02s` 재작업은 반대 방향이었다. **그림이 아니라 사유가 반려됐다.**
검수팀이 *"쇼츠 60초 상한(요구 40~60초)"* 으로 83.6초 → 47.9초를 잘랐는데,
그 숫자는 리포 어디에도 없었다(`routine-prompt.md` 13~21행: **"길이 상한 없음. 글 분량이 정한다."**).
승인된 회차가 109.7초·91.3초다.

이때는 **자막을 늘리는 것이 일**이다. 위 규칙과 충돌하지 않는다 — 얼려 두는 것은
*판정을 통과한 대본*이고, 무효한 사유로 잘려 나간 분량은 애초에 판정을 받은 적이 없다.
ep02s 는 자막 15줄 → 28줄, say 273자 → 약 510자가 됐다.

**How to apply:**
- 자막을 고치는 근거는 **처방 문서에 명시된 자리만**. ep02s 에서 S8 자막을
  "테스트 하나가 방향을 지키고" → "안전망은 테스트 4종" 으로 바꾼 것은 처방 P-D 가
  *"원문보다 작게 말하고 있다"* 고 지목했기 때문이다. 지목되지 않은 S4·S5 는 안 건드렸다.
- 무효 지시는 **집행하지 말고 노트에 무효라고 적는다.** `writer.md` 를 덮어쓰지 말고
  새 노트(`writer-redo.md`)에 "1절과 10절 1항은 폐기"라고 남긴다.
- 🔴 **길이를 목표로 바꿔 잡지 마라.** "60초도 90초도 목표가 아니다"가 지시의 원문이었다.
  담을 것을 담고 나온 길이가 그 회차의 길이다.
