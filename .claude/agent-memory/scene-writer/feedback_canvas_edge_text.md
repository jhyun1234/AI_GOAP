캔버스에 가운데 정렬로 긴 글자를 찍을 때는 **`measureText` 로 폭을 재고, 정렬 기준점 자체를
`clamp(중심, PAD + tw/2, w - PAD - tw/2)` 로 캔버스 안쪽에 가둔다.** 담는 박스가 있으면
박스는 글자를 **감싸야** 한다(`gw = tw + 18`). PAD 는 글로우 blur 를 포함해 잡는다(blur 10 → PAD 16).

**Why:** ep02s S4 에서 폭 제한을 `Math.min(..., bw+8)` 로 **박스에만** 걸고 글자에는 안 걸어,
박스 82.50px 안에 글자 164.60px 이 들어갔다. 글자가 캔버스 오른쪽으로 33.05 CSS px 뚫고 나가
`GOAP 목표 : HungerLevel ↓` 가 `GOAP 목표 : HungerLe` 까지만 보였고 — 하필 뜻을 나르는 `↓` 가
잘렸다 — 3.27초 동안 그 상태로 정지해 `check.mjs` 의 가장자리 검사에 걸렸다.
막대·트랙 같은 도형은 다 안쪽이었고 **오직 글자 하나가 원인**이었다.

**How to apply:**
- 🔴 **문자열을 줄여서 도망가지 않는다.** 화면 문자열은 원문 근거를 가진 자산이라
  자르면 사실이 바뀐다. 폰트 크기·박스 폭·정렬 기준점으로만 푼다 → [[feedback-string-fact-check]]
- 잘리지 않는 요소에도 **여백이 10px 아래면 같은 가드를 미리 건다**(순수 가드라 권장값에서는
  위치가 안 바뀐다). 같은 샷의 `허기 · HungerLevel` 은 여백이 7.05px 뿐이라 폰트 한 눈금 차이로
  넘어갈 상태였다.
- 헬퍼 함수 안에서 `w` 가 요소 폭을 뜻하면 캔버스 폭은 `cw` 로 따로 받는다. 이름이 겹쳐서
  가드를 못 걸고 넘어가는 일이 실제로 있었다.
- **한글이 섞인 문자열에 `mono` 를 쓰지 않는다**(`lib.js:45-48`). SceneMono 에 한글이 없어
  그 글자만 시스템 폴백으로 떨어지고, 한 줄 안에서 폰트가 갈리며 **폴백은 머신마다 달라
  무인 렌더의 재현성이 깨진다.** 위 사고도 같은 줄에서 이게 함께 일어났다.
- 옆으로 퇴장하는 요소는 **가장자리에 닿기 전에 alpha 가 0 이 되게** 한다. `1 - 0.6*k` 처럼
  최솟값이 0.4 면 화면 경계가 대신 지워 주는 것이고, 그건 연출이 아니라 미완성이다.
- 여러 장이 함께 퇴장하면 **이동 거리를 같게** 준다. 출발 간격 106 · 도착 간격 6 이면
  뒤엣것이 앞엣것을 들이받아 글자가 포개지고, 그 순간 `reads` 가 통째로 무너진다.

## 🔴 아래 가장자리는 **좌우와 잣대가 다르다 — 마지막 한 행, 0 이 아니면 red**

`check.mjs` 를 보면 두 검사가 전혀 다르게 잰다(`check.mjs:499-520`):
- **좌우** = 바깥 **2열 띠**에 잉크가 3px 이상인 프레임이 **전체의 25% 넘을 때만** red.
  쓸고 지나가는 연출을 살려 주려고 「몇 프레임이나 서 있었나」를 센다.
- **아래** = **마지막 한 행(`y = H−1`)** 에 알파 > 10 인 픽셀 수의 **최댓값이 0 보다 크면** red.
  프레임 비율도 유예도 없다. **한 프레임만 스쳐도 걸린다.**

**Why:** ep12s-2 가 `S1 18px` 로 반려됐는데 **원인이 계기·글자가 아니라 배경 파티클**이었다.
「하늘에서 계속 내려오는 표식」을 `py = (t·sp + …) % (h + 44) − 22` 로 돌려 캔버스 아래로
흘려보냈고, 폭 3px 짜리 여섯 개가 마지막 행에 걸쳐 18px 이 됐다. 계기 바닥은 y 268 로
캔버스 307 에서 39px 이나 남아 있었다 — **검수도 「세로 계기가 밖으로 나간다」고 잘못 짚었다.**

**How to apply:**
- **세로로 흐르는 배경은 `h` 로 나머지연산하지 마라.** `FALL_END = h − 40` 처럼 **끝을 따로
  잡고**, 마지막 40~46px 에서 알파를 0 으로 뺀다(툭 꺼지면 그것대로 눈에 띈다).
  위쪽은 음수에서 들어와도 된다 — 아래 행만 본다.
- 반려 보고가 지목한 요소를 믿지 말고 **직접 최하단 y 를 전 kind 에서 세라.** 계산은 싸다.
  (ep12s-2: knobs 296 · costgap 274 · pairline 296 — 게이트가 S1 만 잡은 것과 일치했다.)
- 🔑 이 수정은 **좌표 한 곳만 만지므로 다른 샷과의 관계를 안 깬다.** 「S3 은 S1 의 선을
  눕힌 것」 같은 회차 내 대응은 **그 대응이 쓰는 축**(가로 한계선 x)이 안 변했는지만 확인하면
  된다 — 만진 축(세로 배경)이 다르면 영향 0 이다.

### 🔴 보고된 숫자는 **넘어간 거리가 아니라 픽셀 개수**다 (ep12s-3, 2026-08-08)

`S2 870px` 을 보고 「샷 높이 307 의 2.8배라 좌표 단위를 잘못 잡았다」고 읽으면 안 된다.
그 수는 **마지막 행에서 알파 > 10 인 픽셀의 개수**이고 **device px** 다(`check.mjs:500-502`).
870 = 폭 **288 CSS px × dpr 3.02** — 즉 「288px 짜리 띠 하나가 바닥에 얹혀 있다」는 뜻이다.
🔑 **역산하면 범인이 바로 나온다: `보고값 ÷ dpr` = 그 요소의 CSS 폭.** 288 로 grep 하면
`w − 64` 를 쓰는 빗금 띠 하나뿐이었다.

### 🔴 정지 좌표만 검산하면 놓친다 — **움직이는 요소는 「가장 밖으로 나가는 순간」으로 잰다**

**Why:** ep12s-3 의 `hunt` 는 아래 패널이 밑에서 밀려 올라오는 연출이라
`top = 198 + lerp(22, 0, rise)` 였다. **쉬는 자리는 292 라 307 안**이었고 나는 그 수를
검산해 노트에 「캔버스 안이다」라고 적었다. 그런데 **등장 첫 프레임의 top 은 220 이라
바닥이 314** 였고, 패널 바닥의 빗금 띠가 통째로 마지막 행에 얹혔다.
좌우 검사와 달리 **아래는 한 프레임만 스쳐도 red** 라 슬라이드 인/아웃이 그대로 잡힌다.

**How to apply:**
- 좌표를 흔드는 값(`oy` 슬라이드 · `jolt` 진동 · `sink` 붕괴 · spring 오버슈트 1.05)이 있으면
  **그 최댓값을 넣은 수를 주석에 적어라.** 「쉬는 자리 292 < 307」은 검산이 아니다.
- 층을 상수로 뽑아 두면 재계산이 싸다(`P2_Y` · `P2_H` · `P2_SLIDE`). ep12s-3 은 슬라이드를
  22 → 14 로 줄이고 층을 6~18px 위로 올려 **최악의 순간에도 바닥 294**(여유 13px)로 맞췄다.
- 🔴 **잘라서 맞추지 말고 층을 다시 재라**(코디네이터 지시). 요소를 지우면 `reads` 가 무너진다.
- 사고가 하나 나면 **나머지 kind 도 최악값으로 다시 세라.** 같은 회차의 다른 셋은 통과했지만
  검산해 두면 다음 수정에서 안 흔들린다.

### 🔴 「밖에서 밀려 들어온다 / 밖으로 밀려 나간다」는 이 캔버스(352px)에서 거의 항상 가장자리를 문다

**등장·퇴장 모션을 `translate` 로 짜면 그 순간 알파가 남은 채 화면 끝에 걸린다.**
폭 172px 짜리 카드를 오른쪽 밖에서 슬라이드해 들여오면 등장 첫 프레임에 오른쪽 2열 띠가
잉크로 찬다. 퇴장도 같다 — `off = (1 − a) × w × 0.30` 처럼 알파와 이동을 함께 주면
알파가 0.3 쯤일 때 이미 카드 오른쪽 끝이 캔버스 밖이다.

**대체 동작 둘 — 뜻을 안 잃고 좌표만 안전해진다:**
- **등장 = 폭이 자란다.** 도착할 쪽 모서리를 **붙박아 두고**(`right = CX + W/2` 고정)
  `bw = lerp(28, W, k)` 로 자라게 한다. 「오른쪽에서 밀려 들어와 자리를 채운다」로 그대로 읽힌다.
- **퇴장 = 제자리에서 줄어든다.** `scale(0.86 + 0.14·a)` 를 자기 중심에 걸고 알파를 뺀다.
  이동이 0 이라 어느 프레임에서도 밖으로 안 나간다.

🔑 세로 슬라이드는 **아래 검사가 한 프레임만 스쳐도 red** 라 더 위험하다(위 절). 가로는
25% 유예가 있어 눈에 안 띄고 지나가기도 하는데, 그건 통과가 아니라 **아직 안 걸린 것**이다.
🔑 이 대체 동작은 `spring()` 오버슈트(1.05)와도 잘 맞는다 — 기준 크기를 0.95 로 잡아 두면
최대치가 원래 폭이 된다(`lib.js:86`).

### 🔴 겹침은 좌표가 아니라 **구조**로 막아라 — 두 라벨이 수렴할 수 있으면 언젠가 겹친다

**Why:** lf02 `costfloor` 는 `MIN COST n` 을 기준선 위(`fy−7`)에, `GATE` 를 게이트선 위
(`gateY−8`)에 뒀다. 두 좌표는 **다른 값에서 계산되지만 phase 1 의 종점에서 `cur = 8` 이라
`fy == gateY` 가 된다.** 즉 「가끔 겹친다」가 아니라 **정의상 반드시 겹치는** 설계였고,
페이오프 샷이 통째로 판독 불가가 됐다(`MG̶ATE̶N C̶OST 8 8`). 좌표를 조금 밀어 고치면
다음 애니메이션 값에서 또 만난다.

**How to apply:**
- 두 라벨이 **서로 다른 동적 값**에 붙어 있으면 먼저 **부등식을 세워라**(여기서는 비용이
  클수록 y 가 작으므로 `gateY <= fy` 가 항상 참). 그다음 하나는 자기 선 **위**, 하나는
  자기 선 **아래**로 보내면 간격이 `(fy − gateY) + 상수 >= 상수` 로 **하한이 보장**된다.
- 부등식을 못 세우면 **둘을 한 문자열로 합쳐라**(`GATE · MIN COST 8`). 두 개를 유지한 채
  좌표로 피하는 것이 가장 나쁘다.
- 같은 종류: 라벨과 화살표/▼ 가 **같은 오프셋 띠를 나눠 쓰도록** 설계된 경우
  (`handraise`: 라벨 `oy−12`, ▼ `oy−6 ~ oy−18`). 둘 중 하나를 **다른 영역**(칸 안)으로
  옮겨야지 같은 띠 안에서 밀면 안 된다.

### 🔑 방사형 배치에서는 **라벨 통로를 각도로 비운다** (ep14s-4, 08-10)

가운데 하나 + 둘레에 여럿을 놓는 판에서는 라벨 자리가 없다 — 어디에 두든 애니메이션 값에
따라 표식이 그 자리로 들어온다(표식이 안팎으로 움직이므로 「지금은 안 겹친다」가 근거가 못 된다).
**좌표를 미는 대신 자리 각도를 다시 잡아 통로를 만들어라**: 여섯 자리를 전부 90°(바로 아래)에서
±35° 밖으로 배치하면, 아래로 뻗는 세로 띠에는 **어떤 반지름에서도** 표식이 안 들어온다
(각도 θ 의 표식은 x = CX + r·cosθ 이고 |cosθ| 가 하한을 가지므로 상자 가장자리가 통로에 못 닿는다).
🔑 부등식이 반지름과 무관하게 성립하는 것이 요점이다 — 위 「부등식을 세워라」의 방사형 판 버전.
같은 판에서 곁딸린 글립(개인 화덕 등)은 **반지름 방향 오프셋**으로 갈라라. 오프셋 d 는
`d·|cosθ|` 또는 `d·|sinθ|` 중 **하나만** 두 상자의 폭 합을 넘으면 된다(축 정렬 상자라 OR 이다).

### 🔴 wide(롱폼) 무대에서 캔버스 위쪽은 **엔진 HUD 가 실제로 덮는다**

`format:"wide"` 캔버스는 약 **649 × 246 CSS px** 이고 1 CSS px = **2.755** 화면 px 다
(스틸에서 역산: 캔버스 원점 ≈ 화면 (66, 172~178)). 그런데 엔진 HUD 는 별도 레이어라
**캔버스 위쪽 띠를 그대로 가린다** — 실측(lf02 스틸):

| HUD 요소 | 캔버스 좌표로 환산 |
|---|---|
| 진행 막대 | y **13~17** · x **328~591** |
| 챕터 칩 | y **1~21** · x **600~649** |

즉 「우상단만 피하면 된다」가 아니다. **x 328 부터 오른쪽은 y 20 위쪽이 전부 위험하다.**
lf02 는 이걸 몰라서 `mechanisms` 카운터를 칩 아래로 넣었고(2차 반려), 3차에서
`handraise` 라벨을 위로 올리려다 진행 막대에 부딪힐 뻔했다 — **위가 막혀 있으면
라벨을 올리지 말고 겹치는 쪽(표식)을 다른 영역으로 옮긴다.**
