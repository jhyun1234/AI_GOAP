클립 샷(`shot.clip = { id, in, out }`)의 여유는 **`out − in ≥ 샷 길이 + 0.2`** 로 잰다.
그리고 **샷 길이 = 자막 `dur + pause` 합 + `SHOT_TAIL`(0.35)** 이다 — 엔진이 샷마다 붙이는
0.35초 여운이 클램프 계산에 그대로 들어간다. **발화 합만으로 재면 매번 0.35초씩 낙관한다.**

**Why:** lf02 가 같은 자리를 세 번 다른 잣대로 쟀다.
①2차 = 산정(÷6.7)으로 재서 다섯 샷 전부 창을 넘겼고 ②6차 = 실측 **발화 합**으로 재서
S25 하나만 초과로 봤는데 ③렌더 후 엔진 클램프 기준으로 다시 재니 값이 이렇게 갈렸다:

| 샷 | 창 | 발화 합 기준 | **엔진 클램프 기준** |
|---|---:|---:|---:|
| **S1** | 7.0 | +0.39 | **+0.041초 (1.2프레임)** |
| S4 | 13.0 | +1.15 | +0.80 |
| S12 | 7.0 | +0.92 | +0.57 |
| S17 | 7.0 | +0.64 | +0.288 |
| S25 | 7.0 | −0.22 | +0.43 (자막 축소 후) |

**S1 은 자막을 한 글자만 늘려도 마지막 프레임이 언다.** 그 정지는 `check.mjs` 의
정적 구간 검사에 그대로 잡힌다.

**How to apply:**
- 🔴 **7초 규격 클립을 쓰면 처음부터 자막 예산을 `창 − 0.35 − 0.2 = 6.45초`로 잡아라.**
  나중에 깎는 것보다 처음부터 짧게 쓰는 편이 싸다.
- 자막을 줄여야 하면 **화면이 보증하지 않는 것부터** 깎는다 — lf02 S25 는
  「하면서 걷습니다」를 뺐는데, 스틸이 보증한 것은 「말풍선을 띄운 채 **서 있다**」였다.
  길이 문제를 고치면서 사실 정확도가 함께 올라가는 지점이 대개 있다.
  → [[feedback-frame-summary-scope]]
- **창을 늘리는 쪽은 먼저 프레임을 열어 봐라.** lf02 S25 는 18초본으로 재슬라이스해도
  7.4초 지점이 이미 `Day 28` 이라 **첫 자막의 「27일째」를 화면이 반박**했다.
  재슬라이스가 항상 답이 아니다.
- 🔑 롱폼 총 길이는 **산정 ≈ 실측의 82%** 다(lf01 ×1.219 · lf02 ×1.223, 두 편 재현).
  목표 300~600초면 **산정 400~490초**를 겨냥한다.
