## 🔴 원문이 자란다 — 「사건 커밋 범위」 뒤쪽 로그를 반드시 한 번 더 읽어라

**Why:** `d01s-1`(2026-08-11 · dNNs 파일럿 1호) 실측. 사건 범위는 `af9f4dab`(00:36) →
`2351ad9e`(14:38)인데, **같은 파일 15:03 커밋**(`chore(goap): 주민 시야 10 -> 7`)이 파생 반경
셋을 갈아 놓았다 — **시야 10→7 · 부화 15→10 · 회수 20→14.**
- 내 편은 브리프의 「해결부 수치는 붕괴 지점」 경고를 따라 반경을 통째로 버려서 무사했고,
  검수가 「구조적으로 면역」으로 확인했다.
- 그런데 기획 브리프가 형제 `d01s-2` 에 배정한 핵심 수치가 하필 **「10 < 15 < 20−5」** 였다.
- 게이트 총계도 로그 안에서 **474 → 476 → 477 → 478 → 479** 로 네 번 자란다. 「477개」는
  **그 시점 값**이므로 인용할 때 문장에 **「그 시점에」를 박아야** 현재 총계와 안 섞인다
  (검수가 이 처리를 명시적으로 통과시켰다).

🔑 **연속극(블로그 원문)에는 없던 위험이다.** 발행된 글은 얼지만 **세션 로그는 그날 하루에도
계속 append 된다.** ADR-D-1 이 「원문 = 세션 로그 산문」이라고 정한 순간 「원문이 자란다」가
이 트랙의 기본 조건이 됐다.

**How to apply:**
- 수치를 화면에 올리기 전에 **그 수치 이름으로 원문 파일 전체를 grep** 하라(`부화`·`회수`·
  `게이트`). 사건 범위 뒤쪽에 같은 이름이 또 나오면 그게 신호다.
- 바뀐 게 있으면 ①수치를 안 올리거나 ②「그 시점에」를 문장에 박는다. 어느 시점 값을 쓸지는
  **사람이 정할 일**이므로 `notes` 와 최종 응답에 보고한다.
- 🔴 **형제 편에게도 알려라.** 내가 안 쓰는 수라도 형제가 배정받았을 수 있다.

## 🔴 dNNs 의 `outro.source` 는 **날짜**다 — 밀스톤/작업 번호를 걸지 마라

`d01s-1` 1차본이 `outro.source` 를 **「M26-2차 W5R · 상주는 예약이다 (2026-08-11 세션 로그)」**
로 적었다가 **반려**됐다. 이유가 둘이다:
1. **「M26-2차 W5R」은 `ADR-V-10` 의 세 예외 어디에도 안 든다** — 코드·로그 인용도, 기호·단위도,
   고유 기술명도 아닌 **내부 작업 번호**다. 연속극 선례(`ep16s-*` 「M13 사건과 흔적」)는
   **밀스톤 이름까지**였고 차수·주차 번호는 그 선례 밖이다.
2. **「상주」가 내 낱말 배정표에서 ③버리기였는데 카드에 그대로 떠 있었다** — 자기모순.

→ 정답은 **`"2026-08-11 개발 로그"`**(형제 `d01s-2` 가 이미 쓰던 형식). **dNNs 는 밀스톤을 걸
자리가 아니라 날짜가 곧 소재의 이름이다.**

🔴 **그리고 진짜 병은 「전수」가 캔버스 밖을 안 본 것이다.** 낱말 배정표를 자막·캔버스만
훑고 썼는데 `engine/engine.js:306` 이 `outro.source` 를 **카드에 훅 다음으로 큰 글자로** 찍는다.
같은 실패가 `ep15s-5` 의 `shot.chapter` HUD 칩에서 이미 한 번 났다.
→ **캔버스 밖 여섯 층을 표로 적어라**: `hud.title` · `hud.outro` · `scene.hook` ·
`outro.source`+`part` · `outro.next` · `hud.aiHook`. **층은 기억하지 말고 `engine.js` 의
`textContent` 대입을 grep 해서 뽑아라.**
