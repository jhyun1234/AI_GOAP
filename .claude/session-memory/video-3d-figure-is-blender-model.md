**Why:** 이 프로젝트는 「밋밋하다」에 카메라·컷·이펙트를 만지다 여덟 판을 돌린 전례가 있다.
같은 일이 3D 전환에서도 한 번 더 반복됐다. 판정이 나쁘면 **연출을 고치기 전에 피사체를 의심하라.**

**How to apply:**
- 코드는 C(worktree, 브랜치 `exp/palette4`), 산출물은 `D:\AI_GOAP-videos\3d\`.
  D 의 `episodes/` 는 리포 build 의 사본이라 지웠다.
- 블렌더 스크립트는 `tools/scene-video/blender3d/`. **고치기 전에 그 폴더의 `README.md`**
  (밟은 함정 목록과 왜 그 값인지)를 읽어라. 상수는 전부 픽셀을 재서 맞춘 값이다.
- 🔴 **소품을 다시 만들지 마라.** 집·나무·우물·밭·모닥불은 `village.py` 의 함수이고
  좌표만 주면 어디서나 다시 선다. **`blender3d/PROPS.md`** 가 어휘집이다 —
  「무엇이 그것처럼 보이게 하는가」를 판정 네 판으로 뽑아 규칙 여섯으로 적어 뒀다.
  새 소품은 `render_prop_look.py` 로 **주민 옆에 세워** 판정한다(축척이 늘 문제였다).
- 검사는 `python test_*.py` 로 돈다(pytest 안 깐다). **여덟 파일 88종.**
  🔴 회차 무관 파일(`motions`·`village`·`instrument`·`stage`·`palette`)을 고쳤으면 반드시 돌려라.
- 🔴 **동작을 고칠 자리는 `blender3d/motions.py` 하나다** — 여섯 샷이 전부 거기를 지난다.
  걷기·뛰기의 **다리는 각이 아니라 발 자리로 적혀 있다**(2본 IK · [[video-motion-vocabulary]]).
  거기서 `thigh`/`shin` 을 손으로 적으려 들지 마라 — 발이 다시 미끄러진다.
  애니메이션 원칙 넷(예비·빠릿·겹침·곡선)이 손잡이 여덟 개로 파일 맨 위에 모여 있다.
  「굼뜨다」면 `SNAP_P`·`OVER`·`ANTIC` 셋만 올려라.
- 🔴 **로우폴리로 줄여도 안 빨라진다**(실측: 면 75% 감소 → 오히려 느림). 손잡이는 샘플 수다.
- 🔴 뼈 축: **X 앞뒤 · Z 좌우 · Y 비틀림.** 부호는 **뼈가 향한 쪽에 따라 뒤집힌다** —
  아래 뼈(팔·다리)는 X 음수가 앞, 위 뼈(척추·목·머리)는 X 양수가 위. 이걸 놓쳐서
  `look_up` 이 고개를 숙이고 있었고, 검사 11종이 다 통과했는데 사람 눈이 잡았다.
- 🔴 새 모델이 필요하면 TRELLIS(이미지→GLB, **하루 1회**)뿐이다. 지금은 안 쓴다.
  소품은 블렌더 파이썬으로 만든다. 늑대는 게임에서 사라진 종족이라 화면에 안 만든다.
- 쇼츠 길이: **총 63초 이하(60±3) · 권장 31~63 · 본문 18~50**(2026-08-13 개정).
  🔴 **설명을 깎아 짧추지 마라** — 목표는 처음 보는 사람이 영상만으로 이해하는 것이고
  **자막은 그림의 중복이 아니라 입장권**이다([[video-line-by-line-contract]]).
