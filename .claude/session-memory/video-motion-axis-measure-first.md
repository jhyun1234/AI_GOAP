2026-08-13, 동작 어휘를 늘리며 **부호·각도를 추론으로 정하다 네 번 틀렸다.** 매번 실측이 잡았다.

**실측 대응표 (주민 키 0.95 · `upperarm.R` 만 돌려 손 위치를 잼)**

| upperarm X | 손 z | 손 x(정면 −X) | 뜻 |
|---|---|---|---|
| −150° | **0.785** | −0.125 | 가장 높다(머리 옆이 한계) |
| −120° | 0.696 | −0.217 | 앞 위 대각선 |
| −96° | 0.600 | **−0.249** | 가장 앞(어깨 높이) |
| 0° | 0.330 | 0 | 차렷 |

🔴 **X 가 작을수록 높다.** 그리고 **R 팔은 Z 양수가 바깥**(음수면 몸을 가로지른다).
🔴 `hips.location` 로컬 X → 월드 +Y 인데 rig.py 가 **L 을 +Y** 에 두므로 그쪽이 **왼쪽**이다.

**출고된 버그 — `chop` 위상이 뒤집혀 있었다**
`up`(들린 정도)은 맞게 쓰였는데 팔 매핑이 `R(-150)+R(140)*up` 이라 up=1 에서 X −10 = **가장 낮은**
자리였다. 그래서 도끼가 **빨리 올라가고 느리게 떨어졌다** — 「들기」로 적힌 구간이 실제 타격이었고
거기서 감속했다. `unison.BREAK` 로 body3 에 나가고 있었다. `ROOT` 하강은 처음부터 맞게 적혀 있었다.
🔴 **검사가 버그를 지켜 주고 있었다** — `test_chop_overshoots_...` 가 뒤집힌 전제로 쓰여 부등호가
반대였다. 코드와 검사를 같은 오해로 쓰면 검사는 오해를 고정한다.

**Why:** 이 파이프라인은 각도 하나가 「머리 긁는 자세」·「가드 자세」로 읽히게 만든다.
그리고 **판정 각도 자체가 착시를 만든다** — 3/4 정면은 앞으로 뻗는 팔을 단축시키고,
옆모습을 반대쪽(170°)으로 잡으면 일하는 오른팔이 몸통에 가린다.

**How to apply:**
- 🔴 뼈 각도를 정하기 전에 **블렌더에서 재라.** MCP 로 붙은 창에서 관절 하나만 돌려 손 위치를
  찍어 보는 데 1분이면 된다. 추론으로 고치면 「고쳤는데 더 나빠졌다」가 나온다(실제로 두 번).
- 🔴 컨택트 시트는 **각도 둘**이다(3/4 정면 + **오른쪽 −10°**). 한 각도로 판정하지 마라.
- 🔴 타격 동작은 시트에서 **타격 순간**을 잡아라. 엉뚱한 순간을 잡으면 도구가 가려 안 보인다.
- 동작 이름은 게임이 정본이다 — `motions.ANIM_KIND` 가 `AnimKind` 다섯과 대조한다.
- 도구·소품 규칙은 `blender3d/PROPS.md` 「도구 넷」·「대상이 있어야 읽힌다」 절.
