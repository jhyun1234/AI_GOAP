# 실행명세서 구현 절차

## 1단계 — 코드를 열기 전에
1. 명세서의 ADR/아키텍처 결정 절을 전부 읽는다. 구현 중 판단이 갈리면 여기 답이 있다.
2. 담당 항목(예: W5)의 ⚠️ 오해 위험 절을 읽는다. 여기 적힌 실수를 하지 않는 것이 최우선이다.
3. 항목의 "대상 파일"을 열어 코드 스케치와 실제 코드의 차이(이름, 시그니처)를 확인한다.
   스케치의 프로퍼티명이 실제와 다르면 실제 코드를 따르고, 그 사실을 커밋 메시지에 남긴다.

## 2단계 — 구현 중
- 스케치는 뼈대다. 그대로 복붙하지 말고 프로젝트의 기존 스타일(한글 주석, 상수 명명, region)에 맞춘다.
- 수치가 필요한데 명세가 "실제 값을 찾아 쓸 것"이라 하면: grep으로 런타임 원본을 찾는다.
  못 찾으면 임의 값을 넣지 말고 TODO 주석 + 질문으로 남긴다.
- 명세에 없는 개선이 떠오르면: 구현하지 않는다. 커밋 메시지나 이슈에 제안으로만 남긴다.

## 3단계 — 완료 판정
- 항목의 DoD 체크리스트(`- [ ]`)를 하나씩 직접 수행한다.
  수행 완료 항목은 `- [x]`로 표시한다. **읽고 넘기는 것은 수행이 아니다.**
- CLAUDE.md의 커밋 전 체크 4종을 실행한다.
- 전부 `- [x]` → 커밋 (형식: `feat(goap): <항목번호> <요약>`, 이슈 연동 시 `Fixes #N`).
- 하나라도 미완 → 커밋하지 않고 미완 항목을 명시해 보고한다. "거의 됐다"는 없다.

## 보고 형식
[항목번호] 상태(완료/부분/차단) / DoD 체크 결과 / 명세와 달리한 것과 사유 / 발견한 문제
+ 이번 변경이 게임에서 어떻게 보이는지 비개발자용 한 문단 (CLAUDE.md 설명 의무)
