# 실행명세서 작성 규칙 (1차 구현 100%를 위한 형식)

모든 작업 항목은 아래 5요소를 빠짐없이 갖춘다. 하나라도 빠지면 미완성 명세다:

1. **대상 파일 경로** — "어디"가 없는 지시는 지시가 아니다.
2. **코드 스케치** — 시그니처와 핵심 로직. 프로젝트 스타일(한글 주석) 준수.
3. **DoD 체크리스트** — 반드시 `- [ ]` 형식. 테스트 가능한 문장만.
   "잘 동작" 금지. "X 상태에서 Y 플랜 산출", "Console에 Z 로그 출력" 형식 사용.
4. **⚠️ 오해 위험** — 이 지시를 잘못 해석하는 가장 그럴듯한 방식을 미리 적고 차단한다.
5. **작업량/심각도/의존 관계** — 커밋 순서를 결정할 수 있게.

문서 전체 요구사항:
- 서두에 측정 가능한 성공 기준 (숫자로).
- ADR 절 — 구현 중 갈릴 판단을 미리 결정. "바꾸려면 사유를 커밋에" 명시.
- 커밋 분할 계획 — 1항목 1커밋, 각 커밋 단독 실행 가능.
- 스코프 가드 절 — "이번에 하지 않는 것" 목록.
- 큰 데이터 마이그레이션이 있으면 중간 리뷰 시점을 명시.
- 수치는 발명하지 않는다: 기존 값의 위치를 지목하거나, 제안치임을 명시하고 "기존 값 우선" 원칙을 병기.
- **재미 검증 절** — 이 작업이 완료되면 플레이어가 화면에서 무엇을 새로 보게 되는가를 한 문단으로.
  답할 수 없다면 그 작업의 우선순위를 다시 질문한다.
