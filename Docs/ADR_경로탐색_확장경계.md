# ADR — 경로탐색 확장 경계 (Pathfinding Scaling Boundary)

- **작성일**: 2026-07-18
- **상태**: 채택 (Accepted) — 경계 코드 반영 완료, 알고리즘 교체는 미래 트리거 시
- **관련 코드**: `Assets/Scripts/Core/IPathfinder.cs`, `SimulationLoop.Pathfinder`, `VillagerAgent.TryRetargetWhileMoving`, `IActionRunner.GetTrackTarget`, `MapBounds.NearestWalkable`

> **🚨 다른 세션은 이 문서를 먼저 읽을 것.** 맵/지형/AI 수를 확장하기 전에 여기 명시된 경계와 교체 절차를 반드시 확인한다. 이 경계를 모르고 `bool[,] Walkable`이나 `JPSPathfinder`를 호출부에 직접 물리면, 게임 후반(수백×수백 맵·수십 AI·가중치 지형)에 산탄총 수정(shotgun surgery)이 필요해지고 개발이 터진다. 그것을 막기 위한 문서다.

---

## 1. 배경 — 왜 이 경계가 필요한가

게임 후반 로드맵상 확정된 확장 3축:

| 확장 축 | 지금 | 후반 목표 |
|---|---|---|
| 맵 크기 | 100×100 | 수백×수백 |
| 지형지물 | 통과/차단 이분법 (산·호수 = 차단 칸) | + **이동 비용 가중치**(늪=느림 등) 가능성 |
| 동시 AI | 4명 | 10배 이상 (40명+) |

**핵심 진단(오해 방지):** 이 세 압력은 성질이 다르며, "지금 JPS를 갈아치우자"로 직결되지 않는다.

- **맵 크기**: JPS가 오히려 잘 버티는 영역. 커질수록 상대 이득이 커진다. 교체 사유 아님.
- **통과/차단 지형**: 차단 칸은 JPS 정상 입력. 문제 없음.
- **가중치 지형**: 여기서만 JPS가 깨진다. JPS는 "모든 칸 비용 균일" 대칭성을 전제로 점프 가지치기를 하므로, 가변 비용이 들어오면 바닐라 JPS는 못 쓴다. → **A\***로 교체 필요.
- **동시 AI 40명**: 병목은 단일 쿼리 속도가 아니라 **프레임당 쿼리 횟수**. 해법은 알고리즘 교체가 아니라 **쿼리 스케줄링 + 이벤트 기반 리패스**.

**중요 사실:** JPS와 HPA\*(계층 경로)는 대립이 아니다. HPA\*의 클러스터 내부 solver로 JPS를 그대로 재사용하는 것이 표준. 후반 그림은 "JPS 버리기"가 아니라 "**JPS 위에 HPA\* 얹기**"일 가능성이 높다. Flow Field는 다수가 같은 목적지로 몰릴 때만 이득이라 개별 목표(보고·채집)를 가진 이 게임엔 부적합. D\* Lite는 걷는 중 지형이 실시간으로 바뀔 때만 필요(정적 지형엔 과잉).

**결론:** 지금 JPS를 교체하지 않는다(투기적·검증 시스템 회귀 위험). 대신 **교체가 싸지는 경계선**을 지금 심는다.

## 2. 채택한 경계 (지금 코드에 반영됨)

### 경계 1 — `IPathfinder` 창구 (알고리즘 교체 흡수)

```
Assets/Scripts/Core/IPathfinder.cs
  interface IPathfinder { PathResult FindPath(int sx, int sy, int gx, int gy); }
  sealed class JpsPathfinder : IPathfinder   // 오늘의 유일 구현 — JPS 위임
```

- 호출부(`VillagerAgent`)는 `_sim.Pathfinder.FindPath(...)`만 호출한다. `JPSPathfinder` 정적 클래스나 `bool[,] Walkable`을 **직접 참조하지 않는다**.
- `FindPath`는 타일 좌표만 받는다 — 지형 표현(bool이든 가중치든)은 구현 뒤에 숨는다.
- `JPSPathfinder.cs`는 **동결 검증 라이브러리(수정 금지)**. 어댑터가 위임만 한다.

### 경계 2 — 통행 질문의 단일 지점 (가중치 지형 흡수)

- 통행 여부는 `VillagerAgent.IsWalkable(x,y)` **한 메서드**로만 물어본다(러너의 목표 타일 필터).
- 가중치가 오면 이 한 줄을 `EnterCost(x,y) < ∞`로 바꾼다. **호출부 산탄총 수정 없음.**

### (철회) 경계 3 — 이벤트 기반 리패스

> **2026-07-18 철회.** 애초 M8 "새 집 알리러 가는데 상대가 이동 → 헛걸음" 버그를 걷는 중 재조준(`GetTrackTarget`/`TryRetargetWhileMoving`/`NearestWalkable`)으로 풀려 했으나, **동속 추격은 알고리즘으로 수렴하지 않음**(같은 속도로 이동 중인 대상을 쫓으면 간격이 안 좁혀짐)이 Play로 확인됨. 근본 해법은 "쫓아가기"를 버리고 **"보상 빚 + 마주치면 정산"**(조각 Y)으로 전환한 것 — `RequestService.TickRewardSettlement`. 따라서 재조준 코드는 전부 되돌렸다. 스케일 대비 경계는 아래 경계 1·2로 충분하다.
> → 조각 Y 상세: `Docs/퀘스트보드_및_보고심부름정리_후속.md`, `project_reward_settlement` 메모리.

## 3. 미래 트리거별 교체 절차 (이때 무엇을 하나)

### 트리거 A — 지형에 이동 비용 가중치 도입
1. `bool[,] Walkable`을 비용 표현으로 성장시킨다(내부 저장은 그때 float로, 차단=∞). **인터페이스 저장 포맷은 명세될 때 바꾼다** — 지금 선제 변경 금지(불필요 복잡화).
2. `IPathfinder` 구현체로 **`AStarPathfinder`** 추가(가중치 네이티브). `JpsPathfinder`는 균일 비용 구역용으로 병존 가능.
3. `VillagerAgent.IsWalkable`을 `EnterCost < ∞`로 교체(한 줄).
4. `SimulationLoop`의 `Pathfinder = new JpsPathfinder(...)` → `new AStarPathfinder(...)` (한 줄).
5. **호출부·`FindPath` 시그니처 무수정.**

### 트리거 B — 맵 대형화 + 동시 AI 수십
1. `IPathfinder` 뒤에 **HPA\*** 계층 추가. 클러스터 내부 solver = JPS(또는 A\*) 재사용.
2. **쿼리 예산 스케줄러** 도입: 프레임당 리패스 N개 상한 + 대기열(스파이크 제거). 알고리즘과 무관.
3. 이동 목표가 움직이는 액션이 다시 생기면(추격형) 이벤트 기반 리패스를 그때 재도입 — 단 동속 추격은 수렴하지 않으니 대상 협조나 정산형(조각 Y) 설계를 우선 검토.

### 트리거 C — 개체별 통행 차등 (2026-08-08 개정 — M22 문(門)에서 실수요 발생)

> **개정 사유**: M22가 "주민만 통과하는 문"을 1차 범위로 승격하며, 원안의 두 시나리오(가중치·HPA\*)에
> 없던 세 번째 압력 — **"누가 묻는가"에 따라 답이 갈리는 통행** — 이 실수요가 됐다.
> 원안 경계의 정신(배열 = 지형 표현, 시그니처 불변)은 그대로 유지된다.

1. 통행 배열을 **개체 부류당 1벌**로 늘린다 (`Walkable` 주민 + `ThreatWalkable` 위협, ADR-M22-1).
2. `JpsPathfinder` **인스턴스를 부류당 1개** 만들어 각자의 배열을 물린다 — "누가 묻는가"는
   시그니처가 아니라 **인스턴스 선택**이 흡수한다. `IPathfinder.FindPath` 4-int 계약 무수정.
3. 차등 규칙은 순수 함수 한 쌍(`M0SimulationLoop.BlocksVillagerPassage`/`BlocksThreatPassage`)이
   단일 소유한다 — 호출부에 개체별 예외 분기를 만들면 경계 2 위반.
4. ⚠️ 세 번째 부류(타 종족 등)가 필요해지면 배열 복제가 아니라 이 절의 재설계를 먼저 질문한다 —
   부류 수 × 맵 크기만큼 메모리·갱신 지점이 늘기 때문이다.

### 판단 규칙
- 알고리즘 최종 선택은 **지형 모델 확정 + 실제 동시 AI 수 + 프로파일링 병목 실측** 후에 한다. 요구를 모른 채 알고리즘부터 고르지 않는다.
- 유력 후보: "JPS 버리기"가 아니라 "**JPS/A\* 위 HPA\***".

## 4. 하지 않은 것 (의도적)

- **가중치 비용 구조체·인터페이스를 지금 만들지 않았다.** 소비처가 없는 죽은 코드 = 선제 복잡화 = "복잡해지지 않고 넓혀지는 개발" 원칙 위반. 통행 질문(`IsWalkable`)과 `IPathfinder`가 이미 단일 seam이라, 가중치는 그때 이 두 지점만 성장시키면 된다.
- **JPS 내부를 건드리지 않았다.** 동결 검증 라이브러리. 교체는 경계 뒤 구현 교체이지 JPS 수정이 아니다.
