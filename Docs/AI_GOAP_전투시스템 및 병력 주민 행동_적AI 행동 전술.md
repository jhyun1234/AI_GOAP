# 프로젝트 개요
**목표**  
- 플레이어 기지 방어 중심의 생존 전략 게임 구현  
- 적 AI는 **정찰 → 소규모 교전 → 점진적 확장 → 대규모 전투**로 발전  
- 적은 플레이어 행동에 따라 **동적으로 전술을 선택**하고, 플레이어는 패배를 통해 대응법을 학습  
- 주민과 병력은 역할을 분리하여 **자율 전투 + 주민 긴급 대응** 구조로 설계  
- **정신 상태 시스템**을 통해 전투와 생존 루프에 심리적 영향을 부여

**핵심 설계 철학**  
- **모듈화**: 병력 AI, 주민 AI, 전술 시스템, 정신 상태, 침입 스케줄러를 독립 모듈로 설계  
- **점진적 확장**: 간단한 기능부터 시작해 전술·학습·대규모 전투로 확장  
- **하이브리드 AI**: 장기 목표는 GOAP, 긴급 반응은 Behavior Tree(또는 ThinkTree)로 보완

# AI 아키텍처
## 주요 구성 요소
- **병력 AI (전담 전투 유닛)**  
  - **역할**: 전투 전담, 집단 전술 수행, 자율적 목표 달성  
  - **설계**: GOAP 기반으로 장기 목표(방어, 집결, 반격) 계획  
  - **긴급 반응**: Behavior Tree로 폭발 회피, 패닉 등 즉시 반응 처리  
  - **정신 상태**: 사기(Morale), 공포, 분노 등 전투 성능에 직접 영향

- **주민 AI (비전투/생활 유닛)**  
  - **역할**: 자원 채집, 생산, 건설, 생활 관리  
  - **전투 참여**: 기본적으로 비전투, **긴급 상황에서 임시 전투 태세** 또는 은신/대피  
  - **정신 상태**: 스트레스, 우울증 등 생활 성능에 영향

- **집단 제어 시스템 (Lord 시스템 유사)**  
  - **역할**: 집단 이벤트(집결, 포위, 의식 등) 관리  
  - **기능**: 병력의 집단 전술과 주민의 집단 회피/대피 조율

- **정신 상태 시스템**  
  - **역할**: 상황·스트레스·전투 결과에 따라 상태 전환  
  - **예시 상태**: Normal, Fear, Panic, Rage, Depressed  
  - **효과**: 행동 우선순위 변경, 행동 실패 확률, 사기 변화 등

- **전술 시스템**  
  - **역할**: 적 AI가 사용할 전술을 보유하고 조건에 따라 선택  
  - **권장 방식**: 미리 정의된 전술 풀에서 조건 기반 선택  
  - **전술 예시**: 정찰, 기습, 포위, 약탈, 내부 침투, 함정 무력화

- **침입 스케줄러 (Wave Manager)**  
  - **역할**: N일 주기 기반 침입 트리거, **플레이어 상태에 따른 동적 변동**  
  - **입력 요소**: 자원 보유량, 기지 확장도, 최근 전투 결과, 방어력 지표

# 전투와 정신 상태 통합
## 실시간 전투 설계 원칙
- **우선순위**: 전투 최소 루프(공격, 피해, 사망) 먼저 구현  
- **자율성**: 병력은 GOAP로 목표를 세우고 자율적으로 행동  
- **긴급 반응**: 폭발, 함정, 급습 등은 Behavior Tree로 즉시 처리  
- **스케일링**: 소규모 정찰 → 중규모 충돌 → 대규모 집단전으로 자연 확장

## 정신 상태 적용 예시
- **처음 보는 전술** → 높은 패닉 확률 → 행동 실패/도주 가능성  
- **경험 축적 후** → 대응 전략 unlock → 패닉 확률 감소, 집단 대응 향상  
- **사기(Morale)**: 집단 전투의 핵심 변수. 사기 저하 시 후퇴/항복 확률 증가

## 주민과 병력 역할 분리
- **병력**: 전투 전문, 전술 학습의 주체  
- **주민**: 생활 유지, 긴급 시 보조(함정 해제, 자원 보호, 임시 방어)

# 적 전술과 학습 시스템
## 전술 선택 방식 권장안
- **미리 정의된 전술 풀**을 만들고, **플레이어 상태와 환경 조건**에 따라 전술을 선택  
- 이유: 혼자 개발하기에 구현 난이도·밸런스 조정·테스트 용이성에서 유리

## 전술 풀 예시

| 전술 이름 | 목적 | 트리거 조건 | 효과 |
|---|---:|---|---|
| **정찰** | 약점 탐색 | 플레이어 방어 약점 존재 | 소수 병력으로 약점 정보 수집 |
| **기습** | 빠른 피해 | 밤/기상 유리, 함정 존재 | 빠른 침투로 피해 유발 |
| **포위** | 동시다발 공격 | 플레이어 기지 확장도 높음 | 여러 방향 동시 공격 |
| **약탈** | 자원 탈취 | 플레이어 자원 풍부 | 자원만 훔치고 철수 |
| **내부 침투** | 기지 무력화 | 내부 취약점 존재 | 잠입 요원으로 시스템 교란 |
| **함정 무력화** | 방어 무력화 | 플레이어 함정 설치 | 함정 해제 또는 역이용 |

## 전술 학습 메커니즘
- **경험 기록**: 전술별로 플레이어가 당한 피해·성공·실패를 기록  
- **대응 unlock**: 특정 전술에 연속 패배 시, 주민/병력 AI가 해당 전술에 대한 대응 전략을 학습(예: 경계 루틴, 특정 위치 강화)  
- **학습 속도 조절**: 난이도 밸런스에 따라 학습 속도와 효과를 튜닝

# 동적 침입 주기 설계
## 주기 결정 요소
- **기본 주기**: 기본 N일 간격  
- **동적 조정 인자**:  
  - **자원 보유량**: 풍부 → 침입 강도 상승, 빈약 → 소규모 약탈  
  - **기지 확장도**: 확장 빠름 → 포위/대규모 전술 증가  
  - **최근 전투 결과**: 적이 패배하면 재침입 대기 시간 증가, 승리하면 빠른 재침입  
  - **플레이어 행동**: 함정 설치, 내부 취약점 노출 등

## 침입 스케줄러 로직 요약
- 매 틱 또는 매일 평가 → 조건 점수 계산 → 점수 임계치 도달 시 침입 생성  
- 침입 강도와 전술은 점수에 비례해 결정

# 구현 우선순위와 단계별 로드맵
## 권장 개발 순서

| 단계 | 목표 | 산출물 |
|---|---:|---|
| **1. 기초 전투 루프** | 실시간 공격/피해/사망 구현 | 병력 기본 전투 동작 |
| **2. 병력 AI 기본** | GOAP 골 설정, 간단한 계획자 | 목표: 적 제거, 집결 |
| **3. 침입 스케줄러 최소 구현** | 고정 N일 웨이브 트리거 | 간단한 웨이브 발생 |
| **4. 정신 상태 최소화** | Panic/Fear/Rage 기본 적용 | 전투 중 행동 변화 |
| **5. 전술 풀 도입** | 정찰/기습 등 3~4개 전술 추가 | 전술 선택 로직 |
| **6. 학습 시스템** | 전술별 경험 기록 및 대응 unlock | 대응 학습 메커니즘 |
| **7. 집단 제어(Lord)** | 집단 전술(집결, 포위) 구현 | 대규모 전투 지원 |
| **8. 동적 침입 주기** | 플레이어 상태 기반 침입 조정 | 동적 웨이브 시스템 |
| **9. 밸런스 및 확장** | 전술 추가, 정신 상태 확장 | 최종 밸런싱 |

## 개발 팁
- 각 단계마다 **작은 맵과 적은 유닛 수**로 테스트  
- 로그와 시각화로 AI 의사결정(계획, 전술 선택, 정신 상태 전환)을 확인  
- **ScriptableObject**(Unity)로 전술·행동·정신 상태 정의하면 확장 쉬움

# 기술적 권장사항과 데이터 구조 예시
**기술 스택 권장**  
- **엔진**: Unity (실시간 전투와 툴링에 적합)  
- **AI 구성**: GOAP 라이브러리 또는 자체 구현, Behavior Tree 라이브러리 또는 커스텀 ThinkTree 모듈  
- **데이터 정의**: ScriptableObject로 Action, Goal, Tactic, MentalState 정의  
- **저장/로그**: 전술별 전투 로그, 학습 상태, 침입 히스토리 저장

**간단한 데이터 구조 예시 (의사코드)**

- `Action`  
  - id, preconditions, effects, cost, execute()

- `Goal`  
  - id, desiredState, priority

- `Tactic`  
  - id, triggerConditions, unitComposition, behaviorProfile

- `MentalState`  
  - id, modifiers {accuracy, speed, fleeChance}, duration, triggers

- `WaveScheduler`  
  - baseInterval, dynamicModifiers, generateWave()

# 테스트, 밸런스, 메트릭
**핵심 테스트 항목**  
- 전투 루프 안정성(데미지 계산, 사망 처리)  
- GOAP 계획의 합리성(목표 달성 경로)  
- 전술 선택의 다양성 및 트리거 정확성  
- 정신 상태 전환의 빈도와 게임성 영향  
- 동적 침입 주기의 반응성(플레이어 행동에 따른 변화)

**밸런스 메트릭 예시**  
- 평균 전투 지속 시간  
- 플레이어 기지 피해량 분포  
- 전술별 성공률 및 반복 학습 횟수  
- 주민 사기 평균 및 전투 중 패닉 빈도

# 단기 실행 항목 (다음 2주 권장 작업)
1. **전투 최소 루프 구현**: 공격, 피해, 사망, 간단한 병력 AI(접근→공격)  
2. **전술 풀 초안 작성**: 4~5개 전술 정의(정찰, 기습, 포위, 약탈, 내부 침투)  
3. **정신 상태 최소화**: Panic, Fear, Rage 구현 및 전투 연동  
4. **간단한 침입 스케줄러**: 고정 N일 웨이브로 테스트  
5. **로그/디버그 UI**: AI 의사결정(선택된 전술, GOAP 계획, 정신 상태)을 시각화

---

# 장기 고려사항
- **전술 자동 생성**은 고난도 기능으로, 이후 전술 조합/변형 기능으로 확장 권장  
- **멀티플레이어**를 고려하면 동기화와 권한 문제가 추가됨  
- **모드화/스크립팅**을 염두에 두면 ScriptableObject 기반 설계가 유리

---

# 마무리 요약
- **권장 아키텍처**: 병력 전담 AI(GOAP) + 주민 긴급 대응(Behavior Tree) + 정신 상태 + 동적 침입 스케줄러 + 전술 풀 + 학습 시스템  
- **개발 전략**: 전투 최소 루프 먼저 → 정신 상태 통합 → 전술 풀 및 학습 → 집단 전술과 동적 웨이브 확장  
- **혼자 개발 현실성**: 미리 정의된 전술 풀 + 조건 기반 선택 방식이 구현 난이도와 재미의 균형에서 최적
