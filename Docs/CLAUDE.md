# AI_GOAP — Claude 작업 규칙 (M0 개정판, 2026-07-14)

Unity 탑다운 마을 생존 시뮬레이션. GOAP(Burst Job A*) 기반 주민 AI가 핵심.
게임 정체성: "자기 생각이 있는 AI와 협상하는 게임" — 주민은 명령을 거부할 수 있다 (M1 예정).
**최우선 가치: 게임이 재밌어야 한다. 기술적 완성도는 재미의 수단이지 목적이 아니다.**

> 이 문서는 M0 재설계(2026-07-13, `Docs/M0_재설계_실행명세서.md`) 이후 아키텍처 기준이다.
> 舊 아키텍처(VillagerFSM/ActionDatabase/Registry 등 24,800줄)는 W8 커밋 `b175ddf`에서
> 폐기됨 — git 히스토리에만 존재한다. 舊 규칙을 이 문서에서 발견하면 개정 누락이므로 수정할 것.

## 불변 규칙 — ADR-M0 (위반 금지, 변경하려면 사유를 커밋 메시지에)

> **번호 규약 (2026-07-26 단일화):** 정식 번호는 백틱으로 병기한 `ADR-M0-N`이고, **정본은
> `Docs/M0_재설계_실행명세서.md`**다. 아래 1~10은 읽기 순서일 뿐 번호가 아니다 —
> 코드 주석·커밋이 인용하는 것은 언제나 `ADR-M0-N` 쪽이다.
> (개정 사유: 이 목록의 순번과 명세서의 ADR 번호가 어긋나 있어, 코드의 `ADR-M0-7`을 이 목록
> 7번에서 찾으면 엉뚱한 규칙이 나왔다. 찾아볼 수 없는 규칙은 규칙이 아니다.)
> 명세서에만 있고 여기 없는 것: `ADR-M0-4` **폐기 = 삭제** (`_Deprecated` 폴더 금지, git이 히스토리다).

1. **액션 단일 응집** `ADR-M0-1`: 액션 1개의 계획 데이터(전제/효과/비용)·실행 파라미터·말풍선 문구는
   ActionSO 에셋 하나에만 존재한다. **액션 이름으로 분기하는 switch/if를 쓰는 순간 반려** —
   실행은 IActionRunner 다형 디스패치뿐이다. (게이트: M0-T3)
2. **수치 단일 출처 = SO 에셋** `ADR-M0-2`: 게임 밸런스 수치는 에셋에만. 코드 상수는 알고리즘 상수만
   허용. 판정 기준: "플레이어가 밸런스 패치로 바꿀 값인가?" — 예이면 SO. 새 수치는
   발명하지 말고 舊 값을 git 히스토리에서 찾거나, 제안치임을 명시하고 승인받는다.
3. **상태 쓰기 단일 지점** `ADR-M0-3`: 완공은 ConstructionService.Complete()만, 스톡은 WorldModel만,
   효과 해석은 EffectApplier만(BuildRunner 예외는 AppliesOwnEffects로 명시). 두 번째
   경로가 필요해 보이면 설계 오류 — 멈추고 질문. (게이트: M0-T3 SetBuiltFlag 1건)
4. **플래너 잡 동결** `ADR-M0-5`: GOAPPlannerJob의 A* 알고리즘(Closed Set·FNV-1a·MAX_NODES 4096·
   MAX_DEPTH 12) 수정 금지. 입력 형식이 안 맞으면 ActionCompiler가 잡에 맞춘다.
   NoSolutionFound는 버그 증상 — MAX_NODES 인상으로 해결 금지, 진단 순서:
   ① goal/에셋 정합 ② Explore 발견 체인 ③ GoalSelector 후보 제외 여부.
5. **플랜 인덱스 신원** `ADR-M0-6`: 플랜 결과 = ActionCatalog 배열 인덱스. 이름 해시 역매핑 금지.
6. **Goal 목표치·발동 임계값 동일 에셋** `ADR-M0-7`: GoalSO의 두 필드 + OnValidate 정합 검사.
   목표 달성 상태가 발동 조건을 만족하면 무한 루프다.
7. **이동 실패 first-class** `ADR-M0-11` (舊 ADR-8/9 계승): Unreachable/PathBlocked → 좌표 스냅 없이
   AbortPlan → 재계획. `TileX = target...` 강제 대입 금지. (게이트: M0-T3)
8. **타일 두 셀 소유** `ADR-M0-8` (舊 ADR-T3~T6 계승): 현재+다음 타일만 예약, 실패·파괴 시
   ReleaseAllBy. 원자성(舊 ADR-2): 자원 차감은 선검사 후 일괄 — 부분 성공 금지.
9. **좌표계** `ADR-M0-9`: 2D X-Y 평면, `new Vector3(x, y, 0f)`. 슬롯 확장은 SlotId enum 뒤에만
   append (기존 인덱스 불변 — 에셋 호환). 맵 경계·배열 변환은 MapBounds가 유일한 출처
   (게이트: M0-T3 mapOffset 단일 참조).
10. **세이브 원칙** `ADR-M0-10` (ADR-M3-5 계승, 구현은 M4+): 저장 대상 = 서비스 상태만 (WorldModel·Farm·
    Discovery·Construction·에이전트 욕구/위치). 플랜·러너·쿨다운은 저장하지 않는다 —
    로드 후 재계획. 신규 런타임 상태를 추가할 때 "세이브 대상인가"를 주석으로 선언.
11. **goal 목표는 "한 걸음"** `ADR-M0-12` (2026-08-06 신설): 수치형 슬롯 goal의 목표는 한 번의
    행동으로 닿는 **증분**(`RelativeToCurrent`)으로 쓰고, **정지는 트리거가 맡는다**. 최악 결손이
    **5단계를 넘는 절대 목표 금지** — 휴리스틱은 목표 슬롯만 보므로 재료 사슬이 안 보이고,
    노드가 단계 수에 지수적으로 늘어 `NoSolutionFound`(해는 있는데 못 찾음)가 난다.
    ⚠️ 증분 전환 시 **정지 조건을 트리거로 승계**할 것 (상대 goal은 '이미 달성' 스킵 면제).
    하루에 네 번 밟혔다 (피로·Plant·GatherStone·요리) — 전부 Play가 먼저 잡았다. (게이트: M12-T5)

## 후반 확장 인지 규칙 (M5 §0.5, 2026-07-16 — 모든 신규 코드의 리뷰 기준)

로드맵(맵 대형화→야생 위협→종족→전투)은 전부 초반 완성 후 진행하되, 지금부터 신규 코드는:

1. **"에이전트=주민" 전제 하드코딩 금지** — 서비스(예약·클레임·명령)는 ID 문자열·SO
   데이터로만 결합한다. 추후 몬스터/타 종족이 같은 서비스를 공유한다.
2. **주민 전용 로직은 VillagerAgent 안에 가둔다** — 밖으로 새면 종족 도입 시 수술이 된다.
3. **슬롯은 append + 예산 인지** — SlotId 예산 52칸 (M8 종료 시 18 사용), 전투 슬롯 몫을
   남긴다.

## 게임 건강 기준 (2026-07-17 개정 — 회상 테스트 0의 교훈)

- **기술 건강 (10분 무개입 방치)**: 탐험→채집→건설→식사→휴식 순환 유지,
  Console에 NoSolutionFound·에러 0건 (PathBlocked 경고는 자기 회복 로그로 허용).
  단 **생존 goal 예외 (ADR-M6-2, 2026-07-24)**: 식량 goal(`GoalSO.MayHaveNoSolution`=true)의
  '먹을 것이 없음'은 버그가 아니라 굶주림이다 — 겨울 채집 봉쇄(ForageFrozen)로 저장분 없는 주민이
  아사하는 정상 경로. 정보 로그("먹을 것이 없다")로 강등되며 경고 0건 기준에 포함하지 않는다.
- **재미 건강 (겨울 포함 방치)**: **방치가 안락하면 실패다.** 겨울마다 비축이
  아슬아슬해야 하고, 방치 시 이탈 0~2명은 정상 범위(상실이 존재해야 함) —
  이탈 0명이 항상 보장되도록 밸런스를 되돌리는 수정은 반려. 플레이어 개입
  (명령·보상)이 결과를 바꿀 수 있어야 한다. 측정기 = 이야기 회상 테스트.

## 자동 커밋 + 개발 일지

모든 의미 있는 단위(버그 1건·기능 1개·테스트 1건) 완료 시 즉시 커밋. 배치 지연 금지.
커밋 메시지: `<type>(<scope>): <요약>` — type ∈ {fix, feat, refactor, test, docs, spec}.
세션 로그는 PostToolUse 훅이 **절반만** 처리한다 (`devlog/sessions/`, 실패 시 session-log-append 스킬).
**훅은 파일만 쓴다 — 커밋은 자동이 아니다.** 세션 로그는 블로그 파이프라인의 1차 소재이므로
세션 마무리마다 `devlog/` 변경분을 커밋·푸시한다 (2026-07-13 소재 유실 사고의 재발 방지).

**🔴 훅이 채우는 칸과 사람이 채우는 칸 (2026-07-28 정정)** — 템플릿은
`Docs/devlog-workflow.md`의 6칸이고, 훅은 커밋에서 **뽑을 수 있는 것만** 쓴다:

| 칸 | 누가 |
|---|---|
| 태그 · 무엇을 했나 · 변경 파일 | 훅 (커밋 메타데이터) |
| 왜 이렇게 했나 | 훅 — **커밋 본문(`%b`)을 그대로 싣는다.** 그러므로 **커밋 본문에 "왜"를 쓰는 것이 곧 세션 로그를 쓰는 것이다** |
| **막혔던 문제 / 해결 방법** · **다음에 할 일** | **사람/Claude** — 대화에만 있어 훅이 알 수 없다 |

마지막 두 칸은 Stop 훅(`tools/devlog/check-narrative.sh`)이 **하루 1회** 비어 있을 때
불러 준다. 알림이 뜨면 그 자리에서 채운다 — 해당 없으면 "해당 없음"이라고 쓰고,
**빈 칸으로 두지 않는다.**

> **왜 이 표가 여기 있나**: 옛 문장은 "훅이 **자동 처리**"였다. 실제로는 6칸 중 3칸만
> 채웠는데 "자동"이라 적혀 있으니 아무도 점검하지 않았고, **4개 회차 연속**으로
> blog-planner가 "세션 로그에 왜/어떻게가 0줄"이라며 1차 소스를 명세서로 우회했다
> (M9·M10·방법론·M11). 증상은 블로그 쪽에서 보였고 원인은 여기 있었다.
> 지금은 명세서가 두꺼운 밀스톤이라 우회가 통하지만, **명세서 없는 소재**(버그 주간·
> 밸런스·도구 작업)가 오면 우회로가 없다.
문서 허브: `devlog/INDEX.md` (옵시디언 볼트 루트 = 저장소. 과거 기록은 원본보다 INDEX 먼저).

## 응답 규율 (컨텍스트/토큰 절감)

- 종료 요약 1~2문장 + 설명 의무 문단. diff로 보이는 것을 산문으로 반복하지 않는다.
- 툴 호출 사이 나레이션 금지. 방향 전환·발견·차단 시에만 1문장.
- 코드 주석은 "왜"가 자명하지 않을 때만. 파일명·라인·태스크 언급은 커밋 메시지에.
- 명세 밖 아이디어는 코드에 넣지 말고 M1 백로그(메모리/로드맵)에 한 줄.

## 금지 목록

- 플래너 잡(GOAPPlannerJob) 수정 — 동결. 필요해 보이면 "정말 재미에 필요한가"를 질문으로.
- 스코프 밖 기능 추가, 명세 없는 밸런스 수치 변경
- 액션 이름 문자열 분기, 코드 내 게임 수치, 완료 처리 경로 추가 (M0-T3가 감시)
- 재사용 라이브러리(JPS·타일예약·FoW 등) 수정 — 필연적이면 최소 절제 + 커밋에 사유
- 문서(*.md) 신규 생성은 사용자 요청 시에만

## 플러그인 스킬 활용 지도 (2026-07-14 설치분 — 상황 맞으면 자동 호출)
