# M0 재설계 실행명세서 — GOAP 정합 재설계

*작성일 2026-07-13. 사용자 결정: "GOAP에 맞게 바닥부터 재설계. 맞지 않는 부분 전부 폐기. 하드코딩 절대 금물."*

## 0. 목적과 배경

기존 코드의 실패 원인은 GOAP가 아니라 **GOAP를 배신한 구현**이다:
- 액션 로직이 6개 파일 55곳의 문자열 switch에 산탄되어 있음 (VillagerFSM 3,476줄이 전부 흡수)
- 수치가 3원화됨 (GOAPActionRegistry 상수 / ActionDatabase / FSM 상수) → 결함 A의 뿌리
- 완료 처리 경로가 다중화됨 → BC1~BC5의 뿌리

M0는 **GOAP 액션을 단일 응집 객체(ScriptableObject)로 재정의**하고, 검증된 탐색기(GOAPPlannerJob)와 검증된 라이브러리(JPS, 타일예약, FoW)만 남긴 최소 코어를 새로 세운다. 나머지는 전부 폐기한다.

## 2. 재미 검증 — 플레이어가 화면에서 새로 보게 되는 것

M0가 끝나면 플레이어는 다음을 본다: 주민 5명이 **걷기 애니메이션**(Kenmi 스프라이트)으로, **각자 다른 속도**로, 출발·도착 시 **가감속**하며 움직인다. 각 주민 머리 위 **말풍선에 지금의 계획이 한국어로** 떠 있다("숲을 찾아보자 → 나무를 베자"). 배고픈 주민은 일을 멈추고 열매를 먹으러 가고, 지친 주민은 주저앉아 쉰다. 나무가 5개 모이면 누군가 모닥불을 짓고, 실제 모닥불 오브젝트가 나타난다. FoW가 걷히며 마을 주변이 밝혀진다. — 즉 "**계획을 세우고 그 계획대로 사는 작은 사람들**"이 처음으로 화면에 보인다. GOAP의 플랜이 말풍선으로 노출되는 것이 이 게임에서 GOAP가 재미에 기여하는 방식이다.

## 3. ADR-M0 (구현 중 갈릴 판단, 바꾸려면 사유를 커밋 메시지에)

- **ADR-M0-1 (액션 단일 응집)**: 액션 1개의 계획 데이터(전제/효과/비용)·실행 파라미터(소요시간/대상)·표현(표시명/말풍선 문구)은 **ActionSO 에셋 하나**에만 존재한다. 액션 이름으로 분기하는 switch/if를 새로 쓰는 순간 그 커밋은 반려다.
- **ADR-M0-2 (수치 단일 출처 = SO)**: 게임 밸런스 수치(YIELD, 비용, 소비량, 임계값, 속도)는 SO 에셋에만 둔다. 코드 상수 허용 범위는 **알고리즘 상수뿐**(MAX_NODES, 해시 시드, 틱 간격 등). 애매하면 "플레이어가 밸런스 패치로 바꿀 수 있는 값인가?"로 판정 — 예이면 SO.
- **ADR-M0-3 (완료 처리 단일 지점)**: 어떤 상태 변화든 쓰기 API는 1개다. 건설 완료는 `ConstructionService.Complete()`만, 자원 증감은 `WorldModel`의 해당 메서드만. 두 번째 경로가 필요해 보이면 설계 오류로 간주하고 멈춘다.
- **ADR-M0-4 (폐기 = 삭제)**: 폐기 대상은 `_Deprecated` 폴더 이동이 아니라 **git 삭제**한다 (히스토리가 보존한다). 죽은 코드가 컴파일 대상에 남으면 참조가 부활한다.
- **ADR-M0-5 (플래너 잡 보존)**: `GOAPPlannerJob.cs`의 A* 알고리즘(Closed Set, FNV-1a, 휴리스틱 2.9, MAX_DEPTH 6, MAX_NODES 8192)은 **무변경 재사용**한다. 바뀌는 것은 입력 생성 주체(Registry 상수 → ActionCompiler)뿐이다. 잡 구조체가 Registry의 상수를 참조하면 그 상수만 `M0.PlanningConfig`로 이전한다.
- **ADR-M0-6 (플랜 인덱스 역매핑)**: 플랜 결과는 **ActionCatalog 배열 인덱스**로 ActionSO에 직결한다. 이름 해시 역매핑(names[] 배열, ADR-8 "3종 세트")은 폐기한다 — 인덱스가 곧 신원이면 3종 세트가 필요 없다.
- **ADR-M0-7 (Goal 목표치·발동 임계값 동일 SO)**: 기존 ADR-7(목표치 < 임계값이면 alreadySatisfied 무한 루프)의 구조적 해결 — Goal의 목표치와 발동 임계값을 **같은 GoalSO 에셋의 두 필드**로 두고, OnValidate에서 `목표치 임계값 정합`을 검사해 위반 시 에셋에 에러 로그.

## 4. 아키텍처 개요

```
┌─ 데이터 (SO 에셋, 수치의 유일한 집)─────────────────────┐
│ ActionSO(계열별 서브클래스) · GoalSO · BuildingSO       │
│ ActionCatalog(액션 목록+인덱스) · AgentConfigSO         │
└──────────────┬──────────────────────────────────────────┘
               ↓ 시작 시 1회 컴파일
┌─ 계획층 ────────────────────────────────────────────────┐
│ ActionCompiler → NativeArray defs → GOAPPlannerJob(보존)│
│ PlannerGateway(잡 스케줄/폴링, 舊 Scheduler 대체)       │
│ GoalSelector(GoalSO 우선순위 순회, 舊 하드코딩 대체)    │
└──────────────┬──────────────────────────────────────────┘
               ↓ Plan = ActionSO[] (인덱스 직결)
┌─ 실행층 ────────────────────────────────────────────────┐
│ VillagerAgent FSM 5상태 (Idle/Plan/Move/Act/Dead)       │
│ IActionRunner ← ActionSO.CreateRunner() 다형 디스패치  │
│ WorldModel(수치 상태 단일 쓰기) · ConstructionService  │
│ 재사용: JPSPathfinder · TileReservationRegistry        │
└──────────────┬──────────────────────────────────────────┘
               ↓
┌─ 표현층 (M0의 절반) ───────────────────────────────────┐
│ AgentAnimator(Kenmi 걷기) · MoveMotion(이징+속도편차)  │
│ PlanBubble(플랜 말풍선) · 재사용: FowManager           │
└─────────────────────────────────────────────────────────┘
```

**재사용(무변경)**: `GOAPPlannerJob.cs`, `JPSPathfinder.cs`, `TileReservationRegistry.cs`, `FowManager.cs`, `MapChunkRenderer.cs`, `MapConfig.cs`, `CameraController.cs`, `ResourceNode.cs`/`ResourceNodeSpawner.cs`/`ResourceNodeView.cs`, `BuildingSpawner.cs`, Kenmi 에셋.

**신설**: `Assets/Scripts/M0/` 이하 전부 (아래 W 항목).

**폐기(W8에서 git 삭제)**: 부록 A 목록.

                     NearDiscoveredWood, NearDiscoveredFood, CampfireBuilt, AtBuildSite }

[Serializable] public struct SlotCondition { public SlotId Slot; public CompareOp Op; public int Value; }
[Serializable] public struct SlotEffect    { public SlotId Slot; public EffectOp Op; public int Value; } // Sub는 0 클램프 (기존 ADR-4 계승)

    public string DisplayName;          // 말풍선용 한국어 ("나무를 베자")

    public float DurationSec;

    public SlotEffect[] Effects;

public sealed class ActionCatalog : ScriptableObject {
    public ActionSO[] Actions;          // 배열 인덱스 = 플래너 액션 인덱스 (ADR-M0-6)
}
