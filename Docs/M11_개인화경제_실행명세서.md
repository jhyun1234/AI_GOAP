## 0. 목적

M10 실측 진단 3건이 출발점이다: ① 간호 crowding(전원 몰림 → 사망 구조적 불가 = S3 미착탄)
② 구역 밀집(PathBlocked + 부상자 밀집지 즉시 회복) ③ 공용 창고 식량이 있는 한 무노동
주민도 생존(개인의 생존 책임 부재). M11은 **식량 소유를 개인화**해 이 셋을 한 번에 푼다:
개인 식량 = 무노동 생존 소멸, 개인 택지 = 밀집 해소, 간호 2단계 = crowding 자연 해소 + 사망 착탄.

축 분리 원칙: **식량만 개인, 자재(목재·석재)는 공용** — "각자 먹고살되 마을은 함께 짓는다".
전투/격퇴(Warrior·방어 건물·재건·집 타격-식량 상실)는 전부 M12.

## 2. 재미 검증 — 플레이어가 화면에서 새로 보게 되는 것

이제 주민마다 살림이 다르다. 부지런한 농사꾼은 제 밭에서 거둔 곡식을 제 집 저장고에 쌓아
겨울을 앞두고 여유롭고, 집 없는 게으름뱅이는 몸에 지닌 몇 알로 하루하루를 버틴다. 늑대가
들이닥치면 집 있는 주민은 제 집으로 뛰어들지만 노숙자는 허허벌판으로 달아나다 물리고 —
그제서야 "집값 모으기" 말풍선을 띄우고 열심히 채집해 목수를 찾아간다. 새침한 목수는 선불을
요구하고, 가난한 의뢰인은 빚을 진 채 집을 받아 나중에 마주칠 때 곡식으로 갚는다. 새 집이
완공되면 이웃들이 릴레이로 축하하는 집들이가 벌어진다. 부상자 곁에는 이제 온 마을이 몰리지
않는다 — 한 명이 응급조치를 하고 물러나고, 치료사가 없으면 무덤이 생긴다. 화면의 주민
하나하나가 "저 사람은 어떻게 사나"를 갖게 된다.

## 3. ADR-M11 (구현 중 갈릴 판단, 바꾸려면 사유를 커밋에)

1. **개인 스톡 쓰기 단일 (ADR-M0-3 계승)**: 몸 소지 쓰기 = EffectApplier 경유
   `VillagerAgent.ApplyPersonalStock`만, 집 저장 쓰기 = `HomeStorageService`(TryAdd/TrySpend)만.
   보상 이전·시작 분배·방랑자 초기치도 전부 이 두 문을 지난다. 제3 경로 발견 = 설계 오류.
2. **슬롯 = 몸 소지만**: MyRawFood/MyCookedFood는 몸에 지닌 것. 집 저장은 MyHomeRawFood/
   MyHomeCookedFood 별도 슬롯 — 플래너가 "집에 둔 식량을 들판에서 먹는" 계획을 못 세운다.
   몸+집 합산은 MyFoodDaysLeft 파생 1곳뿐 (트리거 전용, ADR-M9-9 계승).
3. **상한 단일 출처 + 컴파일러 자동 주입**: 상한 수치는 AgentConfigSO에만. ActionCompiler가
   개인 스톡 Add 효과를 가진 액션에 `해당 슬롯 ≤ 상한-Add값` 전제조건을 **자동 주입**한다
   (액션 에셋에 상한 리터럴 기입 금지 — 이중 기입). EffectApplier 클램프는 방어선일 뿐,
   발동하면 경고 로그 = 버그다.
4. **보상 = 실제 이전 + 부족 시 연기**: 정산은 의뢰인 잔고(몸+집)가 전액이고 수행자 수령
   공간이 전액일 때만. 아니면 빚 유지 + `정산 연기` 로그 (소실 없음). 부분 지급 금지 (장부
   복잡화). **떼먹기는 성격 경로만** — 파산은 떼먹기가 아니다 (관계 델타 없음).
5. **택지 = 결정적 점수 (ADR-M1-2 계승)**: 후보 순회 순서 고정, 점수 동률은 (x, y) 사전순.
   랜덤 금지. 선호는 성격/직업 에셋 필드 가산치뿐 (기본 0 = 중립).
6. **간호 2단계 (M10 결정 11 공식 개정)**: 안정화 = 부상 1건당 1회, 유예 부여만 (회복 없음).
   완치 = `JobSO.CanTreatInjury` 직업의 간호만. **ADR-M5-4("직업 전용 goal 금지") 부분 개정**:
   GoalSO.RequiredJob은 치료 goal + **목수 자가 건축** 전용 예외 (2026-07-23 개정, 사용자
   결정 — §M11-I 추가 항목) — 그 밖의 goal에 설정하면 반려. 세 번째 용도가 나오면 예외가
   아니라 규칙이므로 ADR-M5-4 자체를 재검토할 것 (남용 = 직업 붕괴 스위치 부활).
7. **자재 공용 유지**: WoodStock·StoneStock 전역 그대로, 창고 성역(ADR-M9-5)은 자재 창고로
   계승. 전역 식량 슬롯(RawFoodStock 1·CookedFoodStock 10)은 **휴면** — 슬롯 삭제 금지
   (append 규약), 초기치 0, 어느 액션·goal도 참조하지 않게 에셋 개편 (S1이 감시).
8. **결말 이원화 유지 (ADR-M10-3)**: 개인 기근도 이탈 계단(포만<10 지속)으로만. 개인화가
   새 결말 경로를 만들지 않는다.
9. **채집 노드 공용 유지**: 야생 노드(열매·나무·돌)에 소유 없음. 개인화는 소지·저장·밭에만.
   "밭 없이 채집만 하는 노숙 생존"은 겨울(RegenMult 0)+저장 불가가 심판한다 (§8 관찰 ①).
10. **세이브 주석 규약 (ADR-M0-10)**: 몸 소지 2종·집 저장(타일 키)·MyWasAttacked·안정화
    플래그·유예 잔량·빚 목록(_pendingReports는 기존 규약대로 저장 안 함 → **개정: 실식량
    빚은 저장 대상으로 승격** — 소실되면 지급 소실) = 세이브 대상.

/// <summary>부상 계단 v2 (순수 — 게이트): 치료 간호 = 회복 진행 (기존과 동일).

}

7. **여력 경로의 좁은 창** (M11-G 자가 재검토, §8-3 확장): 부탁 성립 판정은 스캔 순간의
   `MyRawFood ≥ 5`다. 먹으면 4로 떨어지므로 "5를 유지한 채 목수와 6타일 내 조우 + 쌍방
   쿨다운 해제"라는 좁은 창을 통과해야 한다. 피격 없는 노숙자가 끝내 집을 못 얻는 판이
   나오는지 관측 — 1차 레버는 보상액(5) 하향, 상한(8) 상향은 §8-1과 충돌하므로 후순위.
8. **의뢰인 쿨다운의 에셋 공유**: `_requesterCooldownUntil`은 **의뢰인 단위**(90초)라 집 부탁
   두 에셋이 쿨다운을 공유한다 — Urgent가 거절당하면 90초간 여력 경로도 봉쇄된다. 이원 경로의
   실효가 반감되는지 로그로 확인 (수정한다면 쿨다운 키를 (의뢰인, 에셋)으로 — 지금은 하지 않음).
9. **목수 부재 판**: 직업 7종 풀에서 시작 4명이라 목수 없이 시작하는 판이 흔하다 → 집이
   구조적으로 불가능. **M11-J의 시작 분배와 함께 결정** (사용자 2026-07-23). 근본 해법은
   M1 백로그의 시작 드래프트 UI다. 그전까지의 Play 관측은 목수 유무를 먼저 확인하고 시작할 것.
10. **노숙 도피의 경계 몰림**: `EscapeTile`이 맵 경계로 클램프되므로 반복 도피는 가장자리에
    몰린다 → 추격형 위협에 결국 물린다. 의도("노숙 = 위험", 결정 7)에 부합하나, 물리는 게
    아니라 **끼여서 못 움직이는** 그림이면 PathBlocked 축의 문제다 — 구분해서 관측.
11. **조리식은 집 저장 대상이 아니다** (2026-07-23 중간 리뷰 ② 관측 → 결정). 관측 =
    "집 저장은 되는데 조리식만 UI에 안 잡힌다". 진단 = **구조적 영구 불발**: 조리 goal 3종
    (CookAhead·CookExtra·WinterPrep)의 목표가 전부 `MyCookedFood ≥ 2`인데 `Store_CookedFoodHome`
    전제는 `≥ 3`이라 문턱에 닿을 수가 없다. 이건 **M9 밸런스의 귀결**이지 버그가 아니다 —
    M9는 조리를 칼로리 손실로 튜닝했고(평시 생식3→조리1 = 0.78배, 위기 0.47배) 그래서 조리
    목표가 2로 낮다. 조리를 늘려 쟁이게 하면 겨울 순증 문제(M9 중간 리뷰 ②)가 되살아난다.
    **결정: 조리식 = "지금 먹는 것", 집에 쟁이는 것 = 생식.** `Goal_StoreFood` 목표에서 죽은
    조건 `MyCookedFood ≤ 2` 제거(항상 이미 참이라 착시만 유발). 조리식 저장/꺼내기 액션 2종은
    **삭제하지 않고 휴면 보존** — 되살리려면 조리 목표치 상향 또는 전제 하향이 필요하고 둘 다
    M9 밸런스 재검토를 동반한다 (M12 겨울 저장 재검토 후보).
12. **목수가 집 저장까지 내려오지 못함** (같은 관측): 코드·에셋에 차단 지점 없음 — **우선순위
    굶주림**이 유력하다. `Goal_StoreFood`(16) 위로 부탁(36)·밭(40)·수확(24)·확장(26)이 있고
    목수는 그것들이 끊이지 않는 병목 직업(결정 14)이라 16까지 내려올 틈이 없다. 의도된 설계의
    귀결일 수 있어 **수정하지 않고 관찰** — 부탁이 뜸해지는 후반에도 저장이 없으면 그때
    우선순위 상향(16→28, 수확·확장 위)을 검토한다.
13. 🔴 **플레이어 명령 보상(RewardSO)의 지불 주체 부재** (M11-H 대조에서 발견): `RewardSO.CostSlot`
    이 전역 CookedFoodStock(에셋 Reward_MealRation = 슬롯 10, 2개)이라 `TryGiveOrder`의 재고
    검사에서 **항상 걸린다** — 주민 간 보상과 같은 M11-B 파급인데 이쪽은 **플레이어 개입 동사**다
    (명령 거부를 보상으로 뒤집는 협상 = 게임 정체성). 촌장에겐 개인 잔고가 없고 공용 식량은
    폐지됐으므로 지불 주체를 새로 정해야 한다.
    **→ 결론: 화폐 축으로 해결한다 (사용자 방향 제시 2026-07-23).** 원문 요지: *"보상으로 자원을
    주는 건 이상하다 — 자원은 주민이 스스로 일해서 캐다 창고에 넣는 것인데 그걸 내가 준다는 게
    어색하다. 촌장(플레이어)은 **추가 재화(돈)**를 주는 방식으로 가면 어떨까. 경제에 큰 혼란이
    오지 않을 정도의 보상 재화. 이후 이 재화로 마을에서 물건을 사고팔 수 있는 상태로 가고 싶다."*
    이는 M11 **결정 2**(화폐·부채는 후속 — 선반 호환만 고려)와 **결정 10**("향후 화폐 도입 시 이
    자리에 화폐만 꽂으면 된다")이 예비해 둔 자리와 정확히 맞물린다 — 지불 주체 부재는 설계
    결함이 아니라 **화폐가 아직 없어서** 생긴 공백이었다.
    **처리**: M11-J에서 RewardSO 경로를 **명시적 휴면**으로 정리만 한다 (명령 수락은 친밀도·성격·
    몸 상태로만 — 죽은 채 방치하지 않는다). 화폐·상거래는 **별도 브레인스토밍이 필요한 큰 축**
    이므로 M11 스코프 밖 (사용자 지시). 관련 백로그: CLAUDE.md M1 "개인 소지 재화(지갑)·화폐·
    부채 — 지갑 선반과 함께", 퀘스트보드(조각 X).
