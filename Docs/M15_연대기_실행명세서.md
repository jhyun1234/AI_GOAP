> **북극성 정합**: "성장하며 버티는 기록 경주"(M14 확정)의 후반부 — **"판이 끝나면 마을의

## 0. 성공 기준 (측정 가능)

1. **판 2회 이상 종료 후** `persistentDataPath/chronicle_archive.json`에 RunEntry **2건 이상**,
   각 판의 Roster **1명 이상** (겨울 0번 판 포함 — 전멸 마감이 첫 쓰기여도 남는다).
2. 게임 중 **C 키 1회 = 패널 열림, 재입력 = 닫힘**, Console 에러 **0건**.
3. 과거 판 상세에서 주민 줄에 **성격·직업·생애 구간·사망 원인·사건 요약·퇴장 관계**가 표시
   — **회상 테스트(아카이브판)**: 사용자가 패널만 보고 지난 판의 서사를 재구성할 수 있는가.
4. `RunRecordStore.cs`와 그 호출부(신기록 줄·SaveIfBetter) **코드 diff 0** — 기존 신기록
   통로 병존, 전멸 화면에 "역대 최고:" 줄이 계속 뜬다.
5. 아카이브 파일 삭제·손상 상태에서 실행해도 게임 진행 (경고 로그 1줄, 예외 전파 0).

**중간 리뷰**: ① W2 후 — 겨울 1번 넘기고 json 파일 내용 확인 (스키마 판정).

## 2. 확정 보완 (결정 → 기계 번역 정제 — 승인된 설계에서 실사가 바꾼 것)

1. **전멸 화면 자동 표시 → 힌트 줄 + 동일 토글.** 전멸 화면은 이미 현재 판의 명부다(실사 ②).
   그 위에 아카이브 패널을 자동으로 겹치면 같은 정보 두 형태(2026-07-30 오독 전례)가 된다.
   전멸 문구 끝에 `C — 역대 연대기` 한 줄을 얹고, 열람은 게임 중과 같은 C 토글로 통일한다.
2. **직렬화 대상 = 요약 문자열, 원본 사건 아님.** 기록 깊이 결정("명부까지, 타임라인 제외")의
   기계 번역: `ChronicleEvent` 리스트는 저장하지 않고 `ComposeLifeEvents` 출력(묶음 요약)을
   문자열로 저장한다 (ADR-M15-3). 원본이 필요해지면 RunEntry에 필드 append로 확장.
3. **현재 판 스냅샷 = 저장 경로와 동일 함수.** 패널의 "진행 중" 판도 `SnapshotCurrentRun()`
   하나로 만든다 — 그리기 코드가 RunEntry 한 타입만 알게 되고, 직렬화 경로가 평소 열람으로도
   검증된다 (브레인스토밍 🟡2 합의의 이행).
4. **판 식별 = 순번 + 실제 시각.** RunNumber(1부터)와 마지막 갱신 벽시계 시각(EndedAt)을
   저장 — "내가 이 게임을 해 온 이력"(승인된 조언 2)의 기계 번역.

## 3. ADR — 구현 중 갈릴 판단의 사전 결정 (바꾸려면 사유를 커밋에)

- **ADR-M15-1 (아카이브 파일 분리)**: 연대기 = `chronicle_archive.json` 신설.
  `run_records.json`과 그 코드 경로(SaveIfBetter·신기록 줄)는 **한 글자도 안 바꾼다**.
  최고 기록을 아카이브에서 유도하도록 재배선하는 것도 금지 — 검증된 통로의 병존이 원칙.
  아카이브 스키마는 **append-only + Version** (ADR-M14-3 계승): 필드 제거·의미 변경 금지,
  확장은 필드 append만. 세계 지속(DF 레거시, 장기 백로그)이 이 스키마를 읽는다.
- **ADR-M15-2 (쓰기 지점 2곳뿐)**: 아카이브 쓰기 = 겨울 전환·전멸 래치 (M14 ⚠️W4-③ 계승).
  매 틱·매 사건 쓰기 금지. 중도 종료 판은 마지막 겨울 스냅샷까지만 남는 것이 **의도**다
  (M14 저장 리듬 결정 상속 — 방치 후 종료 패턴에서도 기록이 쌓인다).
- **ADR-M15-3 (요약 저장, 원본 소멸)**: 아카이브가 저장하는 것은 명부와 묶음 사건 **요약
  문자열**이지 `ChronicleEvent` 원본이 아니다. 원본 타임라인은 판이 끝나면 소멸한다 —
  이것은 손실이 아니라 브레인스토밍 결정("명부까지")의 이행. 문구 정책이 바뀌어도 과거
  판의 문구는 기록 당시 그대로다 (아카이브의 본성 — 다시 쓰지 않는다).
- **ADR-M15-4 (파일 실패는 게임을 못 막는다)**: RunRecordStore 원칙 계승 — 읽기 실패 = 빈
  아카이브로 진행, 쓰기 실패 = 경고 로그 후 진행. 예외 전파 금지, 침묵 금지.

```csharp
namespace AIVillage.M0
{
    /// <summary>판별 연대기 아카이브 (M15-W1 — 새 선반 ②).
    /// 파일 = persistentDataPath/chronicle_archive.json. run_records.json과 별개 (ADR-M15-1).
    /// 스키마 = append-only + Version. 쓰기 지점 = 겨울 전환·전멸 래치 2곳뿐 (ADR-M15-2).
    /// 파일 실패는 게임을 못 막는다 (ADR-M15-4).</summary>
    public static class ChronicleArchive
    {
        [Serializable] public sealed class VillagerEntry
        {
            public string ShortName;
            public string Personality;   // 문자열 저장 (VillagerRecord 선례 — 에셋 수명 무관)
            public string Job;
            public int    BornDay;
            public int    LeftDay;       // -1 = 스냅샷 시점 생존
            public int    Cause;         // ExitCause 정수 (append-only enum이라 안전, ADR-M13-2)
            public string BuddyShort;    // 퇴장 시점 단짝 표시명. "" = 없음
            public string GrudgeShort;
            public string LifeEvents;    // ComposeLifeEvents 출력 (요약 문자열, ADR-M15-3)
        }
        [Serializable] public sealed class RunEntry
        {
            public int    Version = 1;
            public int    RunNumber;     // 1부터 (목록 표시용)
            public string EndedAt;       // 마지막 갱신 벽시계 "2026-07-31 21:04" (확정 보완 4)
            public int    Winters;
            public int    LastDay;
            public int    PeakPop;
            public int    Settles;
            public bool   Ended;         // true = 전멸 마감 / false = 겨울 갱신까지 (중도 종료 판)
            public List<VillagerEntry> Roster = new List<VillagerEntry>();
        }
        [Serializable] public sealed class ArchiveFile
        {
            public int Version = 1;
            public List<RunEntry> Runs = new List<RunEntry>();
        }

        /// <summary>순수부 (게이트 M15-T2) — runIndex < 0 이면 append, 아니면 그 자리 갱신.
        /// 반환 = 실제 인덱스. 범위 밖 인덱스는 append로 강등 (방어 — 기록 유실보다 중복이 낫다).
        /// **RunNumber는 여기서 부여한다** — append = Runs.Count+1, 갱신 = 기존 번호 유지.
        /// (조립자 SnapshotCurrentRun은 파일 내용을 모른다 — 번호를 아는 곳은 store뿐.)</summary>
        public static int Apply(ArchiveFile file, int runIndex, RunEntry entry) { ... }

        public static ArchiveFile Load() { ... }   // 없음·손상 = 빈 파일 (경고 로그, ADR-M15-4)
        /// <summary>Load→Apply→Save 한 번에. 반환 = 실제 인덱스 (호출자가 보관).</summary>
        public static int SaveRun(int runIndex, RunEntry entry) { ... }
    }
}
```

/// <summary>현재 판 스냅샷 (M15 — 확정 보완 3: 저장·열람이 같은 함수). Ended = 전멸 여부.</summary>
public ChronicleArchive.RunEntry SnapshotCurrentRun(bool ended)
{
    var entry = new ChronicleArchive.RunEntry {
        // RunNumber는 안 채운다 — Apply가 부여 (W1 스케치 참조. 조립자는 파일 내용을 모른다)
        EndedAt = System.DateTime.Now.ToString("yyyy-MM-dd HH:mm"),
        Winters = WintersSurvived, LastDay = (int)GameTime,
        PeakPop = PeakPopulation, Settles = SettleCount, Ended = ended,
    };
    foreach (VillagerRecord r in Chronicle.RosterByBirth())
        entry.Roster.Add(new ChronicleArchive.VillagerEntry {
            ShortName = r.ShortName, Personality = r.PersonalityName, Job = r.JobName,
            BornDay = (int)r.BornDay, LeftDay = (int)r.LeftDay, Cause = (int)r.Cause,
            BuddyShort = ..., GrudgeShort = ...,       // SeasonHud.ToShortName 규칙 재사용
            LifeEvents = SeasonHud.ComposeLifeEvents(r), // 실사 ③ — 묶음 요약 재사용
        });
    return entry;
}

## 7. 재미 검증 — 플레이어가 화면에서 새로 보게 되는 것

플레이 중 **C 키를 누르면 지난 마을들의 목록**이 뜬다 — "판 3 — 겨울 3 · Day 44 · 최대
8명 · 전멸 · 7/31 21:04". 판을 클릭하면 그 마을의 명부가 펼쳐진다: "† A — 게으름뱅이,
무직. Day 3~34, 굶어 죽음 · D5~34 명령 거부(피로) ×30". 지금까지 전멸 화면이 닫히는
순간 사라지던 이야기가 **다음 판에서도, 그 다음 판에서도** 다시 읽힌다. 새 판을 하다가
"저번 마을은 치료사가 없어서 끝났었지"를 확인하고 이번 판의 대비를 바꾸는 것 — 기록
경주의 비교 동기가 판 도중에 작동하는 첫 화면이다.
