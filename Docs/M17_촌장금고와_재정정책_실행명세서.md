# M17 "촌장 금고와 재정 정책" 실행명세서 — 돈이 유한해지고, 물가가 내 장부의 숫자가 된다

*작성 2026-08-01. 브레인스토밍 = 같은 날 (질문 7문 · `brainstorming` 스킬).*
*직전 밀스톤 = M16 화폐 기반 + 직거래 (`Docs/M16_화폐기반_직거래_실행명세서.md`).*

> ⚠️ **번호 혼동 주의**: 여기서 M17 = **밀스톤** 번호다. `Docs/개발_방법론_명세서.md`의

## 이 밀스톤이 딛는 관측 (M16 Play, 2026-08-01 사용자)

> ①주민 간 직거래 장면 **확인** ③50동 모은 주민의 집 부탁 성사 **확인**
> ② *"웃돈 남발이 물가 상승으로 이어진다는 것을 플레이어가 알아차릴 방법이 없어. 임펙트가 없어."*

②의 실사 진단 — 인과는 구현돼 있다(`TradePrice`·`EffectiveRewardScale`·물가 거부 대사).
도착하지 않는 이유가 셋인데 **근본은 두 번째**다:

1. 인과가 화면에서 끊긴다 — 웃돈을 거는 순간과 물가가 오르는 순간이 하루 떨어져 있다.
2. **아픔이 촌장에게 안 온다** — 촌장은 돈을 공짜로 무한히 찍는다. 비용 없는 버튼은 결정이 아니다.
3. 수치가 잘 안 움직인다 — `M`과 `Q`가 함께 늘면 상쇄돼 100%에 눌어붙는다.

M17은 **②를 고친다.** ①③은 ②의 귀결이므로 함께 풀린다.

## 2. 확정 보완 (결정 → 기계 번역 — 실사 체크리스트 4번 산출물)

브레인스토밍 합의를 슬롯·쓰기 지점·관계식으로 옮기며 발견한 정제 5건.

### 보완 1 — 회계 메서드를 넷으로 나눈다 (`ADR-M16-1` 개정 사유)

"금고는 통화량 밖"을 지키려면 **돈이 어디서 왔는지**를 회계가 구분해야 한다. 지금의
`Mint` 하나로는 "무에서 나온 돈"과 "금고에서 옮겨온 돈"이 섞여 폐곡선 검산이 불가능하다.

| 메서드 | 흐름 | `MoneySupply` | `Treasury` | `MintedTotal` | `BurnedTotal` |
|---|---|---|---|---|---|
| `Mint(to, n)` | 무 → 주민 | **+n** | — | **+n** | — |
| `MintToTreasury(n)` | 무 → 금고 | — | **+n** | **+n** | — |
| `PayFromTreasury(to, n)` | 금고 → 주민 | **+n** | **−n** | — | — |
| `Burn(n)` | 주민 → 무 | **−n** | — | — | **+n** |

**폐곡선 항등식**: `MintedTotal == MoneySupply + Treasury + BurnedTotal`
네 흐름 모두에서 좌우가 같이 움직인다(검산은 §8 탐지기).

### 보완 2 — 🔴 원천징수는 물가를 **내리지 못한다** (설계 정정)

브레인스토밍 3절에서 필자가 *"오늘 세율을 올려 내일 확정값을 되돌릴 수 있다"* 고 적었는데
**부정확하다.** 원천징수는 임금을 줄 때 일부를 **안 푸는** 것이므로 이미 유통 중인 `M`을
줄이지 않는다. 세율을 올려도 그 순간 `M`은 그대로이고, 따라서 **예보도 즉시 안 내려간다.**

물가가 실제로 내려가는 경로는 아래 셋뿐이다:

```
① M 증가 억제   — 세율↑ → 임금 순액↓ → M이 덜 는다              (즉시 시작, 효과는 누적)
② Q 증가        — 세율↑ → 임금노동 기피 → 자급(채집·밭) 회귀 → 식량 개수↑ → 분모↑
③ MintDebt 감쇠 — 찍은 뒤 가만두면 하루 20%씩 잦아든다
```

②가 성립하는 이유는 **임금노동과 식량 생산이 겹치지 않기 때문**이다 — 임금은 벌목·채광·
시설 건설에만 붙고(§변경표 없음, M16-B 그대로), 채집·밭·조리에는 붙지 않는다. 그래서
중과세는 주민을 식량 쪽으로 밀어 `Q`를 늘린다.

**그러므로 세율은 즉효 버튼이 아니라 방향타다.** 명세 전반과 화면 문구는 이 사실에 맞춘다 —
"세율을 올리면 물가가 내려간다"고 **표시하지 않는다**(거짓말 금지). 즉시 움직이는 것은
웃돈·발행뿐이고, 세율의 효과는 며칠에 걸쳐 예보 숫자로 나타난다.

### 보완 3 — 정수 분배 규칙 (합이 새지 않게)

`순액 = floor(W × (100 − r) ÷ 100)`, `세액 = W − 순액`.
세액을 따로 반올림하면 `순액 + 세액 ≠ W`가 되어 폐곡선이 깨진다. **세액은 항상 잔여로 구한다.**

⚠️ 작은 임금에서 실효세율이 튄다: `W=2, r=15%` → 순액 1·세액 1 = 실효 50%. 현재 최소
임금이 5동이라 발현하지 않지만, 임금 에셋을 5동 미만으로 내리면 발현한다. §8 탐지기에 포함.

### 보완 4 — 세율 변경은 플래너 재컴파일을 부른다

임금이 플래너 시야에 있으므로(전제 7) 세율이 바뀌면 `_defs`의 임금 효과값이 낡는다.
`PlannerGateway.Recompile(netPct)`로 다시 만든다. **카탈로그 순서는 안 바뀌므로
`ADR-M0-6`(인덱스 = 신원)이 유지되고, 진행 중인 플랜도 그대로 돈다** — 기대보다 덜 받을
뿐이며 그것이 의도한 이야기다.

### 보완 5 — 화폐 단위 개편의 짝

`1은 = 100동, 1금 = 100은`으로 바꾸면 `ComposeMoney`만 고쳐서는 안 된다. **게이트
M16-T8이 옛 진법을 기대값으로 하드코딩하고 있다**(실사 확인 —
`ComposeMoney(13) == "1은 3동"`, `(100) == "1금"`, `(247) == "2금 4은 7동"`).
함수와 게이트는 짝이다(방법론 M17). 둘을 한 커밋에서 함께 고친다.

새 진법의 기대값: `13 → "13동"` · `100 → "1은"` · `247 → "2은 47동"` ·
`10000 → "1금"` · `0 → "0동"` · `-5 → "0동"`.

지금 규모(임금 5~6동·집 50동)에서는 **은이 거의 안 나온다.** 이는 의도다 — 은이 보이기
시작하는 것 자체가 "마을이 커졌다"의 신호다. **경제 규모(집값·임금)는 건드리지 않는다**
(M16-B 균형 = 전원 아사를 고치며 얻은 값).

## 3. ADR — 구현 중 갈릴 판단의 사전 결정 (바꾸려면 사유를 커밋에)

- **ADR-M17-1 (금고는 통화량 밖)**: `Treasury`는 `MoneySupply`에 포함되지 않는다.
  금고에 잠긴 돈은 시중에 없는 돈이다. 물가 산식의 분자에 금고를 더하지 않는다.
- **ADR-M17-2 (화폐 회계 쓰기는 네 메서드뿐)** *(`ADR-M16-1` 개정 — 사유: 금고 신설로
  "무에서 온 돈"과 "금고에서 옮긴 돈"의 구분이 필요해졌다)*: `Mint`·`MintToTreasury`·
  `PayFromTreasury`·`Burn`. 다섯 번째 경로가 필요해 보이면 설계 오류 — 멈추고 질문.
- **ADR-M17-3 (판정은 확정 물가만 읽는다)** *(`ADR-M16-3` 개정 — 사유: 관측 ②는 "결과를
  앞당기라"가 아니라 "원인을 실시간으로 보이라"였고, 물가를 실시간으로 만들면 `Q`의
  초 단위 요동이 거래가·설득력 판정에 그대로 실린다)*:
  **판정**(거래 실가격·웃돈 실효 오프셋)은 하루 1회 캐시 하나만 읽는다.
  **표시**는 확정과 예보 둘을 보이되, **산식은 `ComputePricePct` 하나를 지난다.**
  예보값이 판정 코드에 들어가면 화면과 실제가 어긋난다 — 게이트로 검사(M17-T4).
- **ADR-M17-4 (발행의 대가는 `MintDebt` 하나)**: 발행 페널티를 물가 외의 축(신뢰도 상태·
  주민 감정·이벤트)으로 늘리지 않는다. 강도는 `MintSurchargeK`, 지속은 `MintDebtDecayPct` —
  **이 둘은 짝이므로 따로 조정하지 않는다**(방법론 M17).
- **ADR-M17-5 (세금은 임금에만)**: 웃돈·직거래·부탁 보상은 과세하지 않는다. 웃돈 과세는
  촌장이 자기 돈을 자기가 걷는 꼴이고 설득력은 이미 물가가 깎는다(이중 과금). 직거래는
  `M`이 안 움직이므로 걷을 인플레가 없다.
- **ADR-M17-6 (세금은 목숨을 끊지 않는다)** *(`ADR-M16-5` 계승)*: 임금노동이 식어도
  채집·밭·조리는 임금과 무관하므로 생존 사슬은 멈추지 않는다. **세금이 아사의 원인으로
  이어지는 경로가 발견되면 그것은 밸런스가 아니라 설계 오류다** — M16이 "경제가 생존
  사슬을 밀어냈다"로 전원 아사를 낸 지점이다.
- **ADR-M17-7 (세율은 즉효 버튼이 아니다)**: 화면·대사·로그 어디에서도 "세율을 올리면
  물가가 내려간다"고 말하지 않는다(보완 2). 세율은 `M` 증가 억제와 `Q` 증가를 통해
  **며칠에 걸쳐** 작용한다.

// WorldModel.cs — M17-W1
/// <summary>촌장 금고 (M17-W1, ADR-M17-1) — 통화량 M 밖이다. 금고에 잠긴 돈은
/// 시중에 없는 돈이므로 물가 분자에 들어가지 않는다. 세이브 대상 (ADR-M0-10).</summary>
public int Treasury { get; private set; }

/// <summary>발행 누적·소멸 누적 (M17-W1) — 폐곡선 검산 전용 (§8 탐지기). 게임 규칙에
/// 쓰지 않는다: 물가는 M과 MintDebt만 본다.</summary>
public int MintedTotal { get; private set; }
public int BurnedTotal { get; private set; }

/// <summary>무 → 금고 (M17-W1). 임금의 원천징수분과 촌장의 발행이 이 통로를 지난다.
/// M은 움직이지 않는다 — 시중에 나가지 않았기 때문이다 (ADR-M17-1).</summary>
public void MintToTreasury(int amount, string why)
{
    if (amount <= 0) return;
    Treasury    += amount;
    MintedTotal += amount;
    Debug.Log($"[Money] 금고 +{amount}동 — {why} (금고 {Treasury} · 통화량 {MoneySupply})");
}

/// <summary>금고 → 주민 (M17-W1). 웃돈의 유일한 지급 통로. 잔고 부족이면 false —
/// 촌장이 없는 돈을 약속하지 못한다 (조용한 실패 금지: 호출자가 알림을 띄운다).</summary>
public bool PayFromTreasury(VillagerAgent to, int amount, string why)
{
    if (amount <= 0 || to == null) return false;
    if (Treasury < amount)
    {
        Debug.Log($"[Money] 금고 부족 — {why} (필요 {amount}동 · 금고 {Treasury}동)");
        return false;
    }
    // 지갑 적립은 Mint와 같은 통로를 쓴다 (ADR-M11-1 — 개인 스톡의 원천은 VillagerAgent).
    // 적립 실패면 회계를 건드리지 않는다 (원자성, ADR-M0-8).
    if (!to.ApplyPersonalStock(SlotId.MyMoney, EffectOp.Add, amount)) return false;
    Treasury    -= amount;
    MoneySupply  = NextSupply(MoneySupply, amount);
    Debug.Log($"[Money] 금고 →{to.AgentId} {amount}동 — {why} (금고 {Treasury} · 통화량 {MoneySupply})");
    return true;
}
```

// WorldConfigSO.cs — M17-W2
[Tooltip("세율 단계 % (원천징수 — 임금에만 부과, ADR-M17-5). 0번이 시작 단계.\n" +
         "제안치 0/15/30 — 실측 근거 없음. Play 재조정 대상 (§4 수치 표).")]
public int[] TaxRatePcts = { 0, 15, 30 };

// ActionSO.cs — 세율 인자 추가 (기본 0 = 무세 → 기존 1인자 호출·게이트 무수정)
/// <summary>플래너 전용 효과 수집 (M16-B, M17-W2 확장). 세율이 붙으면 플래너가 보는
/// 임금이 세후 실수령으로 줄어든다 — 별도 페널티 로직 없이 임금노동의 매력이 떨어진다.
/// 수치 출처는 WagePay 하나 그대로다 (ADR-M0-1); 이 메서드는 정책을 곱할 뿐이다.</summary>
public void CollectPlannerEffects(List<SlotEffect> into, int taxRatePct = 0)
{
    CollectEffects(into);
    if (WagePay <= 0) return;
    int net = NetWage(WagePay, taxRatePct);
    if (net > 0) into.Add(new SlotEffect { Slot = SlotId.MyMoney, Op = EffectOp.Add, Value = net });
}

/// <summary>세후 임금 (M17-W2, 순수 — 게이트 M17-T2. 보완 3): 순액 = floor(W × (100−r) ÷ 100).
/// 세액은 반드시 잔여(W − 순액)로 구한다 — 따로 반올림하면 합이 W와 어긋나 폐곡선이 깨진다.</summary>
public static int NetWage(int wage, int taxRatePct)
    => Mathf.FloorToInt(wage * (100 - Mathf.Clamp(taxRatePct, 0, 100)) / 100f);
```

⚠️ **세율이 100%면 순액 0 → 플래너 효과가 사라진다.** 지금 단계 배열 최대가 30이라

`Goal_SaveForHome`이 `NoSolution`이 된다. **단계 배열 상한은 90으로 `OnValidate` 검사.**

```csharp
// WorldModel.cs — M17-W3
/// <summary>발행 부채 (M17-W3, ADR-M17-4) — 찍은 돈이 물가에 남기는 여파.
/// 발행 시 액수만큼 붙고 하루마다 일정 비율 감쇠한다. 쓰지 않고 쌓아만 둬도 아프다:
/// "찍었다"는 사실 자체가 돈값을 떨어뜨린다는 것이 이 축의 전부다.</summary>
public int MintDebt { get; private set; }

/// <summary>촌장의 발행 (M17-W3) — 무 → 금고. 금고는 M 밖이라 통화량은 안 늘지만
/// MintDebt가 즉시 붙어 물가 예보가 그 자리에서 움직인다 (S2).</summary>
public void IssueCurrency(int amount, string why)
{
    if (amount <= 0) return;
    MintToTreasury(amount, why);
    MintDebt += amount;
    Debug.Log($"[Money] 발행 여파 +{amount} (누적 {MintDebt}) — 찍은 돈은 값이 더 떨어진다");
}

/// <summary>발행 부채 감쇠 (M17-W3, 순수 — 게이트 M17-T3). 하루 1회.
/// 내림이면 잔량 1~4가 영원히 안 사라지므로 5 미만은 0으로 떨군다.</summary>
public static int DecayMintDebt(int debt, int decayPct)
{
    int next = Mathf.FloorToInt(debt * (100 - Mathf.Clamp(decayPct, 0, 100)) / 100f);
    return next < 5 ? 0 : next;
}

/// <summary>감쇠 적용 (M17-W3) — 하루 경계 블록에서 1회 호출 (SimulationLoop 1011행 근처).
/// 순수 함수와 쓰기 지점을 나눈 이유는 게이트가 곡선만 따로 검증할 수 있게 하기 위함이다.</summary>
public void TickMintDebtDecay(int decayPct) => MintDebt = DecayMintDebt(MintDebt, decayPct);
```

// WorldModel.cs — M17-W4 (ADR-M17-3: 산식은 이 함수 하나. 확정도 예보도 여기를 지난다)
/// <summary>물가 산식 (M16-W4 확장, 순수 — 게이트 M17-T1).
/// P% = clamp(100 × (M + k×MintDebt) ÷ (Q × 기준가), 100 ~ 상한).
/// mintDebt·k는 M17-W3의 발행 여파 — 찍은 돈은 쓰기 전부터 값을 떨어뜨린다.</summary>
public static int ComputePricePct(int moneySupply, int foodCount, int basePrice, int capPct,
                                  int mintDebt = 0, float surchargeK = 0f)
{
    int denom = Mathf.Max(1, foodCount * Mathf.Max(1, basePrice));
    int numer = moneySupply + Mathf.RoundToInt(mintDebt * Mathf.Max(0f, surchargeK));
    return Mathf.Clamp(100 * numer / denom, 100, Mathf.Max(100, capPct));
}

## 7. 재미 검증 — 플레이어가 화면에서 새로 보게 되는 것

화면 오른쪽 위에 **금고**가 생긴다. 처음엔 `0동`이다. 주민에게 벌목을 시키면 그가 5동을
버는데 그중 1동이 금고로 들어와 숫자가 `1동`, `2동`, `5동`으로 자란다 — 아무것도 안 해도
마을이 돌아가는 만큼 촌장의 장부가 차오른다. 굶는 주민에게 웃돈을 걸면 금고에서 10동이
**그 자리에서** 빠져나가고, 동시에 달력 줄의 물가 예보가 `→ 내일 ×1.05 ▲`로 튄다. 몇 번
더 걸면 예보가 `×1.4`까지 오르고 괄호가 열려 `(도는 돈 ×1.25 · 발행 여파 ×0.15)`라고
왜 올랐는지 말해 준다. 금고가 비어 웃돈을 못 걸게 되면 `M`을 눌러 돈을 찍을 수 있는데,
찍는 순간 아직 쓰지도 않았는데 예보가 먼저 뛴다 — 찍은 돈은 값이 더 떨어지기 때문이다.
`T`로 세율을 중과로 올리면 금고는 빨리 차지만 주민들이 벌목 명령을 마다하기 시작하고
말풍선으로 *"이만큼 떼가는데 뭐 하러"* 라고 한다. 판이 끝나면 연대기에
`세수 1,240동 · 발행 800동`이 남아, 이 판이 세금으로 굴린 판이었는지 찍어서 버틴 판이었는지가
기록에 박힌다.

**검산 — 회계·산식은 설계대로다.** 금고 10,115동 = 발행 약 101회 + 세수. 물가 4.0은

찍은 돈은 거의 전부 금고에 잠겨 있고 물가를 4배로 만든 건 통화량이 아니라 "찍었다는 사실"
자체다 — 의도대로다. 대가도 작동한다: 생식 2개가 3동 → **12동**, 웃돈 실질 가치 **0.25배**.

### 🔴 발견 A — 상한에 닿는 순간 발행이 공짜가 된다

### 🔴 발견 B — 상한에 닿는 순간 화면이 대답을 멈춘다

예보도 400으로 클램프되어 확정과 같아지므로 `→ 내일 …▲`가 **사라진다**. 더 찍어도 화면이
