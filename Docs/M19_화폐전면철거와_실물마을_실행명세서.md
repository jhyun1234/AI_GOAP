## 0. 왜 하는가 (한 문단)

이 게임의 정체성은 **"마을을 키우면서 야생동물·몬스터 격퇴로 성장하는 마을 게임"**인데,
M16~M18 세 밀스톤이 쌓은 화폐 축(개념 14종: 지갑·임금·원천징수·세율·금고·발행·한도·웃돈·
감쇠·물가 두 층·신뢰·직거래·빚·집값 연동)은 복잡도만 늘리고 방향에서 멀어졌다. 실측도
뒷받침한다: 세율 0% 판과 30% 판의 아사자가 동일(2명) — 재정 층이 판의 결과를 바꾸지 못했다.
동전 개념 자체를 제거하고, 대가는 실물과 관계로, 직업은 독점 대신 효율로 표현한다.

## 5. ADR-M19 (바꾸려면 사유를 커밋에)

- **ADR-M19-1 (전면 철거 = 삭제)**: 화폐 코드는 주석 처리·플래그 비활성이 아니라 **삭제**한다
  (ADR-M0-4). 단 append-only 규약 대상(SlotId 번호·EventId 값·RunEntry 필드)은 휴면 —
  "휴면"의 정의 = 선언은 남고 읽기·쓰기 지점이 0.
- **ADR-M19-2 (대가 = 실물 + 관계, 후불 원형)**: 부탁 보상은 `RewardCostSlot`(실물)로만.
  선불(AlwaysUpfront) 해제 — 실물 사례는 완공 후 마주침 정산(조각 Y 원형)이 정답이며,
  M17-R4의 선불 전환은 화폐 빚 아사에 대한 처방이었으므로 화폐와 함께 제거된다.
- **ADR-M19-3 (직업 = 효율, 독점 금지 복원)**: `ADR-M5-4` 원문이 다시 전면 규칙이다.
  이번 해소는 목수 예외 1건 — `RequiredJob`의 남은 용도는 치료 goal뿐이며(보완①),
  세 번째 용도는 규칙 재검토 신호(기존 문언 유지).
- **ADR-M19-4 (나눔은 거래가 아니다)**: 식량 나눔은 실물 일방 이전 + 관계 델타.
  반대급부 계산·교환비 개념을 붙이지 않는다 — 붙이는 순간 화폐의 재발명이다.

### W2 — 목수 독점 해제 + 건설 시간 배율 (효율 골격)

**대상**: `Assets/M0Config/Goals/Goal_BuildMyHouse.asset` · `Assets/Scripts/M0/Data/JobSO.cs` ·

```csharp
// JobSO — 기존 배율 선반에 append (ADR-M5-3 계열, 생존 계열 아님)
[Tooltip("건설 실행 시간 배율 (M19 — 효율 전문화). 1 = 현행(일반·무직·미배정 전부 불변). " +
         "목수만 <1 = 솜씨 보너스. ⚠️ 플래너 비용(BuildCostMult)과 다른 축 — 실행층 시간이다.")]
public float BuildDurationMult = 1f;

// BuildRunner — DurationSec 판정 오버라이드 (건설 러너만 — 채집·농사 무영향)
// 배율 유도는 VillagerAgent 한 곳: 직업 null = 1 (중립 불변식 M5-S3)
return Elapsed >= Action.DurationSec * agent.BuildDurationMultOfJob();
```

## 10. 재미 검증 (플레이어가 화면에서 새로 보는 것)

HUD에서 물가·세율·금고 숫자가 사라지고, 화면에는 마을의 것만 남는다: 나무·돌·식량·집·
사람. 집을 원하는 주민은 목수를 찾아가 부탁하고, 완공되면 저녁을 대접한다("이거 먹고 가!").
목수가 없거나 바쁘면 **자기가 직접, 두 배 느리게** 짓는다 — 목수의 가치가 독점이 아니라
솜씨로 보인다. 굶는 주민은 이웃에게 식량을 얻어먹고 그 은혜가 관계와 연대기("식량
얻어먹음(2개)")에 남는다. 동전 없이도 마을은 돌고, 화면의 모든 숫자는 이제 생존과 관계의
숫자다 — 다음 밀스톤(M20 직업, 그 뒤 위협·격퇴)이 설 자리가 여기서 정리된다.
