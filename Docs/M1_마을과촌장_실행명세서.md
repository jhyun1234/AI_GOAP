# M1 실행명세서 — 마을과 촌장 (자율 노동 · 식량 순환 · 명령/거부)

*작성일 2026-07-14. 전제: M0 완료 (W8 `b175ddf`, CLAUDE.md 개정 `04f0975`). 브랜치 m0-redesign 계속.*

---

## 0. 목적

M0가 "계획대로 사는 마을"을 만들었다면, M1은 세 가지 공백을 채운다:
1. **할 일이 없으면 정지** (W4 중간 리뷰 관측) → 여가 행동으로 마을이 항상 살아 보이게
2. **열매 고갈 → 아사 예정** (RawFood 노드 재생 0) → 식량 순환 완성
3. **플레이어가 구경꾼** → 게임 정체성인 **명령과 거부**의 첫 등장

## 1. AI 컨트롤 동작 예상 (이 명세의 설계 중심)

### 1.1 우선순위 사다리 — 주민의 머릿속

주민은 매 판단 시점에 아래 사다리를 위에서부터 내려오며 첫 번째로 걸리는 goal을 잡는다.
**명령은 사다리를 대체하지 않고 사다리의 한 칸에 꽂힌다** — 이것이 거부·중단·복귀가
자연스럽게 성립하는 이유다.

| Priority | Goal | 발동 조건 | 출처 |
|---|---|---|---|
| 100 | 배고픔 해결 | 포만감 ≤ 20 | 자율 (M0) |
| 90 | 휴식 | 피로 ≥ 90 | 자율 (M0) |
| **60** | **촌장 명령** | 명령 수락 시 주입 | **플레이어 (M1-C)** |
| 50 | 모닥불 건설 | 미완공 + 목재 5 | 자율 (M0) |
| 20 | 식량 비축 | 식량 < 15 | 자율 (M0) |
| 10 | 목재 수집 | 목재 < 30 | 자율 (M0) |
| 8 | 석재 수집 | 석재 < 30 | 자율 (M0) |
| **1** | **여가** | 항상 후보 (위가 전부 충족일 때만 도달) | **자율 (M1-A)** |

### 1.2 플레이어 조작 (M1-C)

- **좌클릭 주민** → 선택 (발밑 선택 링 표시, 다시 빈 곳 클릭/ESC → 해제)
- **선택 상태에서 우클릭 자원 노드** → "저거 캐와" 명령 (해당 자원 채집 명령 goal 주입)
- **선택 상태에서 우클릭 주민 자신** → 명령 취소 (자율 복귀)
- M1에서 명령은 이 두 가지뿐. 건설 지시·이동 지시는 M2.

### 1.3 거부 — 랜덤이 아니라 상태 기반 (舊 핵심 원칙 계승)

명령 수신 순간 주민이 판정한다:
```
포만감 < 35 (배고픔 근접)  → 거부: "지금은... 배가 너무 고파요."
피로   > 70 (탈진 근접)    → 거부: "숨 좀 돌리고요. 너무 지쳤어요."
둘 다 아님                → 수락: 말풍선이 명령 플랜으로 전환 (명령 강조색)
```
- 거부 사유는 항상 화면에 설명된다 (거부 말풍선 = 대사 변주 테이블의 첫 사용처)
- 임계값(35/70)은 **제안치** — AgentConfigSO 필드, Inspector 튜닝. P0 발동선(20/90)보다
  여유 있게 잡아 "아직 쓰러지진 않지만 시키면 싫은" 구간을 만든다 — 이 간극이 협상 게임의 씨앗

### 1.4 시나리오 워크스루 (구현 완료 시 실제 동작 예상)

1. 촌장이 주민 A를 클릭 → 링 표시. 돌 노드 우클릭.
2. A는 피로 78 → **거부**: "숨 좀 돌리고요…" 링은 유지, 명령은 미주입. A는 하던 여가 지속.
3. 촌장이 주민 B를 클릭 → 돌 노드 우클릭. B는 멀쩡 → **수락**. 말풍선 "[명령] 돌을 캐자 → …".
4. B가 채석 중 포만감 19 도달 → P0(100) > 명령(60) → **명령을 잠시 내려놓고 식사**.
   명령 goal은 사라지지 않는다 — 식사 후 사다리를 다시 내려오면 명령(60)이 최고 → **자동 복귀**.
5. 돌 30 달성(명령 goal 충족) → 명령 자동 소멸 → B는 자율 사다리로 복귀.
6. 아무도 시킬 일이 없고 창고가 그득하면 → 주민들은 모닥불 곁으로 모여 쉬거나 마을을 배회한다(여가).
   식량이 소비되어 15 미만이 되면 자연히 다시 일하러 나간다 — **일↔여가의 호흡**이 마을의 기본 리듬.

## 3. 재미 검증 — 플레이어가 화면에서 새로 보게 되는 것

플레이어가 처음으로 마을에 **손을 댄다**. 주민을 클릭하면 발밑에 링이 생기고, 돌무더기를
우클릭하면 주민이 "알겠어요, 돌을 캐올게요"라며 걸어간다 — 그런데 어떤 주민은 **"지금은
배가 너무 고파요"라며 거절한다.** 시킨 일을 하던 주민이 배가 고파지면 제멋대로 밥을 먹고
돌아오고, 할 일이 없어진 저녁의 주민들은 모닥불 곁에 모여 쉰다. "유닛에게 명령하는 RTS"가
아니라 "**자기 사정이 있는 사람들에게 부탁하는 게임**"의 첫 경험 — 게임 정체성(협상)의 데뷔전.

## 4. ADR-M1 (구현 중 갈릴 판단)

- **ADR-M1-1 (명령 = goal 주입)**: 명령은 별도 상태머신이 아니라 주민 개인 슬롯에 꽂히는
  GoalSO 참조 1개다. GoalSelector 사다리에 합류시켜 평가 — P0 인터럽트/복귀/충족 소멸이
  기존 메커니즘으로 공짜로 성립한다. 명령 전용 FSM 상태 추가 금지.
- **ADR-M1-2 (거부 = 데이터 주도)**: 거부 임계값·대사는 전부 SO 에셋. 거부 판정 코드에
  수치 리터럴 금지 (M0-T3 정신). 거부는 명령 **수신 시점 1회** 판정 — 수락 후 번복 없음
  (수행 중 힘들어지면 P0 인터럽트가 그 역할).
- **ADR-M1-3 (여가는 소비 없는 최하위)**: Goal_Leisure는 Priority 1, 어떤 자원도 생산·소비
  하지 않는다. 여가 중인 주민은 다른 goal이 발동하면 즉시 이탈 (기존 상위 goal 전환 로직).
- **ADR-M1-4 (재생률 에셋 이관)**: ResourceNode.GetDefaultRegenRate(코드 상수)는 ADR-M0-2
  위반 상태 — ResourceNodeSpawnConfig의 타입별 필드로 이관한다. 기존 값(Wood 5/Stone 3/
  Iron 1.5/Copper 0.5/Silver 0.2) 무변경 이관 + RawFood만 신규 결정.
- **ADR-M1-5 (대사 변주 = DisplayName의 일반화)**: ActionSO에 BubbleLines[] 추가, 비어
  있으면 DisplayName 폴백. 문구 선택은 표시 시점 랜덤 — 로직·플래너와 무관 (표현 전용).
