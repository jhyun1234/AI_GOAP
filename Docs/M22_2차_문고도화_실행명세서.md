## 0. 성공 기준 (숫자로)

1. **잠금 중 문 통과 0회**: 잠금 상태에서 주민 신규 경로의 문 타일 포함 0건
   (JPS가 우회 또는 Unreachable). 예외 = 한 걸음 관용: 토글 순간 문을 다음 칸으로
   이미 예약했던 주민의 통과 **최대 1회/인**.
2. **선별 재계획**: 토글 시 잔여 경로에 문 타일이 포함된 주민만 AbortPlan — 판정은
   순수 함수로 분리되어 게이트가 씬 없이 검산 (포함/미포함/관용 3케이스).
3. **해제 시 복원**: 해제 후 같은 출발·도착의 FindPath가 문 경유 PathFound.
4. **전환 원자성**: 완공 울타리 우클릭 1회 = 철거(나무 1 회수) + 문 계획 등록이
   한 호출에서 완결 — 중간 상태(철거됐는데 계획 없음)로 끝나는 경로 0.
5. EditMode 게이트 전체 green (기존 376 + 신규 ≥4). 신규 수치 발명 0
   (전환 비용 = 기존 철거 회수 1 + 문 건설 3 파생).
6. **관측 주 (리뷰①, 완주 후 1회)**: 위협 예고 → L 잠금 → 주민이 안에 머물고,
   밖에 남은 주민의 위험이 갈리는 장면이 화면에서 읽힌다 (합의 4 동형 — 수치는 보조).

## 1. 전제 확인 (0단계 실사 산출물 — 2026-08-09 코드 실사)

1. **L 키는 비어 있다** — `PlayerInputController` 어휘 = ESC·B·C·F·Y/N·숫자·Shift·Ctrl+F9.
   충돌 없음.
2. **우클릭 확장 지점이 이미 있다** — B 모드 우클릭은 `TryAddDefenseGate` 실패 시
   "여기에는 문을 둘 수 없습니다"로 끝난다 (`PlayerInputController.cs:342-352`).
   완공 울타리 위 우클릭이 정확히 이 분기로 떨어진다 → 전환 매크로의 자리.
3. **완공 문 열거는 공짜다** — `DefenseService._durability` 키 중 `slot == GateCount`
   (`NotifyBuilt`가 CountSlot으로 등록, `DefenseService.cs:330-336`). 문 등록부 신설 불필요.
4. **파괴가 잠금을 이기는 건 기존 코드가 이미 한다** — 소실 복구가 두 배열을 무조건
   true로 (`SimulationLoop.cs:839-840`, ADR-M22-6). 잠긴 문이 부서지면 구멍이 뚫린다 =
   의도와 일치. 신규 훅은 **잠금 중 신규 문 완공** 하나뿐 (완공 구독 `888-889` 확장).
5. **선별 Abort 재료 완비** — `_waypoints`+`_wpIndex`(잔여 경로), `_hasNextReserved`
   (한 걸음 관용 판정), `AbortPlan(reason, warn:false, cooldown:false)` 선례
   ("상위 목표 전환", `VillagerAgent.cs:521`). 신규 이동 코드 불필요.
6. **위협 배열은 만질 것이 없다** — 문은 `ThreatWalkable`에서 이미 false
   (`BlocksThreatPassage`, `SimulationLoop.cs:203`). 잠금은 주민 배열만 갱신한다.
7. **세이브는 미구현** (ADR-M0-10: 구현 M4+) — `GatesLocked`는 "세이브 대상" 주석
   선언만 한다.

## 2. ADR (구현 중 갈릴 판단 — 바꾸려면 사유를 커밋에)

### ADR-M22-8 · 구역 밖 집은 시스템이 구제하지 않는다 (합의 6 종결)

방어 구역(울타리) 밖 집 주민에 대한 시스템 개입은 없다 — **어디를 두를지가 공간 선택의
무게다.** 잠금은 이 무게를 날카롭게 한다(밖에 남은 주민은 못 들어온다) — 이는 결함이
아니라 이 결정의 표현이다. 이주 유도는 구역 이전 백로그([[project-zone-relocation]],
코드 선반영 금지 지시 2026-07-20)와 함께 봉인 유지.
**재론 조건**: 구역 밖 집 기인 사망이 반복 관측되고, 그것이 플레이어의 구역·잠금 선택으로
회피 불가능하다고 판정될 때.

### ADR-M22-9 · 잠금 = 이벤트 재계획 (매 틱 재검사 금지)

잠금은 드문 사건(플레이어 개입)이므로 비용은 **토글 순간에만** 낸다: ①완공 문 타일의
주민 통행 배열 갱신 ②잔여 경로에 문이 포함된 주민만 선별 AbortPlan(ADR-M0-11 재사용)
③표현(마커·정보줄). 이동 코어에 매 틱 Walkable 재검사를 넣지 않는다 — 실수요가 잠금
하나뿐이고, 1차가 ADR-M22-5로 피해 간 수술이다. 동적 개폐 실수요가 생기면 그때 사유와
함께 재론. **한 걸음 관용**: 토글 순간 문을 다음 칸으로 예약한 주민은 통과시킨다 —
예약 시스템과 싸우지 않는다. **파괴는 잠금을 이긴다**: 잠긴 문 파괴 = 두 배열 복구
(기존 ADR-M22-6이 처리) = 구멍. 잠금이 파괴를 막는 코드를 만들면 반려.
에셋(`Gate.asset`)은 무변 — 잠금은 배열 상태이지 건물 속성이 아니다.

### ADR-M22-10 · 전환 = 기존 창구 둘의 원자 합성

완공 울타리 → 문 전환은 `TryDemolishDefenseAt`(철거+회수) + `TryAddGatePlan`(문 계획)의
합성이며 **새 건설·제거·정산 경로를 만들지 않는다** (ADR-M0-3). 시공은 여전히 주민
노동이다(합의 2) — 즉석 완공 교체 금지. 문이 설 때까지 그 칸이 열려 있는 것은 정직한
대가다. 부분 성공 금지: 철거 후 계획 등록이 실패할 조건을 **철거 전에** 검사한다.
문→울타리 역방향은 만들지 않는다 (기존 철거+긋기로 가능, 수요 미관측).
**재고 판정 개정 (2026-08-09, 사용자 확정)**: 전환의 부족 판정은 1차 ADR-M22-4의 차단
규약을 따르되 **순 비용**으로 — 보유 + 회수(울타리 1) ≥ 문 비용(3)이면 허용. 매크로
자신이 만드는 회수를 셈에서 빼면 보유 2에서 가능한 전환을 막는 거짓 음성이 된다.

```csharp
// M0SimulationLoop — 전환 창구 (ADR-M22-10: 기존 두 창구의 원자 합성)
public bool TryConvertFenceToGateAt(Vector2Int tile, out int refund)
{
    refund = 0;
    if (Defense == null || !Defense.HasStructureAt(SlotId.FenceCount, tile)) return false;
    if (!Defense.CanPlanGateAt(tile)) return false;           // 철거 전 사전 검사 — 부분 성공 금지
    TryDemolishDefenseAt(tile, out refund);                   // 철거 + 나무 1 회수 (기존 W8)
    return TryAddDefenseGate(tile);                           // 문 계획 (기존 창구)
}
// PlayerInputController 우클릭 분기 개정 (기존 342-352):
//   TryAddDefenseGate 성공 → 기존 그대로
//   실패 && 완공 울타리 타일 → TryConvertFenceToGateAt → "울타리를 헐고 문을 냅니다 — 나무 1 회수"
//   그 외 → "여기에는 문을 둘 수 없습니다" (기존)
```
`CanPlanGateAt` = `TryAddGatePlan`의 실패 조건(중복 계획 등)에서 "타일 점유"만 뺀 순수
검사 — 철거 후 성공이 보장되는지 미리 판정한다.

## 8. 재미 검증 절 — 플레이어가 화면에서 새로 보게 되는 것

지금까지 위협 예고가 떠도 플레이어가 할 수 있는 일은 F(싸워라)와 구경뿐이었다. 이
명세가 끝나면: 예고가 뜨는 순간 **L 하나로 마을의 모든 문에 자물쇠가 걸리고**, 밖으로
나가려던 주민들이 문 앞에서 발길을 돌려 안에 웅크리는 — 농성이 시작되는 — 것이 보인다.
그리고 하필 그때 밖에 있던 한 명이 잠긴 문 저쪽에서 서성이는 장면이, 이 게임이 처음
갖는 "내 선택이 만든 안팎"의 극이다 (구역 밖에 집을 지은 것도, 문을 잠근 것도 플레이어의
선택이다 — ADR-M22-8). 위협이 지나가고 L을 다시 누르면 문이 열리고 일상이 재개된다.
울타리를 긋다 "여기가 출입구여야 했는데" 싶은 자리는 우클릭 한 번으로 헐리고 문 계획이
서서, 긋기 UX의 마지막 가시가 빠진다.
