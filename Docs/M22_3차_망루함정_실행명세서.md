## 0. 성공 기준 (숫자로)

1. **빈 망루는 탑일 뿐**: 탑승 주민 0명인 망루의 요격 0회 (망루 자체에 교전 코드가 없음을
   게이트가 구조로 증명 — 효과는 전부 탑승 주민 경유).
2. **탑승 요격**: 탑승 주민의 교전 사거리 = `Watchtower.TowerRangeTiles` (제안 6), 타격은
   기존 `CombatService.VillagerHit` 문 경유 — 새 판정 경로 0.
3. **함정 검산**: 위협이 함정 타일 진입 시 체력 −`TrapDamage`(**15 — 사용자 확정
   2026-08-09**, 제안 40은 "너무 높다"로 하향) + 함정 소멸 + `TrapCount` −1이 한 사건.
   늑대(HP 60) 검산: 60−15 = 45 > 도주선 24 → **함정은 한 방 격퇴가 아니라 소프트닝**이다
   — 3개 누적(60−45=15 < 24)이거나 주민 타격(10)과 합산해야 격퇴선 아래로. "한 방 격퇴
   금지"를 게이트로 박제한다 (값을 24 이상으로 올리면 red).
4. **브러시 UX**: B 모드 중 1/2/3 = 울타리/함정/망루 전환, 정보줄에 현재 브러시 표시.
   기존 긋기·우클릭 문·Shift 철거 회귀 0 (기존 게이트 green 유지).
5. EditMode 게이트 전체 green (기존 381 + 신규). 슬롯 지출 46 → **50/52** (잔여 2 — §1.5).
6. **에셋 판정 (관측 주)**: 리뷰①에서 사용자가 ①탑승/빈 망루 차이 ②함정 소모·재설치 루프
   ③새 그림(망루·함정·늑대)의 팩 이질감 없음을 판정. 늑대 실패 시 몬스터 전환 재질문.

**중간 리뷰⓪ (W3 직후)**: 주민이 망루에 올라 위협을 쏘는 동선이 화면에서 보이는가.

## 1. 전제 확인 (0단계 실사 산출물 — 2026-08-09 코드 실사)

1. **슬롯은 46/52다** (`SlotId.cs:126 Count = 46`) — 4칸 지출 후 50/52, 잔여 2칸.
2. **전역 "활성 위협" 슬롯은 없다** — 위협 파생은 `ThreatNear(21)`(개인 감지 반경,
   `ThreatService.IsNearThreat` 원천) 하나뿐. 예고 상태도 슬롯에 없다 (HUD는 서비스 직독).

## 2. ADR (구현 중 갈릴 판단 — 바꾸려면 사유를 커밋에)

### ADR-M22-11 · 빈 망루는 탑일 뿐 (효과는 전부 탑승 주민 경유)

망루 자체에는 교전 코드가 없다. 요격 = **탑승 중인 주민**의 타격이고, 사거리만 시설
에셋(`TowerRangeTiles`)이 늘려 준다. 자동 요격·탄약·쿨다운 등 시설 소유 전투 상태를
만드는 변경은 반려 — "완성되면 안전"(ADR-M22-2 위반 구조)으로 가는 문이다. 탑승 주민은
위협의 직접 타격 대상에서 제외되고(높이 — 희생 선정 필터 1조건), 대신 위협은 망루
(내구도 있는 시설)를 공성으로 부술 수 있다. 망루 파괴 = 탑승 즉시 해제 (부상 없음 —
1차는 관측, 낙하 피해는 실측 후).

### ADR-M22-12 · 탑승 트리거 = ThreatNear 재사용 (새 슬롯 금지)

`Goal_ManTower` 트리거는 기존 개인 파생 슬롯 `ThreatNear`다 — "위협을 감지한 주민이
망루로 뛰어 올라간다". 전역 위협 슬롯 신설은 슬롯 1칸 + 파생 배선을 더 쓰면서 그림이
달라지지 않아 기각 (기존 통로 우선 M11). ⚠️ 알려진 한계 = 감지 반경 밖 위협이면 아무도
안 올라간다 — 🟡 관찰 항목이며, "예고 단계 선탑승"이 필요해 보이면 그때 재론 (관측 근거
없이 미리 만들지 않는다 — ADR-V-7).

### ADR-M22-13 · 함정 = 소모, 발동의 문은 하나

함정은 내구도가 아니라 **소모품**이다: 위협 타일 진입 → `TrapDamage` 피해(위협 체력
차감은 기존 `ApplyHit` 문) → 시설 소멸(`RemoveCountableAt` 유일 경로) → **계획 복귀
없음**(소모는 파괴가 아니라 사용 — 철거 동형의 `Demolish` 선행) → 재설치는 플레이어가
다시 긋는다. 발동 판정 지점은 위협 이동의 타일 도착 **한 곳**뿐 — 두 번째 발동 경로
(스폰 위, 밀림 등)를 만들면 반려. 주민·방랑자는 밟아도 무해 (아군 오발 없음 — 위협
전용 판정, 통행 플래그 양쪽 0).

### ADR-M22-14 · 브러시 = B 모드 안 숫자키 (모드 신설 금지)

설치 대상 전환은 B 모드 **안**의 1/2/3 키다 (모드 중 숫자키는 배속에 닿지 않음 — 전제
확인 ⑦). 울타리 브러시 = 기존 전부(줄·우클릭 문·Shift 철거) 그대로 / 함정 브러시 =
줄(`LineTiles` 재사용) / 망루 브러시 = 1칸 클릭. 새 전역 키·새 모드를 만들면 반려 —
입력 어휘는 이미 B·L·C·F·Y/N·숫자·Shift로 꽉 차 있다.

### ADR-M22-15 · 에셋 자체 제작 — 팔레트 강제, 판정은 사용자 눈

새 그림(망루·함정·늑대)은 **기존 시트에서 추출한 Kenmi 팔레트 색만** 쓴다 (신규 색
발명 금지 — 이질감의 제1 원인). 제작 = 팩 조각 합성 기초 + 코드 직조(PNG 픽셀 생성),
그리고-임포트-스크린샷 비교 루프. **품질 판정은 게이트가 아니라 사용자 눈**이다 (미측정
주장 금지 — 내가 "어울린다"고 판정하지 않는다). 늑대 파일럿 실패 시 몬스터(팩 완비)
전환 여부를 사용자에게 재질문 — 조용한 대체 금지.

- **계획 고스트 舊 문 그림** (2차 이월 🟡) — 이번에도 관측만. 신규 시설 고스트는 기존
  문법(MarkerSprite)을 그대로 탄다.
- M21·M22 이월 관측 항목 — 리뷰⓪·①에 얹어 관측만.

## 7. 재미 검증 절 — 플레이어가 화면에서 새로 보게 되는 것

지금까지 방어는 벽이었다 — 서 있는 것만 일하고, 주민은 벽 뒤에서 F로 맞붙는 것 말고는
할 게 없었다. 이 명세가 끝나면: 위협을 감지한 주민 하나가 하던 일을 놓고 **망루로 뛰어가
올라서고**, 벽 밖의 늑대에게 화살이 날아간다. 같은 망루라도 **사람이 없으면 그냥 탑**이라
"누가 올라가 있는가"가 아침마다 다른 그림을 만들고, 목수가 죽은 판의 무너진 망루처럼
**빈 망루는 부재의 화면**이 된다. 울타리 앞 길목엔 플레이어가 그은 함정 줄이 깔려 있다가
늑대가 밟는 순간 터져 절뚝이며 물러나게 만들고, 터진 자리는 비어서 **다시 깔러 가는 노동**
이 생긴다. 그리고 이 모든 것 — 망루도, 함정도, 처음으로 그림을 입은 늑대도 — 이 팩에서
산 그림이 아니라 **우리가 만든 그림**으로 화면에 선다.
