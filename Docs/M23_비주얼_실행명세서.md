## 0. 성공 기준 (숫자로)

1. 울타리 줄이 **이어진 하나의 벽**으로 보인다 — 인접 칸끼리 조각(가로대·세로대·모서리·T자)이
   맞물리고, 파괴로 구멍이 나면 양옆 조각이 끝단으로 바뀐다 (조각 선택 검산 = 게이트,
   16조각 전 마스크 매핑 일치).
2. 문이 문 그림(`Fence_Big_Gate`)으로 보인다.
3. 주민 행동 모션 **5종**이 재생된다: 도끼질(벌목) · 곡괭이질(채석) · 괭이질(심기·수확) ·
   망치질(건설·수리) · 맨손 타격(교전). 해당 없는 액션은 기존 대기/걷기 그대로 (중립).
4. 계획 칸이 **반투명 고스트 조각**으로 보인다 (뭐가 설 자리인지 그림으로).
5. EditMode 게이트 전체 green (기존 373 + 신규), 배선된 스프라이트 참조 실재 (누락 0).

## 2. ADR

### ADR-M23-1 · 표현 파라미터도 에셋 — AnimKind는 ActionSO 필드

어느 액션이 어떤 몸짓인지는 코드 매핑 테이블이 아니라 **`ActionSO.Anim` 필드**가 정한다
(ADR-M0-1 액션 단일 응집의 표현 확장 — 말풍선 문구와 같은 지위). 스프라이트 칸은
`AgentSpriteSetSO.Actions`의 `{AnimKind Kind; Down/Side/Up}` append-only 배열 —
미등록 Kind = 대기/걷기 폴백 (중립 불변식: 배선 전 액션은 오늘과 완전 동일).
🔴 액션 이름으로 모션을 고르는 switch는 반려 (문자열 분기 금지의 표현판).

### ADR-M23-2 · 조각 선택은 순수 함수 — 이웃 = 울타리 ∪ 문

울타리 조각은 `static PieceOf(bool n, bool e, bool s, bool w)` 순수 함수가 4방 이웃
마스크로 정한다 (게이트가 16마스크 전수 검산). **이웃 판정에 문을 포함한다** — 문 곁
울타리가 끝단으로 보이면 벽이 끊긴 그림이 된다. 실제 조각-마스크 매핑은 구현 시
`Fences.png` 슬라이스 rect 좌표로 확정하고 게이트에 박제한다.

### ADR-M23-3 · 뷰는 옷만 입힌다 — 몸은 BuildingVisualizer 하나

방어물의 GameObject 생성·파괴는 지금처럼 `BuildingVisualizer`가 전담하고, 울타리 뷰는
`Spawn`이 반환한 몸의 `SpriteRenderer`에 **조각을 갈아입히고 이웃을 갱신**만 한다
(Dress 패턴). 두 번째 스폰 경로를 만들면 파괴·철거 때 한쪽이 유령으로 남는다.
뷰는 시뮬 상태를 쓰지 않는다 (표현 전용 — 기존 규약).

## 7. 재미 검증 절 — 플레이어가 화면에서 새로 보게 되는 것

지금까지 울타리는 갈색 원이 점점이 서 있는 추상화였고, 주민은 무엇을 하든 서 있는 그림이었다.
이 명세가 끝나면: 내가 그은 줄을 따라 **나무 울타리가 조각조각 맞물려 벽이 되고**, 문이 문처럼
달리고, 늑대가 부순 자리는 **끊긴 끝단**으로 한눈에 보인다. 주민들은 나무 앞에서 도끼를 휘두르고,
채석장에서 곡괭이를 내리찍고, 밭에서 괭이질을 하고, 울타리 앞에서 망치를 두드리고, 늑대 앞에서
주먹을 휘두른다 — "쟤가 뭘 하는지 보인다"(M13 후보 2번, 8일 만의 회수)가 마침내 화면에 도착한다.
