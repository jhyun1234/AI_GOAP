## 2. ADR

> 바꾸려면 **무엇을 관측했고 이 결정이 왜 실패하는가**를 커밋 본문에 남긴다.

### ADR-T-1 — 높이는 **그림의 언어**다 (절벽 = 막는 벽)

층(2.5D)을 만들지 않는다. 절벽·폭포·해변은 **통행 차단 + 장식**이고 게임은 평면이다.

**기각 근거** (되살리려는 유혹이 반드시 온다):
- 안 2(층 2~3단)는 이 프로젝트가 가장 비싸게 지켜온 이음매 **둘을 동시에** 깬다 —
  `IPathfinder.FindPath(int,int,int,int)` 시그니처(층 인자가 없다)와 `WorldSort` bias 규약
  (0~15만 쓴다. *"16 이상이면 한 타일을 건너뛰어 y 판정을 이긴다 — 그 순간 이 규약이 무너진다"*).
  `bool[,] Walkable`도 층당 한 장이 되어 `MapBounds.ToArrayIndex` 전 호출부가 파급된다.
- 안 3(높이 = 시야·사거리)은 **망루와 축이 겹친다**. "높은 곳 = 멀리 본다"는 M22 3차가 이미 갖고 있다.
- 사용자가 고른 성공 기준 4종 중 **층이 있어야만 생기는 항목이 하나도 없다.**
- 팩이 정확히 이 용법으로 만들어져 있다 (`Cliff` + `Waterfall` + `Bridge` + `Beach`).

> 🔑 **되살릴 조건**: 맵이 커져 `HPA*`를 얹을 때가 오면 `IPathfinder`를 어차피 손댄다.
> **층은 그때 같이 하면 절반값**이다. 지금 하면 제값을 다 낸다.

### ADR-T-2 — 경로탐색은 A\*로 간다 (실측 근거)

`ADR_경로탐색_확장경계.md`의 **트리거 A**(가중치 도입) 발동. 그 문서는 *"알고리즘 최종 선택은
프로파일링 실측 후에 한다"* 고 했고, 실측했다 (2026-08-10, 우리 맵·질의 200건):

| 맵 조건 | JPS | A\* |
|---|---:|---:|
| 빈 벌판 (오늘) | 0.224 ms/건 | **0.013** ms/건 |
| 흩뿌린 장애물 12% | 0.050 ms/건 | **0.020** ms/건 |
| 호수·절벽(긴 벽+좁은 길) | 0.062 ms/건 | **0.026** ms/건 |

**세 조건 모두 A\*가 빠르다.** 이유: 우리 맵은 100×100(10,000칸)으로 **작고 뻥 뚫려 있다.**
JPS의 점프 스캔이 빈 벌판에서 맵 끝까지 달려 손해를 보는 반면(그래서 ①이 JPS 최악값),
A\*는 옥타일 휴리스틱이 거의 완벽해 **평균 66칸**만 열고 도착한다.

⚠️ **공정 고지 2건** (게이트가 이 전제를 감시한다):
- 벤치의 A\*는 배열을 재사용하는 시험 구현이라 격차의 일부는 **구현 차이(할당)** 일 수 있다.
  → 배포 구현도 **버퍼를 재사용**한다 (W1 DoD).
- 가중치가 들어오면 휴리스틱이 약해져 확장 수가 는다. 66~122칸에서 출발하니 여유가 크지만,
  **기준선을 게이트에 박아** 회귀를 잡는다 (성공 기준 ③).

🔴 **JPS는 지우지 않는다.** `IPathfinder` 구현체로 **병존**시킨다 — 되돌릴 길을 남기고,
맵이 커졌을 때 균일 비용 구역의 solver로 다시 쓸 수 있다 (ADR 원문의 "JPS 위에 HPA\*").

### ADR-T-3 — 지형은 **주민과 위협에게 똑같이** 걸린다

늪이 주민만 느리게 하면 그건 페널티고, **둘 다** 느리게 해야 **방어선**이 된다 (사용자 판정).
🔴 통행 배열이 **두 장**임에 주의한다 — `Walkable`(주민)과 `ThreatWalkable`(위협, ADR-M22-1).
비용도 **두 장이 아니라 한 장**을 공유한다: 지형 비용은 개체 종류와 무관하기 때문이다
(문은 통행 규칙이 다르지만 **늪은 누구에게나 늪이다**).

### ADR-T-4 — 판 시드는 **하나**이고 **기록된다**

지금 노드 배치 시드는 `randomSeed: 0` → 매 실행 `Random.Range`라 **익명**이다. 즉 오늘도
맵은 판마다 다르지만 **어떤 판이었는지 아무도 모른다** — 같은 판을 다시 볼 수 없다.
1차에서 **판 시드 하나**를 뽑아 지형·노드가 **둘 다 거기서** 나오게 하고, 연대기에 남긴다.
- 🔑 이래야 `ADR-M10R-2`(같은 시드 = 같은 판)가 **맵까지** 덮는다.
- 세이브 대상 선언 (`ADR-M0-10`).

### ADR-T-5 — 지형은 **좌표의 함수**다 (저장하지 않는다)

타일 지형 = `f(판 시드, x, y)` 인 순수 함수. 10,000칸 배열을 저장·직렬화하지 않는다.
- 순수 함수라 **게이트로 전수 검사**가 되고, 로드가 곧 재계산이라 어긋날 여지가 없다.
- ⚠️ **캐시는 둔다** (틱마다 부르므로) — 캐시는 파생이고 원본은 함수다.

### ADR-T-6 — 늪의 대가는 **비용과 속도 둘 다**

경로 비용만 올리면 주민이 **돌아갈 뿐** 느려지는 걸 아무도 못 본다(표현 0).
속도만 낮추면 **일부러 늪으로 들어간다**(경로가 모른다). **둘 다** 걸어야 인과가 닫힌다.
- 두 수치의 원천은 **에셋 한 곳**(`TerrainTypeSO`) — 갈라 두면 반드시 어긋난다 (ADR-M0-2).

/// <summary>
/// A* 경로탐색 (M26-1차 W1, ADR-T-2) — **가중치 네이티브**. JPS는 "모든 칸 비용 균일"을
/// 전제로 대칭 가지치기를 하므로 늪 같은 가변 비용이 들어오면 못 쓴다.
///
/// 🔑 JPS 를 지우지 않고 **병존**시킨다 (되돌릴 길 + 맵이 커졌을 때 균일 구역 solver).
/// 🔑 버퍼는 인스턴스가 **재사용**한다 — 실측 격차의 일부가 할당이었을 수 있어(ADR-T-2 고지),
///    배포 구현이 그 변수를 없앤다. ⚠️ 그래서 **스레드 안전하지 않다** (M0는 단일 스레드).
/// </summary>
public sealed class AStarPathfinder : IPathfinder
{
    private readonly Func<bool[,]> _walkableSource;
    private readonly Func<int, int, float> _enterCost;   // null = 균일 비용 (배선 전 = JPS 와 같은 답)
    private float[] _g; private int[] _parent; private byte[] _state;
    private int[] _heapIdx; private float[] _heapF;      // 이진 힙 (재사용)

    public PathResult FindPath(int startX, int startY, int goalX, int goalY) { /* 옥타일 휴리스틱 */ }
}
```

**비용 창구** — `ADR_경로탐색_확장경계.md` §경계 2가 예고한 자리 그대로:

// SimulationLoop — 통행 질문의 단일 지점 곁에 비용 질문 하나를 나란히 둔다.
// 미배선(Terrain == null)이면 1 = 균일 = 오늘과 같은 답 (중립 불변식).
private float TileEnterCost(int x, int y) => Terrain != null ? Terrain.EnterCost(x, y) : 1f;
```

**대상 파일**: `Assets/Scripts/M0/World/TerrainService.cs`(신규) ·

```csharp
/// <summary>지형 1종의 성질 (M26-1차 W2) — **코드에 지형 표를 두지 않는다** (ADR-M0-2).
/// 종류를 늘리는 것 = 에셋 1개, 코드 0줄 (`ADR-M25-2` 정신의 재사용).</summary>
public sealed class TerrainTypeSO : ScriptableObject
{
    public string DisplayName;          // "늪"
    public bool Walkable = true;        // false = 물·절벽 (주민·위협 **둘 다**, ADR-T-3)
    [Min(1f)] public float EnterCost = 1f;      // 경로 비용 (늪 제안치 3)
    [Range(0.1f, 1f)] public float MoveSpeedMult = 1f;  // 실제 감속 (늪 제안치 0.5) — ADR-T-6 짝
    public Color GroundColor;           // W5 바닥 색
    public float NodeDensityMult = 1f;  // 이 지형의 자원 밀도 (2차에서 쓴다 — 지금은 1)
}
```

```csharp
/// <summary>지형 지도 (M26-1차 W2) — 타일 지형은 **좌표의 함수**다 (ADR-T-5).
/// `f(판 시드, x, y)`로 결정되며 배열을 저장하지 않는다. 캐시는 파생일 뿐이다.
/// 🔑 시드가 같으면 지도가 같다 — `ADR-M10R-2`가 **맵까지** 덮는 지점.</summary>
public sealed class TerrainService
{
    public TerrainService(uint runSeed, TerrainTypeSO[] palette, TerrainTypeSO fallback) { }
    public TerrainTypeSO At(int tileX, int tileY);      // 캐시 경유
    public bool IsWalkable(int x, int y) => At(x, y).Walkable;
    public float EnterCost(int x, int y) => At(x, y).EnterCost;
    public float SpeedMult(int x, int y) => At(x, y).MoveSpeedMult;
}
```

**생성 규칙** — 값 노이즈(좌표 해시 보간) 2장:
① **습도** → 물 / 늪 / 평지, ② **고도** → 절벽 / 평지. 둘의 조합으로 팔레트를 고른다.
🔑 **`PickVariantIndex`가 이미 쓰는 좌표 해시 기법의 확장**이다 (나무 3종이 그렇게 갈린다) —
새 수학을 들여오지 않는다.

**팔레트 5종** (1차): 평지 · 숲 · 늪 · 물 · 절벽. (정글·광산·모래는 **2차** — 자원이 붙어야 뜻이 생긴다)

| 지형 | Walkable | EnterCost | SpeedMult | 근거 |
|---|:---:|---:|---:|---|
| 평지 | ✅ | 1 | 1.0 | 기준 |
| 숲 | ✅ | 1 | 1.0 | 1차에서는 **자원 밀도만** 다르다 (느리게 만들면 벌목이 벌이 된다) |
| 늪 | ✅ | **3**(제안) | **0.5**(제안) | ⚠️ 제안치. 착수 시 **Play로 조정** — 비용 3 = "3배 돌아가도 이득" |
| 물 | 🔴 | ∞ | — | 차단 (2차에서 물고기가 **물가**에 붙는다 — 물 위가 아니다) |
| 절벽 | 🔴 | ∞ | — | ADR-T-1 |

🔴 **커밋 1 직후에도 한 번 본다**: 엔진을 갈았는데 경로가 오늘과 같아야 한다. 다르면 그 자리에서 멈춘다.

## 12. 재미 검증 — 플레이어가 화면에서 무엇을 새로 보게 되는가

지금까지 맵은 **끝없는 초록 벌판**이었다. 어디에 마을을 세우든 같았고, 어디로 가든 같은 시간이
걸렸다. 자원이 멀다는 것은 **기다림**일 뿐 선택이 아니었다.

이 차수가 끝나면 새 판을 시작할 때마다 **다른 땅**이 깔린다. 서쪽에 호수가 있는 판이 있고,
마을 남쪽이 늪으로 막힌 판이 있다. 주민이 채집하러 나서면 **호수를 빙 돌아** 걸어가고,
늪에 발을 들이면 **눈에 띄게 느려진다** — 그리고 고블린도 그 늪에서 똑같이 느려진다.

그래서 플레이어는 처음으로 **땅을 보고 판단하게 된다**: *"저 늪 뒤쪽은 안전하겠군."*
그리고 판이 끝났을 때 남는 말이 달라진다 — *"이번 판은 호수에 갇힌 판이었어."*

## 13. 2·3차 예고

- **2차 (멀리 갈 이유와 대가)** — 정글·광산·모래 + 물고기(`RawFood`, 물가에 선다) + 늪 희귀자원
  + 거리=희귀도(기존 `min/maxDistanceFromBase` 활용) + **들판 상주 위협** + 위험 기억(당해 보고)
  + **채집 선택 통로**(🔴 지금 `FindNearestDiscovered`가 최근접 하나만 봐 "가까운데 위험 vs 먼데
  안전"을 비교할 자리가 **구조적으로 없다** — 2차의 심장) + 구조 명령 UI(치료사 클릭 →
  *"누구를 치료하러 갈까요?"* → 부상자만 목록) + **위치 없는 부상 알림**.
  ⚠️ 2차 설계 시 반드시 다시 볼 것: ①치료사 없는 판 ②구조하러 간 사람도 위험 ③들판 사망 시계가
  "맵 끝까지 걷는 시간"보다 짧으면 구조가 **구조적으로 불가능**해진다.
- **3차 (희귀자원이 값을 한다)** — 더 센 방어 시설 · 상위 함정 · 대장간.
  ⚠️ **대장간은 대장장이 직업을 부른다** — 현재 8종에 없고, 직업을 늘리는 것은 M25 3차의 몫이다.
