## 0. 목적

식량 원천이 "열매 재생" 하나뿐인 단일 실패점을 해소하고, 마을을 "생존"에서 "살림"으로 올린다:
**밭 짓기 → 심기 → (게임일 성장) → 수확 → 모닥불에서 요리 → 조리된 식사.**
동시에 이번 밀스톤은 두 가지 구조 확장의 첫 사례다:
- **건물 = 행동의 무대** 일반화 (사용자 확정 방향): 행동의 장소는 전제조건(플래너 축) +
  앵커(실행 축) 두 에셋 필드로 표현. 추후 집/병원/대장간이 같은 공식으로 들어온다.
- **수량형 건물** (밭 N개): 단일 플래그(CampfireBuilt) 구조를 개수 슬롯으로 확장 —
  추후 "집 여러 채, 가장 가까운 곳으로"의 기반.

## 2. 재미 검증 — 플레이어가 화면에서 새로 보게 되는 것

모닥불이 완성된 마을에서 주민들이 흙을 일궈 **밭**을 만들고, 씨를 심고 — **밭이 날마다
자라는 것이 보인다** (빈 흙 → 새싹 → 익은 작물). 익으면 거둬서 모닥불로 가져가 요리하고
("찌개라도 끓여볼까"), 김이 나는 밥을 모닥불 곁에 모여 먹는다. 말풍선에는 이 게임 최초의
3단 멀티스텝 플랜([작물을 거두자 → 요리하자 → 밥을 먹자])이 떠서, GOAP가 "계획하는 AI"임을
플레이어가 가장 선명하게 읽게 된다. 열매 따기는 흉년의 보조 수단으로 물러난다.

## 3. ADR-M2 (구현 중 갈릴 판단, 바꾸려면 사유를 커밋에)

- **ADR-M2-1 (시간 분리 원칙)**: 성장 대기가 끼는 체인은 한 플랜으로 묶지 않는다.
  심기 goal과 수확 goal은 별개이며, 둘 사이는 FarmService의 게임일 성장 틱이 잇는다.
  "심기→수확"을 플래너가 연결하도록 대기 액션·시간 슬롯을 발명하는 것 금지.
- **ADR-M2-2 (건물 = 행동의 무대 + 앵커 승격 체인)**: 장소 제약은 액션 에셋의 두 필드로만
  표현 — Preconditions의 건물 플래그(플래너 축) + **AnchorPriority[] (실행 축, 우선순위
  목록)**. 러너는 목록에서 "지어진 첫 건물"을 무대로 삼고, 전부 없으면 기지 폴백.
  후반 전용 건물 도입(부엌 등, 사용자 확정 방향: 초반 모닥불 요리 → 후반 부엌에서
  요리·식사) 시 에셋 배열 맨 앞에 새 건물을 추가하는 것만으로 이주 완료 — 코드 0줄.
  장소 분기 코드 금지.
- **ADR-M2-3 (수량형 건물)**: BuildingSO.CountSlot(수치 슬롯) 설정 시 수량형 —
  Complete()는 CountSlot +1, 중복 완공 거부 없음, 완공 위치는 슬롯별 **목록**으로 기록.
  BuiltFlagSlot(단일형)과 배타 사용. 단일형 기존 동작 무변경.
- **ADR-M2-4 (파생 슬롯의 원천)**: EmptyFarmPlot/RipeCropAvailable은 FarmService가
  유일한 원천 (DiscoveryService의 NearDiscovered*와 동일 패턴). 플래너 효과의 해당 슬롯
  기입은 플래너 전용이며 EffectApplier는 무시한다 (기존 논리형 슬롯 규칙 그대로).
- **ADR-M2-5 (P0 쿨다운 면제)**: GoalSO.SkipFailureCooldown(bool) — P0 생존 goal 2종에
  설정. 실패해도 재시도 벌칙 없음 (관찰 항목 ① 해소: 굶는데 여가 가는 상황 원천 차단).
  P0 외 goal에 남용 금지 — 공회전 방지 장치를 무력화한다.
- **ADR-M2-6 (요리는 소비 계열 재사용)**: CookMeal은 신규 계열이 아니라 ConsumeActionSO
  에셋이다 (모닥불 앵커 + RawFood 소비 + CookedFood 산출 = 기존 필드로 전부 표현 가능).
  새 러너를 만들지 않는다 — M2-S3(.cs 0개)의 근거.
