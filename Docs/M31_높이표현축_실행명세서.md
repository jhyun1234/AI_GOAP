## §0. 성공 기준 (숫자)

1. **벽은 두 줄이다**: 고지대 남쪽 가장자리부터 `WALL_ROWS`(제안치 2)줄만 통행 불가.
   게이트가 배포 시드 3개 전수로 "벽 줄 수 ≤ 2" 검사.
2. **막힘 비율**: 현재 **17%**(절벽 10.7% + 물 6%) → **7~9%**로 내려간다 (실측 기반 예측 §1-6).
   `M26_T8`(1% < 막힘 < 30%)은 계속 green — red가 나면 그건 이 축이 아니라 밴드 문턱 문제다.
3. **연결성**: 시드 20개에서 **고지대 타일의 95% 이상이 마을(0,0)에서 도달 가능**
   (남쪽만 벽이라 북·동·서로 열려 있어야 정상 — 5% 미만의 고립은 호수에 갇힌 판과 같은 급).
4. **결정성**: 같은 시드 = 같은 벽 (높이는 지형의 함수이고 지형은 좌표의 함수 — ADR-T-5 승계).
5. 게이트 492 → **+5 내외 green**. 프레임: 벽 스프라이트 포함 표면 렌더 **1000개 이하 / 60fps 이상**
   (현재 314개·705fps — §1-7).

## §0.5 재미 검증 — 플레이어가 화면에서 새로 보는 것

지금 절벽은 "회색으로 칠해진 못 가는 땅"이다. 이 축이 끝나면 **위에서 내려다보는 바위 벼랑**이
선다 — 고지대 위에는 풀이 자라고 주민이 올라가 걸을 수 있고, 남쪽 면은 바위가 층층이 쌓인
벽이며, 그 아래엔 굴러떨어진 잡석이 흩어져 있다. 산악 지대는 "회색 얼룩"에서 **위아래가 있는
지형**이 되고, 광석을 캐러 가는 길이 "돌아가는 길"에서 **"어디로 올라가야 하는가"**가 된다.
🔑 화면에 처음으로 **높이**가 생긴다 — 지금까지 이 게임의 맵은 완전한 평면이었다.

## §2. 설계 — 높이 모델 (이 명세의 심장)

```
HeightLevel(x, y) = At(x, y).HeightLevel          // 0 = 저지대, 1 = 고지대 (에셋 값)

IsWallRow(x, y):                                   // 이 칸이 '벽면'인가
  h = HeightLevel(x, y)
  if h == 0: return false
  for k in 1..WALL_ROWS:                           // 남쪽으로 WALL_ROWS 안에 낮은 땅이 있으면
    if HeightLevel(x, y - k) < h: return true      //   이 칸은 그 벽의 일부다
  return false

IsWalkable(x, y) = At(x,y).Walkable && !IsWallRow(x, y)
```

- **고지대 지형 에셋의 `Walkable`은 `true`로 바뀐다** (절벽 위는 땅이다). 통행 불가는
  `IsWallRow`가 만든다 — 물(`Walkable false`)과 원리가 갈린다: 물은 어디서나 못 지나고,
  절벽은 **가장자리만** 못 지난다.
- **벽은 남쪽만**이다 (팩 아트가 남향 면만 갖는다). 북·동·서 가장자리는 rim만 그리고 통행은
  열려 있다 — 그래서 고지대가 섬이 되지 않는다 (§0-3 연결성 기준의 근거).
- 렌더 (W2): 벽 줄 `k`(남쪽 가장자리에서 0,1)마다 벽면 스프라이트를 그 칸에 그리고,
  벽 아래 첫 저지대 칸에 **기단 잡석**을 얹는다 (장식과 같은 층 — 통행엔 무관).
- 캐시·결정성 계약 그대로: 높이는 지형의 함수, 지형은 좌표의 함수.

## §3. ADR-M31 (바꾸려면 사유를 커밋 메시지에)

- **ADR-M31-1 (높이는 지형이 갖는다)**: 별도 높이 배열·노이즈를 만들지 않는다. `HeightLevel`은
  `TerrainTypeSO`의 필드이고, 높이 지도는 지형 지도의 파생이다. 이유: 높이를 따로 두면 지형과
  어긋나는 순간(밴드 문턱을 돌릴 때마다) 벽이 허공에 선다 — **두 지도는 반드시 한 함수에서 나온다.**
- **ADR-M31-2 (벽은 남쪽만·두 줄)**: 사방을 벽으로 두르지 않는다. 팩 아트가 남향 면만 갖는
  것이 첫째 이유이고, 사방이 벽이면 **고지대가 섬이 되어 그 위의 광석이 스폰 낭비**가 되는 것이
  둘째다 (M29 W3 ⚠️③의 재발). 올라가는 길은 북·동·서다.
- **ADR-M31-3 (통행은 창구 하나에서만 바뀐다)**: `TerrainService.IsWalkable` **한 줄**만 고친다.
  주민·위협·노드 스폰·A*는 구워진 배열을 보므로 자동으로 따라온다 (실사 #1). 두 번째 통행 판정
  경로가 필요해 보이면 설계 오류 — 멈추고 질문 (ADR-M0-3의 지형판).
- **ADR-M31-4 (얇은 띠는 벽이 아니라 땅)**: 세로 런이 `WALL_ROWS`보다 얇은 절벽 띠(실측 6%)는
  **전부 벽**이 된다(위 식이 그렇게 답한다). 이것을 "얇으면 통째로 지면"으로 바꾸지 않는다 —
  1칸짜리 바위 턱이 못 지나는 것은 자연스럽고, 예외 규칙을 하나 만들면 벽 두께가 좌표마다
  달라져 렌더가 두 규칙을 갖게 된다.
- **ADR-M31-5 (경사로 봉인)**: 고지대 진입은 **북·동·서로 돌아가는 것**이 전부다. 경사로·계단·
  다층(2단 이상)은 이 축에서 설계하지 않는다 — 경로탐색에 "층" 개념이 들어가는 순간
  `ADR_경로탐색_확장경계`의 새 트리거가 된다 (그 문서에 트리거 C로 예약만 한다).

## §W1. 높이 모델 — 통행 재정의

- **파일**: [TerrainTypeSO.cs](../Assets/Scripts/M0/Data/TerrainTypeSO.cs) (`HeightLevel` 필드 신설) ·
  [TerrainService.cs](../Assets/Scripts/M0/World/TerrainService.cs) (`IsWallRow` + `IsWalkable` 1줄 ·
  `WALL_ROWS` 알고리즘 상수) · 절벽 에셋 3장 (`Walkable 0 → 1`, `HeightLevel 1`) ·
  [M26_TerrainGates.cs](../Assets/Tests/EditMode/M26_TerrainGates.cs) (T8 막힘 기대값 주석 갱신)
- **스케치**:
  ```csharp
  // TerrainTypeSO
  [Tooltip("이 지형의 높이 (0 = 저지대, 1 = 고지대). 고지대는 **위를 걸을 수 있고**, " +
           "남쪽 가장자리 두 줄만 벽이 된다 (M31). 높이를 따로 안 두고 지형이 갖는 이유 = ADR-M31-1.")]
  [Min(0)] public int HeightLevel;

  // TerrainService — 벽 줄 수는 알고리즘 상수 (팩 아트의 벽면이 두 줄이다)
  private const int WALL_ROWS = 2;

  /// <summary>이 칸이 절벽 '벽면'인가 — 남쪽 WALL_ROWS 안에 더 낮은 땅이 있으면 그렇다.
  /// 🔑 통행 불가는 지형이 아니라 **가장자리**가 만든다 (ADR-M31-2).</summary>
  public bool IsWallRow(int tileX, int tileY)
  {
      TerrainTypeSO t = At(tileX, tileY);
      if (t == null || t.HeightLevel <= 0) return false;
      for (int k = 1; k <= WALL_ROWS; k++)
      {
          TerrainTypeSO below = At(tileX, tileY - k);
          if (below == null || below.HeightLevel < t.HeightLevel) return true;
      }
      return false;
  }

  public bool IsWalkable(int tileX, int tileY)
  {
      TerrainTypeSO t = At(tileX, tileY);
      return (t == null || t.Walkable) && !IsWallRow(tileX, tileY);   // ← 바뀌는 유일한 줄
  }
  ```
- **DoD**:
  - [ ] 절벽 3종 에셋이 `Walkable 1` · `HeightLevel 1`이고 OnValidate 경고 0
  - [ ] 배포 시드 3개 전수: 통행 불가 타일 중 절벽 계열은 **전부** `IsWallRow`가 true
  - [ ] 배포 시드 3개 막힘 비율이 **7~9%** (개조 전 17% — 로그로 출력해 명세 §0-2와 대조)
  - [ ] `M26_T8` green (1% < 막힘 < 30%) · 게이트 전체 green · `dotnet build` 2벌 0오류
- **⚠️ 오해 위험**: ①`HeightLevel`을 **북쪽**으로 재서 벽을 위에 세우기 — 화면에서 벽이 고지대를
  가리고 아래가 뻥 뚫린다 (남쪽 = y 감소 방향이다). ②`Walkable`을 그대로 두고 `IsWalkable`에만
  높이를 더하기 — 에셋이 "못 지나는 땅"이라고 말하는데 서비스가 지나가게 해서 **두 값이 서로
  거짓말**을 한다 (에셋의 `Walkable`을 참으로 바꾸는 것이 이 W의 절반이다). ③`WALL_ROWS`를
  에셋 값으로 승격 — 벽 줄 수는 **팩 아트가 정한 그림 사실**이지 밸런스 수치가 아니다.
