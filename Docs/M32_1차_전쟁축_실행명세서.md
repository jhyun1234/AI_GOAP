## 0. 왜 이 축인가 (사용자 판정 2026-08-16)

> *"또 다시 많은 기능들이 생겨서 복잡해졌다."*

진단은 시스템 수가 아니다. **지는 조건이 없어서**다. M0~M31 서른한 축이 전부 생존 시뮬에
얹혔는데 이 게임은 아직 아무도 못 진다. 필수가 아닌 시스템은 장식이고, 장식이 서른한 개면
복잡해 보인다.

**함락이 생기면 서른한 축을 재는 자가 생긴다:**

> 🔑 **이 시스템이 D-day 결과를 바꾸는가? 아니면 삭제 후보.**

이 명세는 그 자를 세우는 차수다. **철거 자체는 이 차수의 목적이 아니다** — 자를 세우고,
가장 싼 방법(에셋 등록 해제)으로 첫 삽만 뜬다.

## 1. 전제 확인 (실사 ① — 코드로 확인한 것 / 어긋난 것)

### 1.1 🔴 어긋난 전제 넷 — 브레인스토밍에서 말한 것이 틀렸다

| # | 말했던 것 | 실제 (실사 2026-08-16) | 명세에 미치는 영향 |
|---|---|---|---|
| ① | "성격 축이 **15개**" | **6개**다 — `TraitId.cs:16~21` = Diligence · Foresight · Sociability · Wanderlust · Willfulness · **Caution**(겁: 담대↔조심) | **"겁/용맹 한 축만 남긴다"의 신설분이 0이다.** `Caution`이 이미 그 축이다. W1은 나머지 5축을 끄는 일만 한다 |
| ② | "무기를 새로 붙여야 한다" | `SlotId.MyHasWeapon`(40) 이 **이미 있다** — 원천 = `VillagerAgent.AcquireWeapon`. 그리고 `CombatService.HitInterval(baseSec, jobMult, hasWeapon, weaponMult)` 가 **무기를 배율로 이미 받는다** (`ADR-M21-5`: 무기는 게이트가 아니라 배율) | **병과가 코드 0줄로 선다.** 검·활·도끼 = `weaponMult` 셋 |

## 5. ADR (구현 중 갈릴 판단 — 바꾸려면 사유를 커밋 본문에)

- **`ADR-M32-1` 함락은 새 경로가 아니다.** `ShouldShowGameOver`를 **확장**한다. 두 번째
  게임오버 경로를 만들면 `ADR-M0-3`(상태 쓰기 단일 지점) 위반이다.
- **`ADR-M32-2` 진영은 인스턴스지 플래그가 아니다.** `if (isEnemy)` 분기를 쓰는 순간 반려 —
  `ADR-M0-1`(이름 분기 금지)의 정신 계승. 진영별 서비스 11종을 `Faction` 객체가 소유한다.
- **`ADR-M32-3` 저쪽 주민의 경로는 예산 아래로 들어간다.** `ADR-M28-4`가 예산을 면제한 근거는
  *"주민 계획 실행은 게임 코어"* 다. **저쪽은 플레이어의 게임 코어가 아니므로** 그 면제가 안 선다.
- **`ADR-M32-4` 무기는 여전히 배율이다** (`ADR-M21-5` 계승). 병과는 게이트가 아니다 —
  맨손도 싸우고, 다만 느리다. 검·활·도끼는 `weaponMult` 세 값이다.
- **`ADR-M32-5` 이번 차수에 `.cs`를 지우지 않는다.** 철거는 **에셋 등록 해제로만**.
  *"없어도 재밌더라"* 가 Play로 확인된 뒤에 삭제한다 (그때 `ADR-M0-4` 폐기=삭제 적용).
- **`ADR-M32-6` 교전 대상은 인터페이스다.** `CombatService`가 `ThreatAgent`를 직접 받지 않는다.
  타격자가 ID 문자열인 것과 같은 이유다 (`CLAUDE.md` 후반 확장 규칙 ①).
- **`ADR-M32-7` 저쪽 마을은 안 보이면 느리게 돈다.** LOD는 최적화가 아니라 **게임 규칙**이다 —
  정찰하지 않은 것은 알 수 없다. 틱 감속의 근거를 성능으로만 적으면 안 된다.
- **`ADR-M32-8` 창·방패를 만들지 않는다.** 팩에 없는 물건이다. 방어는 **사람이 아니라
  목책·망루가 진다**(M22). 금지선은 「게임에 없는 물건」이지 「시트에 없는 프레임」이 아니다.

```csharp
/// <summary>판이 끝나는 사유 (M32-W2) — 표시 문구와 아카이브 기록의 유일한 분기 키.
/// append-only: 새 사유는 뒤에만 붙인다 (아카이브 호환, ADR-M14-3 정신).</summary>
public enum RunEndReason
{
    None      = 0,
    Wiped     = 1, // 전멸 — 주민이 있었던 마을이 0명 (M10-F 계승)
    Overrun   = 2, // 함락 — 저쪽이 마을 중심에 닿았다 (M32 신설)
}

/// <summary>판 종료 판정 (순수 — 게이트 M32-T1). 舊 ShouldShowGameOver 확장:
/// 인자가 늘었을 뿐 **전멸 경로의 진리표는 한 글자도 안 바뀐다**(중립 불변식).
/// 🔑 함락을 전멸보다 **뒤에** 본다: 전멸과 함락이 같은 프레임에 성립하면 「전멸」이다 —
/// 사람이 다 죽은 마을에 「함락됐다」는 두 번 세는 것이다.</summary>
public static RunEndReason ResolveRunEnd(bool alreadyShown, bool everHadAgents,
                                         int aliveCount, bool centerBreached)
{
    if (alreadyShown) return RunEndReason.None;
    if (everHadAgents && aliveCount <= 0) return RunEndReason.Wiped;
    if (centerBreached) return RunEndReason.Overrun;
    return RunEndReason.None;
}
```

**🔴 함락 조건 개정 (2026-08-16 사용자 반려)** — 스케치의 `centerBreached`(적이 중심 반경에
들어오면 함락)는 **틀렸다**. 사용자 판정 그대로:

> *"적이 마을에 발만 들어와도 함락이라고? **주민 모두가 적한테 사망을 해야** 함락이지."*

**끝나는 조건은 여전히 하나 — 마을이 0명이 되는 것.** 늘어난 것은 **사유 구분**뿐이다.

| 판정 | 뜻 |
|---|---|
| `Wiped` | 0명이 됐고 죽음에 **적 아닌 사유**(아사 등)가 섞였다 — 적이 다 한 일이 아니다 |
| `Overrun` | 0명이 됐고 **모든 죽음이 전투사**였다 = 함락 |

원천 = `Chronicle` 명부의 `ExitCause` (`AllDeathsByCombat`). **빈 명부는 함락이 아니다**
(아무도 안 죽은 판을 함락이라 부를 수 없다 — 빈 검사 함정 차단).
🔑 적이 마을에 들어온 것만으로는 아무것도 안 끝난다 — **들어온 적은 싸워서 물리칠 수 있어야
게임이다.** 반경 필드(`OverrunRadius`)와 중심 훑기(`AnyHostileAtCenter`)는 **되돌렸다**.

## 10. 재미 검증 — 플레이어가 화면에서 무엇을 새로 보게 되는가

지금까지 이 마을은 **끝나지 않았다.** 주민들이 밥을 먹고 자고 채집하고, 늑대도 곰도 사라진
뒤로는 아무도 죽지 않고, 30분을 봐도 판이 끝나지 않는다. 그래서 플레이어가 무엇을 해도
결과가 같았다.

이 차수가 끝나면 플레이어는 **처음으로 지게 된다.** 언덕 너머 저쪽 마을이 광석을 캐서 무기를
벼리는 것이 정찰병의 시야에 잠깐 비치고, 그 수가 어느 선을 넘으면 줄지어 나선다. 이쪽은
그전에 정해야 한다 — 여덟 중 몇을 밭에서 빼서 무기를 쥐어 줄 것인가. 셋을 빼면 밭이 마르고,
안 빼면 목책이 뚫린다. 그리고 적이 마을 중심에 닿는 순간 **화면이 덮이고 판이 끝난다.**

**측정기**: 이야기 회상 테스트 — *"방금 판에서 남에게 말하고 싶은 순간이 있었나?"*
baseline은 여전히 **0**(2026-07-17)이다. 이 차수의 목표는 그 0을 1로 만드는 것이고,
그 1은 **"몇 명을 뽑을지 틀렸다"** 여야 한다.
