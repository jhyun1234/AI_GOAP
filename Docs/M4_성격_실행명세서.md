## 0. 목적

주민들이 전부 동일 인격이라 게임 정체성("자기 생각이 있는 AI와 협상")이 **개인** 단위로
읽히지 않는다. 아키타입 4종 + 개체 편차 ±10%를 재편입해:
**같은 명령에 순둥이는 "네, 알겠어요!" 하고 가고 고집쟁이는 "꼭 내가 해야 해?" 하며 거부하고,
방치하면 농사꾼이 밭을 도맡고 떠돌이가 숲을 도는 — 시키지 않은 역할 분담이 창발한다.**

설계 확정 사항 (2026-07-15 브레인스토밍, 사용자 승인):
- 영향 3축 = 명령 거부 오프셋 · 작업 비용 배율(노동 계열 간 차등) · 대사 톤. 능력치 차이 제외
- 구조 = 아키타입 PersonalitySO + 개체 편차 ±10% (하이브리드), 스폰 시 랜덤 할당
- **확장성 불변식**: 성격 null/중립값 = M3와 동작 완전 동일 (게이트 강제 — 시스템 온오프·
  아키타입 증감의 근거)
- ⚠️ **여가 빈도 성향(부지런/느긋)은 M4 제외**: 여가는 DirectActionPool 특례(ADR-M1-3,
  플래너 우회)라 비용 배율이 닿지 않고, goal 선택 단계 개입이 필요 — M5 이월 (§7)

## 2. 재미 검증 — 플레이어가 화면에서 새로 보게 되는 것

주민을 클릭해 명령을 내리면 **누구에게 시켰는지가 처음으로 중요해진다** — 순둥이는 지쳐도
"네, 알겠어요!" 하고 일어나고, 고집쟁이는 멀쩡해 보여도 "꼭 내가 해야 해?" 하며 거부한다.
가만히 지켜보면 농사꾼은 밭 사이를 돌고 떠돌이는 숲과 지도 바깥을 헤매고 다닌다 — 누구도
역할을 지정하지 않았는데 마을에 직업 비슷한 것이 생긴다. 말풍선에는 이따금 성격 혼잣말이
섞여 나와("흙냄새가 최고야" / "여긴 너무 좁아") 주민들이 서로 다른 사람으로 읽히기 시작한다.

## 3. ADR-M4 (구현 중 갈릴 판단, 바꾸려면 사유를 커밋에)

- **ADR-M4-1 (배율 주입 지점 유일)**: 성격 비용 배율은 PlannerGateway.RequestPlan이 잡에
  넘길 Actions NativeArray를 굽는 시점(`new NativeArray<>(_defs)` 직후)에 BaseCost에 곱하는
  것이 **유일한** 주입 지점. GOAPPlannerJob·ActionCompiler·공유 _defs 원본은 무변경 —
  잡이 Execute 서두에 min(BaseCost)를 실측하므로 휴리스틱 정합은 자동 유지 (S2 주석 확인됨).
  러너·셀렉터 등 다른 곳에 비용 개념을 들이지 않는다.
- **ADR-M4-2 (중립 불변식)**: PersonalitySO가 null이거나 전 필드 중립(배율 1, 오프셋 0,
  문구 빈 배열)이면 M3와 동작이 완전히 동일해야 한다 — M4-T1 게이트가 강제. 이 불변식이
  성격 시스템 온오프·아키타입 추가/삭제 자유의 근거다.
- **ADR-M4-3 (생존 계열 배율 금지)**: 소비(식사)·휴식 계열에는 배율 **필드 자체를 두지
  않는다** — 굶주림과 탈진 앞에서 성격 없음 (ADR-M2-5의 정신). 배율 대상 = 채집/농사/건설/
  탐험 4계열만.
- **ADR-M4-4 (계열 판정 = 타입 is-검사)**: 배율 계열 판정은 ActionSO 서브타입 검사
  (GatherActionSO/FarmActionSO/BuildActionSO/ExploreActionSO)로만 — 액션 이름·문자열 분기
  금지 (ADR-M0-1). 새 계열 SO가 생기면 배율 필드도 그때 추가 (기존 에셋은 기본값 1.0 자동 보충).
- **ADR-M4-5 (세이브 대상 선언)**: 아키타입 참조 + 개체 편차는 "로드 후 재계획"으로 재구축
  불가능한 정체성이므로 **세이브 대상** (ADR-M3-5 목록에 추가: 에이전트 욕구/위치/성격).
  M4는 선언만, 구현은 세이브 밀스톤에서.
- **ADR-M4-6 (수치 출처)**: 아키타입 수치는 전부 §4 제안치 — 舊 F-A 성격 6종은 폐기된
  아키텍처(스탯 배율 중심)라 참조만 하고 강제하지 않는다. 방치·Play 관측 후 에셋에서 튜닝.

## 4. 데이터·수치 (전부 제안치 — 구현 중 첫 사용 시점에 승인 확인)

**PersonalitySO 필드**: DisplayName · RefuseSatietyOffset · RefuseFatigueOffset ·
GatherCostMult · FarmCostMult · BuildCostMult · ExploreCostMult (기본 전부 중립) ·
MoodLines[] · RefuseHungryLines[] · RefuseTiredLines[] (비면 AgentConfig 기본 대사) ·
MoodLineChance(기본 0.2)

**아키타입 4종 제안치** (거부 오프셋은 AgentConfig 문턱에 더하는 절대값 — 현 문턱 값은
AgentConfig.asset의 OrderRefuseSatiety/OrderRefuseFatigue를 구현 시 확인):

| 아키타입 | 거부 오프셋 (satiety / fatigue) | 배율 (Gather/Farm/Build/Explore) | 대사 톤 |
|---|---|---|---|
| 순둥이 | -8 / +10 (지쳐도 수행 경향) | 중립 | 공손 ("네, 알겠어요!") |
| 고집쟁이 | +8 / -15 (**자주 거부**) | 중립 | 퉁명 ("꼭 내가 해야 해?") |
| 농사꾼 | 0 / 0 | 1.15 / **0.7** / 1.0 / 1.1 | 흙 예찬 ("흙냄새가 최고야") |
| 떠돌이 | +3 / 0 | **0.75** / 1.2 / 1.0 / **0.8** | 자연 예찬 ("발길 닿는 대로") |

**개체 편차**: 스폰 시 배율 4종에 각각 ±10% 곱 (거부 오프셋·대사에는 편차 없음 — 단순 유지).
편차 시드는 저장 대상(ADR-M4-5) — M4에서는 값 자체를 필드로 보관.

**스폰 풀**: M0SimulationLoop 인스펙터 `_personalityPool` (PersonalitySO[]) + 씬 등록.
풀이 비면 성격 null = 중립 (불변식 경로).

/// <summary>성격 → 카탈로그 인덱스별 비용 배율 (순수 — 게이트 대상). null 성격 = null 반환(중립).</summary>
public static class PersonalityCost
{
    public static float[] Build(ActionCatalog catalog, PersonalitySO p, float[] jitter)
    {
        if (p == null) return null;
        var mult = new float[catalog.Actions.Length];
        for (int i = 0; i < mult.Length; i++)
            mult[i] = MultiplierFor(catalog.Actions[i], p) * (jitter != null ? jitter[CategoryOf(...)] : 1f);
        return mult;
    }
    // MultiplierFor: is GatherActionSO → p.GatherCostMult, is FarmActionSO → Farm, is BuildActionSO →
    // Build, is ExploreActionSO → Explore, 그 외(Consume/Rest/Wander) → 1f (ADR-M4-3/M4-4)
}
// PlannerGateway.RequestPlan(snap, goal, float[] costMult = null):
//   p.Actions = new NativeArray<GOAPActionDef>(_defs, alloc);
//   if (costMult != null)
//       for (int i = 0; i < _defs.Length; i++) { var d = p.Actions[i];
//           d.BaseCost = _defs[i].BaseCost * Mathf.Max(0.1f, costMult[i]); p.Actions[i] = d; }
// VillagerAgent: _costMult = PersonalityCost.Build(...) 1회 캐시 → RequestPlan에 전달

### M4-C — 명령 거부 성격 계수 + 거부 대사

- **대상**: `M0/Agent/VillagerAgent.cs`(JudgeOrder 오버로드 + TryGiveOrder 성격 대사 우선),

/// <summary>성격 오프셋 포함 거부 판정 (순수, ADR-M1-2 확장). p=null이면 기존과 동일.</summary>
public static OrderResult JudgeOrder(float satiety, float fatigue, AgentConfigSO cfg, PersonalitySO p)
{
    float satLimit = cfg.OrderRefuseSatiety + (p != null ? p.RefuseSatietyOffset : 0f);
    float fatLimit = cfg.OrderRefuseFatigue + (p != null ? p.RefuseFatigueOffset : 0f);
    if (satiety < satLimit) return OrderResult.RefusedHungry;
    if (fatigue > fatLimit) return OrderResult.RefusedTired;
    return OrderResult.Accepted;
}
// 기존 3인자 JudgeOrder는 4인자(p=null) 위임으로 유지 — M1-T1 게이트 무수정 green
// TryGiveOrder: 거부 대사 = Personality?.RefuseHungryLines 비어있지 않으면 그것, 아니면 cfg 기본
