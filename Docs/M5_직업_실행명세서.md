## 2. 재미 검증 — 플레이어가 화면에서 새로 보게 되는 것

마을에 **직업이 보인다.** 농부는 아침부터 밭 사이를 돌며 심고 거두고, 할 일이 없어도 밭 곁을
서성인다. 탐험가는 마을에 붙어 있지 않는다 — 검은 지도 가장자리로 나가 새 자원과 땅을 밝히고
돌아온다. 요리사가 모닥불을 지키고, 나무꾼과 광부는 숲과 바위에 산다. 여기에 성격이 곱해진다:
고집쟁이 농부는 밭일은 기막히게 하는데 심부름은 거부하고, 순둥이 탐험가는 지쳐 돌아와서도
부탁을 들어준다. 주민들이 마을 중심에 뭉쳐 있던 풍경이 **직업 따라 흩어진 마을**로 바뀐다.

## 3. ADR-M5 (구현 중 갈릴 판단, 바꾸려면 사유를 커밋에)

- **ADR-M5-1 (실효 우선순위 — 이원화 금지)**: goal 에셋의 Priority는 **불변**. 직업 보정은
  GoalSelector.Select 호출 시점에 주입되는 함수(bias)로만 존재하며 어디에도 저장하지 않는다
  (쿨다운 skip 술어와 같은 패턴). 실효 우선순위 = Priority + bias(goal). bias=null이면 기존과
  완전 동일 — 게이트 강제 (M4 중립 불변식 패턴).
- **ADR-M5-2 (일과 = 개인 사다리 주입)**: 직업 일과 goal은 씬 전역 _goals에 넣지 않는다 —
  촌장 명령(extra)과 같은 방식으로 주민이 자기 Select 호출에 후보로 주입한다. 우선순위 대역:
  여가(1) < **일과(2)** < 공용 노동(8+) — 일과는 "할 일 없을 때"만 잡힌다.
- **ADR-M5-3 (배율 결합 지점 유일)**: 직업 배율은 PersonalityCost.Build에서 성격 배율과 곱으로
  결합 — 잡 주입 지점은 여전히 RequestPlan per-request 사본 하나 (ADR-M4-1 계승). 생존 계열
  배율 금지도 계승 (직업에도 소비/휴식 배율 필드 없음).
- **ADR-M5-4 (폴백 불변식 — 배타 금지)**: 직업은 공용 사다리 위의 보정일 뿐이다. 어떤 goal도
  "특정 직업 전용"으로 잠그지 않는다 — 전원 무직 구성에서 전 goal 도달이 게이트로 강제된다.
  (예외는 일과 goal 자체 — 그건 개인 주입이라 애초에 공용이 아니다)
- **ADR-M5-5 (세이브 대상 확장)**: Job 참조도 성격·편차와 함께 세이브 대상 (ADR-M4-5 목록 추가).
- **ADR-M5-6 (Select 호출 정합)**: VillagerAgent의 Select 호출 2곳(TickIdle·상위 전환 검사)은
  **반드시 동일 인자**(skip·order·bias·routine)를 쓴다 — 다르면 선택과 전환의 진리가 갈라져
  중단↔재시작 폭주가 재발한다 (M1-C 교훈).

### M5-B — 실효 우선순위 + 배율 결합

- **대상**: `M0/Planning/GoalSelector.cs`(Select 재작성 — 후보 전수 평가·실효 최대 선택),

```csharp
// GoalSelector — 정렬 조기 종료 대신 전수 평가 (goal ~15개, O(n) 무시 가능):
public GoalSO Select(WorldSnapshot snap, System.Func<GoalSO, bool> skip = null,
                     GoalSO extra = null, System.Func<GoalSO, int> bias = null,
                     GoalSO routine = null)
{
    GoalSO best = null; int bestP = int.MinValue;
    void Consider(GoalSO g)
    {
        if (g == null || !Passes(g, snap, skip)) return;
        int p = g.Priority + (bias != null ? bias(g) : 0);
        if (p > bestP) { bestP = p; best = g; }
    }
    foreach (GoalSO g in _goals) Consider(g);
    Consider(extra);    // 촌장 명령 (기존)
    Consider(routine);  // 직업 일과 (M5-C에서 전달 시작)
    return best;
}
// PersonalityCost.Build(catalog, personality, job, jitter):
//   mult[i] = PersonalityMult × JobMult × jitter — 성격·직업 둘 다 null이면 null(중립)
// VillagerAgent: int JobBias(GoalSO g) => Job != null ? Job.BoostFor(g) : 0;
```
