## 0. 목적

주민 간 보상(5ce720e)에 성격 축을 얹는다: 후불 보상은 **떼먹힐 수 있고**(의뢰인 성격·관계
결정적 판정), 깐깐한 성격은 **선불을 요구**한다(수락 시 즉시 지급, 없으면 거절). 떼먹기는
관계 델타로 원한을 낳아 "집 지어줬는데 떼먹혔다 → 다음 부탁 거절"의 창발 루프를 완성한다.

## 2. 재미 검증 — 플레이어가 화면에서 새로 보게 되는 것

순둥이 목수가 새침이의 집을 다 짓고 찾아가 "다 지었어. 잘 살아!" 하자, 새침이가
**"보상?! 하.. 내가 생각 해볼게~"** 하고 떼먹는다 — Console에 관계 하락이 찍히고, 다음에
새침이가 또 부탁하면 목수가 "너랑은 말 섞기 싫어"라며 거절한다. 반대로 고집쟁이 목수에게
부탁하면 창고에 조리식이 있어야만 "좋아, 맡겨 둬"가 나온다 — 없으면 **"빈손으로 부탁하는
거야?"**. 플레이어는 정보줄 관계·성격 표기만으로 이 거래의 결말을 예측할 수 있다.

## 3. ADR (바꾸려면 사유를 커밋에)

- **ADR-보상1 (떼먹기 결정적)**: 떼먹기 = 의뢰인 성격의 친밀 문턱 판정
  (`의뢰인→수행자 친밀 < SkipRewardBelowAffinity`). 랜덤 금지 (ADR-M1-2 계승) —
  플레이어가 관계 표기로 예측 가능해야 한다. 기본값 -100 = 판정 자체가 성립 불가 (중립).
- **ADR-보상2 (선불 = 수락 시 즉시 지급)**: 에스크로 보관(M6 방식) 아님 — "먼저 받고
  일한다"가 선불의 정체성. 선불 완료 부탁은 보고 장면에서 지급·떼먹기 판정 없이 감사
  대사만. 대칭: **선불 = 확실하지만 깐깐, 후불 = 너그럽지만 떼먹힐 위험**.
- **ADR-보상3 (성격 이름 분기 금지 계승)**: 판정은 PersonalitySO 필드값만, 대사는
  성격 오버라이드 + AgentConfig 기본 폴백 (RefuseLines 패턴 그대로).
- **ADR-보상4 (보상 0 부탁과 선불 성격)**: 보상이 없는 부탁(RewardCostAmount 0)은 선불
  성격이 **항상 거절** — "공짜로는 안 해"가 그 성격의 표현이다. 해소는 에셋(부탁에 보상
  달기)으로.

## 4. 데이터·수치 (전부 제안치 — 기존 값 우선)

**PersonalitySO 추가 필드**:
- `SkipRewardBelowAffinity` (int, 기본 -100 = 중립: 절대 안 떼먹음) — 고집쟁이 5, 새침이 10
- `DemandsRewardUpfront` (bool, 기본 false = 후불) — 고집쟁이 true, 새침이 true
- `StiffRewardLines` (string[], 비면 AgentConfig 기본) — 새침이 "보상?! 하.. 내가 생각
  해볼게~"(사용자 원문), 고집쟁이 "보상? 흥, 나중에 생각해 보지"

**AgentConfigSO**: `StiffRewardLines` 기본 풀 ("아 맞다, 보상... 다음에 줄게" 등 2줄)

**RequestSO 추가 필드**: `StiffedDelta` -10 (떼먹힌 수행자→의뢰인 — 원한 재료) ·
`RefuseNoRewardLines` ("빈손으로 부탁하는 거야?" / "선불 없이는 안 해")

**JudgeRequest 판정 순서**: 바쁨→배고픔→피로→친밀→**선불** (몸→마음→조건. 순서 뒤 = 사유 보고 순서)
