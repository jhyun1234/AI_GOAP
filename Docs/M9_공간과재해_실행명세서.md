## 0. 목적

M8까지의 마을은 **잉여가 잡히지 않는다** — 밭이 늘수록 가을 수확이 쌓여 겨울이 안락해지고
("방치가 안락하면 실패" 기준과 정면 충돌), 주민 4명 축소(2d24b0f) 후에는 위기감 수치 전부가
10명 기준 잔재가 됐다. M9는 **공간 축**(밭이 한 구역에 모인다 = 보이는 소프트 상한)과
**재해 축**(여름 폭염이 수확 전 파이프라인을 때린다 = 잉여를 실제로 깎는 지렛대)으로
긴장-해소 리듬을 연 2박자로 만들고, **N명 대화**로 그 순간을 마을 장면으로 보여준다.
회상 테스트 득점 장면 = "폭염이 밭을 태우자 다들 모여서 걱정했고, 그 겨울은 정말 아슬아슬했다."

## 0.5 넓히기 분류 (①선반 위 물건 / ②새 선반 — 사용자 가치관, 필수 항목)

| 항목 | 분류 | 근거 |
|---|---|---|
| 구역 (수량형 건물 배치 규칙) | **②새 선반** (ZoneService — 군집 휴리스틱의 승격·**대체**) | 배치 결정 단일 지점 + 게이트 동반 |
| 재해 (DisasterSO + DisasterService) | **②새 선반** (재해 스키마) | M9-F가 .cs 0 증명 |
| 파괴 문 (작물 소실·밭 시설 소실) | **②새 선반** (기존 '세 문' 패턴의 확장 — 소멸 경로 단일성) | ADR-M9-3 + 게이트 |
| N명 대화 릴레이 | ① M7 대화 선반 위 물건 (Fire 확장) | ChatterSO 필드 1개 |
| 농부 회의 연출 | ① 대화 선반 위 물건 (이벤트 구동 장면) | 표현 전용 유지 (ADR-M9-2) |

| 겨울 수지 재조정 | ① 에셋 값만 (.cs 0) | §4.5 계산 근거 |

**② 두 선반 완성 후 에셋 1개짜리가 되는 것** (M9-F가 커밋으로 증명):
- 새 재해 = DisasterSO 에셋 1개 + WorldConfig.Disasters 등록 (계절 참조·발동 시점·소실 곡선·
  저항 슬롯·대사가 전부 필드) — 리허설 = 홍수 (사용자 원안 3종 중 마지막)
- 새 계절 = SeasonSO 에셋 1개 (M6-F 경로 그대로 — 여름이 두 번째 증명)

- 재해 저항 건물 추가 = BuildingSO+BuildActionSO+GoalSO 에셋 + 슬롯 1개 (기존 건물 비용표 행)

## 2. 재미 검증 — 플레이어가 화면에서 새로 보게 되는 것

첫 밭이 완공되는 순간 그 둘레에 **연갈색 테두리**가 그려지고, 완공한 농부가 "밭은 여기다
모으자!"라고 외치면 근처 주민들이 한 명씩 "좋아, 여기가 좋겠어" — "물도 가깝고" 하고
**릴레이로 맞장구친다** (첫 3인 이상 대화 장면). 이후 모든 밭은 그 테두리 안에만 생겨서
화면에 **농경지**라는 장소가 생긴다. 달력이 여름으로 바뀌면 HUD에 경보가 뜨고 주민들이
"올여름 볕이 심상치 않아" 술렁이다가, 폭염이 발동하는 순간 구역 안 작물 절반이 **눈앞에서
사라진다** — 잘 자라던 새싹·결실 오버레이가 빈 흙으로. 그 가을 수확은 눈에 띄게 얇고,
겨울 Day 로그의 식량 잔량이 한 자릿수로 떨어지며 마을이 진짜로 아슬아슬해진다. 관개수로를
지은 판에서는 같은 폭염에 작물이 덜 죽는 것도 보인다 — 짓는 행위가 곧 방어다.

## 3. ADR-M9 (구현 중 갈릴 판단, 바꾸려면 사유를 커밋에)

- **ADR-M9-1 (군집 휴리스틱 → 구역 대체, 공존 금지)**: BuildRunner의 "동종 곁 링 탐색"
  군집 분기는 **삭제**하고 ZoneService가 수량형 건물 배치의 유일한 결정자가 된다
  (M8 방향 분석 원칙 — 대체하지 않으면 배치 규칙 이원화). 밭만 대체하고 집은 군집을 남기는
  절충 금지 — 구역은 수량형 공통 선반이고 반경만 에셋 값이다 (집 구역 = 주거 구역).
- **ADR-M9-2 (구역 확정 = 첫 완공 타일, 회의는 표현 전용)**: 구역 앵커는 해당 슬롯의
  **첫 완공 타일**이 결정한다 (결정적 — 기존 "첫 건물 곁" 동작과 연속). 농부 회의는 그 확정
  순간을 **표현**하는 이벤트 구동 장면일 뿐, 구역 결정에 개입하지 않는다 (M8 방향 분석의
  1단계 기회주의 회의 채택 확정 — 회의 goal 승격은 반려. 재론 조건: 회의 장면이 관측에서
  "우연 같아서 안 보인다" 판정이 나올 때만).
- **ADR-M9-3 (파괴 쓰기 단일 지점)**: 작물 소실은 FarmService.BlightCrop, 밭 시설 소실은
  ConstructionService.RemoveCountableAt → (OnRemoved 구독) → FarmService.RemovePlot 경로만.
  등록(OnCompleted 구독 → RegisterPlot)과 대칭 — 다른 코드가 밭·카운트를 지우면 반려.
  완공의 문(Complete)처럼 파괴의 문도 하나다.
- **ADR-M9-4 (재해 발동·소실 결정적)**: 재해는 해당 계절마다 **확정 발동** (확률 없음 —
  M6 교훈 "위협은 실제로 발현해야 존재한다". 예고했으면 온다). 소실 수 산식과 희생 선택은
  순수 함수 + StableHash 시드 (게이트 대상). 표현이 아닌 시뮬 쓰기이므로 UnityEngine.Random 금지.
- **ADR-M9-5 (재해는 수확 전 파이프라인만 때린다)**: 파괴 대상 = 자라는 작물·밭 시설.
  **창고 스톡(Wood/RawFood/Cooked/Stone)은 절대 건드리지 않는다** — 플레이어(주민)가 이미
  거둔 결과물의 몰수는 부당 손실이고, 잉여를 잡는 지렛대는 공급 측 차단으로 충분하다
  (memory 분석 수정 1: 겨울 한파가 창고를 못 깎아 무효였던 문제의 반대 방향 오류 방지).
- **ADR-M9-6 (발전 배율 금지 — 저항은 건물 플래그만)**: 소실 완화는 DisasterSO.ResistanceSlot
  (논리형 BuiltFlag) 참조 하나뿐. "마을 발전 지수" 같은 추상 배율 축 신설 금지
  (memory 분석 수정 2 — 직교성: 짓는 행위가 곧 발전이고, 새 저항 건물 = 에셋 1개+슬롯 1개).
- **ADR-M9-7 (N명 대화 정지 상한)**: FaceForChat 정지는 장면당 최대 3명 (알고리즘 상수
  MAX_CHAT_PAUSERS) — 나머지 청중은 걸으며 듣는다. 대화 장면이 길목을 통째로 점유해
  PathBlocked를 유발하는 기존 🟡관찰의 확대 방지.
- **ADR-M9-8 (여름 = 위기 계절)**: Season_Summer는 IsCrisis 1 — 기존 위기 선반
  (DaysToCrisis 슬롯·ForecastLines 술렁임·HUD 경보)을 코드 0줄로 재사용한다. 배율 3종은
  전부 1 (여름의 정체성은 재해뿐 — 배율까지 조이면 위기 원인이 이원화된다). 부작용
  (WinterPrep가 여름 전에도 발동)은 §4.5의 설계 의도로 흡수 — 비축-타격-소모의 연 2박자.

## 4. 데이터·수치

### 4.1 SlotId 확장 (append 규약 — 기존 인덱스 불변)

`IrrigationBuilt = 18` (논리형 — 관개수로 완공. 슬롯 예산 52칸 중 19 사용, SlotIds.Count 19.
IsNumeric 변경 없음). 한파 저항 건물(방풍막) 슬롯은 이번에 만들지 않는다 (§7).

### 4.2 BuildingSO 추가 필드

`ZoneRadius` (int, 기본 0 = 구역 없음 — 기존 에셋 무수정 시 "제자리+링 탐색"만 남고 군집
분기는 사라진다. 수량형 전용 — OnValidate에서 !IsCountable && ZoneRadius > 0 경고).
기존 에셋 값 제안 (전부 제안치): FarmPlot **3** (7×7=49칸 — 밭 소프트 상한 공간),
House **5** (주거 구역 — 기존 "집은 집 곁에" 동작의 연속).

### 4.3 DisasterSO (신규 스키마 — 재해 1종 = 에셋 1개)

| 필드 | 타입 | 설명 |
|---|---|---|
| DisplayName | string | "폭염" |
| Season | SeasonSO 참조 | 이 계절마다 발동 (이름 문자열 금지 — ADR-M0-1) |
| OffsetDays | float | 계절 시작 후 발동 시점 (제안 1.5 — 계절 중반, 예고 여운) |
| TargetCrops | bool | true = 작물 소실 (Growing·Ripe → Empty), false = 밭 시설 소실 (RemovePlot) |
| BaseLossPct | float | 기본 소실 비율 (제안: 폭염 0.25) |
| PerTargetPct | float | 대상 1개당 가산 비율 (제안 0.03 — **밭이 늘수록 가혹** = 사용자 원안의 자기 균형) |
| MaxLossPct | float | 클램프 상한 (제안 0.6) |
| ResistanceSlot | SlotId | 논리형 BuiltFlag — 완공 시 소실 배율 적용 (없으면 CampfireBuilt 외 미사용 값 대신 **UseResistance bool + 슬롯** 쌍으로, 기본 false) |
| ResistMult | float | 저항 건물 완공 시 소실 배율 (제안 0.5) |
| StrikeLines | string[] | 발동 순간 근처 주민 반응 대사 ("밭이 다 타버렸어!") |

소실 수 = `CeilToInt(대상수 × Clamp(BaseLossPct + PerTargetPct × 대상수, 0, MaxLossPct)
× (저항 완공 ? ResistMult : 1))`. 대상 0개면 발동 로그만 (소실 0 — 게이트 케이스).

### 4.5 겨울 수지 계산 — 주민 4명 기준 (본 명세의 필수 숙제, 전 수치 에셋 실측)

**소요** (AgentConfig.SatietyDecayPerGameDay 25 × Season_Winter.SatietyDecayMult 1.75 ×
DurationDays 4):
- 1인 겨울 소모 = 25 × 1.75 × 4 = **175 포만**
- 4명 = **700 포만** = 조리식 14개 상당 (EatCookedFood +50) = 생식 47개 상당 (EatRawFood +15)

**현행 진단**: WinterPrep 목표 Cooked 20 = 포만 1,000 = 소요의 **143%** → 비축만으로 겨울
전체 + 여유. 10명 시절(소요 1,750)의 57%였던 값이 4명 축소(2d24b0f)로 안락 확정이 됐다 —
🚨플래그의 실체.

**제안**: Cooked 20 → **10** (포만 500 = 소요의 71%). 부족 200 포만은 생식 직식(~13개)과
겨울 진입 시점 Ripe 잔여 수확으로 메꾸는 긴장 구간 — 폭염이 가을 수확을 깎은 판일수록 이
구간이 위험해진다 (재해→겨울 전가 고리). 굶주림 계단(StarvingBelowSatiety 10, 0.5일)이
경쟁 약자부터 위협.

**공급 측 상한** (재해·구역이 잡아야 할 잉여): 밭 4(ExpandFarm 목표) × 수확 +6 생식 ×
성장 사이클(1.5일)로 온화+여름 6일 ≈ 이론 최대 96 생식/사이클 — 조리 환산 시 소요(사이클당
총 1,500 포만)의 2배+. 폭염 소실(~40%)과 플랜 오버헤드·경쟁이 실효를 깎는다.
**관측 판정 기준 (M9-S4)**: 겨울 종료 시 Cooked+Raw ≤ 10 아슬아슬 / ≥ 30 안락(폭염 강도
상향 or 목표 재하향) / 이탈 3명+ 과혹(폭염 강도 하향). 수치 확정은 관측 후 사용자와.
