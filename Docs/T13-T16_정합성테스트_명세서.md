## 서두 — 측정 가능한 성공 기준

이 명세를 완료하면 다음이 **수치로** 달성되어야 한다:

1. **T13 통과율 100%** — Registry의 8개 YIELD 상수(`YIELD_CHOP_WOOD/MINE_STONE/MINE_IRON/MINE_COPPER/HARVEST_BERRIES/COOK_YIELD/MEDICAL_HEALTH_GAIN`)가 런타임(VillagerFSM/ActionDatabase) 리터럴과 **1건도 어긋나지 않는다**.
2. **T14 통과율 100%** — `SelectGatherGoalId`의 임계값 5종(Wood/Stone/Iron/Copper/RawFood)이 `BuildGoalState`의 목표치 이하다. 즉 `임계값 ≤ 목표치`가 **모든 자원 타입에서 성립**한다.
3. **T15 통과율 100%** — Registry `BuildActionDefs`에 등록된 액션 수 = `names[]` 배열 길이 = `Debug.Assert(i == N)` 상수 = `BuildGoalState` case 커버리지. **네 값이 모두 일치**한다.
4. **T16 통과율 100%** — 5개 대표 시나리오(빈 마을 / 겨울 / 침략 근접 / 도구 없음 / 자원 원거리)에서 각 P0/P1/P2 Goal의 실제 `NodesExpanded ≤ MAX_NODES × 0.7 = 1434`. 초과 시 실패.
5. **회귀 지표**: 명세 적용 후 첫 10분 방치 테스트에서 **Deadlock 경고 0건, NoSolutionFound 0건**.

측정 도구: Unity Test Runner EditMode, `Assets/Tests/EditMode/AIVillage.Tests.EditMode.asmdef` 하위.

## ADR (구현 중 갈릴 판단 미리 결정)

이 결정을 바꾸려면 **사유를 커밋 메시지에 명시**한다.

- **ADR-T1**: EditMode 테스트만 사용한다 (PlayMode 금지). Job 실행 없이 순수 리플렉션/상수 대조로 계약을 검증한다. PlayMode는 실행 시간 5배 이상 걸려 CI/커밋 게이트에 부적합.
- **ADR-T2**: T13/T14/T15는 **어긋남을 발견 즉시 실패**한다. 경고 로그로 넘기지 않는다. `Assert.AreEqual` / `Assert.LessOrEqual` 사용.
- **ADR-T3**: T16의 시나리오 데이터는 **테스트 파일 내 상수**로 하드코딩한다. Prefab/SO 의존 금지. 씬 로드 없이 순수 GOAP 호출로 실행.
- **ADR-T4**: T16의 임계값(1434)은 **MAX_NODES × 0.7**로 계산한다. `GOAPPlannerJob.MAX_NODES` 값이 바뀌면 자동 반영. 하드코딩 금지.
- **ADR-T5**: 상수 접근을 위해 필요하면 Registry/FSM 상수를 `internal` 또는 `public const`로 승격한다. 리플렉션 사용 금지 (Burst 호환성 이슈).
- **ADR-T6**: 테스트 실패 메시지는 **원인·위치·기대값/실제값** 3요소를 포함한다. "Test failed" 만으로는 커밋 게이트 역할 불가.

```csharp
namespace AIVillage.Tests.EditMode
{
    /// <summary>
    /// T16: 대표 시나리오 5개에서 각 Goal의 실제 NodesExpanded가 MAX_NODES × 0.7 이하인지 검증한다.
    /// 초과 시 = 컨텍스트 비용 배율로 목표 경로 f-cost가 예산을 소진할 위험 (버그 21 재발 방지).
    /// </summary>
    public class T16_MaxNodesBudget
    {
        private const int BUDGET = (int)(GOAPPlannerJob.MAX_NODES * 0.7f); // ADR-T4

        // 5개 대표 시나리오 하드코딩 (ADR-T3)
        private static readonly Scenario[] SCENARIOS = new []
        {
            new Scenario("빈 마을 초기 상태", /* worldState/brain 설정 */),
            new Scenario("겨울 진입 - Autumn 배율 적용",  /* ... */),
            new Scenario("적 근접 - DANGER 배율 적용",   /* ... */),
            new Scenario("도구 없음 - GatherFood만 가능", /* ... */),
            new Scenario("자원 원거리 - DISTANCE_SCALE 상한", /* ... */)
        };

        [TestCaseSource(nameof(SCENARIOS))]
        public void GatherWood_NodesExpanded_within_budget(Scenario s)
        {
            var context = GOAPPlannerScheduler.Schedule("GatherWood", s.Role, s.Brain, s.WorldState, s.Registry);
            context.JobHandle.Complete();
            int nodes = context.NodesExpanded[0];
            context.Dispose();

            Assert.LessOrEqual(nodes, BUDGET,
                $"시나리오 '{s.Name}': GatherWood NodesExpanded={nodes} > 예산 {BUDGET}. " +
                $"MAX_NODES 소진 위험. 컨텍스트 배율 감소 또는 MAX_NODES 승격 필요.");
        }

        // SurviveHunger, BuildStructure, DefendVillage 등 주요 Goal 반복
    }

    public class Scenario
    {
        public string Name;
        public AgentRole Role;
        public VillagerBrain Brain;
        public AuthoritativeWorldState WorldState;
        public ResourceRegistry Registry;
        // 생성자에서 목/스텁 상태 구성
    }
}
```

## 재미 검증 (이 작업이 완료되면 플레이어가 보게 되는 것)

**정직한 답**: 이 명세를 완료해도 플레이어가 화면에서 새로 보게 되는 것은 **없다**. 이 명세는 **재미의 전제조건**이다.

지금까지 플레이어가 보게 되던 것: 멍하니 서 있는 주민 · Console 스팸(Deadlock 경고) · 자원 채취 중단.

명세 완료 후 플레이어가 **계속 보게 되는 것**: F-A 성격 특성이 얹혀도 주민이 계속 움직임. 겨울 배율이 곱해져도 Planning이 무너지지 않음. 명령 거부 후에도 시스템이 회복됨.

즉 이 작업은 "이미 있던 재미가 사라지지 않도록" 하는 안전망이다. `spec-write` 스킬 규칙은 "답할 수 없으면 우선순위 재질문"이지만, 이 경우 **재미 로드맵 F-A~F-F 진입의 전제조건**이라 우선순위가 명확하다.
