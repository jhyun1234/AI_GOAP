# GOAP 개발 블로그 자동화 워크플로우

Unity 2D AI_GOAP 프로젝트의 개발 로그를 세션 단위로 기록하고,
주기적으로 "주제별 딥다이브 포스트" 또는 "주간 요약 포스트"로 가공해
구글 블로그에 발행하기 위한 워크플로우입니다.

이 파일은 프로젝트 루트에 두고, Claude Code에게 참고 지침으로 사용하게 하거나
`CLAUDE.md`에 내용을 병합해서 쓰세요.

---

## 0. 폴더 구조

```
project-root/
  devlog/
    sessions/        # 세션별 원본 로그 (자동 생성)
    published/        # 이미 블로그에 올린 글의 소스 마크다운 보관
    published.log      # 발행 이력 (제목, 날짜, 태그, 블로그 URL)
```

세션 로그를 커밋 대상에 포함시킬지는 자유지만, `.gitignore`에서 제외하지 말고
버전 관리하는 걸 권장합니다. 나중에 "언제부터 이 기능을 만들기 시작했는지"
추적하는 데 유용합니다.

---

## 1. 세션 로그 규칙

### 언제 기록하나
Claude Code로 의미 있는 작업 단위(기능 구현, 버그 수정, 리팩토링 등)를
마칠 때마다 아래 템플릿으로 `devlog/sessions/YYYY-MM-DD.md`에 **append** 합니다.
같은 날 여러 세션이면 같은 파일에 `---`로 구분해서 이어 씁니다.

### 세션 로그 템플릿

```markdown
## [HH:MM] <한 줄 요약>

**태그:** #planner #action-system #world-state #sensor #ui-debug #performance (해당하는 것만)

**무엇을 했나:**
- 

**왜 이렇게 했나 (설계 결정/트레이드오프):**
- 

**막혔던 문제 / 해결 방법:**
- 

**다음에 할 일:**
- 

**변경 파일:** (선택)
```

### Claude Code에게 줄 프롬프트 예시

작업을 마칠 때마다 다음과 같이 요청하세요.

```
지금까지 이 세션에서 작업한 내용을 devlog/sessions/오늘날짜.md에
세션 로그 템플릿 형식으로 append해줘. 변경된 파일 목록도 git diff로 확인해서 포함해줘.
```

## 2. 태그 체계 (GOAP 프로젝트 기준)

| 태그 | 범위 |
|---|---|
| `#planner` | A* 기반 액션 그래프 탐색, 플래닝 알고리즘 |
| `#action-system` | Action의 Precondition/Effect 설계 |
| `#world-state` | World State 표현 방식 |
| `#goal-selection` | Goal 선택/우선순위 로직 |
| `#sensor` | Agent의 인지/센싱 시스템 |
| `#debug-viz` | 플랜 트리 시각화, 디버깅 툴 |
| `#performance` | 플래너 캐싱, 리플래닝 빈도 최적화 |
| `#multi-agent` | 에이전트 간 자원/목표 충돌 처리 |
| `#misc` | 위에 안 걸리는 잡다한 수정 |

새 서브시스템이 생기면 태그를 추가하세요. 태그는 나중에 "주제별 포스트"의
후보 단위가 됩니다.

---

## 3. 발행 판단 로직 (주간 리뷰)

### 실행 주기
주 1회(예: 매주 일요일) 아래 프롬프트를 Claude Code에 실행합니다.

### 판단 체크리스트
`devlog/sessions/` 중 지난 발행 이후 쌓인 로그를 태그별로 묶은 뒤,
각 태그 그룹에 대해 다음 중 하나라도 해당하면 **딥다이브 포스트** 후보로 분류합니다.

- 서브시스템이 데모 가능한 상태에 도달했다
- 풀기 까다로웠던 문제를 해결했고 그 과정이 설명할 가치가 있다
- 트레이드오프가 있는 설계 결정을 내렸다
- 눈에 보이는 마일스톤을 찍었다 (첫 플랜 실행 성공, 프로토타입 완성 등)

**전부 해당 없음** → 그 주 로그는 딥다이브로 묶지 않고, 전체를 하나의
**주간 요약 포스트**로 처리합니다.

같은 주에 딥다이브 후보 태그가 여러 개면, 포스트도 여러 개 나눠서 작성합니다
(한 포스트에 여러 주제를 억지로 합치지 않습니다).

### Claude Code에게 줄 프롬프트 예시

```
devlog/sessions/ 아래에서 devlog/published.log에 기록된 마지막 발행일 이후의
로그를 모두 읽어줘. 태그별로 그룹핑하고, 아래 체크리스트를 기준으로
딥다이브 포스트로 쓸만한 태그 그룹과, 그렇지 않아서 주간 요약으로
묶을 나머지를 분류해서 표로 보여줘.

체크리스트:
- 서브시스템이 데모 가능한 상태에 도달했는가
- 까다로운 문제를 해결했고 과정이 설명할 가치가 있는가
- 트레이드오프가 있는 설계 결정을 내렸는가
- 눈에 보이는 마일스톤을 찍었는가
```

분류 결과를 보고 실제로 어떤 포스트를 쓸지 최종 승인한 뒤 다음 단계로 넘어가세요.
(자동으로 바로 발행하지 말고, 이 단계에서 한 번 확인하는 걸 권장합니다.)

## 4. 포스트 작성 템플릿

### 4-1. 딥다이브 포스트

```markdown
# <구체적인 제목: "GOAP 플래너 구현기 - A* 기반 액션 그래프 탐색">

## 배경
왜 이 작업을 하게 됐는지, 어떤 문제가 있었는지

## 접근 방법
설계 결정과 그 이유

## 구현
핵심 코드/로직 설명 (전체 코드 나열 X, 핵심만)

## 막혔던 부분
문제와 해결 과정

## 결과
데모/스크린샷/gif 등 (있다면)

## 다음 단계
```

### 4-2. 주간 요약 포스트

```markdown
# <프로젝트명> 개발 주간 요약 - <날짜 범위>

이번 주에는 다음과 같은 작업을 진행했습니다.

- 
- 
- 

다음 주에는 <다음 계획>을 진행할 예정입니다.
```

### Claude Code에게 줄 프롬프트 예시

```
승인된 딥다이브 태그 그룹에 대해 devlog-workflow.md의 딥다이브 템플릿을 사용해서
포스트 초안을 devlog/published/<파일명>.md로 작성해줘.
나머지 로그는 주간 요약 템플릿으로 devlog/published/weekly-<날짜>.md에 작성해줘.
작성 후 devlog/published.log에 제목/날짜/태그를 한 줄씩 추가해줘.
```

5. SEO 체크리스트

포스트 초안이 나오면 발행 전에 아래 항목을 확인합니다. 검수 에이전트가
이 체크리스트를 기준으로 자동 점검하도록 프롬프트에 포함시키세요.

제목 / 메타


 -제목에 핵심 키워드가 자연스럽게 포함되어 있는가 (예: "Unity GOAP 플래너 구현", "GOAP Action Precondition 설계")
 -제목이 너무 포괄적이지 않고 구체적인가 ("개발일지 3편" 같은 제목 지양)
 -메타 설명(요약 2~3줄)에 핵심 키워드와 이 글에서 얻을 수 있는 결과물이 명시되어 있는가


본문 구조


 -H2/H3 소제목에 검색될 법한 키워드가 자연스럽게 들어가 있는가
 -본문이 최소 1,000자 이상이며 "왜/어떻게/결과"가 명확히 구분되는가
 -코드 블록만 나열하지 않고, 코드 앞뒤에 맥락 설명 문단이 있는가
 -리스트/불릿만으로 채우지 않고 실제 서술형 문단이 충분한가 (콘텐츠 깊이 신호)


링크 / 이미지


 -같은 시리즈의 이전/다음 글로 내부링크가 걸려 있는가 (예: "저번 편에서 다룬 World State 설계")
 -스크린샷/gif에 alt 텍스트가 키워드를 포함해 구체적으로 작성되어 있는가
 -외부 인용(공식 문서 등)이 있다면 출처 링크가 걸려 있는가


기술적 항목 (사이트 단위, 주기적 점검)


 -Google Search Console에 sitemap이 제출되어 있는가
 -모바일에서 레이아웃이 깨지지 않는가
 -포스트 발행 후 실제로 검색 색인이 되는지 주기적으로 확인하는가 (site:블로그주소 키워드로 검색)
 
## 6. 블로그 업로드 자동화와의 연결

기존에 설정해둔 구글 블로그 자동 업로드 스케줄이 있다면, 그 스케줄이
`devlog/published/` 폴더의 새 마크다운 파일을 소스로 읽어가도록
연결하는 걸 권장합니다. 즉 이 워크플로우는 "발행할 콘텐츠를 무엇으로,
언제 만들지" 결정하는 역할만 하고, 실제 업로드는 기존 자동화 파이프라인이
그대로 맡는 구조입니다.

## 요약: 전체 흐름

1. 코딩 세션마다 → 세션 로그 append (자동/반자동)
2. 매주 1회 → 로그를 태그별로 묶고 체크리스트로 딥다이브/요약 분류
3. 분류 결과 확인 → 승인
4. Claude Code가 템플릿에 맞춰 포스트 초안 작성 → `devlog/published/`
5. 기존 블로그 업로드 자동화가 해당 파일을 읽어 발행
