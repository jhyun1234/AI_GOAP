## 서두 — 측정 가능한 성공 기준

이 명세를 완료하면 다음이 **수치로** 달성되어야 한다:

1. **좌표 스냅 0건** — `VillagerFSM.StartPathTo()`가 경로 실패 시 `Brain.TileX/Y = targetX/targetY` 대입을 **하지 않는다**. 명세 완료 후 파일 전체 grep `Brain\.TileX\s*=\s*targetX` 결과 0건.
2. **PathResult 세 갈래 분기 100%** — `JPSPathfinder.FindPath()` 반환 struct `PathResult`는 `Kind ∈ {Unreachable, AlreadyThere, PathFound}` 셋 중 하나. 호출자는 세 분기 모두 명시 처리. 미처리(default 폴백) 0건.
3. **AbortReason 분리 4종** — Replanning 원인이 `PlanFailed / ResourceReservationFailed / PathUnreachable / ActionPreconditionInvalidated` 4종으로 구분 저장됨. `Brain.FallbackCounter` 대신 `Brain.FallbackByReason[reason]` 카운터로 원인별 관측 가능.
4. **10분 무개입 방치 회귀 지표**: PathUnreachable 카운트 **> 0인 케이스가 존재**하되(≠ 흡수되어 0), 그 뒤 Replanning으로 새 목표를 잡아 정상 이동이 재개되고 Deadlock 경고 **0건**.
5. **T13~T16 게이트 초록 유지** — 본 명세는 액션 상수/임계값을 건드리지 않음. 회귀 시 즉시 게이트로 잡힘.
6. **EditMode 테스트 신규 +6개**: PathResult 반환 규약 3종 + StartPathTo 분기 3종 검증. 총 EditMode 59 + 6 = 65 초록.

측정 도구: Unity Test Runner EditMode, `Assets/Tests/EditMode/`. 방치 테스트는 사용자 육안.

## ADR (구현 중 갈릴 판단 미리 결정)

이 결정을 바꾸려면 **사유를 커밋 메시지에 명시**한다.

- **ADR-M1**: `PathResult`는 **struct**로 만든다 (class 금지). GC 유발 방지 + JPS 호출부가 매 프레임 아님이지만 이동은 빈번. Kind는 `enum PathResultKind { Unreachable, AlreadyThere, PathFound }`.
- **ADR-M2**: `PathResult`에서 `List<Vector2Int> Waypoints`는 **Kind == PathFound일 때만 non-null**. Unreachable/AlreadyThere일 때 null. 호출자가 Kind로 분기하기 전 Waypoints 접근 금지 (nullref로 조기 실패).
- **ADR-M3**: `AlreadyThere`는 실패가 아니다 — StartPathTo는 조용히 반환한다. GOAP 액션은 자원 노드 도달로 간주하고 정상 Perform 진입. 이는 기존 `startX == goalX && startY == goalY` 분기의 의미를 그대로 승계한다.
- **ADR-M4**: `Unreachable` 수신 시 `Brain.TileX/Y` 대입 **금지**. 대신 `Brain.NearDiscoveredResource = false` 강제 + 현재 점유 노드가 있으면 `ReleaseGatherNode()` + `RequestReplanning(AbortReason.PathUnreachable)` 호출. 이것이 결함 C 해소의 핵심.
- **ADR-M5**: `AbortReason` enum은 `Brain`에 `FallbackByReason` Dictionary 필드로 저장하되, **기존 `Brain.FallbackCounter`는 유지**한다 (호환성). `FallbackCounter = sum(FallbackByReason.Values)` 관계. Deadlock 임계는 여전히 `FallbackCounter >= DEADLOCK_THRESHOLD`.
- **ADR-M6**: `HandleDeadlock`은 원인별로 다르게 처리한다:
  - PathUnreachable 3회 → 자원 노드 발견 상태 리셋 후 MoveToBase (기존 동작)
  - PlanFailed 3회 → Idle 전환 후 P0 재평가 (기존 동작)
  - ResourceReservationFailed 3회 → 목표 자원 타입 변경 시도
  - 이번 명세에서는 우선 **관측만** 하고 분기 처리 구현은 후속 커밋 (스코프 가드).
- **ADR-M7**: JPSPathfinder 내부 알고리즘·성능·좌표 변환은 **바꾸지 않는다**. 반환 타입만 wrapping. 알고리즘 변경은 별도 안건.
- **ADR-M8**: 반환 struct 이름은 `PathResult` — `PathFindResult`/`Path` 등 대안 금지. 파일 내 grep 일관성.

#### 코드 스케치

```csharp
namespace AIVillage.Core.Pathfinding // 또는 기존 namespace 유지
{
    public enum PathResultKind
    {
        Unreachable = 0,     // 경로 없음 or 목표 unwalkable or 범위 밖
        AlreadyThere = 1,    // 시작 == 목표
        PathFound = 2        // Waypoints에 최소 1개 이상
    }

    /// <summary>
    /// JPSPathfinder.FindPath()의 반환 계약.
    /// Kind로 분기하기 전 Waypoints 접근 금지 (ADR-M2).
    /// null 반환 시절의 흡수 로직을 강제 종료시키기 위한 명시 struct.
    /// </summary>
    public readonly struct PathResult
    {
        public readonly PathResultKind Kind;
        public readonly List<Vector2Int> Waypoints; // Kind == PathFound일 때만 non-null

        private PathResult(PathResultKind kind, List<Vector2Int> wp)
        {
            Kind = kind;
            Waypoints = wp;
        }

        public static PathResult Unreachable() => new PathResult(PathResultKind.Unreachable, null);
        public static PathResult AlreadyThere() => new PathResult(PathResultKind.AlreadyThere, null);
        public static PathResult Found(List<Vector2Int> wp) => new PathResult(PathResultKind.PathFound, wp);
    }

    public static class JPSPathfinder
    {
        // 기존 static List<Vector2Int> FindPath(...) → 유지 (obsolete 표기) 또는 내부 헬퍼로 격하
        [System.Obsolete("Use FindPath returning PathResult (ADR-M8). 이 오버로드는 M2 완료 후 삭제 예정.")]
        public static List<Vector2Int> FindPath(int sx, int sy, int gx, int gy, bool[,] walkable)
        {
            var r = FindPathResult(sx, sy, gx, gy, walkable);
            return r.Kind == PathResultKind.PathFound ? r.Waypoints
                 : r.Kind == PathResultKind.AlreadyThere ? new List<Vector2Int>()
                 : null;
        }

        public static PathResult FindPathResult(int sx, int sy, int gx, int gy, bool[,] walkable)
        {
            // 기존 FindPath 로직 복붙 — 반환만 PathResult로 감싸기
            // - walkable == null → Unreachable + Warning
            // - startX == goalX && startY == goalY → AlreadyThere
            // - out of bounds → Unreachable + Warning
            // - !walkable[gax, gay] → Unreachable + Warning
            // - 탐색 실패 → Unreachable (Warning 없음 — 정상 흐름)
            // - 탐색 성공 → Found(reconstructedList)
        }
    }
}
```

- [x] `PathResult` readonly struct 정의 + 3개 static 팩토리 메서드
- [x] `JPSPathfinder.FindPathResult()` 신규 메서드가 기존 `FindPath` 로직을 감싸 3분기 반환
- [x] 기존 `JPSPathfinder.FindPath()` 시그니처를 **삭제하지 않고** `[System.Obsolete]` 표기 (M2에서 호출부 마이그레이션 후 M2 커밋 내에서 삭제)
- [x] `AlreadyThere`는 `startX == goalX && startY == goalY` 조건에서만 반환 (기존 `return new List<Vector2Int>()` 위치)
- [x] `Unreachable` 반환 시 기존 `Debug.LogWarning` 4개(walkable null, 시작 범위 밖, 목표 범위 밖, 목표 unwalkable)는 그대로 유지 — 이 경고는 진단 신호

#### ⚠️ 오해 위험

- ❌ **PathResult를 class로 만드는 것**: struct여야 함 (ADR-M1). Waypoints 리스트는 어차피 heap이므로 struct가 gc-free 아니지만, wrapper 자체는 stack에 남아 인지 부담 최소.
- ❌ **Kind == Unreachable일 때 Waypoints를 빈 리스트로 채우는 것**: null이어야 함 (ADR-M2). 빈 리스트는 "탐색은 했지만 결과 없음" 오해 유발 — 호출자가 Kind 대신 Waypoints.Count로 분기하려는 유혹을 차단해야 함.
- ❌ **FindPath 기존 시그니처를 즉시 삭제**: M2 커밋 안에서 호출부 마이그레이션과 함께 삭제. M1에서 삭제하면 EnemyFSM/FactionAI 등 다른 호출자가 있을 경우 이 커밋에서 컴파일 실패 → 스코프 침범.
- ❌ **`FindPath()`를 그대로 두고 반환값만 감싸는 헬퍼 하나 더 만드는 것**: ADR-M8 위반. 이름은 `FindPathResult` 하나로 통일.
- ❌ **AlreadyThere 시 Waypoints를 non-null 빈 리스트로**: null이어야 함. 호출자가 `if (r.Kind == AlreadyThere) return;` 형태로 조기 반환하면 Waypoints를 볼 일이 없음.

```csharp
// StartPathTo 반환값을 enum으로 승격 — 호출자가 "이동 진짜로 시작했는지" 구분 가능
private enum StartPathOutcome
{
    Started = 0,       // Waypoint 이동 개시
    AlreadyThere = 1,  // 이미 목표 — 조용히 성공
    Unreachable = 2    // 경로 없음 — 호출자가 Replanning 결정
}

private StartPathOutcome StartPathTo(int targetX, int targetY)
{
    // walkable 초기화 (기존 유지)
    if (_walkableGrid == null) { /* ... */ }

    _currentPath.Clear();
    _pathIndex = 0;
    _isMoving  = false;

    // 이미 목표에 있음 (기존 조기 반환 위치)
    if (Brain.TileX == targetX && Brain.TileY == targetY)
        return StartPathOutcome.AlreadyThere;

    var result = JPSPathfinder.FindPathResult(
        Brain.TileX, Brain.TileY, targetX, targetY, _walkableGrid);

    switch (result.Kind)
    {
        case PathResultKind.AlreadyThere:
            return StartPathOutcome.AlreadyThere;

        case PathResultKind.Unreachable:
            // ⚠️ 결함 C 해소: 좌표 강제 스냅 금지.
            // 기존 코드: Brain.TileX = targetX; Brain.TileY = targetY; return;
            // 새 코드:  호출자에게 이동 실패를 전달. GOAP가 재계획하도록.
            Debug.LogWarning(
                $"[VillagerFSM] Unreachable 수신, Replanning 요청. " +
                $"AgentId={AgentId}, from=({Brain.TileX},{Brain.TileY}), to=({targetX},{targetY})");
            return StartPathOutcome.Unreachable;

        case PathResultKind.PathFound:
            _currentPath    = result.Waypoints;
            _pathIndex      = 0;
            _isMoving       = true;
            _waypointTarget = new Vector3(_currentPath[0].x, _currentPath[0].y, 0f);
            return StartPathOutcome.Started;

        default:
            // ADR-M2에 따라 도달 불가. 방어 로그 후 Unreachable 취급.
            Debug.LogError($"[VillagerFSM] PathResult.Kind 미지원 값: {result.Kind}");
            return StartPathOutcome.Unreachable;
    }
}

// MoveTileForAction — Unreachable을 받았을 때 결함 C 해소 조치
private void MoveTileForAction(string actionId)
{
    if (actionId == null) return;
    ReleaseGatherNode();

    if (actionId == "Explore")
    {
        var t = FindExplorationTarget();
        if (StartPathTo(t.x, t.y) == StartPathOutcome.Unreachable)
            OnMoveUnreachable(actionId);
        return;
    }

    ResourceType? targetType = GetResourceTypeForAction(actionId);
    if (targetType.HasValue && SensorSystem.Instance != null)
    {
        ResourceNode nearest = FindNearestDiscoveredNode(targetType.Value);
        if (nearest != null && nearest.TryOccupy(AgentId))
        {
            _currentGatherNode = nearest;
            var outcome = StartPathTo(nearest.TileX, nearest.TileY);
            if (outcome == StartPathOutcome.Unreachable)
            {
                ReleaseGatherNode();
                OnMoveUnreachable(actionId);
            }
            return;
        }
    }

    // 기지 이동
    if (StartPathTo(_baseTileX, _baseTileY) == StartPathOutcome.Unreachable)
        OnMoveUnreachable(actionId);
}

/// <summary>
/// 이동 불가 발생 시 결함 C 해소 조치:
/// 1) NearDiscoveredResource=false 강제 → GOAP가 자원 근접 전제조건을 재검사하도록
/// 2) Replanning 요청 (AbortReason.PathUnreachable)
/// </summary>
private void OnMoveUnreachable(string actionId)
{
    Brain.NearDiscoveredResource = false;
    RequestReplanning(AbortReason.PathUnreachable, $"actionId={actionId}");
}
```

```csharp
namespace AIVillage.Tests.EditMode
{
    /// <summary>
    /// M17: JPSPathfinder.FindPathResult()의 반환 계약 3분기 검증.
    /// - Unreachable: Waypoints == null
    /// - AlreadyThere: Waypoints == null
    /// - PathFound: Waypoints != null, Count > 0
    /// (결함 C 재발 방지 — ADR-M2)
    /// </summary>
    public class M17_PathResultContract
    {
        private static bool[,] MakeFullyWalkable(int size)
        {
            var w = new bool[size, size];
            for (int x = 0; x < size; x++)
                for (int y = 0; y < size; y++) w[x, y] = true;
            return w;
        }

        [Test]
        public void AlreadyThere_when_start_equals_goal()
        {
            var w = MakeFullyWalkable(100);
            var r = JPSPathfinder.FindPathResult(0, 0, 0, 0, w);
            Assert.AreEqual(PathResultKind.AlreadyThere, r.Kind,
                "시작==목표 시 Kind는 AlreadyThere여야 한다.");
            Assert.IsNull(r.Waypoints,
                "AlreadyThere일 때 Waypoints는 null이어야 한다 (ADR-M2).");
        }

        [Test]
        public void PathFound_when_reachable()
        {
            var w = MakeFullyWalkable(100);
            var r = JPSPathfinder.FindPathResult(0, 0, 5, 5, w);
            Assert.AreEqual(PathResultKind.PathFound, r.Kind);
            Assert.IsNotNull(r.Waypoints);
            Assert.Greater(r.Waypoints.Count, 0);
        }

        [Test]
        public void Unreachable_when_goal_unwalkable()
        {
            var w = MakeFullyWalkable(100);
            // 목표 타일을 불가로 만들기 — 배열 인덱스 기준 (50,50) = 타일 (0,0)
            // 여기서는 (5,5)를 목표로 지정하고 그 인덱스만 false로 설정
            int offset = 50;
            w[5 + offset, 5 + offset] = false;
            var r = JPSPathfinder.FindPathResult(0, 0, 5, 5, w);
            Assert.AreEqual(PathResultKind.Unreachable, r.Kind);
            Assert.IsNull(r.Waypoints);
        }

        [Test]
        public void Unreachable_when_out_of_bounds()
        {
            var w = MakeFullyWalkable(100);
            var r = JPSPathfinder.FindPathResult(0, 0, 999, 999, w);
            Assert.AreEqual(PathResultKind.Unreachable, r.Kind);
            Assert.IsNull(r.Waypoints);
        }

        [Test]
        public void Unreachable_when_walkable_null()
        {
            var r = JPSPathfinder.FindPathResult(0, 0, 5, 5, null);
            Assert.AreEqual(PathResultKind.Unreachable, r.Kind);
            Assert.IsNull(r.Waypoints);
        }
    }
}
```

**정직한 답**: 플레이어가 화면에서 새로 보게 되는 것은 **없다**. 이 명세는 **재미의 전제조건**이다.

지금까지 플레이어가 보게 되던 것: 자원 노드 근처에 도착한 것처럼 보이지만 정지, Perform 액션이 진행되지 않고 대기, Console에 Deadlock 경고, 결국 MoveToBase 후 재시도 → 사이클이 눈에 띄게 끊김.

명세 완료 후 플레이어가 **덜 보게 되는 것**: Unreachable 상황에서 주민이 도착한 척 정지하는 유령 이동. 그 대신 주민이 즉시 재계획해 실제로 도달 가능한 다른 자원 노드나 탐험 목표를 선택 → 사이클이 매끄러움.

이 작업은 "이미 있던 재미가 사라지지 않도록" 하는 안전망이다. F-A 성격 특성 진입 전 결함 C를 봉합하면 배율 곱셈이 이동 실패를 유발해도 GOAP가 무너지지 않는다.
