## ADR 절 (구현 중 갈릴 판단 미리 결정)

* **ADR-③-1**: `GatherGoalSelector.Select()` 시그니처 확장은 **자원별 bool 인자 5개 추가**로 한다. `Func<ResourceType,bool>` 델리게이트 방식은 알로케이션 유발로 제외한다. 변경하려면 사유를 커밋 메시지에 명시.
* **ADR-③-2**: 발견 판정은 `SensorSystem.Instance.GetAllNodes()`를 O(N) 단일 순회로 처리한다. 캐싱 안 함 — 플래닝 재계산 주기(수 tick)가 O(N=수십 노드) 스캔을 흡수한다. 변경하려면 프로파일러 근거를 커밋에 붙인다.
* **ADR-③-3**: "발견"의 정의 = `IsDiscovered=true` **AND** `CurrentAmount>0`. 채집 후 소진된 노드는 미발견과 동일 처리 (플래너 관점에서 사용 불가). 이는 `GOAPPlannerScheduler.cs:610`의 판정 기준과 동일하다.
* **ADR-③-4**: T17 게이트는 순수 GatherGoalSelector 정적 함수 단위 테스트로 한다. Play Mode/통합 테스트 아님. 이유: EditMode 유지가 68→71 확장선상. 회귀 감지 속도 우선.
* **ADR-③-5**: 이번 커밋에서 **플래너 코어(PlannerJob/CalculateHeuristic) 손대지 않는다**. CLAUDE.md 플래너 코어 동결 규정 준수. 휴리스틱 정보량 부족(원인 2)은 별개 안건으로 로드맵에 남긴다.
* **ADR-③-6**: RawFood는 `hasTool` 없이도 채집 가능하므로 discovered 게이팅에서 **동일하게 미발견 시 스킵**한다. 예외 두면 이슈의 대칭성 무너진다. HarvestWildBerries도 `NearDiscoveredResource=1` 필요.

## F1 — GatherGoalSelector API 확장

**대상 파일**: `Assets/Scripts/AI/GatherGoalSelector.cs`

**코드 스케치** (한글 주석 유지, 기존 파일 리네이밍 최소):

```csharp
namespace AIVillage.AI
{
    public static class GatherGoalSelector
    {
        public const float T_COMMON = 30f;
        public const float T_RARE   = 15f;
        public const float T_FOOD   = 15f;

        /// <summary>
        /// [방향 ③ F1] 발견되지 않은 자원 타입은 후보에서 제외한다.
        /// 미발견 자원의 컨텍스트 배율(FULL_NODE_PENALTY×2=10)이 액션 비용을 폭발시켜
        /// admissible 휴리스틱이 A*를 안내하지 못하고 NoSolutionFound가 발생한다.
        /// 원인 근거: Docs/이슈_GatherIron_초반_무해.md P1-A 진단.
        /// </summary>
        public static string Select(
            float woodStock,
            float stoneStock,
            float ironStock,
            float copperStock,
            float rawFoodStock,
            bool  hasTool,
            bool  woodDiscovered,
            bool  stoneDiscovered,
            bool  ironDiscovered,
            bool  copperDiscovered,
            bool  foodDiscovered)
        {
            string best       = null;
            float  worstRatio = 1f;

            void Consider(float stock, float threshold, string goalId)
            {
                if (stock >= threshold) return;
                float ratio = stock / threshold;
                if (ratio < worstRatio) { worstRatio = ratio; best = goalId; }
            }

            if (hasTool && woodDiscovered)   Consider(woodStock,   T_COMMON, "GatherWood");
            if (hasTool && stoneDiscovered)  Consider(stoneStock,  T_COMMON, "GatherStone");
            if (hasTool && ironDiscovered)   Consider(ironStock,   T_RARE,   "GatherIron");
            if (hasTool && copperDiscovered) Consider(copperStock, T_RARE,   "GatherCopper");
            if (foodDiscovered)              Consider(rawFoodStock, T_FOOD,  "GatherFood");
            return best;
        }
    }
}
```

**DoD**:
- [ ] `GatherGoalSelector.Select`가 11개 인자를 받는다 (기존 6 + 신규 5).
- [ ] 각 자원 discovered 인자가 false면 해당 `Consider` 호출을 스킵한다.
- [ ] `hasTool=false`이면서 `foodDiscovered=true`일 때 GatherFood 후보는 유지된다 (ADR-③-6).
- [ ] 모든 자원 discovered=false면 반환값 null.
- [ ] 기존 파일의 T_COMMON/T_RARE/T_FOOD 상수 값·주석 그대로 유지.
- [ ] 컴파일 초록 (호출부 P1 미갱신 시 F1 커밋 전 임시 오버로드 유지 여부는 커밋 순서에서 명시).

**⚠️ 오해 위험**:
1. "기존 6인자 오버로드를 남겨둔다"고 해석하지 말 것. **파일 안에 6인자 오버로드 남겨두면 P1 갱신 안 된 호출부가 은닉된다.** F1과 P1은 같은 세션에서 P1 커밋을 F1 직후로 붙이고, 6인자 오버로드는 F1 커밋에서 **삭제한다**. 호출부가 컴파일 깨지는 순간은 F1 커밋 진행 중이며, P1 커밋에서 즉시 회복된다.
2. discovered 인자를 "SensorSystem 접근 여부"로 해석하지 말 것. GatherGoalSelector는 정적 순수 함수 유지 (MonoBehaviour 의존성 X). SensorSystem 조회는 호출부(P1)에서 한다.

## P1 — FSM `SelectGatherGoalId` 호출부 갱신

**대상 파일**: `Assets/Scripts/AI/VillagerFSM.cs` (라인 1877 근방)

**코드 스케치**:

```csharp
/// <summary>
/// [방향 ③ P1] 임계값 미만 자원 중 가장 부족한 것의 구체 Goal ID를 반환한다.
/// 미발견 자원은 후보에서 제외되어 무해 Goal이 플래너로 넘어가지 않는다.
/// 발견 판정: IsDiscovered && CurrentAmount>0 (GOAPPlannerScheduler.cs:610과 동일 계약).
/// </summary>
private string SelectGatherGoalId()
{
    if (_registry == null) return null;

    // ── 자원 타입별 발견 여부 스캔 (O(N), N=자원 노드 수) ─────────────
    // 캐싱하지 않는다 (ADR-③-2). SensorSystem이 없으면 전부 false로 안전 폴백.
    bool woodDisc = false, stoneDisc = false, ironDisc = false,
         copperDisc = false, foodDisc = false;
    var nodes = SensorSystem.Instance?.GetAllNodes();
    if (nodes != null)
    {
        for (int i = 0; i < nodes.Count; i++)
        {
            var n = nodes[i];
            if (!n.IsDiscovered || n.CurrentAmount <= 0f) continue;
            switch (n.ResourceType)
            {
                case ResourceType.Wood:    woodDisc   = true; break;
                case ResourceType.Stone:   stoneDisc  = true; break;
                case ResourceType.Iron:    ironDisc   = true; break;
                case ResourceType.Copper:  copperDisc = true; break;
                case ResourceType.RawFood: foodDisc   = true; break;
            }
        }
    }

    return GatherGoalSelector.Select(
        _registry.GetAvailable(ResourceType.Wood),
        _registry.GetAvailable(ResourceType.Stone),
        _registry.GetAvailable(ResourceType.Iron),
        _registry.GetAvailable(ResourceType.Copper),
        _registry.GetAvailable(ResourceType.RawFood),
        Brain != null && Brain.HasTool,
        woodDisc, stoneDisc, ironDisc, copperDisc, foodDisc);
}
```

- [ ] `SensorSystem.Instance`가 null이면 5개 discovered 전부 false로 폴백한다 (안전 기본값).
- [ ] `_registry`가 null이면 기존처럼 null 반환 (변경 없음).
- [ ] EditMode 전체 통과 (68건 → T17 추가 전엔 68건 유지).

**⚠️ 오해 위험**:
1. **`SensorSystem` 접근 성능이 부담**이라고 해석해 캐싱하지 말 것. 프로파일러 근거 없이 캐싱하면 캐시 무효화 시점 관리 부담이 커진다 (ADR-③-2).

3. **`Brain.NearIronOre` 재사용 유혹 차단**. 개별 주민의 근접 플래그가 아니라 **맵 전역**의 발견 여부다. Brain 플래그는 근접 액션에만 쓴다.

using NUnit.Framework;
using AIVillage.AI;

namespace AIVillage.Tests
{
    /// <summary>
    /// [T17] 문맥 배율 무해 회귀 방지 게이트.
    /// 원인 근거: Docs/방향3_무해_문맥배율_명세서.md, Docs/이슈_GatherIron_초반_무해.md.

        [Test]
        public void UndiscoveredIron_should_not_be_selected_as_gather_goal()

                copperDiscovered: true, foodDiscovered: true);
            Assert.AreNotEqual("GatherIron", result,
                "IronOre 미발견 상태에서 GatherIron이 반환되면 A* 4096 노드 소진 (Docs/이슈_GatherIron_초반_무해.md).");

        public void DiscoveredIron_below_threshold_should_be_selected()
        {
            // 시나리오: 도구 O, Wood/Stone 40, Iron 5(< T_RARE 15), IronOre 발견.
