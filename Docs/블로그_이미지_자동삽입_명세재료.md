# 블로그 글 시각 표현 — 명세 재료

작성 2026-08-01, **개정 2026-08-02(결론 뒤집힘)**. 명세서가 아니라 명세 전 실사 기록이다.
실행명세서는 필요성이 선 뒤에 `spec-write` 절차로 따로 쓴다.

시작은 *"쇼츠처럼 블로그에도 이미지를 자동 생성해 붙일 수 있을까?"* 였고, 초판 결론은

가능하면 그게 낫다."** 재보니 맞았다. 아래는 그 재측정 결과다.

## 0-A. 확정 및 반영 완료 (2026-08-02)

**결정이 끝났고 파이프라인에 배선까지 들어갔다.** 이 절이 현재 상태다.

### 쓰는 것 넷 / 안 쓰는 것 넷

| ✅ 쓴다 | 쓸 자리 | 🔴 안 쓴다 | 이유 |
|---|---|---|---|
| 화살표 사슬 | 인과 | `<pre>` ASCII 도식 | 박스 문자가 쇼츠 자막에 샌다 |
| 콜아웃 | 교훈·경고 | 이모지 | 영상 엔진 폰트에 없어 두부(□) 위험 |
| 표 | 값 2+ × 항목 2+ | 2단 카드·타임라인 | 조각이 브리프에 섞이고 이득은 겹침 |
| 비율 막대 **(표 안에서만)** | 비율·배수의 크기 | 그림 파일(이미지·SVG) | 보류 — §5 |

🔑 **막대를 표 안에 가둔 것이 설계의 핵심이다.** 표 밖에 두면 `순둥이0.10` 같은 조각이
쇼츠 브리프에 샌다(실측). 표 안에 있으면 기존 `<table>` 방어선이 공짜로 걸리고,
`div.class` 삭제 규칙을 만들 필요가 없다 — 그 규칙은 **중첩 `<div>` 에서 정규식이 첫
`</div>` 에 끊겨 깨진다.**

### 정확성 3원칙

1. **표는 재배열이지 추가가 아니다** — 모든 셀이 산문에 근거를 가져야 한다.
2. **모든 행에 근거가 있는 열만 만든다** — 빈 칸을 `—` 로 채우는 것도 금지.
3. 🔑 **표를 지워도 글이 성립해야 한다** — 결론과 양 끝 값은 산문에도 남긴다.
   **낱말이 아니라 주장 단위로 확인한다.**

3번은 쇼츠 때문이다. 기획팀이 브리프를 만들 때 표를 통째로 지우므로, 표에만 있는 값은
영상 작성팀에게 도달하지 않는다.

## 0. 결론 (2026-08-02 개정 전 기록)

**기본은 표와 화살표다. SVG 도해는 보류한다.**

뒤집은 이유는 하나가 결정적이다 — **표는 검수 게이트를 통과하고, 그림은 우회한다.**
표 안의 숫자는 텍스트라 `blog-reviewer`의 사실 대조 통로에 그대로 들어간다. 그림 속
숫자는 검증기가 구조만 볼 뿐 내용이 맞는지 못 본다. 이 블로그의 정체성이 "증거와
대조된 정확성"인데, 그림은 그 정체성을 지키는 장치를 비껴간다.

부수 효과로 **초판 설계가 통째로 사라진다** — `[[FIG:]]` 자리표도, `blog-illustrator`
신설도, 검증기 10항목도 전부 "base64가 분량 게이트를 오염시킨다"를 우회하려던 장치였다.
표는 진짜 내용이라 `wc -m`에 계수되는 게 맞다. 문제 자체가 없어진다.

> 🔴 **이 문서는 "착수 준비 완료"가 아니다.** 필요성은 아직 검증되지 않았다 —
> 독자 데이터(이탈률·체류시간)를 본 적이 없고, "그림이 없어서 사람이 나간다"는 관측이
> 아니라 추측이다. §3의 작업(표를 쓸 수 있게 하는 것)은 이미 있는 사람에게 없던 표현
> 수단을 열어주는 것이라 값이 싸지만, §5(SVG)는 필요가 실제로 설 때까지 짓지 않는다.

## 1. 표·화살표 실측 (2026-08-02, 라이브 테마)

발행된 글 페이지에 표본을 주입해 **실제 테마 CSS 안에서** 쟀다. 별도로 블로거에 비공개
초안(id `2368707979970917501`)을 올려 저장 경로도 확인했다.

### 1-1. 저장 경로 = 무손실

| 항목 | 값 |
|---|---|
| 보낸 / 저장된 바이트 | 4,360 → 4,360 (완전 일치) |
| `style` 속성 | 35개 전부 유지 |
| `<table>/<tr>/<th>/<td>` | 49개 전부 유지 |

### 1-2. 폭 실측 (컨테이너 720px / 360px)

| 표본 | 720px | 360px | 판정 |
|---|---|---|---|
| ① 맨 `<table>` (스타일 없음) | 172px | 172px | **글자가 뭉친다** — 테마엔 `td,th{padding:0}` 뿐 |
| ② `width:100%` + 테두리/여백 | 720 | 360 | **기본형.** 넘치지 않음 |
| ③ `min-width:640` + `overflow-x` 감싸개 | 640 | 640(감싸개가 스크롤) | **페이지는 안 밀림** |
| ④ `<pre>` + `overflow-x:auto` | 720 | 자체 스크롤 | 페이지 안 밀림 |

🔑 ③이 핵심이다. 열이 많은 표를 감싸개 없이 넣으면 **페이지 전체가 가로로 밀린다.**
감싸개가 있으면 표만 스크롤된다(페이지 가로 스크롤 없음을 실측 확인).

### 1-3. 테마에서 뽑은 값 (스타일 맞출 때 쓸 것)

```
본문      Roboto, sans-serif · 15px · line-height 24px · #757575 · 폭 810px
h2        22.5px · 700 · margin-top 18.7px
표 규칙   table{border-collapse:collapse} · td,th{padding:0}   ← 이 둘이 전부다
이미지    .post-body img{max-width:100%}
```

**테마가 표를 전혀 꾸미지 않는다.** 선도 여백도 없다 → **인라인 style이 필수다.**
미리보기 표본: `tools/blog-automation/.staging/table-preview.html` (gitignore 대상).

## 2. 지금은 표를 쓸 수 없다 — 파이프라인의 공백

- **편집팀 변환 규칙에 표가 없다.** [blog-editor.md:24-31](../.claude/agents/blog-editor.md)
  의 목록은 `##`→h2, `**`→b, 인용, 번호 목록, `---`→hr, 문단뿐이다.
  마크다운 표를 쓰면 파이프 문자가 그대로 남는다.
- **작성팀은 표를 언급조차 하지 않는다** (`blog-writer.md` 전문 검색 결과 0건).
- **발행 13편 중 `<table>` 사용 0편.** 화살표는 문장 속에 14개.

즉 지금까지 표가 안 나온 건 선택이 아니라 **수단이 없었기 때문**이다.

## 3. 그래서 할 일 (작다)

1. **편집팀**: 마크다운 표 → `<table>` 변환 규칙 + 인라인 style 규격(§1-3).
   열이 4개를 넘으면 `overflow-x:auto` 감싸개를 두른다.
2. **작성팀**: *"수치 비교·전후 대비는 표로, 인과는 화살표(→)로 써도 된다"* 한 줄.
   분량 게이트와 충돌하지 않는다 — 표는 진짜 내용이다.
3. **쇼츠 추출기**: `</td>`·`</th>`에 구분자 한 줄
   (`.replace(/<\/t[dh]>/g,' | ')`). 없으면 셀이 붙는다 — 실측:

   ```
   고치기 전:  0%2명0건통과
   고친 뒤:    0% | 2명 | 0건 | 통과
   ```

**새 에이전트 0개, 새 게이트 0개, 새 검증기 0개.**

## 4. 표가 SVG보다 나은 이유 (실측 기반)

| | 표·화살표 | SVG 도해 |
|---|---|---|
| **검수팀 사실 대조** | 통과 — 숫자가 텍스트 | **우회** — 구조만 검증 가능 |
| 파이프라인 단계 | +0 | +1 (illustrator) + 검증기 |
| 분량 게이트 | 정상 계수 | base64 2,000자/장이 산문으로 계수돼 오염 |
| 쇼츠 추출 | 정상 재료(구분자 한 줄 필요) | 인라인은 **누수**, data URI는 소실 |
| 검색 색인·스크린리더 | 읽힘 | `<img>` 안 글자는 안 읽힘 |
| 모바일 | ②는 자동 축소, ③은 감싸개 | style 없으면 넘침·종횡비 파괴 |

## 5. SVG가 남는 자리 (보류 — 초판 실측 보존)

**공간 배치 자체가 의미인 것** 하나뿐이다: 계획 사슬 그래프(노드-화살표 망), 구역
배치도, 타임라인 위 사건 밀도 — 표로 접으면 뜻이 사라지는 것. 실제로 필요해질 때
아래 실측을 그대로 쓰면 된다(초안 id `3651540856696193014`, 2026-08-01).

- **블로거 저장 경로엔 새니타이징이 없다** — 5,461바이트 무손실 왕복. 인라인 SVG·data
  URI·style·figure 전부 통과. A/B/C 네 방식 모두 브라우저 렌더 확인.
- 🔴 **인라인 SVG는 쇼츠를 오염시킨다.** `scene-planner` 추출 정규식이 `<text>`의
  *내용*을 남겨, 그림 속 라벨이 기사 본문 문장으로 둔갑해 브리프에 들어간다(실측).
  data URI·원격 `<img>`는 base64에 `>`가 없어 통째로 지워진다. → **쓴다면 data URI**.
- 🔴 **`*.png`는 raw 핫링크가 깨진다** — LFS 추적이라 130바이트 포인터가 나온다.
  `*.svg`는 `image/svg+xml`로 정상 서빙(GitHub Pages 불필요).
- 🔴 **테마의 `max-width:100%`만 믿으면 종횡비가 깨진다** — `height` 속성이 남아 360px
  폭에서 68이어야 할 높이가 120이 된다. `style="max-width:100%;height:auto"` 필수.
- 🔑 **`textLength` + `lengthAdjust="spacingAndGlyphs"`** 는 폰트가 달라도 텍스트 폭을
  선언값으로 고정한다(자유 267px vs 선언 280px → 정확히 280). 크로미움 없는 클라우드에서
  **픽셀 검수 없이 잘림을 원리적으로 막는** 수단이다.
- 쓰게 되면 지킬 것: viewBox 안 좌표 · 배경 rect 필수(투명 금지) · 외부 참조 전면 금지
  (`<script>`/`<image href>`/`<foreignObject>`/외부 폰트) · font-family 화이트리스트 ·
  alt/figcaption 필수 · 회차가 그림을 소유(공용 도형 라이브러리 금지).

## 6. 아직 안 잰 것 / 결정할 것

측정된 것처럼 쓰지 않기 위해 분리해 둔다.

1. **필요성 자체** — 독자 데이터가 없다. 이탈률·체류시간을 본 적이 없다. **여전히 미검증.**
2. **표의 실제 효과** — 읽기 쉬워지는지는 재본 적 없다. 실제 발행 회차에 넣어 보고 판단.
3. **테마 안 최종 모습** — 초안은 공개 URL이 없어 로그인 없이 못 본다.
   확인: [표 초안 편집기](https://www.blogger.com/blog/post/edit/6014451945015572125/2368707979970917501)
4. ~~글당 표 개수 기준~~ → **확정: 글당 2개까지.** 그 이상이면 글을 쪼개라는 신호.
5. **기존 13편 소급 적용 여부** — 백필하면 쇼츠 원본이 바뀐다. **미정.**
6. **`og:image`** — 현재 글엔 이미지가 없어 아예 안 붙는다. 소셜 카드가 필요해지면
   그때는 표로 못 하고 그림(§5의 원격 호스팅)이 필요하다.
7. **`eptest-m11` 폴더 처분** — `build/` 만 26MB 다. `scene.json` 과 `kinds/` 만 남기고
   빌드 산출물은 빼는 것을 권함. 이 회차는 **업로드용이 아니다**(`uploads.json` 미기록).
8. **실제 발행 회차 첫 적용** — 위 배선이 무인 사이클에서 처음 도는 것은 아직이다.
   첫 회차는 사람이 결과를 확인하는 것을 권함.
