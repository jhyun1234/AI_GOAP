### 0.3 유튜브 자막 트랙 1차 판단 — 🔴 **③이 틀렸다. §0.4 가 정본이다**

> **이 절은 기각 근거였다가 실측에 뒤집힌 기록이다.** 지우지 않는 이유는 ①·②는 여전히
> 유효하고 ③만 틀렸기 때문이고, **무엇을 어떻게 잘못 판단했는지가 다음 판단의 재료**이기 때문이다.

브레인스토밍 중 "영어 SRT 에 배경 박스를 넣어 번인 한국어를 가린다"는 안(사용자 제안)이
나왔고 **내가 기각했다.**

1. **유튜브가 자막 파일의 스타일을 버린다.** 업로드된 캡션을 자체 내부 표현으로 변환한 뒤
   플레이어 자체 스타일로 렌더한다. SRT·VTT·TTML 모두 배경색·위치·폰트 지정이 무시된다.
   스타일이 먹는 건 문서화되지 않은 SRV3/YTT 뿐이고, 미문서 포맷에 무인 파이프라인을 걸 수 없다.
2. **통제권이 시청자에게 있다.** 자막 배경 유무·크기·색은 시청자 설정이 이긴다.
   배경을 끈 시청자는 겹친 화면을 본다. 그리고 **자막은 끌 수 있다** — 끄면 한국어만 남는다.
3. 🔴 ~~**위치를 못 맞춘다.** 유튜브 자막은 하단 중앙 고정이고 쇼츠 플레이어는 그 위에
   제목·채널·버튼 UI 를 얹는다.~~ → **틀렸다.** 실측 결과 유튜브는 쇼츠에서 자막을
   **화면 위쪽**에 놓는다(§0.4). 우리 번인 자막과 겹치는 일이 애초에 없다.
   내가 "하단 중앙 고정"을 확인하지 않고 일반 유튜브 플레이어의 인상으로 단정했다.

→ ①②는 유효하다. 그러나 **겹치지 않으므로 배경 박스가 필요 없어졌고**, 사용자가 원했던 것
(겹치지 않게 한다)이 제안한 방법(배경색) 없이 달성됐다. **①②는 이 방식을 막지 못한다.**

**파생안(번인을 빼고 clean 렌더 + 자막 트랙 2개)은 여전히 기각한다.** 통제는 되찾지만
①자막이 기본 꺼진 시청자에게 글자가 하나도 없는 영상이 되고 ②자막 2줄 상한·하단 안전영역·
잘림 검사가 전부 의미를 잃는다(그 안전영역 검사는 2026-07-29 "자막 둘째 줄이 채널 아이콘에
묻힌" 실제 사고로 생긴 것이다 — `check.mjs:234`) ③이미 잘 되는 한국어 경험을 깨서
아직 존재하지 않는 영어 시청자를 얻으려는 거래다.

🔑 **교훈**: 나는 여기서 **재보지 않고 기각했다.** 실측 비용은 SRT 한 장과 스크린샷 두 장이었다.
"게이트로 잡을 수 없는 실패다"까지 써 놓고 **재보는 대신 설계를 바꾸려 했다.**
이 프로젝트가 ADR-V-7 로 금지한 것("미측정 주장으로 규칙 만들기")의 거울상이다 —
미측정 주장으로 **길을 막는 것**도 같은 실패다.

## 2. ADR — 구현 중 갈릴 판단을 미리 결정

> 바꾸려면 **무엇을 관측했고 이 결정이 왜 실패하는가**를 커밋 메시지와 이 문서 본문에 남긴다
> (`feedback_living_adr_revision`).

### ADR-V-9 — 🔴 **폐기.** 영어 대본 파일(`scene.en.json`)은 만들지 않는다.
> **무엇을 관측했나**: 사용자가 "영상을 따로 2개 올릴 생각은 없다"로 방향을 확정했다(2026-08-05).
> **옛 결정이 왜 실패하는가**: 영어 대본 파일은 **영어 영상을 만들기 위한 것**이었다.
> 영상이 하나면 영어는 자막 트랙으로만 존재하므로 별도 대본 파일의 존재 이유가 사라진다.

**대신**: 영어는 한국어 대본 **안에** 산다 — `lines[].en` · `youtube.en`(ADR-V-16).
파일 개수가 안 늘어서 무인 파이프라인이 전혀 영향을 안 받는다는 옛 장점은 **더 강하게** 유지된다.

### ADR-V-10 — 🔄 **개정 (2026-08-10).** 화면에 뜨는 글자는 **한국어**가 기본이다.

> **무엇을 관측했나**: 유튜브 **시청자 국가 분포에서 해외가 0.7%** 다(사용자 실측, 2026-08-10).
> 사용자 판정 — *"차라리 그냥 이제 한국 사람들한테 이해가 더 잘되게끔 하는 게 좋을 거 같아."*
>
> **옛 결정이 왜 실패하는가**: 옛 ADR-V-10 은 근거 둘로 서 있었다.
> ①**영어권 시청자가 CC 를 안 켜도 그림의 메커니즘을 따라온다** — 그 시청자층이 실측 0.7% 다.
> ②**한국어 시청자에게 개발일지답게 읽힌다** — 이건 **한 번도 관측된 적 없는 추정**이었다.
> 반대편 비용(**99.3%가 그림 라벨을 매번 한 번 번역해서 읽는다**)은 아예 재 본 적이 없다.
> 🔑 두 근거 중 하나는 대상이 0.7% 였고 하나는 미측정이었다 — **ADR-V-7(미측정 주장으로 규칙을
> 만들지 않는다)이 이 ADR 자신에게는 적용되지 않았다.**

**새 규칙**: 화면에 뜨는 글자는 **한국어가 기본**이다. 영어로 두는 것은 아래 셋뿐이다.

| 한국어로 (기본) | 영어로 남는 것 |
|---|---|
| 상태·축·계기판 이름 (`배고픔`, `비용`, `플래너`) | ① **코드·로그를 그 문자열 그대로 인용**하는 자리 (`NoSolutionFound`, `HungerLevel`) — 옮겨 적으면 인용이 아니게 된다 |
| 자막(`lines[].text/say`) **전체** · 판정 서술(`note`·`quote`) | ② **기호·수식·단위** (`A*`, `%`, `→`, `ms`) — 애초에 언어가 아니다 |
| **고유명사** — `순둥이`·`고집쟁이`·`농부` (전과 같음) | ③ 한국어에 대응어가 없어 **옮기면 뜻이 무너지는 고유 기술명** (`GOAP`, `Claude Code`) |

판정 기준 한 줄이 **뒤집혔다**: 옛 잣대는 *"코드에 있을 법한 말인가"* 였고,
새 잣대는 **"이걸 한국어로 옮기면 뜻이 상하나?"** → 안 상하면 한국어.
🔑 옛 잣대는 **「있을 법한」이라는 추측**을 판정에 넣어서, 라벨 하나를 두고 게임 리포를 열어
파일명을 확인해야 판정이 끝났다(ep12s-2 의 `HEATWAVE`). 새 잣대는 **화면만 보고 판정된다.**

⚠️ **영어 자막(ADR-V-16·V-19)은 이 개정과 무관하게 그대로 간다.** CC 는 켠 사람만 보므로
한국어 시청자에게 비용이 0 이고, 그림 라벨은 **전원이 본다** — 그래서 두 축의 답이 갈린다.
🔑 옛 문서가 *"화면 글자와 자막 글자가 같은 문자가 아니게 되어 겹침이 반으로 준다"* 를 부수
이득으로 적었는데, **그 이득은 개정 후에도 그대로다** — 자막이 영어면 화면이 한국어라 여전히 갈린다.

### ADR-V-11 — 라벨 규칙은 **게이트로 만들지 않는다.**
"짧은 한글은 경고" 같은 검사를 만들 수 있지만 **몇 자부터 짧은지에 근거가 없다.**
지어낸 임계값으로 게이트를 만드는 것은 ADR-V-7 이 금지한 것이다.
→ 에이전트 지침과 검수로 간다. 표기가 실제로 흔들리는 것이 관측되면 그때 근거를 갖고 만든다.

### ADR-V-12 — 🔴 **폐기.** 게이트 언어 테이블은 만들지 않는다.
> **무엇을 관측했나**: 영상이 하나이므로 대본도 하나(한국어)뿐이다.
> **옛 결정이 왜 실패하는가**: 이 ADR 은 `check.mjs` 가 **영어 대본을 판정**하는 상황을 위한
> 것이었다. 영어는 이제 자막 트랙으로만 존재하고 `check.mjs` 가 보는 대본은 언제나 한국어다.
> 예고 정규식·제목 이행·말 속도·`CPS_REF` 전부 **한국어 그대로 두면 맞는다.**

🔑 그러나 이 ADR 이 담고 있던 **원칙은 ADR-V-18 로 살아남는다** — "근거 없는 것은 판정하지 않는다".
번역 품질이 정확히 그런 항목이다.

### ADR-V-13 — 🔴 **폐기.** `bakeScene` 병합은 필요 없다.
> **무엇을 관측했나**: 영어 대본 파일 자체가 없어졌다(ADR-V-9 폐기).
> **옛 결정이 왜 실패하는가**: 병합은 `scene.en.json` 의 `spec` 을 한국어 정본에서 상속하기
> 위한 장치였다. 상속할 대상이 사라지면 병합도 사라진다.

⚠️ **W1 에서 이미 구현해 커밋했다**(`57e04e1` — `langPaths`·`bakeScene`·`langOf`·`--lang`).
지금은 **호출부가 0인 유휴 코드**다. 되돌리지 않고 두는 이유는 §7 스코프 가드에 적었다.

🔑 이 ADR 이 겪은 개정(통짜 복사 → 부분 오버라이드)의 **교훈은 남긴다**:
ADR-V-10 이 "서술은 한국어"라고 정한 순간 `spec` 은 언어 무관 자산이 아니게 되었는데,
같은 세션에서 쓰인 ADR-V-13 이 그 귀결을 안 따라갔다. **한 결정이 다른 결정의 전제를 바꿀 때,
바뀐 전제를 쓰는 곳을 전수로 다시 봐야 한다**(방법론 M10 파급 전수).

### ADR-V-16 — 영어는 한국어 대본 **안에** 산다. 별도 파일을 만들지 않는다.
`scene.json` 에 두 자리를 더한다.

```jsonc
"lines": [
  { "text": "주민 다섯 명이 지금\n한 사람처럼 움직이고 있어요.",
    "say":  "주민 다섯 명이 지금 한 사람처럼 움직이고 있어요.",
    "en":   "Five villagers are moving\nlike one person.",   // ← SRT 가 이걸 쓴다
    "pauseAfter": 150 }
],
"youtube": {
  "title": "...", "blurb": "...", "tags": [ ],
  "en": { "title": "...", "blurb": "..." }        // ← 번역 탭에 붙여넣을 것
}
```

**왜 파일을 안 나누나** — ①**검수 때문이다.** 번역이 원문 옆에 있어야 검수팀이 한 줄씩 대조해
지어낸 내용과 딱딱한 표현을 잡는다. 파일이 갈리면 대조할 자리가 사라진다.
②파일 개수가 안 늘어 무인 파이프라인(`backlog.mjs`·클라우드 루틴)이 **아무 영향을 안 받는다.**
③줄이 늘거나 합쳐질 때 번역이 **자동으로 따라 움직인다** — 인덱스로 짝을 맞추면 어긋난다
(`tts.mjs` 가 인덱스 캐시로 겪은 사고와 같은 종류).

🔴 `en` 은 `text` 를 번역한다(`say` 가 아니다). `say` 는 TTS 용이라 숫자를 소리나는 대로 풀어
쓴다("사천 구십육"). 자막은 `text` 가 정본이다.

### ADR-V-17 — 진행 막대와 영어 자막의 겹침은 **그대로 둔다.**
§0.4 실측: 진행 막대가 308~322px, 유튜브 자막 위 끝이 318px — 같은 줄이다.

고칠 수 있었지만(HUD 압축 / 막대를 제목 위로) **안 고친다**(사용자 판정 2026-08-05,
"막대 진행이 그렇게 거슬리는 정도는 아니다").

🔑 **기술적으로도 이쪽이 낫다.** 318 은 **기기 1대·관측 2건**에서 나온 값이다.
여기에 딱 맞게 재단하면 다른 기기에서 조용히 깨지는데, **`check.mjs` 는 그걸 못 잡는다** —
우리 프레임만 보지 유튜브 UI 는 모른다. 관측이 쌓이기 전에는 배치를 바꾸지 않는다.

바꾸려면: 기기 3종 이상에서 자막 위 끝을 재고, 그 분포를 §0.4 에 적은 뒤에 결정한다.

### ADR-V-18 — 번역 품질은 **게이트로 판정하지 않는다.**
"딱딱한 번역 금지"는 기계로 잴 방법이 없다. 억지로 게이트를 만들면
(문장 길이 비율? 관용구 사전 대조?) **근거 없는 임계값**이 되고, 그건 ADR-V-7 이 금지한 것이다.

→ **에이전트 지침 + 사람 검수**로 간다. 대신 **잴 수 있는 것은 잰다**:

| 항목 | 방법 |
|---|---|
| `lines[].en` 누락 | 🟢 게이트 (W4) |
| SRT 2줄 상한 | 🟢 게이트 (W4) — 근거 = §0.4 |
| 원문에 없는 수치·주장 | 🟡 검수팀 대조 (블로그 원문 기준) |
| **직역인가 아닌가** | 🔴 **사람** — 이 명세에서 유일하게 기계가 못 보는 자리 |

### ADR-V-19 — 등장인물 이름은 **로마자 표기가 아니라 뜻**으로 옮긴다.
사용자 결정 2026-08-05: *"아무 뜻도 전달이 안된다면 의미가 없으니깐."*

| 원문 | ❌ 로마자 | ✅ 뜻 |
|---|---|---|
| 순둥이 | Sundungi | the easygoing one |
| 고집쟁이 | Gojipjaengi | the stubborn one |
| 농사꾼 | Nongsakkun | the farmer |

**근거**: 한국어에서 이 이름들은 **곧 그 성격**이다. 로마자로 적으면 영어권 시청자에게
전달되는 뜻이 0이고, 자막이 그 줄에서 하려던 일(성격에 따라 판정이 갈린다는 것을 보이기)이
통째로 실패한다.

⚠️ **화면 라벨과 자막이 갈린다.** 그림에는 `순둥이`가 한국어로 남고(W0 — C# 에 한국어
문자열 리터럴로 실재한다) 자막에는 `the easygoing one` 이 뜬다. **의도한 것이다** —
자막이 뜻을 지고 그림이 이름을 진다. 반대(그림을 영어로, 자막을 로마자로)는 한국어 시청자와
영어권 시청자 **양쪽 모두**에게 손해다.

### ADR-V-14 — 🔴 **폐기.** 채널 분리는 논점 자체가 사라졌다.
> **무엇을 관측했나**: 영상이 하나로 확정됐다(2026-08-05).
> **옛 결정이 왜 실패하는가**: 채널 분리는 **한국어 영상과 영어 영상을 어디에 나눠 올릴까**의
> 문제였다. 올릴 영상이 하나면 나눌 것이 없다.

🔑 그 안에 있던 **관측 원칙은 살아남는다**: 지금 채널은 시청자 풀이 99% 한국이라
**영어 자막의 효과를 조회수로 판정할 수 없다.** 볼 것은 **시청자 국가 분포**다(§6).

### ADR-V-15 — 옛 회차는 재렌더하지 않는다. (2026-08-10 — **경계가 하나 더 생겼다**)
ep00s~ep05s-3 은 한국어 라벨로 이미 나갔다. ADR-V-10 이 시리즈 중간에서 표기를 가르지만,
이 프로젝트엔 이미 선례와 자리가 있다 — `voice.json` 의 `회차_경계` 가 목소리 M3→ME 전환을
그렇게 적어뒀다. **라벨 경계도 같은 자리에 같은 방식으로 남긴다.**

🔄 **개정 후 경계는 둘이다** (2026-08-10):

| 구간 | 라벨 | 상태 |
|---|---|---|
| `ep00s` ~ `ep05s-3` | **한국어** | 업로드 완료 |
| `ep06s` ~ `ep12s-3` | **영어** (옛 ADR-V-10) | **전부 업로드 완료** — 재렌더하지 않는다 |
| `ep13s` ~ | **한국어** (개정 ADR-V-10) | 앞으로 |

🔑 **같은 규칙이 두 번째로 일한다** — 옛 회차를 안 건드리는 이유가 이번엔 하나 더 있다.
유튜브는 **영상 파일 교체가 안 되므로** 재렌더는 곧 삭제 후 재업로드이고, 조회수·댓글·게시
이력이 사라진다. 15편을 되돌려 얻는 것보다 잃는 것이 크다.
🔑 **가운데 구간이 시리즈에 남는다.** 15편이 영어 라벨인 채로 영구히 남고 앞뒤가 한국어다 —
알고 받아들인 비용이다. 옛 결정을 무를 수 없다는 것이 **결정 전에 재 봐야 할 이유**이지,
지금 와서 재렌더할 이유는 아니다.

### W3 — SRT 조립기

**대상 파일** `tools/scene-video/srt.mjs` (신규)

**코드 스케치**

```js
/* 회차 대본 → 유튜브 업로드용 .srt
   사용: node tools/scene-video/srt.mjs ep06s

   🔴 여기서 번역하지 않는다. `lines[].en` 을 그대로 조립할 뿐이다(ADR-V-16).
   🔴 타이밍을 **여기서 계산하지 않는다.** 엔진의 `window.__timeline()` 을 그대로 읽는다 —
      render.mjs 도 같은 것을 읽으므로 영상과 자막이 정의상 어긋날 수 없다. */
const { cdp, close } = await openEngine(EP, { quiet: true });
let timeline;
try { timeline = await cdp.evaluate('window.__timeline()'); } finally { close(); }

const cues = flat.map((l, i) => {
  const t = timeline.lines[i];
  return `${i + 1}\n${ts(t.t)} --> ${ts(t.t + t.dur)}\n${l.en}\n`;
});
fs.writeFileSync(epBuild(EP, `${EP}.en.srt`), cues.join('\n'), 'utf8');   // 🔴 UTF-8
```

## 8. 재미 검증 — 시청자가 화면에서 무엇을 새로 보게 되는가

> 🔄 **2026-08-10 개정.** 아래 「한국어 시청자」 문단은 **폐기된 예측**이다. 지우지 않고 남긴다 —
> **이 문단이 곧 무엇이 틀렸는지의 증거**이기 때문이다. *"바뀌는 것은 개발일지를 보고 있다는
> 감각의 밀도"* 라고 썼는데, **그 밀도를 누구에게도 물어보지 않았다.** 재미 검증 절이 하는 일이
> 바로 "시청자가 무엇을 새로 보는가"를 적는 것인데, 여기 적힌 것은 **관측이 아니라 내 기대**였다.
>
> **ep13s 부터 한국어 시청자가 보는 것**: 그림 안에서 `배고픔 / 쉼 / 일`, `수락 / 거부` 를
> 본다 — ep05s-3 까지와 같은 자리로 **돌아온다**. 자막이 말하는 낱말과 그림에 적힌 낱말이
> 같은 언어가 되어, 화면을 한 번 더 읽어 옮기는 단계가 사라진다.
> **영어권 시청자**(0.7%)는 CC 로 계속 따라올 수 있다 — 자막은 그대로다.

**한국어 시청자**는 그림 안에서 `HUNGER / REST / WORK`, `ACCEPT / REFUSE` 를 본다.
지금까지 `배고픔 / 쉼 / 일`, `수락 / 거부` 이던 자리다. 영상의 말과 설명은 그대로 한국어고,
바뀌는 것은 **개발일지를 보고 있다는 감각의 밀도**다 — 화면의 라벨이 실제 코드의 식별자와
같은 모양이 되어, 자막이 설명하는 것과 그림이 보여주는 것이 코드와 같은 언어로 이어진다.
등장인물 이름(`순둥이`·`고집쟁이`)은 한국어로 남는다. 코드에도 한국어로 적혀 있기 때문이다.

**영어권 시청자**는 CC 를 켜면 처음으로 이 채널을 **따라갈 수 있게** 된다. 소리는 한국어지만,
화면 위쪽에 영어 자막이 뜨고 그 아래 그림에는 `HUNGER / REST / WORK` 가 적혀 있다.
자막이 말하는 것과 그림이 보여주는 것이 **같은 언어로 만난다** — 다섯 고리가 한 세로선에
걸리는 것을 보면서 "동시에 움직인다"를 읽는다. 번인 한국어 자막은 그 아래 그대로 있지만
겹치지 않는다. 두 언어가 한 화면에서 각자 자리를 갖는다.
