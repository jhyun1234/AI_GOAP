## 0. 이 작업이 완료됐을 때 화면에서 새로 보게 되는 것 (재미 검증 절)

주민 3명이 자원을 채집하러 각기 다른 노드로 향한다. 도중에 서로 경로가 교차해도 **원운동에 갇히지 않는다**. 앞선 주민이 어떤 타일에 들어서면 뒤 주민은 잠깐 멈춰 서서 기다렸다가 그 주민이 다음 타일로 넘어가면 곧바로 자기 걸음을 이어간다 — RTS의 유닛 대기 리듬. 적이 마을 경계에 나타나면 방어 나선 주민이 적을 향해 **곧장** 걸어들어가 사거리에 들어서고, Console에 `[VillagerFSM] Fighting: Enemy=...` 로그가 뜬다. 이전엔 적 주위를 무한히 맴돌기만 하던 유닛이 이제 붙어 싸운다.

같은 게임 세션에서 원운동을 한 번도 못 봤고, 전투 로그가 정상적으로 올라온다면 이 리팩터는 성공이다. 이 두 가지가 눈에 띄지 않으면 스티어링 층을 더 갈아엎을 필요가 있다는 신호.

**답할 수 없으면 이 명세는 착수하지 않는다.** 리팩터가 원운동만 없애고 전투 사거리 진입 문제를 여전히 남긴다면 재미 근거는 0이므로 스코프를 재논의한다.

## 2. ADR (구현 중 갈릴 판단 미리 결정)

이 결정을 바꾸려면 **사유를 커밋 메시지에 명시**한다.

- **ADR-T1**: `Rigidbody` 및 `SphereCollider`는 VillagerFSM/EnemyFSM에서 **완전 제거**한다 (필드·Awake 부착·필드 사용 코드 소진). 유닛은 순수 `GameObject + Transform`. 이동 위치는 `transform.position` 직접 조작.
- **ADR-T2**: 이동 예약은 신규 정적 클래스 `TileReservationRegistry`(전역 static, `Assets/Scripts/AI/TileReservationRegistry.cs`)의 `Dictionary<Vector2Int, string>` 한 벌로 관리. key=타일 좌표, value=소유자 ID(`AgentId`/`EnemyId`). `GameManager` 초기화 시 `TileReservationRegistry.ResetAll()` 호출로 초기화.
- **ADR-T3**: 예약 정책 = **"현재 타일 + 다음 웨이포인트 타일"** 두 셀 소유. 이동 중 다음 타일 예약 성공 순간 걷기 시작, 도착 순간 이전 타일 릴리즈. 이 정책이 무조건 두 셀만이므로 head-on 상쇄가 원천 차단(같은 타일 동시 예약 불가).
- **ADR-T4**: 시각 이동은 `Vector3.MoveTowards(transform.position, nextTileWorld, speed * dt)`. 속도는 **기존 `VILLAGER_MOVE_SPEED = 2.0f`, `VILLAGER_FLEE_SPEED = 3.0f`, `ENEMY_MOVE_SPEED` 그대로 유지**. 임의 튜닝 금지 (스코프 가드).
- **ADR-T5**: 다음 타일 예약 실패 시 **대기 상태**로 전환 (`_waitFrames++`). `WAIT_MAX_FRAMES` 초과 시 `AbortReason.PathBlocked`(신규 값)로 `RequestReplanning` 호출. 대기 프레임 최대치는 **제안치 30**(약 0.5초 @60fps), 방치 관성 실험 1회 후 조정 허용. 이 원칙은 ADR-9(이동 실패 first-class)의 연장선이며 좌표 스냅 금지 원칙 유지.
- **ADR-T6**: **자기 타일 예약 lifecycle**: 스폰 시(`Awake` 이후 `InjectDependencies` 시점) 최초 1회 예약, 이동 도착 시 이전 타일 릴리즈 + 새 타일 예약 순서. `OnDestroy`/사망 진입 시 `TileReservationRegistry.ReleaseAllBy(ownerId)`로 leak 원천 차단.
- **ADR-T7**: `ResourceNode.OccupiedTiles`와 `TileReservationRegistry`는 **분리 병존**. 목적이 다르다:
  - `OccupiedTiles` = 자원 채집 중인 노드 세트 → 다른 주민의 JPS 경로가 관통 방지용
  - `TileReservationRegistry` = 매 프레임 이동 lock → 유닛 겹침 원천 차단
  두 세트를 합치지 않는다. 이름·수명·소유자 시맨틱이 다르므로 통합 시 회귀 위험. 심야 세션의 `StartPathTo` OccupiedTiles 마스킹 블록은 그대로 유지.
- **ADR-T8**: 전투 사거리·데미지·발사체 히트는 **이번 스코프 밖**. `FindNearestEnemy`가 이미 `Brain.TileX/Y` 기반 맨해튼 거리이므로 이 리팩터로 자동 회복. 향후 발사체 도입 시엔 `Physics.Raycast` 대신 타일 좌표 사거리 + `LineOfSight` 헬퍼 검토.
- **ADR-T9**: Boids `ComputeSeparation`, `TANGENT_BIAS_FRACTION`, `SEPARATION_RADIUS`, `SEPARATION_STRENGTH`, `_tangentSign`, `_overlapBuffer` 및 관련 주석은 **전면 삭제**. 파일 grep으로 잔재 0건 강제 (`grep -n "Separation\|Tangent" Assets/Scripts/AI/VillagerFSM.cs Assets/Scripts/AI/EnemyFSM.cs`).
- **ADR-T10**: 예약 상태를 `VillagerBrain`에 슬롯으로 넣지 **않는다**. GOAP 슬롯 폭발 방지(플래너 코어 동결, ADR-9/ADR-11 정신 준수). 진리 소스는 `TileReservationRegistry` 한 곳.

## 4. 시스템 통합 구조 (개괄)

```
[Awake / InjectDependencies]
   Rigidbody/SphereCollider 부착 ❌ 삭제
   → TileReservationRegistry.TryReserve(자기타일, ownerId)  ✅ 신규

[Update — 이동 처리]
   if (_isMoving)
       Vector2Int nextTile = _currentPath[_pathIndex]
       if (!TileReservationRegistry.IsOwned(nextTile, ownerId)) {
           // 다음 타일 예약 시도
           if (!TileReservationRegistry.TryReserve(nextTile, ownerId)) {
               _waitFrames++
               if (_waitFrames > WAIT_MAX_FRAMES)
                   RequestReplanning(AbortReason.PathBlocked)  ✅ 신규 값
               return  // 이번 프레임 이동 스킵
           }
           _waitFrames = 0
       }
       transform.position = Vector3.MoveTowards(transform.position, nextTileWorld, speed * dt)
       if (도착) {
           TileReservationRegistry.Release(이전타일, ownerId)  // 이전 타일 소유권 놓기
           Brain.TileX/Y 갱신 + FoW/SensorSystem 갱신
           _pathIndex++
       }
   else
       // 정지 상태: 자기 타일 소유 유지, 아무것도 안 함

[OnDestroy / 사망 진입]
   → TileReservationRegistry.ReleaseAllBy(ownerId)   ✅ leak 방지
```

**핵심 원칙**: 진리 소스는 Registry 한 곳. `Brain`/`transform.position`은 표시용. 이동 실패는 여전히 GOAP에 first-class로 보고(ADR-9 연장선).

### TR-1 · TileReservationRegistry 신설  〔중요도: 상, 작업량: 소, 의존: 없음〕

**코드 스케치**:
```csharp
// Assets/Scripts/AI/TileReservationRegistry.cs
using System.Collections.Generic;
using UnityEngine;

namespace AIVillage
{
    /// <summary>
    /// 이동 예약 전역 registry. 유닛이 자기 현재 타일 + 다음 웨이포인트 타일을 예약해
    /// 같은 타일에 두 유닛이 동시에 들어서지 못하게 한다.
    /// 자원 채집 점유(ResourceNode.OccupiedTiles)와는 별도 시스템 — 목적·수명 다름 (ADR-T7).
    /// </summary>
    public static class TileReservationRegistry
    {
        private static readonly Dictionary<Vector2Int, string> _reservations
            = new Dictionary<Vector2Int, string>(256);

        public static int Count => _reservations.Count;

        /// <summary>tile이 비어 있거나 ownerId가 이미 소유 중이면 true를 반환하며 예약을 확정한다.</summary>
        public static bool TryReserve(Vector2Int tile, string ownerId)
        {
            if (_reservations.TryGetValue(tile, out string existing))
                return existing == ownerId;
            _reservations[tile] = ownerId;
            return true;
        }

        /// <summary>ownerId가 소유 중일 때만 해제한다. 다른 소유자의 예약은 건드리지 않는다.</summary>
        public static void Release(Vector2Int tile, string ownerId)
        {
            if (_reservations.TryGetValue(tile, out string existing) && existing == ownerId)
                _reservations.Remove(tile);
        }

        /// <summary>tile이 ownerId 소유인지 여부. 예약이 없으면 false.</summary>
        public static bool IsOwnedBy(Vector2Int tile, string ownerId)
        {
            return _reservations.TryGetValue(tile, out string existing) && existing == ownerId;
        }

        /// <summary>OnDestroy·사망 시 호출해 ownerId의 모든 예약을 회수한다 (leak 방지, ADR-T6).</summary>
        public static void ReleaseAllBy(string ownerId)
        {
            var toRemove = new List<Vector2Int>();
            foreach (var kv in _reservations)
                if (kv.Value == ownerId) toRemove.Add(kv.Key);
            for (int i = 0; i < toRemove.Count; i++) _reservations.Remove(toRemove[i]);
        }

        /// <summary>GameManager 초기화·씬 리로드·EditMode 게이트에서 사용.</summary>
        public static void ResetAll() => _reservations.Clear();
    }
}
```

**⚠️ 오해 위험**:
- `TryReserve`를 "예약 없으면 무조건 true, 있으면 무조건 false"로 구현하지 말 것. **같은 owner의 재요청은 true**(idempotent)여야 이동 파이프라인이 자기 타일을 반복 확인해도 문제없다.
- `ReleaseAllBy`를 foreach 안에서 직접 삭제하지 말 것 (`InvalidOperationException`). 별도 리스트에 모아 사후 삭제.
- Registry는 **정적(static)**. `GameManager` MonoBehaviour 필드 아님. `ResetAll()`은 씬 재시작 시 반드시 호출. 잊으면 이전 세션 좀비 예약이 남는다.
- `Dictionary<Vector2Int, string>` 대신 `HashSet<Vector2Int>`로 만들지 말 것 — 소유자 없이는 `ReleaseAllBy`와 idempotent 검사가 불가능.

**작업량/심각도/의존**: 소 / 🟠 / 없음.

```csharp
// ── 경로 이동 처리 (Transform + 타일 예약 기반) ─────────────────────────
if (_isMoving)
{
    float speed = (Brain.FSMState == VillagerState.Fleeing)
                  ? VILLAGER_FLEE_SPEED
                  : VILLAGER_MOVE_SPEED;

    // 다음 타일 예약 확보 — 없으면 대기, 대기 초과 시 재경로.
    Vector2Int nextTile = _currentPath[_pathIndex];
    if (!TileReservationRegistry.IsOwnedBy(nextTile, AgentId))
    {
        if (!TileReservationRegistry.TryReserve(nextTile, AgentId))
        {
            _waitFrames++;
            if (_waitFrames > WAIT_MAX_FRAMES)
            {
                _waitFrames = 0;
                RequestReplanning(AbortReason.PathBlocked, $"tile ({nextTile.x},{nextTile.y}) blocked");
            }
            return; // 이번 프레임 이동 스킵
        }
        _waitFrames = 0;
    }

    // 부드러운 보간
    Vector3 nextWorld = new Vector3(nextTile.x, nextTile.y, 0f);
    transform.position = Vector3.MoveTowards(transform.position, nextWorld, speed * Time.deltaTime);

    // 도착 판정
    if (Vector3.Distance(transform.position, nextWorld) < WAYPOINT_ARRIVE_DIST)
    {
        // 이전 타일 소유권 반환
        Vector2Int prevTile = new Vector2Int(Brain.TileX, Brain.TileY);
        if (prevTile != nextTile) TileReservationRegistry.Release(prevTile, AgentId);

        Brain.TileX = nextTile.x;
        Brain.TileY = nextTile.y;

        // FoW + 발견 갱신 (기존 로직 유지)
        if (MapConfig.Active != null)
        {
            int sight = MapConfig.Active.villagerSightRadius;
            FowManager.Instance?.RevealArea(Brain.TileX, Brain.TileY, sight);
            SensorSystem.Instance?.DiscoverArea(Brain.TileX, Brain.TileY, sight);
        }

        _pathIndex++;
        if (_pathIndex >= _currentPath.Count) _isMoving = false;
    }
}
```

### TR-5 · EditMode 게이트 M19~M22 신설  〔중요도: 상, 작업량: 중, 의존: TR-1~TR-3〕

**대상 파일** (전부 신규):
- `Assets/Tests/EditMode/M19_TileReservationRegistry.cs`
- `Assets/Tests/EditMode/M20_HeadOnReservation.cs`
- `Assets/Tests/EditMode/M21_ThreeBodyReservation.cs`
- `Assets/Tests/EditMode/M22_ReservationLifecycle.cs`

**테스트 케이스**:

**M19 — Registry API 계약**:
- `TryReserve` 빈 타일에 → true, `Count == 1`.
- `TryReserve` 같은 owner 재호출 → true, `Count == 1` (idempotent).
- `TryReserve` 다른 owner → false, `Count == 1`.
- `Release` 소유자 일치 → 제거, `Count == 0`.
- `Release` 소유자 불일치 → no-op.
- `ReleaseAllBy` → 해당 owner의 모든 예약 소진, 다른 owner 예약 유지.
- `ResetAll` → `Count == 0`.

**M20 — Head-on**:
- 유닛 A(tile 0), 유닛 B(tile 2)가 서로의 위치를 향해 이동. 각 스텝별로 예약 상태 시뮬레이션.
- 검증: A와 B가 tile 1을 동시에 소유하는 상태가 **한 스텝도 발생하지 않는다** (`Assert.IsFalse(A owns 1 && B owns 1)`).
- 검증: 한쪽이 대기 → 반대쪽 통과 → 대기측이 재경로 시도 순서로 진행.

**M21 — 3-body 삼각형 (정밀 순환 감지)**:
- 유닛 A, B, C가 세 꼭짓점에서 서로를 향해 이동. 200 스텝 시뮬레이션.
- **소유권 핸드오버 그래프 구축**: 각 스텝에서 발생한 `Release(tile, owner_from)` 직후 같은 tile을 `TryReserve` 성공한 `owner_to`가 있으면 그래프에 edge `owner_from → owner_to` 추가.
- **길이 3 사이클 검출**: 그래프에서 A→B→C→A 형태의 방향 사이클을 명시 탐색 (DFS 또는 인접 리스트 순회). 검출 시 fail.
- 부가 검증: 200 스텝 후 셋 다 목적지 좌표 도달 (Registry에서 각자 목적지 타일 소유).

**M22 — Lifecycle leak**:
- N개 유닛을 예약시킨 후 절반을 `ReleaseAllBy`로 해제 → `Count == N/2 * 2` (각 유닛이 2 타일 소유 시).
- `ResetAll` 후 다시 예약 → 이전 owner ID가 유효했다면 새 예약과 충돌 없음.

**DoD 체크리스트**:
- [ ] 신규 테스트 파일 4개 존재.
- [ ] `TestRunner EditMode` 실행 시 M19·M20·M21·M22 전부 pass.
- [ ] 기존 M17·M18 + T13~T19 유지 pass (grep으로 회귀 검사).
- [ ] 각 테스트 setup에서 `TileReservationRegistry.ResetAll()` 호출 (테스트 간 상태 leak 차단).

**⚠️ 오해 위험**:
- M21에서 "3-body 원운동 없음"을 어떻게 assertion으로 표현할지 — 순환 감지는 복잡. 대신 **모든 유닛의 최종 위치가 목적지**이고 **Registry Count가 이론값(각 유닛 이동 중 2타일)**임을 확인하는 방식으로 우회. 실제 원운동 재현 없음은 육안 5분 방치(S2)로 이중 검증.
- Unity 좌표계 관련 세부 (Vector2Int vs Vector3) 오류 유의. tile 좌표는 Vector2Int.

**작업량/심각도/의존**: 중 / 🟠 / TR-1~TR-3.

- ⑦ `grep -n "Brain\.TileX\s*=\s*targetX"` 0건 유지 (ADR-9 연장선, 이 리팩터도 스냅 금지 유지).
- ⑨ 성격 배율 관련 grep — 이번 리팩터가 F-A 시스템을 건드리지 않음, 무회귀.

## 9. 착수 전 결정 사항 (2026-07-12 사용자 확정)

- ✅ **TR-3 EnemyFSM 대기 초과 정책**: `AbortCurrentPath()` 후 Idle 전환 → 다음 Tick에 재추격 대상 재선정. 별도 재경로 API 신설 안 함.
- ✅ **TR-4 씬 SphereCollider 목적**: 유닛에 다른 용도 없음. TR-4에서 문제없이 지움.
- ✅ **WAIT_MAX_FRAMES = 30 승인**. 방치 관성 실험 1회 이후 조정 허용 (ADR-T5).
- ✅ **M21 assertion 방식**: **정밀 — 순환 시퀀스 계층 감지**. 각 유닛의 예약 획득 타임라인을 기록해 소유권 핸드오버 그래프에서 3-유닛 사이클을 명시 검출. 간이(도달+Count) 방식보다 회귀 감시가 강함.
  - 알고리즘: 각 TryReserve 성공을 `(step, ownerId, tile)`로 기록 → 인접 스텝에서 `owner A가 방금 놓은 tile을 owner B가 즉시 예약` = edge A→B → N 스텝 시뮬 후 이 방향 그래프에서 길이 3 사이클(A→B→C→A) 검출 시 fail.
  - DoD 갱신: M21은 시뮬 200 스텝 후 (1) 모든 유닛 도달 (2) 소유권 핸드오버 그래프에서 길이 3 사이클 미검출 두 조건 모두 만족.

## 10. 재미 근거 재확인 (착수 직전)

이 리팩터의 재미 기여는 **간접적**이다: 자체적으로 새 재미를 만들지 않고, 이전에 있어야 했던 재미(전투 진입, 자원 채집 완주, 방어 응전)가 원운동/겹침 정지로 무산되던 것을 회복시킨다.

만약 착수 직전 사용자가 **"실제로 게임에서 원운동이 재미를 얼마나 죽이고 있나?"** 라는 판단을 다시 하고 싶다면, TR-1~TR-3 착수 전 다음 3분 관찰로 판단:
- (a) 3명 이상 유닛이 이동 중 교차 → 원운동 발생률
- (b) 침략 시 적 주위 원운동으로 전투 로그 부재
- (c) 이 두 가지가 방치 세션에서 이야기 회상 테스트를 방해하는가

관찰 결과 (a)+(b)가 30초 방치에 1회 이상 발생하면 리팩터 착수 가치가 확정된다. 발생률이 낮다면 F-C 보상 선포로 우선순위 이관 후 이 명세는 백로그.
