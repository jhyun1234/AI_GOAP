# 후속 작업 — 퀘스트 보드 + 보고 심부름 코드 정리

- **작성일**: 2026-07-18
- **상태**: 백로그 (지금 안 함 — 조각 Y로 버그는 이미 해결됨)
- **관련**: `RequestService`, `VisitActionSO`(휴면), `VisitRunner`(휴면), `WorldConfigSO.ReportErrandGoal/ReportTimeoutSec`(휴면)

## 배경

M8 "새 집 다 지었다고 목수가 의뢰인에게 알리러 가기"(보고 심부름)가 **동속 추격 미수렴** 문제를 냈다 — 보고자와 의뢰인이 같은 속도라, 이동 중인 의뢰인을 쫓으면 간격이 안 좁혀지고 60초 타임아웃으로 **목수 보상이 소실**됐다.

2026-07-18 **조각 Y**로 전환해 해결: 목수는 쫓아가지 않는다. 일 완수 시 "보상 빚"만 기록하고, 목수와 의뢰인이 **자연스럽게 마주치는 순간**(`RequestService.TickRewardSettlement`, 정산 반경 `WorldConfigSO.RewardSettleRadiusTiles`) 그 자리에서 정산 장면 + 보상 지급. 못 만나면 빚은 남는다(소실 없음, 정리는 이탈뿐).

## 후속 1 — 휴면 코드/에셋 정리 (소, 에디터 필요)

조각 Y로 아래가 **더 이상 실행되지 않는 죽은 경로**가 됐다. 컴파일·동작엔 무해하나 정리 대상:

- 코드: `VisitActionSO`, `VisitRunner`, `VillagerAgent`의 `GiveReportErrand`/`CompleteVisit`/`ClearRequestErrand`/`FindVisitTarget`/`VisitTargetAgentId`.
- 에셋: `ReportErrand` goal 에셋, `VisitAction` 에셋, `WorldConfig.asset`의 `ReportErrandGoal`/`ReportTimeoutSec` 값.
- 주의: 에셋 삭제는 씬/SO 참조 끊김을 유발할 수 있어 **Unity 에디터에서** 참조 제거 후 삭제할 것. `VisitAction`은 "주민에게 걸어가는" 재사용 primitive라, 아래 퀘스트 보드나 다른 사회 기능에서 되살릴 수 있으면 보존 판단.

## 후속 2 — 퀘스트 보드 (대, 별도 마일스톤)

사용자 원안(2026-07-18)의 물리 게시판 버전. 조각 Y는 이 중 "빚+정산"만 취한 것이고, 게시판 자체는 **선택적 큰 기능**으로 미룸.

원안 메커니즘:
1. 마을 게시판에 주민이 부탁을 게시
2. 다른 주민이 부탁을 수행하고 완료를 게시판에 기록
3. 의뢰인이 게시판을 확인해 완료를 인지
4. "목수에게 보상해야 함" 기억 → 서로 가까워지면
5. 보상 지급 (← 이 4~5단계가 조각 Y로 이미 구현됨)

게시판이 추가로 주는 것 = **비동기 발견 모델**(근접 스캔 → 게시-청구)과 물리적 공간감(퀘스트 보드로 걸어가 읽기). 개발 비용이 큰 이유:
- 새 월드 객체(게시판 건물·타일·비주얼·프리팹).
- `RequestService`의 근접 매칭(M8 게이트 있음)을 게시-청구 모델로 리팩터 → 회귀 위험.
- 게시판까지 걸어가 읽는/쓰는 새 goal·행동.

착수 시 `spec-write`로 별도 명세. 발견 모델 교체가 핵심 설계 결정이므로 M8 매칭 테스트를 먼저 확보.
