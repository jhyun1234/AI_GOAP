## 세션 마무리 — 훅이 못 채우는 칸 (2026-08-12)

**막혔던 문제 / 해결 방법**

1. **진단이 둘로 갈렸다.** 스튜디오는 `ep14s-1·2·3` 부진의 원인을 인트로로 지목했는데,
   인트로는 `ep13s`~`ep16s` 전 회차의 **상수**라 특정 회차의 하락을 설명할 수 없었다.
   → 두 문제로 갈라 각각 처방: **(A) 레벨 문제**(사건이 6.8~7.0초에 시작 — 전 회차 공통,
   구조 개정으로 해결) **(B) ep14s 특유**(훅의 사건이 약함 — 「안 굶더라고요」·「목수뿐이었어요」
   = 부재의 서술. M11 개인화 경제가 소재로 약한 것이라 구조로는 못 고침, 기획 항목으로 이월).
2. **보일러플레이트 길이를 글자 비례로 쟀다.** 우리가 스스로 금지한 방법이다(`dur` 에
   후행 무음 0.44~0.57초가 들어 있어 과대평가). → 한계를 명시하고 두 값(비례 2.3 / 무음
   제외 2.0)을 함께 적었다. 결론은 어느 쪽이든 같아 방향 판단에는 영향 없음.
3. **`check.mjs` 주석을 깨뜨려 전 게이트가 죽었다.** 기존 `/* … */` 안에 새 문장을 넣으면서
   여는 `/*` 없이 붙여 `SyntaxError`. → 오류 줄을 직접 열어 수정. 7편 재검으로 회복 확인.
4. **16편 `upload.txt` 재생성에 `--prepare` 를 돌렸다** — 텍스트만 바뀌는데 mp4 를 16번
   다시 렌더하는 낭비(16분 예상). → 중단하고 노드 한 줄로 앵커 뒤 삽입, 2초에 47건 완료.

**뒤집힌 것 (믿었던 것 → 실제)**

1. **「인트로 무죄」 → 무죄지만 훅을 창 밖으로 민다.** 낮에 `12-1편` 지속 곡선으로
   *"인트로 구간은 평평하니 이탈 원인이 아니다"* 라고 판정했고 그 판정 자체는 지금도 맞다.
   그런데 **던지지 않은 질문**이 있었다 — 이탈을 만들지 않아도 **사건을 8초 창 밖으로
   밀어낸다**. 실측 결과 사건 시작이 **6.8~7.0초**(창의 85%). 관측은 옳았는데 물음이 좁았다.
2. **「전환 목적지를 만들었다」 → 목적지만 만들고 들어올 이유는 안 만들었다.**
   디스코드를 개설하고 배선까지 끝냈는데, 사용자 한마디에 무너졌다. 사람이 디스코드에
   드는 이유 셋(여기서만 얻는 것 / 이미 있는 사람 / 내가 주는 영향) 중 우리는 **0/3**이었다.
3. **「$100 은 채널 수익으로 번다」 → 광고로는 수년이다.** YPP 요건 실측: 쇼츠 조건이
   **76배** 부족(90일 13만 vs 1,000만), 시청 시간은 3배 부족. 방향(관객 먼저)은 맞았는데
   **기계가 틀렸다** — 광고비가 아니라 관객이 $100 의 가치를 만든다.
4. **「제안치는 작은 결정이다」 → 같은 날 두 번 같은 함정.** 인트로 상한 3.0 과 대역 하한
   33 을 실측 없이 두어 전환 3편 **전부에 warn** 을 켰다. 이미 두 번 배운
   *"제안치 전에 그 자리 값부터"* · *"상시 켜지는 경고는 경고가 아니다"* 를 다시 밟았다.
   → 당일 재개정(3.6 / 31). 하한은 지어내지 않고 **기존 산식에 새 고정비를 대입**해 도출.
