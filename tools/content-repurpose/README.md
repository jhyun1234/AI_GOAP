## ⚠️ 미해결 전략 충돌 (가장 중요 — 구현 전 반드시 판정)

`Docs/블로그_자동화_수익화_기획서.md` 5장 끝 + `memory/project_blog_automation.md`
(2026-07-09)에서 사용자가 **"SNS 카드뉴스 자동 홍보(마케팅팀)"를 이미 검토하고 기각**했다.
기각 근거:
- 이 블로그는 Unity/GOAP 니치 기술 콘텐츠 → 유입이 거의 **구글 검색(SEO) 중심**,
  SNS 바이럴 효과 낮음.
- 무인 마케팅 에이전트 추가 운영 = 비용 대비 효과 낮음.
- 단, **"추후 개인 브랜딩으로 목적이 바뀌면 재검토"** 라고 여지를 남김.

**이 트랙이 그 기각을 뒤집으려면, 기각 근거를 통과하는 축소 설계여야 한다:**

| 항목 | 2026-07-09 기각한 버전 | 이 트랙(축소 버전) |
|---|---|---|
| 대상 | 모든 글 | **C층 메타-서사 글만** (기획서 5장 C층 = "AI(Claude)가 스스로 게임을 만드는 개발일지"). 이 서사는 X·Reddit에서 실제로 바이럴됨 → 기각 근거("니치라 SNS 효과 낮음")의 예외 |
| 게시 | 무인 자동 포스팅 | **초안만 생성 → 사용자가 검토 후 직접 게시.** 무인 마케팅 에이전트 비용/리스크 = 0. Reddit 자동 포스팅 밴 위험도 제거 |
| 소재 | 새로 생성 | **이미 발행된 `tools/blog-automation/published/` 글 재활용.** 신규 생성 비용 최소 |
| 목적 | 바이럴 홍보 | **C층 글의 유입 증폭 → 블로그 페이지뷰 → 애드센스** (기존 수익 모델과 동일 방향) |

→ 즉 "그때 기각한 마케팅팀"이 아니라 **"C층 차별화 글의 유입 증폭기 (초안 전용)"**.
이 재정의가 사용자에게 유효한지 `/grill-me`로 먼저 확정할 것.

## 확정된 사용자 선택 (2026-07-24 대화)

- 출력 채널: **X 스레드 / YouTube Shorts 대본 / Reddit r/gamedev** (3개)
- 언어: **한글 + 영문 자동 병행** (영문이 애드센스 RPM에 유리)
- 퍼널 끝점: **블로그 트래픽 → 애드센스** (Steam/위시리스트 아님)

## 채널별 현실 제약 (2026-07-24 그릴링에서 도출)

- **X 스레드**: 블로그 유입에 가장 효율적. 각 스레드 끝에 "전체 글 →" 블로그 링크.
- **Reddit r/gamedev**: 자기홍보 규정 엄격 → **자동 포스팅 금지, 초안만.** 사람이 규정
  확인 후 직접 게시.
- **YouTube Shorts**: 외부 링크 유입 약함(설명란 클릭률 낮음) → 역할은 "인지도/구독",
  블로그 유입 주력은 X·Reddit. 대본만 생성하고 실제 영상은 사용자 몫.

## 구현 계획 (다음 세션에서 만들 것 — grill-me 통과 후)

기존 blog-automation의 부서형 서브에이전트 패턴을 그대로 따른다.

```
.claude/agents/
  repurpose-planner.md    # published/ 중 C층 글 선별 (메타-서사만), 채널 배분 결정
  repurpose-x.md          # X 스레드 초안 (한/영), 끝에 블로그 링크
  repurpose-shorts.md     # Shorts 대본 초안 (한/영)
  repurpose-reddit.md     # r/gamedev 초안 (영), 규정 체크리스트 동봉

tools/content-repurpose/
  README.md               # 이 문서
  .staging/               # 사이클별 작업 파일 (gitignore 권장)
  drafts/                 # 생성된 초안 (사람이 검토·게시). 채널/날짜별
  state/
    repurpose_log.md      # 어떤 글을 어떤 채널로 파생했는지 (중복 방지)
```

**트리거 방식 (2안 중 grill-me에서 선택)**:
- (A) blog-automation 발행 성공 후 하류로 연결 (routine-prompt Step 8 뒤에 훅).
- (B) 독립 on-demand — 사용자가 "이 글 파생해줘" 할 때만. **초안 전용이라 (B)가 안전·저비용.**

**게시는 사람이 한다** — 이 파이프라인은 `drafts/`에 파일만 남기고 끝. 무인 게시 없음.

## 절대 규칙 (기존 프로젝트 원칙 상속)

- `Assets/`, `ProjectSettings/` 등 게임 코드/에셋 **절대 건드리지 않는다.**
- `tools/blog-automation/`의 기존 파일(에이전트·스크립트·state) **수정하지 않는다.** 하류로만 붙는다.
- 자격증명·토큰을 초안·로그에 옮겨 적지 않는다.
- 저품질 양산 금지 — C층 글만, 초안 전용, 사람 검토 필수.
- 새 에이전트 description은 1~3문장 (`project_token_reduction.md` 정책).
