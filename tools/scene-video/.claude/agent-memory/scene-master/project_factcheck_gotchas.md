원본 html 대조를 `grep` 으로 할 때 두 번 헛짚을 뻔했다. 둘 다 재현되는 형태다.

**① 인용문 `grep` 0 이 곧 날조가 아니다 — 태그가 문장을 자른다.**
발행 html 은 문장 가운데에 `<b>` 를 넣는다. 예: `감으로 밸런스를 만지는 대신, <b>겨울 수지를
직접 계산</b>해봤습니다`. 작성팀 `source` 는 **렌더된 산문**을 인용하므로 원문 그대로인데
raw html 을 `grep` 하면 0 이 나온다.
→ 0 이 나오면 반려하기 전에 `grep -o "앞부분.\{0,120\}"` 로 **뒤를 열어 본다.**

**② 「원문에 없어서 안 그렸다」는 사유 문장이 `grep` 에 잡힌다.**
`548`(= 1,110 − 562, 원문에 0건)을 리포 전체에서 찾으면 여러 건 나오는데 전부 주석·노트의
**사유 문장**이다. 값이 실제로 화면에 오르는지는 다른 방법으로 봐야 한다 →
`kinds/*.js` 의 `fillText` 를 전수로 훑어 **그려지는 문자열이 전부 `spec.*` 에서 오는지**
(하드코딩 수치 문자열 0건인지) 본다. 그러면 spec 에 없는 값은 렌더 경로 자체가 없다.

**③ 낱말 대조와 «분류» 대조는 별개 절차다 — `grep` 이 통과시키는 날조가 있다.**
ep09s-1 1차본이 「농사꾼」·「떠돌이」를 화면 `M5 JOB` 행에 넣었다. **낱말 셋은 원문에 실재했고
`grep` 도 통과했는데 셋 다 성격(M4)이었다** — 원문은 셋을 나란히 쓰기만 하고 어느 쪽인지
말하지 않는데 화면이 그 빈칸을 채웠다. 오염이 페이오프 샷까지 갔다.
→ **화면이 표·행 라벨·칸으로 값을 담으면, 주장하는 것은 낱말이 아니라 «라벨과의 짝»이다.**
낱말 존재 확인 뒤에 **「원문이 이 값을 그 분류로 부른 적이 있나」를 따로 묻는다**(반대편 이름을
전수로 `grep` 해 0 인지 보는 것이 빠르다 — 직업 7종 0건이 결정적이었다).
🔑 **「축은 원문에 있고 값은 원문에 없다」면 축만 남기고 값을 가리는 것이 정답**이고, 가린 칸이
「없다」로 오독되는지는 **렌더 경로**로 본다(같은 행에 값과 빗금이 섞여 있는가 · 가린 칸에서
연결선이 실제로 나가는가).

**Why:** 셋 다 «원문에 없는 값이 화면에 오르는 것»을 잡으려다 생긴 오탐/누락이다. 오탐으로
반려하면 정확한 작성팀을 되돌리게 되고, ②를 «주석에 있으니 안전하다»고 읽으면 진짜 누출을
놓친다. ③은 **게이트도 `grep` 도 구조적으로 못 보는 형태**다.

**How to apply:** 수치 표본 대조 때 ①인용문이 0이면 문맥을 열고 ②「안 썼다」는 값은
사유 문장이 아니라 렌더 경로로 판정하고 ③화면에 표·라벨이 있으면 **분류 대조를 한 번 더**
돌린다. 그 회차가 다루는 밀스톤 명세의 ADR 이 같은 혼동을 이미 이름 붙여 뒀을 수 있다
(ADR-M7-5 가 그랬다). 관련 = [[verdict-evidence-grades]] · [[ep09s-split]]
