**판정에서 「그림이 화면에 실제로 떴는가」와 「소리가 그림에 맞았는가」는 이 두 공식으로 직접 검산한다.**
둘 다 작성팀·검수팀 보고를 안 믿고 `build/timed.json` + `engine/engine.js` 로 다시 푼 결과다.

### ① 마지막 샷의 판정이 카드에 안 먹히는가 — **마지막 자막 길이 하나가 정한다**

`shot.dur = ΣL + 0.35`(`engine.js:167`) · 카드는 `TOTAL − 2.6`(`engine.js:181,259`) ·
`cue` 의 완성 시각 `b = l.t + l.dur × span`(`engine.js:292`, **lead 는 안 들어간다**).
마지막 샷이 자막 2줄(L5·L6)이고 판정이 `cue(1, ·, span)` 이면:

```
여유 = 0.92 × L6 − 2.25        (span = 0.08 일 때. L5 가 소거된다)
연결선(cue 0, 0.85) 여유 = 0.15 × L5 + L6 − 2.25
```

→ **`L6 < 2.446초`면 아무리 조여도 판정이 카드 뒤로 밀린다.** ep08s-3 실측 `L6 = 2.792` →
여유 **0.319초**(카드 직전 프레임 스틸로 확인). 같은 구조인 ep08s-1 이 통과한 이유도
설계가 아니라 `L6 = 4.779` 였기 때문이다.
🔑 그래서 마지막 샷은 **앞줄을 아무리 줄여도 안전해지지 않는다** — 감량 대상에서 L6 만 뺀다.

### ② `sfx.delayMs` — **산정치로 두면 반드시 이르다**

`delayMs` 는 `render.mjs:113` 에서 **그 자막(`at` 인덱스)의 시작 시각 기준**으로 얹힌다.
`c* = (delay + lead) / (lead + l.dur × span)` 이므로 실측 `l.dur` 이 나오면 값이 달라진다.
검산법 = kind 의 draw 식에서 **소리가 가리키는 사건의 진행도**를 역산해 `delay` 를 다시 푼다.

- 실적: ep08s-1 두 값이 0.2~0.3초 이르게 나갔고, **ep08s-3 도 같은 크기로 일렀다**
  (latch 2,300 → 그 순간 10개 중 7개만 문턱을 넘음. 맞추면 2,460 / thud 2,590 → 2,810).
- 원인이 산수가 아니라 **앵커 승계**였다: 창 이동 계산(`c*` 보존)은 맞는데, 보존한 `c*` 자체가
  옛 회차부터 어긋나 있었다. 같은 `why` 안에 올바른 역산값이 적혀 있는데 안 쓴 경우도 있다.
- 🔑 **`why` 에 역산식이 적혀 있다는 것이 값이 맞다는 뜻이 아니다** — 식과 값을 따로 본다.
- 🔴 **`cue` 가 쓰는 척도는 `rel.dur` = 말하는 시간 + `pauseAfter`**(`engine.js:163`). wav 길이가
  아니다. ep09s-2 에서 이 척도가 **네 번 혼동됐다**(코디네이터 1 · 검수 1 · 작성팀 2).
- 🔴 **「실측 환산」이라고 적힌 값이 모형값일 수 있다.** ep09s-2 sweep 은 `l.dur 3.50초(실측 환산)`
  라고 적었는데 `timed.json`·wav 헤더·`window.__timeline()` 셋 다 **3.343** 이었다(모형 0.1795초/자로
  낸 값). `delayMs` 가 62ms 늦었다. → **주석의 숫자를 읽지 말고 `timed.json` 을 직접 연다.**

**Why:** 둘 다 「기계 게이트가 전부 통과하는데 화면·소리는 틀린」 자리다. `check.mjs` 24항목은
아웃트로 카드에 먹힌 판정도, 이른 효과음도 못 본다 — 관련 = [[gate-metric-gaps]].

**How to apply:** 마지막 샷이 있는 모든 회차에서 ①`L6` 로 여유를 계산하고 **카드 직전 프레임
스틸**로 확인 ②`sfx` 가 있으면 `timed.json` 으로 `delayMs` 를 다시 푼다. 어긋남이 0.2초 안이고
소리가 의도한 낱말 위에 앉으면 **승인을 막지 않는 지적**으로만 적는다([[verdict-evidence-grades]]).
