「수치 목록」과 「제목 후킹 권고」를 쓸 때, **이미 나간 편이 쓴 훅을 다시 1순위로 올리지 않는다.**

이미 소진된 것:
- **「코드는 0줄이에요」 계열** — `ep05s-3` 이 썼다. 그런데 이 프로젝트 원문은 「데이터 주도 설계 = 코드 0」을
  밀스톤마다 반복해서 자랑한다(M7-E, M8-F, …). 즉 **글에서 가장 눈에 띄는 수치가 매번 `0`**이라
  가만히 두면 채널이 같은 제목을 계속 낸다. 다른 얼굴을 붙여 권하라(예: ep10s-2 는 「5번째」와 묶었다).
- **「4타일 → 2타일」** — `ep09s-2`.

**Why:** 제목에 아라비아 숫자를 요구하는 게이트(`check.mjs`)가 warn 이라 작성팀은 브리프의 1순위를 거의 그대로
가져간다. 기획팀이 같은 수를 계속 1순위로 올리면 게이트는 통과하는데 채널만 단조로워진다.

**How to apply:** §6-D(제목 후킹 권고)를 쓰기 전에 이 목록을 보고, 겹치면 ①다른 수치를 1순위로 올리거나
②원문 근거가 있는 다른 수와 묶어 새 문장으로 만든다. 새로 소진한 훅이 생기면 이 파일에 한 줄 추가한다.
