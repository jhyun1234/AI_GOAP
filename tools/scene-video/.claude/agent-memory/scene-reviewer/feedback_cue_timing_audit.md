`cue` 물림은 눈으로 인덱스만 보지 말고 **초로 환산해 검증한다.** 계산에 필요한 사실 둘이
코드에 흩어져 있어 매번 다시 찾게 된다.

**Why:** 지금까지 두 번 사고가 났다(ep02s `tripwire` = `frac(t/5.2)` 로 도는 조건에 sfx 를 물림,
ep00i `runmark` = 다른 cue 의 진행도로 만든 문턱이 1.64초 먼저 터짐). 인덱스만 보면 둘 다 멀쩡해 보인다.

**How to apply:**

1. `engine/engine.js` `buildTimeline` — `rel[i].dur` 은 **TTS dur + `pauseAfter`** 다
   (`engine.js:163` → `cue()` 가 `s.rel[i].dur` 을 읽는다, `:289-292`).
   `build/timed.json` 의 dur(= wav 길이) 만 쓰면 창이 `pauseAfter` 만큼 짧게 나온다.
   🔴 **이 혼동은 검수·작성 양쪽에서 반복해서 난다.** ep09s-2 에서는 코디네이터가
   *"실측 `l.dur` 은 3.313초"* 라며 작성팀이 쓴 3.563 을 「7% 빗나갔다」고 했는데,
   3,313 + `pause` 250 = **3,563 이 맞는 값**이었다. 회차 전체가 130~250ms 씩 밀린다.
   🔑 **모형이 「말하는 시간」을 예측하고 `pause` 를 빠뜨리는 형태도 같은 뿌리다** —
   ep09s-2 tick 은 두 모형이 4.08~4.44 를 줬고 TTS dur 4.374 는 그 안이었지만
   cue 가 쓰는 rel 은 4.504 로 **폭 바깥**이었다.
2. 창 `W = lead + rel[i].dur × span`, 진행도 p 인 시각 = `p × W − lead` (자막 시작 기준 초).
3. `ease` 는 smoothstep `3k²−2k³` 다. **역함수를 손으로 넣지 말고 이분탐색으로 풀 것** —
   실측 `ease(k)=0.9 → k=0.8065` · `0.95 → 0.8646` · `0.72 → 0.6513` · `0.5 → 0.5`.
   🔴 작성팀이 여러 회차에서 `ease(k)=0.9 → k=0.729` 로 적어 왔는데 **틀린 값**이다
   (0.729 = 0.9³). span 이 큰 샷(0.9)에서는 이 오차만으로 0.5초가 어긋난다.
4. `render.mjs` 의 sfx 배치는 `line.t + delayMs` — **자막 시작 기준**이 맞다.
   `sweep` 은 `sin(PI·k)` 포락선이라 **에너지 정점이 dur/2 뒤**다. 시작 시각이 아니라 정점을 맞춰야 한다.
5. 판정선 = ±20프레임(0.667초). 그 안이면 통과지만, 10프레임 넘게 어긋나면 사유를 적어 올린다.
5-1. 🔴 **정정으로 자막을 한 글자라도 건드리면 그 줄의 `delayMs` 는 반드시 다시 푼다.**
   `l.dur` 이 바뀌면 창 `W` 가 통째로 바뀐다(ep09s-1: 19자→20자로 `rel dur` 3,808→4,067ms,
   `delayMs` 2,012→2,151). 🔑 **되돌림 루프의 구조적 결과** — 대본→실측→정정→재실측 순서라
   자막을 고친 회차는 `notes.길이` 와 `delayMs` 가 **항상 한 걸음 뒤진다.** 반려 사유로 삼지
   말고 **검수가 정확한 값을 계산해 넘겨** 마스터가 렌더 직전에 끼우게 한다(TTS 재생성 불필요).
   안 바뀐 줄도 함께 다시 풀어 **정말 안 바뀌었는지** 확인한다.
6. 🔑 **「자막 안의 어느 어절에서 터지는가」는 wav 포락선으로 실측할 수 있다.**
   글자수 비례 추정은 쉼표 앞뒤에서 어긋나는데, `build/audio/NN-*.wav` 를 20ms 프레임 RMS 로
   훑으면 **쉼표 자리의 무음 구간이 그대로 보인다** — 거기가 절이 갈리는 시각이다.
   ep08s-1 S2 실측: `noinput.js` 의 `split 0.60` 이 가리키는 시각 2.699초, 실제 「감 대신」 발화
   시작 2.66초(무음 2.48~2.66) → **1.2프레임**. 글자수 비례 추정(2.85초)보다 정확했다.
   ⚠️ wav 앞머리에 **0.36~0.46초의 무음**이 붙어 있고 `dur` 은 그걸 포함한다. 어절 위치를
   비례로 낼 때는 그 무음을 뺀 **발화 구간**에 대해 비례해야 맞는다.

`t` 로 도는 것(`frac(t/N)`)은 전부 장식 루프인지 확인한다 — 거기에 sfx 나 나레이션이 물려 있으면 반려.
`grep -n "frac(t\|Math.sin(t" kinds/*.js` 로 한 번에 뽑힌다.
