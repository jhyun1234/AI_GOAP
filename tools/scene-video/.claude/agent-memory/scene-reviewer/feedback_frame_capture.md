`check.mjs` 14종을 전부 통과해도 **도형끼리 겹쳐 라벨을 덮는 결함은 안 잡힌다.**
검수 때 샷마다 스틸을 뽑아 눈으로 본다.

**Why:** eptest-m11 은 14종 전부 OK 였는데, 스틸을 보니 S4 에서 흰 토큰이 `주머니 상한 8`
라벨 위에 앉아 '상한' 두 글자를 덮고 있었다. 픽셀 점검은 팔레트·잘림·정적 구간만 보고
"무엇이 무엇을 가렸는가"는 보지 않는다. 자막을 화면이 옮겨 적었는지도 스틸이 제일 빠르다.

**How to apply:** `tools/scene-video/` 에 임시 mjs 를 만들어 돌리고 지운다.
(`lib-node.mjs` 를 절대경로로 import 하면 `ERR_UNSUPPORTED_ESM_URL_SCHEME` 이 난다 —
스크립트를 `tools/scene-video/` 안에 두고 `./lib-node.mjs` 로 상대 import 할 것.)

```js
import fs from 'fs';
import { openEngine, shot } from './lib-node.mjs';
const { cdp, close } = await openEngine('<ep>', { quiet: true });
for (const ms of process.argv.slice(2).map(Number))
  fs.writeFileSync(`<outdir>/${ms}.png`, await shot(cdp, ms));
await close();
```

찍을 시각은 `build/timed.json` 으로 만든다 — 샷 시작을 누적할 때 **샷마다 `SHOT_TAIL` 0.35초**를
더해야 실제 타임라인과 맞는다(그래서 `timed.json` 의 totalMs 보다 영상이 0.35×샷수 만큼 길다).
🔴 이산 분기 시각을 정확히 찍으면 `>` 비교라 **직전 프레임**이 나온다. +300ms 쯤 뒤도 같이 찍을 것.

## 🔴 흰색×강조색 겹침은 팔레트 게이트가 **구조적으로** 못 본다 (증명, ep08s-2 검수)

`#00FF88` 을 흰색(또는 흰 위의 회색) 위에 알파 a 로 얹으면 결과는
`r=255(1-a) · g=255 · b=136a+255(1-a)` 이고, hue = `60×((b−r)/c + 2)` 에서
`(b−r)/c = 136a/255a = 0.533` 으로 **a 가 약분돼 사라진다** → 어떤 알파에서도 hue 는 정확히
**152도**, `check.mjs` 의 accent 대역(138~168) 한복판이다.
🔑 그래서 "팔레트 통과 = 안 섞였다"는 **절대 성립하지 않는다.** 작성팀이 z 순서를 짚어
자기신고했더라도 반드시 스틸로 확인한다. 실제로 볼 것은 색이 아니라 **흰 글자·숫자가
강조색에 훑히는가**(8-1 반려 형태)이고, 그건 라벨의 y 대역과 강조색 요소의 y 대역을
코드에서 뽑아 겹치는지 보면 스틸 없이도 1차로 걸러진다.

### 🔬 섞인 픽셀은 **세면 된다** — 눈짐작 말고 숫자로 (ep10s-3 검수에서 확립)

`openEngine` 으로 열어 `cdp.evaluate` 안에서 `window.seek(ms)` 뒤 캔버스를 직접 읽는다.

🔴 **캔버스는 샷마다 하나이고, 안 보이는 샷도 마지막에 그린 그림을 그대로 들고 있다**
(ep12s-2 검수에서 세 번 헛짚었다). `document.querySelectorAll('#vis canvas')` 는
**샷 수만큼** 돌아오고 `[0]` 은 언제나 S1 이다 — 다른 시각을 재려면 **샷 인덱스로 직접 고른다.**
「잉크가 제일 많은 캔버스」로 고르면 **틀린다**: 24.9초(S4)에 잉크가 S3 canvas 72,624 vs
S4 canvas 27,551 이라 S3 을 집는다. 샷 경계는 `timed.json` 의 rel 합 + `SHOT_TAIL` 0.35 로 만든다.
🔑 코드 좌표 → 픽셀 배율은 `canvas.height / 307`(fitCanvas 가 `setTransform(dpr,…)` 을 건다).
정확한 원점은 **가로 전체를 지나는 선**(띠 테두리 등)의 행을 찾아 코드 y 와 맞춰 확인한다.

흰색 α 를 `#00FF88` 위에 얹은 픽셀은 **`g=255` 이고 `r = 255α`, `b = 255α + 136(1−α)`** 라
`r` 만 보면 α 가 역산된다. 그 형태만 골라 개수를 세면 「고의 알파」와 「안티에일리어싱」이 갈린다:

```js
if (a < 200) continue;
if (g0 > 240 && r0 > 40 && r0 < 235 && b0 > 150 && b0 < 250) mix.set(r0+','+g0+','+b0, ...);
```

🔴 **캔버스는 투명 배경이다 — `a` 로 두 번 걸러라** (ep12s-1 검수에서 확립).
검정은 CSS 가 깔고 kind 는 투명 위에 그리므로 `getImageData` 는 **비premultiplied** 로 돌아온다.
그래서 `tone('track')`(흰 0.12)은 `(255,255,255, a=31)` 이고 `#00FF88` 후광은 `(0,255,~0, a=낮음)`
이다(저알파에서 premultiply 반올림 때문에 b 가 0 으로 뭉갠다 — 순수 초록처럼 보여도 놀라지 마라).
- `a < 200` 만 쓰면 **반투명 안내선 위의 겹침이 통째로 안 보인다.**
- 그래서 **두 번 센다**: `a > 20`(전부) → 위치·색을 보고, `a > 120`(실질 불투명) → **이 값이 0 이면
  「흰 글자·흰 선을 덮은 자리 없음」이 확정**이다. ep12s-1 은 267프레임에서 `a>120` 이 **0** 이었고,
  `a>20` 에 잡힌 것은 전부 `setShadow(GLOW,14~15)` 후광이 0.12 안내선에 닿은 것뿐이었다.
🔑 **작성팀은 좌표 거리(「6px 물러났다」「4px 떨어져 있다」)로만 논증한다 — GLOW 후광(blur 14~15)은
그 거리를 넘는다.** 무해한 경우가 많으니 🟡 로 내되, **「자라는 사각형」은 다르다**:
`quota.js` 의 검사 테두리는 `rh = H * ring` 이라 아래 획이 y 88→158 을 쓸며 격자 두 줄을 지났는데
노트는 「4.5px 못 미친다」고 단언했다. **애니메이션되는 도형은 완성 좌표가 아니라 궤적으로 따져라.**
- **같은 값이 수십~수백 개로 뭉쳐 있으면 `globalAlpha` 로 고의로 얹은 것**이다
  (ep10s-3: `rgb(115,255,189)` 98개 = 흰색 α0.451, `rollback.js` 의 목수 고리가 강조색 레일 위).
- **값이 다 다르고 1~2개씩 흩어져 있으면 안티에일리어싱 경계**다 — `check.mjs` 주석이
  스스로 "팔레트 위반이 아니라 허용된 두 색이 섞인 자리"라고 인정한 형태이니 지적하지 않는다.
- 🔑 **면적으로 등급을 가른다.** 글자를 훑으면 반려(ep08s-1), 선 교차부 100px 안팎이면
  🟡 **「그림이 아니라 노트의 주장을 고쳐라」** — 작성팀 노트의 "얹지 않았다"가 거짓이 된다.

### 🟢 혼합 픽셀의 **일반 판별식** + 자가검증 (ep12s-3 검수에서 확립 — 이걸 먼저 써라)

위 두 레시피는 「흰색이 강조색 **위**」 한 방향만 잡는다. 순서·알파와 무관한 항등식이 있다:
흰 w · 강조 a 의 가산 혼합은 `r=255w · g=255(w+a) · b=255w+136a` 이므로 **항상**
```
b = r + 0.533·(g − r)          // 이 항등식이 혼합의 정의다
```
를 만족한다. `0.12 < r/g < 0.88` 을 같이 걸면 **순수 흰(r/g=1)·순수 강조(r/g=0)·회색이 전부
빠지고 진짜 혼합만 남는다.** 어느 쪽이 위든, 알파가 얼마든 잡힌다.
```js
const isMix = (r,g,b) => g > 90 && r/g > 0.12 && r/g < 0.88
                      && Math.abs(b - (r + 0.533*(g-r))) < 22;
```
🔴 **탐지기를 반드시 자가검증하고 그 수를 리포트에 적어라.** 시험 캔버스에 흰 사각형을 채우고
그 위 절반을 `globalAlpha 0.5` 로 `#00FF88` 칠한 뒤 세면 **정확히 그 절반 픽셀 수**가 나와야
한다(ep12s-3: 20×10 = 200 검출). 이 한 줄이 없으면 「0 건」이 「탐지기가 죽었다」와 구별 안 된다.

### 🔴 `check.mjs --fps 30` = **mp4 에 들어갈 모든 프레임을 본 것**

`check.mjs` 의 기본 `FPS` 는 **5**(200ms 간격)인데 `render.mjs` 의 기본 `FPS` 는 **30**이다.
즉 기본 점검은 **여섯 프레임 중 하나만** 본다 — 슬라이드·jolt 처럼 짧게 밖으로 나갔다 들어오는
요소의 최악 순간을 통째로 놓칠 수 있다. **가장자리·팔레트·정적 구간 주장을 검증할 때는
`--fps 30` 으로 한 번 더 돌려라**(27초 회차 = 813프레임, 몇 분이면 끝난다).
🔑 30fps 가 통과하면 「그 프레임은 mp4 에 없다」가 아니라 **「mp4 의 모든 프레임이 안전하다」**
가 되어, 작성팀의 연속 수식 검산을 믿지 않고도 결론이 선다(ep12s-3 의 `hunt` 반려 수정 검증).
🔑 샷별 **「잉크가 있는 가장 아래 행」** 을 직접 재면 작성팀 주석의 검산 누락도 잡힌다 —
ep12s-3 작성팀은 `flood` 최악을 「격자 201」이라 적었지만 실측 최저는 **로그 카드 290** 이었다.

🔴 **단, `정적 구간` 만은 fps 를 올려 읽으면 안 된다 — 잣대가 fps 불변이 아니다**
(ep12s-2 검수에서 확립). 이 검사는 `연속 두 **샘플**의 평균 휘도차 < 0.0008`(check.mjs:536)인데
그 상수는 **기본 FPS 5 에서 잡힌 값**이다. 간격을 6배 줄이면 같은 움직임이 6분의 1로 보여
자동으로 문턱 아래로 내려간다. ep12s-2 는 **0.2 → 1.6 → 2.8 → 3.0 → 3.4s**(fps 5/10/15/20/30)로
**단조 증가**했고, **이미 승인·발행된 `ep11s` 도 0.0 → 2.5s** 로 뛴다.
→ 팔레트·가장자리·안전영역·결정성은 `--fps 30` 판독이 **더 강한 근거**이지만,
정적 구간은 **기본 fps 5 판독이 정본**이다. fps 30 값으로 반려하면 ADR-V-7 위반이다.
🔑 그래도 **회차 간 비교에는 쓸 수 있다**(같은 fps 로 나란히 재면 상대 비교는 유효) —
「어디가 조용한가」의 위치를 찾는 데 좋다. ep12s-2 는 30fps 최대 정적 구간의 양 끝이
**「페이오프 완성」과 「예고 띠 점등」에 정확히 맞아떨어져** 비는 자리를 특정할 수 있었다.

## 🔴 **같은 색끼리 붙는 것**도 봐라 — 겹침 감사는 늘 흰색×강조색만 잰다 (ep12s-1 4단본)

작성팀의 겹침 논거는 **색이 다른 쌍**만 잰다(팔레트 게이트가 그 축이라서다). 그래서
**흰색↔흰색 두 라벨이 세로 간격 0px 로 붙는 것**이 통째로 감사 밖에 있다. ep12s-1 의
`nextpeek` 은 `GAUGE_Y=66`(중앙정렬 `cx`)와 `FAIL_LBL_Y=74`(중앙정렬 `fx=IX+IW*failAt`)가
**x 를 절반 넘게 공유**해 「WINTER LEFTOVER」와 「FAIL 30」이 한 덩어리로 뭉갰다.
노트에는 *"가장 가까운 쌍이 12px"* 라고 적혀 있었는데 그건 강조색↔흰색 쌍이었다.
**판정법**: baseline 차(8px)를 글리프 높이(disp 800@12.5 ≈ 9.6px · mono 700@12 ≈ 8.3px)와
비교하고, **중앙정렬 기준점이 서로 다른 텍스트는 x 구간이 겹치는지 따로 본다.**
확인은 스틸 → 회색 raw 로 뽑아 **행별 밝은 픽셀의 x 범위**를 찍는다. 두 덩어리 사이에
**빈 행이 0줄**이면 붙은 것이다(캔버스 배율은 알려진 도형 두 점 — 삼각형 `TIP_T`/`TIP_B` 등 —
으로 역산한다).

## 🟢 「이 kind 가 앞 회차와 계열이 겹치는가」의 정본도 스틸 두 장이다

코드를 읽으면 겹쳐 보이고 스틸을 보면 안 겹치는 일이 있다. ep10s-1 `squeezed` 는 작성팀이
*"`ep09s-1/infoline` 과 계열이 같다고는 말하지 않겠다"* 고 **자진 신고**했는데, 두 편의
마지막 샷 완성 프레임을 나란히 놓으니 **같은 그림으로 안 읽혔다**(infoline = 프레임 + 3칸 +
코드칸 + 연결선 + 밑줄 / squeezed = 띠 하나 + 굽은 줄 둘 + 세로로 쌓인 라벨 + 훑개).
공유하는 것은 「가로로 긴 둥근 사각형」뿐이었고 그건 이 엔진에서 축을 그릴 최소 단위다.
🔑 **작성팀의 자진 신고는 과잉인 쪽이 많다 — 신고를 근거로 반려하지 말고 스틸로 판정하라.**
반대로 작성팀이 *"대조했다"* 고 단언한 자리(sfx 파라미터)에서 실제 겹침이 나왔다
([[recurring-script-defects]] ③). **신고한 곳보다 단언한 곳을 의심하라.**
