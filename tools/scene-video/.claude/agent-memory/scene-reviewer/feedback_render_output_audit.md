렌더가 끝난 회차의 픽셀 검증은 **`build/video.mp4` 에서 직접 프레임을 뽑는다.**
엔진을 다시 열어 스틸을 뜨는 것([[frame-capture-for-review]])은 렌더 **전** 방법이다 —
렌더 후에는 「실제로 나간 파일」이 정본이고, ffmpeg 한 줄이면 크로미움 없이 된다.

```
ffmpeg -loglevel error -y -ss <t> -i episodes/<ep>/build/video.mp4 -frames:v 1 out.png
```

**Why:** lf02 렌더 후 검증에서 이 방법으로 90여 장을 뽑아 21개 kind 전수 + 클립 5샷 +
아웃트로 카드 직전을 한 번에 봤다. 엔진 재렌더는 회차당 수 분이 걸리고, 무엇보다
**mp4 에 들어간 것과 다를 수 있다**(클립 seek·인코딩). 리포 밖 스크래치에 뽑으면
`build/` 를 한 바이트도 안 건드린다.

**How to apply:** 시각은 `timed.json` + `engine.js:buildTimeline` 을 그대로 복제해 만든다
(`dur = timed.dur + scene.pauseAfter`, 샷마다 `SHOT_TAIL 0.35` 추가). 총계가 `check.mjs` 의
「총 길이」와 소수점까지 맞으면 타임라인 복제가 옳다는 뜻이다 — **먼저 이걸 확인하고 시작하라.**

## 🔴 클립 창 여유는 **두 종류**다 — 팀 전체가 발화 합만 쓰고 있다

작성팀·마스터가 쓰는 「여유 +0.39초」는 **자막 발화 합** 기준이다. 그런데 엔진이 실제로
클램프하는 기준은 **샷 길이**이고, 샷 길이 = 발화 합 + `SHOT_TAIL 0.35`다.

```js
// engine.js — 이 식이 정본
want = Math.min(out - 1/120, in + (t - shot.t)/1000 + 1/60);
// 얼어붙는 조건: in + shotDur > out - 1/120
```

즉 **실제 여유는 보고된 값보다 언제나 0.35초 작다.** lf02 실측:
S1 +0.39 → **+0.041**(1.2프레임) · S4 +1.15 → +0.80 · S12 +0.92 → +0.57 ·
S17 +0.64 → +0.288 · S25 +0.79 → +0.43. **S1 은 자막 한 글자만 늘려도 마지막 프레임이 언다.**
표에 둘 다 적고, 「+0.2초 확보」 같은 주장은 어느 기준인지 물어라.

## 🔴 「정적 구간」 클립 경고는 **원본 클립을 따로 재야** 원인이 갈린다

`check.mjs` 는 클립 샷에서 `.shot.on canvas` 가 아니라 **활성 클립 비디오**를 160×90 으로
줄여 잰다(3픽셀마다 · 평균 절대 휘도차 `m < 0.0008`). 그래서 경고만 보면
**①창이 모자라 마지막 프레임이 얼었다** 와 **②컷 자체가 고요하다** 가 구분되지 않는다.
lf01 선례상 ②는 허용, ①은 재슬라이스다 — **반드시 갈라야 한다.**

원본 클립에 같은 잣대를 그대로 씌운다(`/d/AI_GOAP-videos/clips/library/<id>.mp4`):

```
ffmpeg -loglevel error -ss <in> -to <out> -i <clip>.mp4 \
  -vf "fps=5,scale=160:90,format=gray" -f rawvideo raw.gray
# 그 뒤 노드에서 프레임 간 |Δ| 를 3픽셀마다 평균 / 255 → m
```

lf02 실측(전부 in~out 구간): `built-08` 최대 0.00891 · `disaster-65` 0.00655 ·
`forecast-58` 0.00509 · `broll-178` 0.00227 · **`death-162` 0.00073(34/34 표본이 문턱 아래)**.
→ death 컷은 **원본이 정지에 가깝다**가 확정됐고, 위 클램프 계산으로 ①도 배제돼
「재슬라이스 불필요」 판정이 섰다. 🔑 **사건이 없다는 뜻은 아니다** — 무덤 하나가 생기는
변화는 160×90 에서 몇 픽셀이라 이 잣대로는 안 보인다. 사건 유무는 스틸로 따로 본다.

## 🟡 클립 샷에서 **게임 스프라이트가 엔진 HUD 를 덮는다**

「게임 HUD 는 좌상단 x≤730, 엔진 HUD 는 x≥1030 이라 겹치는 컷이 없다」는 세 라운드 내내
인용된 문장인데 **HUD 텍스트 패널에만 맞다.** 주민 스프라이트와 말풍선은 맵 어디든 간다 —
lf02 S4 는 65.3~66.3초에 주민이 우상단으로 올라와 `hud.aiHook` 의 글자를 반쯤 가렸다.
반려 등급은 아니지만(1초 미만 · 브랜딩 줄) **클립 고를 때 「우상단으로 주민이 지나가는가」를
항목으로 넣어라.** 반대 방향(엔진 HUD 가 게임 페이오프를 덮음)은 lf01 선례 금지 #4 = 반려다.
