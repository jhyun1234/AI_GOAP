**파형 상관값 하나로 반려하지 말고, 먼저 「승인돼 나간 회차끼리」의 같은 kind 전수 쌍을
재서 분포를 만든 뒤 그 안에서 판정하라.**

**Why:** `ep13s-3`(2026-08-10) 의 `thud(0.36/108)` 은 가장 가까운 이웃 `ep05s-2(0.21/112)` 와
**r = 0.8730** 이었다. 높아 보여서 반려할 뻔했는데, 승인 회차 thud 19개의 **171쌍 전수**를
재 보니 중앙값 0.074 · 90분위 0.448 · **최댓값 0.9904** 였고 0.873 보다 높은 쌍이 **여섯**이었다
(`lf01(0.16/150)–lf02(0.17/150) 0.9904` · `ep04s-3(0.20/168)–eptest(0.16/170) 0.9619` ·
`ep00i(0.32/125)–ep04s-2(0.30/124) 0.9038` 등, 기본값 150 을 쓴 줄끼리가 특히 높다).
**0.873 을 반려하면 승인 여섯 쌍에 안 댄 잣대를 한 편에만 대는 것**이 된다 —
[[self-report-is-not-evidence]] 의 「같은 종류를 다른 기준으로 재고 있지 않은가」 그대로다.

**How to apply:**
- 재는 법(리포트에 반드시 함께 적는다 — 같은 쌍이 검수 0.851 / 마스터 0.595 로 갈린 전례):
  `sfx.mjs` 의 `synth(kind, opt, 44100)` 을 씬의 **실제 인자**로 호출하고,
  **정규화 위치로 리샘플하지 말고 절대 표본 인덱스 0 정렬**로 짧은 쪽 길이만큼 피어슨 상관.
  (리샘플하면 같은 seed 쌍이 −0.02 로 나와 검출 자체가 안 된다.)
- 판정 순서: ①그 kind 의 **기존 전수를 기계로 다시 뽑는다**(작성팀 `why` 의 열거는 늘 빠진다 —
  ep13s-3 은 sweep 14건 중 2건이 빠졌고 하필 빠진 `ep06s`(0.44)가 **이 편과 dur 이 같았다**)
  ②이 편 vs 기존 전부 ③기존끼리 전수 ④②가 ③의 분포 안이면 통과.

## 🔑 kind 별로 상관의 바닥·천장이 다르다 (실측 캘리브레이션)

| kind | `rng` 쓰나 | 다른 seed/인자 쌍의 상관 | 뜻 |
|---|---|---|---|
| `sweep` | `rng(seed ?? 11)`, 잡음이 전 구간 지배 | **\|r\| ≤ 0.024** (14건 전수) | seed 만 다르면 완전히 갈린다. 판정이 쉽다 |
| `latch` | `rng(seed ?? 7)` 인데 잡음이 `exp(-260t)` 로 15ms 만에 죽고 340/680Hz 몸통이 지배 | **0.72~0.78 이 하한** (ep13s-1 seed157 ↔ ep13s-2 seed191 = **0.7444**) | 「더 갈라라」가 **물리적으로 불가능**하다. 반려 금지 |
| `thud` | 안 부름 (기음+2·3배음) | freq 가 가까우면 0.87~0.99 | (dur, freq) 대조가 곧 파형 대조. 분포로 판정 |
| `tick`·`riser`·`drop` | 안 부름 | 인자 같으면 **bit 단위 동일** | 인자 대조로 끝 |

🔑 **kind 가 다르면 같은 seed 여도 안 겹친다.** `sweep(0.44, seed 191)` ↔
`latch(0.17, seed 191)` = **r = 0.0020**. 「같은 seed 를 형제 편이 쓴다」는 지적은
**같은 kind 일 때만** 유효하다 — 다른 kind 면 재 보고 조용히 통과시켜라.

## 🔑 0.85 가 임의값이 아니라는 실측 (ep16s-1, 2026-08-11)

**`seed` 를 명시한 latch 26건 325쌍의 내부 최대가 0.8408**(`ep08s-1/S4` 0.205/83 ↔
`lf02/S19` 0.2/179), 95% 0.8148 · 중앙 0.7594 — **통제군이 스스로 0.85 아래를 지킨다.**
기본 seed(7) 계열을 섞으면 최대가 0.9976 으로 뛰어 분포가 통째로 오염된다.
🔑 참고 통과값: `ep16s-1` sweep(0.54/**277**) 최대 **0.0184** · latch(0.165/**281**) 최대 **0.7937**.

`latch dur 0.14 seed 7` 한 칸에 `ep02s/S8`(인자 없음)과 `_archive/eptest-m11/S10`(인자 없음)이
들어 있어 r = 1.0000 이다 — 접는 잣대는 아래 「같은 호출」 절 그대로다.

## 🔴 작성팀이 만들어 오는 「대체 척도」는 반드시 상관으로 검증하라 (ep16s-2, 2026-08-11)

`ep16s-2` 작성팀이 tick 을 고르며 **새 척도**를 세웠다 — *"포락선이 dur 로 정규화돼 있으니
**정규화 위치로 리샘플하면 모양을 정하는 것은 `freq × dur` = 진동 수 하나**"*. 재 봤더니
**틀렸다.** tick 서로 다른 호출 29종 · 406쌍 전수에서

| 설명 변수 | r 과의 상관 |
|---|---:|
| \|Δ진동수(freq×dur)\| | **−0.032** ← 척도 |
| \|Δfreq\| | −0.145 |
| \|Δdur\| | −0.067 |

반례가 양방향이다: **Δ진동수 0.4 인 쌍이 r = −0.194**(전혀 안 닮음)이고, **Δ진동수 38.3 인
쌍이 r = 0.9748**. r 상위 쌍은 **전부 Δfreq ≤ 40** 이다.
🔑 원인 = 전제 오류. **판정 절차는 정규화 리샘플이 아니라 절대 표본 정렬**이라,
실시간 주기를 정하는 `freq` 가 지배하고 `dur` 은 감쇠 속도만 바꾼다.
→ **tick 의 실효 판별축은 `freq` 하나다.** 옛 표의 「인자 같으면 bit 동일」은 맞지만
「인자가 다르면 다른 소리」는 **거짓** (freq 1180 이 같고 dur 이 0.052/0.05 로 다른
`ep09s-1/S3` ↔ `lf01/S28` 이 **r = 0.9998**).

🔴 **판정선 0.85 는 이제 `scene-reviewer.md` 본문에 있는 정본이다**(2026-08-10 신설).
기억에서 대역을 꺼내 쓰지 마라 — 세 층이 각자 다른 값을 적은 사고가 있었다.

**측정된 통제군(같은 호출 접은 뒤, 2026-08-11):**
- `latch` 29종 378쌍 — 중앙 **0.7602** · 95% **0.8145** · 최댓값 0.9976
  (최댓값은 `ep02s/S8`(기본 seed 7) ↔ `ep03s/S5`(**seed 미지정 = 7**) — 나간 편이라 안 되돌린다)
- `tick` 29종 378쌍 — 중앙 **−0.0220** · 95% **0.5638** · 최댓값 0.9998
- 참고 통과값: `ep16s-2` latch(0.105/251) 최대 **0.7207** · tick(0.095/1560) 최대 **0.7030**
- 참고 통과값(ep16s-4, 2026-08-11): **sweep(0.68/seed 263) 통제군 19건 최대 |r| 0.0202** ·
  **tick(0.064/freq 2760) 통제군 29건 최대 |r| 0.1808**(상대 = ep10s-1 freq 2320).
  🔑 **freq 2760 은 기존 tick 최고(2540)보다 위라 최근접 Δfreq 가 220** — 상관 상위 대역
  (Δfreq ≤ 40) 밖이어서 여유가 크다. **고역 tick 은 아직 2100~2760 넷뿐이라 자리가 넉넉하다.**

🔴 **「진동 수(freq×dur)」 척도가 두 번째로 반박됐다 (ep16s-4, 2026-08-11).**
코디네이터가 *"tick 판정은 표 대조가 아니라 진동 수 축으로"* 라고 지시했지만, 이 편에서
**진동 수 최근접(ep10s-1, −5.4%)과의 r = 0.1808** 이 **진동 수가 한참 먼 ep11s(111.8 vs 176.6)와의
r = 0.1458** 과 사실상 같았다. 줄 세우는 것은 `freq` 다.
🔑 **지시서·코디네이터 지시가 이 척도를 말해도 그대로 받지 말고 상관으로 검산해 근거를 바꿔 적게 하라** —
결론(통과/반려)은 대개 안 바뀌지만 `why` 에 남는 근거가 다음 회차의 판단을 오염시킨다.

🔑 **「같은 호출」 접기의 잣대는 「인자를 적었나」가 아니라 「기본값을 채운 뒤 인자가 같나」**다.
`ep03s/S5` 는 `dur` 만 적고 `seed` 를 안 적어 기본 7 이 되는데, 그걸 안 접으면 통제군 최댓값이
자기쌍으로 부풀어 다음 회차가 「이 정도는 괜찮다」의 근거로 쓴다.

## 🔑 「kind 쌍 집합이 형제와 같다」는 판정 대상이 아니다 (ep16s-5, 2026-08-11)

`ep16s-5` 작성팀이 *"형제 `ep16s-2` 와 sfx kind 쌍의 집합이 같다({tick, latch})"* 를 자진
신고하며 판정을 넘겼다. **재 보니 무해했다** — `ep16s-2/S3` tick ↔ 이 편 tick = **−0.0357**,
`ep16s-2/S2` latch ↔ 이 편 latch = **0.6496**(통제군 중앙 0.757 **아래**).
🔑 **이 파이프라인이 무는 것은 파형이지 kind 이름의 조합이 아니다.** 「같은 두 kind 를 쓴다」로
반려하면 6종뿐인 킷에서 형제 5편이 조합을 다 소진하게 된다. **자진 신고를 받으면 칭찬하고,
판정은 상관으로 하라.**

**ep16s-5 실측(통제군 재계산 · 같은 호출 접은 뒤 tick 28종 / latch 28종 · 각 378쌍):**
- `latch` 중앙 **0.7565** · 95% **0.8122** · 최대 0.9976 → 이 편 latch(0.285/**271**) 최대
  **0.8366**(`ep08s-3` 0.225/97). **95% 위이지만 판정선 0.85 아래**라 통과시켰다.
- `tick` 중앙 **−0.0322** · 95% **0.5953** · 최대 0.9998 → 이 편 tick(0.092/**2210**) 최대
  **0.2790**(`ep00i` 0.04/**2100**, Δfreq 110). **freq 가 지배축**이라는 위 결론의 재확인.
- 무경고 상한: **tick(0.092/2210) 0.0727**(gain 0.058) · **latch(0.285/271) 0.0953**(gain 0.064).
  🔑 latch 는 `dur`↑ ⇒ 피크↓ 라 0.285 가 리포 최장이면서 천장에서 가장 멀다.
- ⚠️ `ep16s-1` 의 latch seed 가 **251 → 281 로 바뀌어 있었다**. 형제가 병렬로 고치므로
  **작성팀 `why` 의 census 는 리포트 쓰는 시점에 이미 낡는다 — 검수도 다시 세라.**

## 🔑 `riser` 는 판별이 가장 쉬운 kind다 + sweep 통제군의 정확한 오염원 (ep16s-3, 2026-08-11)

- **`riser` 18건 153쌍 전수** — 중앙 **0.0001** · 95% **0.1817** · **최댓값 0.3088**
  (`ep02s/S9B` 기본 160→520 ↔ `ep04s-3/S2` 150→470). **통제군 자체가 0.31 을 못 넘는다.**
  → riser 는 인자만 겹치지 않으면 사실상 자동 통과. `ep16s-3`(0.30/320→850)은 나머지 17건 대비
  **최대 0.0001**. 🔴 옛 표의 「riser 는 인자 같으면 bit 동일」은 맞지만, **인자가 조금만 달라도
  즉시 0 으로 떨어진다**는 쪽이 실무에 중요하다(위상이 `∫f dt` 라 절대 표본 정렬에서 금방 어긋난다).
- 🔴 **작성팀이 riser 용으로 만든 「총 진동 수 N = dur×(f0+(f1−f0)/3)」 척도도 검증 없이 받지 마라.**
  결론은 맞았지만(N 149.0 이 빈 구간) **근거는 상관이지 그 환산이 아니다** — tick 의 진동 수
  척도가 두 번 반박된 것과 같은 형태다.
- **`sweep` 통제군의 오염원이 정확히 넷이다** — `ep02s/S7` · `ep03s/S11` · `ep04s-2/S3` ·
  `_archive/eptest-m11/S2`. 전부 **`seed` 미지정 = 기본 11** 이고 `dur` 만 다르다.
  이 넷을 넣으면 20건 190쌍 최댓값 **0.9944**(ep04s-2 ↔ eptest-m11), 넷을 빼면
  **16건 120쌍 · 중앙 0.0059 · 95% 0.0210 · 최댓값 0.0367**.
  🔴 **`dur` 이 다르다고 「같은 호출이 아니다」로 넘기지 마라** — sweep 은 컷오프·포락선이
  전부 정규화 위치라 `dur` 은 시간축만 늘인다. **seed 가 같으면 접어라.**
- 참고 통과값: `ep16s-3` sweep(0.42/**269**) 최대 **0.0367** · riser(0.30/320→850) 최대 **0.0001**.
  무경고 상한 = **riser 0.3108**(gain 0.062 → 여유 5.0배) · **sweep 0.1778**(gain 0.060 → 2.96배).
- 형제 `ep16s` 다섯 실측(2026-08-11 종결): sweep 최대 **0.0072** · latch 최대 **0.7784**
  (`ep16s-1` 281 ↔ `ep16s-5` 271) · tick 최대 **0.0998** · riser 는 3편 단독.
  ⚠️ `ep16s-1` 은 sweep seed 도 **263 → 277** 로 바뀌어 있었다 — census 는 매번 다시 세라.

🔑 피크 천장은 표를 믿지 말고 `synth()` 를 실인자로 돌려 경고 유무를 본다
([[sfx-gain-ceiling]]). ep13s-3 의 둘은 목표 RMS 를 정확히 달성했다
(sweep peak 0.1583 · thud 0.1560, 천장 0.46).
실측 앵커 추가(ep16s-2): **latch(0.105/seed251) 무경고 상한 0.0667** ·
**tick(0.095/1560) 0.0754** — 산식은 `0.46 / (synth() 반환 피크 / gain)`.
🔴 상한은 `0.46 / (synth() 반환 파형 피크 / gain)` — **반환값에 gain 을 또 곱하지 마라.**
실측 여유가 kind 마다 크게 다르다: `sweep 0.54/277` 상한 **0.1775**(넉넉) vs
`latch 0.165/281` 상한 **0.0778**(gain 0.064 면 여유 21%뿐).
🔴 **고역 tick 은 기본 gain 0.060 조차 아슬아슬하다** — `tick 0.064/freq 2760` 상한 **0.0628**
(여유 4.7%). 옛 문서의 「tick 상한 0.065」를 그대로 썼으면 **걸렸다.**
같은 편 `sweep 0.68/seed 263` 상한은 **0.1829**(여유 186%). 같은 회차 안에서도 30배 차이다.
