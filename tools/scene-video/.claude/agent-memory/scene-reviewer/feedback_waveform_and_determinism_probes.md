## 🔴 latch·sweep 돌려막기 — `seed` 하나가 전부다 (ep13s-1 반려 실측, 2026-08-10)

**규칙:** `latch`·`sweep` 의 중복은 **`seed` 만 보면 된다.** `dur` 이 달라도 개성은 안 갈린다.

**Why:** `sfx.mjs:73-84` 의 `KIT.latch` 는 몸통이 **340/680Hz 고정**이고 개성이
`click = r() * exp(-260·t)` 하나에서 나온다. `r()` 은 `rng(o.seed ?? 7)` 이고 `exp(-260t)` 는
절대 시각 함수라 **앞 15ms 는 `dur` 과 무관하게 표본 단위로 같다.** `dur` 은 몸통 감쇠
(`env(...,14)` 의 `t/dur`)만 바꾼다. ep13s-1 S3 `latch(dur 0.135, seed 157)` 가
`lf02 S5 latch(dur 0.16, seed 157)` 와 충돌했고, 작성팀 `why` 는 「157 은 목록에 없다」며
lf02 를 **179 하나로만** 적었다(lf02 는 157·163·167·179 넷이고, lf02 자신의 `why` 가 그걸 적어 뒀다).

**How to apply — 재는 절차(리포트에 그대로 적을 것).**
1. `synth(kind, 씬의 실제 opts, 44100)` 을 호출해 Float32Array 를 얻는다.
2. **절대 표본 정렬**로 피어슨 상관을 낸다(짧은 쪽 길이만큼 앞에서부터 그대로).
   🔴 정규화 위치로 리샘플하면 같은 seed 쌍이 **−0.02** 로 나와 검출이 안 된다.
   (같은 쌍이 검수 0.851 / 마스터 0.595 로 갈렸던 전례가 이 차이다.)
3. **클릭 전이(앞 15ms = 662표본)만** 따로 한 번 더, 그리고 **최대 절대차**도 낸다.
4. 판정선은 **기준선 대비**로 잡는다 — 서로 다른 seed 쌍 10개를 같이 재서 대역을 만든다.

실측(2026-08-10): 같은 seed 쌍 = **전체 0.9963 · 클릭 0.9982 · 최대 절대차 0.0143**.
🔑 **다른 seed 쌍의 대역은 리포 전수 22건 기준 0.63~0.80 이다**(처음에 10쌍만 재서 「0.71~0.78」로
적었다가 2차에서 넓어졌다 — **0.80 을 봐도 놀라지 마라**). 판별선은 상관값이 아니라
**「0.99대 + 최대 절대차 0.02 미만」** 조합이다. 최근접 이웃이 0.7983 이어도 최대 절대차가
0.29 면 다른 소리다.
🔴 **seed 를 바꾸면 피크 천장도 다시 재라** — 잡음 실현이 달라진다(`latch 0.135/seed 211` 상한 0.07501).
🔑 kind 가 다르면 seed 가 같아도 무해하다(`latch191` vs `sweep191` = **0.0020**).
🔑 `tick`·`thud`·`riser`·`drop` 은 `seed` 를 안 받으므로 `(dur, freq)` 대조가 곧 파형 대조다.

🔴 **`why` 의 전수 열거는 항상 다시 세라.** ep13s-1 은 `tick` 을 「22건」이라 적었는데 실제 25건,
`latch` seed 를 「16건」이라 적었는데 실제 21건이었다. **빠진 줄 안에 충돌이 들어 있었다.**
이름으로 `rg` 하지 말고 `shot.sfx` 를 파싱해 세는 한 줄을 쓸 것([[recurring-script-defects]] ③).

## 🔴 `check.mjs --fps 30` 은 **대조군 없이 반려하지 마라** (같은 회차 실측)

**규칙:** 30fps 판독에서 `결정성`·`팔레트`·`가장자리`가 red 로 뒤집히면, **승인·발행된 회차 2편 +
형제 편 전부**에 같은 명령을 돌려 0 인지 확인한 뒤에야 반려로 낸다.

**Why:** `render.mjs:32` 의 기본 `FPS = 30` 이라 30fps 판독이 mp4 의 실제 모든 프레임이다.
그런데 결정성 검사는 **패스 순서**(전진·역방향·3칸 건너뛰기)를 비교하므로 fps 를 올리면
비교 쌍이 6배로 늘어 엔진 공통 결함까지 드러날 수 있다. ep13s-1 은 44/1062 였고
`ep12s-1`·`ep12s-3`(승인) · `ep13s-2`·`ep13s-3`(형제)이 **전부 0** 이라 회차 고유 결함이 확정됐다.
🔴 **`정적 구간` 만은 예외 — fps 를 올려 읽으면 안 된다**(문턱 0.0008 이 fps 5 상수).

**How to apply — 위치를 좁히는 법.** check.mjs 의 `det` 블록을 복사해 임시 mjs 로 돌리되
`sig()` 를 **캔버스 해시와 DOM 해시로 쪼개** 어느 쪽이 어긋나는지부터 가른다. 그다음 어긋난
프레임 하나에서 세 패스의 `getImageData` 를 뜨고 **행별 차이 픽셀 수 히스토그램**을 찍으면
코드 y 좌표로 범인이 바로 나온다(ep13s-1 = `chase.js` 의 `dashRule` 세 줄, y 84·126·276,
차이는 `tone('track')` 흰 0.12 의 알파 21↔19 = 점선 안티에일리어싱).
🔑 **캔버스 배율 = `canvas.height / 307`.**

🟢 **닫힌 방법(ep13s-1 2차에서 검증)** = 가로 점선을 `setLineDash` 대신 **조각을 `fillRect` 로 채우는
순수 산술 루프**로 바꾸면 44 → **0** 이 된다. 긴 축정렬 점선이 타는 래스터 경로가 원인이었다.
`lineDashOffset` 의 음수 mod 를 `((v%P)+P)%P` 로 정규화하는 것만으로는 부족했다(값이 같아서 무해).

🔴 **「모양 동일」 주장은 반드시 픽셀로 받아라.** 1차 스틸을 남겨 뒀다가 **같은 시각으로 다시 떠서
PNG 를 직접 디코드해 비교**한다(파서 40줄이면 된다 — zlib inflate + Paeth 언필터).
판정 잣대: **`Δ>8` 인 픽셀이 「의도한 편집 상자」 밖에 하나라도 있으면 그림이 바뀐 것**이다.
ep13s-1 실측 = 22장 중 5장 **비트 단위 동일**, 나머지는 점선 행에서 최대 Δ 1~4/255(안티에일리어싱뿐),
`Δ>8` 은 계절 라벨과 인트로 터미널 두 상자에만 = 의도 외 변화 0건.
🔑 산술로도 한 번 더 받는다 — 옛 `(s + lineDashOffset) mod P < DASH` 와 새 조각 시작 좌표가
**같은 켜짐 조건**으로 정리되는지, 세로 띠(`y±lineWidth/2` vs `fillRect(y−1.5,…,3)`)와
`lineCap='butt'`(끝단 연장 없음)까지 확인한다.
