여러 회차에서 같은 자리가 반복해서 걸린다. 검수 때 이 셋을 먼저 확인한다.

**① 화면이 자막을 옮겨 적는다.**
선례 = ep00s S4 반려 · ep02s S9B 🔴 반려. eptest-m11 에서도 S3 `badPlan`("집에 둔 곡식을
들판에서 꺼내 먹는")이 같은 순간 자막 그대로였다. 반대로 **허용된 형태**도 있다 —
ep02s S10 처럼 화면은 정확한 표기(`2막 · 리셋`), 자막은 그것을 말로 부르는 경우는 통과했다.
경계 = *문장을 통째로* 겹치면 반려, *표기/라벨*을 화면이 쥐고 말이 그것을 부르면 통과.

**② `notes` 의 자기보고를 그대로 믿으면 안 된다.**
작성팀은 `화면이_자막을_옮겨_적지_않게` · `수치_정직성` 같은 자가 점검표를 notes 에 적는데,
항목이 사실과 다른 경우가 있다(eptest-m11 ④번은 S4 목표 카드를 "자막이 안 부른다" 고 했으나
자막이 두 줄 다 불렀다). **표의 각 항목을 자막과 대조해야 한다.** 반대로 "안 만들었다"는
주장(주민 이름·성격 거리값·간호 수치)은 실제로 지켜지고 있었다 — 대조는 하되 편견은 갖지 말 것.

**③ 앞 회차 sfx 파라미터를 답습한다.**
`kinds` 이름·형태는 대조하는데 **sfx 는 대조를 안 한다.** eptest-m11 의 tick 둘은
ep02s 의 tick 둘과 dur 이 똑같았고(0.05 / 0.09) freq 만 조금 달랐다. thud 쌍(짧고 높음 +
길고 낮음)도 ep00i 와 같은 구성이다. 회차별 sfx 표를 뽑아 대조할 것:
`for ep in ...; do jq '.shots[].sfx' episodes/$ep/scene.json; done`

🔴 **작성팀이 `why` 에 적은 「전 회차 훑어 봤더니 이 값은 처음이다」 열거를 절대 인용하지 마라 —
반드시 기계로 다시 훑어라** (ep10s-1 반려 실측, 2026-08-08). 그 회차 `why` 는 tick freq 14개·
dur 7개를 나열하고 「1180 은 어디에도 없다 / 0.052 는 처음」이라 단언했는데, **`ep09s-1 S3` 이
정확히 `dur 0.052 · freq 1180`** 이었다(열거에서 그 줄만 통째로 빠졌고 dur 도 다섯 개가 빠졌다).
같은 `why` 의 sweep 쪽 「dur 0.58 · seed 43 둘 다 처음」도 거짓이었다(ep04s-2 dur 0.58 ·
ep07s-1 seed 43). **열거가 길수록 신뢰가 가는데, 실제로는 길수록 빠진 줄이 는다.**
🔑 **왜 치명적인가 — `tick`·`thud`·`riser`·`drop` 은 `seed` 를 안 받는다.** 인자가 같으면
**파형이 bit 단위로 같다.** ep10s-1 tick 은 ep09s-1 tick 과 길이 2293 샘플이 동일하고 진폭만
0.26dB 달랐다 = 귀로 구별 불가. (`seed` 를 받는 것은 `latch`·`sweep` 둘뿐.)
🔑 인자가 겹치면 **성격까지 겹치는지**도 보라 — 위 둘은 `why` 가 각각 「없던 것이 자리에 앉는다」·
「뻗은 것이 자리를 잡는다」로 사실상 같은 사건이었다. 인자 복사의 방증이다.
🔴 **바로 다음 회차 ep10s-2 에서 또 났다(2026-08-08) — 이건 우연이 아니라 고정 결함이다.**
`why` 가 「현역 thud **여섯 쌍**」·「tick **열한 쌍**」이라 열거했는데 실제는 **thud 11 · tick 14** 였고,
빠진 줄 안에 겹치는 것이 정확히 들어 있었다: `thud freq **168**` = ep04s-3(둘 다 `why` 가 「막힌다」) ·
`tick freq **1520**` ≈ ep05s-1 `1510`(둘 다 「딱 물린다」). **freq 가 겹치면 성격도 겹친다**는 관찰이
두 회차 연속 성립했다. 🔑 `dur` 이 다르면(+45%/+62%) 감쇠가 달라 **반려까지는 아니지만**,
`freq` 만 바꾸면 `delayMs` 재계산이 없으므로 **정정 요구로 내면 비용 0 이다.**
전수 훑기 한 줄:
```
node -e "const fs=require('fs'),p=require('path');(function w(d){for(const n of fs.readdirSync(d,{withFileTypes:true})){const f=p.join(d,n.name);
 if(n.isDirectory())w(f);else if(n.name==='scene.json'){const s=JSON.parse(fs.readFileSync(f,'utf8'));
 for(const sh of s.shots||[])for(const x of sh.sfx||[])console.log(s.id,sh.id,x.kind,'dur',x.dur,'freq',x.freq,'seed',x.seed,'gain',x.gain);}}})('episodes')"
```

**한 파일이 자기 모순**이 된다. `outro.siblings` 도 같다 — 「형제 대본이 없어 비웠다」고

🔑 그리고 **예측 `l.dur` 로 푼 `delayMs` 는 2차 실측 뒤 반드시 다시 풀린다.**
ep09s-2 tick 은 예측 4.25s 로 2,050ms 를 냈는데 실측 rel 은 4.504s → 이상값 **2,177ms** 였고,
그 127ms 차이로 소리가 「멈춰서」가 아니라 앞 어절 「잠깐」에 앉았다(허용선 안이지만 `why` 는 거짓).

**⑦ 🔴 분할 회차인데 한국어 `youtube.blurb` 에 형제 편으로 가는 길이 없다. (ep12s-1 반려)**

🔴 **반려는 형제 편에 전파되지 않는다 — 트리오는 한꺼번에 봐라** (ep12s-3 검수, 2026-08-08).

(1차 반려서에 요구 문장까지 통째로 적어 줬는데도). 작성팀이 **3단 → 4단 전면 재작성**을 하면서
1차 반려 사유가 새 판본에 안 옮겨 온 것이다. 🔑 **전면 재작성본은 「이전 반려 사유가 새 판본에
살아 있는가」를 체크리스트 0번으로 따로 물어라** — 새 구조를 검수하다 보면 옛 지적을 안 세게 된다.

**⑧ `why` 에서 `ease()` 의 출력과 입력을 섞어 적는다. (ep12s-3 관측, 🟡)**
`brk = ease(clamp((c0−0.68)/0.30))` 인데 `why` 는 「brk ≈ 0.20 → c0 = 0.68 + 0.20×0.30 = 0.74」로
적었다 — 0.20 은 **`brk` 가 아니라 ease 의 입력**이라 실제 `brk` 는 `ease(0.20) = 0.104` 다.
sink 문턱이 0.10 이었으므로 「눈에 잡히는 순간」이 아니라 **막 시작한 순간**이었다.
🔑 **결과는 대개 안 뒤집힌다** — 지속음(0.4초대)이면 어택이 시작에, 감쇠가 완성에 닿아 오히려
좋은 배치가 된다. 🔴 **다만 짧은 소리(tick 0.1초대)에서 같은 혼동이 나면 진짜로 빗나간다.**
판정: `ease` 가 한 번 걸린 이름(`brk`·`fall`·`sink`·`rise`)이 `why` 에 숫자로 나오면
**그 숫자가 ease 전인지 후인지 반드시 되물어라.** 정정 요구로 내고 비용은 0(문구만).

**⑨ 🔴 「카드 전에 끝난다」는 주석·notes 가 옛 `rel` 로 계산돼 있다. (ep10s-2 재제작 실측, 2026-08-08)**
작성팀은 `카드 = 자막 시작 + rel + 0.35 − 3.0` 이라는 **맞는 식**을 적어 놓고 **옛 `rel` 을 대입**한다.
ep10s-2 `nextpeek` 은 소개 줄 `rel` 3.3초를 가정해 `linkCue` span 을 0.14 로 골랐는데,
3차 감량으로 그 줄이 20 → 14 발화자가 되어 실측 `rel` 이 **2.467초**가 됐고 — 그 식에 넣으면
**−0.183초(음수)** = **줄 전체가 카드 뒤에서 시작한다.** 이음 바는 **0프레임**이었다.
같은 파일 안에서 **주석은 span 0.20, 코드는 0.14, notes 두 칸도 서로 다른 값**을 적고 있었다.
🔑 **자막 길이를 건드린 회차는 그 샷의 cue 산수를 전부 다시 풀어야 한다** — 값을 안 바꿔도
`rel` 이 바뀌면 결론이 바뀐다(같은 편의 `stripout` split 0.5 는 가리키는 낱말이 세 번 이사했다).
🔑 **페이오프가 아니면 반려는 아니다**(작성팀이 「장식」이라 선언해 뒀으면 더욱). 정정 요구로 낸다.
판별 한 줄 = **마지막 줄 `rel < 2.65초` 면 그 줄의 화면 변화는 전부 안 보인다**
([[last-shot-outro-collision]]).

**⑩ 🔴 재제작 회차는 `build/` 산출물이 옛 판본으로 남는다. (ep10s-3 4단 재제작 실측, 2026-08-08)**

`video.mp4`·`<ep>.en.srt`·`upload.txt` 는 **이전 판본 그대로 남는다.** ep10s-3 은 timed 09:32 인데
셋 다 08:52 였고, `en.srt` 가 **7항목**(9줄이어야 함)에 마지막 자막이 삭제된 옛 줄

**⑪ 🔴 예고·미리보기가 「다음 글」을 가리키고 「다음 편」을 안 본다 — 분할이 이미 끝나 있다. (ep11s 4단 재제작 반려, 2026-08-08)**
