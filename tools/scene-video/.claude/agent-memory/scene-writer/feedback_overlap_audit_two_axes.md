**겹침 감사를 적을 때 축을 둘 다 적어라. 하나만 적으면 적은 것으로 치지 않는다.**

- **축 A — 강조색↔흰색**: 강조색이 흰 픽셀을 덮는가. 좌표 분리가 보장하는 것은
  「불투명하게 덮지 않는다」까지이고 후광(`GLOW`, 14~15px)은 경계 밖으로 더 번진다.
- **축 B — 흰색↔흰색**: 서로 다른 것을 가리키는 **흰 글자 둘이 붙어 한 덩어리로 읽히는가.**
  라벨과 그것이 가리키는 물건이 6~12px 로 붙는 것은 **의도된 쌍**이라 정상이다.
  문제는 서로 다른 것을 가리키는 둘이다.

**Why:** ep12s-1 `nextpeek` 가 축 B 로 반려됐다(2026-08-08). `WINTER LEFTOVER`(baseline 66)와
`FAIL 30`(baseline 74)이 **캔버스 간격 0.3px** 로 붙고 x 를 절반 넘게 공유해, 다음 편을 파는
유일한 화면에서 실패선 숫자가 안 읽혔다 — **노출 시간 전부**가 그 상태였다.
그때 notes 에는 *"가장 가까운 쌍이 12px"* 이라고 적혀 있었는데 그건 **축 A 만 잰 값**이라
사실상 거짓 보고였다.

🔑 **놓친 이유가 구조적이다 — 게이트가 있는 축만 쟀다.** 축 A 는 팔레트 검사가
(불완전하게나마) 보므로 늘 의식하는데, **축 B 는 어떤 게이트도 안 본다.**
**게이트가 없는 축일수록 손으로 재야 한다.**

## 🔴 잴 때 **선 반폭과 숨 진폭까지** 세라 — 안 세면 값이 1~3px 후해진다

`ctx.lineWidth = 3` 인 획은 경로에서 **양쪽으로 1.5px** 씩 번진다. 반지름이 숨 쉬는 도형
(`r + 1.5 × sin(...)`)은 **진폭만큼 더** 나간다. 이 둘을 빼먹으면 「12px 뜬다」가 실제로는
9px 이 된다.

**Why:** ep16s-1 이 1차 계산에서 둘 다 빼먹었고, 다시 재니 두 자리가 10px 아래였다
(새김 줄↔무덤 9.5px · 예고 빈 칸↔알림 줄 9px). 좌표를 6px 씩 내려 고쳤다.
🔑 **자진 신고한 값이 아니라 「충분히 뜬다」고 단언한 값에서 났다** —
[[sfx-uniqueness-is-the-arg-tuple]] 의 「단언한 쪽을 다시 센다」와 같은 자리다.

**How to apply:** 바깥 경계를 이렇게 쓴다 —
`원: cy ± (r + 숨진폭 + 1.5)` · `사각 획: y ± 1.5` · `강조색: 거기에 GLOW blur(보통 8) 더`.
kind 주석에 **산식째로** 남기면 검수가 한 줄로 재검산한다.

## 🔑 세 번째 해법 — **시간으로 가르기**(좌표를 못 벌릴 때만)

같은 자리에서 흰 것이 강조색으로 **바뀌는** 그림은 좌표를 벌릴 수가 없다. 그때는
두 알파가 **같은 프레임에 0.01 을 동시에 넘지 않는지**를 진행률로 보여라
(예: 흰 점선 알파 `g0 × (1 − alive)` / 강조 채움은 `since(1) 1.05초`부터 = `alive` 가 이미 1).
🔴 **「거의 안 겹친다」는 안 된다.** 겹치는 프레임이 **0** 임을 산수로 적어야 근거가 된다.

**How to apply:**
- kind 를 새로 쓰거나 좌표를 재배치할 때마다 **두 축의 최소 간격을 샷별로 숫자로** 적는다.
  축 B 는 「서로 다른 것끼리의 최소」와 「의도한 쌍」을 나눠 적는다.
- 같은 baseline 에 둘을 놓을 거면 **x 로 갈랐다는 것을 함께 적는다**
  (예: 좌 x14 / 우 w−14, 또는 좌측정렬 + 폭 상한).
- 붙은 것을 고칠 때는 **세로로 벌리기 + 정렬 바꾸기를 둘 다** 한다. 하나만 하면
  라벨 문자열이 길어졌을 때 다시 붙는다. 폭 상한(`fitFont` 의 max)까지 걸어야 완전하다.

## 🔴 같은 병이 `youtube.en.title` 에도 있다 — **en 자수는 게이트가 없다**

`check.mjs` 는 ko 제목만 보고 **`youtube.en.title` 의 100자 상한은 아무도 안 잰다.**
그래서 두 번 넘겼다 — `ep12s-3`, 그리고 `ep16s-2`(**101자**, 코디네이터가 손으로 잡음).

🔑 원인이 구조적이다: ko 제목은 79자쯤이라 여유가 넉넉한데 **영어는 같은 뜻이 1.2~1.3배로
불고, 꼬리(` · Unity GOAP Devlog #N-N #shorts`)만 34자**를 먹는다. ko 가 편해서 안 세게 된다.

**How to apply:**
- `en.title` 을 쓴 직후 **꼬리 34자를 먼저 빼고 본문에 66자가 남는지** 본다.
- 넘치면 **문장을 다시 쓰지 말고 가장 안 싣는 낱말 하나를 빼라.** ep16s-2 는 `so ` 를 뺐고
  (앞의 `—` 가 이미 대조를 지고 있어 뜻이 안 줄었다) 101 → **98자**가 됐다.
- 🔴 **100자 정확히로 맞추지 마라.** 여유 0 은 다음 사람이 한 글자만 손대도 다시 넘긴다.
