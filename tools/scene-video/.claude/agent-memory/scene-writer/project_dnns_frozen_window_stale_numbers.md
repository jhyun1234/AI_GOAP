**dNNs 회차를 쓸 때는 패키지가 준 수치를 화면에 올리기 전에 `devlog/sessions/<그날>.md`
**뒷부분**을 직접 읽어라. 원장 커버 범위 뒤에서 그 수가 이미 바뀌어 있을 수 있다.**

**Why:** `d01s-2`(2026-08-11) 실측. 패키지·브리프가 이 편 소유로 표시한 수치가
「시야(10) < 부화(15) < 회수(20)−배회(5)」였는데, **같은 로그 파일의 25분 뒤 커밋**
(15:03 「주민 시야 10 -> 7」)에서 사용자 판정으로 **7 / 10 / 14** 로 바뀌어 있었다.
원장 커버(`4c9b874a`, 14:40:55) 밖이라 「이 편의 원문」은 아니지만, 그대로 올렸으면
**업로드 전에 이미 틀린 수**가 화면에 박힌다. 연속극(두 달 전 글)에는 없는 위험이다 —
**신선도가 상품인 트랙은 원문도 신선해서 계속 움직인다.**

같은 자리에서 둘째 함정도 나왔다: 원문이 쓴 사슬이 **20 − 5 = 15 라 엄격 부등식이 아니었다**
(로그 717행의 원래 표기는 부등식 **둘**이고, 768행이 그걸 한 줄로 눌러 쓴 것). 패키지와
브리프가 둘 다 768행 표기를 옮겨 적어서, 그대로 화면에 올렸으면 「15 < 15」가 떴다.

**How to apply:**
- **패키지 ⑤의 커밋 범위 뒤를 grep 한다.** 그 편의 핵심 수치 낱말(반경·시야·개수)로
  같은 로그 파일을 훑어 **더 뒤에서 바뀐 적이 없는지** 본다. 30초면 끝난다.
- 바뀌었으면 **수를 버리고 「관계」를 그려라.** `d01s-2` 는 원 두 개(안쪽 = 보이는 데 /
  바깥 = 나타나는 데)로 갈음했고, 그 관계는 새 값(7 < 10 < 14−5)에서도 참이라 안 낡는다.
  🔑 **관계는 낡지 않는다. 값만 낡는다.**
- 범위 밖에서 발견한 사건은 **버리지 말고 부모에게 보고**한다 — 다음 창의 소재다
  (`d01s-2` 는 14:51 A2b 「두 달 동안 기억 상태가 존재한 적이 없었다」를 그렇게 넘겼다).
- 🔴 **브리프의 수치표를 그대로 믿지 마라.** 기획팀도 패키지도 로그를 정확히 옮겼는데
  **로그 자신이 두 곳에서 다르게 적어 두었다.** 인용할 줄 번호를 `notes` 에 남겨라.

## 🔴🔴 같은 잣대를 **화면의 문장에도** 대라 — `outro.next` 는 dNNs 마지막 편에서 **비운다**

`d01s-2` 는 반경 수치를 「곧 낡는다」는 이유로 통째로 뺐으면서, **아웃트로 카드의 문장에는
그 질문을 안 던졌다.** `engine.js:321` 이 `다음 편 · ${next}` 로 접두를 하드코딩하는데
dNNs 는 다음 편이 무엇인지 모른다(ADR-D-3 의 이유가 바로 그것이다). 게다가 미발행 대기분이
14편이라 **「다음 편 = 위험 기억」은 곧 거짓이 될 값**이었다.

작성팀(나)은 **「비우면 카드 쪽 예고를 잃는다」**며 채운 채로 판단을 올렸고, 마스터가 뒤집었다:

> **잃는 한 줄보다 낡는 한 줄이 비싸다.**

- **대가는 0** — `outro.next=""` 면 엔진이 그 줄을 안 그리고, 예고 게이트는 **음성 자막**으로
  통과한다(2안이 필요 없다). 마스터가 복제본으로 실측했다.
- 예고의 뜻은 **음성 + `nextpeek` 그림 + 라벨 「다음 항목」** 셋이 그대로 진다.
- 🔴 **`track` 으로 엔진을 분기하면 안 된다** — 같은 dNNs 라도 **중간 편**(`d01s-1`)은
  `outro.next` 가 **형제 편**을 가리켜 「다음 편」이 **참**이다. 가르는 축은 트랙이 아니라
  **`next` 가 형제 편을 가리키나 이월 항목을 가리키나**다(제안: `outro.nextKind: 'episode'|'item'`).
- 🔑 **트랙 관행**: 중간 편 = 형제 편 지시 → 「다음 편」 유지 / **마지막 편 = 이월 항목 → 비운다.**

🔑 **잣대를 한 파일 안에서 두 번 다르게 대지 마라.** 「이 값이 두 주 뒤에도 참인가」를
수치에만 묻고 문장에는 안 물으면, 정확히 그 문장에서 낡는다.

### dNNs 고유 규약 중 실제로 걸린 것 (`d01s-2` 기준)
- `outro.siblings` = **빈 배열이 정본.** 형제 라벨 게이트의 정규식
  (`^(.+) · 유니티 GOAP 개발일지 ([\d-]+편) #shorts$`)이 연속극 id 전용이라 채우면 fail.
  형제 잇기는 **blurb 문장**이 진다(`publish.mjs` 의 자동 형제 안내도 dNNs 엔 안 붙는다).
  🔑 blurb 에는 **앞 편 제목 문장을 축자로** 넣어라 — 서술만 있으면 검색으로 못 닿는다.
- 제목 꼬리는 **형제 편과 통일**하라(`d01s` 둘 = `· Claude Code로 48일차 · 유니티 GOAP 개발일지 #shorts`).
  금지된 것은 **연속극의 회차 번호 꼬리**(「N-N편」)이지 채널 색인 낱말이 아니다.
- 제목 꼬리 = **`· Claude Code로 N일차 #shorts`** (연속극 꼬리 금지). N 은 패키지 ⑤ 동결값.
- 예고는 **패키지 ④에서만 · 예정형**(「다음은, ~할 차례예요」 — `check.mjs:222` 정규식이 잡는다).
  **다음 dNNs 번호는 예고하지 않는다.** `nextpeek` = 다음 회차가 아니라 **이월 항목**의 시각화.
- 인트로 문안·4단 구조·길이 대역·낱말 규격은 **연속극과 한 글자도 다르지 않다**(§0 상속).
