**산정식은 못 믿어도, 「이미 통과한 회차와 같은 그릇」은 쓸 만하다.**

**Why:** `ep10s-1`(2026-08-07) 실측이 두 가지를 한 번에 보여 줬다.
- `check.mjs` 산정 경로 **21.3초** → 실측 파일 **26.3초**(+5.0초). 산정으로 판정했으면
  「짧으니 늘려라」로 갔을 것이고 상한을 넘겼다.
- 반면 겨냥한 그릇은 맞았다 — 승인된 `ep09s-2`(4샷 · 7줄 · **124자** · pause 1,140ms →
  실측 **26.2초**)를 그대로 겨냥해 4샷 · 7줄 · **124자** · pause 1,360ms 로 짰더니
  **26.3초**가 나왔다. 자수는 `check.mjs` 와 같은 방식으로 셌다
  (`(say).replace(/[.,?!…·「」"'\s]/g,'').length`).

**How to apply:**
- 초안 단계에서 길이를 잡을 때 **식을 세우지 말고 통과한 회차의 그릇을 골라 겨냥하라.**
  네 축을 다 맞춘다: 샷 수 · 줄 수 · 자수 · `pauseAfter` 합. 하나만 달라도 근거가 약해진다.
- 🔴 그래도 **겨냥은 예측이지 판정이 아니다.** 정본은 `tts.mjs` → `check.mjs` 출력 하나뿐이고
  `notes.길이` 는 그 줄을 **인용**하는 자리다.
- ⚠️ 그릇이 맞아도 **여유는 얇을 수 있다.** ep10s-1 은 상한까지 1.7초인데 본문 하한(20초)
  까지는 **0.8초**뿐이었다 — 그 뒤로 자막을 한 줄만 빼도 반대쪽 게이트가 켜진다.
- 그릇 목록은 [[video-25s-budget]] 의 「실측으로 통과한 그릇」 표에 이어서 적는다.

## 🔴 실측 표를 받으면 `dur` 이 아니라 `rel` 을 집는다 — 그리고 **행을 잘못 집지 마라**

`cue(i)` 창은 `s.rel[i]` 를 쓰고 `rel = durOf(...) + (pauseAfter ?? 0)`(`engine.js:163`).
그래서 `sfx.delayMs` 를 다시 풀 때 필요한 값은 **그 `sfx.at` 이 가리키는 줄의 `rel`** 이다.

**Why:** ep10s-1 에서 코디네이터가 전달한 지시가 「S1[0] 의 rel 3,837 로 확정하라」였는데
해당 `sfx` 는 `at = 1` 이었다(맞는 값은 S1[1] 의 **3,485**). 그대로 따랐으면 90ms 어긋났다.
같은 회차에서 척도 혼동(`dur` ↔ `rel`)은 이미 두 회차 연속 사고였다.

**How to apply:** 새 `delayMs` 를 낼 때 `why` 에 **어느 줄의 rel 을 썼는지 숫자로 적어라.**
그러면 지표가 틀렸을 때 다음 사람이 바로 본다. 초안(예상 rel) 값은 실측에서 늘 **늦는
쪽으로** 틀렸다 — ep10s-1 은 두 소리가 각각 0.21초 · 0.26초 늦어 목표 낱말을 지나쳤다.
