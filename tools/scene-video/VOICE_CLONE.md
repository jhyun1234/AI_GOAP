# 내 목소리를 Supertonic 목소리로 — 실행 절차

쇼츠 나레이션을 프리셋(M3) 대신 **사용자 본인 음색**으로 바꾸기 위한 절차.
결과물은 `voice_styles/` 에 들어가는 JSON 한 개다.

> ✅ **2026-08-02 제작 전환 완료.** `voice.json` → `voice: "ME"`, `speed: 1.1`.
> 쇼츠 나레이션은 이제 사용자 본인 목소리로 나간다. 되돌리려면 그 두 값만 `"M3"`, `1.0` 으로.

조사·확인 일자: 2026-08-02

---

## 0. 왜 이 방법인가

Supertone 공식 **Voice Builder 는 이미 닫혔다.** 2026-07-23 부터 신규 가입·구매 중단,
2026-08-31 서비스 종료, 리포도 아카이브 예정. 오픈웨이트에는 화자 인코더가 들어 있지 않다
(`vendor/assets/onnx/` 에 text_encoder·duration_predictor·vector_estimator·vocoder 넷뿐).

그래서 **문제를 뒤집는다.** `음성 → 임베딩` 함수는 없지만 `임베딩 → 음성` 은 우리가 이미
갖고 있으므로, 모델을 통째로 얼려 두고 임베딩 숫자만 변수로 두어 경사하강으로 깎는다.

```
매 스텝:  임베딩 → (얼린 Supertonic) → 합성 음성
          합성 음성 ─┐
                     ├→ ECAPA 화자 임베딩 코사인 거리 = 손실
          내 녹음   ─┘
          손실을 임베딩으로 역전파해서 임베딩만 갱신
```

도구: [saurabhv749/supertonic3-voice-clone](https://github.com/saurabhv749/supertonic3-voice-clone) (MIT).
원저자는 kdrkdrkdr, Zenodo DOI `10.5281/zenodo.19646514`.

> ⚠️ 비슷한 도구인 `kdrkdrkdr/supertonic.embed` 는 **Supertonic 2 용이라 쓸 수 없다.**
> 우리 자산은 3 이다(`vendor/assets/config.json` → `"model_name": "Supertonic 3"`).
> 버전이 다르면 임베딩 공간 자체가 달라서 JSON 이 안 꽂힌다.

## 1. 🔴 무엇이 옮겨오고 무엇이 안 옮겨오는가

코드를 읽고 확정한 것이다. 기대치를 여기 맞춰야 한다.

| | 옮겨오나 | 근거 |
|---|---|---|
| **음색** (누구 목소리인지) | ✅ | `style_ttl` 12,800개를 최적화한다 |
| 말의 리듬·길이 | ❌ | `style_dp` 128개는 **얼려 둔다** (`train_style.py:142`) |
| 억양·감정·강조 | ❌ | 손실이 화자 동일성뿐이다 (`utils/loss.py:97` = `1 - cos`) |

즉 **"내 음색으로 말하는 Supertonic"** 이 나온다. 내 말투가 아니다.
리포 README 도 같은 말을 한다 — *"loss function prioritizes identity over prosody"*.

따라서 `voice.json` 의 발화 규칙 8종(어미 섞기·한 호흡 한 문장·담화표지·호흡 배치)은
**그대로 계속 유효하다.** 낭독조를 막는 일은 여전히 대본이 한다.

### 따라오는 결론 두 개

- **전사본이 필요 없다.** 손실이 텍스트와 무관하다. 학습에 쓰는 문장은 `configs/utterances.py`
  에 박혀 있는 별개의 것이고, 내 녹음이 무슨 말인지는 전혀 안 본다.
- **녹음 내용은 거의 상관없다.** 대본을 읽든 아무 말이나 하든 결과가 비슷하다.
  다만 평소 나레이션 톤으로 말하는 편이 음색 분포가 실전과 맞아 안전하다.

## 2. 녹음 규격 (사용자가 할 일)

| 항목 | 기준 | 이유 |
|---|---|---|
| 길이 | **90초 안팎** | 아래 "길수록 좋지 않다" 참조 |
| 포맷 | WAV / 44.1kHz / 모노 | 스크립트가 16kHz 모노로 알아서 내리지만, 원본은 좋을수록 낫다 |
| 후처리 | **전부 끄기** — 노이즈 제거·컴프레서·EQ·리버브 | 후처리 흔적이 "내 음색"으로 학습된다 |
| 무음 | 앞뒤 및 긴 공백은 잘라낸다 | ECAPA 가 무음까지 평균 내서 임베딩이 흐려진다 |
| 환경 | 조용한 방, 반사 적은 곳 | 잔향은 임베딩에 그대로 박히고 되돌릴 수 없다 |
| 거리 | 입에서 15~20cm, 마이크를 살짝 비스듬히 | 파열음 방지 |
| 톤 | 한 테이크 내내 일정하게 | 톤이 섞이면 평균이 나서 흐려진다 |

### 🔴 길수록 좋지 않다

직관과 반대라 적어 둔다. **녹음은 학습 데이터가 아니라 과녁 하나다.**

```python
self.emb_original = self.embed_audio(target_wav_path)   # 초기화 때 한 번뿐
```

파일 전체가 ECAPA 를 통과해 **192차원 벡터 하나로 뭉개지고**, 학습 3000스텝은 그 벡터 하나만 본다.
1분을 넣든 10분을 넣든 과녁은 똑같이 숫자 192개다. 길게 읽어도 **정보가 느는 게 아니라
평균 낼 재료만 는다.**

그리고 평균이라서 길어지면 손해다 — 목이 지치고 마이크 거리가 흔들리면 그 흔들림이 평균에
섞이는데, 파일이 하나라 골라낼 수가 없다. 화자 인증 모델은 원래 3~10초로 쓴다.
**90초면 이미 포화**고 그 위로는 곡선이 눕는다.

### 그래서 회차별로 나눠 뜬다

우리 회차 길이가 마침 규격에 들어맞는다(`build/timed.json` 실측):

| 회차 | 실측 길이 | 줄 수 |
|---|---|---|
| ep00s | 91초 | 27 |
| ep01s | 106초 | 33 |
| ep02s | 91초 | 30 |

**회차 하나 = 테이크 하나**로 뜨면 90초 규격에 정확히 맞고, 후보 3개가 생겨 골라 쓸 수 있다.
학습이 6~30분이라 각각 돌려 `best_loss` 를 비교하고 귀로 고르면 된다.
긴 파일 하나는 나쁜 구간을 못 버리고, 나눠 두면 버릴 수 있다 — 이게 전부다.

낭독용 원고는 `voices/*.txt` 로 뽑아 뒀다(대본의 `say` 만 추출).
저장 위치는 `voices/ep00s.wav`, `voices/ep01s.wav`, `voices/ep02s.wav`. 리포에 커밋하지 않는다(5장).

### 🔴 녹음 검수 — 학습 전에 반드시 (2026-08-02 실측)

GPU 30분을 태우기 전에 계측한다. 첫 녹음에서 실제로 두 가지가 걸렸다.

| 항목 | 첫 녹음 실측 | 기준 | 판정 |
|---|---|---|---|
| 피크 레벨 | -21 ~ -24 dBFS | **-5.7 dBFS** | ❌ 20dB 낮음 |
| 무음 비율 | 31~37% (구간 38~48개) | 최소 | ❌ 임베딩이 흐려진다 |
| 클리핑 | 없음 | 없음 | ✅ |
| 험·DC 오프셋 | 없음 / 0 | 없음 | ✅ |
| 고역 | 16~17kHz까지 자연 감쇠 | 구멍·절벽 없을 것 | ✅ |

**피크 기준 -5.7 dBFS 의 근거**: 우리 Supertonic 출력이 전 회차 일관되게 피크 -5.7dB / 평균 -25.6dB 다
(`episodes/*/build/full.wav` 실측). 손실이 내 녹음 임베딩과 **합성 결과 임베딩**을 비교하므로
둘의 레벨을 맞춰야 계통 오차가 안 생긴다.

스펙트로그램도 한 번 본다(`showspectrumpic`). 말 사이가 완전한 검정이면 무음 게이트인데,
어차피 잘라낼 구간이라 무해하다. 반면 **말하는 중에** 고역이 잘리거나 구멍이 나 있으면
스펙트럼 노이즈 제거가 걸린 것이고, 그건 음색을 바꾸므로 재녹음해야 한다.

보정은 순수 게인과 무음 제거뿐이다 — **컴프레서·EQ 는 쓰지 않는다**(음색이 바뀐다).

```bash
ffmpeg -i raw/원본.wav -af "silenceremove=stop_periods=-1:stop_duration=0.1:stop_threshold=-50dB,aformat=channel_layouts=mono,volume=18.6dB" -ar 44100 -c:a pcm_s16le ep00s.wav
```

게인 값은 파일마다 `-5.7 - (측정 피크)` 로 계산한다. 원본은 `voices/raw/` 에 남긴다.

### 결과가 아쉬울 때 만질 것

음색이 안 닮았으면 녹음을 다시 뜨는 게 맞다. 하지만 **"닮았는데 어색하다"면 녹음 문제가 아니다** —
아래가 손잡이고, 이때 더 길게 읽어봐야 안 바뀐다.

| 손잡이 | 무엇이 바뀌나 |
|---|---|
| `--gender M` / `F` | 얼려 둘 `style_dp` = **최종 말 리듬**을 고른다. 음색과 무관하게 인상이 꽤 달라진다 |
| `--reference-style` | 출발점 프리셋. `auto` 가 고른 결과를 로그에서 확인해 둔다 |
| `--seed` | 수렴 지점이 달라진다 |

mp3·m4a 로 녹음됐으면 변환한다(ffmpeg 은 이미 깔려 있다):

```bash
ffmpeg -i 원본.m4a -ac 1 -ar 44100 -c:a pcm_s16le tools/scene-video/voices/anjyo.wav
```

## 4. 절차

작업 위치는 리포 밖(스크래치패드나 임의 폴더). 게임 리포를 오염시키지 않는다.

```bash
git clone --depth 1 https://github.com/saurabhv749/supertonic3-voice-clone.git
cd supertonic3-voice-clone
```

**① 자산을 새로 받지 말고 우리 것을 쓴다** — 스크립트는 `supertonic3/onnx`, `supertonic3/voice_styles` 를 본다.

```bash
cp -r /c/Users/anjyo/AI_GOAP/tools/scene-video/vendor/assets ./supertonic3
```

**② torch 를 CUDA 빌드로 먼저 깔고, 나머지를 깐다**

```bash
py -m pip install torch==2.9.1 torchaudio==2.9.1 torchvision==0.24.1 --index-url https://download.pytorch.org/whl/cu128
```

```bash
py -m pip install onnxruntime onnx onnx2torch onnxslim numpy soundfile librosa transformers speechbrain
```

**③ GPU 를 실제로 잡았는지 확인한다** — 여기서 `True` 가 안 나오면 아래 단계는 무의미하다

```bash
py -c "import torch; print(torch.cuda.is_available(), torch.cuda.get_device_name(0) if torch.cuda.is_available() else '')"
```

**④ 학습 문장을 한국어로 바꾼다** — `configs/utterances.py` 의 16줄이 전부 영어 애니메이션 명대사다.
손실 자체는 언어와 무관하지만, 우리가 합성할 언어로 최적화하는 편이 안전하다.
`[lang, text]` 형식이므로 아래로 갈아끼운다(우리 회차 대본에서 뽑은 실제 문장).

```python
# [lang, text]
texts = [
    ["ko", "콘솔을 열어봤더니, 원인이 한 칸에 몰려 있더라고요."],
    ["ko", "길도, 자원도 아니었어요. 셋 다 계획을 못 짠 거였죠."],
    ["ko", "후보를 사천 구십육 개 뒤졌거든요. 그러고도 못 찾았어요."],
    ["ko", "이런 걸 저희끼린 무해라고 불러요. 한자 그대로, 풀이가 없다는 뜻이에요."],
    ["ko", "탐험하고, 세 번 캐면 끝. 딱 네 단계예요."],
    ["ko", "사천 구십육 번을 뒤지고도, 이 네 칸을 못 찾은 거예요."],
    ["ko", "성격은 대사랑 행동 비용을 정하는데요, 리크루팅을 거친 주민한테만 붙거든요."],
    ["ko", "씬에 직접 놓은 셋은 그 경로를 안 지나요."],
    ["ko", "그래서 어웨이크에 한 줄 넣었어요. 비어 있으면, 여섯 종 중에 랜덤으로."],
    ["ko", "그리고 플레이 모드를 다시 켰더니, 그 대사가 그제야 뜨더라고요."],
    ["ko", "다른 게이지는 다 높을수록 좋아요. 근데 허기만, 높을수록 배고픔이에요."],
    ["ko", "그래서 이름을 뒤집었어요. 허기가 아니라, 포만감."],
]
```

**⑤ 돌린다** (6~30분)

```bash
py train_style.py --name anjyo --gender M --target-wav-path voices/anjyo.wav --reference-style auto --num-steps 3000
```

- `--reference-style auto` 는 프리셋 10종 중 내 목소리와 제일 가까운 것을 먼저 찾아 거기서 출발한다.
  랜덤 초기화(`none`)보다 훨씬 빨리 수렴한다. 시작 지점 로그를 남겨 둘 것.
- `--gender M` 은 초기 `style_dp`(리듬) 선택에 쓰인다. 이게 곧 **최종 말 리듬**이므로
  결과 리듬이 마음에 안 들면 `F` 로도 한 번 뽑아 비교해 볼 가치가 있다.
- 손실이 `0.015` 이하로 떨어지면 조기 종료한다. 500스텝마다 체크포인트가 남는다.

산출: `logs/anjyo/anjyo.json`

## 5. 붙이기

출력 JSON 은 우리가 읽는 형식과 **완전히 같다** — `style_ttl{data,dims:[1,50,256]}` +
`style_dp{data,dims:[1,8,16]}` + `metadata` (`utils/style.py` 확인함). 변환이 필요 없다.

1. `logs/<name>/<name>_0500.json` → `tools/scene-video/voice_styles/ME.json`
   (**`vendor/` 안이 아니다** — 아래 커밋 정책 참조)
2. `voice.json` → `engine.voice` 를 `"ME"` 로, `engine.speed` 를 재보정값으로

캐시는 안전하다. `tts.mjs` 의 해시 키가 `voiceName` 을 포함하므로(`tts.mjs:46`) 목소리를 바꾸면
전 회차가 자동으로 재합성된다. 옛 wav 는 참조되지 않고 남으므로 `episodes/*/build/audio/` 를 비워도 된다.

### 커밋 정책

- ❌ `voices/anjyo.wav` — **커밋하지 않는다.** 리포가 PUBLIC 이다. 생목소리 원본을 공개
  저장소에 올리면 누구나 같은 방법으로 복제할 수 있다. `.gitignore` 에 `voices/` 를 넣어 뒀고,
  원본은 로컬에 따로 보관한다.

- ❌ `voice_styles/ME.json` — **커밋하지 않는다.** (283KB)
  🔴 **2026-08-02 개정 — 하루 만에 뒤집힌 결정이다.**

  처음엔 ✅ 커밋으로 정했다. 근거는 *"녹음 원본이 비공개라 리포만 보고는 재현할 수 없고,
  날리면 GPU 30분을 다시 태워야 한다"* 였고, 경계를 **`vendor/` = 남의 것(무시) /
  `voice_styles/` = 우리 것(추적)** 으로 그었다.

  🔑 **그 판단은 "위험한 건 생녹음뿐"이라고 본 것이었다.** 그런데 임베딩도 본인 음색이고
  **이걸로 임의의 문장을 합성할 수 있다.** 리포가 PUBLIC 이라는 사실은 `voices/` 를 뺄 때
  이미 알고 있었는데, 같은 이유가 이 파일에도 걸린다는 걸 그때는 안 이었다.

### 🔴 손실은 품질이 아니다 — 500스텝이 이겼다

체크포인트별로 합성해 출력 피크를 재면 **학습이 진행될수록 계속 커진다.**

| 스텝 | 출력 피크 | |
|---|---|---|
| 500 | -5.70 dBFS | 깨끗 |
| 1000 | -2.86 | 깨끗 |
| 1500 | +0.08 | ⚠️ 클리핑 |
| 2500 | +1.65 | ⚠️ 클리핑 |
| 3000 | +1.21 | ⚠️ 클리핑 (43샘플, flat factor 11.5) |

임베딩 공간에 음량 제약이 없어서 **옵티마이저가 음색뿐 아니라 음량으로도 손실을 줄인다.**
그래서 loss 0.0173 이 loss 0.046 보다 더 닮았다는 보장이 없다 — 일부는 음량 일치분이다.

사용자 청취 판정도 같았다: **M3 / 500 / 1000 / 3000 을 -6dB 로 음량 정렬해 비교한 결과 500스텝 채택.**
계측(클리핑 없는 유일한 지점)과 귀가 일치했다.

**교훈: 이 도구에서 `--num-steps` 를 올리는 것은 개선이 아니다.** 다음에 돌릴 때도
`--save-steps` 를 작게 잡아 초반 체크포인트를 확보하고, 반드시 음량을 맞춰 비교한다.

### 실사용 실측 (ep01s 대본 33줄 전체)

| | 말 속도(발화만) | 피크 | 클리핑 |
|---|---|---|---|
| M3 @ speed 1.00 | 6.72자/초 | -6.23 dBFS | 0 |
| ME @ speed 1.00 | 6.15자/초 | -4.77 dBFS | 0 |
| ME @ speed 1.05 | 6.46자/초 | -6.14 dBFS | 0 |

채택본(500스텝)은 전 구간 클리핑이 없으므로 **출력 게인 조정은 필요 없다.**

> ⚠️ 관측 (미처리): `voice.json` 의 `speed_실측` 표는 **발화만** 기준인데
> `tts.mjs:112` 는 **쉼 포함** 수치를 찍으면서 참고 영상 6.93 과 나란히 보여준다.
> 두 지표가 섞여 있다. ME @ 1.10 은 발화만 6.77 / 쉼 포함 6.28 이다.

### 밟은 지뢰 3건

1. `requirements.txt` 에 **`httpx` 가 빠져 있다** — `utils/model.py:9` 가 import 한다.
2. **torchaudio 2.9 의 `load` 는 torchcodec 을 요구하는데 Windows 휠이 없다.**
   `utils/loss.py` 의 `load_audio_16khz_mono` 를 `soundfile` 로 읽도록 고쳤다(모노화·리샘플은 원본 그대로).
3. **`print("✅ ...")` 가 cp949 콘솔에서 죽는다.** 코드를 고치지 말고
