# 내 목소리로 TTS 만들기 — 처음부터 끝까지

**아무것도 없는 상태에서 시작해 "내 목소리로 아무 문장이나 읽어주는 프로그램"까지** 가는 절차다.
전부 내 컴퓨터에서 돌아간다. 서버도, 구독료도, 월 사용량 제한도 없다.

실제로 이 절차를 밟아 완주한 기록을 정리한 것이다. 중간에 밟은 함정까지 다 적었다.
막히는 자리는 대부분 여기 이미 적혀 있다.

## 🔴 0. 읽자마자 먼저 할 일 — 이건 시한부다

Supertone(수퍼톤)은 **2026-07-23 부로 이 모델의 지원을 끝냈다.** 공식 공지 요약:

설치하기 전에, 녹음하기 전에, **모델부터 받아서 딴 데 복사해 둔다.** 382MB다.

> 이미 못 받는 상태라면 이 문서는 여기서 끝이다. 대안은 다른 오픈 TTS(예: XTTS, F5-TTS)를

## 1. 이 방법이 만들어 주는 것과, 만들어 주지 않는 것

여기서 기대치를 맞추고 가야 나중에 실망하지 않는다. **코드를 직접 읽고 확인한 내용이다.**

| | 옮겨오나 | 왜 |
|---|---|---|
| **음색** — 누구 목소리로 들리는가 | ✅ | 이 숫자 뭉치(12,800개)를 최적화한다 |
| 말의 리듬·속도감 | ❌ | 리듬 담당 숫자(128개)는 **얼려 둔 채로 건드리지 않는다** |
| 억양·감정·강조·말버릇 | ❌ | 학습 목표가 "같은 사람인가" 하나뿐이다 |

즉 결과물은 **"내 음색으로 말하는 기계"** 다. **"나처럼 말하는 기계"가 아니다.**
내가 웃으면서 말해도, 화내면서 말해도, 결과는 똑같이 차분한 낭독조로 나온다.

이걸 미리 알아야 하는 이유: 결과가 밋밋하게 느껴질 때 **녹음을 다시 뜨는 건 헛수고다.**
말투는 녹음에서 오는 게 아니라 **읽히는 문장 자체**에서 온다. 자연스럽게 들리게 하려면
대본을 구어체로 쓰는 게 답이지 녹음을 더 잘하는 게 답이 아니다.

### 따라오는 결론 두 개 (아마 예상과 다를 것이다)

- **녹음을 글로 옮겨 적을(전사) 필요가 전혀 없다.** 학습은 내 녹음이 무슨 말인지 아예 안 본다.
- **무슨 말을 녹음하든 거의 상관없다.** 아무 말이나 해도 된다. 다만 평소 톤으로 말하는 게
  실전과 맞아서 안전하다.

## 3. 왜 이렇게 복잡한 방법을 쓰나 (건너뛰어도 됨)

궁금하지 않으면 4장으로 가도 된다. 다만 이걸 알면 나중에 문제가 생겼을 때 훨씬 잘 대처한다.

보통 목소리 복제는 `내 녹음 → (분석기) → 목소리 숫자` 로 한다. 그런데 **수퍼톤은 그 분석기를
공개하지 않았다.** 공식 서비스(Voice Builder)가 그 역할을 했는데 그게 문을 닫았다.

그래서 **문제를 거꾸로 푼다.** `숫자 → 음성` 방향은 우리가 이미 갖고 있으니까:

```
숫자를 아무렇게나 하나 찍는다
  → 그 숫자로 음성을 만든다
  → 만든 음성이 내 목소리와 얼마나 닮았는지 점수를 낸다
  → 점수가 나아지는 쪽으로 숫자를 아주 조금 민다
  → 이걸 3000번 반복한다
```

닮은 정도를 재는 자는 **ECAPA** 라는 별개의 화자 인식 모델이 맡는다(성문 대조에 쓰는 것과
같은 부류다). 점수는 딱 하나, "이 둘이 같은 사람인가". 그래서 1장의 표처럼
**음색만 따라오고 말투는 안 따라온다.**

## 4. 도구 설치

### ① 클론 도구 받기

```bash
git clone https://github.com/saurabhv749/supertonic3-voice-clone.git
cd supertonic3-voice-clone
```

### ② 0장에서 받은 모델을 이 안에 넣는다

도구는 `supertonic3/onnx`, `supertonic3/voice_styles` 경로를 본다.
0장에서 받은 폴더를 그 이름 그대로 이 폴더 안에 두면 된다.

```
supertonic3-voice-clone/
├── train_style.py
├── supertonic3/          ← 0장에서 받은 것
│   ├── onnx/
│   └── voice_styles/
└── voices/               ← 녹음을 여기에 둔다
```

> ⚠️ `setup.sh` 가 모델을 자동으로 받아주긴 하는데, 아래 ③의 문제가 있으니
> **`setup.sh` 는 쓰지 말고 손으로 하는 걸 권한다.**

### ③ 🔴 torch 는 반드시 따로, 먼저 깐다

**여기서 제일 많이 망한다.** `requirements.txt` 를 그냥 설치하면 Windows 에서는
**GPU 를 못 쓰는 버전**이 깔린다. 그런데 스크립트는 에러를 내지 않고 조용히 CPU 로 떨어져서,
30분이면 끝날 게 몇 시간이 된다. **끝날 때까지 뭐가 잘못됐는지 모른다.**

[pytorch.org](https://pytorch.org/get-started/locally/) 에서 본인 GPU 에 맞는 설치 명령을
받아서 **먼저** 실행한다. 예시(RTX 50 시리즈 기준):

```bash
pip install torch==2.9.1 torchaudio==2.9.1 torchvision==0.24.1 --index-url https://download.pytorch.org/whl/cu128
```

> GPU 세대별로 필요한 CUDA 버전이 다르다. RTX 50 시리즈는 cu128 이상이 필요하고,
> 30·40 시리즈는 cu121/cu124 로도 된다. 모르겠으면 pytorch.org 가 골라준다.

### ④ 나머지를 깐다 — 목록을 그대로 쓰지 않는다

```bash
pip install onnxruntime onnx onnx2torch onnxslim numpy soundfile librosa transformers speechbrain httpx
```

두 가지가 원본 `requirements.txt` 와 다르다. **둘 다 실제로 밟은 지뢰다.**

- **`httpx` 를 추가했다** — 코드가 쓰는데 목록에서 빠져 있다. 없으면 실행하자마자 죽는다.
- **`torchcodec` 을 뺐다** — Windows 용이 아예 없다. 대신 ⑤에서 코드를 한 줄 고친다.

### ⑤ 🔴 코드 한 곳을 고친다 (Windows 필수)

`utils/loss.py` 를 연다. 맨 위 `import` 줄 아래에 한 줄 추가:

```python
import soundfile
```

그리고 `load_audio_16khz_mono` 함수 안의 이 줄을 찾아서:

```python
    signal, _ = torchaudio.load(file_path)
```

이렇게 바꾼다:

```python
    data, _ = soundfile.read(file_path, dtype="float32", always_2d=True)
    signal = torch.from_numpy(data.T)  # (ch, T)
```

> 이유: `torchaudio` 최신 버전의 오디오 읽기가 `torchcodec` 이라는 별도 부품을 요구하는데
> Windows 용이 없다. 읽는 방법만 바꾸고 나머지 처리는 원본 그대로 둔다.
> **macOS·Linux 는 이 단계를 건너뛰어도 된다.**

### ⑥ GPU 를 실제로 잡았는지 확인한다 — 건너뛰지 말 것

```bash
python -c "import torch; print(torch.cuda.is_available())"
```

**`True` 가 안 나오면 여기서 멈추고 ③으로 돌아간다.** `False` 인 채로 진행하면
학습이 몇 시간 걸리고, 다 끝나고 나서야 알게 된다.

## 5. 녹음하기

### 규격

| 항목 | 기준 | 왜 |
|---|---|---|
| **길이** | **90초 안팎** | 길수록 좋지 **않다**. 아래 참조 |
| 포맷 | WAV / 44.1kHz / 모노 | 폰으로 찍었으면 아래 명령으로 변환 |
| **후처리** | **전부 끈다** — 노이즈 제거·EQ·컴프레서·리버브 | 후처리 흔적까지 "내 목소리"로 학습된다 |
| 환경 | 조용하고 울림 적은 곳 | 울림은 그대로 박히고 나중에 못 뺀다 |
| 거리 | 입에서 15~20cm, 마이크를 살짝 비스듬히 | 파열음(ㅍ, ㅂ) 튀는 것 방지 |
| 톤 | 처음부터 끝까지 일정하게 | 섞이면 평균이 나서 흐려진다 |
| 내용 | **아무거나.** 평소 말투면 된다 | 무슨 말인지는 안 본다(1장) |

> 🔴 **노이즈 제거를 끄라는 게 제일 중요하다.** 요즘 마이크·회의 앱은 기본으로 켜져 있는
> 경우가 많다. 그게 켜져 있으면 목소리의 고음 부분이 깎이는데, **그 깎인 소리가 곧
> "내 목소리"로 학습된다.** 결과가 먹먹하게 나오는 원인 1번이다.

### 🔴 길게 녹음해봐야 소용없다

직관과 반대라 따로 적는다. **녹음은 학습 데이터가 아니라 과녁 하나다.**

파일 전체가 분석기를 한 번 통과해서 **숫자 192개짜리 요약본 하나로 뭉개지고**, 이후
3000번의 학습은 그 요약본만 본다. 1분을 넣든 10분을 넣든 **과녁은 똑같이 숫자 192개다.**

게다가 그게 평균이라 길면 손해다. 오래 읽으면 목이 지치고 마이크 거리가 흔들리는데,
그 흔들림이 평균에 섞이고 파일이 하나라 골라낼 수가 없다.
화자 인식 모델은 원래 3~10초로 쓰는 물건이다. **90초면 이미 충분하고 그 위로는 의미가 없다.**

### 그래서 이렇게 한다 — 90초짜리 3개

한 번에 5분 읽지 말고 **90초씩 따로 3개를 뜬다.** 그러면 셋 다 학습을 돌려보고
제일 나은 걸 고를 수 있다. 하나가 망해도 나머지가 있다. 긴 파일 하나는 나쁜 구간이 섞여도
버릴 수가 없다.

### 폰으로 녹음했다면

```bash
ffmpeg -i 원본.m4a -ac 1 -ar 44100 -c:a pcm_s16le voices/myvoice.wav
```

### 🔴 학습 전에 녹음을 검사한다 — GPU 30분 태우기 전에

첫 녹음에서 실제로 두 개가 걸렸다. **눈으로 봐선 모르고 재봐야 안다.**

| 항목 | 기준 | 첫 녹음 실측 |
|---|---|---|
| **피크 레벨** | **-6 dBFS 근처** | -21 ~ -24 dBFS ❌ **20dB 나 작았다** |
| **무음 비율** | 최소한으로 | 31~37% ❌ |
| 클리핑(찌그러짐) | 없을 것 | 없음 ✅ |

재는 법:

```bash
ffmpeg -i voices/myvoice.wav -af volumedetect -f null -
```

`max_volume` 이 나온다. **`-6 dBFS` 를 목표로 한다.**

> **왜 하필 -6인가:** 이 모델이 만들어내는 음성이 항상 그 정도 크기로 나온다.
> 학습은 "내 녹음"과 "만들어진 음성"을 비교하는데, 둘의 크기가 다르면 그 차이까지
> 목소리 차이로 착각한다. 그래서 미리 맞춰 준다.

**무음이 왜 문제인가:** 말 사이의 침묵까지 전부 평균에 들어가서 "내 목소리" 요약본이
흐려진다. 잘라내야 한다.

### 보정 — 크기 맞추기 + 무음 잘라내기, 그게 전부

```bash
ffmpeg -i voices/myvoice.wav -af "silenceremove=stop_periods=-1:stop_duration=0.1:stop_threshold=-50dB,aformat=channel_layouts=mono,volume=15dB" -ar 44100 -c:a pcm_s16le voices/myvoice_fixed.wav
```

`volume=15dB` 자리에는 **`-6 빼기 (측정한 피크)`** 를 넣는다.
예: 측정값이 -21 이면 → `-6 - (-21) = 15` → `volume=15dB`.

보정 후 다시 재서 -6 근처인지 확인한다. **원본은 지우지 말고 남겨 둔다.**

> ⚠️ **컴프레서와 EQ 는 쓰지 마라.** 크기 조절과 무음 제거만 해야 한다.
> 나머지는 전부 음색을 바꾼다 = 내 목소리가 아니게 된다.

## 6. 학습 문장을 내 언어로 바꾼다

`configs/utterances.py` 를 연다. 기본값이 **영어 문장 16개**로 되어 있다.
한국어 목소리를 만들 거면 한국어로 갈아끼운다.

```python
# [lang, text]
texts = [
    ["ko", "오늘은 날씨가 좋아서 잠깐 걷다 왔어요."],
    ["ko", "이게 생각보다 오래 걸리더라고요."],
    ["ko", "그래서 처음부터 다시 해봤습니다."],
    # ... 10~15개 정도
]
```

평소에 말할 법한 **구어체 문장**을 넣는 게 좋다. 언어 코드는 `ko`, `en`, `ja` 등
31개 언어를 지원한다.

> 엄밀히 말하면 학습 자체는 언어와 무관하다. 그래도 **실제로 쓸 언어로 맞춰 두는 게 안전하다.**

## 7. 돌린다

```bash
python train_style.py --name myvoice --gender M --target-wav-path voices/myvoice_fixed.wav --reference-style auto --num-steps 3000
```

| 옵션 | 뜻 |
|---|---|
| `--name` | 결과물 이름. `logs/myvoice/` 에 저장된다 |
| `--gender` | `M` 또는 `F`. **말의 리듬**을 고른다(음색 아님). 결과가 어색하면 반대쪽도 해볼 것 |
| `--target-wav-path` | 5장에서 만든 보정본 |
| `--reference-style auto` | 기본 목소리 10개 중 나와 제일 가까운 것에서 출발한다. 훨씬 빨리 수렴한다 |
| `--num-steps 3000` | 반복 횟수. **더 키우지 마라** (8장) |

Windows 에서 한글이 깨지며 죽으면 이렇게 실행한다:

```bash
set PYTHONUTF8=1 && set PYTHONIOENCODING=utf-8 && python train_style.py --name myvoice --gender M --target-wav-path voices/myvoice_fixed.wav --reference-style auto --num-steps 3000
```

**6~30분** 걸린다. 500스텝마다 중간 결과가 저장된다.

진행되면서 `loss` 숫자가 줄어든다. 참고용 실측값:

```
출발점 자동 선택 : M4.json (loss 0.6009)
3000스텝 후     : 0.0173  (20.9분, RTX 5060 Ti)
```

결과물은 `logs/myvoice/` 에 쌓인다:

```
myvoice_0500.json  myvoice_1000.json  myvoice_1500.json
myvoice_2000.json  myvoice_2500.json  myvoice_3000.json  myvoice.json
```

> 📌 **쓴 명령어를 메모해 둬라.** 특히 `--seed`(기본값 49)와 `--gender`.
> 같은 값으로 다시 돌리면 같은 결과가 나오므로, 파일을 잃어도 되살릴 수 있다.

## 8. 🔴 제일 중요한 단계 — 마지막 결과를 쓰면 안 된다

**loss 가 낮다고 좋은 게 아니다.** 이걸 모르면 애써 만든 게 찌그러진 소리로 나온다.

체크포인트별로 소리를 만들어 크기를 재보면 **학습이 진행될수록 계속 커진다.**

| 스텝 | 출력 크기 | |
|---|---|---|
| **500** | **-5.70 dBFS** | ✅ 깨끗 |
| 1000 | -2.86 | ✅ 깨끗 |
| 1500 | +0.08 | ⚠️ **찌그러짐(클리핑)** |
| 2500 | +1.65 | ⚠️ 찌그러짐 |
| 3000 | +1.21 | ⚠️ 찌그러짐 |

**왜 이렇게 되나:** 학습에 "너무 커지면 안 된다"는 제약이 없다. 그래서 최적화가
음색뿐 아니라 **소리를 키워서도 점수를 올린다.** loss 0.017 이 loss 0.046 보다
더 닮았다는 보장이 없다 — 일부는 그냥 "더 커진 것"이다.

실제 청취 비교에서도 **500스텝이 이겼다.** 계측과 귀가 일치했다.

### 그래서 반드시 이렇게 한다

체크포인트마다 같은 문장을 만들어서 **직접 들어보고 고른다.**

```bash
python generate.py --style logs/myvoice/myvoice_0500.json --text "안녕하세요, 테스트 문장입니다." --lang ko
python generate.py --style logs/myvoice/myvoice_1000.json --text "안녕하세요, 테스트 문장입니다." --lang ko
python generate.py --style logs/myvoice/myvoice_3000.json --text "안녕하세요, 테스트 문장입니다." --lang ko
```

`samples/` 폴더에 생긴다.

> 🔴 **비교할 때 반드시 볼륨을 맞추고 들어라.** 사람 귀는 큰 소리를 무조건 좋게 듣는다.
> 볼륨을 안 맞추면 **제일 찌그러진 걸 제일 좋다고 고르게 된다.**
> 오디오 편집기에서 전부 같은 크기로 맞춘 뒤 비교한다.

**대개 500 또는 1000 이 답이다.** 고른 파일을 알아보기 쉬운 이름으로 복사해 둔다.

```bash
cp logs/myvoice/myvoice_0500.json ./MYVOICE.json
```

## 9. 실제로 쓰기

### 방법 A — 방금 쓴 그 스크립트 (제일 간단)

```bash
python generate.py --style MYVOICE.json --text "읽고 싶은 문장을 여기 넣는다." --lang ko --speed 1.05
```

| 옵션 | 범위 | |
|---|---|---|
| `--speed` | 0.7 ~ 2.0 | 말 빠르기. **목소리를 바꿨으면 다시 맞춰야 한다**(아래) |
| `--total_step` | 5 ~ 12 | 품질. 높을수록 느리고 좋다. 8이 무난 |
| `--lang` | `ko` `en` `ja` … | 31개 언어. **같은 목소리로 다른 언어도 읽힌다** |

### 방법 B — 공식 Python 패키지

```bash
pip install supertonic
```

```python
from supertonic import TTS

tts = TTS(auto_download=True)
style = tts.get_voice_style(voice_name="M1")   # ← 여기에 내 JSON 을 물린다

wav, duration = tts.synthesize(
    text="안녕하세요.",
    lang="ko",
    voice_style=style,
    total_steps=8,
    speed=1.05,
)
tts.save_audio(wav, "output.wav")
```

### 방법 C — 로컬 서버로 띄우기

다른 프로그램에서 갖다 쓰고 싶을 때. OpenAI 음성 API 와 호환되는 창구도 열어준다.

```bash
pip install "supertonic[serve]"
supertonic serve --host 127.0.0.1 --port 7788
```

`http://127.0.0.1:7788/docs` 에서 바로 눌러볼 수 있다.

### 🔴 말 빠르기는 다시 맞춰야 한다

**목소리를 바꾸면 말 빠르기가 달라진다.** 기본 목소리 기준으로 맞춰 둔 `speed` 값이
내 목소리에서는 안 맞는다. 실측 예시:

| | 말 속도 |
|---|---|
| 기본 목소리 M3 @ speed 1.00 | 6.72자/초 |
| 내 목소리 @ speed 1.00 | 6.15자/초 ← **느려졌다** |
| **내 목소리 @ speed 1.10** | **6.77자/초** ← 원래대로 |

긴 문장 하나를 만들어서 `글자수 ÷ 초` 를 재보고 조정한다.
**한국어 나레이션은 6.5~7.0자/초** 가 편하게 들리는 대역이다.

## 10. 안 될 때

| 증상 | 원인 | 해결 |
|---|---|---|
| `ModuleNotFoundError: httpx` | 설치 목록에서 빠져 있다 | `pip install httpx` |
| `torchcodec` 관련 에러 | Windows 용이 없다 | 4장 ⑤ 코드 수정 |
| 한글 출력하다 죽는다 | 콘솔 인코딩 | `set PYTHONUTF8=1` |
| 학습이 몇 시간째다 | **CPU 로 돌고 있다** | 4장 ⑥ 확인 → ③ 재설치 |
| `CUDA out of memory` | VRAM 부족 | 다른 프로그램 끄기, 안 되면 Colab |
| 결과가 먹먹하다 | 녹음에 노이즈 제거가 걸렸다 | 끄고 재녹음 |
| 결과가 찌그러진다 | **마지막 체크포인트를 썼다** | 8장 — 500스텝으로 |
| 안 닮았다 | 녹음 품질 | 5장 검사부터 |
| 닮았는데 어색하다 | **말투는 원래 안 옮겨온다(1장)** | `--gender` 반대쪽 시도, 대본을 구어체로 |
| 모델을 못 받는다 | 서비스 종료 | 0장 — 받아둔 사람에게 복사 요청 |

## 11. 다 되면 — 백업부터 하고 끝낸다

결과물 JSON 은 **약 280KB짜리 파일 하나**다. 작아서 방심하기 쉬운데,
**이게 없으면 GPU 를 다시 태워야 한다.**

챙길 것:

```
MYVOICE.json          ← 고른 최종본
logs/myvoice/         ← 체크포인트 전부 (나중에 다시 고르고 싶을 때)
voices/               ← 녹음 원본 (재학습용)
```

**메모도 같이 남긴다** — 쓴 명령어 전체, `--seed` 값(기본 49), `--gender`, 고른 스텝 수.
이게 있으면 같은 결과를 다시 만들 수 있다.

## 12. 🔴 지켜야 할 선

기술적으로는 **아무 목소리나 복제된다.** 그래서 규칙이 필요하다.
클론 도구와 모델 라이선스(OpenRAIL-M) 양쪽이 명시하는 것들이다.

1. **본인 목소리이거나, 당사자의 명시적 동의를 받은 목소리만.** 유튜브·방송에서 따온
   남의 목소리는 안 된다. 동의 없는 복제는 대부분의 나라에서 법적 문제가 된다.
2. **사칭·속임수 금지.** 특정인을 사칭하거나, 보이스피싱, 가짜 발언 만들기 등.
3. **공개할 때는 AI 음성임을 밝힌다.** 유튜브 등 주요 플랫폼은 합성 음성 표시를
   정책으로 요구한다. 업로드 시 해당 항목을 체크하면 된다.
4. **미성년자 관련 악용 금지.**

라이선스는 전부 **영구**다. 갱신·구독료 같은 건 없고, 서비스가 종료돼도
이미 받은 모델의 사용권은 유지된다. 상업적 이용도 허용된다.

| | 라이선스 |
|---|---|
| 모델 가중치 | OpenRAIL-M (상업 이용 가능, 용도 제한 있음 — 위 4개) |
| Supertonic 코드 | MIT |
| 클론 도구 | MIT |
| ECAPA (speechbrain) | Apache 2.0 |
