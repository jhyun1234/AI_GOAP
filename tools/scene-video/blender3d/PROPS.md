# 소품 어휘집 — 다음 회차가 여기서 시작한다

`village.py` 의 소품 함수는 **좌표만 주면 어디서나 다시 세워진다.** 회차마다 다시 만들지 마라.

```python
import village
village.house(x, y, rot_z)      # 벽·지붕·문·창.  반환 몸통
village.tree(x, y, s=1.0)       # 기둥·층진 잎 둘. 반환 아래 잎
village.bush(x, y, s=1.0)       # 덤불 = 게임의 **식량 자원 노드**. 반환 가운데 덩이
village.well(spot)              # 테두리·기둥·도르래 대·줄·두레박
village.field(spot, rows=6)     # 흙바닥·두둑·흙덩이
village.build()                 # ep15s-1 의 마을 한 벌(위 넷 + 모닥불 + 지면)
village.flame(spot)             # 🔴 불. 유채색 예산을 쓴다 — 아래 「불」 절
village.flicker(parts, t, k=1, lean=0)   # 불꽃 흔들기. 매 프레임. lean 은 바람
village.snow(center, n=140)     # 눈발. 반환 [(객체, x, y, 위상)] — 아래 「날씨」 절
village.snowfall(parts, t, wind=0, k=1)  # 눈 내리기. 매 프레임 부른다
village.mats()                  # 세계층 재질 표(wall·earth·ground·stone·char·soil·tilled·leaf)
```

`build()` 안에 새 소품을 **가두지 마라.** 함수로 떼어 놓아야 다음 회차가 쓴다.

## 도구 넷 — 게임 `AnimKind` 와 짝이다 (2026-08-13)

```python
village.axe()          # 도끼   · Clear(벌목)          · AnimKind.Chop
village.pickaxe()      # 곡괭이 · Clear(채석)          · AnimKind.Mine
village.hammer()       # 망치   · Build·Repair·Craft   · AnimKind.Hammer
village.wateringcan()  # 물뿌리개 · Farm(Plant)·Tend   · AnimKind.Water
stage.hold(arm, tool, 'hand.R', loc, rot_x)   # 손에 붙인다
```

🔴 **`chop`·`mine`·`hammer` 는 도구가 없으면 서로 구별이 안 된다.** 셋 다 「팔을 들었다
   내린다」이기 때문이다. 게임이 `AnimKind` 로 이름을 갈라 놓은 이유가 그것이다.
🔴 도구 머리는 **등(두껍고 짧다) + 날(얇고 길다)** 둘로 갈라야 한다. 상자 하나면 주걱이고,
   등과 날을 같은 축으로만 뻗으면 옆에서 **T자 막대**가 된다(두 판 그랬다).
   도끼 날은 **삼각 쐐기를 X 로 납작하게** 눌러 넓은 면이 스윙 평면을 향하게 한다.
🔑 갈리는 지점은 도구마다 다르다: 도끼는 **면**, 곡괭이는 **뿔과 좌우 대칭**,
   망치는 **짧은 자루**(긴 자루면 메다), 물뿌리개는 **주둥이**(없으면 양동이다).
🔴 물은 안 그린다 — 유채색이면 뜻층 예산을 쓰고 무채색이면 안 보인다. 기울인 주둥이가 대신한다.
🔴 `stage.hold` 규약: 블렌더 뼈 자식은 **뼈 꼬리(=손끝)**에 붙고 **로컬 +Y 가 손 방향**이다.
   그래서 자루는 `+Y` 를 따라 눕힌다(`_haft` 가 `_cyl` 을 X −90° 로 눕힌다).

## 동작은 **대상이 있어야** 읽힌다 — 덤불 (2026-08-13)

`gather`(채집)를 「나무에서 열매 따기」로 만들었다가 두 판 버렸다. 원인 둘이 겹쳤다.

1. **이 캐릭터는 손이 정수리를 못 넘는다.** 실측(upperarm.R 만 돌려 손 위치를 잰 값):
   X −150° → 손 z **0.785**(최고) · X −120° → z 0.696 · X −96° → x −0.249(가장 앞).
   머리 꼭대기가 0.95 다. 곧게 들면 팔이 머리 실루엣에 먹혀 「머리 긁는 자세」가 된다.
2. **이 마을 나무는 침엽수다**(층진 원뿔 둘). 열매가 안 달린다. 주민을 나무 옆에 세워
   팔을 뻗게 했더니 **무엇을 향해 뻗었는지가 없어서** 동작이 통째로 안 읽혔다.

🔑 게임을 보고 고쳤다. `GatherActionSO.TargetResource` 는 **자원 노드**를 가리키고
   식량 노드(`ResourceType.RawFood`)는 덤불이다 — 높이가 허리께라 **굽혀서 캔다.**
   이 몸에 맞는 유일한 높이이고, 굽힌 등은 멀리서도 실루엣이 확실하다.

🔴 덩이 셋을 붙여 놓으면 **이끼 낀 돌**로 읽힌다. 나무가 층진 잎 둘로 나무가 된 것과 같다 —
   덩이를 떼어 놓고 높이를 어긋내고, 사이로 **잔가지**가 삐져나와야 덤불이다.
🔴 열매를 유채색 점으로 찍지 마라. 그 순간 뜻층 예산을 쓴다.
🔴 `build()` 에 넣지 마라 — 이미 구운 회차의 그림이 바뀐다. 쓰는 샷이 세운다.

**판정 도구가 두 군데 틀려 있었다** (`render_prop_look.py`, 둘 다 고쳤다):
- 주민 방향이 `atan2(-oy, -ox)` 였다. 규약이 **정면 = (−cos θ, −sin θ)** 이므로 그 값은
  주민을 소품에 **등지게** 세운다. 대칭 소품만 판정해 와서 안 드러났다.
- 주민을 카메라와 소품 사이에 세우면 뒤통수가 소품을 가린다. 카메라 축에 **수직**으로 세운다.
- 소품 자리를 나무 근처로 잡으면 **렌즈가 잎 속에 들어간다**(초록 벽만 나온 판이 있다).

## 날씨는 소품이 아니다 — 반응이다 (2026-08-13)

한기를 **파란 색 면이 마을을 가로지르는 것**(`cold_front`/`sweep`)으로 그렸다가 「너무 저급하다」로
반려됐다. 색을 바꾸거나 도형을 다듬어서 될 일이 아니었다 — **한기는 물체가 아닌데 물체로 그린 것**이
문제였다. 이 파이프라인의 규칙(연출을 고치기 전에 피사체를 의심하라)이 여기에도 그대로 걸렸다.

🔑 **바람은 눈에 안 보인다. 보이는 것은 바람에 반응하는 것들이다.** 세기 하나(`CHILL`)를 셋에 나눈다:

| 무엇 | 어떻게 반응하나 | 부르는 것 |
|---|---|---|
| 불 | 눕고 · 낮아지고 · 빨리 떤다 | `village.flicker(..., lean=)` |
| 눈 | 옆으로 눕고 빨리 지나간다 | `village.snowfall(..., wind=)` |
| 사람 | 몸을 말고 떤다 | `motions.huddle` 을 하던 일에 `blend` |

🔴 **세 값을 따로 적지 마라.** 어긋나면 「바람이 분다」가 아니라 「세 가지가 각자 흔들린다」가 된다.
🔴 사람은 **하던 일을 한 채로** 움츠린다(`blend` 0.55). 통째로 갈아타면 「추워서 일을 멈췄다」가
   되는데, 본문1 의 사건은 「일하는 채로 한기를 맞는다」다.
🔴 눈은 **세계층(무채색)**이라 뜻층 색 예산을 안 쓴다. 알베도 0.38 — 지붕(0.28)보다 밝고
   주민(sRGB 0.85)보다 어둡다. 눈이 주인공보다 밝으면 마을을 보러 온 화면에서 눈이 주인공이 된다.
🔴 자리를 `random` 으로 뿌리지 마라 — **결정성 게이트가 깨진다.** 무리수 배수의 소수부로 뿌린다.
🔴 `snowfall` 에서 `o.scale = (k, k, k)` 로 쓰지 마라. `_cube` 는 크기를 스케일로 준다 —
   덮어쓰면 눈송이가 1m 큐브가 돼서 화면이 흰 상자로 덮인다(실제로 그렇게 한 판 나왔다).

## 무엇이 「그것처럼」 보이게 하는가 — 네 번 고쳐서 얻은 규칙

이 다섯 소품을 사용자 판정으로 네 번 고쳤다. 매번 결론이 같았다.

### 1. 🔴 상자 하나는 **아무것으로도** 안 읽힌다

| 소품 | 첫 판 | 판정 | 무엇이 그것으로 만들었나 |
|---|---|---|---|
| 모닥불 | 돌 상자 하나 | 「불이 없는 게 제일 이상해」 | **돌 테두리 일곱 + 장작 넷.** 불이 아니라 자리가 문제였다 |
| 우물 | 돌 상자 하나 | 상자 | **줄과 두레박.** `draw` 동작이 허공을 당기고 있었다 |
| 집 | 상자 + 원뿔 | 문도 창도 없다 | **파낸 구멍 둘.** 실루엣은 지붕이 만들지만 「사람이 산다」는 구멍이 만든다 |
| 밭 | 판 + 각목 여섯 | 나무 데크 | **파묻은 둥근 두둑.** 아래 3 번 |
| 나무 | 기둥 + 원뿔 | 이건 괜찮았다 | 잎을 두 층으로 나눠 조금 더 나무가 됐다 |

검사가 이걸 지킨다: `test_no_prop_is_a_single_box` · `test_the_house_has_openings_cut_into_it`.

### 2. 🔴 축척 기준은 **주민 0.95** 다 — 혼자 보면 다 그럴듯하다

```bash
PROPS=well,field blender --background --factory-startup --python render_prop_look.py
```

`render_prop_look.py` 가 소품 옆에 **주민을 세워** 찍는다. 소품 판정은 늘 축척 문제였다.
🔴 거리를 하나로 통일하지 마라 — 2.35 로 다 찍었더니 집이 지붕만 꽉 차서 판정이 불가능했다.

### 3. 🔴 **흙에서 솟은 것에는 평평한 면이 없다**

밭을 세 판 돌렸다. 각목 → 눌러 납작하게 → 파묻은 둥근 두둑.
- 각진 띠 = 각목
- 납작하게 누른 띠 = **윗면이 평평해져서** 널빤지
- 반쯤 파묻어 **둥근 윗면만** 보이는 것 = 두둑

바닥판도 같은 함정이다. 0.05 로 띄웠더니 옆면이 테두리로 보여서 밭이 **나무 쟁반**이 됐다.
밭은 파인 것이지 얹은 것이 아니다 — 0.018 로 땅에 붙였다.

🔑 색 차이도 줄여야 한다. 밝은 띠가 어두운 바닥에 또렷하게 얹히면 그게 널빤지다(`soil` ↔ `tilled`).

### 4. 🔴 소품끼리 **겹쳐서 한 물건이 된다**

모닥불이 훅 카메라에서 우물 뒤 **2.6°** 에 있었다. 두 소품이 겹쳐 보이면서 우물 틀 안에서
불이 타는 꼴이 됐다 — 각각은 멀쩡한데 화면에서는 처음 보는 물건 하나였다.
🔑 소품 자리를 **월드 좌표가 아니라 카메라에서 본 각도**로 확인해라. 3.7 m 떨어져 있어도
카메라가 일직선상에 있으면 붙어 보인다. 우물을 (2.0,-1.2) → (3.0,-0.4) 로 옮겨 13° 를 벌렸다.

### 5. 🔴 같은 것 여럿은 **배경 무늬**가 된다

나무 넷을 같은 크기로 두면 마을이 아니라 텍스처다(`TREE_SIZES`).
모닥불 돌 일곱을 같은 크기로 두면 공산품이다.
🔴 **난수는 안 쓴다** — 결정성 게이트가 죽는다. 번호에서 뽑아 흔든다: `0.15 + 0.045 * ((i * 3) % 4) / 3`.

### 6. 🔴 파낼 때는 **뚫지 말고 파라**

`_carve()` 가 불리언 차집합을 적용한다(Bool Tool 애드온은 이 일의 UI 껍데기라 스크립트에선 안 쓴다).
- 관통시키면 집 속이 비어 반대편이 보인다. 깊이를 벽 두께보다 얕게 준다
- 🔴 **판 자리에 어두운 안쪽을 대라.** 불리언이 만든 새 면은 벽 재질을 물려받아 그냥
  회색 판으로 보인다 — 문이 문이 아니라 벽에 붙인 패널로 읽힌 이유가 그것이다
- 모디파이어는 **적용**한다. 남기면 매 프레임 평가된다

## 색 — 소품은 세계층이다

🔴 소품에 유채색을 쓰지 마라. 마을은 **세계층**(무채색 + `earth`)이고, 유채색은 뜻이 있을 때만 뜬다.
`stage.world_mat` 이 알베도 채도 상한(0.34)을 강제한다 — 손으로 적은 값 하나가 규약을 깬 적이 있다.

### 불 — 유일한 예외이고, **공짜가 아니다**

`village.flame()` 은 앰버(삶·온기)라 **뜻층**이다. 부르는 순간 그 프레임의 유채색 둘 중 하나를 쓴다.
그래서 `build()` 가 안 켠다 — **샷이 정한다.**

| 샷 | 프레임당 뜻층 |
|---|---|
| 인트로 | 1 (초록 획 0.79 초에 사라짐 → 불 3.35 초에 붙음. **한 프레임에 안 겹친다**) |
| 훅 | 2 = 보라(성격 표식) + 앰버(불). **규약 상한** |
| 본문2 | 2 = 보라(닿은 칸) + 앰버(불). 시안은 계기층이라 예산 밖 |

```python
probe.metrics(png)['chroma_hues']      # 프레임마다 재라. 기억해서 지킬 규칙은 안 지켜진다
```

⚠️ 넓은 샷에서 불은 화면의 0.08~0.12% 라 `MIN_HUE_FRAC` 문턱 언저리다.
**게이트에 안 잡히는 것과 안 쓰는 것은 다르다** — 가까운 샷에서는 반드시 잡힌다.

## 새 소품을 만들 때

1. `village.py` 에 **좌표를 받는 함수**로 쓴다. `build()` 안에 인라인하지 마라
2. 재질은 `mats()` 에서 꺼낸다. 새 색이 필요하면 거기 추가하고 채도 상한을 확인한다
3. 프리미티브만 쓰고 `verts` 를 낮게 잡는다 — 캐릭터가 플랫 셰이딩 6,786 면이다.
   🔴 **로우폴리로 줄여도 안 빨라진다**(실측: 면 75% 감소 → 오히려 느림). 손잡이는 샘플 수다
4. `render_prop_look.py` 의 `LOOKS` 에 한 줄 넣고 **주민 옆에서** 본다
5. 조각 수를 `village_report.json` 에 남기고 검사를 건다 — 상자로 되돌아가는 것은 한 줄이면 된다
6. 주민이 지나다니는 자리라면 `render_hook.py` 의 궤적 검사가 자동으로 잡는다
   (높이 0.15 미만은 밟고 지나가고, 밑동이 0.90 위인 것은 밑으로 지나간다)
