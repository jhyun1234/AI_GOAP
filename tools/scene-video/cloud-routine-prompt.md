# 영상 대본 루틴 — 클라우드용 (사람이 claude.ai 스케줄에 붙여넣는 것)

> 이 파일은 **붙여넣을 프롬프트 원문**이다. 아래 「붙여넣을 것」 절 전체를 복사해
> claude.ai 의 스케줄 루틴에 넣는다. 이 문단과 「왜」 절은 사람이 읽는 설명이라 안 넣어도 된다.

## 왜 클라우드인가

영상 파이프라인은 반씩 나뉜다.

| 절반 | 어디서 | 왜 |
|---|---|---|
| **대본** (기획→작성→검수→마스터) | **클라우드** | Claude 만 있으면 된다. PC 가 꺼져 있어도 쌓인다 |
| **렌더** (음성→mp4→점검) | **로컬 PC** | TTS 모델 645MB · 크로미움 · ffmpeg 가 이 PC 에만 있다 |

블로그가 PC 없이 발행되는 것과 같은 구조다. 대본이 브랜치로 올라오면
`.github/workflows/scene-script-auto-merge.yml` 이 main 에 머지하고,
로컬 스케줄러(로그온 3분 뒤 · **매일 15:00**)가 `git pull` 해서 밀린 것을 렌더한다.

🔴 **로컬은 클라우드보다 뒤에 와야 한다.** 옛 등록이 격일 09:00 이었는데 클라우드가
09:09 에 시작해 11:04 에 push 해서, 로컬이 9분 먼저 돌고 가 매 회차가 하루씩 밀렸다.
박자는 언제나 **대본을 만드는 쪽**이 쥔다 — 로컬에서 또 잠그면 박자가 두 군데가 되고,
하루 어긋나면 영영 하루씩 밀린 채로 간다.

⚠️ **켜기 전에 `state/schedule.json` 에 `"scriptBy": "cloud"` 를 넣어야 한다.**
안 넣으면 로컬도 대본을 만들려 들어 **양쪽이 같은 회차를 두 번 쓴다.**

## 클라우드가 못 하는 것 (알고 시작할 것)

크로미움이 없어서 **검수팀이 픽셀을 못 본다.** `check.mjs` 도 `render.mjs --still` 도 못 돌린다.
그래서 이런 것은 클라우드에서 안 잡힌다 — 좌우 잘림 · 정적 구간 · 팔레트 · 하단 안전영역.

**대신 로컬이 렌더할 때 `check.mjs` 14종이 잡고, 실패하면 되돌림 루프가 고친다.**
즉 늦게 발견될 뿐 새어 나가지는 않는다. 원문 대조·사실 확인·다음 편 예고 같은
**글 수준 검수는 클라우드에서 그대로 된다.**

## 주기 — **하루 두 편** (2026-08-03 사용자 지시로 하루 1편 → 2편)

```
0 0,12 * * *   (UTC 00:00·12:00 = KST 09:00·21:00, 매일 두 번)
```

🔴 **여기서 크론이 본체다.** 게이트만 낮추고 크론을 하루 한 번으로 두면
게이트를 0으로 만들어도 **여전히 하루 한 편이다.** 둘을 함께 바꿔야 한다.

박자는 프롬프트의 **0-A 게이트**가 잡는다. 크론이 하루 두 번 도니 게이트를
0.5일에서 **0.25일(6시간)** 로 낮춘다 — 같은 회차가 두 번 도는 것만 막고
12시간 간격의 두 실행은 통과시킨다.

🔑 왜 이 변경이 필요했나: 실측 절대 시청 시간이 16~27초인데 영상이 80~122초였고,
한 글에 사건이 둘이면 제목이 약속한 장면이 30초 뒤에 나왔다. 그래서 회차를
**사건 단위로 30~45초씩 쪼갰고**(Docs/영상_이탈률_개선_실행명세서.md §W1),
글 하나가 2~3편이 되어 발행 박자를 올릴 재료가 생겼다.

⚠️ **하루 2편은 재료가 있을 때만이다.** 공급(격일 1글 × 2~3편 = 하루 1~1.5편)이
소비(하루 2편)보다 적어 구조적으로 적자다. 밀린 미발행 소재가 완충재라 2~3주는
버티고, 마르면 `backlog.mjs` 가 `IDLE` 을 내고 그날은 1편만 나간다.
**그건 사고가 아니다**(ADR-V-6). 아무것도 고치지 마라.

🔴 **크론 숫자로 주기를 표현하려 하지 마라.** 격일이 다시 필요해져도 `0 0 */2 * *` 는
1·3·5…31일이라 **31일 다음이 1일이라 이틀 연속으로 돈다.** 주기는 언제나 여기 게이트에서,
달력이 아니라 **경과 시간**으로 잰다. 실행이 하루 밀려도 다음 날 알아서 따라잡는다.

🔑 **매일이라고 매일 만들어지는 건 아니다.** 블로그가 격일 발행이므로, 순서표에 쌓아 둔
회차를 다 소진하고 나면 실제 산출은 **블로그가 글을 내는 속도**를 따라간다. 재료가 없는
날은 0절이 "만들 회차 없음"으로 조용히 끝낸다 — 그게 정상이고, 새 글이 나오면 저절로 재개된다.

블로그 루틴(짝수일 13:03)과는 시각이 겹치지 않는다.

### 0-A. 간격 게이트 — 하루에 두 편
마지막으로 대본이 만들어진 때를 **git 이력**에서 본다:
```
git log -1 --format=%cI -- $(node -p 'require("./tools/scene-video/state/schedule.json").order.map(i=>"tools/scene-video/episodes/"+i+"/scene.json").join(" ")')
```
그때로부터 **0.25일(6시간)이 안 지났으면 아무것도 하지 말고 "아직 이르다"만 보고하고 끝낸다.**
커밋도 하지 마라.

🔑 **0.25일인 이유**: 목표는 **하루 두 편**이고 크론은 12시간 간격으로 돈다. 그러니 이
게이트가 막아야 하는 것은 "두 번째 실행"이 아니라 **같은 실행이 두 번 도는 것**
(재실행·수동 실행)뿐이다. 0.5일로 두면 21:00 실행이 몇 분만 늦어져도 그 편을 통째로
건너뛴다 — 격일 시절에 실제로 겪은 밀림과 같은 종류의 사고다. 12시간 간격에 6시간
게이트면 양쪽으로 반씩 여유가 있다.

🔴 **`order` 에 있는 회차만 본다 — 시리즈 밖 특별편은 박자를 먹지 않는다.**
그래서 `episodes/*/scene.json` 같은 넓은 글롭을 쓰지 마라. 회차 목록은 `schedule.json` 의
`order` 가 정본이고, 0절에서 회차를 고를 때 쓰는 기준과 같은 것을 쓰는 셈이다.

🔑 **왜 좁혔나(2026-08-01 사용자 판정)**: 처음엔 넓은 글롭이었는데, 손으로 만든 특별편
`ep00i` 가 게이트를 물어 `ep03s` 착수가 **하루 밀렸다** — 크론이 하루 1회라
15.6시간 차이가 하루가 된다. **시리즈 박자는 시리즈가 정한다.** 특별편은 본편과 별개로
아무 때나 만들 수 있어야 하고, 그것 때문에 본편이 밀리면 안 된다.

🔑 **왜 크론이 아니라 여기서 재나**: 크론으로는 격일을 제대로 표현할 수 없다.
`*/2` 는 1·3·5…31일이라 **31일 다음이 1일이라 이틀 연속으로 돈다.**
달력에 기대지 말고 "마지막으로 만든 때로부터 며칠"을 직접 본다 —
로컬 렌더 쪽도 같은 이유로 같은 방식을 쓴다. 실행이 하루 밀려도 알아서 따라잡는다.
⚠️ 파일 mtime 을 쓰지 마라. 새로 clone 하면 전부 체크아웃 시각이라 쓸모가 없다. **git 이력이 정본이다.**

### 0. 할 회차 정하기 — 스크립트가 정한다

```
node tools/scene-video/backlog.mjs --extend
```

이 한 줄이 판정과 순서표 갱신을 함께 한다. 출력의 **상태**만 보고 갈라라.

| 상태 | 뜻 | 할 일 |
|---|---|---|
| `PENDING` | 순서표에 아직 대본 없는 회차가 있다 | 그 회차로 1절 진행 |
| `EXTENDED` | 순서표를 다 만들어서 **새 블로그 글 한 편을 회차로 편입했다** | 그 회차로 1절 진행 |
| `IDLE` | **재료가 없다** | 아무것도 하지 마라. "만들 회차 없음"만 보고하고 끝낸다. **커밋도 하지 마라** |

🔴 **`IDLE` 은 사고가 아니다.** 순서표를 다 만들었고 아직 영상이 안 된 발행 글도 없다는 뜻이다.
블로그가 다음 글을 발행하면 그다음 실행이 `EXTENDED` 로 저절로 재개된다.
**억지로 소재를 찾지 마라** — 미발행 밀스톤을 앞질러 만들거나, 이미 만든 회차를 다시 쓰거나,
번외를 마음대로 끌어오는 것 전부 금지다.

- ⚠️ `state/uploads.json` 은 보지 마라. 그건 로컬이 렌더한 기록이라 클라우드와 박자가 다르다.
  **기준은 오직 `scene.json` 의 존재 여부다**(스크립트도 그것으로 판정한다).
- 🔑 `EXTENDED` 로 새로 편입된 회차는 **`Docs/영상_시리즈_구성안.md` 표에 행이 없다**(그 문서는
  1~13편 + 번외까지만 다룬다). 막·주제는 원문에서 읽어라. 구성안이 없다고 SKIP 하지 마라.
- 🔑 편입 줄에 `⚠️ 공개 URL 미확인` 이 붙었으면 `tools/blog-automation/BLOG_COVERAGE.md` 나
  `tools/blog-automation/state/blog_last_published_commit.md` 에서 그 글의 공개 URL 을 찾아
  `schedule.json` 의 `url` 을 채워라. 영상 설명의 블로그 링크가 거기서 나온다.
  못 찾으면 `null` 로 두고 그 사실을 보고에 적어라 — **지어내지 마라.**

### 1. 대본 만들기
`tools/scene-video/routine-prompt.md` 의 절차를 그대로 따른다. 4개 부서를 순서대로:
`scene-planner` → `scene-writer` → `scene-reviewer` → `scene-master`.
각 단계 산출은 반드시 `tools/scene-video/episodes/<id>/notes/` 에 파일로 남긴다
(서브에이전트는 무상태라 대화로 못 물려받는다).

정본 문서를 먼저 읽어라 — `routine-prompt.md` 와 `.claude/agents/scene-*.md` 에
길이 규칙·다음 편 예고·효과음·그림 소유 규약이 전부 들어 있다.

### 2. 이 환경에서 못 하는 것
- 🔴 **렌더하지 마라.** `tts.mjs` · `render.mjs` · `publish.mjs` 를 부르지 마라.
  크로미움도 ffmpeg 도 TTS 모델도 없다. 렌더는 로컬 PC 가 한다.
- 🔴 **`check.mjs` 도 못 돈다**(크로미움 필요). 검수팀은 **글 수준 검수만** 한다 —
  원문 대조 · 화면 문자열 사실 확인 · 다음 편 예고 정본 대조 ·
  돌려막기(앞 회차 `kinds/*.js` 와 장치 비교) · 효과음 배치와 절제.
  - 🔴 **말·그림 도착 시각은 인덱스 대조로 끝내지 마라.** `cue` 를 **안** 쓰는 조건
    (`frac(t/N)` 같은 `t` 기반 · `rk > 0.7` 처럼 다른 자막의 진행도로 만든 문턱)이
    언제 참이 되는지 초로 환산해서 대조해라. 이 계열로 **이미 두 번 샜다**
    (ep02s `tripwire` · ep00i `runmark` — 후자는 결말이 자막보다 1.64초 먼저 터졌다).
    이건 크로미움 없이도 되는 검수다 — 계산이지 픽셀이 아니다.
  - 🔴 **효과음 `gain` 상한.** 렌더 로그의 천장 경고는 **로컬에서만** 나오므로 여기가
    유일한 사전 방어선이다. 기본 0.060 이고 상한이 kind 마다 다르다 —
    `tick` 0.065 · `latch` 0.071 · 나머지 넷 0.085 이상 여유.
    넘기면 그 소리만 조용해진다(RMS 정규화가 없애 둔 불균형이 되살아난다).
  픽셀 판정(잘림·정적 구간·팔레트·안전영역)은 **로컬이 렌더할 때 잡는다** — 그걸 전제로 통과시켜라.
  검수 보고서에 **"픽셀 판정 미실시(클라우드)"** 라고 명시해라.
- 🔴 유튜브에 올리지 마라. 업로드는 언제나 사람이 한다.
- 🔴 `Docs/영상_시리즈_구성안.md` 를 수정하지 마라. 읽기 전용이다.

### 3. 커밋과 push
성공했으면 **대본 산출물만** 커밋한다.
```
tools/scene-video/episodes/<id>/scene.json
tools/scene-video/episodes/<id>/kinds/*.js
tools/scene-video/episodes/<id>/notes/*
tools/scene-video/state/schedule.json      ← 0절이 회차를 편입했을 때만
```
🔴 **다른 경로를 건드리지 마라.** 워크플로우가 이 네 경로만 받고, 벗어나면 머지를 거부한다.
⚠️ `schedule.json` 은 **0절의 `--extend` 가 실제로 고쳤을 때만** 들어간다. 손으로 `everyDays`·
`scriptBy`·기존 매핑을 고치지 마라 — 그건 사람이 정하는 값이다.
`.claude/agent-memory/` 도 이번엔 커밋하지 마라 — 경로 밖이라 브랜치가 통째로 막힌다.

커밋 메시지: `feat(scene-video): <id> 대본 — 클라우드 루틴`

push 는 **현재 작업 브랜치 그대로** 한다(샌드박스는 세션 브랜치로만 push 를 허용한다).
`.github/workflows/scene-script-auto-merge.yml` 이 받아서 main 에 fast-forward 머지한다.

### 4. 멈춰야 하는 조건
- 0절이 `IDLE`(재료 없음) — 커밋 없이 즉시 종료
- 기획팀 `SKIP`(원본 글 미발행 등)
- 검수 반려 3회 / 마스터 반려 3회
멈출 때는 `notes/` 에 사유를 남기고 **`scene.json` 을 만들지 마라.**
`scene.json` 이 없으면 로컬이 "대본 대기"로 조용히 넘어가고, 다음 회차에 다시 시도한다.
**애매하면 통과시키지 말고 멈춰라** — 영상은 글과 달리 되돌리는 비용이 크다.
