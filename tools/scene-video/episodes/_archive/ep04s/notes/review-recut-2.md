## 1. R-1 재계산 — ✅ 풀렸다. 표식이 60 → 100 → 60 으로 실제로 간다

`S8` 은 1차본과 **완전히 동일**하다. 스크립트로 대조했다:

```
S8 1차본 lines: 5줄 · spec 동일? true (leaveCue 2 · returnCue 3) · sfx 동일? true · reads 동일? true
```

`rung60.js:54` 의 이중 lerp 는 그대로지만, 이제 `lk`(자막 2)와 `rk`(자막 3)의 **창이 시간으로
갈려 있어** 상쇄가 일어나지 않는다. `engine.js` 의 `cue()`·`buildTimeline()` 을 그대로 옮겨
심고 자막 길이를 두 모델로 잡아 `my(t)` 를 프레임 단위로 훑었다:

| 발화속도 모델 | 상승 시작 | **100 도달** | 하강 시작 | **60 복귀** | 100 칸 `hot` 최대 |
|---|---|---|---|---|---|
| 5.6자/초 (엔진 provisional) | 자막2 +0.23s | 자막2 **+2.60s** | 자막3 +0.20s | 자막3 **+2.25s** | **1.000** |
| 6.7자/초 (check.mjs 산정) | 자막2 +0.15s | 자막2 **+1.95s** | 자막3 +0.10s | 자막3 **+1.67s** | **1.000** |

- 표식 y 는 **174(60 칸) → 70(100 칸) → 174** 로 **전 구간 104px 을 다 간다.**
  1차 반려 때는 26px(25%)만 들썩였고 `hot(100)` 이 0.000 이었다. 이제 **1.000** 이다 —
  배고픔(100) 칸이 실제로 켜진다.
- 두 사건 다 **그 사건을 부르는 자막 안**에서 시작하고 끝난다. 자막 2("일하다 배고프면
  밥부터 먹으러 가고")가 말해지는 동안 올라가고, 자막 3("배 채우면 알아서 명령으로
  돌아와요")이 말해지는 동안 내려온다. 움직임 개시가 자막 시작 +0.10~0.23초라
  가이드 한도(±20프레임 = 0.67초) 안이다.
- **자취 점선의 순서도 살아났다**(`rung60.js:137-154`). `upK = ease(lk)` 는 자막 2 동안,
  `downK = ease(rk)` 는 자막 3 동안만 자란다 — 1차 반려 때 "동시에 같은 속도로 자란다"고
  지적한 자리다. 복귀 경로의 흐르는 점(`rk > 0.6`)도 자막 3 후반에만 뜬다.
- `reads` 의 *"오른쪽 레일의 표식이 60에서 100으로 튀어 올랐다가 다시 60으로 내려온다"* 가
  이제 **화면에서 실제로 일어난다.**

**sfx 도 함께 살아났다.** S8 `at:0 tick delayMs 1270` — 자막 0 이 1차본과 글자 하나 안 다르고
`pauseAfter 200` 도 같다. `slide` 도착(`ease(clamp(pk/0.85)) = 1`)을 다시 풀면 `pk=0.85 →
raw 0.755`, `W = 0.15 + 2.887×0.6 = 1.882s` → **자막 시작 +1,271ms**. 적힌 값과 1ms 차.

### 2-2. 상호 참조 — 양방향 다 있다 (편이 나뉜 회차 필수 항목)

### 2-3. 길이 — 게이트 안, 문서 목표보다 0.6초 김

`24자 ÷ 6.7 + pauseAfter 0 = 3.58초`. `check.mjs` 의 `TEASER_MAX = 4.0`(warn) 안이라 통과다.
다만 같은 파일의 주석과 `scene-reviewer.md` 7 은 *"3초 안에"* 라고 적혀 있어 0.58초 넘는다.
게이트가 판정 기준이므로 **반려도 정정 요구도 아니고 관찰로 남긴다.**

### 2-4. 정적 구간이 늘었는가 — ❌ 안 늘었다. 실측으로 갈랐다

기본 5fps 로는 1차(예고 없음)와 2차(예고 있음)가 **똑같이 `최대 3.0s`** 다.
요청하신 대로 ep05s 와 같은 일이 났는지 보려고 **분해능을 12fps 로 올려 두 번 돌렸다** —
현재 씬과, 마지막 자막 한 줄만 뺀 사본(`episodes/zztmp`, 측정 후 삭제):

```
$ node check.mjs ep04s  --fps 12   → ⚠ 정적 구간 3초 이하   S8 3.1s, S11 9.3s   (편당 76.4초)
$ node check.mjs zztmp  --fps 12   → ⚠ 정적 구간 3초 이하   S8 3.1s, S11 9.3s   (편당 72.8초)
                                     🔴 다음 편 예고 있음  마지막 샷(S11)에 예고가 없다
```

**예고 유무와 무관하게 값이 완전히 동일하다.** 예고가 정적 구간을 만들지 않았다는 직접
증거다. 12fps 에서만 뜨는 9.3s 는 `oneline.js:73-80` 의 RTS 표식이 `frac(t/2.2)` 로
**끊임없이 도는데 프레임 간격이 좁아 이동량(1프레임 4.6px)이 평균차 문턱 0.0008 아래로
떨어지는** 계측 특성이고, 그림이 실제로 멈추는 것이 아니다(멈추는 코드 경로가 없다).
5fps 기본 게이트가 판정 기준이며 그쪽은 3.0s 로 통과다. → 관찰 항목.

🔑 ep05s 가 걸린 이유와 갈린 지점이 분명하다: 저 편의 마지막 kind 는 계속 도는 요소가
`qk` 이후 멈추는 구조였고, ep04s 의 `oneline` 은 `rk > 0.1` 이면 끝까지 도는 표식을 갖고 있다.
작성팀 가설이 맞았다.

## 3. 편당 76.4초 — 더 나누지 않는 판단, ✅ 타당하다

`notes.편당_길이_판단` 의 세 근거를 하나씩 봤다.

1. **"축이 하나라 더 자를 수 없다"** — 맞다. 남은 다섯은 문제(S1) → 거부(S7) → 우선순위
   한 칸(S8) → 사각지대(S9) → 성공 기준(S11)이고, 훅("거절은 기능이 아니라 주민의
   상태였다")을 회수하는 것은 S11 인데 S7·S8 없이는 그 문장이 서지 않는다.
2. **"초과분의 출처가 분명하다"** — 실측으로 맞다. S8 복원분(1차본 5줄 ↔ 4줄 컷 차이)과
   예고 3.58초가 그대로 초과분이다. **둘 다 검수·사용자가 요구해서 들어온 것**이라
   이걸 빼라고 하는 것은 자기모순이다.
3. **"3편을 만들 재료가 없다"** — 맞다. `excluded` 대조 결과 이 원문에서 아직 안 쓴 덩어리는
   말풍선 정리(5절 M1-D)·프로세스 일반화(5절)·협상의 다음 수(7절)뿐이고, 셋 다 사유를 달아
   버린 것들이라 한 편이 되지 않는다.

🔑 **1.4초 때문에 자막을 지우라고 요구하지 않는다.** 그것이 ep02s 에서 36초를 잃은 경로다.
상한 90초 안이고 warn 은 "판단하고 사유를 적어라"이며 사유가 적혀 있다. 통과.

## 5. 나머지 사람 점검 — 전부 유지

- **첫 10초** — 제목 카드 없다. 첫 프레임에 사다리 검사선이 이미 내려간다. 0~2.5초
  "창고가 차니까 할 일이 사라졌어요" → ~5초 "주민들이 그 자리에서 그냥 굳었어요"에서
  수수께끼가 선다. 첫 자막 3.0초. ✅
- **말·그림 동기** — cue 인덱스 전수 재확인: S1(0·0·1·2 / 3줄) S7(0·1·2·3·3 / 4줄)
  S8(0·1·2·3·4 / 5줄) S9(0·1·2 / 3줄) S11(0·1·2·3 / 5줄). 범위 밖 0건. 한 자막에 둘이
  물린 자리 둘(S1 `liveCue`/`fullCue`, S7 `refuseCue`/`notRandomCue`)은 kind 안에서 독립
  경로라 상쇄가 없다(1차에서 코드로 확인, 코드 무변경). `t` 로 도는 것은 전부 배경 운동이고
  사건은 하나도 `t` 위에 있지 않다.
  🟡 단 하나 어긋난 것이 S7 의 `reads` 순서다 → C-4(그대로 남음).
- **효과음** — 4개 / 76.4초 = 90초 환산 **4.7개**로 기준(5~8) 바로 아래다. 배치는 전부
  나레이션이 부르는 사건 위에 있고 정적을 메우려 깐 소리가 없다. `delayMs` 넷 다 1차에서
  draw 코드로 재계산해 최대 오차 5ms 였고 자막이 안 바뀌었으므로 그대로 유효하다.
  gain 은 `tick` 둘이 0.057·0.055 로 문서표 상한(0.065)보다 낮고, 작성팀이 `synth()` 로 잰
  옵션별 무경고 상한(0.0596·0.0601)의 96%·91.5%다. 렌더 로그의 피크 천장 경고는 이 환경에서
  확인 불가(ffmpeg 없음) — **로컬 렌더에서 반드시 눈으로 확인할 것.**
  🟡 `why` 하나가 이제 거짓이다 → C-7.
- **말투** — 큰 쉼 2회(한도). 가장 긴 `say` 29자. 담화표지 4개/20줄. 어미 3연속 없음.
  🟡 소리 내어 읽으면 걸리는 자리가 **새로 하나 생겼다** → C-9.
- **돌려막기** — kind 다섯이 다른 회차·2편과 겹치지 않는다. 예고를 전용 샷(`nextup`)이 아니라
  기존 마지막 샷의 자막으로 붙인 것은 오히려 반복을 줄인다. ✅

## 6. 🟡 정정 요구 — 1차 잔여 넷 + 이번에 새로 본 셋

🔴 **먼저 사실 확인.** 1차 리포트의 정정 요구 여섯 중 `scene.json` 에서 실제로 바뀐 것은
**C-2 뿐**이다(그것도 절반). C-1·C-3·C-4·C-5·C-6 은 diff 에 흔적이 없다.
반려 사유는 아니지만 **발행 전에 닫아야 한다** — 지금 상태로 커밋되면 리포에
"없는 샷을 근거로 든 기록"이 영구히 남는다.

### C-1(재요구). `excluded` 여섯 항목이 이 편에 없는 샷을 근거로 든다 — **미반영**

원문 그대로 남아 있다:

| `excluded` 항목 | 문제 문장 | 실제 |
|---|---|---|
| 원문 5절 "초보 개발자…" | "이 편은 그 규칙의 **결과**만 가져온다 — **S10 relative** 는…" | S10 은 2편(ep04s2)에 있다 |
| 원문 3절 2단계 | "세 버그의 이름과 공통 뿌리는 **S4 idlespin** 이 통째로 받지만" | S4 는 2편에 있다 |
| 원문 4절 클릭/우클릭 | "자막은 '클릭하고, 우클릭' **여섯 자**로 줄였다" | 실제 자막은 "이제 촌장이 명령을 내려요. 우클릭이요." |
| 원문 6절 사이클 | "S9 의 첫 자막이 '구멍이 **하나** 나왔어요'" / "프로세스 이야기는 **S10** 의 칩 하나로 충분" | "하나"는 없고, S10 도 없다 |
| 원문 8절 M2 예고 | "구체 이미지는 **S12 화면의 재료**로 썼다" | S12 는 삭제됐다 — 이 재료는 어디에도 안 쓰인다 |
| M1 명세서 수치 | "**S3 sidedoor** 의 배회 노드는…" | S3 은 2편에 있다 |

🔴 **여기에 하나 더 늘었다.** 1차본 S12 항목의 사유가 *"예고는 설명란과 고정 댓글로 옮긴다"*
인데, **예고는 되살아나 S11 자막 4로 들어왔다.** 지금은 씬 자신과 모순이다.

### C-2(부분 반영 → 재요구). `notes.길이`·`pacing`·`재구성` 이 다시 옛 값이다

`cue_인덱스` 는 잘 고쳤다(S8 상쇄 수식까지 적어 둔 것은 좋다). 나머지는 **예고 한 줄을 붙인
뒤 다시 세지 않아** 또 어긋났다. 실측(스크립트로 직접 셈):

```
S1 3줄 66자 | S7 4줄 94자 | S8 5줄 115자 | S9 3줄 73자 | S11 5줄 119자
합계 20자막 467자 4,960ms → 발화 69.70s · 통짜 74.66s · 렌더 76.41s
```

| 항목 | 적힌 값 | 실제 |
|---|---|---|
| `notes.길이` | "say 합계 **443자**(샷별 66·94·115·73·**95**) … 통짜 71.1초 … 렌더 약 **72.8초**" | **467자**(…·**119**) · 통짜 74.7 · 렌더 **76.4** |
| `notes.길이` | "check.mjs 총 길이 항목이 … (**상한 75초**)" | 게이트가 바뀌었다 — **목표 75(warn)·상한 90(fail)** |
| `notes.재구성_2026-08-03` | "5샷·**19자막**·렌더 약 **72.8초**" | **20자막 · 76.4초** |
| `notes.pacing` | "5샷 **19자막**" / "**19줄에 3개**로 **6.3줄에 하나꼴**" | **20자막** / 담화표지는 **4개**(S8 "그래서", S9 "근데"·"그래서", S11 "근데") = 5줄에 하나 |

🔑 같은 파일 안에서 `길이`(72.8초)와 `편당_길이_판단`(76.4초)이 서로 다른 값을 말한다.

### C-3(재요구·선택). S9 자막 1이 1편 단독 시청자에게 남기는 전제 — 미반영

*"쉬어도 안 풀리면요?"* 는 주민이 쉴 수 있다는 것(여가)을 전제하는데 그 소개는 2편에 있다.
원문 표현 그대로인 *"모닥불 곁에서 쉬어도 안 풀리면요?"* 로 받치면 전제가 사라진다
(원문: "주민이 피로 80 상태로 모닥불 곁에서 계속 쉬면서도"). 선택 사항.

### C-4(재요구). S7 — 지워진 자막의 `excluded` 사유 없음 + `reads` 순서가 실제와 다름 — 미반영

1차본 S7 다섯째 자막 **"랜덤이 아니에요. 실제 상태로 내린 판정이죠."** 가 사라졌는데
`excluded` 에 항목이 없다. 이건 원문이 못박은 한 줄이라 **이름 붙은 개념**에 가깝다
(축 자체는 S11 자막 2가 받으므로 반려는 아니다).

`reads` 의 *"**마지막에** 점선으로 된 세 번째 갈래(수락)가 아래에 열린다"* 를 이번에 직접 풀었다.
`nk = ease(cue(3, 0.15, 0.55))`, 자막 3 = 27자 → `W = 0.15 + 4.630×0.55 = 2.697s`:

```
세 번째 갈래 등장 nk>0.03  → raw 0.104 → 자막3 +0.13s   (완성 nk*1.6≥1 → +1.39s)
첫 말풍선 완전 표시                                      → 자막3 +0.81s
둘째 말풍선 완전 표시                                    → 자막3 +1.83s
```

**"마지막"이 아니라 두 말풍선 사이에 완성된다.** 게다가 그 요소를 부르던 자막이 삭제돼
**지금은 아무도 부르지 않는 채로 켜진다.** `spec.notRandomCue` 는 이름만 남았다.
→ `excluded` 에 한 줄, `reads` 를 실제 순서로. (또는 `nk` 문턱을 올려 정말 마지막이 되게.)

### C-5(재요구·선택). 콜드 오픈 세 줄이 전부 "-었어요"로 닫힌다 — 미반영

`voice.json` rules.1 의 문자적 위반은 아니다(중간에 "했죠"가 끼어 3연속이 아니다). 다만
이탈이 가장 큰 0~11초에서 줄 끝소리가 셋 다 같다. S1-0 을 *"…사라지더라고요."* 로 한 줄만
바꾸면 된다. ⚠️ **S1-1 은 sfx 유도값이 걸려 있으니 건드리지 말 것.**

### C-6(재요구). 효과음 `why` 에 `ep00i` 대조가 없다 — 미반영

`why` 들이 `ep03s` 만 대조한다. 실측 대조는 이렇다:

| 이 편 | 가장 가까운 앞 회차 | 간격 |
|---|---|---|
| S11 tick `dur 0.04 · 1750Hz` | **ep00i S9 tick `dur 0.04 · 2100Hz`** | **dur 완전 일치**, freq 약 3반음 |
| S1 thud `dur 0.26 · 132Hz` | **ep00i S8 thud `dur 0.32 · 125Hz`** | dur 0.06 차, freq 약 1반음 |

3반음이면 즉시 반려는 아니지만 `project_recurring_defects.md` ③ 과 같은 모양이다.
`why` 에 ep00i 대조를 명시하거나 dur 을 0.035 로 한 번 더 옮겨라.

### 🆕 C-7. S11 `sfx.why` 가 없는 샷을 근거로 gain 을 정당화한다

```
"이 편의 마지막 소리는 다음 샷의 riser 이고, 여기 카드에는 그보다 작은 소리를 둔다"
```

**그 riser 는 S12 에 있었고 S12 는 삭제됐다.** 지금 S11 tick 이 이 편의 마지막 소리다.
gain 0.055 자체는 피크 천장 여유(9%)로 따로 근거가 서므로 값을 바꿀 필요는 없다 —
**문장을 현재 컷에 맞게 다시 써라.** (`notes.효과음` 도 여전히 "12샷 중 7샷"을 설명한다.
그건 1차본 기록이라고 선언돼 있어 정정 대상은 아니지만, **지금 컷이 왜 4개인지**는
어디에도 적혀 있지 않다 — 90초 환산 4.7개로 기준 밴드 아래라 한 줄 필요하다.)

### 🆕 C-8. 이 편은 스스로를 한 번도 "1부"라고 부르지 않는다

```
ep04s   hud.title   "4편 · 명령을 거부한 날"          youtube.title  "… 개발일지 4편 #shorts"
ep04s2  hud.title   "4편 2부 · 쉬는 걸 만들었더니"     youtube.blurb  "… 4편 1부에서"
```

2부가 "4편 1부에서"라고 가리키는 대상이 화면 어디에도 그 이름으로 없다. 시청자가 2부를
먼저 보고 "4편 1부"를 찾으면 "4편"만 나온다. `hud.title`(과 유튜브 제목)을 **"4편 1부"** 로
맞추는 것을 권한다. 덤으로 예고 나레이션이 부르는 "4편 2부"에 화면 근거가 생긴다.

### 🆕 C-9. 예고 한 줄이 소리 내어 읽으면 걸린다 (`voice.json` rules.7)

```
"다음은 4편 2부, 쉬는 걸 만들었더니예요."
```

제목을 인용부호 없이 명사처럼 쓰면서 연결어미 "-더니"에 "-예요"를 붙였다. 눈으로는 읽히지만
**귀에는 문장이 끊긴 것처럼 들린다** — rules.7 이 말하는 "소리 내어 읽어 걸리는 자리"다.
길이도 함께 줄어드는 대안: **"다음은 4편 2부예요. 쉬는 걸 만들었더니."**(21자 ≈ 3.13초)
또는 **"다음은 4편 2부, 쉬는 걸 만들었더니 생긴 일이에요."**(길어지므로 비권장).
사실관계는 그대로 유지된다.
