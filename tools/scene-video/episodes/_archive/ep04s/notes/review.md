### 2-2. `kinds/sidedoor.js` — 코드로 직접 확인했다

**(a) `draw` 가 순수 함수인가** 🟢
- `Math.random()` · `Date.now()` · `performance.now()` · `new Date` **0건**. `lib.js` 의 `rnd` 도 안 부른다.
- 모듈 스코프에 `let`/`var` 이 **0개** — 상수 셋(`FLOW = 2.8`, `WANDER = 4.2`,
  `BAR_PERIOD = [2.4, 2.9, 3.5]`, `BAR_OFFSET = [0, 0.9, 1.8]`)뿐이라 **이전 프레임 기억이 없다.**
- 그리는 값이 전부 `t` · `cue` · `spec` 에서만 나온다. 쓰는 함수(`frac`·`ease`·`clamp`·`lerp`·
  `spring`)는 `lib.js` 의 순수 수식이다.
- `check.mjs` 의 결정성 3패스(정순·역순·건너뛰기)가 **1039프레임 불일치 0** 으로 뒷받침한다.

**(b) 그 구간을 이번엔 무엇이 메우는가 — 작성팀 설명 말고 코드로**

1차의 구조 진단은 옳았다: `sk`/`ek`/`dk` 는 `span 0.6` 이라 각 자막의 60% 지점에서 1.0 으로
포화하고, 그 뒤부터 다음 `cue` 까지가 매 자막마다 남는다. 배회 점은 지금도 **`dk > 0.25`(217행)라
자막 0·1번 구간엔 없다** — 이 문턱은 그대로다. 그러니 그 자리를 메우는 것은 새로 들어온
**62~96행의 진행 막대**뿐이고, 실제로 그렇다:

```js
const u = frac((t + BAR_OFFSET[i]) / BAR_PERIOD[i]);   // 76행 — cue 아님, t 만
const full = tx - gx - 3;                              // 77행 — 목표선까지의 거리
const fl = u < 0.18 ? 1 - u / 0.18 : 0;                // 80행 — 리셋 직후 칸 전체 섬광
roundRect(ctx, gx + 3, y + 3, Math.max(2.5, full * u), 14, 2);  // 88행
```

- **`cue` 가 아니라 `t` 에 물려 있다** → 자막 진행도와 무관하게 **첫 프레임부터 끝까지** 돈다.
  세 줄이 무조건 그려진다(`sk` 게이트 밖, 62행 `for` 문에 조건이 없다).
- 폭이 `full = tx − gx − 3`, `tx = 118 − 6i` → **107 · 101 · 95px**. 1차가 지적한
  35px 표식의 **3배**이고, 높이 14px 를 곱하면 매 프레임 바뀌는 면적이 비교가 안 된다.
- 속도는 `full / 주기` = **44.6 · 34.8 · 27.1 px/초** → FPS 5 샘플 간격(0.2초)마다
  **8.9 · 7.0 · 5.4px** 씩 움직인다. 문턱을 넘기는 것이 이 값이다.
- 주기 2.4 / 2.9 / 3.5 초가 서로 배수가 아니고 오프셋(0 / 0.9 / 1.8)까지 갈라져 있어
  **세 줄이 동시에 리셋되지 않는다.** 한 줄이 섬광 구간(주기의 18%)에 들어가도 나머지 둘이 자란다.
- 사건이 `t` 에 물린 것 아닌가 — 아니다. **이 샷에는 `sfx` 가 없고**(무음 샷 다섯 중 하나),
  자막이 부르는 사건(옆문·배회·이탈)은 전부 `dk` 에 물려 있다. `t` 로 도는 것은 장식뿐이라
  1차 5-(a) 의 판정("사건이 `t` 에 물린 곳 0건")이 유지된다.

**(c) 실물 프레임으로 확인** — 크로미움에서 S3 을 5시점(38.2 / 39.4 / 40.6 / 45.0 / 51.0초)
렌더해 눈으로 봤다. 세 막대가 서로 다른 위상으로 차오르고, 40.15초에 첫 줄이 목표선 눈금에
정확히 닿는다(`u=1` 에서 오른쪽 끝 = `tx`, 계산과 일치). 리셋 직후엔 칸 전체가 회색으로 뜬다.

### 왜 S2·S6·S10 은 통과인데 S3 만 반려인가

- **선례로 닫힌 범위**: ep03s(승인) S5 3.6s · S6 3.2s · S10 3.8s, ep02s(발행분) S4 3.4s.

- 🔴 **경계가 아니라 완전한 정지다.** S2 의 최저 밝기차는 0.000407 로 문턱(0.0008)의 절반이라

  (S10 의 0.000000 은 아예 동일 프레임인데, 첫 자막 동안 재고 막대가 아직 안 떠서
  움직일 것이 하나도 없는 구간이다 — 길이가 3.4초라 선례 범위로 넘긴다.)

판정 근거는 전부 리포 안에서 가져왔다 — 한도 3초는 `check.mjs` 의 점검 항목이고,
비교 대상은 이 리포의 승인된 회차들이다.

### 원인 — 작성팀이 적어 둔 대책이 실제로는 작동하지 않는다

`notes.정적_구간_대책` 은 sidedoor 의 상시 동작을 이렇게 적었다:

> sidedoor(위 경로를 흐르는 표식 + 배회 노드 안을 도는 주민)

코드를 열어 보면 그 둘이 전부다(`kinds/sidedoor.js`):

- **표식** (108~118행): `frac(t / FLOW)` 로 도는 **7×5px 사각형**. 경로 총 길이는
  `legA + legB = (158−140) + (266−250) = 34px` — 352px 폭 캔버스에서 **좌우 10%도 못 간다.**
- **배회 점** (203~208행): 반지름 3.5px 원. 게다가 `dk > 0.25` 조건이라 **셋째 자막이
  시작한 뒤에야 뜬다** — 정적 구간(자막 0·1번 구간)에는 존재하지도 않는다.

즉 정적 구간 동안 화면에서 움직이는 것은 **35px짜리 점 하나뿐**이고, 그 크기가
이 프로젝트 자신의 검출 바닥보다 18배 작다. 대책이 있는 게 아니라 없는 것이다.

구조적으로는 이렇다 — `sk`/`ek` 는 `span 0.6` 이라 각 자막의 60% 지점에서 이미 1.0 으로
포화한다. 포화한 뒤부터 다음 `cue` 가 열릴 때까지가 매 자막마다 남고, S3 은 그게 자막 둘에
걸쳐 연달아 이어지면서 9.2초로 합쳐졌다. **`cue` 를 다 쓰고 남는 자리를 `t` 기반 장식이
메워야 하는데 그 장식이 너무 작다.**

이건 ep03s 검수가 다음 회차에 남긴 경고와 정확히 같은 자리다
(`notes/cloud-pixel-check.md`: *"이 셋은 그림이 cue 를 다 쓰고 난 뒤 자막만 남는 구간이라,
t 기반 장식이 그 자리를 못 메우고 있다는 뜻이다"*). 그 경고가 이번에 3배로 커져 돌아왔다.

### 고칠 방향 (대본을 다시 쓰라는 뜻이 아니다)

S3 한 샷의 그림 문제다. 예를 들어 — 위 goal 셋의 **진행 막대가 목표선을 향해 계속 차오르다
리셋되게** 하거나(달성이 있다는 뜻 자체가 움직임이 된다), 표식을 goal 셋의 경로 **세 줄에

### 5. `cue` / `t` / 파생 문턱 — 어긋난 곳 없음 🟢

**(a) `t` 로 도는 조건** — `kinds/*.js` 12개에서 `frac(t/…)`·`sin(t…)` 를 전부 뽑아
19곳을 하나씩 확인했다. **전부 장식 루프다**(검사선·걸음·호흡·불꽃·김·빗금·점선 흐름·
선택 링 회전). **사건이 `t` 에 물린 곳은 0건이고, `sfx` 가 `t` 조건에 물린 곳도 0건**이다.
ep02s `tripwire` 같은 사고는 없다.

**(b) 다른 `cue` 에서 파생된 문턱** — 12개 kind 의 파생 문턱을 전수 추적했다.
**모든 문턱이 자기 샷의 자기 `cue` 변수에서만 나온다.** ep00i `runmark` 같은 교차 파생은
0건이다. 유일하게 둘을 섞는 곳이 `blindspot.js` 103행

```js
const kk = clamp((sk - 0.4) / 0.5) * (1 - clamp(fk * 1.6));
```

인데, `sk`(자막 1 "쉬어도 안 풀리면요?")가 띄운 문구를 `fk`(자막 2 "그래서 −2, −4를
줬어요")가 **지우는** 것이라 의미가 맞다. 통과.

**(c) 초로 환산한 검증** — `W = lead + rel[i].dur × span`, 시각 = `p × W − lead`.
`ease` 역함수는 이분탐색으로 풀었다(작성팀이 흔히 쓰는 `0.729` 오류 확인용).

|---|---|---|---|---|
| S1 thud | 못이 절반 박힘 | zk 0.45 → **0.466** | +0.755 | 🟢 자막 2번 안(3.59s) |

🟢 **작성팀의 `ease` 역함수가 전부 정확하다** — 내가 이분탐색으로 다시 푼 값과

여러 회차에서 반복되던 `0.729` 오류가 이번엔 없다.

⚠️ `delayMs` 는 절대 ms 라 **`timed.json` 이 나오면 다시 계산해야 한다.** 각 `why` 에
창 계산식이 그대로 적혀 있어 재계산은 가능하다. `cue` 로 도는 사건 자체는 자막에 정규화돼
있어 실측 길이가 달라져도 물림이 깨지지 않는다.

**(d) `cue` 인덱스 분리** — S7 이 상태 칸(1)/문턱 숫자(2)를, S8 이 꽂힘(0)/이웃(1)/이탈(2)/
복귀(3)를 나눠 쓴 것은 옳다. 한 `cue` 로 묶었으면 숫자가 나레이션보다 한 줄 앞섰을 것이다.
