## 🟢 2. S2 의 sfx `delayMs` 는 그대로 맞다 — 직접 확인했다

**작성팀 판단이 옳다.** 근거를 코드로 닫았다:

- `render.mjs:111` — `at = Math.round((line.t + (s.delayMs ?? 0)) / 1000 * rate)`.
  `delayMs` 는 **그 자막(`at: 2`)의 시작 기준**이지 샷 시작 기준이 아니다.
- `engine/engine.js:240-245` — `cue(i, lead, span)` 의 창은 `a = l.t - lead`, `b = l.t + l.dur*span`.
  둘 다 **자막 i 자신의 `t`·`dur`** 로만 만들어진다. 자막 0·1 이 길어지면 `l.t` 가 통째로 밀리지만
  `ts - l.t` (자막 시작 기준 경과)는 안 변한다.

그래서 자막 2("이 차이 하나 위에…", 29자 · pause 600 — **손대지 않았다**)로 다시 유도했다:

```
W  = 0.15 + 4.9284 × 0.55 = 2.8606s
착지 sk = 0.55  →  smoothstep⁻¹ = 0.5335
t  = 0.5335 × 2.8606 − 0.15 = 1.376s  = 1,380ms  ✅ (씬 값과 일치)
```

같은 방법으로 S3 = 2,107ms(씬 2,100 ✅) · S9 = 2,644ms(씬 2,640 ✅). 셋 다 붙은 자막을 안 건드렸으니
유도가 살아 있다. gain 도 그대로 안전권이다 — tick 0.056 < **0.065**, thud 0.070 < **0.085**.

### ③ — 기존 줄 안에서 이은 처리가 **더 낫다**

새 자막을 세우지 않고 S8 자막 0 을 `"집은 그 사이에 지었고요. 정작 남은 작업은 한 파일이었어요."`
로 이은 것은 내가 권한 안(ⓐ 새 줄 추가)보다 낫다. cue 가 안 붙는 자막이 생기는 문제를 피하면서
**그림이 그 말과 같은 순간에 도착**하기 때문이다. 계산으로 확인했다:

```
자막 0: say 34자 + pause 200ms → dur 5.275s,  W = 0.15 + 5.275×0.6 = 3.315s
movein.js:102  집·모닥불·주민이 그려지기 시작하는 fk > 0.35
   → smoothstep⁻¹(0.35) = 0.4076  →  0.4076 × 3.315 − 0.15 = +1.06s
"집은 그 사이에 지었고요." 는 0 → 약 2.09s (14자 ÷ 6.7)
```

즉 **집이 화면에 서는 순간(+1.06초)이 "집은 … 지었고요"를 말하는 한가운데다.** S1 이 점선으로
열어 둔 '집' 칸이 회수됐다. 가이드 한도(±20프레임 = 0.67초)를 이 자리에서 재는 것은 아니지만,
자막 시작과 그림 등장이 같은 문장 안에 들어온다.

원문 근거도 있다 — 14행 "**집을 완공하고** 마지막으로 남은 작업은 사실 **한 파일짜리**였습니다."
'그 사이에'는 수치·고유명사가 아닌 서사 접속이라 지어낸 사실이 아니다.

⚠️ 남은 칸 하나: S1 이 연 **'밭'** 은 이 편에서 회수되지 않는다(1차 리포트와 동일 판단 —
치명적이지 않다. 밭은 `ep05s2` sprout 가 받고 양쪽 blurb 가 서로를 가리킨다).

## 🟡 C-4. 자막 `text` 에 한글 수사가 들어갔다 — 리포에서 여기 한 자리뿐

R-1 수정이 `say` 뿐 아니라 **`text` 까지** 한글 수사로 바꿨다.

```
before  text "…날 것을 먹으면 포만감 3."      say "…포만감 삼."
after   text "…날 것을 먹으면 포만감 소비 삼."  say "…포만감 소비 삼."
before  text "요리해서 먹으면 2고요. / 차이는 딱 1이에요."
after   text "요리해서 먹으면 소비 이고요. / 차이는 딱 일이에요."
```

8회차 전 `scene.json` 의 `text`/`say` 쌍을 기계로 훑었다 — **말로 푼 수사가 자막 text 에 들어간
것은 이 두 줄이 유일하다.** 같은 씬 안에서도 관행이 깨진다:

- S9: `text "에셋 1개, 코드 0줄."` / `say "에셋 한 개, 코드 영 줄."` ← 정상
- S9: `text "M2 요리에서 한 번,"` / `say "엠투 요리에서 한 번,"` ← 정상
- S2: `text`·`say` 가 동일 ← 여기만 다르다

그리고 **화면은 숫자로 그린다** — `hairline.js:75` `ctx.fillText(String(value), …)` 로 탑에 `3`·`2`,
`:99-101` 로 `차이 1`. 자막은 "소비 삼 / 소비 이 / 딱 일"이라 시청자가 읽는 글자와 보는 글자가
표기부터 갈린다. R-1 이 되살리려던 **말↔그림의 결합**을 표기에서 다시 약하게 만든다.
`notes.pacing` 도 rules.4 를 "**say 에서** 3·2·1 을 '삼·이·일'로"라고 적어 두었다 — 원래 의도가
`say` 한정이었다는 증거다.

**요구:** `text` 만 숫자로 되돌릴 것. `say` 는 지금 그대로 둔다.

```
text "첫 결정은 숫자 하나였어요.\n날 것을 먹으면 포만감 소비 3."
text "요리해서 먹으면 소비 2고요.\n차이는 딱 1이에요."
```

(글자 수가 줄어 S2 자막 0 이 34자 → 32자가 된다. **`say` 는 안 바뀌므로 길이·delayMs 는 그대로다** —
자막 길이 계산은 `check.mjs:73`·`engine.js:151` 모두 `say` 를 우선으로 쓴다.)
