# 반려 사유

## 1. 🔴 S7 — 얼음은 깼지만 **처방의 절반만 들어갔고, `reads` 는 여전히 거짓이다**

### 1-A. m 재측정 — 지시가 물은 그대로 (`check.mjs:216~222` 복제, 5fps 전 프레임)

**m 은 0.000000 을 벗어났다.** 이건 사실이다.

| 엔진시각 | 1차본 m | 현재 m | 임계 0.0008 대비 |
|---|---|---|---|
| S7 36.0 ~ 38.8s (15프레임) | **0.000000** | **0.000747 평균** | **0.93배 — 여전히 미달** |

전 프레임 덤프(현재):

```
S7  35.80  0.000949
S7  36.00  0.000770  STATIC   ← 여기서부터
S7  36.20  0.000770  STATIC
S7  36.40  0.000773  STATIC
S7  36.60  0.000769  STATIC
S7  36.80  0.000591  STATIC
S7  37.00  0.000773  STATIC
   …  (15프레임 연속 STATIC)  …
S7  38.80  0.000773  STATIC
S7  39.00  0.002617          ← mk 가 들어오며 선 알파가 0.75→1.0 으로 뛴 한 프레임
S7  39.20  0.000673  STATIC
```

바이트 동일은 아니다 — 점 둘이 실제로 움직인다. 하지만 **`check.mjs` 의 눈에는 15프레임
연속 정적**이고, 그것이 곧 3.0초다. 게이트를 **간신히** 통과했다.

### 1-B. 면적 산술은 맞았다 — 다만 **점만 넣은 쪽에 맞았다**

지시가 물은 항목이다. 1차 리포트의 표를 다시 붙이면:

| 넣은 것 | 예측 m | 실측 m | 오차 |
|---|---|---|---|
| 점 둘만 (201px²) | 0.00068 | **0.000747** | +10% ✅ 모델 유효 |
| 점 + 흐르는 통행선 (420px²) | 0.00142 | (§1-D 실험) **0.002764** | 예측이 **1.9배 보수적** |

즉 **작성팀이 넣은 것은 「점만」이다.** 1차 리포트 142행에 이렇게 적어 두었다:

> *"점만 살리면 0.00068 로 **임계 미달**이다. 선까지 흘려야 한다 — 그래서 둘 다 적었다."*

실측 0.000747 이 그 예측과 10% 안에서 맞았다는 것이, 곧 **선이 안 들어갔다는 증거**다.

### 1-C. 🔴 `reads` 는 아직 거짓이다 — 그리고 **새 주석이 거짓을 하나 더 얹었다**

`quota.js:89~90` 은 1차본과 동일하다:

```js
ctx.moveTo(16, PATH_Y); ctx.lineTo(HX, PATH_Y);          // 16 → 132
ctx.moveTo(HX + HW, PATH_Y); ctx.lineTo(w - 16, PATH_Y); // 220 → 336
```

x 132~220 은 집이 서는 자리다. **선은 처음 뜨는 프레임부터 이미 그 구간이 없다.**
`mk` 로 넘어가며 새로 생기는 것은 ✕ 둘과 `standNote` 뿐이다.

스틸 두 장으로 확정했다:

| 시각 | 자막 | 통행선 상태 |
|---|---|---|
| 36.0s | 자막0 "집을 지으니까 문제가 한꺼번에 터졌어요" | **이미 집 좌우에서 끊겨 있음** |
| 42.0s | 자막1 "건물은 통행을 막는데, 주민이 갇히면 안 되잖아요" | 같은 자리에 ✕ 만 추가 |

→ `scene.json` S7 `reads` 의 **"마을을 가로지르던 통행선이 집 테두리에 닿아 끊기고"** 는
두 절 다 화면에 없다. **가로지른 적도 없고, 끊기는 순간도 없다.**

🔴 그리고 새로 쓴 `quota.js:83` 이 **없는 사실을 하나 더 선언한다**:

> `이제 선과 점은 bk(자막 0)부터 있고 ✕(끊김)만 mk 에 남는다 — 그래야 reads 의
> "마을을 가로지르던 통행선"이 참이 되고, **끊기지 않은 길 위로 집이 떨어진다.**`

앞 절(선과 점이 bk 부터)은 참이고, **뒤 두 절은 거짓**이다. 20행 주석의 자기보고 오류를
고치라고 반려했는데, 그 자리에 **같은 종류의 자기보고 오류가 새로 생겼다.**
ep04s2 §4-E 와 1차 리포트 §1 과 **정확히 같은 결함이 3연속**이다.

### 1-D. 처방 — 이번엔 예측이 아니라 **실험으로 닫았다**

임시 회차 `eprevtmp` 를 만들어 처방을 실제로 적용하고 `check.mjs` 까지 돌렸다(검수 후 삭제).
바꾼 것은 **통행선 그리는 6줄뿐**이다:

```js
ctx.strokeStyle = tone('ink'); ctx.lineWidth = 3;
const cut = mk > 0.02 ? clamp((mk - 0.3) / 0.4) : 0;   // 끊기는 정도
ctx.setLineDash([8, 6]); ctx.lineDashOffset = -(t * 11) % 14;
ctx.beginPath();
ctx.moveTo(16, PATH_Y);                        ctx.lineTo(lerp(HX + HW / 2, HX,      cut), PATH_Y);
ctx.moveTo(lerp(HX + HW / 2, HX + HW, cut), PATH_Y); ctx.lineTo(w - 16, PATH_Y);
ctx.stroke();
ctx.setLineDash([]); ctx.lineDashOffset = 0;
// 아래 ✕ 블록의 게이트도 같은 값을 쓴다: const xk = cut;
```

`cut = 0` 이면 두 토막이 집 한가운데(HX+HW/2)에서 만나 **한 줄로 이어진다.**
`mk` 가 오면 양쪽이 집 테두리(HX · HX+HW)까지 물러나며 **끊긴다.** ✕ 는 그 위에 그대로 얹힌다.

실측 결과:

| | 현재 제출본 | 실험본 |
|---|---|---|
| S7 자막0 구간 m (36.0~38.8s 평균) | 0.000747 (임계의 **0.93배**) | **0.002764 (임계의 3.46배)** |
| `check.mjs` 최대 정적 구간 | **3.0s** (게이트 경계) | **1.0s** |
| 결정성 3패스 | 불일치 0 | **불일치 0** |
| 3색 팔레트 · 좌우/아래 가장자리 | 위반 없음 | **위반 없음** |
| `reads` 첫 문장 | 거짓 | **참** (스틸 확인: 36.0s 이어진 길 → 42.0s 끊김 + ✕) |

**여유가 3.46배**라 실측 TTS(자막이 짧아짐)로 넘어가도 안전하다.
`lineDashOffset` 은 `t` 의 함수라 결정성도 깨지 않는다(3패스 0 확인).

⚠️ 이 코드를 그대로 쓰라는 뜻은 아니다. **조건은 둘뿐**이다 —
① 자막0 구간에 통행선이 **이어져 있을 것**, ② 자막1 에 **끊기는 사건이 일어날 것**.
어떻게 하든 `reads` 와 주석이 화면과 같으면 된다.

## 2. 🔴 S7 `sfx.why` — 거짓을 정정하면서 **새 거짓 숫자 둘을 넣었다**

정정문을 남기고 원문장을 보존한 형식은 좋다. 그런데 정정문 자체가 틀렸다.

작성팀이 새로 붙인 문장:

> "가장 가까운 것은 ep03s S5 의 latch dur 0.16(chapter 해결)이라
> **이 편(0.15·해결)** 과 **dur 0.01 차**다."

리포 전 회차 `shot.sfx` 를 기계로 다시 뽑았다:

```
ep02s       S8   latch dur=(기본) gain=0.036  chapter=증명
ep03s       S5   latch dur=0.16   gain=0.068  chapter=해결
ep05s2      S7   latch dur=0.13   gain=0.066  chapter=해결
eptest-m11  S10  latch dur=(기본) gain=0.068  chapter=해결
```

- **이 편의 latch dur 은 0.13 이다.** `scene.json` S7 `sfx[0].dur = 0.13` — 같은 객체 안에 적혀 있다.
  정정문이 **폐기한다고 선언한 바로 그 숫자(0.15)를 자기 값으로 다시 쓴다.**
- 따라서 차이는 **0.16 − 0.13 = 0.03** 이지 0.01 이 아니다.

→ 두 숫자를 실제 값으로 고쳐라. 예: *"가장 가까운 것은 ep03s S5 의 latch(dur 0.16 · chapter 해결)
이고, 이 편은 dur 0.13 이라 0.03 짧다."*
🟢 **배치·`delayMs`·`gain` 은 손대지 마라** — 1차 검수에서 무경고 상한 0.0702 를 재현했고
값이 소수 넷째 자리까지 맞았다. 지금도 `⚠️ sfx …: 피크 천장에 걸려` 는 0건이다.
🟢 **돌려막기도 아니다** — 가장 가까운 latch 가 두 회차 떨어져 있고 장치도 다르다(카드에 걸쇠 ↔ 문에 빗장).

## 6. chapter 칩이 첫 프레임부터 「해결」인 것 — **반려하지 않는다**

리포 전 회차의 chapter 배열을 뽑았다:

```

ep04s       사건 증명 증명 해결 결과
ep04s2      해결 해결 해결 해결 해결          ← 승인된 분할 2편
ep05s       사건 사건 해결 증명 증명
ep05s2      해결 해결 해결 해결 결과          ← 이 편
```

**`ep04s2` 가 「해결」 다섯으로 이미 승인됐다.** 이 편은 마지막이 「결과」라 그보다 낫다.
