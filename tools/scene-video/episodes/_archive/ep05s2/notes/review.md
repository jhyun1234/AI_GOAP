# 반려 사유

## 1. 🔴 S7 — **이 편의 클라이맥스가 3.0초 동안 완전히 얼어붙는다**

파견 지시가 물은 「정적 구간 S7 3.8s」다. **원인은 ②(움직이는 게 작아서)가 아니라
①(아무것도 안 움직인다)이고, 프레임 간 차이가 정확히 0 이다.**

`check.mjs:216~222` 의 판정식을 복제해 5fps 전 프레임의 `m`(프레임간 평균 휘도차)을 직접 덤프했다:

```
샷    엔진시각   m
S7    35.6s     0.001696
S7    35.8s     0.000000  ← 여기서부터
S7    36.0s     0.000000
  …               …        (16프레임 연속 m = 0.000000)
S7    38.8s     0.000000
S7    39.0s     0.000323  ← 다음 자막 cue 가 들어오며 되살아난다
```

**m = 0.000000 은 "작아서 안 잡힌다"가 아니라 캔버스가 바이트 단위로 동일하다는 뜻이다.**
3.0초 동안 영상이 아니라 정지 사진이다. 스틸(37.0s)을 떠서 눈으로도 확인했다 — 집 한 채가
화면 위쪽에 떠 있고 아래 절반은 전부 검정이다.

**원인은 코드에 있다.** `quota.js` 는 이 편의 「계속 도는 것」을 셋 다 `mk`(cue 1)·`qk`(cue 2)
뒤에 가둬 놨다:

| 움직이는 요소 | `quota.js` | 게이트 |
|---|---|---|
| 끊긴 통행선 앞 되돌아가는 점 `frac(t/2.4)` | 99~103행 | `if (mk > 0.02)` (78행) |
| 문턱 대시 흐름 `lineDashOffset = -(t*11)%14` | 129행 | `if (qk > 0.02)` (123행) |
| 물러난 일꾼 걸음 `frac(t/1.3)` | 151행 | `if (qk > 0.02)` (123행) |

자막0 구간에는 `bk`(cue 0)만 산다. `bk` 는 집을 스프링으로 한 번 앉히고 나면 `clamp(bk*2)`·
`spring(bk*1.3)` 이 둘 다 포화해 **완전한 정적 그림**이 된다.

🔴 그런데 `quota.js:20` 은 이렇게 적어 놓았다:

> `계속 도는 것 = 물러난 일꾼들의 걸음, 끊긴 통행선 앞에서 되돌아 흐르는 점.`

**둘 다 샷의 첫 3분의 1 동안 존재하지 않는다.** ep04s2 §4-E 에서 잡은 것과 **같은 종류의
자기보고 오류**다(`relative.js` 가 "재고 막대 안을 흐르는 빗금"을 적어 놓고 자막0 구간에는
안 그렸다). 거기서는 10번째 샷이었지만 **여기는 이 편의 클라이맥스이고 훅이 나온 자리**다.

### 🔴 그리고 이 경고는 렌더 기계에서 사라질 수 있다 — 그래도 결함은 남는다

`check.mjs` 가 `timed.json` 없이 돌면 엔진의 잠정 길이(`provisionalDur`)를 쓴다. 그 타임라인에서
S7 자막0 은 4.609초이고 정지 구간은 그 **34% 지점부터 끝까지**다. 실측 TTS 로는 자막0 이
3.46초쯤(6.7자/초 기준)이므로 같은 비율이면 **정지 2.28초** — 3초 게이트를 안 넘는다.
즉 **로컬에서 렌더하면 ⚠ 가 사라지는데 화면은 그대로 얼어 있다.** 경고가 없어졌다고 고쳤다고
보지 마라.

### 처방 — 통행선을 `bk` 로 올린다 (자막을 지우지 않는다 · 이야기도 좋아진다)

`quota.js` 78행의 블록을 둘로 가른다.

- **`bk` 에 그린다**: 통행선 본체(16→HX, HX+HW→w−16) + 그 위를 되돌아 흐르는 점 둘.
  **끊기지 않은 채로**, 그리고 선을 `setLineDash([8,6])` + `lineDashOffset = -(t*11)%14` 로
  흐르게 한다(문턱과 같은 장치가 이미 129행에 있다).
- **`mk` 에 남긴다**: 선을 끊는 것, ✕ 둘, `BlocksMovement` 라벨, `standNote`.

**면적 산술**(메모리 `review-method-static-motion-floor` 의 보정값 — 168px² 완전 변위 ≈ m 0.00057):

| 요소 | 0.2초당 바뀌는 잉크 | 기여 m |
|---|---|---|
| 점 둘(r 4, 최대 125.7px/s → 완전 변위) | 2점 × 2자리 × π·4² = **201px²** | 0.00068 |
| 대시 흐르는 통행선(길이 232 · 폭 3 · 주기 14 · 11px/s) | 2 × 2.2 × 3 × 16.6 = **219px²** | 0.00074 |
| **합** | **420px²** | **≈ 0.00142 = 임계의 1.78배** ✅ |

점만 살리면 0.00068 로 **임계 미달**이다. 선까지 흘려야 한다 — 그래서 둘 다 적었다.

🟢 **이야기도 이쪽이 맞다.** 지금은 자막0 "집을 지으니까 문제가 한꺼번에 터졌어요" 에
집만 뜨고, 자막1 "건물은 통행을 막는데" 에 선과 ✕가 **동시에** 나타난다. 즉 시청자는 끊기기
전의 길을 한 번도 못 본다. 위 처방이면 **살아 있는 길 위에 집이 떨어지고 → 길이 끊긴다** 가
되어 `reads` 의 첫 문장("마을을 가로지르던 통행선이 집 테두리에 닿아 끊기고")이 비로소 참이 된다.
지금 `reads` 는 "가로지르던"이라고 과거형으로 적었는데 **가로지른 적이 없다.**

## 2. 🔴 원문이 괄호로 이름 붙인 개념 「앵커」가 이 편에서 사라졌다

검수 지침 3번 — *"원문이 이름 붙인 개념(용어·별명·한 문장 규칙)이 버려지지 않았는가 —
1편에서 실제로 놓친 적이 있습니다."* 그 항목이다. 그리고 ep04s2 §4-B 에서 잡은 용어와
**글자 그대로 같은 단어**다.

원문은 이 단어를 **정의까지 붙여** 내놓는다(4절 첫 문단):

> "**앵커(주민이 특정 행동을 수행하는 고정 장소)** 를 찾는 코드가 각 Runner마다 따로 생겨나고
> 있었습니다."

이 편에서 「앵커」가 나오는 자리 — 전수:

| 자리 | 문자열 |
|---|---|
| S6 자막0 | "**앵커** 찾는 코드가 Runner마다 따로 자랐어요." |
| S6 자막1 `say` | "**앵커 타일 찾기**, 창구 하나로 합쳤고요." |
| S6 자막2 | "이제 새 **앵커**가 늘어도 Runner는 안 건드려요." |
| S6 `spec.piece` | "앵커 찾기" |
| S6 `spec.newAnchor` | "새 앵커 — 집" |

**정의는 자막에도, 화면 문자열에도, `excluded` 에도 없다.** S6 은 11.31초로 이 편의 **23%** 이고,
그 11초를 정의되지 않은 기술 명사 하나가 통째로 진다.

🔴 **분할이 이걸 악화시켰다.** 1차본에서도 정의는 없었지만 S8 `movein` 이 구체 사례를 줬다 —
*"모닥불 옆에서 쉬기. 그 **앵커**를 집으로 옮겼어요."*(현 `ep05s/scene.json` S8). 그 샷이 1편으로
갔으므로 **1편에는 사례만 있고 정의가 없고, 2편에는 추상만 있고 사례가 없다.**
2편만 본 사람에게 앵커는 끝까지 안 갚는 빚이다.

### 처방 ⓑ 를 권한다 — 화면 문자열 한 줄. 0초 든다

`wicket.js` 는 위쪽 y 0~48 이 통째로 비어 있다(`dupNote` 가 y 48, `RY[0]` 상자가 y 60,
`newAnchor` 칩은 x 209~349 · y 38~64 라 왼쪽과 안 겹친다). 거기에 `dk` 게이트로 한 줄 넣는다.

```js
// scene.json S6.spec
"anchorDef": "앵커 = 주민이 특정 행동을 하는 고정 장소"

// wicket.js — dupNote 블록(42~49행) 바로 위
if (dk > 0.02 && spec.anchorDef) {
  ctx.globalAlpha = clamp(dk * 2);
  ctx.textAlign = 'left';
  const fs = fit(spec.anchorDef, 700, 10.5, w - 26, 8);
  ctx.font = disp(700, fs); ctx.fillStyle = tone('sub');
  ctx.fillText(spec.anchorDef, RX + 2, 26);

```

`dk = cue(0)` 이라 **「앵커」가 처음 발음되는 그 자막에 정의가 도착한다.** 원문 괄호의 압축이라
지어낸 말이 0 이고, 길이가 1초도 안 늘고, cue 인덱스를 하나도 안 건드린다.
검수 지침 blind-spot ④(*"화면 문자열이 원문에만 있고 자막에는 없는 것인가"*)에도 정확히 맞다.

**대안 ⓐ** — S6 앞에 자막 한 줄을 더한다(`say: "주민이 행동하는 고정 자리를 앵커라고 해요."`
22자 · 3.28초). 이러면 `mergeCue 1→2`, `addCue 2→3` 으로 시프트해야 하고 `dupCue` 는 0 을
유지해야 한다(안 그러면 새 자막 동안 화면이 비어 또 정적이 된다). 총 53.2초로 게이트에 여유는
크다. 다만 손댈 곳이 많아 ⓑ 를 권한다.

⚠️ **어느 쪽이든 「앵커」를 자막에서 빼는 방향은 안 된다.** 원문이 이름 붙인 개념을 버리는 것이
바로 이 항목이 막으려는 일이다.

## 4. 🔴 S7 `sfx.why` 의 **앞 회차 대조가 사실과 다르다**

배치와 `delayMs` 는 옳다. 정당화하는 사실이 틀렸다(ep04s2 §3 와 같은 종류).

작성팀 주장(`scene.json` S7 `sfx[0].why`):

> "직전 편은 latch 를 **도입의 막 표지에 dur 0.15** 로 썼는데 여기는 0.13 으로 더 짧다"

리포 전 회차의 `shot.sfx` 를 기계로 뽑아 대조했다:

| 회차 | 샷 | kind | dur | chapter | why 요지 |
|---|---|---|---|---|---|
| ep02s | S8 | latch | (기본 0.14) | 증명 | 실선이 걸리는 자리 |
| ep03s | S5 | latch | **0.16** | 해결 | "고른 카드에 걸쇠가 다 걸리는 순간" |
| eptest-m11 | S10 | latch | (기본 0.14) | 해결 | "정착 순서가 확정되는 자리" |
| ep04s / ep04s2 / ep05s | — | **latch 0건** | | | |

- **`dur 0.15` 인 latch 는 이 리포에 없다.**
- **"도입의 막 표지"로 쓴 latch 도 없다** (가장 가까운 ep03s S5 는 chapter 「해결」이고
  카드에 걸쇠가 걸리는 자리다).
- 무엇보다 **직전 편들(ep05s · ep04s2 · ep04s)에는 latch 가 아예 안 나온다.**

### D-1. 「밭」의 유래(요리·생산 체인)가 1편에 있는 것 — **구멍이 아니다**

ep04s2 §1-B(「가장 먼저」의 지시 대상이 없다)와는 **다르다.** 거기서는 자막이 **존재하지 않는
순서**를 가리켰다. 여기 첫 자막 "밭이 화면에서 살아 움직여요"는 **화면이 그 자리에서 전부
갚는다** — 첫 프레임 스틸(0.4s)에 `FarmService` 칩, `Kenmi 밀 스프라이트`, 밀 세 포기가 실제로
자라는 밭이 이미 있다. 시청자가 밖에서 가져와야 할 지식이 0 이다.
「그리고」를 뺀 판단도 옳다 — 그게 남았으면 앞이 잘린 티가 났다.

수수께끼 도착 시각도 규칙 안이다: **6.22초**에 "근데 쿨다운이 긴급 목표까지 막고 있었어요"가
들어온다(10초 규칙 통과). 제목 카드·자기소개 없음. 🟢 콜드 오픈 성립.

🟡 다만 짚어 둔다 — 이 편의 chapter 칩은 **첫 프레임부터 「해결」**이고 끝까지 「해결」×4 +
「결과」×1 이다. 「사건」/「문제」 칩이 한 번도 안 뜬다(1차본의 문제 샷 S1 `worn` 이 1편으로 갔다).
시청자에게 보이는 것은 **무엇을 해결하는지 모른 채 뜨는 「해결」 딱지 6.2초**다.
§1 처방(살아 있는 길 위에 집이 떨어진다)과 §2 처방으로 각 샷 안에 문제가 서면 완화되므로
별도 요구는 하지 않는다.

### D-2. S10 이 마지막으로 적절한가 · 「요리」가 1편 소관인 것 — **적절하다**

- 자막 "이제 밭을 갈고, 요리하고, 집에서 쉬어요"는 **원문 6절 문장 그대로**다
  ("주민들은 이제 밭을 갈고, 요리하고, 집에서 쉽니다"). 인용을 깨면서까지 「요리」를 뺄 이유가 없다.
- 「요리/부엌」이 이 편에서 처음 나오는 것은 맞지만 **아무 지식도 요구하지 않는다.** 마을 사람이
  밥을 짓는다는 한 낱말이고, 화면은 그것을 `부엌` 이라는 노드 하나로 받는다.
  ep04s2 §1-C(화면이 「35 = 명령 거부 임계와 같은 수치」라고 **안 본 편의 값을 주장**한 것)와
  질이 다르다. **이 편의 화면에는 밖의 지식을 요구하는 문자열이 하나도 없다**(전수 확인).
- 오히려 S10 은 이 편의 세 사건을 **전부 회수한다** — 밭(S4) · 집(S7) · 그리고 그 집이 준
  「돌아갈 곳」. 훅도 여기서 마무리된다. 끝맺음으로 맞다.
- 🟢 다섯 샷 중 유일한 「결과」 chapter 이고 고리가 닫히는 그림이라 **자동 루프에도 맞는다.**

### D-3. 그래서 이 편의 진짜 자기완결성 구멍은 **「앵커」 하나**다 (§2)

세 군데를 잡은 ep04s2 와 달리 여기는 하나다. 문구 이식이 깨끗했기 때문이고
(1차본에서 잘라 온 다섯 샷이 각각 자기 문제→해결을 안에 갖고 있다), 그 하나가 하필
**11.31초(전체의 23%)를 지는 샷**이라 반려로 올린다.

## E. 다음 편 예고 — **사실 대조 통과 · 상호 참조 양방향**

정본 둘로만 대조했다(원문의 "다음 편에서는…" 문장은 근거로 쓰지 않았다).

```

```

→ `ep05s` 가 `ep05s2` **앞**이므로 "1부"라 부르는 것이 맞다.

| 예고 문구 | 대조 대상 | 판정 |
|---|---|---|
| "**1부**에선" | `order` 상 ep05s 가 직전 | 🟢 |
| "**코드 영 줄**로" | `ep05s` `hud.title` = "5편 · **코드 0줄**로 늘어난 것" · S3 "씨에스 파일은 한 줄도 추가 안 했고요" · S9 "에셋 한 개, **코드 영 줄**" | 🟢 |

**상호 참조 — 양방향 다 있다** (지침의 `ep04s2` 규약):

- 1편 → 2편: `ep05s` S9 마지막 자막 *"다음은 5편 2부, 집을 지었더니예요."* + blurb
  *"(집을 지으며 터진 문제들은 5편 2부에서)"*
- 2편 → 1편: `ep05s2` S10 마지막 자막 + blurb *"(에셋만 더했는데 기능이 는 이야기는 5편 1부에서)"*

🟡 **마스터에게 남기는 것**: `ep05s` 의 `hud.title`("5편 · 코드 0줄로 늘어난 것")과
`youtube.title`("… 개발일지 5편 #shorts")에는 **"1부"라는 말이 없다.** 2부를 본 사람이
"1부"를 찾으면 "5편"으로 나온 영상을 만난다. ep04s/ep04s2 도 똑같은 상태이고 그건 이미
승인됐으므로 **이 회차의 반려 사유로 쓰지 않는다** — 다만 시리즈 규약으로 정할 문제다.
(`ep05s` 는 아직 `build/` 가 없어 고칠 수 있다.)

  쉼표로 갈린 두 마디다. ep04s2(26자)와 같은 폭. 🟢
- **담화표지**: `근데`×1 · `그래서`×1 · `이제`×2 = 13문장에 4회 ≈ 3.3문장에 하나. 기준 안. 🟢
- **숫자·영문은 말하는 대로**: `P0 → 피제로` · `TryGetAnchorTile → 앵커 타일 찾기` ·
  `Runner → 러너` · `0줄 → 영 줄`. 🟢 (`1부` 만 안 풀었다 — §11)
