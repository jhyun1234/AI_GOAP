## 1. 🔴 반려 ① — `latch` 효과음이 형제 편과 같은 소리다 (|r| 0.8652 > 판정선 0.85)

**측정**: `synth(kind, opts, 48000)` 절대 표본 정렬 상관(리샘플 없음), 기본값 채운 뒤 인자 비교.

| 대상 | 인자 | \|r\| |
|---|---|---|
| **d01s-2 S3** ↔ **d01s-1 S3** | `latch dur 0.245 seed 293` ↔ `latch dur 0.32 seed 283` | **0.8652** 🔴 |
| d01s-2 S3 ↔ ep08s-3/S1 | `dur 0.225 seed 97` | 0.8444 |
| d01s-2 S3 ↔ ep16s-5/S3 | `dur 0.285 seed 271` | 0.8392 |

**통제군**(같은 호출 제거 · seed 동일 쌍 제거 후 **462쌍**): 중앙 0.7563 · 85% 0.7927 · 95% 0.8139 · 최대 0.8745.
🔑 최대 0.8745 도 `d01s-1 × ep16s-5` 라 **d01s-1 이 물고 있는 값**이다 — **발행·승인분끼리의 최대는 0.8408**(`ep08s-1/S4 × lf02/S19`). 즉 0.8652 는 **이 리포에 나간 어떤 쌍보다 높다.**

🔴 **통제군에서 뺀 것을 밝힌다**(오염된 상단을 근거로 「안전하다」가 나오는 것을 막기 위해):
- `latch dur 0.14 seed 7` = `ep02s/S8` · `eptest-m11/S10` → **r = 1.0000** (기본값 채우면 같은 호출)
- 여기에 `ep03s/S5 dur 0.16 seed 7` 이 붙어 셋이 **0.9976~1.0000** — dur 만 달라 「같은 호출」 필터를 빠져나간다.
- `sweep` 도 같다: `seed 11` 기본 4건(`ep02s/S7`·`ep03s/S11`·`ep04s-2/S3`·`eptest-m11/S2`)이 상호 **0.8980~0.9943**.
이 쌍들을 넣으면 두 kind 의 통제군 최댓값이 1.0 로 뛴다 — 전부 뺀 뒤의 값이 위 숫자다.

### 🔴 처방이 `seed` 가 아니다 — 작성 노트의 진단이 반증됐다

`scene.json` S3 `why` 와 `writer.md` §4 가 「latch 에서 파형을 가르는 것은 `seed` 사실상 단독」·
「겹치면 **`seed` 만** 갈면 된다」고 적었다. **`dur 0.245` 를 고정하고 seed 만 바꿔 재면 안 갈린다**:

```
dur 0.245 · 형제(d01s-1 dur0.32 seed283) 대비 |r|
  seed 293 → 0.8652   seed 311 → 0.8453   seed 313 → 0.8481   seed 317 → 0.8590
  seed 331 → 0.8425   seed 347 → 0.8729   seed 7   → 0.8637   seed 997 → 0.8568
```

기제는 `sfx.mjs:73-84` 다 — 몸통이 **340/680Hz 고정**이고 클릭(`r()·exp(−260t)`)만 seed 를 탄다.
`dur` 이 길수록 결정적 몸통의 비중이 커져 **긴 latch 끼리는 무조건 붙는다.** 갈리는 인자는 `dur` 이다:

```
seed 293 을 dur 만 바꿔 재면 (형제 r / 과거 최대)
  0.14 → 0.7558 / 0.7785     0.16 → 0.7882 / 0.8018     0.18 → 0.8138 / 0.8184
  0.20 → 0.8340 / 0.8302     0.225 → 0.8534 / 0.8398    0.245 → 0.8652 / 0.8444  ← 현행
```

**권고 = `dur 0.16` 안팎**(형제 0.7882 · 과거 최대 0.8018 = 깨끗한 통제군 85%대). `seed 293` 은 그대로 둬도 된다.
🔑 `ep15s-2` 가 **정확히 같은 병**으로 2차 반려(0.8587)됐고 `dur` 을 0.255 → 0.12 로 내려 해소했다(0.7958).
🔑 `dur` 을 내리면 소리가 짧아지므로 `delayMs 2250` 은 그대로 쓴다 — 그림 구간(since(0) 2.20~2.85)이 0.65초라 0.16 도 통째로 들어간다.

**함께 정정할 것**: 위 두 주석의 「seed 단독」·「seed 만 갈면 된다」 문장. 다음 회차가 그대로 인용하면 같은 자리에서 또 걸린다.

🟢 `sweep seed 307` 은 문제 없다 — 최근접 **0.0191**(`ep13s-3/S2`), 깨끗한 통제군(184쌍) 중앙 0.0058 · 95% 0.0210 · 최대 0.0359 → 백분위 91%.
🟢 **gain 천장**(`0.46 / (peak/gain)`, `peakCeil:99` 로 실측): `sweep 0.1757`(여유 193%) · `latch 0.0923`(여유 54%). 둘 다 `gain 0.060` 안전, 피크 경고 없음. 작성팀의 「0.09528 보다 조금 낮겠지만 거리는 크게 남는다」는 맞았다.

## 3. 정정 요구 (반려와 함께 돌려보냄 — 재검수 때 같이 본다)

1. 🔴 **`notes.길이` 가 아직 「아직 인용할 실측이 없다」** 상태다. 작성 노트가 스스로 약속한 대로 `check.mjs` 줄을 **그대로** 갈아 끼울 것:
   `총 길이 35.2초 = 자막 33.1 + 꼬리 2.10` · `본문 20.1초` · `예고 3.6초` · `인트로 4.6초`. 자체 계산식은 쓰지 말 것.
2. 🟡 **아웃트로 카드가 「다음 편 · 위험했던 자리를 기억하게 만들 차례」로 굳는다**(스틸 32.3s). `engine.js:321` 이 `다음 편 · ${next}` 를 **하드코딩**한다. 그런데 ADR-D-3 은 dNNs 가 **다음 회차를 예고하지 않는다**고 정했고, 이 편 음성은 그 규약대로 「다음**은**, …할 차례예요」(항목형·예정형)다. 화면만 「다음 **편**」이라고 단정한다.
   → 작성팀이 고를 수 있는 것은 **`outro.next` 를 비우는 것**뿐이다(게이트는 음성 예고만으로 통과한다 — 실제 출력이 「SO 자막 1줄 (음성 예고)」). 엔진에 트랙 인지를 넣는 것은 파이프라인 몫. **마스터 판단을 요청한다.**
3. 🟡 **`youtube.en.title` 실측 80자**(도구 계수). 노트의 「79자(꼬리 29 + 본문 50)」는 1자 틀렸다. **상한 100 이하는 통과**이므로 노트 값만 정정. `en` 에 태그 없음 ✅ · `scene.en.json` 없음 ✅.
4. 🟡 **부등식 사슬이 새 값에서 거짓이다.** `scene.json` `source.note`·`excluded[1]`·`writer.md` §1 세 곳이
   「이 관계는 바뀐 값(**7 < 10 < 14−5 = 9**)에서도 그대로 참」이라고 적었는데 **10 < 9 는 거짓**이다.
   화면이 지는 관계(시야 < 나타나는 데 = **7 < 10**)는 참이라 **영상에는 영향이 없다.** 다만 다음 회차가 이 문장을 근거로 인용하면 그대로 틀리므로, 로그 **717행의 부등식 둘**(「시야 < 부화, 시야 < 회수 − 배회」) 표기로 고쳐 적을 것. (작성팀이 768행의 사슬 표기를 화면에서 뺀 판단 자체는 **옳다** — §4 참조.)
5. 🟡 **형제 두 편의 제목 꼬리가 다르다.** `d01s-1` = 「· Claude Code로 48일차 **· 유니티 GOAP 개발일지** #shorts」 / `d01s-2` = 「· Claude Code로 48일차 #shorts」. 트랙 정본(§ADR-D-7)은 「Claude Code로 N일차」만 규정하므로 둘 다 위반은 아니지만, **같은 주에 나란히 올라가는 2편**이라 통일 권고.
6. 🟡 **blurb 의 앞 편 경로가 서술뿐이다.** 「판 시작 당일에 유령 같은 습격 경보가 뜨고, 맞서라는 명령에 주민이 혼자 죽으러 간 이야기가 앞 편에 있습니다」로 **앞 편을 특정할 수는 있다**(형제 제목과 내용이 일치). 다만 `publish.mjs` 의 자동 형제 안내가 dNNs 에 안 붙으므로(브리프 §10), 앞 편 제목 문장(「마을엔 아무도 안 왔는데 왜 습격 경보가 떴을까요?」)을 그대로 넣으면 검색으로 닿는다. `d01s-1` → `d01s-2` 역방향은 실재한다 ✅.

9. 🟡 **S3 라벨 둘이 캔버스 양 끝 바닥에 있어 어느 원을 가리키는지 이어지지 않는다**(스틸 28.6s). 「보이는 데」가 왼쪽 점선 삼각형에 붙어 읽힐 여지가 있다. **③-a 는 라벨 없이도 읽히므로 통과**이고 이건 취향에 가깝다.

(옛 쌍의 값을 그대로 인용하면 근거가 낡는다.)

| 쌍 | 1차 | 2차 | 판정 |
|---|---|---|---|
| **d01s-2(0.16/293) × d01s-1(0.13/283)** | 0.8652 🔴 | **0.7647** | ✅ 판정선 0.85 한참 아래 |
| d01s-2 × 리포 전체 31건 **최댓값** | 0.8652 | **0.8018** (`ep08s-3/S1`) | ✅ |
| d01s-2 최근접의 통제군 백분위 | 100% | **93%** | ✅ |

**깨끗한 통제군**(같은 호출 + 같은 seed 쌍 제거 · 462쌍): 중앙 **0.7525** · 85% 0.7898 · 95% 0.8119 · 최대 **0.8408**.
- 새 형제 쌍 **0.7647 은 중앙값 바로 위**(백분위 ≈55%) — 「발행된 임의의 두 latch 만큼도 안 닮았다」.
- 최댓값 0.8018 < 통제군 최대 0.8408. 🔑 **그 0.8408 이 이제 발행분끼리의 쌍**(`ep08s-1/S4 × lf02/S19`)이다.
- 🔴 **§5-2 에스컬레이션도 같이 닫혔다** — `d01s-1 × ep16s-5` 가 **0.8745 → 0.7447**.
  즉 **통제군 상단을 오염시키던 미발행 쌍이 사라졌고, 이제 상단이 발행분으로만 이뤄져 있다.**

### 🔴 작성팀이 안 지어낸 값 = 내가 잰다 — `dur 0.16` 의 gain 천장

작성 노트가 *"0.16 의 천장은 아무도 아직 안 쟀다 — 추정치를 지어내지 않는다"* 고 적고 리포 실적
(0.16 대역 다섯 편 무경고 발행)에만 걸었다. **옳은 처리다.** 그 빈칸을 실측으로 채운다
(`synth(kind, {...opt, gain, peakCeil: 99})` 의 반환 파형 피크 · `0.46 / (peak/gain)`):

| 소리 | 설정 | 피크 | 천장 | 여유 |
|---|---|---|---|---|
| **d01s-2 S3 latch** `0.16 / 293` | gain **0.060** | 0.3587 | **0.0769** | **+28%** ✅ |
| d01s-2 S1 sweep `0.62 / 307` | gain 0.060 | 0.1571 | 0.1757 | +193% ✅ |
| (참고) d01s-1 S3 latch `0.13 / 283` | gain 0.062 | 0.3758 | 0.0759 | +22% ✅ |

`dur` 을 내리면 천장이 내려온다는 방향은 그대로다(0.245 에서 0.0923 → 0.16 에서 0.0769).
**둘 다 천장 아래라 피크 경고는 안 뜬다.** `gain` 을 손댈 이유가 없다.

🟡 **사소한 갱신 1건**: `S3.sfx.why` 가 통제군을 「462쌍 · 최대 **0.8745**」로 인용하는데, 그 최댓값은
**형제가 고쳐지면서 사라진 값**이다(현재 최대 0.8408 · 중앙 0.7525). 인용값이 안전한 쪽으로 움직였고
결론(0.8018 이 통제군 안)은 그대로다 — 다음에 이 주석을 볼 때만 고치면 된다.

🟢 `sweep`(0.62/307)은 1차와 동일하고 재측정도 동일 — 최근접 **0.0191**, 통제군 최대 0.0359.

## 7-3. ⓒ `misread.js` 문턱 변경이 정렬 실측을 안 깬다 ✅

변경은 **한 줄**이다 — 가위표 `k = ease(clamp((s1 − **0.25** − i×0.22) / 0.30))`(전 `0.50`). 주석에 사유 기재됨.

- **§4-5 의 소리·그림 정렬은 안 깨진다.** S1 의 `sweep` 은 **line 0**(`at: 0` · `delayMs 400`)에 걸려 있고
  바뀐 문턱은 **line 1**(`s1`)이다 — 서로 다른 원점이라 **닿지 않는다.** 그림 사건(표식 소멸 `since(0) 0.37~1.12`)도 그대로다.
- **§4-6 의 알파 표도 안 깨진다.** 라벨 `la = ease(clamp((s1 − 0.25) / 0.45))` 는 **손대지 않았다** → 「내가 읽은 것」 ≥0.6 시각 `s1 0.506` 유지.
- **새 위치의 발화 대조**: 가위표는 이제 `s1 0.28~0.99` 에 뜬다. 그 줄의 wav 실측 발화는 **0.321~2.210** —
  **같은 줄 안**이고 발화 개시보다 0.04초 앞설 뿐이다(한도 0.67초). ✅
- **겹침도 안 는다** — 좌표는 한 픽셀도 안 바뀌었고, 가위표(150·200·250)가 뜨는 시점에 흰 표식은 이미 292 에 도착해 있다(도착은 `since(0) 1.60` = 훨씬 앞).

### ⚠️ 다만 대가가 있다 — 정적 여유가 0.2초로 줄었다 (통과 · 기록만)

| | 1차 | 2차 |
|---|---|---|
| 정적 최대 (5fps) | 0.8s | **1.2s** |
| 정적 최대 (**30fps = mp4 전 프레임**) | (미측정) | **2.8s** / 한도 3.0s → **여유 0.2s** |

**기제**: 가위표를 0.25초 **앞당긴 만큼 완성 뒤 정지 구간이 뒤로 길어졌다.** S1 은 6.32초짜리인데

🟡 **판정**: 게이트 통과이므로 **반려하지 않는다.** 다만 이 회차에서 **가장 여유가 적은 게이트**이고,
