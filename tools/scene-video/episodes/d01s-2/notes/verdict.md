## 5. ⚖️ 마스터 판단 ⓐ — `engine.js:321` 「다음 편 ·」 하드코딩

### 사실

```js
// tools/scene-video/engine/engine.js:321
$('ocNext').textContent = ocNext ? `다음 편 · ${ocNext}` : '';
```

내가 다시 뜬 **32.3s 스틸**에 아웃트로 카드가 **「다음 편 · 위험했던 자리를 기억하게 만들 차례」**로 3.0초 찍힌다.
음성은 「다음**은**」(항목형·예정형)이고, `nextpeek` 캔버스 라벨도 「**다음 항목**」이다.
**셋 중 카드 하나만 「편」이라고 말한다.**

### 판정 = 🔴 **이대로는 승인하지 않는다. 이행 조건으로 `outro.next` 를 비운다.**

근거 넷.

1. **ADR-D-3 이 금지하는 것의 실질을 어긴다.** 조문의 이유가 괄호에 적혀 있다 — *"다음 소재를 모르는 트랙이다."*
   「다음 편 · X」는 **다음 영상이 X 를 다룬다**는 단정이고, 이 트랙은 그것을 뒷받침할 수 없다.
2. **이번엔 실제로 거짓이 될 공산이 크다.** 채널의 미발행 대기분은 `ep14s`·`ep15s`·`ep16s` **14편**이고
   다음 회차 후보는 `ep17s`(M14 가을과 겨울) 또는 `d02s` 다. **다음 편이 「위험 기억」일 가능성이 낮다.**
   화면의 수는 안 낡게 지켜 놓고(§3) **화면의 문장이 낡는 것**을 두는 것은 앞뒤가 안 맞는다.
3. **작성팀이 고칠 수 있다.** 「기계 파생이라 못 고치니 반려가 아니다」(형제 라벨 수치 선례)가 **여기엔 적용 안 된다** —
   `outro.next` 는 회차가 쥐고 있는 필드다.
4. **`scene.json` 자신이 이미 모순을 안다.** `SO.source` 가 *"예고가 가리키는 것은 「다음 편」이 아니라
   **원문이 이월한 다음 항목**"* 이라고 적어 놓고, 같은 파일의 `outro.next` 가 카드에 「다음 **편**」을 띄운다.

**대가는 거의 없다 — 내가 복제본으로 실측했다.**
`outro.next=""` 로 두면 엔진이 그 줄을 **통째로 안 그리고**(삼항 else `''`), 게이트는 **전부 통과**한다
(「다음 편 예고 있음」은 **음성 자막**으로 이미 만족 · 예고 3.6초 · 카드 넘침 0 · 겹침 0).
예고의 뜻은 **음성 + `nextpeek` 그림 + 그림 라벨 「다음 항목」** 셋이 그대로 진다.

### 🔴 이행 조건 (렌더 전 · 작성팀 → 코디네이터 재검)

1. `outro.next` → **`""`**. **다른 필드는 건드리지 않는다**(자막이 바뀌면 `timed.json` 이 죽는다).
2. `SO.source` 의 「음성·카드·미리보기 셋이 같은 것을 가리킨다」 문장과 `notes.dNNs 특수 규칙 이행` 의
   예고 칸을 **현재 상태로 갱신**한다(카드 줄은 비웠고 사유는 ADR-D-3 ↔ `engine.js:321` 충돌).
   🔴 **노트에 반려/이행 사유가 안 남으면 다음 회차가 그대로 되풀이한다**(유형 ⑯).
3. 재검 = `JSON.parse` → `check.mjs d01s-2` → `check.mjs d01s-2 --fps 30` → `render.mjs d01s-2 --still 32.3`
   (카드에서 초록 줄이 사라졌는지 눈으로 1장). 셋 다 통과면 **재승인 없이 렌더로 간다.**

### 🔧 엔진 개정 제안 (판정서에 남긴다 · 실행은 코디네이터 → 사용자)

**제안**: `engine.js:321` 의 접두를 **트랙 인지**로 바꾼다.

🔴 **형제 판정서를 대조하고 제안을 고쳤다.** `d01s-1` 은 `outro.next` = 「적이 눈앞에서 사라진 이야기」이고
그 편에서는 **다음 편이 실제로 이 편**이라 카드의 「다음 편 ·」이 **참**이다(형제 판정서 = APPROVED, 이 자리 지적 없음 —
**누락이 아니라 그 편에선 문제가 아니었던 것**이다). 그러므로 **`track` 만으로 접두를 갈면 `d01s-1` 이 되레 틀린다.**
가르는 축은 트랙이 아니라 **`outro.next` 가 「형제 편」을 가리키는가 「트랙의 다음 항목」을 가리키는가**다.

```js
// 제안 (마스터 승인 아님 — 사용자 결정 사항)
// outro.nextKind: 'episode'(기본 · 옛 회차 그대로) | 'item'(dNNs 마지막 편처럼 회차가 아닌 이월 항목)
const nextPrefix = (o.nextKind === 'item') ? '다음 항목' : '다음 편';
$('ocNext').textContent = ocNext ? `${nextPrefix} · ${ocNext}` : '';
```

- **왜 지금 제안하나**: 이 충돌은 **모든 dNNs 마지막 편에서 재발**한다. 회차마다 `outro.next` 를 비우는 것은
  「예고 한 줄을 카드에서 영구히 포기」하는 관행이 되고, 그 관행은 **왜 비웠는지 아는 사람이 사라지면 되살아난다.**
- **왜 `track` 분기가 아닌가**: 위 대조 그대로다. `d01s-2/scene.json` 의 `track` 은 `"dNNs"` 이지만
  `d01s-1` 도 같은 트랙이고 그 편의 카드는 **고쳐선 안 된다**. 기본값(`nextKind` 없음 = 「다음 편」)이라
  **기존 44편은 한 글자도 안 바뀐다.**
- 🔗 **형제 판정서의 `ADR-D-3` 개정 제안과 한 묶음으로 올릴 것** — 그쪽은 *①진짜 미래 = 예정형 의무 /
  ②같은 원문에서 이미 닫힌 사건 = 단정형 허용* 을 제안했다. 두 제안을 합치면 dNNs 예고 규약이 이렇게 닫힌다:
  **중간 편 = 형제 편을 가리킴 → 단정형 + 「다음 편」 / 마지막 편 = 트랙의 이월 항목을 가리킴 → 예정형 + 「다음 항목」.**
  파일럿 2편이 그 두 갈래를 하나씩 실물로 냈다.
- **파급 검증 요구**(ep00s 선례 — 엔진 변경은 전편에 걸린다): 개정하면 **연속극 1편 + 롱폼 1편 + dNNs 1편**의
  32~35초 구간 스틸을 떠서 카드가 안 흔들렸는지 확인할 것.
- 🔴 **마스터는 도구를 직접 고치지 않는다.** 이 편의 승인은 **엔진 개정과 무관하게** 위 이행 조건으로 성립한다.
