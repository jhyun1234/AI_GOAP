## 🔴 발행 전 정정 1건 — `notes.staticSegments` 의 수치가 실측과 다르다

씬 파일이 이렇게 단언한다.

> "남은 정적 구간은 전부 3초 상한 안이고…"

**실측은 그렇지 않다.** `check.mjs` 출력:

```
⚠  정적 구간 3초 이하   S7 5.8s, S9 4.4s, S10 3.4s
```

| 샷 | 1차 실측 | `notes` 주장 | 2차 실측 | 상한 대비 |
|---|---|---|---|---|
| S9 | 8.6s | 약 2.9s | **4.4s** | 1.5배 초과 |
| S7 | 7.2s | 약 2.3s | **5.8s** | 1.9배 초과 |
| S10 | 3.6s | 약 2.5s | **3.4s** | 초과 |
| S5 | 3.4s | 약 2.9s | 상한 내 | ✅ |

**개선은 실재한다** — S9 8.6→4.4, S7 7.2→5.8, S5 는 상한 안으로 들어왔다.
문제는 개선폭이 아니라 **씬 파일에 적힌 넷이 전부 실측과 다르고, 그중 셋은 아직 초과**라는 것이다.

**왜 어긋났나(진단).** 작성팀은 "이벤트가 없는 자막 한 줄의 길이"를 정적 구간으로 셌다.
실제 정적 구간은 **앞 자막의 애니메이션이 끝난 시점부터** 다음 이벤트까지다.
S7 을 예로 들면 `strikeCue 1` 의 애니메이션은 자막 1의 전반(`cue` span 0.5~0.75)에서 끝나므로
정적 구간 = **자막 1의 후반 + 자막 2 전체** ≈ 5.8초다. 자막 2만 세면 2.3초가 나온다.

**요구.** `notes.staticSegments` 의 수치 넷을 실측값으로 바꾸고, "전부 상한 안"이라는 문장을
"S7·S9·S10 은 아직 초과이며 kind 가 줄 수 있는 이벤트 수가 상한이다"로 정정할 것.
이 편의 주제가 "실패를 성공이라고 보고하지 않는다"이므로 여기서 넘길 수 없다.

> 정적 구간 초과 **자체**는 반려 사유로 올리지 않는다. 1차에서 확인 항목으로 분류했고,
> `check.mjs` 도 ⚠ 로 둔다. 기준을 사후에 올리지 않는다.

### ✅ 2. S6 도장 잘림 — 해소 (실측)

좌우 가장자리 스캔(캔버스 0열·W-1열의 알파를 100ms 간격으로 계수):

2차: S6 항목 0건

54.8초 프레임에서 "두 배"가 온전히 들어간 것을 눈으로 확인했다.
남은 좌우 접촉은 S5(파편, 선언 예외)와 S7(rule 상자가 `x:0`·`x:w-boxW` 로 설계상 프레임에
맞닿음 — ep01s 도 동일한 엔진 동작), S9(강조 카드의 글로우 번짐)뿐이다. 전부 결함 아님.

**🔴 "두 배"가 열린 고리를 닫는가 — 판정: 닫는다.**

고리는 S1 마지막 자막(7.10s) "이거 하나 고치는 데 커밋 여섯 개 썼어요"에서 열린다.
S6 에서 닫히는 경로를 실측 타임라인으로 따라가면:

| 시각 | 자막 | 화면 |
|---|---|---|
| 49.35s | **"커밋 여섯 개 중에, / 버그를 지운 건 두 개고요."** | 왼쪽 막대 2 가 자람 |
| 53.25s | "나머지 넷은 전부 / 감시 장치였어요." | 오른쪽 막대 4 + 도장 "두 배" |

고리를 닫는 건 **자막 첫 줄이다** — "커밋 여섯 개 중에"가 여섯을 그대로 되받는다.
도장은 고리를 닫는 물건이 아니라 2:4 라는 비율에 도장을 찍는 물건이고, 그건
ep01s 의 "50배"와 정확히 같은 역할이다. 값(2·4)과 라벨이 이미 화면에 있으므로
작성팀 논리가 성립한다. **"여섯 중 넷"이 더 정확했던 건 사실이지만, 잘려서 안 읽히는 5자보다
온전히 박히는 2자가 낫다** — 이 교환은 옳다.

🟡 하나만 기록해 둔다. 도장은 `bars.js` 설계상 **작은 값 쪽(2 막대) 위**에 앉는다.
그 순간 목소리는 "나머지 넷은 전부 감시 장치였어요"라 **"두 배"를 말하지 않는다** —
2 막대 위의 "두 배"가 순간적으로 "이쪽이 두 배"로 읽힐 여지가 있다.
바로 옆 막대가 눈에 띄게 두 배라 실사용에서 오독될 가능성은 낮다고 본다. 다음 회차에서
같은 자리를 쓸 때 자막에 배수를 한 번 얹으면 완전히 닫힌다.

### ✅ 3. S6 등장 순서 — 해소, 잔여 노출은 수용

`b`=버그 2(cue 0, 왼쪽) / `a`=감시 4(cue 1, 오른쪽). `bars.js` 의 `keys=['b','a']` 와 맞물려
**읽기 순서(좌→우)와 나레이션 순서가 같아졌다.**

**잔여 0 노출 실측: 49.35s → 53.25s = 약 3.9초** (1차 5.3초).
숫자만 보면 1.4초 줄었을 뿐이지만, **성질이 뒤집혔다**는 게 요점이다.

- 1차: 아직 0인 칸이 **왼쪽**(먼저 읽는 자리)이고, 목소리는 그때 **오른쪽 값**을 말했다
  → 화면이 "감시 장치 = 0"이라고 **주장**했다.
- 2차: 아직 0인 칸이 **오른쪽**(나중에 읽는 자리)이고, 목소리는 아직 그 칸을 언급하지 않았다
  → "아직 안 왔다"로 읽힌다. 51.0초 프레임에서 15% 밝기의 어두운 0 임을 확인했다.

**수용 가능하다고 판정한다.** 왼쪽부터 자라는 막대 그래프는 표준 문법이고, 남은 건 15% 밝기의
숫자 하나다. 작성팀이 `notes.barsOrder` 에 "🔴 남는 것"으로 스스로 적어 둔 점도 정직하다.

완전히 없애고 싶으면 방법은 있다 — `bars.js` 가 라벨과 숫자를 `k` 와 무관하게 항상 그리므로,
둘의 `globalAlpha` 를 `cue` 에 물리면 아직 안 온 칸은 빈 트랙만 남는다. 급하지 않다.

`guide:true` 를 끈 판단도 동의한다. 기준선은 `gk = small.cue` 에 물려 있어 이 회차에서는
첫 자막에 뜨는데, 그러면 아직 아무것도 안 그려진 칸 안에 초록 선이 먼저 앉는다.
`notes.noGuide` 의 서술이 코드와 일치한다.

### ✅ 변경 ② 도장 자동 축소

오버슈트(1.05)까지 넣어 폭을 재고 넘치면 기준 크기를 줄인다.

```js
const maxW = (Math.min(nx, w - nx) - 4) * 2;
ctx.font = disp(900, Math.round(size * 1.05));
const wide = ctx.measureText(spec.note).width;
if (wide > maxW) size = Math.max(14, Math.floor(size * maxW / wide));
```

- `measureText` 는 결정적이다 → `check.mjs` 결정성 474프레임 불일치 0 ✅
- 가운데 정렬이라 가까운 가장자리까지의 거리 × 2 로 잰 것도 맞다 ✅

🟡 **한 가지만 기록해 둔다.** 폭 계산에 `setShadow(ctx, GLOW, 26, 4)` 의 글로우(blur 26 +
offset 4)가 들어 있지 않다. "두 배"는 여유가 커서 안 걸리지만, 폭이 딱 맞는 문구가 오면
**글자는 안 잘려도 글로우가 잘린다.** 이번 회차 결함은 아니다 — 다음에 긴 도장 문구를 쓸 때
걸릴 자리다.
