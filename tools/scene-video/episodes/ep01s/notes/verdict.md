## 1. A. 돌려막기 — 이번 승인의 본안. **끊겼다.**

검수팀 표를 베끼지 않고 파일을 직접 열었다. `pins.js` 191행 · `channels.js` 141행 **전문 대조**.

### 1-1. `pins` vs `ep00s/channels` — 겹치는 것은 인용문과 숫자뿐

| | `ep00s/channels` | `ep01s/pins` |
|---|---|---|
| 그릇 | 세로 관 **4개** (`tubes[]` 4원소 균질 배열) | 가로 레인 **3개** + 우측 카드 **3장**. 4짜리 배열이 코드에 없다 |
| 값의 운동 | 블록 3개가 관으로 **떨어진다** (`lerp(TY+10, restY, …)`) | 획이 벽 앞 15px 을 **밀었다 물러난다** (`tipX = stopX-15+15*push`) |
| 강조 대상 | 세 0 중 `경로`에 `focus:true` — **0 이 주인공** | 세 0은 무강조. 시선은 전부 왼쪽 이름표로 |
| 로그 캡션 | 하단 가운데 `y=274`, `textAlign='center'` | 상단 왼쪽 `y=13`, 좌→우 클립 wipe |
| 논지 | 어느 갈래로 흘렀나(가려내기) | 셋이 같은 벽 앞에 섰다 |

`pins.js` 전문에 네 개짜리 그릇이 없다는 검수팀의 단언은 **사실이다**(`spec.lanes` 3 · `spec.unused` 3,
`used` 는 배열 원소가 아니라 별도 필드). 남은 겹침은 `ByReason=[…]` 인용문과 3/0/0/0 이고,
그건 두 원문이 같은 로그를 싣기 때문이다 — 바꾸면 §2 수치 정직성 위반이 된다. **더 요구할 것이 없다.**

### 1-2. 새 10종 vs ep00s 9종 · 옛 11종 — 코드 수준 표본

지시가 요구한 최소 3종을 넘겨 **5쌍을 전문/본문으로 읽었다.**

| 쌍 | 왜 골랐나 | 판정 |
|---|---|---|
| `pins` ↔ `ep00s/channels` | 1차 반려의 본안 | ✅ 위 표 |
| `erasure` ↔ `ep00s/handoff` | **둘 다 마지막 샷 · 둘 다 "이름표가 꺼지고 하나만 남는다"** | ✅ 다른 장치. handoff=이름 하나에 가로 취소선 + 칸이 오른쪽으로 이동 / erasure=2×2 넉 장을 세로 wipe 가 훑고 지나가며 잔해가 흘러내림. **겹칠 뻔한 자리인데 안 겹쳤다** |
| `teardown` ↔ `ep00s/excise` | 둘 다 "코드를 지운다" | ✅ 접힘(`h→0`) 관용구만 공유. excise 는 접힘이 샷의 전부, teardown 은 첫 큐에 사라지는 곁요소이고 본체는 가림막·균열·드러남 |
| `latch` ↔ `ep00s/checkpoint`·`fork` | 토큰 유사도 최상위(0.50) | ✅ 캔버스 어휘가 겹친 것. checkpoint=세로 문 행렬, latch=가로 빗장. 구조 무관 |
| `rebound` ↔ `ep00s/wire` | **둘 다 "회차의 척추 + 같은 그림 두 번(막힘→열림)"** | ✅ 아래 1-3 |

기계 대조도 붙인다(주석 제거 후 토큰 Jaccard):

```
옛 ep01s vs ep00s (기준선)  최대 0.444
새 ep01s vs ep00s           최대 0.500
새 ep01s vs 옛 ep01s        최대 0.455
```

전부 0.4~0.5 대역 = `ctx`/`roundRect`/`tone` 등 **붓(lib.js)의 바닥값**이다.
복사-붙여넣기라면 0.8 을 넘는다. **10종 어디에도 복제가 없다.**
이름 겹침 옛 11종 0건 · ep00s 9종 0건(직접 확인).

## 6. G. `rebound` 골격이 세 샷 — **성립한다. 단 여기까지다.**

검수팀 논거("회차 간이 문제이지 회차 안이 아니다")를 그대로 받지 않고 좌표와 화면으로 봤다.

- `pins.js:39-45` 가 `rebound.js:45-52` 의 상수(`HEAD/FOOT/GAP 34/30/10`, `baseX/baseW 12/38`,
  `wallX=round(lerp(startX,outX,0.56))=209`, `LEAD 1.9`)를 **한 줄도 안 틀리고 복제**한다.
  어긋난 되받기는 버그인데, 어긋나지 않았다.
- 실측 배치: S1 0.0~9.1s → S1B 9.5~17.9s → S9 95.0~105.5s.
  **S1·S1B 는 연속이라 "같은 장면을 확대해 들여다본다"로 읽힌다**(자막도 "제자리에서 아무것도
  못 해요" → "콘솔을 열어봤더니"). 세 번째가 아니라 **한 장면의 두 프레임 + 80초 뒤의 되받기**다.
- 스틸로 확인: 4s(흰 점이 튕김) · 17.9s(초록 이름표 3 + 우측 0 카드 3 + 콘솔 줄 — 화면 밀도가 딴판) ·
  103s(**벽이 사라지고 초록 점이 `탐험` 까지 흘러 나간다**). 벽이 열리는 것은 S9 뿐이고 payoff 는 살아 있다.

📌 **못박는다 — 이 골격은 세 샷이 상한이다.** 네 번째 샷이 같은 레인·벽 기하를 쓰면 반려한다.
그리고 이 기하는 **ep01s 소유**다. 다른 회차가 `pins.js`/`rebound.js` 를 복사해 오는 것은
"의식적인 결정"이 아니라 돌려막기로 본다.

🟡 같은 종류의 관찰 하나 더: `latch` 는 **옛 `rule`** 과 좌우 from/to 박스 골격을 공유한다
(검수팀이 🟡 로 봤고 나도 동의 — 옛 `rule` 은 ep01s 만 쓰던 그림이라 다른 회차 재탕이 아니고,
X 도장 한 번 → 매번 밀었다 되돌아오는 빗장으로 **논지가 바뀌었다**).
**단 이 from→to 박스 쌍도 이제 ep01s 의 어휘다. ep02s 가 "막힌 길"을 같은 배치로 그리면 반려한다.**

| `writer.md:66` | *"사방으로 퍼지다 만 점 4,096개"* | 위와 같음 |

**차단 사유가 아닌 이유:** 화면에 안 나온다. `scene.json.notes`·`reads`·kind 주석은 전부 갱신됐고,
영상 파일에는 어떤 영향도 없다. 여기서 두 번째 반려를 쓰면 화면과 무관한 사유로 반려 슬롯
(상한 3회 중 2회차)을 소모하고 7/30 일정을 밀게 된다.

**그래도 반드시 고쳐야 하는 이유:** 1차 반려의 근본 원인이 **"문서의 주장이 코드와 다른 것"** 이었다.
`notes/` 는 기기 간·세션 간 인수인계 경로라 저위험 문서가 아니다.
ep02s 작성팀이 `writer.md` §1 을 읽으면 **반려된 논법을 좋은 예시로 배운다.**

> **조건: 커밋 전에 `writer.md` 40·43·66 행을 고친다. 고치는 주체는 작성팀이다(내가 대본·문서를
> 고치면 검수 없이 나간 글이 된다). 렌더는 이 조건과 무관하게 진행해도 된다.**

### 7-B. 🟡 검수팀 논거 하나를 정정한다 — HUD 제목

검수팀은 HUD 제목 `계산 4096개` 를 *"상시 요소라 회차 하나가 단독으로 바꿀 자리가 아니다"* 라며
범위 밖으로 뒀다. **사실이 아니다.** `scene.hud.title` 은 회차별 `scene.json` 필드이고
(`engine.js:172` 가 그대로 읽는다), ep00s·ep01s·ep01 이 각자 다른 값을 갖고 있다.
**한 글자 고치면 되는 자기 회차 파일이다.**

다만 **반려·필수 조치는 아니다**: 원문 자체가 `4096`(자릿점 없음)으로 쓰므로 화면 표기가
원문과 어긋난 것이 아니다. 회차 내 표기 통일(HUD `4096` vs 화면·hook `4,096`,
109.3s 마지막 프레임에서 둘이 한 화면에 보인다)은 **권고**로 남긴다.
📌 잘못된 근거로 넘긴 항목이므로 기록한다 — **"HUD 는 회차가 못 바꾼다"는 근거를 다음 회차가
인용하면 받지 않는다.**
