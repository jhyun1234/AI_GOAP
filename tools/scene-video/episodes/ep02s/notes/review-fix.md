## 1. S4 `reverse.js` — 진단 확정 + 정정 1건

### 1-1. 실측 숫자

막대 기하 (코드 29~32줄 그대로 계산):

```
cols = 4, gap = 10, totalPad = 24
bw   = (352 - 24 - 30) / 4       = 74.50
x    = 12 + 3 × (74.5 + 10)      = 265.50   (허기 막대 왼쪽)
막대 중심 x + bw/2               = 302.75
막대 오른쪽 끝                    = 340.00
가운데 정렬이 쓸 수 있는 폭 = (352 − 302.75) × 2 = 98.50
```

문자열 `GOAP 목표 : HungerLevel ↓` 폭 (엔진에 로드된 실제 폰트로 `measureText`):

| 폰트 | 폭 (CSS px) |
|------|---|
| **`mono(700, 11)` — 현재** | **164.60** |
| `disp(700, 11)` | 138.72 |
| `disp(700, 12)` | 151.33 |
| `disp(700, 13)` | 163.94 |

→ 302.75 를 중심으로 찍으면 **220.45 ~ 385.05**.
캔버스 폭 352 이므로 **오른쪽으로 33.05 CSS px = 91.06 device px 초과**.

**독립 확인**: 화면에 남는 폭은 352 − 220.45 = **131.55**.
`GOAP 목표 : HungerLe` 의 `mono(700,11)` 실측 폭 = **131.60**.
두 값이 0.05px 차이 → 스틸에 보이는 `HungerLe` 까지가 정확히 맞습니다.
`17s.png` 에서 `GOAP` 의 시작 픽셀은 image x≈663 → CSS (663−55)/2.7551 = **220.7**,
계산값 220.45 와 일치합니다. **눈대중이 아니라 산술로 확정됩니다.**

잘려 나간 것은 `vel ↓` 입니다. 즉 **"낮춰라"를 뜻하는 ↓ 가 라벨에서 사라졌습니다.**
(막대 위쪽의 큰 ↓ 화살표는 남아 있으므로 `reads` 가 전부 무너지진 않았습니다.)

### 1-2. 원인 — 오케스트레이터 진단 그대로 성립

`reverse.js:90-99`

```js
const gw = Math.min(ctx.measureText(gwText).width + 18, bw + 8);   // ← 폭 제한이 박스에만
...
ctx.fillText(gwText, x + bw / 2, gy + 15);                          // ← 글자는 제한 없이 중앙
```

`gw = min(164.60 + 18, 74.5 + 8) = **82.50**`. 글자는 164.60.
**박스가 글자의 절반 크기**이므로 글자가 박스를 양쪽으로 41.05px 씩 뚫고 나갑니다.

### 1-3. 정정 — 박스는 화면 밖으로 나가지 않았습니다

> 오케스트레이터 진단: "그 글자를 감싼 초록 박스의 오른쪽 변도 캔버스 밖으로 나가 사라져 있다"

이 부분만 사실과 다릅니다. 박스는 `gx = 302.75 − 41.25 = 261.50`, 오른쪽 변 **344.00**
→ 캔버스(352) **안쪽 8px** 입니다. `17s.png` 에서 박스 오른쪽 변은 image x≈1003 에
실제로 그려져 있습니다(캔버스 오른쪽 끝은 image x=1025).
**사라진 것은 박스가 아니라 박스를 뚫고 나간 글자의 오른쪽 33px** 입니다.
처방 방향은 같지만, 기록은 정확해야 하므로 남깁니다.

### 1-4. 추가로 발견한 것 — 한 줄 안에서 폰트가 갈려 있습니다 (기계 확인)

`lib.js:45-48` 이 금지한 자리입니다: **mono 는 ASCII 전용, 한글 라벨은 disp.**

측정:

```
'목표' @ 700 11px "__NoSuchFont__", monospace  → 26.00
'목표' @ 700 11px SceneMono, monospace         → 26.00   (동일 = SceneMono 에 한글 없음 → 시스템 폴백)
```

`17s.png` 에서도 `GOAP` / `HungerLe` 와 `목 표` 의 글자꼴·자간이 눈에 띄게 다릅니다.
**폴백은 머신마다 다르므로 무인 렌더에서 재현성 위험입니다.** 잘림과 같은 줄에서
같이 고칩니다(문자열은 그대로).

### 1-5. 추가로 발견한 것 — 바로 위 막대 라벨의 여유가 7.05px

`허기 · HungerLevel` @ `disp(700,10)` = **84.40**, 중심 302.75
→ 260.55 ~ **344.95**. 오른쪽 여백 **7.05 CSS px = 19.4 device px**.
지금은 안 잘리지만 폰트가 한 눈금만 달라져도 넘칩니다. 같은 방식으로 막아 둡니다
(권장값으로는 **위치가 바뀌지 않습니다** — 순수한 가드).

## 2. S10 `nextnote.js` — (a) 로 판정합니다

### 2-1. 접촉의 정체 (30fps 분해)

| 구간 | 방향 | 프레임 | 정체 |
|------|------|--------|------|
| 44.80 ~ 45.37s | **오른쪽** | 18 | 새 표식 카드(152×60)가 오른쪽에서 들어오며 띠를 지나감 |
| 45.30 ~ 45.93s | **왼쪽** | 19 | 옛 표식 두 장이 밀려나며 잘림 |

최대 336px 은 **글자가 아니라** 들어오는 카드의 위·아래 변입니다
(카드 높이 60 CSS × 2.7551 = 165 device × 2열 = 330 ≈ 336).

### 2-2. (b) 를 못 고르는 이유 — 잘림보다 앞선 문제가 있습니다

`45.45s.png` 를 보면 옛 표식 두 장이 **겹친 채 글자가 포개져** 있습니다.
`빈 말풍선` 과 `거꾸로 게이지` 가 같은 자리에 인쇄되어 `말꿍섡로 게이지` 같은
읽을 수 없는 글자 덩어리가 됩니다. 44.9s 스틸에서는 이미 두 상자가 맞붙어 있습니다.

원인은 가장자리가 아니라 **속도**입니다. `nextnote.js:41-42`

```js
const startX = w / 2 - 60 + i * (tagW + 10);   // 두 장의 출발 간격 = 106
const endX   = -tagW - 10 + i * 6;             // 두 장의 도착 간격 = 6
```

이동 거리가 i=0 은 222, i=1 은 **322**. 뒤엣것이 100px 더 달려 앞엣것을 들이받습니다.
간격 = `106 − 100·e`.

| e (위치 진행률) | 샷 상대 시각 | 절대 시각 | 상태 |
|---|---|---|---|
| 0.10 | 0.42s | **44.87s** | 두 상자가 겹치기 시작 |
| 0.56 | 0.87s | **45.32s** | 두 **글자**가 포개지기 시작 |
| 0.746 | 1.03s | **45.48s** | `거꾸로 게이지` 가 캔버스에서 잘리기 시작 |
| 0.932 | 1.27s | **45.72s** | 글자가 화면 밖으로 다 나감 |

(선형 타이밍 근거: S10 은 1줄, `timed.json` dur 3154ms · pause 0.
`shiftCue 0, lead 0.1, span 0.55` → `shk_raw = (ts+0.1)/1.8347`, 위치는 `ease(ease(·))`.)

즉 **상자 겹침 약 1.06초 · 글자 포갬 약 0.25초 · 글자 잘림 약 0.24초**입니다.

`check.mjs:269-275` 의 기준("잘린 글자는 몇 초씩 서 있고 쓸고 지나가는 그림은 스친다")만
놓고 보면 잘림 0.24초는 스치는 쪽입니다. **그런데도 (a) 로 판정하는 근거는 세 가지입니다.**

1. **`reads` 가 성립하지 않습니다.** `scene.json` S10 `reads` = *"이번 편 **두 사건의
   표식**이 옆으로 밀려나고"*. 시청자가 두 표식을 각각 알아보고 떠나보내야 이 그림이
   뜻을 나릅니다. 지금은 두 장이 한 덩어리로 뭉개져 **하나로도 안 읽히는 글자**가 됩니다.
   가장자리 규칙 이전에 그림이 제 몫을 못 합니다.
2. **잘림이 "지나가서" 생긴 게 아니라 "안 사라져서" 생겼습니다.** `alpha = 1 - 0.6*shk`
   의 최솟값이 **0.4** 입니다. 표식은 끝까지 불투명한 채로 캔버스 경계에 **잘려 나갑니다.**
   설계된 퇴장이라면 사라지면서 나가야 하는데, 이건 화면 경계가 대신 지워 주고 있습니다.
   연출이 아니라 미완성입니다.
3. **선언의 대가가 큽니다.** `checks.edge` 는 다음 회차가 인용할 기록입니다.
   여기서 "글자가 잘린 채 가장자리에 서 있어도 된다"를 남기면, `check.mjs:186-206` 이
   *바로 이 회차의 S4 사고* 때문에 추가된 검사를 같은 회차에서 무력화하는 셈입니다.
   편해서 고르는 선택이 됩니다. 선언하지 않습니다.

반대로 **오른쪽에서 카드가 들어오는 동작 자체는 정당한 연출**입니다(0.57초, 상자 외곽선).
그건 없애지 않습니다. 다만 그 카드 위의 **글자**는 카드가 걸쳐 있는 동안에도 찍혀서
`성격`(31.11px)이 반토막 나므로 그것만 막습니다.

```js
    const SLIDE = 170;
    prev.forEach((label, i) => {
      const startX = w / 2 - 60 + i * (tagW + 10);
      const cx = startX - SLIDE * ease(shk);
      const y = laneY - tagH / 2;

      /* 🔴 옛 투명도 1-0.6*shk 는 최솟값이 0.4 라 끝까지 안 사라졌다. 표식이 사라진 게
         아니라 캔버스 경계가 잘라 준 것이고, 잘린 '게이지' 세 글자가 그 자리에 섰다.
         가장자리에 닿기 전에 0 이 되게 한다: shk=0.526 에서 alpha=0 이고
         그때 왼쪽 끝이 x=24.4 라 띠(바깥 2열)에 닿지 않는다. */
      const alpha = clamp(1 - 1.9 * shk);
      if (alpha < 0.02) return;
```

(49~57줄은 그대로 둡니다.)

검산: `ease(0.526) = 0.539` → 이동 91.6px.
i=0 왼쪽 끝 116 − 91.6 = **24.4**, i=1 은 222 − 91.6 = **130.4**.
소멸 시점(샷 0.849s)에 새 카드는 217.8~369.8 에 있으므로 겹침은 8.6px 뿐입니다.
**왼쪽 가장자리 접촉 = 0.**

> 판단 기록: 이 처방은 옛 표식을 "화면 밖까지 밀어내는" 대신 "밀려나며 흐려져 사라지는"
> 것으로 바꿉니다. `reads` 의 *"옆으로 밀려나고"* 는 유지됩니다(한 표식 폭만큼 이동).
> 끝까지 밀어내려면 잘림이 되돌아오므로, 이 회차에서는 소멸을 택합니다.

**② 77~82줄 — 카드가 다 들어온 뒤에 글자를 켠다**

```js
      ctx.textAlign = 'center';
      /* 🔴 카드가 오른쪽 가장자리에 걸쳐 있는 동안 글자를 찍으면 '성격'(31.11px)이
         화면 밖에서 반토막 난다. 상자가 들어오는 것은 연출이지만 글자는 아니다. */
      const inK = clamp((w - 6 - (cx + nextW)) / 20);
      ctx.globalAlpha = clamp(ak * 1.4) * inK;
      ctx.fillStyle = tone('accent'); ctx.font = disp(900, 18 * Math.min(1, s));
      ctx.fillText(next.label || '', cx + nextW / 2, y + 24);
      ctx.fillStyle = tone('sub'); ctx.font = disp(700, 11 * Math.min(1, s));
      ctx.fillText(next.note || '', cx + nextW / 2, y + 46);
      ctx.globalAlpha = 1;
```

`globalAlpha` 를 상자 stroke(71~74줄) **뒤에** 다시 잡는 것이므로 상자에는 영향이 없습니다.
글자는 샷 0.92s(절대 **45.37s**)부터 완전히 켜집니다 — 샷이 끝나기 2.6초 전이라 충분합니다.

🟡 **남는 위험**: S10 의 17% 는 여유가 8%p 뿐이고, `check.mjs` 는 5fps(샷당 약 17샘플)로
세므로 한 프레임이 **5.9%p** 입니다. 재실행에서 아슬아슬하게 걸리면 다음 레버를 쓰십시오.

- `nextnote.js:64` 의 `lerp(startX, endX, ease(ak))` → **`easeOut(ak)`**.
  카드가 빨리 들어와 늦게 앉으므로 띠 통과가 0.57s → **약 0.48s** 로 줄고,
  도착 모션으로도 더 낫습니다. **2줄 import 에 `easeOut` 을 추가해야 합니다.**
- 그래도 남으면 그때 `checks.edge` 를 논의하되, 사유는 **"오른쪽에서 카드가 들어오는
  진입 모션"** 으로 한정해서 적어야 합니다. "글자가 잘려도 된다"로 적으면 안 됩니다.
