## 2.2 커밋 도장의 뜻이 흐려지지 않았는가 — **안 흐려짐** (수치로)

`strokeAlong` 이 x 를 `[xL, xR]` 로 clamp 하지만 `lineCap='round'` 라 **캡 반경 6.5px 만큼
더 나갑니다**(코드만 읽으면 놓치는 자리). 도장 왼쪽 끝은 `commitCx − rC = (xR+20) − 22 = xR − 2`
라, 산술적으로는 캡이 도장을 8.5px 침범할 수 있습니다. 그래서 **잉크가 도장에 닿는 최대 알파**를
봉투식으로 뽑았습니다:

```
도장(좌단 xR-2)에 잉크가 닿는 최대 알파 = 0.142   (샷내 t = 7.725)
```

닿는 자리는 안티에일리어싱된 둥근 캡의 **끝점**이라 실제 잉크는 이보다 훨씬 옅고,
스틸 63s · 64.5s · 68.5s · 70s 어디에서도 도장 위에 흰 얼룩이 안 보입니다.
**도장은 아홉 장 전부 깨끗한 초록입니다.** 신호는 도장 앞에서 꺼집니다 — 작성팀 주장대로입니다.

📌 다만 작성팀 §8.3 의 **근거 문장 하나가 코드와 다릅니다**(결함 아님, 기록용).
> "도장에 불이 들어오는 것은 **화살표가 끝까지 갔을 때 한 번**이어야 합니다."

실제로는 `ok = ease(cue(okCue=0, ...))` (`tripwire.js:55`, `94`) 라 **자막 0번에 켜져서
샷 내내 켜져 있습니다** — 화살표 위치와 무관합니다. 스틸 63s 에서 화살표가 아직 중간인데
도장이 이미 초록인 것이 그 증거입니다. 이건 1차에서 통과시킨 기존 동작이고
이번 수정이 만든 게 아니라 반려하지 않습니다. 다만 **다음 회차가 이 문장을 옳은 모델로
베끼면 안 되므로** 적어 둡니다 — 지켜야 했던 것은 "도착의 한 번"이 아니라
"도장 위에 새 잉크를 얹지 않는다"였고, **그건 지켜졌습니다.**

## 2.3 trapped 구간에서 띠가 실선을 벗어나 떠 있지 않은가 — **정확히 붙어 있음**

작성팀은 `wireY(x)` 가 근사가 아니라 실선과 **정확히 같은 자리**라고 주장했습니다.
믿지 않고 대수로 확인했습니다.

`quadraticCurveTo` 의 제어점이 두 끝점의 **중점**일 때
`B(s) = (1−s)²P₀ + 2s(1−s)·(P₀+P₀... )` 를 전개하면
`B(s) = (1−s)P₀ + s·P₁` — **차수가 떨어져 직선**이 됩니다.
그래서 실선(187~191행)의 좌측 도막은 `y = cy − pull·(x−xL)/(pinX−xL)`,
우측 도막은 `y = cy − pull·(xR−x)/(xR−pinX)` 이고, 이는 `wireY`(151~153행)와 **한 글자도 같습니다.**
근사가 아니라 동일식입니다. ✅

`strokeAlong` 이 N=6 도막으로 쪼개므로 꺾임점(pinX)을 가로지르는 띠만 코너를 미세하게
자르는데, 도막 하나가 2.7px(머리)·3.8px(꼬리)이고 양쪽 기울기가 0.11/0.37 이라
어긋남이 **1px 미만**입니다. 눈으로도 확인 — 스틸 66.5s 에서 세 띠가 전부 텐트로 당겨진
실선 위에 얹혀 있습니다(x≈500 의 띠가 y≈770, 같은 x 의 실선도 y≈772). **떠 있지 않습니다.**

## 2.4 🟡 새로 생긴 것 하나 — 화살촉이 띠 머리에 잠기는 구간 (관찰, 반려 아님)

띠와 화살표가 **같은 색·같은 레인**이라, 빠른 화살표(140.7px/s)가 느린 띠(106.7px/s)를
추월할 때 머리 안으로 들어갑니다. 눈으로 68.5s 스틸을 봤을 때 화살촉을 못 찾아서
**수식으로 지속 시간을 쟀습니다**(둥근 캡 반경 6.5px 포함, 화살촉이 통째로 잠기고
띠 알파 > 0.7 인 구간만):

```
잠기는 시간 = 0.97s / 8.43s (12%)
연속 구간(엔진 시각): 63.62~63.71(0.09) 65.41~65.51(0.10) 66.01~66.11(0.10)
                      66.61~66.70(0.09) 66.90~66.94(0.03) 67.15~67.18(0.02)
                      67.32~67.35(0.03) 68.19~68.63(0.43)
최장 = 0.43s
```

**반려하지 않는 이유** — 근거를 붙입니다.

1. **최장이 0.43초, 한 샷에 한 번**입니다. 나머지 일곱 번은 0.02~0.10초로 5fps 한 프레임
   안팎이라 지각되지 않습니다. 제가 처음 계산했던 "1.98초"는 **알파 0.55 짜리 꼬리까지
   가림으로 센 오산**이었습니다 — 스틸 63.4s 가 반증합니다. 그 시각 화살표는 꼬리 위에
   있는데 **또렷하게 보입니다**(오히려 꼬리가 화살대처럼 붙어 더 잘 읽힙니다).
2. **`reads` 가 살아 있습니다.** S8 `reads` = "화살표가 오른쪽으로 지나가면 커밋에 초록 등이
   들어오고, 다시 왼쪽으로 지나가려는 순간 실선이 팽팽해지며 붙잡는다".
   출발(63.0s) · 도착(64.0s · 70.0s) · 붙잡힘(65.5s · 66.5s) **전부 화살표가 또렷합니다.**
   잠기는 것은 이동 **중간**뿐이고, 화살표가 띠보다 빨라 **앞으로 뚫고 나옵니다**
   (실려 가는 게 아니라 추월합니다) — 69.2s 스틸에서 띠 앞으로 빠져나온 화살표가 보입니다.
3. 제가 1차 §1.5 에 적은 금지 다섯 줄(밝기만 흔들기 · 난수/시각/프레임 기억 · `tone()` 밖
   색 · 팔레트 예외 선언 · 두 번째 사건)을 작성팀이 **전부 지켰습니다.**
   전부 지킨 뒤에 제가 안 적었던 기준을 새로 꺼내 반려하는 것은 골대를 옮기는 일이고,
   그건 이 재작업 트랙이 존재하는 이유(리포에 없는 기준으로 반려해서 36초를 잘라낸 사고)와
   같은 종류의 잘못입니다. 리포 어느 문서에도 "주인공이 가려지면 안 된다"는 규정은 없습니다.

**다음 회차를 위한 권고**(이번엔 고치지 마십시오 — 렌더를 다시 돌릴 값이 아닙니다):
같은 레인에 같은 색으로 재질을 심을 때는 **주인공보다 얇게** 두면 됩니다.
지금 머리는 `lineWidth 13`, 화살촉 높이는 12px 이라 화살촉이 통째로 들어갑니다.
