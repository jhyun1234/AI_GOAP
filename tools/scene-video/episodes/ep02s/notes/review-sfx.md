# ep02s 효과음 검수 — 검수팀 (2026-07-31)

검수 범위 = **효과음만**. 대본·그림·길이·구성은 승인된 것이라 심사하지 않았다.
`writer-sfx.md` 의 주장을 믿지 않고 `kinds/*.js` · `engine/engine.js` · `build/timed.json` 에서
**전부 다시 풀었다.** 아래 수치는 전부 내가 독립적으로 낸 값이다.

## 최종 판정 — 🟢 **통과**

여섯 개 전부 `delayMs` 가 그림이 그 사건을 그리는 프레임에 물려 있다. 다시 푼 값과
작성팀 주장값의 최대 차이가 **3ms**(0.1프레임)다. 배치·절제·길이·음량 모두 문제 없다.
아래 「기록 정정」 넷은 반려 사유가 아니라 **notes 문서의 참고 열 오차**다 — 렌더가 읽는
필드(`at`·`kind`·`delayMs`·`dur`·`gain`·`freq`)는 하나도 안 틀렸다.

## 0. 검산의 기준 — 먼저 못 박는다

`cue(i, lead, span)` = `clamp((ts − a)/(b − a))`, `a = lᵢ.t − lead`, `b = lᵢ.t + lᵢ.dur×span`
(`engine/engine.js:240-245`). `lᵢ.dur` 는 **발화 + pauseAfter** (`engine.js:156`).
효과음은 `line.t + delayMs` 에 놓인다(`render.mjs:111`) — 그림의 `cue` 와 **같은 기준선**이다.

따라서 `delayMs` ↔ cue 진행률의 변환식은

```
c = (delayMs/1000 + lead) / (lead + dur×span)
delayMs = (c × 창 − lead) × 1000
```

캔버스는 **352×307** 이다(`style.css:46` stage 392px, `:75` .vis 좌우 inset 20px →
352; 392×16/9×(1−0.21875−0.340625) = 307.0). 작성팀이 쓴 `w=352`·`nextW=152` 는 맞다.

실측 시간표(`build/timed.json`)로 확인한 각 줄 dur(발화+pause):
S3B[2] 2409 · S5[0] 4029 · S7[0] 2972 · S8[0] 2640 / [1] 2865 / [2] 2927 ·
S9B[1] 3607 · S10[1] 3856. 작성팀 표와 일치.

**결론: 여섯 개 전부 그림 위에 얹혀 있다.**

- **S3B @440ms** — 임계 437ms 를 3ms 넘긴 자리. 30fps 로 환산하면 소리(abs 30516ms)가
  색이 갈리는 첫 프레임(abs 30533ms)보다 **0.5프레임 이르다.** 실효 동시.
  🔑 작성팀이 테두리 전환(+116ms)을 버리고 글자 밝기를 고른 근거도 재확인했다 — 코드상
  `sk` 가 0.1 을 넘는 순간 글자는 회색 α 0.45 에서 강조색 α 0.15 로 **오히려 어두워진다**
  (`relight.js:195-202`). α 가 0.45 를 회복하는 시점이 +342ms 이고 0.6 을 지나는 것이
  +437ms 다. "대사가 떴다"로 읽히는 자리는 440ms 가 맞다.
- **S5 @1130ms** — 번쩍임 구간 [1101, 1167] 안. abs 로는 [40442, 40508] 이고 30fps
  프레임이 40466.7·40500 두 장 걸린다 — **번쩍임이 프레임 사이로 빠지지 않고 실제로 보인다.**
  소리 시작 40471ms 는 그 두 프레임의 첫 장이다. `drop` 은 2ms 어택이라 가장 큰 순간이
  거의 시작점이다. 정확하다.
- **S7 @730ms** — `sweep` 은 `lp × sin(πk)` 라 에너지가 한가운데 몰린다(`sfx.mjs:98`).
  730 + 620/2 = 1040ms = 앞머리 중앙 통과. 역산이 맞다.
  획 범위 재확인: 730ms 에 `headIdx=10.5`, 1350ms 에 `headIdx=23.5` — **13칸**이다.
- **S8 @325ms** — 이번 검수에서 가장 중요한 자리다. `tripwire.js` 의 걸림은 `cue` 를 안 쓰고
  `frac(t/5.2)` 로 돈다(`:117, :131`). `trapped` = `u∈[0.57,0.85)` → 샷 안 [2.964s, 4.420s).
  자막 시작 시각 at0=0 · at1=2.640 · at2=5.505 를 timed.json 으로 직접 계산해 대조했다.
  **at2 시점 `u = 5.505/5.2 = 1.0587 → frac = 0.0587`** — 정방향 구간, 실선은 곧다.
  참고 배치(at2)대로 뒀으면 **아무 일도 없는 화면 위에서 철컥 소리가 났다.** 교정이 옳다.
  두 번째 걸림 8.164s 도 확인했다 — at2 발화 종료(7.732s) 뒤라 못 쓴다.
- **S9B @380ms** — 소수 넷째 자리까지 일치. 검산할 것이 없다.
- **S10 @1150ms** — `inK` 램프 [1145, 1227] 의 시작점. abs 프레임으로 2644(inK≈0) →
  2647(inK=1), 3프레임에 걸쳐 글자가 통째로 든다. 소리가 그 첫 프레임에 문다.
  `tick` 은 어택 1ms 라 시작점 정렬이 맞다. **상자가 아니라 글자에 물린 판단이 옳다.**

### ⚠️ 유일한 계산 오차 — S10 `spring(ak)` 정점

`spring(k)` 은 `lerp(0.86,1.05,easeOut(min(1,k/0.55))) − 0.05×settle` 이라
**정점이 ak = 0.55 에서 나온다**(`lib.js:87-92`). 역산하면 c ≈ 0.5333 → **+1061ms** 다.
작성팀이 적은 +1099ms 는 38ms 틀렸다. 다만 이건 `참고:` 로 적은 곁줄이고, 그 문장이
말하려던 것("상자 정점이 글자보다 이르다")은 1061 < 1145 라 **결론이 그대로 성립한다.**
`delayMs` 에 영향 없음.

### 소리를 뺀 자리 — 자기모순 회피 3건, 전부 타당

- **S1** "이 셋, 지금 아무 말도 안 해요" — 소리를 넣으면 자막을 부정한다. ✅
- **S9** "둘 다 에러 한 번 안 났어요" — 같은 이유. ✅

  알파가 0 이 되어 멎는다. 코드와 사유가 맞는다. 6종을 다 쓸 의무는 어디에도 없다. ✅

발음 골**에 정확히 떨어졌기 때문이다. 말을 먹는 게 아니라 말이 쉬는 자리에 들어갔다.
설계 의도(제목이 걸린 반전을 가장 크게)와 실측이 서로를 지지한다.

주파수도 겹치지 않는다 — 말 위에 얹히는 셋(S3B 1750Hz · S7 6287Hz · S10 1044Hz)이 전부
성대 기본주파수 대역 밖이고, 그 대역에 있는 둘(S5 239Hz · S9B 279Hz)은 말이 쉬거나
시작 전인 자리에 있다. 우연이 아니라 delayMs 를 그림에 맞춘 결과다.

## 6. 회차 안 돌려막기 — 🟢

같은 kind 가 두 번 나오는 것은 `tick` 뿐이다(S3B · S10). 실측 파형 대조:

- **S3B**: 50ms · 실측 1750Hz · 피크 0.2395
- **S10**: 90ms · 실측 1044Hz · 피크 0.1843

음정 차이가 1750/1044 = **1.68배 ≈ 9반음(장6도)**, 길이 **1.8배**. `env` 의 감쇠 지수 d=22 는
`dur` 로 정규화돼 있어 모양은 같지만 절대 길이가 다르다 — 하나는 짧고 밝은 "틱",
다른 하나는 낮고 늘어지는 "톡" 이다. 게다가 둘 사이가 57.6초다. **귀에 다른 소리로 들린다.**

kind 여섯 중 다섯을 썼고(`thud` 만 사유 있는 미사용), 여섯 소리가 서로 성격이 다르다.
회차 안 반복 없음.

## 7. `why` 와 `notes.효과음`

여섯 개 전부 `why` 가 있고, 전부 **draw 코드의 줄 번호·식**을 근거로 든다. 사유 없이 단 것
없음. `notes.효과음` 은 안 넣은 자리의 사유까지 적었다 — 이 항목은 요구 이상이다.

## 검수하지 않은 것

- 대본·그림·`spec`·길이·구성 — 승인된 회차라 범위 밖.
- `check.mjs` — 효과음 검사 항목이 없어 이 작업에 대해 아무 증거도 못 낸다. 돌리지 않았다.
- 렌더·`tts.mjs` — 금지. 대본 무수정이므로 `tts` 재실행도 불필요하다(작성팀 판단 동의).
- 소리 자체의 감상 — 나도 들을 수 없다. 판정은 **"배치가 말이 되는가"** 까지다.
  최종 청취 확인은 사람이 한다.

## 작성팀에 남기는 한 줄

세 자리(S3 → S3B · S5 at1 → at0 · S8 at2 → at1)를 참고 배치에서 뒤집은 것이 이 작업의
값이다. 셋 다 근거가 코드에 있었고, 셋 다 안 뒤집었으면 **소리가 빈 화면 위에서 났다.**
특히 S8 은 걸림이 `cue` 가 아니라 `frac(t/5.2)` 로 돈다는 것을 찾아낸 것이라 —
자막 인덱스만 보고는 절대 못 잡는다. 다음 회차도 `delayMs` 는 draw 를 풀어서 낼 것.
