### 2차 반려 해소 방식 검증

`kinds/wardline.js` 26~27줄:
```js
const KNOWN = new Set(['게으름', '탐구', '용감함']);
const options = rawOptions.map(name => KNOWN.has(name) ? name : '···');
```

`scene.json` S3.spec.options 는 원문 그대로 6개 이름:
```
["게으름", "탐구", "용감함", "성실", "겁많음", "쾌활"]
```

**렌더 계층에서 걸림**:
- KNOWN 3개 = 원문 33줄에 명시된 이름 → 화면에 이름 그대로 표시
- 나머지 3개(성실·겁많음·쾌활) → `···` 익명 자리로 치환
- 6칸 자체는 유지 — 원문 47줄 `Random.Range(1, 7)` = 6종 존재는 사실
- `picked = 0` (게으름) → 원 안에 채워지는 이름도 KNOWN 안, 안전

**지시 준수 확인**:
- 지시: "scene.json 은 변경 안 함" → 준수. git diff scene.json 결과 spec.options 배열 무수정.
- 지시: "화이트리스트가 실제로 화면에 나가는 텍스트를 제한" → wardline.js 44줄 forEach 안 `ctx.fillText(opt, ox, oy + 4)` 가 `options`(치환된 배열)를 그린다. 원문 미명시 이름은 `···` 로 나감.
- 지시: "코드 실제 내용 확인" → 완료.

**"원문에 있는 문자열만 화면에 나간다" 규칙이 데이터가 아니라 렌더 계층에서 지켜진다.**
writer.md 3차 노트(0.1절, 7절 각주)가 이 사실을 정직하게 기록.
