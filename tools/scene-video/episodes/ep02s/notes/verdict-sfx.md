## 🔴 직접 재검증한 고위험 3건

### ① `at` 이 샷 안 인덱스인가 — **확인. 6개 전부 의도한 자막에 앉는다**

`check.mjs` 에 효과음 검사가 **한 항목도 없다**는 것부터 확인했다
(`grep -n 'sfx|효과음' check.mjs` → 0건). 즉 여기가 틀려도 조용히 렌더된다.
그래서 해석 경로를 끝까지 따라갔다.

```js
// render.mjs:103-111
let li = 0;
for (const sh of scene.shots) {
  const base = li; li += sh.lines.length;
  for (const s of sh.sfx || []) {
    const idx = base + (s.at ?? 0);
    const line = timeline.lines[idx];
    ...
    const at = Math.round((line.t + (s.delayMs ?? 0)) / 1000 * rate);
```

`timeline` 은 `window.__timeline()`(`render.mjs:154`)이고 그 `lines` 는
`engine.js:340-342` 가 엔진의 평탄화 배열 `lines` 를 그대로 내보낸 것이다.
그 배열은 `buildTimeline`(`engine.js:151-159`)이 `scene.shots` 순서로 샷마다
`s.lines` 를 하나씩 push 해 만든다 — **render 의 `base` 누적과 완전히 같은 순서·같은 개수**다.
따라서 `at` 은 전역 인덱스가 아니라 **그 샷 안의 자막 인덱스**가 맞다
(`.claude/agents/scene-writer.md:115` 의 규약과도 일치).

실제로 6개를 평탄화 인덱스로 풀어 **그 줄의 `say` 문자열까지** 찍어 대조했다:

|---|---|---|---|---|---|
| S3B | 2 | 10 | S3B[2] ✅ | "그 대사가 그제야 뜨더라고요." | 30.516s |
| S5 | 0 | 13 | S5[0] ✅ | "그래서 이름을 뒤집었어요…" | 40.471s |

### ② S8 `at2 → at1` 교정 — **확인. 참고 배치는 빈 화면 위에 소리를 놓는 것이었다**

`tripwire.js` 를 직접 열었다. 걸림은 `cue` 를 안 쓴다:

```js
// tripwire.js:117-133
const u = frac(t / CYCLE);            // CYCLE = 5.2 (:33)
} else if (u < 0.85) {
  const rv = (u - 0.5) / 0.35;
  if (rv < 0.2) { ... } else { ...; trapped = true; latchDepth = ease(clamp((rv-0.2)/0.3)); }
```

`trapped` = `rv ≥ 0.2` 이고 `u < 0.85` → **`u ∈ [0.57, 0.85)`**. 그리고 `draw` 가 받는 `t` 는
`engine.js:221, 251` 의 `ts = (t - s.t)/1000` — **샷 로컬 초**다(전역 시각이 아니다).
따라서 걸림 구간은 샷 안 **[2.964s, 4.420s)** · 2차 [8.164s, 9.620s).

`timed.json` 으로 낸 S8 줄 시각(샷 로컬): at0 = 0 / **at1 = 2.640** / at2 = 5.505.

| 시점 | 샷 로컬 | `u` | `trapped` |
|---|---|---|---|
| at1 시작 | 2.640s | 0.5077 | false |
| **소리(at1+325ms)** | **2.965s** | **0.5702** | **true** ✅ |
| at2 시작 | 5.505s | 0.0587 | **false** ← 참고 배치 자리 |
| at2 발화 끝 | 7.732s | 0.4869 | false |

**at2 시점에는 실선이 곧고 화살표가 정방향이다.** 2차 걸림(8.164s)은 at2 발화가 끝난
7.732s 뒤에나 온다. 참고 배치대로 뒀으면 아무 일도 없는 화면에서 철컥 소리가 났다.
검수팀 주장 그대로였고, **교정이 옳다.**

곁가지로 두 가지를 더 쟀다.
- `latch` 는 140ms 인데 **그 140ms 전 구간이 걸림 상태 안**이다(4.420s 까지 여유 1.3초).
- 30fps 프레임 격자와 대조: 걸림이 켜지는 첫 프레임은 #1957(abs 65.2333s),
  소리 시작은 abs 65.2330s — **차이 0.3ms.** 클릭과 색 전환이 같은 프레임에 있다.

## 판정 기준별

**1. 나레이션이 부르는 사건에 물려 있는가 — 🟢**
6개 전부 `delayMs` 가 그림이 그 사건을 그리는 프레임에 앉는다(위 표). kind 의 뜻도
`scene-writer.md:106-113` 표와 겹친다 — 뒤집힘=`drop` · 쓸어냄=`sweep` · 규칙이 걸림=`latch`
· 굵어짐=`riser` · 자리에 앉음=`tick`.
🟡 `delayMs` 넷(440·730·1130·1150)이 경험칙 200~400ms 밖이지만, 같은 줄(`:123-124`)의
구속력 있는 규칙은 *"그림이 그 사건을 그리는 순간에 맞춘다"* 이고 200~400 은 "대개"다.
넷 다 draw 를 풀어서 나온 값이라 규칙을 어긴 것이 아니라 규칙을 지킨 결과다.

**2. 절제 — 🟢**
6개 / 95.539초 = 90초 환산 **5.65개**. 기준 5~8개(`scene-writer.md:130`) 안, 하한 쪽.
최소 간격 7.94초, 겹치는 소리 0.

**첫 30.5초 무음은 설계로 인정한다.** 근거는 전부 리포 안에 있다 —
`scene-writer.md:135` *"소리를 안 다는 샷이 대부분인 게 정상"*, `sfx.mjs:14-15`
*"나레이션이 실제로 부르는 사건에만"*, 그리고 이 회차의 `hud.title`("조용히 거꾸로 돌던 마을")
· S1 자막("이 셋, 지금 아무 말도 안 해요") · `notes.이_글의_기본_도형`.
S1·S2·S3 이 담는 것은 각각 *신호가 없다 · 선이 없다 · 아직 안 넣은 한 줄*이고, 그중 S3 는
위에서 확인했듯 물 사건이 코드에 없다. **"소리를 못 찾아서 빈 것"이 아니라 셋 다 사유가 다르고
검증된다.** 🔴 무음 길이를 반려 사유로 삼으려면 리포 안 숫자가 있어야 하는데 없다 —
없는 숫자로 반려한 것이 이 회차의 3차 라운드를 만든 사고다(`routine-prompt.md:31-39`).

**3. `why` 의 질 — 🟢**
6개 전부 `why` 가 있고 최단 것이 200자를 넘는다. 전부 **파일명·식·임계값**을 든다
(`relight.js` 의 `sk`, `flip.js` 의 `absScale<0.06`, `sweep.js` 의 `headIdx`,
`frac(t/5.2)`, `tangle.js` 의 `lerp(84,224,lk)`, `nextnote.js` 의 `inK`).
내가 여섯 식을 전부 코드에서 확인했고 전부 실재한다 — **인상평이 하나도 없다.**
안 넣은 자리의 사유(`notes.효과음` + `writer-sfx.md` 4절)까지 있는 것은 요구 이상이다.

**4. 회차 안 돌려막기 — 🟢**
같은 kind 반복은 `tick` 둘뿐. 실제로 합성해 쟀다:
S3B 50ms · peak 0.2395 · 1760Hz / S10 90ms · peak 0.1843 · 1050Hz — 길이 1.8배,
음정 1.68배(≈장6도). 둘 사이가 57.6초. 다른 소리로 들린다.
`thud` 미사용은 사유가 있다(S2 는 "닿지 않음", S6 은 "스스로 그은 반경" — 둘 다 충돌이 아님).
6종을 다 쓰라는 규정은 리포 어디에도 없다.

**5. 음량 — 🟢** (재측정)
`sfx.mjs` 의 `synth` 를 직접 불러 6개를 합성했다. 목표 단기 RMS 가 지정한 `gain` 과

합계 리미터(`render.mjs:123`, 0.98)에 걸릴 여지가 없다.

**6. 범위 — 🟢**
HEAD 판과 현재 `scene.json` 을 파싱해 `sfx`·`notes.효과음` 만 지우고 직렬화 대조 →
**완전 동일**. HEAD 에는 `sfx` 가 있는 샷이 0개, 현재 6개. 모든 샷에 `reads`·`source` 있음.
대본·`spec`·길이 무수정을 내 손으로 다시 확인했다.

## 🔴 렌더 단계에 넘길 때 주의할 점

1. **`tts.mjs` 를 다시 돌리지 말 것.** 대본이 무수정이라 재실행할 이유가 없고,
   재실행해서 줄 길이가 1ms라도 바뀌면 **6개 `delayMs` 가 전부 무효**가 된다.
   특히 **S8 이 치명적**이다 — 걸림 시각은 샷 로컬 2.964s 에 고정인데 `at1` 의 위치는
   `S8 line0 의 dur`(현재 2,640ms)이 정한다. 즉 `delayMs = 2964 − 2640 = 324`.
   line0 의 길이가 변하면 그만큼 그대로 어긋난다. 소리는 걸림 시작 **1ms 뒤**에 착지하므로
   **이른 쪽 여유가 사실상 0** 이다(늦은 쪽은 1.3초).
2. **`build/video.mp4` 는 반드시 덮어써야 한다.** 그림은 한 프레임도 안 바뀌지만
   `render.mjs` 에는 소리만 다시 만드는 경로가 없다(`buildTrack` 이 프레임 추출과 같은 실행 안에
   있다). 전체 재렌더가 유일한 길이다. 프레임이 동일하므로 결과 영상의 길이·화면은 그대로여야 한다 —
   **길이가 95.5초에서 달라지면 그 자체가 이상 신호다.**
3. **렌더 로그에서 `소리` 줄을 확인할 것.**
   - `⚠️ … at=N 이 자막 범위 밖 — 건너뜀`(`render.mjs:109`)이 한 줄이라도 뜨면 중단.
     지금 계산으로는 뜰 수 없지만, 이건 `check.mjs` 가 못 잡는 유일한 경보다.
   - `⚠️ 합계 피크 … 로 줄임`(`:126`)도 떠서는 안 된다(예상 최대 0.24 + 나레이션 0.49).
   - 붙은 소리 개수가 **6** 인지.
4. **최종 청취는 사람이 한다.** 나도 검수팀도 소리를 못 듣는다. 판정은
   *"배치가 코드가 그리는 것과 맞는가"* 까지다. 특히 첫 소리가 30.5초에 처음 나는 설계는
   근거가 서 있지만 **체감은 사람만 판정할 수 있다** — 사용자에게 그 지점을 먼저 물을 것.
5. 유튜브 업로드는 사람이 한다(`publish.mjs` 주석).
