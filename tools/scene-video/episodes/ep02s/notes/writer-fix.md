## 1. 바꾼 자리 목록

### `kinds/reverse.js` (S4)

| # | 자리 | 무엇을 | 왜 |
|---|------|--------|-----|
| A-1 | import (2줄) | `mono` 를 목록에서 제거 | A-2 로 이 파일에서 `mono` 를 쓰는 곳이 없어졌습니다. 안 쓰는 import 를 남겨 두면 "여기는 mono 를 쓰는 파일"이라는 잘못된 신호가 됩니다 |
| A-2 | GOAP 목표 라벨 블록 (구 85~101줄) | 처방 3-A① 로 통째 교체 — ①폰트 `mono(700,11)`→`disp(700,11)` ②박스 폭을 `tw + 18` 로(글자를 감싸도록) ③가운데 정렬 기준점을 `gcx = clamp(x + bw/2, PAD + gw/2, w - PAD - gw/2)`, `PAD = 16` 로 캔버스 안쪽으로 당김 ④`fillText` 기준점을 `x + bw/2` → `gcx` | 잘림의 직접 원인. 폭 제한(`Math.min(..., bw+8)`)이 **박스에만** 걸려 있어 박스 82.50px 안에 글자 164.60px 이 들어가 있었고, 글자가 오른쪽으로 33.05 CSS px 삐져나가 `GOAP 목표 : HungerLe` 까지만 보였습니다 |
| A-3 | `drawBar` 서명 (구 108줄) | 끝에 `cw` (캔버스 폭) 인자 추가 | 막대 라벨도 같은 방식으로 못 넘게 막기 위한 통로 |
| A-4 | `drawBar` 라벨 그리기 (구 120~123줄) | `lw` 실측 후 `lcx = (cw && lw < cw - 16) ? clamp(x + w/2, 8 + lw/2, cw - 8 - lw/2) : x + w/2` | `허기 · HungerLevel`(84.40px)의 오른쪽 여백이 **7.05 CSS px** 뿐입니다(검수팀 실측). 지금은 안 잘리지만 폰트가 한 눈금만 달라져도 넘칩니다. **권장값에서 위치는 바뀌지 않습니다**(중심 상한 303.80 > 현재 302.75) — 순수한 가드입니다 |

### `kinds/nextnote.js` (S10)

| # | 자리 | 무엇을 | 왜 |

## 2. `scene.json` 을 안 건드렸다는 확인

✅ **`episodes/ep02s/scene.json` 은 열어서 읽기만 했고 한 바이트도 쓰지 않았습니다.**
`build/*.wav` · `build/timed.json` 도 마찬가지입니다.

- `lines`(`text`/`say`/`pauseAfter`) — 변경 0. 음성 재굽기 불필요, 마스터 승인 유지.
- `spec` 문자열 — 변경 0. `oddBar.goal`, `oddBar.label`, `prev`, `next` 전부 원문 근거를 가진 값이라 그대로입니다.
- `reads` · `source` · `excluded` · `notes` · `youtube` — 변경 0.
- 샷 순서·`kind` 이름·cue 인덱스 — 변경 0. 이번 수정은 **cue 를 읽는 쪽(그리기)만** 바꿨습니다.

승인된 대본은 얼려 둔다는 원칙(ep00s 2차 지시)에 따른 것이고, 이번 건은 반려 자체가 대본이 아니라 **그리기 코드의 폭 계산**이었습니다.

## 3. 화면 문자열이 한 글자도 안 바뀌었다는 확인

✅ **화면에 나가는 문자열은 전부 `spec`/`scene` 에서 읽어 오며, 리터럴을 새로 만들거나 자르거나 줄인 곳이 없습니다.**

| 문자열 | 출처 | 수정 후 |
|--------|------|---------|
| `GOAP 목표 : HungerLevel ↓` | `spec.oddBar.goal` (`gwText = odd.goal \|\| ''`) | **전문 그대로 한 줄에 표시.** 폰트·박스 폭·정렬 기준점만 바뀜 |
| `허기 · HungerLevel` | `spec.oddBar.label` | 그대로. 위치도 그대로(가드가 걸리지 않는 값) |
| `체력` · `기분` · `충성도` | `spec.goodBars[].label` | 그대로 |
| `높을수록 →` | reverse.js 사인(기존 리터럴) | 손대지 않음 |
| `빈 말풍선` · `거꾸로 게이지` | `spec.prev[]` | 그대로. 이제 서로 안 포개지고 각각 읽힘 |
| `성격` · `8단계 커밋` | `spec.next.label` / `.note` | 그대로. 켜지는 타이밍만 늦춤 |
| `게이지가 가득 찼는데 배고픈 상태였다` | `scene.hook` | 손대지 않음 |

🔴 금지 사항이었던 **"긴 문자열을 줄여서 도망가기"** 는 하지 않았습니다. `GOAP 목표 : HungerLevel ↓` 는 24자 그대로이고, 폭 138.72px 이 박스 156.72px 안에 들어가 오른쪽 여백 16 CSS px(글로우 10px 을 더해도 346 < 352)을 확보합니다.

`ctx.font` 크기 축소 코드도 새로 넣지 않았습니다(`disp(700,11)` 고정). nextnote 의 옛 표식 라벨 축소 루프(`while (ls > 8 ...)`)는 기존 코드 그대로이며 이번에 손대지 않았습니다.

## 4. 처방과 다르게 한 것

**없음.** 처방 3-A①·3-A③·3-B①·3-B② 를 그대로 넣었습니다. 판단이 갈릴 수 있는 자리만 아래에 적어 둡니다.

- **3-A②(식별자만 `mono` 로 나눠 그리기)는 채택하지 않았습니다.** 지시대로 ①만 했습니다. 두 조각의 x 를 직접 계산해야 해서 폭 계산 실수의 재발면이 넓고, 한 줄 안에서 폰트가 갈리는 문제(1-4 절)를 완전히 없애지 못합니다.
- **4장의 예비 레버(`nextnote.js:64` 의 `ease(ak)` → `easeOut(ak)`)는 넣지 않았습니다.** 처방이 "재실행에서 아슬아슬하게 걸리면"이라는 조건부로 제시한 것이라, 재점검 결과를 보기 전에 미리 쓰면 조건 없이 연출을 바꾸는 셈이 됩니다. `easeOut` import 추가도 하지 않았습니다 — 필요해지면 그때 한 번에 넣습니다.
- **`checks.edge` 는 선언하지 않았습니다.** 처방 2-2 의 판단(선언의 대가가 크다 — 바로 이 회차의 S4 사고 때문에 추가된 검사를 같은 회차에서 무력화하게 됨)을 그대로 따릅니다. `scene.json` 을 안 건드린다는 제약과도 일치합니다.
- **다른 6개 kind(`hush` `wardline` `flip` `sweep` `tripwire` `hidefault`)는 열지 않았습니다.**
- 🟡 관찰만: `nextnote.js` 의 `mono` import 는 **이번 수정 전부터** 이 파일에서 안 쓰이고 있었습니다(전부 `disp`). 제 수정이 만든 상태가 아니고 처방 범위 밖이라 그대로 뒀습니다. 정리한다면 다음 손댈 때 함께.

## 5. 자가 점검

- **결정성** — 두 파일 모두 `Math.random()`·`Date.now()`·프레임 간 상태를 쓰지 않습니다. 새로 넣은 값은 전부 `w`·`shk`·`ak`·`measureText` 에서 나온 순수 계산입니다. `ctx.measureText` 는 같은 폰트·같은 문자열이면 같은 값이고, 오히려 이번에 **폴백 폰트 의존을 없애 결정성이 올라갔습니다.**
- **팔레트** — 새 색 없음. `tone('accent')`/`tone('sub')`/`tone('ink')`/`tone('track')` 만.
- **선 굵기** — `lineWidth` 값은 손대지 않았습니다(3·5 유지).
- **`clamp` 3인자** — `lib.js:5` 가 `(v, a=0, b=1)` 이므로 `clamp(x + bw/2, PAD + gw/2, w - PAD - gw/2)` 와 `clamp(1 - 1.9*shk)` 둘 다 정상입니다.
- **`reads` 유지 여부** — S4 `reads` 의 "GOAP 목표 화살표는 아래(↓)로 향한다" 는 **잘려 나갔던 `↓` 가 돌아오면서 오히려 복구됩니다.** S10 `reads` 의 "두 사건의 표식이 옆으로 밀려나고" 는 표식 폭만큼(170px) 밀려나며 흐려져 사라지는 것으로 유지됩니다 — 처방 3-B① 의 판단 기록대로, 끝까지 밀어내면 잘림이 되돌아옵니다.

🔴 **미확인**: 작성팀에는 셸이 없어 `render.mjs --still` 과 `check.mjs` 를 직접 돌리지 못했습니다. 위 기하 수치는 전부 검수팀 실측을 인용한 것이며, 실제 접촉률(S4 0% / S10 약 17% 예상)은 오케스트레이터의 재점검에서 확인해야 합니다.
