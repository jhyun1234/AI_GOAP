# ep02s — 작성 노트 (2차 컷)

## 0. 이 문서가 다루는 것

이 노트는 **2차 컷 재작성** 노트입니다. 1차 컷 반려 두 건을 반영해 scene.json 과
`kinds/hush.js` 를 손봤습니다. 1차 컷의 설계 이유 대부분은 여전히 유효하지만,
**축소된 컷에 맞춰 다시 정리**합니다.

## 0.1 3차 수정 — S3 wardline 익명화 (2026-07-30)

2차 컷도 반려 1건 잔존: **S3 wardline 이 화면에 나열한 6종 성격 이름 중 3개
(성실·겁많음·쾌활)가 원문에 없다** — 1차 반려 사유 2와 같은 종류의 사실관계 위반.
숫자만 대조하고 문자열 대조를 놓친 편향(6절 "수치 정직성")이 원인.

**수정 = 선택지 A(익명 자리 처리).** `kinds/wardline.js` 안에서만 처리:
```
const KNOWN = new Set(['게으름', '탐구', '용감함']);
const options = rawOptions.map(name => KNOWN.has(name) ? name : '···');
```
- 6칸 자체는 유지 — 원문의 `Random.Range(1,7)` = 6종 존재라는 사실은 근거 있음
- 화면에 표시되는 이름은 원문 확인된 셋(게으름·탐구·용감함)만
- 나머지 세 칸은 `···` = "원문 미명시" 를 시각적으로 정직하게 표현
- `picked = 0`(게으름) 이라 채워지는 원 안 텍스트도 안전

**scene.json 은 안 건드림** — 반려 지시대로 파일 하나만. `spec.options` 배열은
그대로 두고 render 단에서 화이트리스트 필터. 원문 미명시 3개 이름은 데이터로는
남지만 화면에는 안 나감.

**7절 "수치 정직성" 갱신 필요 항목**: "6개 성격 상자 = 화면에만" 은 이제 사실이
아니다 — 화면에도 셋만 이름으로, 셋은 익명. 아래 7절 각주 참조.

**같은 편향의 재발 방지**: 4차 컷이 필요한 상황이면 화면 문자열 전수를 원문에서
grep 한 뒤에만 통과 선언. 숫자 검사와 문자열 검사는 별도 절차.

## 1. 반려 반영 요약

### 반려 1 — 총 길이 초과 (83.6초 → 목표 50초 이내)

- **씬 10개 → 8개**. 두 개를 통째로 뺐습니다.
  - **S2 blank 삭제** — 원인 설명 샷(리크루팅 경로 vs 씬 배치 두 갈래). 원인은 S3 wardline
    의 준비(‘Personality.None 딱지가 문턱에 걸려 성격이 채워진다’)와 자막 ‘그래서 Awake 에
    한 줄’ 로 함축합니다. 원문의 ‘아키텍처의 틈’·‘RecruitmentSystem을 통해 …’ 서술을
    자막으로 부르려면 별도 그림이 필요한데, 60초 상한 안에서는 자리가 없어 아예 부르지
    않는 편을 골랐습니다(‘그림 없이 자막만 부르면 두 채널이 겉돈다’).
  - **S6 scoped 삭제** — 트레이드오프 패널. 이 편에서 처음 쓰려던 패턴이었으나 60초
    상한 때문에 자리가 없어졌습니다. 원문의 ‘명시적인 트레이드오프가 필요했습니다’ 문장은
    S5 flip 의 source 각주 안 ‘GOAP 액션 이름은 유지했습니다’ 로만 남겼습니다.
    다음 회차에서 처음 쓸 자리로 남겨 둡니다.
- **자막 26줄 → 15줄**. 각 씬을 대부분 **2줄**로 정리했습니다(S10 만 1줄).
- **각 문장을 짧게**. voiceover 한 줄을 대략 4~5초 안에 들어가게 다듬었습니다.

계산(문자당 6.5자/초 근사):
- 발화 약 40~42초 + 정지 3.8초 = 약 44~46초
- SHOT_TAIL 0.35 × 8 = 2.8초 → 렌더 총 약 47~49초
- 60초 상한 안, 목표 50초 안. 실측이 넘치면 다이어트 자리는 S4 두 번째 줄과 S5 첫 줄
  (예상_길이 항 참조).

### 반려 2 — 원문에 없는 대사 삭제

원문의 실제 대사는 **‘왜 나만 시키지..’ 하나뿐**입니다. 1차 컷 hush 가 만들어 낸 세 위반:
- `spec.quiet[1].expects = "탐구하고 싶어."` → 원문 없음. **삭제.**
- `spec.quiet[2].expects = "겁이 나요."` → 원문 없음. **삭제.**
- `spec.loud.line = "탐구하고 싶어!"` + 위쪽 정상 주민 성격 ‘탐구’ → **위쪽 정상 주민 자체를 삭제.**

**재설계된 hush**: 위쪽 대비군을 지우고 조용한 셋만 나란히 세웁니다. 셋 중 맨 위 자리에만
회색으로 원문 유일 대사 ‘왜 나만 시키지..’ 가 기대치로 남습니다(‘저 자리에 이 대사가 들어왔어야 했다’).
나머지 둘은 말풍선 상자만 점선으로 놓고 안은 커서 깜빡임뿐입니다. ‘조용함’ 자체가
대비군 없이도 읽히도록 **빈 자리를 재료로 씁니다.**

### 부수 확인 — cue 인덱스 정합

1차 컷은 lines 배열이 2줄인데 cue 인덱스가 2를 가리키는 자리가 4곳 있었습니다
(S3.rollCue=2, S5.settleCue=2, S6.pickCue=2, S10.arriveCue=1). engine 의 `cue()` 가
`Math.min(i, s.rel.length - 1)` 로 안전하게 클램프하기 때문에 렌더는 통과했지만,
지시대로 명시적으로 맞췄습니다. **2차 컷은 모든 lines 가 최대 2줄이므로 cue 인덱스는
전부 0 또는 1 만 사용합니다.**

| 샷 | lines 수 | 사용 cue |
|----|---------|---------|
| S1 hush | 2 | quietCue=0, expectCue=1 |
| S3 wardline | 2 | wardCue=0, rollCue=1 |
| S4 reverse | 2 | fillCue=0, flagCue=1, goalCue=1 |
| S5 flip | 2 | flipCue=0, settleCue=1 |
| S7 sweep | 2 | sweepCue=0, beatCue=1 |
| S8 tripwire | 2 | okCue=0, trapCue=1 |
| S9 hidefault | 2 | reviveCue=0, stampCue=1 |
| S10 nextnote | 1 | shiftCue=0, arriveCue=0 |

## 2. 이 회차의 기본 도형 (유지)

**방향의 이야기**. 두 사건 모두 방향 축 위에 있습니다.

- A(성격 누락) = 성격이 붙는 **방향**(리크루팅→배분)에 이 셋이 들어오지 않아 **조용한 자리**
- B(허기) = 게이지가 도는 **방향**이 반대라 채워질수록 굶주렸다

두 사건이 원문 마지막 절 ‘왜 중요한가’ 에서 한 문장으로 묶입니다 —
*“시스템이 조용히 잘못된 방향으로 작동하고 있었다.”* 이 문장이 이 편의 S9 결말.

| 샷 | kind | 이 축에서의 몫 |
|----|------|---------------|
| S1 | hush | 있어야 할 방향의 신호가 나오지 않는다 (조용한 자리) |
| S3 | wardline | 문턱 하나가 방향을 채워 준다 |
| S4 | reverse | 방향이 반대인 하나가 잘 어울리는 셋 옆에 튀어 있다 |
| S5 | flip | 반대를 뒤집는다 (이름·방향 동시 회전) |
| S7 | sweep | 뒤집힘이 파일들 사이로 흘러간다 |
| S8 | tripwire | 방향이 다시 뒤집히면 실선이 잡아챈다 |
| S9 | hidefault | 왼쪽엔 없는 신호, 오른쪽엔 거꾸로 신호가 되받는다 |
| S10 | nextnote | 이 편의 표식이 옆으로 밀리고 다음 편 표식이 앉는다 |

## 3. 회차 안의 되받기 (유지)

- **hush → hidefault** (S1 → S9 왼쪽). 조용한 자리 → 결말의 왼쪽 반절.
- **reverse → hidefault** (S4 → S9 오른쪽). 거꾸로 게이지 → 결말의 오른쪽 반절.

되받기 자리가 유지되어야 두 사건이 결말에서 하나의 결함으로 묶입니다.

## 4. 옛 어휘 대조 (유지 — 축소분만)

새 이름 8개(hush wardline reverse flip sweep tripwire hidefault nextnote) 모두
ep00s(9종)·ep01s(10종) 어느 쪽과도 겹치지 않습니다. **삭제된 blank·scoped 는 다음 회차
자리로 남깁니다** — 특히 scoped(트레이드오프 패널)는 시리즈에서 아직 처음 안 쓴 패턴이라
쓸 자리를 골라 아껴 둡니다.

**파일 정리**: `kinds/blank.js`, `kinds/scoped.js` 는 scene.json 에서 참조되지 않아
로드되지 않습니다. 두 파일은 삭제하려 했으나 이 실행 환경에서 파일 삭제 도구가 없어
남겨 뒀습니다 — check.mjs 는 참조되는 kind 만 검사하므로 결과에는 영향 없습니다.
후속 정리 자리로 표시해 둡니다.

## 7. 수치 정직성 (검증됨)

화면이 주장하는 숫자는 여섯이고 **전부 원문에 있습니다**:

- **3** — 씬 배치 주민 수. 원문 ‘주민들’ 복수형 + 게으름/탐구/용감 세 성격 예시 언급
- **6** — 성격 종류. 원문 `Random.Range(1, 7)` = 1~6
- **34** — 파일 수. 원문 그대로
- **30 → 70** — 초기값. 원문 그대로
- **<20** — P0 임계값 SatietyLevel <20. 원문 그대로
- **15** — RecruitData 에셋. 원문 그대로

**만들지 않은 것**: S4 게이지 채워진 정도(체력 85·기분 72·충성도 66·허기 90)는
원문에 수치가 없어 도형 파라미터로만 썼고, 자막은 어떤 %도 부르지 않습니다.

**3차 수정 후 각주 (2026-07-30)**: 위 6종 성격 이름 항목은 2차 컷 시점 자체 검토
누락이었습니다. 3차 컷은 wardline 이 화면에 이름으로 그리는 성격은 셋(게으름·
탐구·용감함, 전부 원문 근거) 뿐이고 나머지 세 칸은 `···` 익명 자리입니다.
scene.json 의 `spec.options` 는 그대로지만 wardline.js 내부 화이트리스트가
표시를 걸러 냅니다. **"원문에 있는 문자열만 화면에 나간다"** 는 규칙이 데이터가
아니라 렌더 계층에서 지켜집니다.

| kind | 계속 도는 것 |

## 9. 페이싱

8샷 15자막. voice.json rules.6 준수 — 600ms 이상 큰 쉼은 **1회뿐** (S8 마지막
‘테스트 하나가 방향을 지키고 있었거든요.’ 뒤 700ms). 나머지는 평시 150~300ms.

이 자리에 큰 쉼을 아낀 이유는 1차 컷과 같습니다 — 이 문장이 이 편의 안전망을 못박는
자리라, 다음 자막(S9 결말)이 들어오기 전에 무게를 실어야 합니다.

## 10. 미확인 항목

작성팀에는 셸 실행 권한이 없어 다음을 직접 못 돌렸습니다. 검수팀 컷에서 확인 필요:

1. **TTS 실측 길이** — 예상 44~46초는 문자당 6.5자/초 근사값. 넘치면 다이어트 자리:
   - S4 두 번째 줄: ‘근데 허기만, 높을수록 배고픔이에요.’ → ‘허기만 반대로.’ (약 -12자)
   - S5 첫 번째 줄: ‘그래서 이름을 뒤집었어요. 허기가 아니라, 포만감.’ → ‘이름을
     뒤집었어요. 포만감으로.’ (약 -7자)
2. **결정성 3패스** — 모든 움직임을 t·cue·rnd(정수) 의 함수로만. Math.random/Date/프레임
   기억/CSS transition 없음.
3. **아래 가장자리 잘림** — 모든 요소를 캔버스 바닥에서 15px 이상 띄웠습니다.
   축소된 hush 는 FOOT=44 로 늘려 에러 로그 상자가 안전영역 안.
4. **3색 팔레트** — 3색만 사용. 예외 선언 없음.
