## 2. 말·그림 도착 시각 — 통과 (인덱스 대조로 끝내지 않았음)

`cue(i, lead, span)` 은 `engine/engine.js` 236~248행: `W = lead + rel.dur × span`, 진행도 p 인 시각 =
`p × W − lead`. 각 kind 의 `ease(cue(...))` 는 **이중 ease**(cue 값을 ease 한 뒤 다시 ease 하는 자리가
있다)라 그 점까지 풀어서 환산했다.

**① `t` 로 도는 조건 — 사건은 하나도 없다.** 14개 kind 를 전부 열어 `frac(t/N)` · `t %` 사용처를 세었다:
`swell` 궤도(DRIFT 2.3) · `rash` 스캔선(3.1+i×0.37) · `threeway` 값 표식(2.6) · `godfile` 코드 줄(4.2) ·
`thirdway` 표식(2.9) · `freeze` 탐색 점(3.4) · `ladder` 빛 띠(3.8) · `oneasset` 테두리 표식(4.6) ·
`rehearsal` 커서(1.05)·호흡(2.4) · `askfirst` 진행 표식(5.2) · `purge` 훑는 선(3.6) · `weight` 숨(2.7) ·
`pinrule` 검사 표식(2.2) · `handover` 흐름 표식(3.2)·호흡(2.2). **전부 장식이고, 사건을 여는 문턱이 아니다.**
사건성 흔들림도 진폭이 cue 에 곱해져 있다(`godfile` `sway = sin(frac(t/0.42)…) × 3.4 × sk`,
`threeway` shake 는 `cut > 0.4` 즉 `dk` 안에서만). ep02s `tripwire` 형 사고 없음.

**② 다른 cue 로 만든 문턱 — 없다.** 한 샷 안의 모든 파생 문턱이 **그 샷의 같은 cue 값**에서 갈라진다
(`pinrule` 의 게이트 등장·접근·되밀림·반려 라벨이 전부 `gk`, `oneasset` 의 접근/되튕김이 전부 `bk`).

`tk` = 자막 3("M1, 여가와 명령과 거부요")이라 **그 자막이 부르는 것이 바로 명령과 거부**다 — 어긋남이 아니다.
ep00i `runmark` 형 사고 없음.

## 3. 효과음

### 3-1. 🔴 반려 — S9 `tick` gain 이 이 설정의 피크 천장에 걸린다

`sfx.mjs` 의 `synth()` 를 **씬에 적힌 옵션 그대로** 불러 재현했다(이 환경이 유일한 사전 방어선이라 실행함).

```
$ node -e "... import('./sfx.mjs') ... synth(kind, {dur, freq, from, to, gain}) ..."
S1  at=2 thud  gain=0.070 dur=0.22            상한 0.1728  ok
S4  at=1 riser gain=0.066 dur=0.85 120→400    상한 0.3217  ok
S5  at=2 latch gain=0.068 dur=0.16            상한 0.0749  ok
S9  at=2 tick  gain=0.065 dur=0.05 freq=1900  상한 0.0602  🔴 CLIP
S11 at=2 sweep gain=0.072 dur=0.70            상한 0.1845  ok
S11 at=3 drop  gain=0.076 dur=0.55            상한 0.2649  ok
S14 at=1 riser gain=0.062 dur=0.95 220→700    상한 0.3222  ok
```

**무엇이 틀렸나.** `tick` 의 상한 0.065 는 **기본 옵션(dur 0.06 · freq 1400)** 에서 잰 값이다(재현: 0.0657).
이 씬은 `dur 0.05 · freq 1900` 으로 **더 짧고 더 높게** 잡았고, 그러면 피크/RMS 가 7.01 → **7.64** 로 올라가
같은 gain 에서 먼저 천장(0.46)에 닿는다.

```
tick dur=0.05 freq=1900  peak/RMS=7.64  최대 gain=0.0602   ← 씬은 0.065
tick dur=0.06 freq=1400  peak/RMS=7.01  최대 gain=0.0657   ← writer.md 가 인용한 상한
```

**결과**: 렌더 시 `⚠️ sfx tick: 피크 천장(0.46)에 걸려 목표 RMS 0.065 → 실효 0.0602 (-0.7dB)` 가 찍히고,
**이 편의 클라이맥스(말풍선에 '돌 채집'이 뜨는 순간)에 놓인 소리만 조용해진다.** RMS 정규화가 없애 둔
뾰족한 소리의 불균형이 되살아나는 자리라, 단순히 작아지는 것과 다르다.

**고칠 방법(둘 중 하나 · 실측 상한 첨부)**
- (A) 성격을 유지하고 gain 을 내린다 → **0.058 이하**. (0.060 은 상한 0.0602 와 0.3% 차라 여유가 없다.)
- (B) gain 0.065 를 유지하려면 `dur` 을 늘린다 → `dur 0.07` 상한 0.0685 · `dur 0.08` 상한 0.0718.
  단 "짧고 높게"라는 이 소리의 설계 의도가 바뀌므로 `why` 를 함께 고쳐야 한다.

함께 고칠 것: `scene.notes.효과음` 과 `writer.md` 4절의 **"tick 0.065(상한 0.065)"** 문구.
상한은 kind 만이 아니라 **그 kind 의 옵션까지 넣어야 정해진다** — 그 사실이 문서에 남아야 다음 회차가 안 밟는다.
`latch` 0.068(이 설정 상한 0.0749)은 여유 9%로 안전하다.

### 3-2. 배치·절제·`delayMs`·`why` — 통과

- 14샷 중 6샷 · 총 7개. **90초 기준 5~8개** 안이고, 산정 133초짜리에 7개면 오히려 절제된 쪽이다.
- **나레이션이 부르는 사건에만 붙었다**: 질문 카드 착석 / 기둥 차오름 / 걸쇠 잠금 / 말풍선 점화 /
  격자 걷힘 / 숫자 낙하 / 3막 열림. 정적을 메우려고 깐 소리는 없다.
- **안 넣은 자리에 사유가 있다**(S2 · S7 · S12 · S14 마지막). 특히 S7 에서 아홉 칸에 `tick` 아홉 번을
  안 단 판단은 옳다.
- `delayMs` 는 전부 draw 를 풀어서 낸 값이고 위 2절에서 **7개 모두 재검산해 일치**했다. `why` 는 전부
  채워져 있고 draw 근거가 초로 환산돼 있다. 자막과 동시(0ms)로 둔 자리 없음.
- S11 한 샷에 둘을 둔 것도 자막이 둘로 갈린 별개 사건이라 납득된다. `drop` 을 착지(+2016ms)가 아니라
  낙차 구간에 둔 이유(나레이션이 '오천 구백 칠십칠'을 부르는 자리를 덮지 않으려고)도 타당하다.

## 4. 🟠 그림 돌려막기 — `purge` 와 ep02s `sweep.js` 의 장치가 겹친다

`notes.돌려막기를_어떻게_피했나` 는 `purge` 를 ep01s `teardown` · ep00s `excise` · ep01s `erasure` ·
ep01s `budget`/`shortfall` 과 대조했다. **정작 가장 가까운 이웃인 직전 회차 ep02s `sweep` 이 빠졌다.**

```
ep02s/kinds/sweep.js   : 34칸 격자, headIdx = sk × total, 왼쪽 위 → 오른쪽 아래 순차,
                         앞머리 뒤의 칸은 흰색으로 '채워진다'
ep03s/kinds/purge.js   : 59칸 격자, gone = clamp(wk × 67 − i), 왼쪽 위 → 오른쪽 아래 순차,
                         앞머리 뒤의 칸은 '비고' 윤곽만 남는다
```

둘 다 **파일 개수만큼의 격자 + 좌상→우하 순차 앞머리**다. 극성(채움 ↔ 비움)과 뜻(바뀐다 ↔ 없어진다)이
반대라는 점은 인정하고 통과선 위로 두지만, 사용자 판정("비슷한 애니메이션을 돌려막기하는 건 내가 원하는
방향이 아니야")에 비추면 **작성팀이 스스로 이 대조를 하지 않았다는 것 자체가 문제**다.

요구: `notes.돌려막기를_어떻게_피했나` 에 **ep02s `sweep` 항목을 추가**하고, 무엇으로 갈랐는지 적어라
(빈 슬롯 윤곽이 남는다 · 게이지/막대를 안 쓴다 · 이름 붙은 칸이 하나 있다 등, 이미 코드에 있는 차이).
가능하면 걷힘의 **순서**를 바꾸는 것도 검토해 달라(좌상→우하가 아니어도 뜻은 산다).

나머지 13개 kind 는 앞 회차와 겹치지 않는다. 이름 14개 전부 신규이고, 장치도 갈렸다 — 특히
`ladder`(쌓임이 아니라 '아래 칸의 확인이 위를 허락한다'라 두 번 올라감), `rash`(퍼짐·얽힘이 아니라
여섯 기둥에 번갈아 돋음), `handover`(카드가 아니라 막의 가로 띠가 주인공), `pinrule`(걸림을 화면

## 7. 그림이 뜻을 나르는가 — 통과

14개 `reads` 를 각각 해당 `kinds/*.js` 와 대조했다. "무언가를 보여준다" 수준의 빈말은 하나도 없고,
`reads` 에 적힌 획이 코드에 실제로 있다. 특히 확인한 자리:

- `swell` — 블록은 1개씩, 점은 `[1,2,4,7,11]`. **두 증가율의 차이**가 문장의 뜻 그대로다.
  고침(강조색 채움 + 링) 옆에서 다른 열 점 둘이 ×로 터진다 = "고치면 다른 데가 터진다".
- `threeway` — 왼쪽만 취소선이 그어지고 나머지 두 갈래가 `breakY` 에서 끊긴 뒤 상자가 흔들린다.
  **새 숫자를 안 쓴다**(원문이 바꾼 값을 말하지 않으므로). 뜻이 정확하다.
- `weight` — 조각 55개가 **하나도 안 줄고** 다섯 상자로 재배치된다. 이 편의 반전(73행)을 문장이 아니라
  개수 보존으로 말한다. 사라지는 연출을 안 넣은 판단이 옳다.
- `rehearsal` — 편집기 줄 번호가 `1` 에 고정되고 커서만 깜빡인다. **변하지 않는 숫자**가 증명이다.
- `askfirst` — 다섯 칸 중 오른쪽 열은 '결정' 하나뿐이고, 계속 도는 표식이 매 바퀴 그 한 칸을 건너갔다 온다.
- `handover` — 1막 점선 / 2막 짧은 칸 + 마감 캡 / 3막이 가장 길게 자람. '다음 편'이 아니라 '다음 막'을 넘긴다.
