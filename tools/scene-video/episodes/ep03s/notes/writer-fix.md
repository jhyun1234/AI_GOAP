## 🔴 1. S9 `tick` gain 이 이 설정의 피크 천장에 걸린다

**→ (A) 안으로 고쳤다. 옵션은 그대로 두고 gain 만 0.065 → `0.058`.**

| | 값 |
|---|---|
| 조합 | `tick` · `dur 0.05` · `freq 1900` (그대로) |
| 실측 peak/RMS | **7.64** (기본 옵션 `dur 0.06·freq 1400` 은 7.01) |
| 이 조합의 실측 상한 | **0.0602** |
| 1차 컷 | 0.065 → 천장 0.46 에 걸림 (🔴 CLIP) |
| 2차 | **0.058** — 상한의 96.3%, 여유 3.7% |
| 음량 변화 | 0.065 → 0.058 = **−1.0 dB** |

**왜 (B)가 아닌가.** (B)는 `dur` 을 0.07~0.08 로 늘려 상한 0.0685~0.0718 을 확보하는 안인데,
그러면 이 소리의 설계 의도인 **"짧고 높게 — 계획이 화면에 뜨는 점화음"** 이 바뀐다.
0.065 ↔ 0.058 의 차이는 −1.0dB 로 귀로는 사실상 같은 크기다. 반면 천장에 걸리면 −0.7dB 로
주저앉을 뿐 아니라, **RMS 정규화가 없애 둔 "뾰족한 소리만 작게 들리는" 불균형이 되살아난다**
(sfx.mjs 142~151행). 이 편의 클라이맥스(말풍선에 '돌 채집'이 뜨는 순간)에 놓인 소리라
음량 1dB 보다 성격과 균일함을 지키는 쪽을 택했다. 0.060 을 안 쓴 것은 상한과 0.3% 차라
실측 자막 길이가 바뀌어도 여유가 없기 때문이다.

**함께 정정한 문서** — 요구대로 "상한은 kind 가 아니라 **kind + 옵션**이 정한다"를 남겼다.

- `scene.json` → `notes.효과음`: 일곱 조합 전부의 실측 상한과 현재 값을 표로 적고,
  1차 컷이 문서표의 `tick 0.065` 를 다른 옵션에 그대로 적용해 반려된 경위를 명시.
- `scene.json` → S9 `sfx[0].why`: 7.01 → 7.64 / 상한 0.0602 / −1.0dB / (B)를 안 고른 이유.
- `notes/writer.md` 4절: **「gain 상한 — kind 가 아니라 kind + 옵션이 정한다」** 절을 새로 두고
  일곱 조합 표(상한·현재값·여유)를 넣었다. 끝에 다음 회차에 넘기는 한 줄 —
  *"표의 `tick 0.065` / `latch 0.071` 은 기본 옵션의 값이다. `dur`·`freq` 를 건드렸으면
  그 조합으로 다시 재라."*
- **다른 여섯 개 sfx `why` 에도 그 조합의 실측 상한을 한 줄씩 붙였다**(thud 0.1728 / riser
  0.3217 · 0.3222 / latch 0.0749 / sweep 0.1845 / drop 0.2649). 다음 검수가 씬만 읽고 대조할 수 있게.
- `latch` 0.068 은 지시대로 **안 건드렸다**. 다만 `why` 의 "상한 0.071" 표기를
  **"이 설정(dur 0.16)의 실측 상한 0.0749, 여유 9%"** 로 고쳤다 — 0.071 은 기본 dur 0.14 의 값이라
  같은 착각을 재생산하는 문구였다.

## 🟠 2. S11 `sweep` 이 ep02s S7 과 같은 kind · 같은 성격이다

**→ (a)와 (b)를 둘 다 했다. 그림의 사건을 갈고, `why` 에 ep02s S7 을 호명해 대조했다.**

**(a) 그림을 갈았다** — `kinds/purge.js` 의 걷힘 순서.

```
1차: gone = clamp(wk × 67 − i)                                  ← 좌상→우하 순차 앞머리
2차: gone = clamp((wk × (dmax + 0.7) − (dmax − d_i)) × 2)       ← 이름 붙은 칸에서 먼 것부터
     d_i  = markAt(=58, VillagerFSM) 까지의 거리. 세로에 칸 간격비 22/36 을 곱해 화면 거리로 맞춤
     dmax = 5.426 (맨 윗줄 양 끝 칸)
```

앞머리라는 '선'이 없어지고 **같은 거리의 칸들이 한꺼번에 사라진다** — 바깥 고리가 그 한 칸으로
조여드는 그림이다. 이 순서는 이 편에만 뜻이 있다: W8 은 훑고 지나가는 단계가 아니라 원문 71행이
말하는 **'일괄 삭제'**이고, 지난 편에 손댄 그 파일이 **구조적으로 맨 마지막에 남아야**
S11 두 번째 자막("지난 편에 한 줄 넣었던 그 파일도 여기 있어요")이 갚아진다.
(1차에서는 그 칸이 마지막 인덱스라 '우연히' 마지막이었다.)

**(b) `why` 에 ep02s S7 을 호명했다.** 소리는 `sweep` 그대로 두되 근거를 세웠다 — 6종 중
'여럿이 한꺼번에 사라지는 넓은 소리'는 `sweep` 뿐이다(`tick`·`latch`·`thud` 는 한 점의 사건을
가리켜 59칸을 못 받고, `drop` 은 같은 샷 다음 자막이 이미 쓰며, `riser` 는 방향이 반대다).

| | ep02s S7 | ep03s S11 (2차) |
|---|---|---|
| 그림의 사건 | `headIdx = sk×34` — 좌상→우하로 **선이 지나간다** | 바깥 고리가 한 칸으로 **조여든다**. 앞머리 없음 |
| 소리를 무엇에 맞췄나 | 앞머리가 한가운데 칸을 지나는 때(+1040ms) | **한꺼번에 비는 칸 수가 최대인 때**(30칸째 = +690ms) |
| 극성 | 지나간 자리가 흰색으로 채워진다(**바뀐다**) | 지나간 자리에 윤곽만 남는다(**없어진다**) |
| dur 의 근거 | 0.62 = 앞머리가 10번→24번 칸을 가는 시간 | 0.70 = 거리 4→3 고리에 19칸이 몰린 구간(+518~+739ms)을 앞뒤 0.35초로 감싼다 |
| delayMs | 730 | **340** (새 순서로 다시 냄) |

**`delayMs` 를 다시 낸 과정**(전부 산정 자막 기준. 자막 3 = "파일 쉰아홉 개가 지워지고," 15자,
`rel.dur` = 15÷6.7 + 0.15 = 2.389s, `cue(2, 0.15, 0.75)` → 창 W = 1.942s):

- 30칸(절반)이 비는 때 → `wk` = 0.400 → `ease` 역산 raw = 0.4328 → **자막 시작 +690ms**
- `sweep` 은 `sin(πk)` 포락선이라 정점이 소리 한가운데(dur 0.70 → +350ms)
- ⇒ `delayMs` = 690 − 350 = **340** (1차 385)
- 곁수치: 첫 칸 **+86ms** / 마지막(이름 붙은) 칸 **+1470ms** / 소리 구간 0.34~1.04초에 **6칸 → 51칸**

같은 표를 `writer.md` 4절 「`sweep` — 같은 kind 를 쓰면서 ep02s S7 과 무엇을 갈랐나」에도 남겼다.
