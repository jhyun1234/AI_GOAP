## 2. 🔴 R-1 (반려) — 효과음 `latch` 가 형제 편과 겹치고, 겹치지 않는다는 근거가 거짓이다

`scene.json` `notes.효과음` 이 이렇게 적혀 있다:

> "②latch — **이 회차 계열에서 latch 를 쓰는 것은 여기 하나뿐이다.**"
> "③riser — 4-2편은 sweep, 4-1편은 drop·tick 을 쓴다. **세 편이 여섯 종을 겹치지 않게
> 나눠 쓰게 됐는데**…"

**둘 다 거짓이다.** 형제 편 `scene.json` 을 열어 전수 대조한 결과:

| 편 | 실제 sfx |
|---|---|
| `ep04s-1` | S1 `thud`(dur 0.16 · f 210) · S2 `drop` · S3 `tick` |
| `ep04s-2` | S1 `thud`(dur 0.30 · f 124) · **S1 `latch`(dur 0.16 · seed 기본 7)** · S3 `sweep` |
| `ep04s-3` | S1 `thud`(dur 0.20 · f 168) · **S1 `latch`(dur 0.16 · seed 23)** · S2 `riser` |

- `thud` 는 **세 편 전부** S1 에서 쓴다(음색은 셋 다 다르니 이건 지적하지 않는다).
- `latch` 는 **4-2편과 4-3편이 같은 dur 0.16 으로** 쓴다.

### 소리로 얼마나 같은가 — 파형을 실제로 합성해 쟀다

`sfx.mjs` 의 `latch` 는 `click(seed 잡음 · exp(-260t)) × 0.5 + body(340/680Hz · env d=14) × 0.7`
이다. **`dur` 이 같으면 body 는 완전히 동일하다.** seed 는 앞부분 잡음 전이만 바꾼다.

```
정규화 상관(ep04s-2 latch vs ep04s-3 latch)  0.7460
차이 에너지 — 앞 5ms  3.85e+0   /   나머지 155ms  3.28e-1   (92% 가 앞 5ms 에 몰려 있다)
```

click 은 시정수 3.8ms 라 **15ms 뒤엔 사라진다.** 즉 두 소리는 **첫 5ms 의 질감만 다르고
나머지 145ms 는 같은 파형**이다. RMS 정규화가 크기까지 맞추므로 체감은 사실상 같은 소리다.

### 성격도 같다

- `ep04s-2` S1 `latch.why`: *"'여가' 칸이 사다리 맨 아래에 **걸리는** 순간"*
- `ep04s-3` S1 `latch.why`: *"없던 규칙이 **자리에 앉는다**"*

같은 kind · 같은 길이 · **같은 성격**("한 칸이 자리에 앉는다")이 하루 차이로 나가는
형제 편 둘에 연달아 붙는다. 이것이 지시서가 말하는 돌려막기다.

### 원인 — 대조 기준을 잘못 잡았다

작성 노트가 `thud` 를 *"ep04s 1차본의 첫 thud(dur 0.26 · freq 132)"* 와 비교한다.
확인해 보니 `episodes/ep04s/scene.json`(1차본)의 sfx 는 `thud 0.26/132 · drop · tick · tick`
으로 **`latch` 가 아예 없다.** 그래서 "여기 하나뿐"이 나온 것이다.
그런데 **1차본은 발행되지 않는다** — `state/schedule.json` 의 `order` 는
`… "ep04s-1", "ep04s-2", "ep04s-3", …` 이고 `ep04s`·`ep04s2` 는 치환돼 사라졌다.
**대조 대상은 형제 편 `ep04s-1`·`ep04s-2` 다.**

### 고칠 것

둘 중 하나. 어느 쪽이든 `notes.효과음` 과 `sfx.why` 의 **거짓 문장을 함께 고쳐라.**

1. `latch` 를 유지하고 `dur` 을 확실히 갈라라(예: 0.16 → 0.11 또는 0.22).
   body 의 감쇠가 `exp(-14·t/dur)` 라 dur 이 바뀌면 소리의 길이와 꼬리가 같이 바뀐다.
   seed 만 바꾸는 것은 앞 5ms 만 바꾸는 것이라 부족하다(위 실측).
2. 아니면 kind 자체를 바꿔라. 이 회차 셋 중 `drop`·`sweep`·`tick` 이 안 쓰였고,
   그중 4-2·4-1 이 쓰지 않는 것은 없으니 결국 1번이 현실적이다.

🟢 **`gain` 은 손대지 마라.** 셋 다 0.060 에서 피크 천장 0.46 에 **안 걸린다** — 직접 합성해 쟀다:

```
thud (0.20/168)      peak 0.1676  단기RMS 0.0600  피크/RMS 2.79   천장까지 여유 큼
latch(0.16/seed23)   peak 0.3377  단기RMS 0.0600  피크/RMS 5.63   (이 설정의 상한 gain ≈ 0.0825)
riser(0.72/150→470)  peak 0.0865  단기RMS 0.0600  피크/RMS 1.44   (상한 gain ≈ 0.30)
```

`⚠️ sfx …: 피크 천장에 걸려` 경고는 **셋 다 안 난다.** 렌더 로그를 못 본 상태에서
기본값에 붙여 둔 판단이 옳았다.

### 3-B. S1 사각지대 상자·`90` 눈금이 그것을 부르는 자막보다 3.6초 이르다

`blindspot.js:123` 의 사각지대 블록 게이트가 `sk`(= `stuckCue` = **자막 1**)다.
합성 타임라인으로 시각을 풀었다:

```
자막 1 시작 = 3.484s → 상자가 보이기 시작 3.46s
자막 2 시작 = 7.097s   ("피로 칠십에서 구십, 거부가 영구가 되는 거죠")
선행 = 3.6초   (가이드 한도 ±20프레임 = 0.67초)
```

스틸 `6.5s.png`(자막 1 구간)에 이미 점선 상자 · `90` 눈금 · 「사각지대」가 다 서 있다.
🔑 **ep00i `runmark` 형 사고는 아니다** — 다른 cue 의 진행도로 만든 문턱이 아니라
정직하게 `stuckCue` 에 물려 있고, 자막 1 이 부르는 ✕/점선 화살표도 같은 자리에서 함께 뜬다.
그래서 반려가 아니라 정정 요구다. 다만 **작성팀의 방어 문장이 틀렸다** —

> `notes.타이밍_규율`: *"나레이션이 '구십'을 부르는 것은 자막 2 지만 **그때 새로 그릴 것이
> 없다**"*

`permCue = 2` 라 자막 2 에서 「거부가 일시적인 상태가 아니라 사실상 영구가 된다」가 새로 뜨고,
거부 구간 채움이 `0.12+0.14·pk` 로 진해지고, 표식 떨림 폭이 `4+4·pk` 로 커진다.
스틸 `9s.png` 에서 셋 다 보인다. 그릴 것이 있다.

→ 상자·`90`·「사각지대」를 `permCue` 로 옮기고 자막 1 에는 ✕·점선 화살표·리뷰 칩만 남기거나,
아니면 위 문장을 사실에 맞게 고쳐 **왜 그래도 자막 1 이 맞는지**를 다시 써라.

### 3-C. `tworules` 의 「다가오다 멈춘다」가 화면에서 안 읽힌다

`reads` 와 kind 머리주석의 논지가 전부 여기 걸려 있다 —
*"두 요소가 다가오다 멈춰 틈을 남기는"*, *"마주 보는 것이 아니라 못 만나는 것이 도형이다"*.

코드를 풀면 이동 거리가 `tops = [lerp(46,54,approach), lerp(148,132,approach)]`,
즉 **캔버스 8px 과 16px**(화면 환산 약 22px · 45px)다. 게다가

```
alpha    = clamp(rk*1.8)      → rk = 0.556 에서 1.0 도달
approach = ease(clamp(rk/0.55)) → rk = 0.55 에서 1.0 도달
```

**페이드인이 끝나는 순간 이동도 끝난다.** 스틸 `28.4s.png`(샷 시작 +0.14초)에서 카드는 이미
거의 제자리에 있고 흐릴 뿐이다. 시청자가 보는 것은 "다가오는 둘"이 아니라
**"이미 자리에 있는 둘이 밝아지는 것"** 이다.

🟢 **뜻 자체는 전달된다** — 스틸 `30s.png` 에서 ✓「옳다」 둘 + 그 사이 점선 「사각지대」가
"지목당하는 것은 카드가 아니라 사이"를 정확히 준다. 그래서 반려가 아니다.
그러나 `reads` 가 화면에 없는 동작을 적고 있으므로 **둘 중 하나**를 하라:
① 이동 거리를 늘리고 `approach` 를 `alpha` 보다 늦게 끝내 실제로 다가오게 하거나,
② `reads` 와 머리주석에서 "다가오다"를 빼고 실제 그림(멈춘 둘 사이의 틈)으로 다시 쓴다.

### 3-E. `sfx.delayMs` 는 유도 방식이 맞다 — 실측 나오면 재산정

세 값의 유도를 처음부터 다시 풀었다. **`raw` 진행도는 세 개 다 소수 넷째 자리까지 일치한다**
(0.3986 / 0.4696 / 0.7129). 차이는 자막 길이 추정에서만 온다 —
작성팀은 문장부호 포함 자수를, `tts.mjs` 는 `[.,?!…]` 제거 자수를 쓴다.

| sfx | 무엇이 그때 | 작성팀 `delayMs` | 합성 실측 | 차 | 그 자막 발화 길이 |
|---|---|---:|---:|---:|---:|
| S1 자막1 `thud` | ✕ 가 다 그어짐 `sk=0.35` | 810 | 774 | +36 | 3,433ms |
| S1 자막3 `latch` | 산책 -2 화살표 완성 `fk=0.4545` | 1,225 | 1,138 | +87 | 3,881ms |
| S2 자막2 `riser` | 목표선 도착 `rk=0.8` → 도착 1,871 − dur 720 | 1,220 | 1,151 | +69 | 4,030ms |

전부 ±0.67초 안이고 셋 다 해당 자막의 발화 구간 안에 든다. 🟢
🔑 **`riser` 를 "끝이 도착점"으로 보고 dur 만큼 앞당긴 판단은 맞다.**
`sfx.mjs` 의 riser 는 `f = f0 + (f1−f0)·k²` 로 **주파수가 끝에서 최고**가 되므로
심리적 도착점이 끝이다. (다만 포락선 `min(1,4k)(1−k²)` 의 최대는 `k=0.25` 이므로
**에너지 정점은 도착보다 0.54초 이르다.** 지금 배치면 정점이 1.4초 부근에 오고
목표선이 자라는 구간 한가운데라 문제는 없다. 알고 있으라는 뜻으로만 적는다.)
실측 `timed.json` 이 나오면 위 세 식으로 다시 내라.

## 5. 🟡 마스터에게 올리는 시리즈 규약 의견 — 훅 카드 vs 아웃트로 카드

**반려 사유가 아니다.** 이 편의 설계 문제가 아니라 엔진의 성질이다. 다만 작성팀이 적어 올린
것보다 **더 나쁘다**는 것을 프레임으로 확인했으므로 사실을 정정해 올린다.

### 실측

```
engine/style.css:105  .outrocard{ top:21.875%; left:20px; right:20px; bottom:34.0625%;
                                   z-index:3; background:var(--bg); }
engine/style.css:75   .vis      { top:21.875%; left:20px; right:20px; bottom:34.0625%; }
engine/engine.js:174  OUTRO_MS = 2600
engine/engine.js:240  $('outroCard').hidden = !(t >= TOTAL - OUTRO_MS);
```

좌표가 **한 픽셀도 다르지 않고** 배경이 불투명 `--bg` 다. 즉 마지막 2.6초 동안 비주얼은
통째로 가려진다.

이 편의 숫자:

```
TOTAL                 38,365ms
아웃트로 카드 등장     35,765ms
S3 예고 자막 시작      35,776ms   ← 카드보다 11ms 늦다
```

→ 작성팀은 *"훅 카드는 뜨자마자 카드 뒤로 들어간다"* 고 적었는데, 실제로는
**단 한 프레임도 보인 적이 없다.** 스틸 `37s.png` 에 훅 문장이 없다 —
아웃트로 카드(「M1 여가·명령과 거부」 · 3편 중 3편 · 형제 셋 · AI 문구)만 있다.

### 의견

1. 🔴 **`check.mjs` 의 `정적 구간` 이 이 구간을 못 본다.** 그 검사는 `.shot.on canvas` 의
   `getImageData` 만 읽는데, 그 캔버스는 카드 **뒤**에 있다. 즉 마지막 2.6초는
   **보이지 않는 그림의 움직임으로 통과**한다. 이 편은 실제 정적 0.4초라 무해하지만,
   "예고 구간의 바닥을 검사선이 받친다"는 작성팀의 설계 근거는 **그 구간에 한해 무효**다.
   보이는 화면에서 움직이는 것은 자막 페이드와 진행바뿐이다(둘 다 3초 안이라 규칙 위반은 아니다).
2. 그러므로 **훅을 마지막 자막에 물리는 현행 관행은 시리즈 전체에서 헛일**이다
   (`ep04s2`·`ep05s` 계열도 같은 상태다). 셋 중 하나로 정하는 게 맞다고 본다:
   - ⭐ **아웃트로 카드에 훅 한 줄을 넣는다.** 카드는 어차피 그 자리를 다 쓰고 있고,
     `.oc-src` 위에 `.oc-hook` 한 줄이면 훅이 **실제로 마지막에 남는다**.
     명세서 §0.5 가 "아웃트로 카드가 생기면 회차성 마무리를 `scene.json` 필드 하나로 붙일 수
     있다"고 이미 이 확장을 예고해 뒀다.
   - 훅을 **마지막에서 두 번째 자막**으로 옮긴다(예고 직전). 작성팀 범위 안이지만
     페이오프와 예고 사이에 한 박자가 더 생긴다.
   - `OUTRO_MS` 를 줄인다. 🔴 비권장 — 명세서 W4 가 2600 을 고른 이유가
     `정적 구간 3초` 게이트라, 되돌리면 그쪽이 깨진다.
