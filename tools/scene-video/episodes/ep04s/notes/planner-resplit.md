## 2. 사건 세기 (ADR-V-1) — 원문에 사건이 **다섯** 있다

기준: ①어긋난 상태·결정이 하나 있고 ②그게 뒤집히거나 해결되고 ③남는 한 줄이 있다.

| # | 사건 | ① 어긋남 | ② 뒤집힘/해결 | ③ 남는 한 줄 | 판정 |
|---|---|---|---|---|---|
| **E1** | 여가 = 계획할 수 없는 목표 | 할 일이 사라지면 주민이 그 자리에 굳는다. 게다가 여가는 GOAP 의 "달성" 전제에 안 맞는다 | 우선순위 1 로 사다리 맨 아래 + 플래너를 안 거치고 `GoalSO.DirectAction` 으로 배회 직접 실행 | 끝이 없는 목표는 계획이 되지 않는다 | ✅ 사건 |
| **E2** | 공회전 버그 셋 | 채집 경쟁 공회전 · 상위 goal 전환 폭주 · 정상 완료에 걸린 쿨다운 | 점유 스냅샷 + 쿨다운을 **실패에만** | 셋은 독립처럼 보였지만 뿌리는 하나 — goal 전환이 빨라진 것 | ✅ 사건 |
| **E3** | 밥 먹는 게 안 보였다 / 동시에 배고파졌다 | 제자리에서 수치만 오르는 행위 · 모두 같은 시각에 허기 | 모닥불 앵커 + 반경 내 산개 / `Goal_Snack` 35 완충 + ±15 편차 | **없다** — "수치를 자리로 옮겼다" 정도 | 🟡 준사건 → 버림 |
| **E4** | 명령을 넣었더니 거절당했다 | 플레이어가 명령할 방법이 없다(관람). 그리고 명령 전용 상태머신을 만들 것인가 | **안 만들었다** — 사다리에 60 한 칸. 거부는 문턱 둘(포만감 35 미만·피로 70 초과)의 상태 판정 | 거절은 기능이 아니라 주민의 상태였다 | ✅ 사건 (최강) |
| **E5** | 명령 목표값이 절대값이었다 | "창고에 돌을 30개까지" — 재고 28 이면 겨우 2 개. 명령의 무게가 재고에 따라 달라진다 | 구현을 멈추고 물었다 → 현재 재고 **+10** 상대값 | 플레이어 의도는 "특정 수치까지"가 아니라 "지금보다 더" | ✅ 사건 |
| **E6** | 피로 사각지대 | 피로 70 초과면 거부하는데, 여가가 피로를 안 풀어 준다 → 70~90 구간에서 거부가 **영구**가 된다 | ADR-M1-3 개정 — 산책 -2 · 모닥불 곁 휴식 -4 | 각자 옳은 규칙 둘이 만나 구멍을 만들었다 | ✅ 사건 |
| E7 | 말풍선 정리(M1-D) | — | — | **없다** | ❌ 버림 |

🔴 **사건이 다섯인데 편은 셋이다** — ADR-V-2 의 상한이다. 그러니 **묶는 것이 불가피하다.**
묶을 때 지킨 규칙 둘, 이것이 이 브리프의 핵심 판단이다:

1. **인과로 이어진 것만 묶는다.** E1 → E2 는 원문이 직접 잇는다
   (*"여가 시스템을 넣고 나서 버그가 세 가지 연달아 나왔습니다"*).
   E6 · E5 는 둘 다 **M1-C 리뷰**가 잡은 것이다
   (*"M1-C 구현 직후 리뷰에서 결함이 나왔습니다"* / *"M1-C 리뷰 중에 문제가 발견됐습니다"*).
   원문이 준 묶음이지 내가 만든 묶음이 아니다.
2. **제목이 약속하는 사건을 그 편의 0초에 둔다.** 묶어도 뒤엣것이 도입이 되지 않는다.
   이게 지켜지면 ADR-V-1 이 막으려던 병(ep02s 형)은 재발하지 않는다.

🟡 **정직하게 적어 둔다**: 편 2·3 은 각각 사건 **둘**을 담는다. 명세의 이상은 "한 편 = 사건 하나"다.
4편으로 나누면 사건 하나씩이 되지만 ADR-V-2(글당 최대 3편)를 넘는다 —
**넘기려면 사람에게 물어야 한다.** 나는 상한 안에서 최선을 골랐다.
4편이 낫다고 판단되면 §7 에 그 대안을 적어 두었다.

| 항목 | 값 |

| **0초에 오는 것** | 촌장이 명령을 내렸는데 주민이 **거절**한다 |

- 🔴 **`oneline`(S11) 의 RTS 대비 두 줄을 결말이 아니라 도입으로 옮겨라.**
  그러면 0초에 제목 이행이 서고, 결말은 성공 기준 한 마디 + 예고로 짧아져 43초에 든다.
  예: *"게임에서 유닛은 명령하면 그냥 복종하죠."* / *"근데 이 주민은 촌장 명령을 거절했어요."*
- 🔴 S7 첫 줄 *"**이제** 촌장이 명령을 내려요"* 의 `이제` 는 **앞 장면을 전제한다.** 지워라 —
  이 편에 앞 장면이 없다.
- 🔴 **`rung60`(S8) 은 5줄 그대로 유지한다.** 4줄로 줄이면 `leaveCue`·`returnCue` 가 한 자막에 물려
  `rung60.js` 의 이중 lerp 가 상쇄되고, 표식이 25%만 들썩이다 되돌아와 배고픔(100) 칸이
  한 번도 안 켜진다 (`ep04s/notes/review-recut.md` 반려 R-1 · `review-recut-2.md` §1 실측).
- 효과음이 붙은 자막(S7 *"지금은, 배가 너무 고파요."* / S8 *"…육십이에요."*)은 **문구·pauseAfter 를
  바꾸지 마라.** `delayMs` 가 그 자막의 글자 수에서 유도된 값이다.

**제목 방향** (`youtube.title` — W2 게이트가 red 다. 핵심어가 **첫 두 줄** 안에 있어야 한다)

### ep04s-3 — 사건 **E6 → E5** (M1-C 리뷰가 잡은 구멍 둘)

| 항목 | 값 |
|---|---|
| **맡는 사건** | E6(주) + E5(같은 리뷰가 잡은 두 번째) |
| **0초에 오는 것** | 너무 지쳐서 명령을 거절하는데, **아무리 쉬어도 피로가 안 풀린다** |
| 재료 | 전제 1줄 → `blindspot`(S9) → `relative`(S10) → 결말 1줄 + 예고 1줄 |
| 산정 길이 | 전제 3 + S9 12.3 + S10 16.1 + 결말·예고 6 ≈ **34~37초** |
| 훅 | §5 참조 — 기존 훅이 없다. 새로 세워야 한다 |
| 남는 한 줄 | 각자 옳은 규칙 둘이 만나 사각지대를 만들었고, 그걸 코드가 아니라 리뷰가 잡았다 |

**구성 지시**

- 🔴 **이 편은 "명령"이라는 전제를 스스로 세워야 한다.** 첫 줄에서 사실로 한 번 말하면 된다:
  *"주민은 너무 지치면 촌장 명령을 거절해요."* 원문 그대로다(피로 70 초과 → 거부).
  이러면 편 1 을 안 봐도 성립한다 — ADR-V-8 이 요구하는 자체 완결이다.
- 🔴 `relative`(S10) 자막 1 에는 **반드시 「촌장 명령」이 들어가야 한다.**
  `ep04s2` 검수 1-A 가 잡은 자리다 — 없으면 "돌 30까지"가 갑자기 나타난 남의 말이 된다.
  현재 파일은 이미 *"촌장 명령이 '돌 서른까지'거든요"* 로 고쳐져 있으니 그대로 살려라.
- 🔴 `relative.js` 는 훅 문턱이 `hookCue`(예고 자막)로 옮겨져 있고 재고 막대가 `ak` 에도 걸려 있다
  (`ep04s2` 검수 2회차 정정). 그 두 수정은 유지하라 — 되돌리면 정적 구간 3.2초가 돌아온다.
- 🔴 `mealspot.js` 는 이 편에서 안 쓴다. `buffer.js` 도 마찬가지 → §4.
- ⚠️ E6 과 E5 는 인과가 아니라 **같은 리뷰**로 묶였다. 화면·자막으로 그 묶음을 한 번 말해 줘야
  두 사건이 남남으로 보이지 않는다. 원문 근거가 두 곳에 실재한다:

## 6. `schedule.json` 변경안 — **내가 고치지 않았다. 확인 후 사람이 적용한다**

```jsonc
"order": [
  "ep00s", "ep01s", "ep02s", "ep03s",
  "ep04s-1", "ep04s-2", "ep04s-3",   // 🔴 기존 "ep04s","ep04s2" 두 줄을 이 셋으로 **치환**
  "ep05s", "ep05s2", "ep06s", ...
],
"sources": {
  "ep04s": {                          // 🔴 글 단위 그대로. -1/-2/-3 키를 만들지 않는다
    "local": null,
    "url":   "https://gamedevclaude.blogspot.com/2026/07/unity-goap-ai-ai-m1.html",
    "note":  "M1 여가·명령과 거부. 구성안에서 4번 자리로 이동된 편",
    "split": 3                        // 설명문(publish.mjs W5)·아웃트로가 읽는다
  }
  // 🔴 "ep04s2" 키는 **삭제**한다 — 편 단위 키 금지(명세 §W1-a · §1)
}
```

**적용 후 기대 동작 (명세 §1 참조 개편 표 기준)**

- `backlog.mjs` → `PENDING ep04s-1`
- `nextId()` 는 `/^ep(\d+)s$/` 로만 세므로 `ep04s-1..3` 을 안 잡는다 → 번호 잠식 없음 ✅
- `publish.mjs:342` 가 `-N` 을 떼고 `sources.ep04s` 를 읽는다 ✅
- `publish.mjs:676` 의 형제 편 라벨 정규식 `^ep0?(\d+)s-(\d+)$` → **"4-1편"·"4-2편"·"4-3편"** ✅
  → 그러므로 **`hud.title` 도 `"4-1편 · …"` 형식**이어야 설명문과 화면이 같은 이름을 쓴다.

**파일 이동이 필요한 것** (사람/작성팀)

| 지금 | 어디로 |
|---|---|
| `episodes/ep04s/kinds/refusal.js` · `rung60.js` · `oneline.js` | `episodes/ep04s-1/kinds/` |
| `episodes/ep04s/kinds/standstill.js` + `episodes/ep04s2/kinds/sidedoor.js` · `idlespin.js` | `episodes/ep04s-2/kinds/` |
| `episodes/ep04s/kinds/blindspot.js` + `episodes/ep04s2/kinds/relative.js` | `episodes/ep04s-3/kinds/` |
| `episodes/ep04s/kinds/actopen.js` · `nextup.js`, `ep04s2/kinds/buffer.js` · `mealspot.js` | 안 쓴다 — 삭제하거나 어디든 보관(§4) |
| `episodes/ep04s/notes/*` · `episodes/ep04s2/notes/*` | 이력이다. `ep04s-1/notes/` 아래로 옮겨 보존 권장 |
| `episodes/ep04s/`, `episodes/ep04s2/` 디렉터리 | 위를 옮긴 뒤 삭제. **`order` 에서 빠지므로 남아 있어도 파이프라인은 안 멈춘다** |

⚠️ **범위 밖이지만 알려 둔다**: `ep05s`/`ep05s2` 도 같은 구 규약(편 단위 `sources` 키 + "1부/2부"
표기)이다. 이 글만 고치면 리포에 규약이 두 벌 존재한다. 두 회차는 이미 검수 3회차를 통과한
상태라 **내 판단으로 건드리지 않았다.** 통일 여부는 사람이 정할 일이다.

## 7. 기각한 대안 — 왜 이 배치인가

| 대안 | 기각 사유 |
|---|---|
| **4편** (E1 / E2 / E4+E5 / E6) | 사건 하나씩이라 ADR-V-1 은 가장 잘 지킨다. 그러나 **ADR-V-2 상한 3 을 넘으므로 사람에게 물어야 한다.** 편당 20~25초로 짧아져 명세 **S2(절대 시청 15초 하한)** 도 위태롭다. 🔑 사용자가 4편을 허용하면 이쪽이 더 옳다 |
| 편 2 를 E2(버그 셋) 중심으로 잡고 E1 을 한 줄 전제로 압축 | 제목은 세기 쉬우나 원문의 백미(달성이 없는 목표는 플래너에 못 넣는다)가 통째로 사라진다. 그리고 E2 는 E1 의 결과라 인과가 역행한다 |
| 편 3 = E6 + E3(모닥불) — "모닥불"로 묶기 | 모닥불은 소품이지 사건의 연결이 아니다. E3 는 ③ 남는 줄이 없어 애초에 편이 못 된다 |
| `ep04s`(77초) 를 그냥 두고 `ep04s2` 만 손보기 | 둘 다 상한 50 초과라 W3 red 다. 길이만 줄이면 또 "잘라내기"가 되어 ep02s 사고(36초 삭제)를 되풀이한다 |
| 기존 5샷/5샷 구성을 id 만 `-1`·`-2` 로 바꾸기 | **가장 그럴듯한 오답.** 챕터 경계라는 근본 위반이 그대로 남고, 검수팀이 올린 반려 사유 둘도 그대로 남는다 |

## 8. 작성팀이 편별로 반드시 확인할 것 (체크리스트)

- [ ] `youtube.title` 의 핵심어가 **첫 두 줄(`text`·`say` 둘 다)** 안에 있다 — `check.mjs` 「제목 이행」 **red**
- [ ] 제목을 첫 줄에 **낭독하지 않는다.** 약속을 **이행**하는 것이다 (정답 형태 = ep00i)
- [ ] 총 길이 **30~45초**(warn) · **50초 이하**(red). 산정치는 `say` ÷ 6.7 + `pauseAfter` + 0.35×샷수
- [ ] 마지막 샷에 **예고 자막 1줄**(red) · **4초 이하**(warn). §5 의 재료만 쓴다
- [ ] `hud.title` = `"4-N편 · <부제>"` — 설명문 라벨과 같은 이름
- [ ] `youtube.blurb` 에 형제 편으로 가는 길 한 줄 (`publish.mjs` 가 `split:3` 을 읽어 자동으로 붙이지만, 사람이 읽을 문장 하나는 blurb 에 두는 것이 이 리포의 관례다)
- [ ] 이 편이 **다른 편을 안 봐도 성립**하는가 — 화면 라벨까지 본다. 실패 전례: `buffer.js` 의 「35 = 명령 거부 임계와 같은 수치」가 명령을 한 번도 말하지 않는 편에 떠 있었다
- [ ] 훅 문형이 앞 회차와 겹치지 않는가 — ep03s 「지운 건 코드가 아니라 아키텍처의 무게였다」와
      ep04s-1 「거절은 기능이 아니라 주민의 상태였다」가 **같은 문형**이다.
      ep05s 가 그래서 대구형(「한 번은 우연이고, 두 번은 구조였다」)으로 바꿨다.
      **세 편이 같은 문형이면 시청자가 문형 자체를 알아본다** — 편 3 의 훅은 다른 문형으로 세워라
- [ ] `notes.길이` 를 **파일에서 직접 세어** 적는다. 이 회차는 그 값이 세 번 틀린 이력이 있다
