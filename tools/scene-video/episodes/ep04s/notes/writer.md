## 1. 이 편의 축을 무엇으로 잡았나

원문은 "명령을 거부하는 기능을 만들었다"로 읽히기 쉽다. 그런데 4절을 끝까지 읽으면
글쓴이 본인이 그 읽기를 뒤집는다.

> 명령 전용 상태머신은 따로 만들지 않았습니다(ADR-M1-1). 명령은 그냥 사다리의 한 칸에
> 꽂히는 goal 참조 하나입니다. 중단·복귀·충족 소멸이 기존 GOAP 메커니즘으로 공짜로
> 성립합니다.

그래서 축을 **"거부는 기능이 아니었다"** 로 잡았다. 이게 구성 전체를 결정했다.

- 거부 장면(S7)을 결말에 두지 않는다. 거부 **다음에** 그것이 왜 성립하는지(S8)를 붙인다.
- 두 샷을 붙여 놨다. 사이에 짧은 샷을 끼워 숨을 돌리면 "왜 그렇게 되는가"가 다른
  이야기로 들린다. 이 편에서 가장 긴 샷 둘(각 5자막)이 연달아 오는 유일한 자리다.
- `scene.hook` = **"거절은 기능이 아니라 주민의 상태였다"**.
  원문 4절의 두 문장('거부는 랜덤이 아닙니다. 주민의 실제 상태에 근거한 판정입니다' +
  ADR-M1-1)을 한 줄로 합친 것이다.

3막이 "한 편에 기능 하나씩 쌓이는 구간"이라는 구성안의 설명도 이 축 안에서만 실감이
난다 — 이 편에서 쌓인 것은 시스템이 아니라 사다리의 한 칸이다.

## 2. 도입 — 이전 편과 부딪히지 않게 자리를 잡은 것

기획 브리프가 가장 크게 경고한 자리다. 원문 2절 첫 문장은 이렇다.

> M0 마일스톤이 끝났을 때, 마을은 **꽤 그럴듯하게 돌아가고 있었습니다.**

시청자는 ep03s 를 방금 보고 온다. ep03s 는 M0 코드가 재앙이라 하루 만에 갈아엎은
이야기다. 이 문장을 그대로 옮기면 "방금 다 갈아엎었다면서?"가 된다.

**처방대로 "재설계가 끝난 그 자리에서"로 잡았다.** 지어낸 게 아니다 — ep03s 원문이
'이 재설계 위에서 M1 개발이 시작됐습니다'라고 순서를 직접 말한다. 화면에서 사라진
순서를 자막 한 줄로 되살린 것이다.

**막 전환은 S2 가 통째로 맡는다.** ep03s 의 마지막 샷이 네 마디로 끝났고
("2막 리셋은 이 한 편으로 끝이에요 / 다음 편부터 3막, 다시 짓기 / M1, 여가와 명령과
거부요 / 주민이 촌장의 명령을 거부하기 시작합니다"), 이 편은 그것을 셋으로 받는다.

1. S1 첫 자막이 재설계를 이어받는다
2. S2 가 3막을 화면에 못박는다 — 표지가 위에서 내려와 박히고 latch 소리가 붙는다
3. S2 의 마지막 칸 이름이 '명령과 거부'다. 지난 편이 부른 이름 그대로다

반대로 **예고(S12)에서는 막을 바꾸지 않는다.** ep05s 도 3막이다. 띠가 자라거나 끊기는
연출을 넣으면 없는 전환을 만들게 된다.

## 3. 무엇을 버렸나 — 그리고 왜

`scene.json` 의 `excluded` 에 11건을 사유와 함께 적었다. 무거운 순으로 셋만 여기 옮긴다.

### (1) Claude 협업 절의 일반화 — 🔴 앞 회차가 이미 가진 비트라서

원문 5절은 "명세에 없는 판단이 필요하면 구현하지 말고 선택지와 추천을 정리해 질문하라"는
규칙을 설명한다. **이 비트의 소유자는 ep03s S10 `askfirst` 다.** 저 편이 규칙 문장을
화면에 못박고 다섯 칸 중 어느 칸이 사람 쪽인지까지 그렸다. 한 회차 건너 같은 규칙을
다시 설명하면 시리즈가 제자리걸음이 된다.

그래서 규칙은 버리고 **결과만** 가져왔다. S10 `relative` 는 규칙을 한 글자도 설명하지
않는다. 칩 하나('구현을 멈추고 물었다')만 두고 나머지는 절대값과 상대값의 길이 차이가
전부다. 초보 개발자 이야기와 AI 사용법 문단은 통째로 뺐다.

### (2) 말풍선 정리(M1-D) — 🟡 같은 그림이 세 번째가 되므로

연속 반복 접기, 변주 문구 3종. 재미있는 디테일이지만 이 편에서 말풍선은 이미 S7 에서
두 번 뜬다. 그 두 마디("지금은... 배가 너무 고파요." / "숨 좀 돌리고요. 너무 지쳤어요.")가
이 회차의 클라이맥스다. 앞뒤에 '말풍선을 정리했다'는 샷을 세우면 같은 그림이 세 번째로
나오면서 정작 거부 대사의 무게가 깎인다.

🟢 다만 두 조각은 살렸고, **자기 샷을 주지 않고 다른 샷 안에 숨겼다.**
- `[명령]` 프리픽스 → S8 의 60 칸 이름이 그대로 `[명령]` 이다. 자율 행동과 촌장 명령을
  구분한다는 뜻이 그 칸 하나로 성립한다.
- '작업 액션에 실제 소요 시간을 부여했다' → 같은 칸 안에서 계속 채워졌다 비워지는
  진행 막대가 받는다. 이 샷의 '계속 도는 요소'이기도 하다.

### (3) 원문의 자체 예고 — 🔴 근거로 쓰지 않고 재료로만 썼다

원문 8절이 "다음 이야기: M2"로 끝나고, 이번엔 그게 우연히 정본(ep05s = M2·M3)과 맞는다.
**그래도 근거로 쓰지 않았다.** 정본은 구성안 「한눈에 보기」 표와 `schedule.json` order
둘뿐이다. ep02s 가 정확히 이 방식으로 예고를 냈다가 틀렸다.

🟢 문장 안의 구체 이미지(밭·부엌·요리된 밥, 모닥불이 식당으로)는 원문에 실재하므로
S12 화면의 재료로 썼다. **근거는 표에서, 그림은 원문에서** 가져온 셈이다.
'앵커 승격 체인(ADR-M2-2)'과 '식당이 더 큰 전용 건물로'는 뺐다 — 다음 편이 아직 다루지
않은 층까지 예고하면 예고가 두 편치가 된다.

### 나머지 여덟

자기소개 문단(1절) · 공회전 버그 셋의 해결 수단 상세 · '나무를 베고, 돌을 캐고' 세 행동 ·
클릭/우클릭 조작 설명 · 사각지대 절의 교훈 문장 · 협상의 다음 수('밥부터 먹고 와라') ·
M1 실행명세서의 배회 반경 같은 수치 · 원문 소제목 여섯. 사유는 전부 `excluded` 에 있다.

한 건만 여기서 다시 짚는다 — **'주민들은 나무를 베고, 돌을 캐고, 모닥불을 지었습니다'**
를 화면에 안 올린 이유다. 이 세 이름을 S1 왼쪽 사다리 칸에 넣고 싶은 유혹이 컸는데,
그러면 **액션 이름을 goal 칸에 옮겨 적는 것**이 된다(이 프로젝트에서 액션과 goal 은 다른
층이다). 원문은 이 시점의 goal 이름을 대지 않는다. 그래서 칸은 이름 없이 `···` 로 뒀다.

## 4. 그림 — 12개를 어떤 생각으로 설계했나

### 기본 도형: 경로와 문턱

이 편의 사건은 전부 "닿느냐 못 닿느냐"다. 그래서 회차 전체가 두 재료로 짜여 있다.

| 묶음 | kind | 하는 일 |
|---|---|---|
| 길이 없다 | `standstill` | 검사가 도는데 켜지는 칸이 없다 |
| | `actopen` | 뚫린 자리에 칸이 내려와 박힌다 |
| 길을 새로 낸다 | `sidedoor` | 상자를 지나쳐 가는 옆문 |
| | `idlespin` | 닫힌 고리가 열린 선이 된다 |
| | `buffer` | 떨어지는 값을 문턱 앞에서 잡는다 |
| | `mealspot` | 수치가 자리로 옮겨 간다 |
| 문턱이 판정한다 | `refusal` | 두 문턱에 걸려 되밀린다 |
| | `rung60` | 숫자 하나가 순서를 정한다 |
| 길이가 뜻이다 | `blindspot` | 회복 화살표 둘의 길이 차 |
| | `relative` | 목표선까지의 거리 차 |
| | `oneline` | 표식이 도착하느냐 되돌아오느냐 |
| | `nextup` | 막은 그대로, 칸만 하나 더 |

### 사다리를 세 번 그리지 않았다 — 이 회차에서 가장 오래 고민한 것

원문은 '우선순위 사다리'를 세 대목에서 부른다(정지 문제 / 여가 추가 / 명령 우선순위).
그대로 그리면 **12샷 중 셋이 같은 모양**이 되고, 게다가 ep03s 에 이미 `ladder`(아홉 칸이
아래에서 위로 켜지는 그림)가 있다. 세 가지로 갈랐다.

1. **S1 `standstill`** — 사다리를 그리되 칸에 이름이 없다. 움직이는 것은 위에서 아래로
   **끝없이** 내려가는 검사 표식이고, 어느 칸도 안 켜진 채 바닥을 벗어난다. 요점은
   사다리가 아니라 '검사는 정상인데 결과가 없다'이다.
2. **S3 `sidedoor`** — 사다리를 **아예 안 그렸다.** 이 문단이 실제로 말하는 것은 '맨
   아래'가 아니라 '달성이 없어서 플래너를 못 쓴다'이다. 그래서 위쪽 goal 셋에는 목표선을
   그려 주고 여가만 그 자리를 점선으로 비웠고, 여가의 경로가 A* 상자 **아래를 지나** 배회
   노드에 바로 닿게 했다. 사다리 위치('우선순위 1 · 사다리 맨 아래')는 칩 한 줄로 적었다.
   🔴 **1차본은 위 goal 셋의 진행 막대를 0.4 / 0.58 / 0.76 에 세워 뒀다.** 그게 반려
   사유였다 — 정적 구간(자막 0·1번) 동안 화면에서 움직이는 것이 7×5px 표식 하나뿐이라
   9.2초가 얼어 있었고, 배회 점은 `dk > 0.25` 라 그 구간엔 존재조차 안 했다.
   고칠 때 새 장식을 얹지 않고 **이 샷의 논지 자체를 움직임으로 바꿨다** — '달성이 있다'는
   말은 곧 목표선까지 차오르고 충족되고 다시 시작한다는 뜻이므로, 막대가 멈춰 있던 것이
   오히려 그림의 오류였다. 세 줄의 주기를 2.4 / 2.9 / 3.5초로 갈라 한 줄이 리셋으로 비어도
   나머지가 자라게 했고, 달성 순간에는 칸 전체가 한 번 밝아졌다 꺼진다. 전부 `t` 만의
   순수 함수다. 이제 아래 Goal_Leisure 의 '차오를 것이 없는 점선'과 대비도 선다.
3. **S8 `rung60`** — 칸마다 숫자가 붙고, 움직이는 것은 검사선이 아니라 '지금 최상위'를
   가리키는 표식 **하나**이며, 방향이 위아래 왕복이다(60 → 100 → 60). 그 왕복 자체가
   원문의 '중단·복귀가 공짜로 성립한다'이다.

셋 다 ep03s `ladder` 와도 다르다. 저기는 칸이 아래에서 위로 켜지고 확인 표식이 다시
한 번 올라간다.

### 지난 편의 마지막 획을 되받은 자리 — S7 `refusal`

ep03s S14 `handover` 는 '촌장의 명령이 주민에게 다가왔다가 주민 앞에서 밀려나는' 한 획으로
끝났다. 이 편의 S7 이 **의도적으로 그 획을 다시 그린다.** 시리즈에서 같은 사건을 두 번
그리는 유일한 자리이고, 그게 예고가 지킨 약속이라서 그렇다.

다만 다르게 그린다. 저기는 결과만 한 번 보여 주는 예고였고, 여기는 **되밀리기 전에**
두 문턱이 숫자로 채워지는 판정 과정이 화면의 절반이다. 그리고 마지막에 점선으로 된
세 번째 갈래(수락)가 열린다 — 거부만 있는 판정이 아니라는 것을 화면에서도 세 갈래로
보여야 '랜덤이 아니라 상태 판정'이 성립한다.

### 공회전을 '멈춤'으로 그리지 않은 이유 — S4 `idlespin`

세 버그를 목록이나 막대가 아니라 **닫힌 고리 셋**으로 그렸다. 공회전은 '앞으로 안 가면서
계속 도는 것'이라 고리가 정확한 도형이다. 표식이 한 바퀴마다 같은 자리의 ✕ 를 지난다 —
실패하고, 다시 달리고, 또 실패한다.

🔴 문제는 고친 뒤다. 고리를 멈추면 그 순간부터 화면이 죽는다. 그래서 **표식은 계속
움직이되 궤적이 닫힌 고리에서 열린 직선으로 바뀌게** 했다. 아래에서 뿌리 선이 그어지면
표식 셋이 고리를 벗어나 그 선을 타고 오른쪽으로 흘러 나간다. 고쳐졌다는 뜻이 정지가
아니라 **움직임의 모양**으로 나온다.

같은 판단을 S1 에도 적용했다. 정지를 그리는 샷인데 멈추는 것은 주민뿐이고 사다리 검사는
끝까지 돈다. 멈춘 주민 옆에서 검사만 계속 도는 그림이 '굳었다'보다 정확하다.

### 축의 방향을 한 번만 눕힌 이유 — S9 `blindspot`

포만감(S5)도 우선순위(S8)도 세로다. S9 만 가로로 눕혔다. '못 나간다 → 나간다'가 방향의
이야기이기 때문이다. 세로였다면 회복이 '떨어짐'으로 읽혀 좋을 것이 나쁜 것처럼 보인다.
그리고 산책 −2 와 모닥불 −4 의 화살표 **길이 차이 자체**가 원문이 말한 설계 의도다
("건물이 존재하는 의미를 피로 회복 보너스로도 나타내기 위해서").

### 예고를 세로로 세운 것 — S12 `nextup`

ep03s `handover` 는 1·2·3막의 가로 띠가 오른쪽으로 자라는 그림이었다. 이 편은 같은 재료를
반대로 쓴다 — **띠는 못 박혀 있고, 움직이는 것은 그 아래에 쌓이는 칸이다.** 이번 편 칸
위로 다음 편 칸이 내려와 얹힌다. 구성안이 3막을 두고 적어 둔 '한 편에 기능 하나씩 쌓이는
구조'를 예고의 형태 자체로 쓴 셈이다.

예고가 "다음 편도 기대해 주세요"가 되지 않게, 화면이 이름으로 말한다 —
`M2 · M3 · 생산 체인과 집` / `밭 → 부엌 → 지은 밥` / `모닥불 → 식당`.

### 이름이 겹치지 않는 것 말고 더 본 것

12개 kind 이름은 ep00s · ep01s · ep02s · ep03s · ep00i · eptest-m11 어느 쪽과도 겹치지
않는다. 하지만 이름보다 **장치**를 먼저 갈랐다.

- **격자가 하나도 없다.** ep01s `budget`·`shortfall` 과 ep03s `purge` 가 격자와 게이지를
  썼다. 이 편의 게이지는 S5 하나뿐이고 그것도 눈금이 아니라 문턱 두 개가 주인공이다.
- **고리** — ep00i `rings` 는 동심원, eptest-m11 `orbits` 는 궤도였다. S4 는 따로 떨어진
  닫힌 고리 셋이고, 핵심은 고리 자체가 아니라 표식이 고리를 **벗어나는** 전환이다.
- **예고 카드** — ep02s `nextnote` 는 카드가 옆에서 밀려 들어왔고, ep03s `handover` 는
  카드가 띠 아래 부속이었다. S12 의 카드는 **무엇 위에 놓이느냐**가 그림이다.
- **회차 안에서도** 같은 장치를 두 번 안 썼다. 흐르는 빗금은 S10 하나(재고 막대), 테두리를
  도는 표식은 S2 하나, 점선 회전은 S7 하나다.

## 5. 효과음 — 7개

| 샷 | kind | 사건 | gain / 상한 |
|---|---|---|---|
| S1 | `thud` | 주민 발밑에 못이 박힌다 | 0.070 / 0.1854 |
| S2 | `latch` | 3막 표지가 바닥에 닿는다 | 0.068 / 0.0733 |
| S4 | `sweep` | 고리 셋이 정리되고 뿌리가 그어진다 | 0.070 / 0.1825 |
| S7 | `drop` | 판정이 수락에서 거부로 뒤집힌다 | 0.076 / 0.2505 |
| S8 | `tick` | [명령] 칸이 60 자리에 꽂힌다 | 0.057 / 0.0596 |
| S11 | `tick` | 성공 기준 한 마디가 카드로 앉는다 | 0.055 / **0.0601** (dur 0.04) |
| S12 | `riser` | 다음 편 칸이 내려와 얹힌다 | 0.064 / 0.3211 |

- **상한은 kind 가 아니라 kind+옵션(dur·freq)이 정한다.** 일곱 조합 전부 `node` 로
  `sfx.mjs` 의 `synth()` 를 그 옵션 그대로 불러 50ms 최대 RMS 대비 피크를 재고 천장 0.46 을
  나눠 냈다. 뾰족한 셋(`latch`·`tick` 둘)만 상한 가까이 붙였고(여유 7% · 4% · 5%) 나머지
  넷은 상한의 3분의 1 아래다.
- **ep03s 와 돌려막지 않으려고** 같은 kind 를 쓰는 자리마다 성격을 갈랐다.
  `thud` 는 저 편이 카드가 좌석에 앉는 dur 0.22 였고 여기는 dur 0.26 · freq 132 로 더 낮고
  더 긴 '내려앉아 안 움직이는' 소리다. `riser` 는 저 편이 새 막이 열리는 220→700 이었고
  여기는 같은 막 안에 한 칸이 더 얹히는 200→640 이라 덜 올라간다.
- **`latch` 는 한 번뿐이다.** 이 회차에서 되돌릴 수 없는 것은 막이 바뀐 것 하나다.
- **`tick` 이 두 번인 것은** '자리에 앉는' 사건이 정확히 둘이기 때문이고(칸이 꽂힘 ·
  한 마디가 앉음), `dur 0.055 · 1250Hz` 둔탁 / `dur 0.04 · 1750Hz` 예리로 갈랐다.
- 🔴 **ep03s 의 `tick` 과 대조하지 않은 것이 1차 검수 지적이었다.** `thud`·`riser` 는
  대조해 놓고 `tick` 만 안 했다. 저 편 S9 `tick` 은 `dur 0.05 · freq 1900` 인데 1차본의
  S11 이 `dur 0.05 · freq 1750` 이라 **`dur` 완전 일치 + `freq` 소폭 이동** —
  `project_recurring_defects.md` ③ 이 기록한 eptest-m11 ↔ ep02s 와 같은 모양이다.
  S11 의 `dur` 을 **0.04** 로 내렸다. 같은 편 S8(0.055)과의 간격도 0.005 → 0.015 로
  벌어져 두 `tick` 이 `freq` 뿐 아니라 `dur` 로도 갈린다. 짧아진 만큼 '한 마디가 딱
  떨어지는 소리'라는 원래 의도에도 더 맞는다.
  `dur` 이 바뀌면 상한도 바뀌므로 `sfx.mjs` 의 `synth()` 를 새 인자 그대로 불러
  무경고 상한을 다시 이분탐색했다 — 피크/RMS 7.988 → **7.651**, 상한 0.0576 →
  **0.0601**. `gain` 0.055 는 그 91.5%(여유 9%)라 그대로 뒀고 `synth()` 는 경고를
  뱉지 않는다. `delayMs` 660 은 그대로다(`tick` 은 어택 1~2ms 라 `dur` 이 정점 위치를
  옮기지 않는다).
- **일부러 안 넣은 자리 셋.** ①S3 — 옆문이 열리는 것은 sweep 을 달고 싶은 자리인데 같은
  편 S4 가 이미 sweep 을 쓰고 그쪽이 훨씬 큰 사건이다 ②S5·S6 — 이 편의 유일한 짧은 샷
  둘이고 여기가 조용해야 앞뒤(S4·S7)의 간격이 벌어진다 ③S9 — 사각지대가 메워지는 것은
  되돌리는 사건이라 소리가 붙으면 새 사건처럼 들린다.
- `delayMs` 는 전부 각 kind 의 `draw` 를 풀어서 냈다. 계산식은 각 `why` 에 그대로 있다.
  **실측 `timed.json` 이 나오면 창 W 가 바뀌므로 다시 계산해야 한다.**

캔버스 2D 컨텍스트와 `document` 를 가짜로 세우고 12개 kind 를 import 해서 각 샷의 산정

   만들었다. '자리를 찾아 들어간다'는 뜻은 그대로다.
2. **S5 `buffer`** — ±15 라벨의 `fit()` 최대 폭을 `w−262` 로 잘못 잡아 오른쪽 끝이 356 까지
   나갔다. `w−(bx−6)−8` 로 고쳤다.
3. **S2 `actopen`** — 칸이 메워진 뒤부터 새 칸이 뜨기 전까지 그리기 호출열이 **3.05초**
   멈춰 있었다. 메워진 칸 안을 지나가는 표식을 더했다.
4. **S11 `oneline`** — 첫 **0.95초**가 멈춰 있었다. RTS 표식의 등장 문턱을 0.35 → 0.1 로
   내렸다.

🔴 **이 검사로 "정적 구간 12샷 전부 0.00초"라고 적은 것이 1차 반려의 두 번째 사유였다.**
스텁은 픽셀이 아니라 **그리기 호출열**을 비교한다 — 7×5px 표식이 2px 움직인 것도
"다른 그림"으로 세어 준다. 그래서 실물에서 9.2초 얼어 있던 S3 을 0.00초로 통과시켰다.
**정적 구간 판정의 근거는 7-1 의 `check.mjs` 출력뿐이다.** 스텁이 실제로 값을 한 것은
위 1·2 의 좌표 검사이고, 3·4 도 "호출열이 멈췄다"는 뜻이지 픽셀이 멈췄다는 뜻이 아니다.
폰트 폭도 실물과 다르므로 `fit()` 이 고른 글자 크기는 달라질 수 있다.
`check.mjs` 를 대신한다고 주장하지 않는다.

3. **`voice.json` 이 이 회차부터 ME @ speed 1.1 로 바뀐다.** 목소리가 바뀌는 첫 회차라
   실제 렌더에서 말맛을 한 번 들어 봐야 한다 — 특히 S7 의 거부 대사와 S11 의 성공 기준
   한 마디는 대본이 아니라 인용문이라 억양이 평평하면 힘이 빠진다.

## 부록 — 브리프 오염 점검

기획 브리프에서 표 조각(`|` 구분), CSS 조각, 문장이 아닌 단어 나열을 **찾지 못했다.**
브리프 스스로도 "이 글은 애초에 표·코드블록·인라인 SVG 를 쓰지 않은 순수 산문 글"이라고
실측으로 적어 두었고, 「본문 전문」 절을 훑어 본 결과와 일치한다.

브리프에 `|` 로 구분된 표가 여럿 있지만 전부 **브리프 자신의 메타 정보**(회차 식별,
오염 점검 결과, 다음 편 예고 재료)이지 원문 본문이 아니다. 본문 전문 절 안에 있는
인용 블록 셋(주민 대사 2개 + 명령 거부 판정 3줄)은 원문이 의도적으로 쓴 대사 인용이고,
이 편의 핵심 재료라 그대로 살렸다.
