### ① `riser` 돌려막기 — 🟡 **절반 통과.** 산수는 맞고, 근거 문장은 낡았다

**(a) `delayMs` 보정은 맞다. 다시 계산했다.**

| | 구 | 신 |
|---|---:|---:|
| `dur` | 0.72 | **0.62** |
| `delayMs` | 980 | **1,080** |
| `delayMs + dur` (= 음정 꼭대기 도착) | **1,700ms** | **1,700ms** ✅ |

riser 의 음정은 `from → to` 스윕의 **끝**에서 정점이므로 `(delayMs + dur)` 이 도착점이다.
불변이 유지됐다. 「수확 가능」 칸(자막 시작 +1,700ms, 산정)에 그대로 닿는다. ✅

진폭(몸통) 정점도 실측했다 — `synth` 출력에서 **k = 0.251** 지점이다(why 의 "k=0.25" 와 일치).
- 구: 980 + 0.72×0.251 = **1,161ms** (둘째 칸 +1,201ms 대비 −40ms)
- 신: 1,080 + 0.62×0.251 = **1,236ms** (둘째 칸 +1,201ms 대비 **+35ms**)
→ 오차가 **줄었다.** 보정이 옳다. ✅

**(b) 피크 실측 — `why` 의 숫자가 정확하다.**

```
$ node -e "import('./sfx.mjs')…"
ep05s-1 S3 신   riser 0.06/0.62/210→520  peak 0.0871  rms 0.04004  peak/rms 2.18  gain상한 0.3168
ep05s-1 S3 구   riser 0.06/0.72/170→560  peak 0.0863  rms 0.03966  peak/rms 2.18  gain상한 0.3199
ep04s-3 S2      riser 0.06/0.72/150→470  peak 0.0865  rms 0.03973  peak/rms 2.18  gain상한 0.3191
ep05s-2 S4      riser 0.06/0.55/150→430  peak 0.0868  rms 0.03995  peak/rms 2.17  gain상한 0.3179
```

`why` 가 적은 **피크 0.0871 · gain 상한 0.317** 이 실측과 소수 셋째 자리까지 맞는다. ✅
`⚠️ sfx …: 피크 천장에 걸려` 경고 **0건**(tick 0.4388 · riser 0.0871 · thud 0.1737, 천장 0.46).

**(c) ep04s-3 S2 · ep05s-2 S4 와 갈렸나 — 갈렸다. 다만 「도착점」은 오히려 가까워졌다.**

| 축 | ep05s-1 신 | ep04s-3 S2 | 거리 |
|---|---|---|---|
| `dur` | 0.62 | 0.72 | −100ms (−14%) |
| 시작 음정 | 210 | 150 | **5.83 반음** ✅ |
| **끝 음정(도착점)** | **520** | **470** | **1.75 반음** 🟡 |
| 스윕 폭 | 15.70 반음 | 19.77 반음 | 4.07 반음 |
| 포락선 | peak/rms 2.18 · 정점 k=0.251 | 2.18 · k=0.250 | **같음** |

세 축(길이·시작·폭)이 벌어졌으므로 **같은 소리는 아니다 — 이 부분은 통과다.**
🟡 다만 `why` 스스로 *"riser 는 **끝이 도착점**"* 이라고 못박아 놓고,
**그 끝을 ep04s-3 쪽으로 1.28 반음 당겨 놨다**(560 → 520: 3.03 → **1.75 반음**).

리포 전체 riser 끝 음정을 늘어놓으면 **400 · 430 · 430 · 470 · [여기] · 640 · 700** 이고,
470~640 사이 빈칸의 한가운데는 **520 이 아니라 549** 다.

> **제안 (정정 요구 N-4):** `to` 를 **560** 으로 되돌려라. `dur`·`delayMs` 는 그대로 둔다 —
> `to` 는 `(delayMs + dur)` 에 영향이 없으므로 **도착 시각 1,700ms 가 그대로다.**
> `0.62/210→560` 실측 피크 **0.0863**(천장 여유 동일). 그러면 세 축 전부에서 최대로 벌어진다:
> ep04s-3 대비 끝 **3.03 반음** · ep00i S2(640) 대비 **2.31 반음**.

**(d) 🔴 `why` 본문 첫 문단이 아직 폐기된 값을 현재형으로 설명한다.**

> `sprout` … *"riser 는 진폭이 k=0.25 에서 정점이고 음정은 끝에서 정점이라,
> **dur 0.72 를 delayMs 980 에 걸면** 몸통이 두 번째 칸(+1,201ms)에 앉고…"*

`0.72`·`980` 은 **이미 버린 값**이다. 같은 `why` 가 세 문단 뒤에서
*"0.62/210→520 으로 옮겨 … delayMs 를 980 → 1,080 으로 올렸다"* 라고 스스로 반박한다.
읽는 사람이 어느 쪽이 현재 설정인지 알 수 없다. → 정정 요구 N-4 에 포함.

### 반려 사유 1 — `sfx.why` 의 대조표가 아직도 삭제된 디렉터리에서 나온 값이다

근거는 §1-② 전부. 고칠 것은 셋이다.

   `0.045/1520`(=ep05s S3·S9 고아)을 빼고, 빠진 **`ep05s-2 S3` 0.07/1080** ·
   **`ep05s-3 S3·S4` 0.048/1380** 을 넣어라.
   그 뒤 **1120Hz 를 유지할 근거를 적거나 옮겨라** — `ep05s-2` 와 0.63 반음이다.
   (같은 글에서 나온 바로 다음 편이라 연속 시청 확률이 가장 높은 쌍이다.)
2. **S5 thud 의 `why` 대조표도 다시 뽑아라.** `0.19/176`(=ep05s S2 고아) · `0.26/132`(=ep04s S1 고아)를
   빼고 `ep04s-1` 0.16/210 · `ep04s-2` 0.3/124 · `ep04s-3` 0.2/168 · `ep05s-2` 0.21/112 를 넣어라.
   🔑 **값 자체는 안 겹치므로 결론은 안 바뀐다** — 근거만 바로잡으면 된다.
3. **`notes.돌려막기를_어떻게_피했나` 의 회차 목록도 아직 고아다.** 1차 §2-d 가 같이 지시한 자리다:

   으로 바꿔라. (내가 대신 확인해 두었다 — 이 편의 kind 다섯 `hairline` `worn` `sprout`
   `p0gate` `keystone` 은 현역 어느 회차와도 실제로 안 겹친다. **결론은 안 바뀐다. 근거만 고쳐라.**)
   같은 문단이 참조하는 *"SkipFailureCooldown ↔ ep04s2 idlespin"* 도 현역 id 는 **`ep04s-2`** 다.
4. ✅ **S3 riser 의 「실측 전수」는 검수 도중에 닫혔다**(46건 · latch 일곱 · `ep05s2 S7` 삭제).

### 4-d. `siblings` 라벨 — 「자기 이름은 자기가 짓는다」

지금 같은 편을 세 편이 제각각 부른다(실측):

| 가리키는 편 | 5-1 이 부르는 이름 | 5-2 가 부르는 이름 | 5-3 이 부르는 이름 |
|---|---|---|---|
| 5-1 | **숫자 하나 차이가 요리를 하게 만들었다** | 숫자 1 차이가 만든 경제 루프의 동기 | 숫자 1 차이가 주민을 요리하게 만들었다 |
| 5-2 | 집을 지었더니 주민이 그 안에 갇혔다 | **집 한 채가 부른 문제들** | 집을 지었더니 주민이 그 안에 갇혔다 |
| 5-3 | 기능을 두 번 늘렸는데 코드는 0줄이었다 | 「에셋 1개, 코드 0줄」이 두 번 재현 | **기능이 두 번 늘었는데 코드는 0줄** |

**제안 규약:** *"각 회차의 `outro.siblings` 에서 `me:true` 인 항목의 `label` 이 그 편의 정본이고,
나머지 두 편은 그것을 **글자 그대로** 옮겨 적는다."*
정본을 어디 새로 만들지 않아도 되고, 편이 늘거나 제목이 바뀌어도 한 군데만 고치면 된다.
지금 기준으로는 굵게 표시한 셋이 정본이 된다.

🔑 **이건 세 편에 걸친 일이라 `ep05s-1` 단독 반려 사유로 세지 않았다.**
마스터가 셋을 한 번에 맞추는 편이 낫다. `outro.source` 는 다르다 — **정본이 이미 문서에 있고
혼자 어긋난 것이 이 편이므로 이 편에서 고쳐라.**

## 5. 다시 확인한 것 — 1차 통과 판정이 유지된다

건드린 곳이 sfx 하나뿐이라 아래는 **재확인만** 했다. 전부 유지된다.

- **사실관계 / 지워진 표 대조** — 원본 HTML 을 다시 열어 태그를 셌다:
  `table 0 · pre 0 · svg 0 · style 0 · script 0 · img 0 · figure 0 · ul 0 · ol 0`(`code` 8, 전부 문장 안 고유명).
  **표가 애초에 0개**라 "표를 지워서 값이 빠졌을 가능성" 자체가 없다.
  원문 숫자 전수 = `0 1 2 3 7 4 5`(뒤 넷은 M0·M1·M2·M3·M4·M5·S1~S7 의 번호),
  화면에 뜨는 숫자는 **3 · 2 · 1** 셋뿐이고 셋 다 원문 3절에 있다. **지어낸 값 0건.** ✅
- **제목 이행** — 게이트가 `겹침: 숫자, 하나, 차이, 주민, 요리`. 0초 자막에서 이행된다. ✅
- **첫 10초** — 제목 카드 없음. 0초에 이미 탑이 쌓인다. 수수께끼는 11.8초 자막
  (`이 한 칸이 / 왜 필요했냐면요`)에서 던져지고 답이 S5 다. ✅
- **다음 편 예고의 사실성** — `order` 상 다음이 `ep05s-2` 이고, 그 편 제목이
  「집을 지었더니 주민이 갇히게 생겼어요」, 첫 자막이 「집을 한 채 지었더니 / 주민이 갇히게 생겼어요」다.
  **예고가 사실이다.** ✅ 구성안 표 20행의 막(3막)과도 맞고, 없는 막을 지어내지 않았다. ✅
  상호 참조도 있다(blurb 끝 `(… 5-2편에서)` + `siblings` 셋). ✅
- **`t` 로 도는 조건 / 다른 cue 파생 문턱** — 다섯 kind 전수 재확인, 사건인 것 0건. ✅
- **`excluded` 10건** — 사유 유지. 원문 7절 「다음 단계」(M4·M5)를 예고 근거로 안 쓴 판단 그대로. ✅
- **효과음 배치·개수·gain** — 43초에 셋. 전부 나레이션이 부르는 사건에 붙었다.
  `tick 0.060 ≤ 이 설정의 실측 상한 0.0629` · `thud 0.070 ≤ 0.1854` · `riser 0.060 ≤ 0.3168`.
  **피크 천장 경고 0건.** ✅ (🟡 tick 은 자기 상한의 95.4% 라 여유가 가장 적다 — 올리지 마라.)

## 되돌리는 곳

**작성팀.** 마스터에게 올리지 않는다.

**닫아야 하는 것 = §2 반려 사유 2건.** 둘 다 기계적이다 —
전수 스크립트 한 번 돌려 세 `why` 를 다시 쓰고(46건이 나와야 한다),
`keystone.js` 에서 문장 둘·변수 하나·import 하나를 지우면 끝난다.

**같이 고칠 것 = §3 표의 열린 정정 8건**(4-1~4-7 + N-4). `outro.source` 는 §4-b 대로
`M2·M3 생산 체인과 집` 으로 바꾼다.
