## 2. 🔴 반려 사유 — 효과음 S3 riser 가 직전 회차와 같은 소리다

### 2-a. 사실

`state/schedule.json` 의 `order` 에서 `ep05s-1` 바로 앞은 **`ep04s-3`** 이다.

| | kind | gain | dur | 스윕 | 역할 |
|---|---|---:|---:|---|---|
| **`ep04s-3` S2 `relative`** | riser | 0.06 | **0.72** | 150→470 | *"목표선이 밀려 나가고 그 사이가 채워지는 구간 — 이 편에서 **무언가가 커지는 유일한 자리**"* |
| **`ep05s-1` S3 `sprout`** | riser | 0.06 | **0.72** | 170→560 | *"단계 띠 세 칸이 씨앗 → 자라는 중 → 수확 가능 순으로 **차례로 켜지는** 구간"* |

같은 kind · 같은 gain · **같은 길이** · 같은 "자라서 도착한다" 성격이고, 실호출로 잰
포락선도 사실상 같다(peak 0.0865 vs 0.0863). 음정만 시작 **2.2 반음** · 끝 **3.0 반음**
위로 옮긴 것이다 — 한 편 건너 듣는 사람에게는 **같은 소리를 조금 높인 것**이다.

```
$ node -e "import('./sfx.mjs')…"
S1               tick   gain 0.06 | peak 0.4388 | 천장0.46 초과 false
S3               riser  gain 0.06 | peak 0.0863 | 천장0.46 초과 false
S5               thud   gain 0.07 | peak 0.1737 | 천장0.46 초과 false
비교 ep04s-3 S2    riser  gain 0.06 | peak 0.0865 | 천장0.46 초과 false
```

### 2-b. 더 무거운 것 — `why` 의 대조표가 저장소에서 반증된다

`scene.json` S3 `sfx[0].why` 는 이렇게 적었다:

> 🔴 리포의 riser 는 0.85/120→400 · 0.9/200→640 · 0.95/220→700 · 1.02/130→430 이고
> 여기 0.72/170→560 은 **넷 다와 겹치지 않는다 — 이 회차 것이 가장 짧다.**

**두 문장 다 사실이 아니다.** 저장소 전수(`episodes/*/scene.json`)의 riser 는 넷이 아니라 일곱이고,
빠진 셋 중 하나가 위의 `ep04s-3` **0.72** (같은 길이), 하나가 `ep05s-2` **0.55** (더 짧다).

같은 누락이 thud 에도 있다. `why` 는 *"리포의 thud 는 0.15/190 · 0.16/170 · 0.19/176 ·
0.22/기본150 · 0.24/120 · 0.26/132 · 0.32/125"* 라고 일곱을 적었는데, 실제로는
`ep04s-1` 0.16/210 · `ep04s-2` 0.3/124 · `ep04s-3` 0.2/168 **셋이 더 있다**
(thud 값 자체는 다행히 안 겹친다 — 0.28/142).

`notes.돌려막기를_어떻게_피했나` 도 비교 대상을
*"ep00s · ep01s · ep02s · ep03s · **ep04s** · **ep04s2** · ep00i"* 로 적었다.

### 2-c. 원인 — 폐기된 고아 디렉터리를 봤다

`episodes/ep04s/` 와 `episodes/ep04s2/` 는 **`order` 에 없는 분할 전 잔해**다
(브리프 §8-e 가 예고한 상태). 현재 순서표의 4편은 `ep04s-1` · `ep04s-2` · `ep04s-3` 이고,
**빠진 sfx 셋이 정확히 그 세 편의 것**이다. 고아를 보고 현역을 못 본 것이다.

기획 브리프 §9-4 가 이 실패를 **미리 지목해 뒀다** — *"`sfx.why` 의 앞 회차 대조를 실제
값으로. 지난 편은 '직전 편 latch dur 0.15' 라고 썼는데 리포에 그런 latch 가 없었다."*
같은 자리가 두 번째다.

### 2-d. 고칠 것

1. **S3 riser 를 `ep04s-3` S2 와 갈라라.** dur 을 0.72 에서 떼고(0.72 는 이미 쓰였다)
   스윕도 다시 잡아라. 이 편의 사건은 "밀 세 포기가 단계를 밟는" 것이고 저 편은
   "막대가 밀려 나가는" 것이므로 성격도 갈릴 수 있다.

## 3. 통과한 것 — 근거를 붙여 남긴다

### 3-a. 사실관계 — 지어낸 값 0건

**지워진 표와의 대조**: 원본 HTML 을 직접 열어 셌다.

```
$ for tag in table pre svg style script img figure ul ol code; do … done
table 0 · pre 0 · svg 0 · style 0 · script 0 · img 0 · figure 0 · ul 0 · ol 0 · code 8
```

**표·도식·코드블록이 애초에 0개다.** 순수 산문이라 "표를 지워서 값이 빠졌을 가능성"
자체가 없고, 브리프 §2 의 실측과 일치한다. `<code>` 8개는 전부 문장 안 고유명이다.

화면·자막에 뜨는 숫자를 전수로 뽑았다:

```
$ node -e "…shots 의 spec·lines·reads 전체에서 숫자 토큰 추출"
3 2 1 0 150 200 320 5
```

`0`·`320`·`5` 는 `reads` 산문("320px 짜리 판", "5px 짜리 기둥")과 cue 인덱스,
`150`·`200` 은 `pauseAfter` 다 — **화면에 뜨는 숫자는 3 · 2 · 1 셋뿐**이고 셋 다 원문 3절
("포만감 소비 3, 조리하면 소비 2. 단 1 차이지만")에 있다. 스프라이트 3단계도 원문 그대로다.
브리프 §11 이 금지한 것(테스트 개수·방치 일수·줄 수·커밋 수·주민 수)은 한 자리도 없다.

### 3-b. 🔴 함정 ① — "소비"가 안 빠졌다

원문: *"날 것을 먹으면 포만감 소비 3, 조리하면 소비 2."*

| 자리 | 실제 문자열 |
|---|---|
| 자막 `text` | `날 것을 먹으면 포만감 소비 3,` / `요리하면 소비 2예요.` |
| 자막 `say` | `날 것을 먹으면 포만감 소비 삼, 요리하면 소비 이예요.` |
| 화면 축 이름 | `포만감 소비` |
| 화면 탑 라벨 | `날 것` = 3칸 / `조리` = 2칸 (높이 = 소비량) |
| accent(정답 표시) | **조리 쪽**(`hairline.js:120` `tower(rx, cooked.v, vk, gk > 0.3, …)`) |

**프레임으로 확인했다.** 4.0초 프레임에 「포만감 소비」 축 이름 아래 「날 것」 3칸(값 3) ·
「조리」 2칸(값 2)이 서 있고, 9.0초 프레임에 「차이 1」 괄호가 물리면서 **조리 탑만 초록으로
바뀐다.** 높이만 보면 날 것이 커 보이는 오독을 색이 막는다. `포만감 3` 이라는 문자열은
화면 어디에도 없다. ✅

### 3-c. 🔴 함정 ② — `SkipFailureCooldown` 이 예방 조치로 남았다

원문: *"…쿨다운에 막혀 발동 못하는 사태를 **막기 위해** P0 목표에 `SkipFailureCooldown` 플래그를 추가"*

- 자막 0 = **`실패 쿨다운이 긴급 목표까지 / 막을 수 있었어요.`** — 가능·조건법이지
  "막혔어요"가 아니다.
- 화면 `riskNote` = **`긴급 목표가 발동 못 하는 사태를 막으려고`** — 원문 표기 유지.
- 45.65초 프레임 확인: 사고를 뜻하는 표시(쓰러진 표식·경고 부호)가 **0개**. ✕ 넷은
  전부 띠 위에 있고 "이렇게 되면 못 나간다"는 가정의 그림으로 읽힌다.
- `p0gate.js:15-18` 머리말에 같은 경고가 다시 적혀 있다.

"실제로 주민이 굶었다"에 해당하는 문자열은 자막·`say`·`spec`·`reads` 전체에 0건이다. ✅

지난 반려 사유(✕ 가 「실패 쿨다운」 라벨을 취소선처럼 가로지름)가 유지·강화됐다.

`"…요리하면 소비 이예요."` — `이예요` 는 지정사 `-이에요` 와 발음이 겹쳐
**「소비예요」로 들릴 위험**이 있다. 이 편 전체가 3 대 2 위에 서 있으므로 그 자리에서
2 가 안 들리면 사건이 사라진다(자막에는 `2` 가 있으니 치명적이진 않다).
`요리하면 소비는 이예요` / `요리하면 소비 이, 하나 적어요` 처럼 한 박자를 넣어 갈라 줘라.

### 4-6. 🟡 마무리 넉 줄이 전부 `-어요` 계열이고 마지막 둘이 각운이다

```
9  …막을 수 있었어요.     (-었어요)
10 …건너뛰게 했어요.       (-었어요)
11 …동기가 얹혀요.         (-여요)
12 …주민이 안에 갇혀요.     (-여요)
```

과거 2연속 + 현재 2연속이라 `voice.json` rules.1 의 "**같은** 어미 3연속 금지"는
문자 그대로는 안 걸린다. 다만 소리 내어 읽으면 **`얹혀요` / `갇혀요` 가 각운으로 붙어**
착지(11)와 예고(12)가 한 덩어리로 들린다 — 예고는 박자가 꺾여야 하는 자리다.
12번을 `다음 편은 집을 짓는데, 주민이 그 안에 갇힙니다.` 처럼 끊는 것을 권한다
(rules.1 의 예외 조항 — *"단정하고 싶은 한 문장은 일부러 '~한다'로 끊는다"*).

### 4-7. 🟡 예고 길이 3.5초 — 게이트는 통과, 사용자 확정 기준(3초)은 초과

`check.mjs` 의 `TEASER_MAX = 4.0` 으로 **3.7초 통과**이고, 실측 계수(140.9ms/자)로 다시
재도 **3.52초**다. 사용자 확정 기준은 3초라 0.5초 넘는다. **반려가 아니라 정정 요구**로
짚는다 — 25자를 22자 안쪽으로 줄이면 든다(예: `다음 편은 집을 짓는데, 주민이 갇혀요.` = 21자 → 2.96초).

## 5. 🟡 판단을 넘기는 것 — 아웃트로 훅 카드 규약 (반려 사유 아님)

### 5-a. 이 편이 어떻게 했나 — 프레임으로 확인

`.outrocard` 는 `.vis` 와 **좌표가 완전히 같고**(`style.css:75` vs `105` — 둘 다
`top:21.875%; left:20px; right:20px; bottom:34.0625%`) `z-index:3` 에 `background:var(--bg)`
불투명이라, `OUTRO_MS = 2600` 구간에 **비주얼이 통째로 사라진다.** 63.7초 프레임에서
`keystone` 의 판·기둥·「차이 1」·훅 한 줄이 전부 없어지고 형제 편 목록만 남은 것을 확인했다.

이 편의 산수:

```
마지막 자막(예고) 길이 3,523ms + SHOT_TAIL 350ms = 3,873ms 가 남는다
카드 등장(TOTAL − 2600) = 마지막 자막 시작 +1,273ms
keystone 훅 카드: hk 로 +40ms 에 뜨기 시작 → +1,172ms 에 불투명 도달 → +2,113ms 에 완성
```

즉 **훅이 100ms 만 온전히 보이고 덮이며, spring 애니메이션은 끝까지 못 간다.**
그리고 `notes.정적_구간_대책` 이 *"가장 위험한 자리는 S5 의 마지막 자막 … 그래서
`hookCue` 를 물려 훅 카드가 그때 올라오게 했다"* 고 선언한 **바로 그 대책이 덮이는
대상**이다. 결과적으로 마지막 2.6초의 실제 화면은 정지한 카드 + 정지한 자막이다.

🔴 **`check.mjs` 의 `정적 구간 3초 이하` 는 이 구간을 못 본다.** 그 검사는
`document.querySelector('.shot.on canvas')` 픽셀만 읽는데(`check.mjs:296-303`)
아웃트로 카드는 그 위에 얹힌 DOM 이다. `최대 0.0s` 는 캔버스가 계속 움직인다는 뜻이지
**보이는 화면이 안 멈춘다는 뜻이 아니다.** `OUTRO_MS = 2600` 이 3초 게이트를 넘지
않으려고 고른 값(`engine.js:170-172` 주석)이라는 점이 이 사각지대를 방증한다.

### 5-b. 여섯 편이 어떻게 갈렸나 (실측)

| 편 | 마지막 샷 | 카드 등장 = 마지막 자막 시작 +? | 마지막 샷에서 가려지는 비율 |
|---|---:|---:|---:|
| `ep04s-1` | 6.4s | +850ms | 41% |
| `ep04s-2` | 14.2s | +1,132ms | 18% |
| `ep04s-3` | 10.1s | **+145ms** | 26% |
| **`ep05s-1`** | 7.9s | **+1,273ms** | 33% |
| `ep05s-2` | 10.6s | +709ms | 25% |
| `ep05s-3` | 13.1s | +568ms | 20% |

**여섯 중 `ep05s-1` 이 그림에 가장 긴 시간을 준다.** 반대 끝인 `ep04s-3` 은 마지막 자막이
시작하자마자(+145ms) 덮여, 그 편의 마지막 그림은 사실상 안 보인다.

### 5-c. 검수 의견 (마스터 판단 요청)

**규약을 하나 정하는 것을 권한다. 셋 중 하나다.**

1. 🥇 **훅을 `kind` 에서 빼고 아웃트로 카드가 맡는다.** 지금은 같은 문장이 두 곳에서
   경쟁하다 한쪽이 100ms 만에 덮인다. 카드에 `hook` 줄을 한 칸 더해 주면 훅이 **끝까지
   남고**, `kind` 는 그림에만 집중한다. 사용자 요구(*"어느 글의 몇 편인지"*)와도 안 부딪힌다.
2. 🥈 **`OUTRO_MS` 를 마지막 자막 길이에 맞춘다** — 예컨대 `min(2600, 마지막 자막의 60%)`.
   `ep04s-3` 형(마지막 자막이 짧아 통째로 덮이는 편)을 구조적으로 막는다.
3. 🥉 **카드를 반투명·부분 상자로 바꾼다.** 🔴 권하지 않는다 — `style.css:104` 주석이
   적어 뒀듯 뒤 샷이 비치면 `3색 팔레트` 검사가 섞인 색으로 읽고, 새 좌표를 발명하면
   `하단 안전영역`·`가장자리` 검사를 처음부터 다시 맞춰야 한다.

**어느 쪽이든 `check.mjs` 의 `정적 구간` 을 캔버스가 아니라 합성 화면 기준으로 바꿔야**
이 자리를 기계가 다시 볼 수 있다. 지금은 규약을 어겨도 게이트가 아무 말을 안 한다.
