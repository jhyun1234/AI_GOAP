## 1. 구성 — 왜 숫자가 먼저인가

브리프 §5 가 이 자리를 콕 짚었다. 1차 구성은 배경(S1 worn, 18초)이 먼저였고 숫자는
18초에 나왔다. 실측 절대 시청 시간이 16~27초이므로 **그 순서면 시청자 절반이 제목이
약속한 숫자를 한 번도 못 보고 나간다.** 그래서 순서를 뒤집었다.

- 0줄: `날 것을 먹으면 포만감 소비 3, / 요리하면 소비 2예요.`
- 1줄: `숫자 하나 차이인데, / 주민이 그때부터 요리를 해요.`
- 2줄: `이 한 칸이 / 왜 필요했냐면요.` ← 배경으로 넘어가는 이음매이자 열린 고리

`youtube.title` = 「숫자 하나 차이로 주민이 요리를 시작했어요」. `check.mjs` 의
`titleWords` 를 손으로 돌려 보면 제목 핵심어 `[숫자, 하나, 차이, 주민, 요리, 시작했어요]`
가운데 **다섯**이 첫 두 줄에 있다(`차이` 는 `차이인데` 가 포함 관계로 잡힌다).
제목을 낭독한 게 아니라 제목이 약속한 **장면**을 0초에 준 것이다 — 화면도 같은 자리에서
탑 둘과 「차이 1」 을 보여 준다.

## 2. 이 회차의 그림을 어떤 생각으로 설계했나

### 2-1. 핵심 결정 — 판(slab)을 첫 샷에서 떼어 마지막 샷으로 옮겼다

기존 `hairline` 은 한 샷 안에서 **재고**(탑 둘 · 차이 한 칸) **얹었다**(넓은 판이 내려와
기둥에 앉는다). 그림 자체는 좋지만 이 편에서는 못 쓴다 — 착지(③ 남는 한 줄)가 첫 10초에
다 소모되고 남은 세 샷이 전부 뒷이야기가 되기 때문이다.

그래서 둘로 갈랐다.

| | S1 `hairline` | S5 `keystone` |
|---|---|---|
| 성격 | **재는 그림** | **떠받치는 그림** |
| 있는 것 | 탑 둘 · 눈금 · 괄호 · 기둥 | 한 칸 · 기둥 · 판 |
| 없는 것 | 판 | 탑 · 눈금 · 괄호 |
| 표식이 도는 방향 | 차이 한 칸의 **테두리를 돈다**(재는 중) | 칸에서 기둥을 타고 **위로 올라간다**(힘이 가는 중) |
| 눈이 읽는 것 | 차이가 몇 칸인가 | 저 큰 것을 저 가는 것이 혼자 받고 있다 |

S1 의 기둥은 마지막 자막(`이 한 칸이 왜 필요했냐면요`)에서 솟아 **꼭대기가 빈 채로 끝난다.**
그게 이 편의 열린 고리이고, S5 가 그 위에 판을 얹으며 닫는다.
`keystone` 에서 판 320px 대 기둥 5px, **64 : 1** 로 벌려 놓은 것이 이 샷의 전부다 —
원문이 말한 "단 1 차이지만 게임 루프 전체의 동기가 이 숫자에 걸려 있다"가 크기 대비로만
읽혀야 한다. 게이지도 막대도 퍼센트도 쓰지 않았다.

### 2-2. 다른 세 그림도 이 편의 자리에 맞춰 다시 짰다

- **`worn`** — 「GOAP 엔진 — 준비됨」 배지를 **자막 0 → 자막 1** 로 내렸다.
  이 편의 자막 1 이 `엔진은 다 됐는데,` 로 시작하기 때문이다. 배지를 자막 0 에 두면
  아무도 안 부르는 문자열이 3초 넘게 떠 있게 되고, 그건 이 시리즈가 실제로 겪은 결함이다.
  cue 도 3개(`pathCue`/`emptyCue`/`lackCue`)로 다시 나눴다.
- **`sprout`** — 자라는 밀의 수학(주기 5.4초, 위상 1/3 어긋남, 띠의 고정 위상
  0.10 · 0.44 · 0.74)은 검증된 값이라 그대로 뒀다. 바꾼 것은 **머리말의 근거**다 —
  이제 이 샷의 앞 샷은 `worn` 이고, 아무도 안 가던 점선 빈 칸 「밭」이 여기서 흙과
  이랑으로 바뀐다. 그 인과를 주석에 적었다.
- **`p0gate`** — ✕ 를 띠 한가운데(`my = BAND_Y + BAND_H/2`)에 두는 수정은 **그대로 유지**했고,
  라벨 baseline 도 `BAND_Y − 4` 로 내려 두 번 안전하게 갈라 놨다(브리프 §9-2).
  새로 붙인 것은 상단 `riskNote` 한 줄이다 — 아래 3-2 참조.

### 2-3. 돌려막기 점검

kind 이름 다섯(`hairline` `worn` `sprout` `p0gate` `keystone`)이 ep00s · ep01s · ep02s ·
ep03s · ep04s · ep04s2 · ep00i 어느 쪽과도 겹치지 않는다.
브리프 §9 의 「부딪히는 자리」 표에서 이 편에 해당하는 것은 하나뿐이다.

> **`SkipFailureCooldown` ↔ ep04s2 `idlespin`**

저 편의 쿨다운은 **닫힌 고리에 걸리는 걸쇠**였고 사건은 표식이 고리를 벗어나 직선으로
나가는 것이었다. 여기 쿨다운은 고리가 한 번도 안 나오고 **가로로 누워 길을 막는 띠**이며,
사건은 띠에 **틈이 둘 뚫리고 그 둘만 아래로 내려가는 것**이다.
나머지 둘이 그대로 막혀 있는 것이 요점이다 — 쿨다운을 없앤 게 아니라 예외를 뚫었다.

`hook` 문형도 갈랐다. 최근 두 편이 `A 는 B 가 아니라 C 였다` 를 연속으로 썼고,
`한 번은 우연이고, 두 번은 구조였다` 는 브리프가 5-3 몫으로 남겨 뒀다.
이 편은 역접형 — **「차이는 1인데, 그 위에 게임 전체가 선다」.**

## 3. 브리프가 크게 박은 경고 둘 — 어떻게 지켰나

### 3-1. 「포만감 소비 3 / 소비 2」에서 '소비'를 빼지 않았다

빼면 3 > 2 라 요리가 더 나쁜 것으로 들려 사실관계가 뒤집힌다. 다섯 곳이 같은 방향을
가리키게 만들었다.

1. 자막 `text` — `포만감 소비 3` · `소비 2`
2. `say` — `포만감 소비 삼` · `소비 이`
3. 화면 축 이름 — `포만감 소비` (`hairline` 의 `axisLabel`)
4. 그림 — **값이 클수록 탑이 높다** (소비량이므로 높은 쪽이 손해)
5. 색 — accent(정답 표시)를 값이 큰 **날 것**이 아니라 **조리** 탑에 붙였다

넷까지만 맞추고 다섯째(색)를 반대로 두면 "높고 초록인 쪽이 좋아 보이는" 화면이 된다.
그래서 기존 `hairline` 이 `raw` 쪽에 걸던 `strong` 을 **`cooked` 쪽으로 옮겼다.**
화면 어디에도 `포만감 3` 이라는 문자열이 없다.

### 3-2. `SkipFailureCooldown` 은 예방 조치다

원문은 *"발동 못하는 사태를 **막기 위해**"* 라고 썼다. 실제로 주민이 굶었다고 쓰면
지어낸 것이 된다.

- 자막이 **조건법**이다 — `막을 수 있었어요` (`막혔어요` 가 아니다)
- 화면 `riskNote` 가 원문 표기 그대로 — `긴급 목표가 발동 못 하는 사태를 막으려고`
- 화면에 사고를 뜻하는 표시가 **하나도 없다** — 쓰러진 표식 · 경고 · 붉은 것
- `p0gate` 의 ✕ 는 *"이렇게 되면 못 나간다"* 는 **가정의 그림**이다.
  같은 경고를 `p0gate.js` 머리말에 다시 적어 뒀다(다음 사람이 그림만 보고 사고로 읽지 않게).

## 5. 효과음 — 셋뿐이다

43초에 셋이면 기준(90초에 5~8)의 절반쯤이다. 일부러 아꼈다 — 이 편은 사건이 하나여서
소리가 날 자리도 셋밖에 없다.

| 샷 | kind | dur / freq | gain | 무슨 사건 |
|---|---|---|---|---|
| S1 at 1 | `tick` | 0.042 / 1120 | 0.060 | 차이 한 칸에 괄호가 딱 물린다 (+1,120ms = '차이' 발음 한가운데) |
| S3 at 1 | `riser` | 0.72 / 170→560 | 0.060 | 단계 띠 셋이 차례로 켜지고 음정 꼭대기가 「수확 가능」에 닿는다 |
| S5 at 0 | `thud` | 0.28 / 142 | **0.070** | 넓은 판이 기둥 하나 위에 앉는다 (+1,155ms = '위에' 발음 안) |

- **소리를 안 단 샷 둘**이 있다. `worn` 은 *아무 일도 일어나지 않는 마을*이 요점이라 사건이
  없고, `p0gate` 는 **통과 자체가 조용해야 예방 조치로 읽힌다** — 요란하면 사고가 났다
  지나간 것처럼 들린다.
- `dur`·`freq` 를 리포 전 회차와 한 쌍도 겹치지 않게 골랐다. 대조표는 각 `sfx.why` 안에 있다
  (tick 9종 · riser 4종 · thud 7종을 실제로 뽑아 대조했다).
- `gain` 은 기본값 0.060 을 쓰고 착지(thud)만 0.070 으로 올렸다. kind 별 상한
  (tick 0.065 · latch 0.071 · thud 계열은 0.085 위 여유) 안이다.
- `delayMs` 셋 다 각 kind 의 draw 식을 역으로 풀어 냈고, 그 시각에 나레이션이 무슨 글자를
  발음하는지까지 `why` 에 적었다.

## 6. 🔴 닫지 못한 것 — 검수자가 먼저 볼 것

### 6-1. `check.mjs` 를 돌리지 못했다

이 작성 환경에 셸이 없다(도구가 Read / Write / Glob / Grep 뿐이라 `node` 를 호출할 수 없다).
따라서 **길이 · 말 속도 · 정적 구간 · 가장자리 잘림 · 하단 안전영역 · 3색 팔레트 ·
결정성 3패스가 전부 미검증**이다. `scene.json` 의 `notes.길이`·`notes.정적_구간_대책`·
`notes.checks` 는 설계 의도와 산정치이지 실측이 아니다.

기계가 볼 수 있는 것 가운데 **파일만 보고 손으로 확인한 것**은 이렇다.

| 항목 | 손 확인 결과 |
|---|---|
| shot 메타 완비 | 5샷 전부 `reads`·`source`·`kind` 있음 |
| kind 파일 존재 | `episodes/ep05s-1/kinds/` 에 5개 전부 |
| 자막 2줄 상한 | 12줄 전부 `\n` 1개 이하 |
| 큰 쉼 2회 이하 | **0회** (600ms 이상 없음) |
| 제목 이행 | 겹침 `[숫자, 하나, 차이, 주민, 요리]` — 통과 |
| 다음 편 예고 있음 | S5 마지막 줄이 `/다음\s*편/` 에 걸린다 |
| 예고 4.0초 이하 | 25자 ÷ 6.7 = **3.73초** |
| 총 길이 | 추정 **42.9초** (상한 50 · 권장 30~45 안) |

### 6-2. 🔴 `check.mjs` 자체가 지금 실행되지 않는다

`tools/scene-video/check.mjs:104`

```js
const teaserDur = teaserLines.reduce((a, l) =>
  a + (l.say ?? l.text.replace(/\n/g, ' ')).length / CPS_REF + (l.pauseAfter ?? 0) / 1000, 0);
```

**`CPS_REF` 가 이 파일 어디에도 선언돼 있지 않다.** 리포 전체 검색 결과 정의 0건 · 사용 1건이다.
예고 자막이 있는 회차(= 최근 회차 전부)는 `reduce` 콜백이 실제로 돌면서 `ReferenceError`
로 죽는다. 예고가 없으면 `reduce` 가 콜백을 안 불러 통과하므로, **예고를 제대로 단 회차만
게이트가 터지는** 모양이다.

- `episodes/ep05s/notes/review-split.md:229` 가 *"`check.mjs` 의 길이 산정도 `CPS_REF = 6.7`
  을 쓴다"* 라고 적어 뒀다 → 예전에는 있었다.
- `check.mjs:95~98` 주석이 *"같은 커밋에 있던 「편당 길이 75/90」과 「첫 자막 3.5초」는 버렸다"*
  라고 말한다 → 그 두 검사를 지울 때 상수 선언이 함께 지워지고 104행 사용처만 남은 것으로 보인다.

**작성팀 소관이 아니라 손대지 않았다.** 이 편을 기계로 검수하려면 `const CPS_REF = 6.7;`
한 줄을 먼저 되살려야 한다.

### 6-3. 그 밖

- `delayMs` 셋이 **산정 자막 길이** 위에서 계산됐다(발화 6.77자/초 = `voice.json`
  `engine.speed_실측` 의 ME@1.10). 실측 `timed.json` 이 나오면 각 `why` 의 창 계산식
  `W = lead + 자막길이 × span` 에 실제 길이를 넣어 다시 내야 한다.
- `sfx` 의 피크/RMS 를 `synth` 실호출로 확인하지 못했다. 렌더 로그의
  `⚠️ sfx …: 피크 천장에 걸려` 만 보면 된다.
- 폰트 폭 미확인. 가장 긴 문자열은 S5 의 `게임 루프 전체의 동기가 이 숫자에 걸려 있다`
  (21자, 폭 294)와 S4 의 `SkipFailureCooldown`(19자 mono, 폭 196)이다.

### 6-4. 결정성은 코드로 보증했다

`Math.random()` · `Date.now()` · 이전 프레임 기억 · CSS 애니메이션을 다섯 파일 어디에도
쓰지 않았다. 무작위가 필요한 자리가 없어 `lib.js` 의 `rnd` 도 부르지 않았다.
시간에 의존하는 것은 전부 `frac(t/주기)` 와 `sin` 이고 인자는 `t` 와 상수뿐이며,
`ctx.lineDashOffset` 에도 `t` 만 들어간다. 3패스 비교는 로컬 몫이다.

## 7. 파이프라인 쪽에 남기는 메모 (이 편 밖)

브리프 §8 의 `state/schedule.json` 변경안은 **아직 적용되지 않았다**(사람이 한다).
`order` 에서 `ep05s`·`ep05s2` 두 줄이 `ep05s-1`·`ep05s-2`·`ep05s-3` 으로 **치환**되기 전까지
`backlog.mjs` 는 이 편을 못 찾는다. 그리고 `episodes/ep05s/`·`episodes/ep05s2/` 는 새 id 와
안 맞아 고아가 되는데, 다음 사람이 그 `scene.json` 을 참고 구현으로 착각할 수 있다
(특히 `ep05s/kinds/hairline.js` 는 이 편 것과 **판의 유무**가 다르다).
