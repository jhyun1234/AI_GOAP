> **게이트의 첫 자막 3.5초 상한도 넘어서** "엔진은 다 돌고 있었어요"로 바꿨다(**2차 검수 C-2** 반영)

git 으로 실제 이력을 뽑았다:

| 커밋 | S1 자막 0 `say` | 길이(6.7자/초) |
|---|---|---|
| `c20164f` 1차본(11샷) | "엔진은 벌써 다 돌고 있었어요. **주민들도 계속 움직였고요.**" | **5.0초** |
| `bce5f68` 분할 | "주민들은 계속 움직이고 있었어요." | **2.8초** |

  그 두 단계 전에 이미 없어졌다.

  `OK 첫 자막 3.5초 이하  2.8초 — "주민들은 계속 움직이고 있었어요."` **통과였다.**

  사라졌다"*(review-split.md:123). 게이트가 아니라 **말↔그림 결합**이 사유였다.

  내가 "C-2"로 잘못 적었고 작성팀이 그걸 그대로 옮겼다. **라벨은 작성팀 책임이 아니다.**

### `notes.화면이_자막을_옮겨_적지_않게` — 절반 🟡

끝에 정정문이 붙었다(`🔴 2026-08-04 정정 — 이 항목이 "포만감 소비"를 …`). 내용은 정확하고

## 📌 사람에게 올리는 이유와 권고

규약대로다 — **`excluded`/`notes` 의 기록 정확성이 3회차째 남았으므로 작성팀에 돌려보내지 않는다.**

**영상은 내보내도 된다고 본다.** 남은 지적 전부가 `notes`/`excluded` **산문**이고,
화면·소리·자막·타이밍에 닿는 것이 하나도 없다. 사실관계·예고·효과음·cue 결합·팔레트·결정성·
안전영역은 3회 연속 통과했고, 2차 반려의 실질(R-2)은 이번에 픽셀로 닫혔다.

사람이 정할 것 (전부 문자열 편집 · 렌더 영향 0):

1. `excluded[5]` `[6]` `[10]` 의 샷 귀속. 특히 **`[6]` 은 처분 기록이 반대**라 이것만은 고치는 편이
   좋다 — "S11 의 화면 문자열로 썼다" → 실제로는 예고 샷이 양쪽에서 삭제되며 **통째로 버려졌다.**
2. `notes.길이` 를 현재 컷(425자 · 69.2초 · 16줄 · 5샷)으로.
3. `notes.분할` 의 "5.0초 / 3.5초 상한 초과" 두 사실 주장 삭제(진짜 사유는 1차 C-3 = 배지 결합).
4. 나머지 설계 메모에 "1차본(11샷) 기준" 한 줄.
5. 날짜 `2026-08-04` → `2026-08-03` (3곳), `notes.효과음` 의 `±3ms` → `±7ms`.

**진행 방식에 대한 관찰:** 1·2차는 *"고쳤다"고 적고 안 고친* 거짓 자기보고였는데, 이번 보고는
**사실이었다**(치환 2건이라 적었고 정확히 2건 들어갔다). 남은 것은 정직성이 아니라 **요구 범위를
문자열 하나로 좁혀 읽은 것**이다. 4·5번 항목처럼 줄 번호로 지정된 요구는 앞으로
"지정된 각 자리를 고친 뒤 파일에서 다시 읽어 대조" 를 항목별로 걸어야 같은 일이 안 난다.
