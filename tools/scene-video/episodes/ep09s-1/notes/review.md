## 1. 🔴 R1 — 「농사꾼」·「떠돌이」를 직업(M5)으로 놓았다

### 화면이 실제로 주장하는 것

스틸 `S3 / 16150ms` · `S4 / 21500ms` 에서 눈으로 확인:

```
CODE
M4 TRAIT   [고집쟁이] [//////] [//////] [//////]
M5 JOB     [농사꾼]   [떠돌이] [//////] [//////]

`scene.json` S2·S3 `spec.rows[1] = {label:"M5 JOB", cells:["농사꾼","떠돌이", …]}` ·

`undersurface.js:18` 주석도 「「고집쟁이」(성격) · 「농사꾼」(직업) · 「떠돌이」(직업)」이라고 적었다.

`Personality_Farmer.asset:DisplayName "농사꾼"` · `Personality_Wanderer.asset:DisplayName "떠돌이"`
(둘 다 `fd626e9 2026-07-15 feat(m4): M4-A PersonalitySO 스키마` 에서 생성 = **M4 성격**).
직업 에셋은 `d149e66 2026-07-16 feat(m5): M5-D 직업 에셋 5종` 이고 밭 직업의 이름은 **「농부」**다.

정보줄을 실제로 그리는 코드도 같은 말을 한다 —
`Assets/Scripts/M0/UI/SeasonHud.cs:214-215`

```
$"{a.ShortName} — 성격 {a.Personality.DisplayName}" + $" · 직업 {a.Job.DisplayName}"
```

### 결정적인 것 — 이 함정은 프로젝트가 이미 이름 붙여 뒀다

`Docs/M7_상호대화_실행명세서.md:68` · `Assets/Scripts/M0/Presentation/NameTag.cs:9`

> **ADR-M7-5 (이름표엔 직업만)**: 상시 이름표 = "이름 · 직업". 성격은 선택 정보줄에서만 —
> **성격 이름이 직업처럼 들리는 혼동 방지.**

이 편이 다루는 바로 그 밀스톤(M7-A)의 ADR 이 「농사꾼·떠돌이가 직업처럼 들린다」를
경계하려고 존재하는데, 대본이 정확히 그 혼동을 화면에 박아 넣었다.

### 왜 반려인가

- 원문은 「그동안 저는 주민마다 성격(M4)과 직업(M5)을 나눠 넣는 작업을 해왔습니다. 농사꾼은
  밭을 붙들고, 떠돌이는 잘 돌아다니고, 고집쟁이는 웬만하면 시키는 걸 미룹니다」로 셋을
  **나란히만** 쓰고 **어느 쪽인지 말하지 않는다.** 낱말 셋이 원문에 실재하는 것은 맞지만
  (`grep` 확인), 화면은 낱말이 아니라 **분류**를 주장했고 그 주장이 틀렸다.
- 작성팀 스스로 `notes.사실_정확성 ②` 에 *"🔴 이 배치가 틀리면 원문이 말하지 않은 분류를
  주장하게 되므로 따로 짚어 둔다"* 고 적었다. 짚어 두고 틀렸다.
- 오염 범위가 넓다: S2 행 라벨 · S3 행 라벨 · **S4 정보줄의 `JOB 농사꾼`** · S4 의 연결선 둘
  (`cells[i] → colX(i+1)`) 이 전부 이 분류 위에 서 있다. **페이오프 샷의 글자가 틀렸다.**

### 요구

원문이 라벨을 안 붙였으므로 **화면도 붙이지 않는 것**이 안전한 처리다. 예: 두 행을
`M4 TRAIT` / `M5 JOB` 으로 가르지 말고 `M4 성격` 한 행에 「고집쟁이·농사꾼·떠돌이」를 두고
`M5 직업` 행은 값 없이(가림) 두는 형태 — 「속은 다 갈려 있다」는 뜻은 그대로 서고,
지어낸 분류는 사라진다. S4 정보줄은 원문 순서(이름·성격·직업)를 지키되 `JOB` 칸을
글자 없이(NAME 칸과 같은 처리) 두면 페이오프 「농사꾼 고집쟁이」와도 안 부딪힌다.
어떤 형태로 갈지는 작성팀 판단이나, **「농사꾼 = 직업」을 화면이 말하는 형태는 안 된다.**

## 2. 🔴 R2 — S3 `tick` 이 피크 천장에 걸린다

```
$ node -e "import('./sfx.mjs').then(({synth})=>synth('tick',{dur:0.052,freq:1180,gain:0.060},48000))"
⚠️ sfx tick: 피크 천장(0.46)에 걸려 목표 RMS 0.060 → 실효 0.0598 (-0.0dB).
   이 소리만 조용해진다 — gain 을 낮추거나 peakCeil 을 올릴 것.
```

- 이 옵션 조합의 실제 gain 상한은 **0.0598** 이다(gain 1당 피크 7.688 → 0.46 ÷ 7.688).
- `sfx.why` 는 *"gain 0.060 은 기본값이고 tick 기본 옵션 상한(0.065) 아래다"* 라고 적었는데,
  **상한은 kind 가 아니라 kind + 옵션이 정한다.** 0.065 는 기본 옵션(dur 0.05·freq 1400)의 값이라
  `dur 0.052 / freq 1180` 에는 안 맞는다.
- 실효 감쇠는 −0.0dB 로 귀에는 안 들리겠지만, **렌더 로그에 경고가 찍히는 것 자체가 반려 사유**다.
- 요구: `gain` 을 **0.059 이하**로. (참고로 S4 `latch{dur:0.185,seed:89,gain:0.064}` 는
  피크 0.3719 로 여유가 있다 — 그 옵션의 상한은 0.0792 다. 그쪽은 문제없다.)

## 3. 🔴 R3 — S3 `tagup` 의 이름표가 서로 겹친다

`tagup.js` 의 `dotAt()` 궤도를 30fps 로 전수 스윕한 결과(샷 길이 3.045초 = 92프레임):

| 검사 | 결과 |
|---|---|
| 이름표(46×18) 둘이 겹치는 프레임 | **50 / 92 (54%)** |
| 최악 순간 | rel **3.033초**(샷 마지막 프레임), 태그 1·2 가 **dx 3.6px · dy 3.2px** — 사실상 포개짐 |
| 동그라미(지름 18) 둘이 겹치는 프레임 | 29 / 92, 최소 중심거리 **4.9px** |

스틸 `16150ms` 로 확인했다 — **가운데에서 이름표 둘이 한 덩어리로, 동그라미 둘이 이중 고리로
뭉쳐 화면이 「이름표 셋」으로 읽힌다.** 그것도 이 샷의 마지막 프레임, 즉 「해결」 챕터가
시청자에게 남기는 그림이다.

- 이 샷의 선언된 `reads` 는 「이름표 넷이 **각** 동그라미 머리에 앉는다 · 이름이 적히는
  자리의 길이가 다르다」다. 넷이 각각이라는 것이 뜻인데 화면이 그것을 못 나른다.
- `notes.이_편의_기본_도형` 은 *"ep07s-1 의 oneheap(다 같이 한 곳에 몰린다)과도 반대다 —
  **여기 넷은 절대 안 뭉친다**"* 라고 자기신고했다. 스윕이 그 문장을 반박한다.
- 궤도 상수 `CX = [0.20, 0.70, 0.42, 0.80]` / `CY = [0.32, 0.68, 0.70, 0.26]` 에서
  1·3번(0.70,0.68 / 0.80,0.26)과 2번(0.42,0.70)이 진폭(rx = 폭×0.16, ry = 높이×0.24) 안에서
  서로의 영역을 침범한다. **S1·S2 는 세로 여유가 커서 26/202 프레임(13%)만 겹치는데,
  S3 만 `by0/by1` 을 이름표 자리 만들려고 좁혀(66~138) 밀도가 2.5배가 됐다.**
- 요구: `CX`/`CY` 를 벌리거나(넷을 사분면으로 고정하고 진폭만 흔들기) 진폭을 줄여
  **최소 중심거리가 태그 폭(46px)을 넘도록** 잡을 것. 고친 뒤 같은 스윕으로 0프레임을 보일 것.

## 4. ✅ 확인하고 통과시킨 것

### 4-1. 마지막 2.6초 — 페이오프는 카드에 안 먹힌다

실측 타임라인(`build/timed.json`, 샷별 `SHOT_TAIL` 350ms 포함):

```
TOTAL 25,939ms   →  아웃트로 카드 = 23,339ms
S4 시작 16,206 / rel: L0 0~3.808 · L1 3.808~6.891 · L2(예고) 6.891~9.383
카드 시각을 S4 기준으로 = 7.133초
```

페이오프 = `linkCue`(코드 칸 알파 0.25→1.0 + 연결선 둘 + 폭 310px 강조 밑줄).
`cue(1, 0.12, 0.45)` → `W = 0.12 + 3.083×0.45 = 1.507`, 완성 시각 `1×W − lead = 1.387초`
= **rel 5.195초 / abs 21,401ms**. 카드보다 **1.94초 빠르다.**

스틸 두 장으로 눈 확인 — `21500ms`(완성 직후) · `23200ms`(카드 직전 프레임) 둘 다
연결선·코드 칸·밑줄이 온전히 떠 있다. **ep08s-3 형태의 사고 없음.**

🔑 갈린 이유는 설계가 아니라 배치다 — 이 편은 페이오프를 **마지막 자막이 아니라 그 앞 자막**에
걸었고, 뒤에 예고 자막 2.492초가 완충으로 서 있다. 옳은 처리다.

### 4-2. 말과 그림의 동기 — `t` 로 도는 것과 파생 문턱을 전수 스윕

`grep -n "frac(\|Math.sin(\|cue("` 로 뽑아 하나씩 풀었다.

| 자리 | 형태 | 판정 |
|---|---|---|
| `samedots` 훑개 `frac(t/4.6)` | 알파를 `sin(πu)` 로 흔들 뿐 문턱 없음 | ✅ 장식 |
| `undersurface` `press()` = `frac((t+i·0.34)/2.4)` → `hit = clamp((k−0.72)/0.28)` | **파생 문턱이다.** 스윕: 열마다 24~25프레임 발화, 최대 k = 1.000 | ✅ 사건이 아니라 반복 상태이고 sfx·나레이션이 안 물려 있다. ep08s-3 `weightknob`(문턱을 한 프레임도 못 넘김) 형태 아님 |
| `tagup` `rise(i)` | 스윕: 넷 다 완전 착석 46~60프레임 | ✅ |
| `infoline` `fk/lk/nk` | 완성 rel 2.700 / 5.200 / 7.767초 | ✅ (nk 는 §5 C3 참조) |
| 점선 흐름 · 빗금 흐름 · `dx = sin(2πt/6.4)` | 전부 문턱 없는 연속 운동 | ✅ |

`cue` 인덱스도 전부 그 내용을 말하는 자막을 가리킨다 —
S1(화면 켜짐 0 / 하나 고름 1) · S2(코드 칸 0 / 선이 벽 1) · S3(0) · S4(정보줄 0 / 코드 칸 또렷 1 / 예고 2).

### 4-3. 첫 줄 — 실측 3규칙 통과

```

| ②우리 프로젝트 진행 상황 보고(18.30% 형태) | ✅ 통과. 「재설계가 끝난 그 자리에서」는 **끝난 내부 작업의 상태 보고**인데 이 줄은 **막 벌어지려던 일**이다. 'M7'·'성격과 직업을 다 넣고 나서' 같은 표현이 실제로 0건 |

**앞 편 약속 이어받기에 대한 판정** — `ep08s-3` 의 `outro.next = "9편 · 주민들이 서로에게
말을 걸다"` 를 실물로 확인했다. 이 편이 그것을 **요약이 아니라 발단**으로 쓴 처리를 승인한다.
앞 편을 본 시청자는 기다린 것이 0초에 나오고, 안 본 시청자에게는 그냥 서는 문장이다.
둘째 줄에서 「만든 저부터 몰랐다」로 꺾여 배신이 아니라 인과가 된다. **이 판단은 옳다.**

🟡 **의견(미검증 4번 규칙이라 반려 사유 아님)** — 상위 3편의 축(주민이 무언가를 하고 있고
그게 어긋난다)은 이 편에 없다. 첫 줄에서 주민은 **행위자가 아니라 대상**이고(내가 말을 걸게
하려던 참), 어긋남은 둘째 줄에서 **내가** 진다. 작성팀도 같은 것을 적어 뒀다. 등급을 섞지
않기 위해 의견으로만 남긴다 — 이걸로 고치라고 요구하지 않는다.

### 4-4. `제목 후킹 (수치)` 경고 — 원문 대조 결과 **정당하다**

원본 전문을 훑어 아라비아 수치를 전수로 뽑고 넷이 아니라 **여섯**을 확인했다:

| 원문 수치 | 위치 | 이 편이 못 쓰는 이유 |
|---|---|---|
| `M4`·`M5`·`M7` | 4·7절 | 밀스톤 번호. 값이 아니라 이름 |
| `다섯 단계` | 7절 제목 | 이 편은 그중 A 하나. 제목이 약속하면 편의 사건이 바뀜 |
| `0`(스크립트 파일 수) | 8절 | M7-B 소재 + **ep05s-3 이 같은 뜻으로 이미 사용** |
| `에셋 1개, 코드 0` | 11절 | 같은 이유(M7-E) |
| `4타일 → 2타일` | 16절 | **9-2 의 것**(`ep09s-2/scene.json` 제목에 실재 확인) |
| `여섯 갈래(ADR)` · `한 주기 최대 한 쌍` · `동시 1명`(모닥불) | 13·15·17절 | 전부 9-2·ep10s 재료. `excluded` 에 사유와 함께 있음 |

**이 편이 맡은 사건(이름표)에 붙은 수치가 원문에 정말 없다.** 지어내지 않은 것이 옳은 처리다.
🔑 그리고 숫자가 없다고 첫 줄이 수치 설명이 되지도 않았다(§4-3). **경고를 사유로 쓰지 않는다.**

### C1. `delayMs` 둘을 실측으로 다시 냈다 — 값을 갈아 끼울 것

작성팀 신고대로 어림값이었다. 실측 타임라인으로 풀면:

| | 목표 사건 | 창 `W` | 문턱 raw | **실측 delayMs** | 현재 | 오차 |
|---|---|---|---|---|---|---|
| S3 `tick` | 마지막 이름표 착석 `ok = 0.90` | `0.10 + 2.695×0.72 = 2.0404` | 0.8042 | **1,541** | 1,870 | **+329ms = 9.9프레임** |
| S4 `latch` | 마지막 칸 `fk = 0.84` | `0.14 + 3.808×0.72 = 2.8818` | 0.7467 | **2,012** | 2,130 | +118ms = 3.5프레임 |

- `rel dur` 은 **`pauseAfter` 포함**이다(S3 = 2445+250, S4 L0 = 3678+130).
- `ease` 역함수는 이분탐색으로 풀었다 — `ease(k)=0.90 → k=0.8042` · `0.84 → 0.7467`.
  🔑 작성팀이 `why` 에 적은 0.805 / 0.747 은 **맞는 값이다**(옛 회차들이 쓰던 0.729 오류 없음).
  틀린 것은 `W` 뿐이다.
- 둘 다 판정선 ±20프레임(0.667초) 안이라 그 자체로 반려는 아니지만, S3 는 10프레임에 걸쳐 있고
  무엇보다 **작성팀이 「실측 나오면 소리부터 다시 계산할 것」이라고 스스로 적어 둔 숙제**다.

### C2. `notes` 자기보고 3곳이 실물과 어긋난다

| 칸 | 적힌 것 | 실물 |
|---|---|---|
| `notes.길이` / writer.md §4 | *"지금은 인용할 실측이 없다 … `build/timed.json` 이 아직 없다"* | **있다.** `build/timed.json` · `full.wav` · `check.mjs` 출력 전부 존재 → 게이트 네 줄(총 길이·권장대역·본문·예고)을 그대로 옮겨 적을 것 |

`check.mjs` 의 식을 인용한 것이라 문제없지만, 그 밖의 환산은 넣지 않는다.

### C3. 🟡 관찰 — S4 예고 말풍선은 끝내 완성되지 않는다

`nk = ease(cue(2, 0.05, 0.35))` → 완성 시각 **rel 7.767초 = abs 23,973ms**.
카드는 **23,339ms** 에 뜬다. 카드 순간의 `nk = 0.237`(알파 0.57 / 0.43, 밀어내기 2.8px).

말풍선은 **페이오프가 아니라 예고 자막의 장식**이므로 반려 사유가 아니다(페이오프 `linkCue` 는
§4-1 대로 1.94초 여유로 완성). 다만 `notes.정적_구간_대책 ④` 가 이 말풍선을 예고 구간의
움직임 대책으로 세워 뒀으니, **끝까지 안 열린다는 것을 알고 두는지** 확인만 해 두자.
(`정적 구간` 게이트는 최대 0.2초로 통과했으므로 실질 문제는 없다.)
