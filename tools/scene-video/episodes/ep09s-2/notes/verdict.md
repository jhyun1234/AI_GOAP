## 5. 🔴 검수팀이 놓친 것 — 2건 (출고는 막지 않는다)

### M2. **D1 은 닫히지 않았다.** 법선 30px 로도 표식 A 의 방향선이 말풍선을 뚫는다

`faceoff.js:152-163` 의 증명은 **「두 방향선은 연결선 위에 놓인다」**를 전제로 법선 지지폭
22.24 + 1.5 = 23.74px 를 구하고 30px 면 여유 6.26px 이라고 적는다.
**그 전제는 샷의 일부에서만 참이다** — `one()` 의 각은 `lerp(0, toB, fk)` 라 회전 중에는
방향선이 연결선이 아니라 **거의 수평**을 향하고, 그쪽이 바로 말풍선을 밀어낸 법선 방향
`(0.776, −0.630)` 쪽이다.

내가 상자를 라운드렉트 외곽(반폭 18.5×12.5, 코너 7.5)으로, 방향선을 butt-cap 직사각형
(8~23px · 반폭 1.5)으로 놓고 샷 전 구간을 스윕한 결과:

```
정상상태(fk = 1)만 보면   최소 +9.30px  (표식 B 방향선, u 0.768)   ← 작성팀이 잰 자리
전 구간(fk 0.25~1)       최소 −1.12px  (표식 A 방향선, ts 2.238)  ← 안 잰 자리
30fps 실제 프레임        frame 420~424 (abs 14,000~14,133) 5프레임이 음수
                        −0.41 / −0.97 / −1.11 / −0.77 / −0.03 px
```

**스틸 14,060ms 로 눈으로 확인했다** — 흰 방향선의 끝이 초록 상자 왼쪽 테두리 안으로 들어가
초록에 먹힌다. 코디네이터가 본 **13,921ms 는 겹침이 시작되기 79ms 전**이라 깨끗했다.
(검수 2차가 22px 시절 잡은 −3.00px 도 같은 자리다. 30px 은 그것을 −1.12px 로 줄였을 뿐 못 없앴다.)

**막지 않는 이유** — ①가려지는 글자·숫자 0 ②30fps 기준 **5프레임**(0.17초), 침범 최대
1.11 CSS px = **3.1 디바이스 px** ③검수가 **이보다 나쁜 상태(−3.00px · 0.371초)를 근거를 갖춰
비차단으로 판정**했고 작성팀은 그것을 더 줄였다 — 개선분을 반려로 갚지 않는다.
④승인 조건 넷 중 어느 것도 건드리지 않는다.

🔴 **다만 코드에 남은 「최소 간극 6.25px」는 거짓 증명이다.** `faceoff.js` 는 다른 회차로
복사될 수 있고, 그때 이 주석은 「30px 이면 안전하다」로 읽힌다. §6 M2 로 정정을 건다.

### M4. `sweep` 의 `delayMs` 가 **틀린 실측값**으로 풀렸다 (척도 혼동 4번째)

`onepair.js` 의 sweep 주석은 S4 첫 줄 `l.dur` 을 **「실측 환산으로는 3.50초」**라고 적는다.
**실측은 3.343초다.**

```
build/timed.json    05-0m4om92.wav  dur 3,213ms
wav 헤더 직접 파싱                   3,213.1ms
window.__timeline()                 dur 3,343   (= 3,213 + pauseAfter 130)
```

`3.50` 은 1차 실측의 초/자(0.1795)로 낸 **모형값**이지 실측이 아니다.
올바른 값은 `ts = −0.15 + 0.434 × (0.15 + 3.343 × 0.85)` = **1,148ms** 이고, 실물은 **1,210ms** —
**62ms(30fps 1.9프레임) 늦다.** 가이드 한도(±20프레임) 안이라 화면에는 영향이 없고,
그래서 막지 않는다. 하지만 **이 회차에서 척도가 틀린 네 번째 자리**이고, 검수 2차가
`C1` 표에서 「sweep 1,210 유지 ✅」로 통과시킨 곳이다.

🟢 대조군: `tick` 2,177 은 **정확하다.** `rel` 4.504(= 4,374 + 130, timed.json 실측 일치),
`W = 0.15 + 4.504 × 0.8 = 3.7532`, `c0 = 0.62` → `−0.15 + 0.62 × 3.7532` = **2,177ms**. 오차 0.
