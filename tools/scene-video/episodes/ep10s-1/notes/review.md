## 1. 작성팀이 먼저 봐 달라고 한 3자리 — **전부 통과**

### ①-1 `squeezed` 가 `ep09s-1/kinds/infoline.js` 와 계열이 겹치는가 → 🟢 **겹치지 않는다. 돌려막기 아님**

작성팀이 *"완전히 다르다고는 말하지 않겠다"* 고 자진 신고한 자리다. **코드 대조 + 스틸 대조**
둘 다 했고, 판정은 **통과**다.

**스틸로 본 것** (`ep09s-1` 21,500ms · `ep10s-1` 23,680ms — 둘 다 각 편 마지막 샷의 완성 상태):

| | `ep09s-1 / infoline` | `ep10s-1 / squeezed` |
|---|---|---|
| 화면 구조 | **SCREEN 프레임** 안에 정보줄 상자, 그 아래 점선 경계 + **CODE 칸 2개**(빗금) + 연결선 2줄 + 강조 밑줄 바 | **띠 하나뿐.** 프레임·경계선·아래 칸·연결선·밑줄이 **전부 없다** |
| 띠 안에 든 것 | **세로 칸 3개**(NAME / TRAIT / JOB) + 한글 값 + 진행 밑줄 | 왼쪽 주민 점에서 뻗은 **굽은 대시 줄 2개** |
| 라벨 배치 | 셋이 **가로로 늘어선다**(x 가 다르다) | 둘이 **세로로 쌓인다**(x 가 같다 — 둘 다 `AX2`) |
| 띠가 생기는 방식 | 처음부터 있고 **왼→오른 순서로 차오른다**(`fill(i)`) | **위아래 경계선에 눌려 생긴다**(`bandTop`/`bandBot` lerp) |
| 회차 고유 장치 | 코드 칸 빗금 흐름 | **`3s` 세로 훑개**가 되풀이 지나간다(`infoline` 에 없음) |
| 글자 종류 | 한글 값(`고집쟁이`)이 띠 안에 있다 | 띠 안에 한글 0자 — 영어 라벨 둘뿐 |

**두 스틸을 나란히 놓으면 같은 그림으로 읽히지 않는다.** 공유하는 것은 「가로로 긴 둥근
사각형」 하나뿐이고, 그건 이 엔진에서 라벨 붙은 축을 그릴 때의 최소 단위라 계열로 세지 않는다.
작성팀의 자진 신고는 **과잉 신고**였다. 고치지 마라.

### ①-2 `sfx.delayMs` 두 값 독립 재계산 → 🟢 **둘 다 맞다.** `at=1` → **둘째 줄** `rel` 사용도 맞다

먼저 **`at` 의 의미를 코드로 확정**했다(전달 착오가 이 자리에서 났으므로):

```js
// render.mjs:110-113
const idx = base + (s.at ?? 0);          // base = 그 샷의 첫 자막이 평탄화 목록에서 몇 번째
const line = timeline.lines[idx];
const at = Math.round((line.t + (s.delayMs ?? 0)) / 1000 * rate);
```

→ `at=1` 은 **그 샷의 둘째 자막**이고 `delayMs` 는 **그 줄 시작**에서의 오프셋이다.
따라서 S1 은 `rel[1] = 3,485ms`(3,235+250), S2 는 `rel[1] = 3,298ms`(3,048+250) 를 쓰는 것이
맞다. **코디네이터가 건넨 「S1[0] 의 3,837」은 첫째 줄 값이고 잘못이다** — 작성팀 지적이 옳다.
같은 실수가 남은 자리는 **없다**(sfx 2개 전부 `at=1`, 둘 다 `rel[1]` 로 풀려 있다).

**S1 `sweep` = 70ms** — 캔버스 폭 `w = 352`(stage 392 − .vis 좌우 20×2, `style.css:46,75`),
`cue(1, 0.20, 0.45)` → `W = 0.20 + 3.485×0.45 = 1.7682초`. `dayX = lerp(10, 342, ease(c1/0.62))`,
이동 폭 332px. ease 역함수를 **이분탐색**으로 풀면:

| 지점 | dayX 진행률 | c1 | 자막 시작 기준 |
|---|---|---|---|
| 왼쪽 주민 `LX=64` | 0.16265 | 0.15850 | **+0.0803초** |
| 오른쪽 주민 `RX=288` | 0.83735 | 0.46150 | **+0.6160초** |

호가 실제로 긁히는 구간이 **0.080~0.616초**이고, `dur 0.58` 짜리 sweep 을 **70ms** 에 놓으면
0.070~0.650 을 덮어 **구간 전체를 포함한다.** 🟡 산술적 최적은 80ms 지만 차이가 **10ms
= 0.3프레임**이라 가이드 한도(±20프레임)의 1.5% 다. **고칠 필요 없다.**
(작성팀 값 0.069/0.628 과 내 값 0.080/0.616 의 차이는 ease 역산 정밀도 차이이고, 결론은 같다.)

**S2 `tick` = 1,384ms** — `cue(1, 0.15, 0.80)` → `W = 0.15 + 3.298×0.80 = 2.7884초`.
`attach = ease(clamp(ck/0.55))` 가 1 이 되는 `ck = 0.55` → `0.55×2.7884 − 0.15 = **1.3836초**`.
**1,384ms 와 완전 일치.** 낱말 자리(19음절/3,048ms = 160.4ms)로 「엿듣는」이 0.962~1.443초이므로
그 안이다. ✅

## 2. 🔴 반려 사유

### 🔴 R-1. S2 `tick` 이 **`ep09s-1 S3` 과 완전히 같은 소리**다 — 효과음 돌려막기

`scene.json` S2 sfx: `kind tick · dur 0.052 · freq 1180`
`episodes/ep09s-1/scene.json` S3 sfx: `kind tick · dur 0.052 · freq 1180`

**`tick` 은 seed 를 안 받는다**(`sfx.mjs` KIT.tick — `dur`·`freq`·`rate` 만으로 파형이
결정된다). 실측:

```
len equal: true 2293
ep09s-1 tick rms 0.05688 | ep10s-1 tick rms 0.05863
두 파형의 진폭 비 = 1.0308 → 차이 dB = 0.26
```

**길이가 같고 파형이 같고 크기가 0.26dB 차이다 — 귀로 구별되지 않는다.**
게다가 **성격까지 같다.** ep09s-1 의 `why` = *"이름표가 표면을 뚫고 **올라와** 머리 위에
**꽂히는** 순간 … **없던 것이 자리에 앉는** 것이라 tick"*.
이 편의 `why` = *"점선 안테나가 위 상자 바닥에 **딱 닿는** 순간 … 가늘게 **뻗은** 것이
**자리를 잡는** 「딱」"*. **아래에서 위로 뻗어 자리를 잡는 사건**이 두 편 연속 같은 소리다.
두 편 사이는 회차 하나뿐이다.

🔴 그리고 작성팀의 대조 기록이 **사실이 아니다**:

> 「현역·아카이브 전 회차의 tick 이 쓰는 freq 는 2100·1980·1900·1760·1660·1650·1510·1420·1380·
> 1250·1080·1050·960·880 이라 **1180 은 어디에도 없다.** dur 도 …만 쓰였고 **0.052 는 처음**이다.」

전 회차 `shots[].sfx[]` 를 기계로 훑은 실측(18건):

```
ep09s-1 S3 tick dur 0.052 freq 1180 gain 0.058 delay 1541   ← 열거에서 통째로 빠졌다
ep08s-2 S1 tick dur 0.062 freq  960
ep06s   S3 tick dur 0.066 freq 1980
ep05s-2 S3 tick dur 0.07  freq 1080
ep04s-1 S3 tick dur 0.055 freq 1250
ep05s-3 S3/S4 tick dur 0.048 freq 1380
ep10s-2 S5 tick dur 0.068 freq 1520
```

`freq 1180` 도 `dur 0.052` 도 **둘 다 이미 쓰였고, 하필 같은 한 줄에서 같이 쓰였다.**
dur 열거에서도 0.048·0.055·0.066·0.068·0.070 다섯이 빠졌다. 대조를 했다면 나올 수 없는 목록이다.

**요구**: `freq` 와 `dur` 을 **둘 다** 바꿔라(하나만 바꾸면 같은 계열로 남는다).
위 18건 실측표에 없는 조합이어야 한다. 바꾼 뒤 `attach` 문턱(0.55)이 그대로면 `delayMs 1,384`
는 유효하다 — **재계산 불필요**(`delayMs` 는 파형이 아니라 cue 창에서 나온 값이다).

### 🔴 R-2. 그 `tick` 이 **피크 천장에 걸린다** — 렌더 로그에 경고가 찍힌다

실제 인자로 `synth()` 를 호출한 결과:

```
⚠️ sfx tick: 피크 천장(0.46)에 걸려 목표 RMS 0.060 → 실효 0.0598 (-0.0dB).
   이 소리만 조용해진다 — gain 을 낮추거나 peakCeil 을 올릴 것.
tick peak 0.4600 rms 0.0586
```

이분탐색으로 잰 **무경고 상한 = `gain 0.05979`**. 씬은 `0.060` 이라 **0.00021 초과**다.

🔴 그리고 `why` 에 적힌 사유가 **방향이 거꾸로**다:

> 「dur 이 기본 0.06 보다 짧아 50ms 창의 에너지가 덜 담기므로 피크 천장(0.46)까지 **여유가 더 있다**」

`synth()` 는 **50ms 창 최대 RMS(`loud`)로 나눠서** 이득을 정한다(`g = gain / loud`).
창에 담기는 에너지가 **적을수록 `loud` 가 작고 → `g` 가 커지고 → `peak × g` 가 천장에 **더
빨리** 걸린다.** 즉 짧을수록 **여유가 줄어든다.** 실제로 걸렸다.

🔑 **같은 자리에서 형제 편이 이미 한 번 잡혔다.** `ep09s-1 S3` 의 `why` 에 그대로 적혀 있다 —
*"🔴 gain 0.060 → 0.058 로 내렸다. 1차본이 「tick 상한 0.065」를 근거로 0.060 을 썼는데 그
0.065 는 기본 옵션의 값이고, 이 조합(dur 0.052 · freq 1180)의 실제 상한 …"*.
**같은 인자를 가져오면서 그때 내린 gain 만 원래대로 되돌린 꼴**이고, 이것이 R-1(돌려막기)의
방증이기도 하다.

**요구**: R-1 대로 `freq`·`dur` 을 바꾼 뒤, **그 새 조합으로 `synth()` 를 직접 호출해**
경고가 안 뜨는 `gain` 을 정하라. 표를 믿지 마라 — 상한은 kind 가 아니라 **인자 조합마다**
다르다.

```bash
node -e "import('./sfx.mjs').then(m=>{const fs=require('fs');
  const sc=JSON.parse(fs.readFileSync('episodes/ep10s-1/scene.json','utf8'));
  for(const sh of sc.shots) for(const s of sh.sfx||[]){console.log(sh.id,s.kind); m.synth(s.kind,s,44100);}})"
```

> 참고 — S1 `sweep`(dur 0.58 · seed 43 · gain 0.066)은 **무경고 상한 0.18435** 라 한참 아래다. 문제 없다.

### 🟡 W-1. S1 `sweep` 의 대조 기록도 틀렸다 (소리 자체는 새것이라 통과)

> 「sweep 이 쓰는 dur 은 0.64·0.62·0.55·0.50·0.47 이고 seed 는 23·61·79(+기본 11)뿐이라,
> **dur 0.58 과 seed 43 은 둘 다 처음 쓰는 값이다.**」

실측(11건): **`ep04s-2 S3` sweep dur 0.58** · **`ep07s-1 S6` sweep seed 43** ·
그 밖에 ep03s 0.70 · ep06s 0.44/seed 29 · ep10s-3 0.60/seed 101 이 열거에서 빠졌다.
**둘 다 처음이 아니다.**

다만 `dur 0.58 + seed 43` **조합**은 처음이고, `sweep` 은 seed 로 잡음이 갈리며 길이도 다르므로
**나오는 소리는 새것이다.** 그래서 반려하지 않는다. 🔴 **그러나 `why` 의 문장은 사실이 아니므로
R-1 을 고칠 때 함께 정정하라.** 사실 아닌 대조 기록이 남으면 다음 회차가 그것을 근거로 삼는다.

### 🟡 W-2. `notes.outro_siblings` 가 현재 파일과 어긋난다

`outro.siblings` 는 **이미 3항목이 채워져 있고**, `check.mjs` 의 「형제 라벨 = 그 편의

세 편의 `siblings` 가 서로 모순되지 않는다. **필드는 옳고 노트만 낡았다.** 노트를 고쳐라.

### 🟡 W-3. `3s` 라벨이 마지막 1초 동안 점선 상자 테두리와 겹친다

`squeezed` 예고 구간에서 띠 전체가 `dy = 44×nk` 만큼 내려가는데 `3s` 라벨은 띠에 붙어 함께
내려가고(`STRIP_Y − 6 + dy`), 위에 열리는 빈 줄(`NY=100, NH=42`)은 **`dy` 를 안 받는다.**
그래서 카드 직전(abs 23,680) 스틸에서 `3s` 글자가 그 상자의 **점선 아래변 위에 얹힌다.**
가독성이 죽지는 않았고(초록 글자 / 회색 점선) 페이오프도 이미 끝난 뒤라 **반려하지 않는다.**
다음에 이 kind 를 손댈 일이 있으면 `NY` 를 6~8px 올리거나 `scanK` 를 `nk` 로 서서히 끄는 쪽이 낫다.

### 🟡 W-4. 영어 blurb 한 문장이 부자연스럽다

> `and the listener's resentment grows the larger of the two.`

한국어는 「듣는 쪽의 원한이 더 크게 쌓이도록 했습니다」다. 뜻은 틀리지 않았지만
`grows the larger of the two` 는 영어로 잘 안 읽힌다. `the listener's resentment grows faster`
쪽이 자연스럽다. **자막(`lines[].en`) 이 아니라 설명란이고, 없는 사실을 더한 것도 아니라
반려 사유가 아니다.**

### 🟡 W-5. (의견 · 미검증 축) 첫 줄 4번 항목

첫 줄 「어제 이 주민이 저 주민한테 잔소리를 퍼부었어요」는 **주어가 주민**이고 **주민이 무언가를
하고 있으며**(잔소리), 어긋남은 둘째 줄에서 온다. 상위 3편의 패턴(거절 55.16% · 반복 52.25% ·
거절 46.52%)과 같은 모양이고, 하위 패턴(주어가 개발자·기능 / 주민이 멈춤 / 주민이 성공)에
해당하지 않는다. **⚠️ 이 4번 축은 아직 검증 전이므로 의견으로만 올린다.**

## 4. 사실관계 — 🟢 통과 (원문에 없는 수치·문자열 0건)

### 4-1. 지워진 표와의 대조 — **대조할 표가 없다**(기획팀 주장 독립 확인)

```
$ f=tools/blog-automation/published/2026-07-21-...-m8-...html
table:0 svg:0 pre:0 img:0 ul:0
```

원본 html 에 `<table>`·`<svg>`·`<pre>`·`<img>`·`<ul>` **전부 0건**. 정규식으로 잘려나간 것이
없으므로 「브리프 밖에서 지어냈는가」를 볼 표 자체가 없다. 기획팀·작성팀의 §0 주장이 맞다.

### 4-2. 원문 본문의 아라비아 숫자 전수 vs 화면·자막

태그를 제거한 본문에서 숫자를 전수로 뽑았다:
`8`(M8) · `7`(M7) · `1단계`~`5단계` · **`3초`** · `0줄` · `0으로`.

| 화면/자막에 뜨는 수 | 값 | 원문 근거 | 판정 |
|---|---|---|---|
| S3 `spec.oneLabel` | `1` | 「"A와 B의 사이"를 **숫자 하나**로 저장할까 했는데」 | 🟢 한글 수사 → 아라비아. 브리프 §6-A #2 가 명시 허용 |
| S4 `spec.readLabel` | `3s` | 「**3초 안에** 읽기에 충분했습니다」 | 🟢 원문에 아라비아로 실재 |
| 자막 L6 `text` | `3초` / `say` 「삼 초」 | 같은 문장 | 🟢 (`say` 가 숫자를 소리대로 푼다 — 규약대로) |
| 제목 | `3초` | 같은 문장 | 🟢 **지어낸 숫자 아님** |

🟢 **`2` 를 안 썼다.** 「방향이 둘」·「1명씩」이 눈앞에 있었지만 원문에 `2` 라는 글자가 없어
도형이 개수를 지게 뒀다(남은 갈래가 둘). 브리프 §6-A 의 「⚠️ 원문에 `2`는 없다」를 지켰다.
🟢 **`10명 → 4명`**(브리프가 「커밋 기록에만 있다」고 경고한 값)을 안 썼다.
🟢 `kinds/*.js` 전체에 **`fillText` 로 박은 수 0건** — 화면의 수는 전부 `spec` 경유다(직접 확인).

### 4-3. 화면 문자열 vs 원문

| 라벨 | 원문 | 판정 |
|---|---|---|
| `CHATTER` | 「대화를 담당하는 코드(**ChatterService**)」 | 🟢 |
| `RELATION` | 「**관계**를 관리하는 별도의 서비스」 | 🟢 ADR-V-10 「코드나 인스펙터에 그대로 있을 법한 말」 |
| `A→B` / `B→A` | 「"A가 B를 어떻게 느끼는가"와 "B가 A를 어떻게 느끼는가"」 | 🟢 원문 그대로 |
| `BEST` / `GRUDGE` | 「"**단짝**"과 "**원한**"을 한 명씩만 표시」 | 🟢 |

자리를 아예 만들지 않았다. 게임 에셋과 대조할 분류 주장이 0건이다.

### 4-4. 자막 7줄 전수 대조

  **표현과 계산의 분리**(S2 의 「두 상자를 실선으로 안 잇는다」로 그림이 짐).

  선분류했고 ②`0` 이 이 편 안에서 「기록이 없다」와 「영향을 안 준다」 두 반대 뜻을 갖게 된다는

- **회차 기본 도형**(두 사람 사이의 굽은 줄)이 네 그림을 관통하고, S1↔S3 의 재사용은

## 9. 길이 · 말투 · 효과음 밀도

### 길이 — 🟢 (실측 인용만 함. 자체 산정식 없음)

`build/timed.json` 이 실측본이므로 **「산정 길이(참고)」 줄은 안 나온다.** 값은 전부 게이트 인용:

| 항목 | 값 | 판정 |
|---|---|---|
| 총 길이 28초 이하 | **26.3초** = 자막 24.9 + 꼬리 1.40 | 🟢 |
| 22.6~28초 권장대역 | 26.3초 | 🟢 |
| 본문 20초 이상 | **20.8초** | 🟢 (여유 0.8초 — 자막을 한 줄이라도 빼면 반대쪽이 켜진다) |
| 예고 3.0초 이하 | **2.9초** | 🟢 |

🔴 **길이를 이유로 아무것도 깎으라고 하지 않는다.** 예고도 첫 3초도 온전하다.
🔴 **`notes.길이` 가 자체 계산식을 적고 있지 않다** — 전부 `check.mjs` 출력 인용이고, 「산정
21.3 → 실측 26.3(+5.0)」은 *산정으로 판정하면 안 된다*는 관측 기록이지 판정 근거가 아니다. 🟢

### 말투 — 🟢

`voice.json` rules 대조: 어미 3연속 **없음**(L4 `-였어요` ↔ L5a `-었어요` 가 2연속, L5b
`-니까요` 가 끊는다) · 담화표지 「근데 / 그래서 / 이제」 3개(7문장에 3개, 「서너 문장에 하나」
대역) · `say` 최장 28자(두 문장으로 쪼갠 L5 포함) · 「삼 초」로 숫자를 소리대로 풂 ·
큰 쉼(600ms+) 0회.
🟡 샷 전환 `pauseAfter` 가 250 이다(rules 6 은 300 권장). 게이트 대상이 아니고 리듬을 해치지
않아 그대로 둔다.

### 효과음 밀도 — 🟢 (배치·개수는 통과, 값만 R-1/R-2)

- **2개 / 26.3초 = 초당 0.076** → 기준 대역(0.06~0.09) 안, 「23초에 1~2개」와도 맞는다. 🟢
- **나레이션이 부르는 사건에만 붙었다.** S1 = 하루가 지나며 쓸려 나감(L2), S2 = 구독이 걸림(L4).
  정적을 메우려고 깐 소리 **0개**이고 **4샷 중 2샷이 무음**이다. 🟢
- `delayMs` 가 0ms 인 자리 없음(70 / 1,384). 🟢
- `why` 둘 다 채워져 있다(내용에 오류가 있어 R-1/R-2/W-1). 🟢/🔴
- 🔑 「지워짐(sweep) ↔ 앉음(tick)」의 짝 구성은 설계로서 **좋다.** R-1 을 고칠 때 **개수나
  배치를 바꾸지 마라** — 바꿀 것은 `tick` 의 인자 세 개뿐이다.

## 11. 작성팀에게 — 되돌림 지시 (최소 범위)

**고칠 곳은 `scene.json` 의 `shots[1].sfx[0]` 하나다.**

1. `freq` 와 `dur` 을 **둘 다** 바꿔 `ep09s-1 S3`(0.052 / 1180)와 갈라라.
   기존 18건 실측 목록: dur `0.04·0.042·0.048·0.05·**0.052**·0.055·0.058·0.062·0.066·0.068·0.07·0.075·0.09`
   / freq `880·960·1050·1080·**1180**·1250·1380·1420·1510·1520·1650·1660·1760·1900·1980·2100`.
2. 새 조합으로 `synth()` 를 **직접 호출해** 경고가 안 뜨는 `gain` 을 정하라(§2 R-2 의 명령줄).
   표에 적힌 「tick 상한 0.065」를 근거로 쓰지 마라 — **그 0.065 는 기본 인자의 값**이다.
3. `sfx[0].why` 에서 세 문장을 정정하라 —
   ①「1180 은 어디에도 없다 / 0.052 는 처음」(거짓) ②「dur 이 짧아 천장까지 여유가 더 있다」
   (방향이 거꾸로 — 짧을수록 여유가 **준다**) ③ S1 `sweep` 의 「dur 0.58·seed 43 둘 다 처음」(거짓, W-1).
4. `notes.outro_siblings` 를 현재 파일 상태에 맞게 고쳐라(W-2).

🔴 **건드리지 말 것**: 자막 7줄 · 제목 · 예고 · `en` · `excluded` · `spec` · `kinds/*.js` 4개 ·
S1 `sweep` 의 `delayMs 70` · S2 `tick` 의 `delayMs 1,384`.
`delayMs` 는 파형이 아니라 **cue 창**에서 나온 값이라 `freq`·`dur`·`gain` 을 바꿔도 유효하다.
`tts.mjs` 를 다시 돌릴 필요도 없다(자막이 안 바뀌므로 `timed.json` 이 그대로 정본이다).
