## 2. 🔴 반려 사유 — S1 `sweep` 이 `ep07s-1 S6` 과 **같은 소리**다

### 실측 (내가 직접 돌렸다)

```
ep10s-1 S1  sweep  dur 0.58  seed 43
ep07s-1 S6  sweep  dur 0.52  seed 43
→ 정규화 파형 상관 = 0.9773
```

전 회차 sweep 10건과 전부 대조한 결과, **0.977 은 압도적 이상치**다
(나머지 아홉은 −0.027 ~ 0.016).

| 상대 | dur/seed | 상관 |
|---|---|---|
| **ep07s-1 S6** | 0.52 / **43** | **0.9773** |
| ep06s S5 | 0.44 / 29 | 0.0164 |
| ep10s-3 S3 | 0.60 / 101 | 0.0149 |
| ep08s-2 S4 | 0.50 / 61 | −0.0270 |
| 나머지 여섯 | — | \|0.003\| 이하 |

### 왜 `dur` 로는 안 갈리는가 — 코드로 확인했다

`sfx.mjs` KIT.sweep 은 잡음 `r = rng(seed)` 를 **샘플 순서대로** 뽑고, 컷오프와 포락선은
둘 다 `k = i/n` 즉 **정규화 위치**의 함수다.
→ seed 가 같으면 **잡음 실현이 글자 그대로 같고**, `dur` 은 같은 모양을 시간축으로
늘일 뿐이다. `dur` 만 옮겨 봤다:

```
seed 43, ep07s-1(0.52) 대비   dur 0.44 → 0.9532   0.50 → 0.9969
                              0.58 → 0.9773   0.70 → 0.8801   0.90 → 0.7596
seed 만 갈면 (dur 0.58 고정)  13→0.019  17→0.015  53→0.025  71→0.015  89→0.016  113→0.010
```

**쓸 수 있는 `dur` 대역 전체에서 0.95 아래로 안 내려간다. seed 를 갈면 한 번에 0.02 다.**

### 이것이 리포의 어느 규칙에 걸리는가

`.claude/agents/scene-writer.md` §3 「🔴 **돌려막기 금지**」 + `scene-reviewer.md` §8
「🔴 앞 회차와 돌려막기가 아닌가 … 같은 kind 를 같은 성격으로 반복하고 있지 않은지」.

그 항의 `latch` 조항이 **판정 척도와 대역까지 못 박아 놨다** —
*「seed 를 안 주면 길이만 잘릴 뿐 같은 잡음이라 회차 셋이 실제로 같은 소리를 내고 있었다
(정규화 상관 0.9993 · 0.9948). seed 를 갈면 0.68~0.79 로 떨어지고 그 대역이 이 합성기의
하한이다.」*

**0.9773 은 그 「같은 소리」 대역이고, 하한(0.68~0.79)보다도 한참 위다.**
바깥 상식이 아니라 **리포가 세운 척도를 sweep 에 그대로 적용한 결과**다.

### 작성팀 `why` 의 어디가 틀렸나

> 「🟢 그래도 **소리는 유일하다** — 갈라내는 것은 값 하나가 아니라 **조합**이기 때문이다.
> … **(0.58, 43) 조합은 리포에 없다.** … 🔑 latch 와 달리 sweep 은 seed 를 실제로 받으므로
> **seed 하나로 확실히 갈린다.**」

- 「조합이 새것이면 소리가 새것이다」 — **거짓이다.** 실측 0.977.
- 마지막 문장은 **방향만 맞고 적용이 거꾸로다.** seed 가 갈면 갈린다는 말은 맞다.
  그런데 이 씬은 **seed 를 안 갈았다**(43 = ep07s-1 과 같다). 갈린다고 적어 놓고
  안 갈린 쪽을 골랐다.
- 검수 W-1 도 같은 논리로 통과시켰다 — 「**나오는 소리는 새것이다.** 그래서 반려하지 않는다」.
  **파형을 안 재고 파라미터 표만 봤다.** 검수는 tick 은 파형을 쟀는데 sweep 은 안 쟀다.

🔑 이 회차가 3차까지 온 원인이 「대조표를 안 세고 단언했다」인데, **바로 그 잘못이
sweep 쪽에 그대로 살아남아 있었다.** 검수·작성 둘 다 tick 만 보고 sweep 은 넘겼다.

### 🟢 요구 — 고칠 것은 **`seed` 한 값**이다

1. `shots[0].sfx[0].seed` 를 **안 쓴 값**으로 갈아라.
   현재 쓰인 sweep seed = `11`(기본 — ep02s·ep03s·ep04s-2·eptest-m11) · `23` · `29` ·
   `43` · `61` · `79` · `101`.
   내가 미리 재 둔 후보(최대 상관 / 무경고 gain 상한):
   `53` → 0.0245 / 0.1877 · `89` → 0.0163 / 0.1765 · `113` → 0.0101 / 0.1785.
   **셋 다 안전하다.** 고른 뒤 **직접 다시 재서** `why` 에 상관값을 적어라.
2. 🔴 **`dur 0.58` 과 `delayMs 70` 은 건드리지 마라.** 포락선이 `sin(πk)` 라
   **seed 를 갈아도 에너지 마루 위치(dur 한복판)와 덮는 구간이 안 바뀐다** —
   「0.069~0.628초의 긁힘 구간을 덮는다」·「마루가 「오늘」에 11ms 오차로 앉는다」는
   근거식이 **그대로 유효하다.** `tts.mjs` 도 다시 돌릴 필요 없다.
3. `gain 0.066` 도 그대로 둬도 된다 — 후보 seed 셋 모두 무경고 상한이 0.176 이상이다.
4. `why` 에서 「소리는 유일하다 / 조합이 갈라낸다」 문단을 **정정**하라.
   남길 문장 = **「sweep 은 seed 가 같으면 dur 로는 안 갈린다(실측 0.977). latch 와 같다.」**
   이 문장이 다음 회차가 인용할 값이다.

### ②`gain 0.055` 가 피크 천장(0.46) 아래인가 — 🟢 **재서 확인. 통과**

씬의 실제 인자로 `synth()` 를 직접 호출했다. **경고가 한 줄도 안 뜬다.**

```
S1 sweep gain 0.066 → peak 0.1647  rms 0.04203
S2 tick  gain 0.055 → peak 0.3783  rms 0.04583      ⚠️ 없음
무경고 상한 (이분탐색 60회)
  tick  0.072 / 2320  = 0.06688      ← 새 조합
  tick  0.052 / 1180  = 0.05979      ← 옛 조합 (검수 값과 일치)
  sweep 0.58  / 43    = 0.18435
```

🟢 **`0.055` 는 상한의 82.2%** — 여유 17.8%. 작성팀이 「보간으로 약 0.061 추정」이라 했는데
실제 상한은 **0.0669** 로 그보다 높다. **추정이 보수적이었을 뿐 방향은 맞았고, 결과는 안전하다.**
🔑 작성팀이 R-2 에서 바로잡은 이론(`gain_max = 0.46 × loud / peak`, dur 이 길수록 `loud` 가
올라 여유가 는다)이 실측으로 확인된다 — 0.052→0.072 로 상한이 0.0598→0.0669 로 **올랐다**.

### ③`squeezed` vs `ep09s-1/kinds/infoline.js` — 🟢 **무혐의. 검수 판정 유지**

두 파일을 직접 읽고 draw 를 항목별로 갈랐다.

| | `infoline` | `squeezed` |
|---|---|---|
| 화면 골격 | SCREEN 프레임 3변 + 점선 분리선 + **코드 칸 2개(빗금)** + 연결선 + 밑줄바(`fillRect`) | **띠 하나뿐.** 프레임·분리선·칸·연결선·밑줄 **전부 없다** |

| 띠가 생기는 원리 | 처음부터 있고 `fill(i)` 로 **차오른다** | `bandTop`/`bandBot` 이 **눌러서 생긴다** |

축을 그릴 때의 최소 단위다. **두 그림의 동사가 다르다** — 저쪽은 「채워져서 사람이 된다」,
이쪽은 「눌려서 둘만 남는다」. 🟢 작성팀 자진 신고는 과잉이었고 검수 판정이 옳다. **고치지 마라.**

ⓘ 관측 하나 — 「가로 띠」는 `ep09s-1` 과 이 편, **두 편째**다. 아직 계열이 아니지만
**세 편째가 나오면 그때는 축을 갈아야 한다.** (규정 아님 · 다음 회차가 근거로 못 쓴다)

## 2-1. 🔴 먼저 척도를 판정한다 — **절대 표본 정렬이 정본이다**

코디네이터가 「두 척도가 갈리니 마스터가 정하라」고 넘긴 항목이다. **정했다.**

같은 인자 쌍을 두 척도로 재 봤다(44.1kHz, `synth()` 직접 호출):

| 대조 쌍 | **절대 표본 정렬** | 정규화 위치 리샘플 |
|---|---|---|
| 완전 동일 `(0.58,43)` vs `(0.58,43)` | 1.0000 | 1.0000 |
| **같은 seed · dur만 다름** `(0.58,43)` vs `(0.52,43)` | **0.9773** | **−0.0190** |
| **같은 seed · dur만 다름** `(0.58,113)` vs `(0.52,113)` | **0.9779** | 0.0254 |
| **다른 seed** · 같은 dur `(0.58,113)` vs `(0.58,11)` | **0.0003** | 0.0205 |

🔴 **정규화 리샘플은 2행(같은 잡음)과 4행(다른 잡음)을 구별하지 못한다** — 둘 다 0.02 언저리다.
가려내야 하는 바로 그 축에서 **분해능이 0** 이다. 절대 정렬은 같은 쌍을 **0.977 vs 0.0003**,
세 자릿수 차이로 가른다.

**근거는 취향이 아니라 코드다** — `sfx.mjs:101-111` 에서 잡음 `r()` 은 **표본 색인 `i` 순서**로
뽑히고, 회차마다 `rate` 가 같다. 따라서 **표본 색인 = 절대 시간**이고, 되풀이되는 실체
(잡음 실현)가 정렬되는 축도 그것이다. `k=i/n` 으로 리샘플하면 그 정렬을 **정의상 깨뜨린다.**

🟢 **1차와 충돌한 적이 없었다.** 내가 44.1kHz 절대 정렬로 재니 **0.9773** — 1차가 적은 값과
소수 넷째 자리까지 같다. 갈린 것은 측정이 아니라 **「정규화」라는 낱말**이었다(§2-6-②).

## 2-3. 🟢 `why` 의 정정이 옳은가 — **옳다. 출처 표기도 그대로 둔다**

- 「조합이 새것이면 소리도 새것」이라는 **거짓 명제가 지워졌고**, 그 자리에 **「sweep 은 seed 가
  같으면 dur 로 안 갈린다(실측 0.977)」** 가 들어갔다. 1차가 남기라고 한 문장 그대로다. 🟢
- 「`113` 이 안 쓰인 값인 것은 **부수 확인일 뿐이고 통과 근거는 상관 0.010**」이라고
  근거의 지위까지 갈아 끼웠다. 🟢 **이것이 이 회차가 남기는 값이다.**
- 재발 방지 규칙(`tick` 은 seed 를 안 받아 (dur,freq) 표 대조가 유효 / `sweep`·`latch` 는
  상관을 재야 함)이 **S1·S2 양쪽 `why` 에 상호 참조로 박혔다.** 🟢 정확하다 —
  `KIT.tick` 에 `seed` 인자가 없음을 코드에서 확인했다.

🟢 **「상관값은 마스터가 잰 것이고 내가 다시 재지 못했다」는 출처 표기는 그대로 둔다.**
셸이 없는 실행 환경에서 **지어내는 대신 출처를 밝힌 것**이고, 값은 방금 내가 독립으로
재서 전부 참임을 확인했다. 🔑 **이것이 옳은 처신이다** — 못 잰 것을 「쟀다」고 쓰는 쪽이
이 파이프라인이 반복해 낸 사고다. 이 판정서(§2-2)가 그 독립 확인 기록을 대신한다.

  세도 그대로 산다.** 1520 이든 1830 이든 2320 과 안 겹친다.
- **렌더 산출물이 안 바뀐다.** `why` 는 화면에 안 나온다.

🔴 §2-6-① 에 박제한다.
