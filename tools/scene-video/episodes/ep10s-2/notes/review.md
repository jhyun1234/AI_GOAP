| S4 | **「계획을」** | 「나무를 하러 가는 것부터 **계획을 스스로 짜는 게** 원래 GOAP이 하는 일」 |

🟢 **없던 말을 지어내지 않았고, 줄이면서 뺐던 원문 어휘를 되돌린 것이 맞다.**

### 미수행 설계를 「만들었다」로 만들지 않았는가 → 🟢

원문은 「처음엔 다른 방식도 **고민했습니다**」이므로 선검사·예약은 **구현된 적이 없다.**
자막이 「검사시키려고 **했거든요**」(미수행)이고, 화면에서 그 상자 둘에 **강조색이 한 번도 안 붙는다**
(전부 `tone('ink')` — `askover.js:113`·`headon.js:62`·`stripout.js:110`). 🟢 설계 의도대로다.
🟡 제목의 「목수한테 **시킨** 재료 검사를 **지웠더니**」는 원문보다 한 뼘 세지만,
**원문 자신이 「선검사도 예약도 다 걷어내고」라고 쓴다** — 원문보다 더 주장하지 않았다. 통과.

## 4. 말과 그림이 같은 순간에 도착하는가

🔴 **인덱스만 보지 않고 다섯 샷의 문턱식을 전부 초로 풀었다.** `t` 로 도는 조건과
다른 cue 에서 파생된 문턱이 있는지부터 훑었다.

```
askover.js:124-125  Math.cos(t·2π/WALK) · Math.sin(t·2π/BOB)   → 위치/흔들림, 문턱 없음
headon.js:49        Math.sin(t·2π/PRESS)                        → 눌림 진폭(hk 에 곱해짐), 문턱 없음
selfgrow.js:116     frac(t / RUN)                               → 점 위치·알파 sin(πu), 문턱 없음
```

🟢 **`frac(t/N) > x` 형태의 시각 문턱이 0건**이고, **다른 cue 의 진행도로 만든 문턱도 0건**이다
(ep02s `tripwire`·ep00i `runmark` 의 사고 형태가 구조적으로 없다).
🔑 `askover` 의 말풍선만 `t` 에 닿는데(출발점이 왕복 위상), **알파·진행은 `cue` 에만 달려 있어**
ep09s-2 의 1차 반려 형태가 안 난다. 코드로 확인했다(`askover.js:151-153` `ak` 만 참조).

## 5. 그림 5종 — 이 회차 소유인가

- **형제 편 파일명 교차 확인**(recurring-defect ④ 방지):
  `ep10s-1/kinds` = `earshot·notrace·oneway·squeezed` / `ep10s-3/kinds` = `gnaw·rollback·selfbuilt·trace`.
  **이름 충돌 0건**, 형태 계열도 안 겹친다.
- **코드 복사 여부**를 24-gram 겹침으로 쟀다(주석·공백 제거 후):
  `ep05s-3/snapin` **11.1%** · `ep05s-3/bothon` 4.1% · `ep01s/shelf` 4.8% · `ep03s/oneasset` 4.5%.
  11.1% 는 import·`fitCanvas`·`fit()` 헬퍼·`roundRect` 같은 **공통 골격 수준**이다. **복사 아님.** 🟢
- **다섯 스틸을 전부 눈으로 봤다**(2,900 / 6,200 / 9,600 / 14,765 / 19,244 / 23,600 / 24,300ms):
  도형이 라벨을 덮는 자리 0건 · 가장자리 잘림 0건 · 흰 글자가 강조색 위에 얹힌 자리 0건.
  `S4` 의 t-구동 점이 `WOOD` 마디 **테두리** 위를 지나가지만 글자와는 안 겹친다.
- **뜻을 나르는가** — `reads` 가 빈말인 샷이 없다. 축 하나(「목표 칸과 그 아래 사슬 — 누가 그리는가」)를
  다섯이 각도만 바꿔 그리고, **①askover(위→아래 = 내가 얹는다) ↔ ④selfgrow(아래→위 = 스스로 짠다)** 가
  값도 라벨도 없이 이 편의 논지를 진다. 스틸에서 실제로 그렇게 읽힌다. 🟢

🟡 **작성팀 대조표에 `ep05s-3` 행이 없다.** `secondcard`(빈 자리 + 카드 꽂힘 + 코드 0 계기)는
`ep05s-3/snapin`(빈 슬롯 셋 + 에셋 카드 꽂힘 + 「.cs 는 한 줄도 추가하지 않았습니다」)과
**계열이 인접하다.** 최종 그림은 다르고(카드 방향 반대 · 마지막에 판이 그어져 선반이 된다)
코드도 안 베꼈으므로 통과이지만, **`0줄` 을 그 편에서 가져다 쓰면서 그 편의 그림을 대조하지 않은 것**은
recurring-defect ④ 그대로다. 대조표에 한 행 추가할 것.

## 6. 효과음 — 배치는 옳고, 변별 근거가 틀렸다

- **밀도**: 26.9초에 **2개**. 기준(23초에 1~2개 · 초당 0.06~0.09)의 딱 안쪽이다. 🟢
- **나레이션이 부르는 사건에만 붙었는가**: thud = 「정면으로 어긋났어요」의 부딪힘,
  tick = 「코드 0줄로 붙었어요」의 꽂힘. **정적을 메우려고 깐 소리 0건.** 가운데 두 샷은 의도적 무음.
  🟢 *"걷어냄에 sweep 을 얹으면 이 편에서 가장 큰 그림을 소리가 설명해 버린다"* 는 판단에 동의한다.
- **`delayMs`**: 위 §1-② 대로 둘 다 정확. `0ms` 로 놓은 소리 없음. 🟢
- **`why`**: 둘 다 kind 선택 사유와 draw 근거가 적혀 있다. 빈 칸 없음. 🟢
- **피크 천장**: §1-② 표. 경고 미발생. 🟢

🟡 🔴 **돌려막기 대조가 불완전하고, 그 결과 두 소리 다 앞 회차와 주파수가 겹친다.**
전 회차 `shots[].sfx[]` 를 뽑아 대조했다(19편):

| 이 편 | 겹치는 앞 회차 | 성격 |
|---|---|---|
| `thud` **freq 168** · dur 0.29 | **`ep04s-3` S1 `thud` freq 168** · dur 0.20 | ep04s-3 `why` = *"이 편에서 처음으로 무언가가 **막힌다**"* — **같은 뜻** |
| `tick` **freq 1520** · dur 0.068 | **`ep05s-1` S1 `tick` freq 1510** · dur 0.042 | ep05s-1 `why` = *"괄호가 **딱 물리는** 순간"* — **같은 뜻** |

🔴 작성팀 `why` 는 *"현역 회차의 thud 가 쓰는 (dur, freq) 는 …**여섯 쌍**"*, *"tick 은 …**열한 쌍**"*
이라고 열거했는데, **실제 thud 는 11개 · tick 은 14개**이고 **빠뜨린 것 안에 위 둘이 정확히 들어 있다.**
즉 「어디에도 없다」는 결론의 근거가 무효다.
🔑 **(dur, freq) 쌍 자체는 여전히 유일**하고 dur 차이(+45% / +62%)가 감쇠를 눈에 띄게 바꾸므로
**반려하지 않는다.** 다만 한 글자짜리 수정으로 겹침을 0 으로 만들 수 있으므로 정정 요구로 낸다
(→ 🟡-2). 지침의 🔴 「같은 kind 를 같은 성격으로」는 kind 가 6종뿐인 팔레트에서 완전 배제가 불가능하니
**주파수만이라도 갈라 두는 것**이 실행 가능한 최선이다.

1. **원문에 없는 수치·주장이 영어에만 섞였는가 → 없다.** 숫자는 `2nd`·`0` 둘뿐이고 한국어와 같다.
2. 🔴 **가정법이 완료형이 되지 않았는가 → 안 됐다. 이 회차의 가장 중요한 자리다.**
   원문이 「처음엔 다른 방식도 **고민했습니다**」(미수행)인데 `en` 이 **`My plan was to make him check`**
   로 옮겼다. `He checked` / `the carpenter would check and reserve` 처럼 **한 일로 만들지 않았다.**
   🔑 `everyone loitered` 형 사고의 정확한 반대다. 🟢
3. 🔴 **이름이 로마자가 아니라 뜻으로 옮겨졌는가 → 그렇다.** `목수` → **`the carpenter`**(ADR-V-19 준수).
   로마자 표기(`Moksu` 등) 0건. 화면의 한국어 문자열도 `목수` 하나뿐이다.
4. **`say` 를 번역하지 않았는가 → 안 했다.** `en` 은 `text` 를 따른다
   (`text` 「2번째/0줄」 → `2nd`/`0 lines`. `say` 「두 번째/영 줄」을 옮겼다면 `the second`/`zero` 가 됐을 것).
5. **직역으로 읽히는가 → 아니다.** `ran head-on into` · `ripped both out` · `worked out the whole plan
   himself` · `getting out of its way` 는 전부 관용 어순이다. 한국어 어순을 따라간 자리가 없다.
   🟡 3번의 `the planner this game already had` 는 한국어 「게임 두뇌」와 은유가 다르지만,
   **원문이 「이 게임의 두뇌인 GOAP」로 이미 있는 것으로 쓴다**는 사실을 정확히 진다. 통과.
   🟡 5번의 `the whole plan` 의 `whole` 은 원문 「계획을」에 없는 강조다. 아주 약하고 사실을
   부풀리지 않으므로 통과하되 기록해 둔다.
6. **`youtube.en.title` = 98자**(상한 100) 🟢 · **`youtube.en` 에 `tags` 칸 없음** 🟢
   (키는 `_`·`title`·`blurb` 셋뿐). `en.blurb` 안의 `#Unity` 등은 설명문 해시태그이지 태그 칸이 아니다.

### 2. 중점 ③ 아웃트로 카드 산수 — 🟢 페이오프 안전 / 🔴 사실 오류 1

**ⓐ S5 페이오프(CODE 0) — 카드와 무관하다.** S5 는 31,067 에 끝나고 카드는 33,816 이라

**ⓑ 미리보기(nextpeek) — 카드 전에 완성된다.**
`peekCue 0`, `cue(0, 0.15, 0.42)` → 창 W = 0.15 + 2.932 × 0.42 = **1.381초**,
진행도 1.0 시각 = 1.0 × W − lead = **+1,231ms** → 절대 **32,298ms**. 카드까지 **1,518ms 여유**.
집 루프가 실제로 화면에 드는 것(`ak ≥ 0.55`)은 +약 600ms → **31,666ms**부터라
**카드 전 약 2.15초 = 0.5초 루프 4바퀴**가 보인다. 스틸 `33.7s.png`(카드 116ms 전)에
벽이 올라간 집 · 빈 말풍선 · `AUTO BUILD` 가 실제로 보인다. ✅

**ⓒ 🔴 그런데 `linkCue 1` 이음 바는 한 프레임도 안 나온다 — 주석과 노트가 틀렸다.**
`nextpeek.js` 주석은 *"카드가 덮기 전에 끝난다(span 0.20)"* 라고 적혀 있는데,
같은 파일의 코드는 `cue(spec.linkCue ?? 1, 0.15, 0.14)` 로 **0.14** 이고,
실측을 넣으면 **어느 값으로도 안 된다**:

- 소개 줄이 시작하는 시각 = 33,999ms인데 **카드는 그보다 183ms 먼저인 33,816ms에 뜬다.**
  즉 **소개 자막 구간 전체가 카드 밑**이다.
- 바가 그려지기 시작하는 시각(lead 0.15) = 33,849ms → **카드가 이미 떠 있다.**
  완성은 33,999 + 2,467 × 0.14 = **34,344ms** = 카드보다 **528ms 늦다.**

작성팀이 쓴 식 자체는 맞다(`카드 = 자막 시작 + rel + 0.35 − 3.0`). 틀린 것은 **대입값**이다 —
3차 감량으로 소개 줄이 20 → 14 발화자가 되면서 `rel` 이 **2.467초**가 됐고,
그 식에 넣으면 **−0.183초(음수)** 가 나온다. 작성팀은 `rel` 3.3초를 가정하고 0.14 를 골랐다.

### 3. 중점 ④ S5 `secondcard` 개정 — 🟢 cue 산수 성립, 손검산 재현됨

S5 `rel` = 2,831 + 130 = **2.961초**(실측). `secondcard.js:44,53` 의 창 두 개로 풀었다.

**옛 span 0.06 으로 자막 시작 직후 선반이 다 그어졌을 것**이다. 게이트가 못 잡는 종류가 맞다.

  다른 cue 에서 파생된 문턱(`rk > 0.7` 류) 0건 — 전부 같은 자막의 앞뒤 구간 분할이다.
