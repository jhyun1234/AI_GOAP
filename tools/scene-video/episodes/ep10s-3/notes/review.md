## 3. 작성팀이 스스로 지목한 네 자리 — 독립 재계산

`cue(i, lead, span)` 은 `a = l.t − lead`, `b = l.t + l.dur × span` 이고 **`l.dur` = `s.rel[i].dur` = wav dur + `pauseAfter`**
(`engine.js:163 · 169 · 292`). 아래 산수는 전부 이 정의로 다시 풀었다.

### 3-1. S3 `sweep` `delayMs` 1240 — **맞다 (독립 재현: 1,237ms)**

- 실측 `rel` = 3357 + 130 = **3.487s** · `cue(0, 0.15, 0.8)` → `W = 0.15 + 3.487×0.8 = 2.9396s`
- `rollback.js:83` `roll = ease(clamp((d0 − 0.35)/0.45))`.
  smoothstep 역함수: `3x²−2x³ = 0.18` → **x = 0.2707**(이분탐색. 0.26 은 0.1676, 0.27 은 0.1793)
  → `d0 = 0.35 + 0.45×0.2707 = 0.4718`
- 절대 시각 = `0.4718 × 2.9396 − 0.15` = **1.2369s → 1,237ms**. 설정값 1,240 과 **3ms(0.09프레임) 차**.
- 어절 대조(`dur` 3,357ms · spoken 19자 = 0.1767s/자): 1.237s 는 **「건설도」 한복판**,
  0.6초 지속음이 「건설도 + 자동」을 덮는다. 걷히는 것이 「자율 건설 · 자동 배정」이므로 맞다.

### 3-2. S3 `latch` `delayMs` 2030 — **맞다 (독립 재현: 2,029ms)**

- 실측 `rel` = 3054 + 250 = **3.304s** · `cue(1, 0.15, 0.8)` → `W = 2.7932s`
- `rollback.js:85` `run = ease(clamp((r1 − 0.24)/0.54))` = 1 ⟺ `r1 = 0.78`
- 절대 시각 = `0.78 × 2.7932 − 0.15` = **2.0287s → 2,029ms**. 설정값 2,030 과 **1ms 차**.
- 그 순간이 실제로 사건인지 확인: `fill = ease(clamp((run − 0.86)/0.14))` 이 `run=1` 에서 1 →
  **캡슐이 집에 닿아 빗금이 차는 바로 그 프레임**. 스틸 `17760ms` 로 눈으로도 확인(집 채워짐).
- 어절 대조(`dur` 3,054ms · 17자): 2.029s = **「부탁해야만」의 66% 지점**. 배타 어미가 닫히기 직전.

### 3-3. S2 `split` 0.42 → **0.55 — 정정이 맞다 (독립 재현: 0.546)**

- 🔴 **분모는 `rel`(4,314ms)이 맞다.** `dur`(4,064) 이 아니다 — `buildTimeline` 이
  `rec.dur = durOf(...) + pauseAfter` 를 넣고 `rel` 이 그 값을 그대로 쓰므로(`engine.js:163,169`),
  `cue()` 안의 `l.dur` 은 `rel` 이다. 작성팀 판단 정확.
- `W = 0.15 + 4.314 × 0.85 = 3.8169s`
- 경계 시각은 **`dur`(4,064ms)** 로 잰다(pause 는 말 뒤의 침묵). `say` 에서 구두점·공백을 뺀
  spoken 21자 중 「존재」 앞 = 방금(2)+만든(2)+부탁(2)+시스템의(4) = **10자**
  → `10/21 × 4.064 = 1.9352s`
- `c0 = (1.9352 + 0.15) / 3.8169 = **0.5463** → 0.55`. ✅
- 결과 검산(`gnaw.js:84,128`): `gk` 가 0 을 벗어나는 순간이 곧 `c0 = 0.55` 이므로 파먹힘이
  **「존재」의 첫 음절과 같은 프레임**에 시작한다. 완전히 먹히는 지점(모든 segment `eaten ≥ 1`,
  `gk = 0.916` → `c0 = 0.920`)은 자막 시작 **+3.362s** 로 발화(4.064s) **안**에서 끝난다.
- 스틸 대조: `9515ms`(= 경계) 에서 레일이 온전하고, `10900ms` 에서 거의 다 먹혀 있다. ✅

### 3-4. `trace.payCue` span 0.10 → **0.06 — 검산 통과 (여유 242ms 정확)**

- 카드 시각(샷 기준) = `(3848 + 2651 + 350) − 2600` = **+4,249ms** ✅
- **본 페이오프**: `c0 = cue(0, 0.15, 0.75)` → `W = 3.036s`.
  `chain = ease(clamp((c0−0.30)/0.40))` = 1 ⟺ `c0 = 0.70` → `0.70×3.036 − 0.15` = **+1,975ms**.
  → **여유 = 4,249 − 1,975 = 2,274ms.** 작성팀 주장 2.274초와 **일치**.
  (하위 요소도 전부 그 앞에 끝난다: 집 +791ms · 캡슐 +1,368ms · 목수 고리 +1,708ms · 사슬 끝점 +1,878ms)
- **예고 그림**: `c1 = cue(1, 0.45, span)`. `b = 3.848 + 2.651×span`.
  - span 0.10 → b = 4.1131s → 여유 **136ms** (4.1프레임)
  - span 0.06 → b = 4.0071s → 여유 **242ms** (7.3프레임) ✅ 주장과 일치
- 🔴 **확인 사살(스틸)**: 카드 직전 프레임 `23600ms` 을 뽑아 눈으로 봤다 —
  집 두 채 · 왼쪽 빈 윤곽 셋 · 오른쪽 채워진 사슬 셋 · `AUTO`/`REQUEST` 라벨 · 예고 트랙
  (`REWARD` 캡슐 + 목수 표식, 간격 불변) 이 **전부 완성된 채로 보인다.**
  `23700ms` 은 카드가 덮은 상태. **ep08s-3 형 사고 없음.**

### 3-5. 🟡 「화면에 아라비아 숫자 0개」 — **문제 아니다**

- 이 편 몫의 원문에 아라비아 숫자로 실재하는 수가 **하나도 없다**(`세 군데`·`세 가지` 는 한글 수사,
  `주민이 넷뿐인` 은 예고 문단 소속). grep 으로 재확인했다.
- 규격 어디에도 「화면에 숫자가 있어야 한다」는 조항이 없다. `제목 후킹 (수치)` 는 **제목만** 보고
  이미 `3` 으로 통과했다.
- 검수 지침이 못박은 대로 **없는 수치를 넣으라고 요구하지 않는다.** `수치_정직성` 이 열거한
  「만들지 않은 것」 목록(줄 수 · 시간 · 확률 · 집/주민 개수 · 커밋 기록의 `10→4`)을 `spec`·`lines`
  전수와 대조했고 **한 건도 새어 들지 않았다.**
- 화면 밀도는 라벨 다섯(`AUTO BUILD`·`AUTO ASSIGN`·`AUTO`·`REQUEST`·`REWARD`)과
  네 그림의 연속 운동이 진다. 정적 구간 실측 최대 **1.4s**(상한 3s)로 여유가 크다.
- 🔑 오히려 **제목 밖에서 `3` 을 주장하지 않은 것이 옳다** — 이 편은 세 군데 중 **한 군데**만
  다루므로, 화면에 `3` 을 그리면 화면이 보여주지 않는 것을 주장하게 된다.

## 7. 🟡 정정 권고 (전부 반려 사유 아님)

1. **`youtube.en.title` 의 `1 of 3` 이 회차 번호로 오독될 수 있다.**
   `I deleted a handy feature on purpose — 1 of 3 things I undid · Unity GOAP Devlog #10-3 #shorts`
   — 같은 제목 안에 `#10-3` 이 있고 `en.blurb` 에 `Part 3 of 3` 이 있어, `1 of 3` 이 「3부작 중 1편」으로
   읽힐 여지가 있다. **`one of the 3 things I undid` 처럼 풀어 쓰기를 권한다**
   (게이트는 한국어 제목만 보므로 숫자 손실 없음).

2. **`youtube.blurb` / `en.blurb` 에 형제 편으로 가는 길이 없다.**
   현재 꼬리는 `(같은 글에서 나온 3편 중 3편)` 뿐이다. 승인 선례 `ep09s-2` 는
   `(… 2편 중 2편 — … 이야기는 9-1편)`, 형제 `ep10s-1` 도 10-2·10-3 을 본문에 적었다.
   **이 편은 3편 중 마지막이라 back-link 가 가장 필요한 자리다.** 한 구절 추가를 권한다.
   ⚠️ 반려로 올리지 않은 이유: `outro.siblings` 가 채워져 **아웃트로 카드가 10-1·10-2 제목을
   실제로 띄운다**(스틸 `23700ms` 로 확인). 길이 아예 없는 상태는 아니다.

3. **`notes.다음_편_예고` 와 `writer.md §7` 의 「`outro.siblings` 는 빈 배열로 두었다」가 낡았다.**
   실제 `scene.json` 에는 3개가 차 있다(코디네이터가 채움). 문서만 갱신하면 된다.
   (같은 형태의 낡은 칸이 ep08s-2·ep09s-2 에서도 났다.)

4. **`writer.md §5-4 ①「반투명 흰색을 강조색 위에 얹지 않았다」는 완전히 참이 아니다.**
   하이라이트는 고쳤지만 **목수 고리는 여전히 반투명 흰색으로 강조색 레일 위에 그려진다.**
   `rollback.js:164` `ringA = clamp(rail*2) × (0.45 + 0.55×near)` → `near = 0` 일 때 α = 0.45.
   실측(캔버스 `getImageData`, `t = 17,760ms`): **`rgb(115,255,189)` 픽셀 98개**
   (= 흰색 α0.451 위에 `#00FF88`). 팔레트 게이트는 이 색을 hue 152 로 읽어 **구조적으로 통과시킨다.**
   ⚠️ 크기가 970×846 중 **98px**(0.012%)이고 글자를 훑는 자리가 아니라 시각적 손상은 없다 —
   그래서 반려하지 않는다. **고칠 것은 그림이 아니라 노트의 주장이다**(또는 고리를 α 1.0 로
   그리고 밝기를 `near` 로만 흔들면 원천 해소된다).

5. **`rollback` 의 접히는 칸에서 라벨이 상자 밖으로 흘러넘친다.**
   `rollback.js:118-123` — `bw` 가 줄어드는 동안 폰트는 `min 8` 에서 멈추므로,
   `bw` 가 34~60 구간일 때 `AUTO BUILD` 가 테두리 좌우로 삐져나온다.
   스틸 `13500ms` 에서 육안 확인. 지속 시간은 약 **0.16초(4.7프레임)**이고 그때 알파가
   0.65→0.29 로 빠지는 중이라 눈에 크게 걸리지 않는다.
   → `ctx.save(); roundRect(...); ctx.clip();` 한 줄이면 잘린다. **다음 회차부터 적용 권고.**

6. **형제 편 `ep10s-1` 도 `sweep` 을 「지워지는 소리」로 쓴다** (`S1 sweep dur 0.58 seed 43`,
   `why` = 「통째로 **쓸려 나가는** 소리」). 이 편의 `sweep` 은 「걷혀 나가는」이라 **성격이 겹친다.**
   파라미터는 다르고(0.60/101 vs 0.58/43) 화면 사건도 다르며(경계선 통과 vs 호 되감김),
   여기서 sweep 말고 맞는 kind 가 없어 **반려하지 않는다.**
   다만 `writer.md §8` 의 전 회차 대조에 **형제 편 행이 없다** — 이것이 반복 결함 ④의 형태다.
   다음부터 대조표에 형제 편을 넣을 것.

**의견(미검증 축 — 등급 아님)**: 첫 줄의 주어가 「집」이라 상위 3편의 공통 축(주민이 거스르거나
고집한다)과는 멀다. 작성팀도 이를 인지하고 **그림 쪽으로 옮겼다**(S1 에서 주민의 요청 캡슐이
부풀었다 도로 꺼진다 — 스틸 `6000ms` 로 확인). 이 축은 15편을 본 뒤 만든 미검증 분류이므로
반려 근거로 쓰지 않았고, 관측 대상으로만 남긴다.

  가운데(S1 두 줄→한 줄 · S4 −2자)이고, 인트로 4.6 / 훅 4.2 / 예고 4.9 / 소개 2.5 는 규격값이다.
- **37.0 은 구조의 산수다**: 예고 상한이 3.0 → 5.0 으로 열리면서(ADR-V25-10 2차 개정) 아웃트로
  샷이 7.7초가 됐다. 인트로 4.6 + 훅 4.2 + 본문 20.6 + 아웃트로 7.7 = 37.1(꼬리 포함 37.0).
  권장대역에 넣으려면 **본문에서 2초를 더 덜어야** 하는데 본문은 이미 20.6(대역 중앙)이고,
  더 덜면 자막을 지우는 일이 된다 — 그건 하지 않는 것이 규율이다. **경고를 수용한다.**

### 11. 예고 4.9초가 상한 5.0 에 붙어 있는 것 — 위험 낮음 (판단 기록)

1. **게이트가 warn 이다** — `check.mjs:321` 의 `add(..., 'warn')`. 넘겨도 **fail 이 아니다.**
2. **재합성해도 값이 안 바뀐다** — `tts.mjs` 는 **문장 내용으로 캐시를 찾아 재사용한다**
   (`tts.mjs:85` 「같은 내용의 파일이 어느 인덱스에 있든 찾아서 재사용한다」). 예고 줄의
   `say` 를 안 바꾸는 한 wav 가 그대로 쓰이므로 4,877ms 는 고정값이다.
3. 만약 캐시가 없는 기계에서 재합성돼 5.0 을 넘으면, **줄일 곳은 예고가 아니다**
   (ADR-V25-9 가 못박은 자리). 그때는 경고를 그대로 받는 것이 정답이다.
→ **여유 123ms 가 빡빡한 것은 사실이나, 그 빡빡함이 만드는 실패 경로가 없다.**
