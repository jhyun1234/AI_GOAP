## 4. `split 0.55` · `payCue span 0.06` — 엔진 코드를 열어 직접 검산

🔴 **분모 논쟁부터 코드로 끝냈다.** `engine.js:163` 이 `dur = durOf(...) + (l.pauseAfter ?? 0)` 이고
`engine.js:169` 가 `rel = ls.map(l => ({ t: …, dur: l.dur / 1000 }))` 다. `cue()`(engine.js:292)의
`l` 은 `s.rel[i]` 이므로 **`l.dur` 은 `rel`(= wav + pauseAfter)이 맞다.** 작성팀·검수 판단 정확.

`timed.json` 실측 wav: S1 3449·3401 / S2 **4064** / S3 3357·3054 / S4 3718·2651.

**ⓐ S2 `split` 0.55** — `gnaw.js:81-84` 확인(`cue(0,0.15,0.85)`, `rk=c0/split`, `gk=(c0−split)/(1−split)`)
- `rel` = 4064 + 250 = 4.314s → `W = 0.15 + 4.314×0.85 = 3.8169s`
- 경계는 **`dur` 4.064s** 로 잰다(pause 는 말 뒤 침묵). spoken 21자, 「존재」 앞이 10자
  (방금2+만든2+부탁2+시스템의4) → `10/21 × 4.064 = 1.9352s`
- `c0 = (1.9352 + 0.15) / 3.8169 = **0.5463** → 0.55` ✅ 자진 정정이 옳다.
  (분모를 `dur` 로 잘못 잡으면 0.58 이 나온다 — 값이 실제로 갈리는 자리다.)

**ⓑ S3 `sweep` delayMs 1240** — `rollback.js:83` `roll = ease(clamp((d0−0.35)/0.45))`
- `rel` = 3357+130 = 3.487s → `W = 2.9396s`. smoothstep 역산 `3x²−2x³ = 0.18` → x ≈ 0.2707
  → `d0 = 0.4718` → `0.4718 × 2.9396 − 0.15 = **1.237s**`. 설정 1,240 과 **3ms(0.09프레임)** 차 ✅

**ⓒ S3 `latch` delayMs 2030** — `rollback.js:85` `run = ease(clamp((r1−0.24)/0.54))` = 1 ⟺ r1 = 0.78
- `rel` = 3054+250 = 3.304s → `W = 2.7932s` → `0.78 × 2.7932 − 0.15 = **2.029s**`. 설정과 1ms 차 ✅
- 그 프레임이 실제로 사건인지도 코드로 확인: `rollback.js:209` `fill = ease(clamp((run−0.86)/0.14))`

세로 사슬.** 두 파일을 열어 코드로 대조했고, **네 항목이 전부 성립한다.**

| 축 | `selfgrow` (ep10s-2) | `trace` (ep10s-3) | 갈림 |
|---|---|---|---|
| 방향 | `nodeY = h − 46 − i×62` — i=0 이 맨 아래, **아래 → 위로 돋음** | `y1 = lerp(SLOT.vill 122, hTop, …)` — **위 → 아래로 채워짐** | ✅ 정반대 |
| 시제 | `spec.chain` 라벨(CHOP·WOOD·HOUSE) = 앞으로 실행할 **계획** | 주민·요청·목수 = 이미 지나온 **이력** | ✅ |
| 모양 | 마디가 전부 **같은 둥근 사각 130×30, 전부 강조색** | 원 r7(흰) · 캡슐 66×24(강조) · 고리 r12+점선 r19(흰) — **셋 다 다름** | ✅ |
| 대조 | 사슬 **하나뿐** + 상단에 폭 전체를 쓰는 목표 칸(글로우) | **옆에 빈 윤곽 사슬이 하나 더 있는 것이 그림의 본체** + 똑같은 집 두 채 | ✅ |

추가로 `selfgrow` 에만 `setShadow/GLOW` 가 있고 `trace` 에는 글로우가 없다. `trace` 에만
`hatch()` 로 채워지는 집 두 채와 가로 삯 트랙이 있다. **돌려막기 아님.** ✅

**ⓒ `ep10s-1` 과의 겹침** — 네 kind 머리주석을 전부 읽었다. `notrace` 가 선언한 그 편의 기본 도형은
「**두 사람 사이에 놓인 굽은 줄 하나**」이고 `earshot`(두 상자가 끝내 실선으로 안 이어짐) ·
`oneway`(줄이 갈려 한쪽만 굵어짐) · `squeezed`(여섯 갈래를 한 줄 높이로 누름)가 그 변주다.
→ 이 편에는 **사람과 사람을 잇는 줄이 없고, 값이 굵기로 지는 자리가 없고, 집이 없다**
(`hatch` 가 ep10s-3 전용인 것이 그 기계적 증거다). ✅

**ⓓ 이 회차의 강조색 규율** — `tone()` 사용을 세어 확인했다. 네 파일 모두 accent/ink/sub/track 만
쓰고 임의 색이 없다. `check.mjs` 의 3색 팔레트도 위반 0.

## 7. 🔴 넘긴 채 통과시킨 항목 — **다음 회차가 선례로 인용할 수 없다**

셋 다 **렌더 산출물에는 영향이 0** 이고, 셋 다 **「고쳤다/안 했다」는 자기보고가 실제와 어긋난** 같은 부류다.
검수는 이 중 하나(③)만 잡았다.

**① 🔴 `sfx[1].why` 의 전 회차 latch seed 명단 3건이 틀렸다** (§3-5).
ep04s-2=41 · ep05s-2=67 · ep05s-3=37 인데 「기본 7」로 적혀 있다.
결론(103 미사용)은 내가 기계로 확인해 참이고 렌더 영향 0 이라 반려하지 않았다.
🔴 **박제** — 다음 회차는 **전 회차 파라미터 명단을 `why` 에 손으로 옮겨 적지 마라.**
적어야 한다면 그 자리에서 스크립트로 뽑은 출력을 그대로 붙이고, 「다시 세었다」는 문장은
그 출력을 첨부할 때만 쓴다. **「이건 ep10s-3 도 그랬다」는 통과 근거가 되지 못한다.**

**② 🟡 `trace.js` 머리주석(24행)이 `span 0.10` 이라고 말한다 — 실제 코드는 `0.06` 이다.**
정정본은 70~72행 인라인 주석에 있고 46줄 아래다. 머리만 읽는 사람은 틀린 값을 얻는다.
(같은 주석에 「242프레임 아닌 242ms」라는 깨진 문장도 남아 있다.)
🔴 **박제** — **값을 고치면 그 값을 말하는 주석을 같은 커밋에서 전부 grep 해서 고친다.**
인라인에만 적고 머리주석을 남겨 두는 것은 정정이 아니라 모순 문서를 하나 더 만드는 것이다.

**③ 🟡 `rollback.js:173` 의 목수 고리가 반투명 흰색(α 0.45)으로 강조색 레일 위에 얹힌다.**
검수 실측 `rgb(115,255,189)` 98px(970×846 중 **0.012%**), 팔레트 게이트는 hue 152 로 읽어
**구조적으로 통과시킨다.** 글자를 훑는 자리가 아니고 면적이 미미해 반려하지 않았다.
작성팀은 코드가 아니라 `writer.md` 의 주장을 고쳤다 — **이 판정에서는 그 선택이 옳다**
(렌더된 결과를 안 건드리는 쪽이 위험이 작다).
🔴 **박제** — 다음 회차는 **고리를 α 1.0 으로 그리고 밝기를 `near` 로만 흔들어 원천 해소하라.**
「팔레트 게이트가 통과시켰다」는 통과 근거가 아니다(ep02s 판정의 「규정 없음은 통과 근거가
아니다」와 같은 잣대). **0.012% 라서 넘긴 것이지 옳아서 넘긴 것이 아니다.**

🟢 넘기지 **않은** 것: 정적 구간(최대 1.4s, 상한 3s) — 이 편은 ep00s 형 예외를 쓰지 않았다.
