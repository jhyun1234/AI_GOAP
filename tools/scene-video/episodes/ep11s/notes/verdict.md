## 3. 🔴 `premise.js` 글자 복제 — 프레임을 직접 뽑았다

검수 보고를 근거로 삼지 않고 **엔진을 직접 띄워 6개 시각의 프레임과 캔버스 픽셀**을 받았다
(12.9s / 13.15s / 13.65s / 14.4s / 15.4s / 16.0s. S2[1] 시작 = 12.744s).

**① 틈이 실제로 열린다** (판 윗변 y=190 · 아랫변 y=268 의 밝은 런):

| 시각 | y=190 런 | 틈 |
|---|---|---|
| 12,900ms | `[27.9, 323.7]` 단일 | **0px** (off≈0, 이음매 붙음 — 정상) |
| 13,150ms | `[24.7,172.4]` `[179.3,327.0]` | **6.9px** |
| 13,650ms 이후 | `[18.1,165.8]` `[185.8,333.5]` | **20.0px = 2×off** |

**② 글자가 복제되지 않았다 — 런 개수와 좌표로 증명.**
인용문 행(y=246)의 밝은 런을 벌어지기 전(12,900ms)과 후(13,650ms)로 세었다:

```
전 (off≈0) : 102.7 110.3 131.0 149.1 168.4 | 181.8 206.1 210.1 216.6 244.9 251.1   → 11개
후 (off=10): 92.9 100.5 121.2 139.3 158.6  | 192.0 215.9 219.9 226.4 254.7 260.9   → 11개
             (왼쪽 5개 전부 정확히 −10)      (오른쪽 6개 전부 정확히 +10)
```

**개수가 11 → 11 로 같고, 왼쪽은 −off · 오른쪽은 +off 로 정확히 한 번씩 옮겨졌다.**
복제된 런도, 사라진 런도 없다. 금 자리(≈176)는 168.4 에서 끝난 덩이와 181.8 에서 시작하는
덩이 **사이의 공백**에 떨어졌다 — `measureText` 로 낱말 사이를 잡았다는 주장이 참이다.

**③ 눈으로도 봤다.** 14,400ms 프레임에서 「**쫓아가서**」와 「**건네준다**」가 각각 온전한
덩이로 벌어지고 「 」 괄호도 살아 있다. 「서」 복제 없음.

**④ 균열이 흰 판을 침범하지 않는다.** 강조색 픽셀은 전 시각에서 `[178.2, 181.1]` 등
**틈(165.8~185.8) 안쪽에만** 있다. **혼합 픽셀 4행 × 6시각 전부 0개.**
대수로도 성립한다 — 확장폭 `min(4.2, 0.42·off)+1.5` < 틈 반폭 `off` 이고 `crackA` 가
`off ≤ 3` 에서 0 이라 발동 구간 전체에서 참이다.

🔑 작성팀이 *"이번에 틀린 것이 바로 그 손으로 푼 좌표"* 라고 한 자리다. 그래서 산수를
믿지 않고 **픽셀을 받았다.** 코드도 읽어 클립 구간이 `x < crackX` / `x ≥ crackX` 로
정확히 분할됨을 확인했다(`premise.js:190-199`).

**같은 계층의 반려 사유 B(강조색 빗금이 강조색 라벨을 훑음)도 프레임으로 봤다** —
`chase.js` `REWARD`(2,000ms) · `settle.js` 위 `DEBT`(21,450ms) · 아래 빚 카드 `DEBT` 셋 다
**완전히 읽힌다.** 빗금이 테두리 밖 점선 후광으로 나가 글자를 지나가지 않는다.

## 6. sfx — 코드·전수·`delayMs`·파형을 전부 독립 재계산

**① 「`rng` 를 안 부르는 kind 를 골랐다」는 주장이 코드에서 참인가 — 참이다.**
`sfx.mjs` 에서 `rng(` 를 부르는 곳은 **딱 두 줄**이다: **74행 `latch`** · **102행 `sweep`**.
`tick`(50-54) · `drop`(114-124) 은 `rng` 도 `seed` 도 안 받는다.
→ `(dur, freq)` · `(dur, from, to)` 가 파형을 완전히 결정한다. **파라미터 대조 = 파형 대조**가 성립한다.

**② 그래도 파형을 직접 쟀다 — 절대 표본 정렬 상관**(`ep10s-1` 반려 척도 그대로):

```
drop  ep11s(0.50/640/84)  vs 기존 7건 : 최대 |r| = 0.0255  (ep08s-1)
tick  ep11s(0.044/2540)   vs 기존 17건: 최대 |r| = 0.2682  (ep00i 0.04/2100)
```

`ep10s-1` 이 반려된 값이 **0.977** 이었다. 두 소리 다 그 근처가 아니다 — **진짜로 갈렸다.**

**③ 전수 — 내가 다시 셌다.** `episodes/**/scene.json`(`_archive` 포함, 23개 파일) sfx **73건**
= drop **8** + tick **19** + 기타 46. 이 편의 2건을 빼면 drop 7 · tick 18 로
작성팀 표와 맞는다(§7-a 참조). **`(0.50, 640, 84)` 도 `(0.044, 2540)` 도 기존 목록에 없다.**

**④ `delayMs` 독립 재계산** — `timed.json` 으로 타임라인을 다시 조립하고
`engine.js:292` 의 `cue` 정의(`a = l.t − lead`, `b = l.t + l.dur·span`, **분모는 `rel`**)로 풀었다:

| | `rel` | 창 W | 겨냥 | 재계산 | 씬 값 | 차 |
|---|---:|---:|---|---:|---:|---:|
| S1 `drop` | 4.931s | 4.5879 | `fall` 개시 `c1=0.72` | **3,153.3ms** | 3,150 | **3.3ms** |
| S4 `tick` | 4.475s | 3.7300 | `stamp` 개시 `pass=0.80` → `c0=0.4998` | **1,714.3ms** | 1,720 | **5.7ms** |

둘 다 30fps **0.2프레임 이내**. `3x²−2x³=0.8` 의 해를 이분법으로 풀어 **0.7129** 를 얻었고
작성팀·검수 값(0.7120)과 일치한다. 🔴 작성팀이 초안의 역산 오류(0.7286)를 스스로 잡고
**값은 그대로, 근거만 고친 것**도 맞는 처리다 — 겨냥한 자리가 처음부터 「체크가 서는 순간」이었다.

**⑤ 피크 천장** — `synth` 를 실제로 돌렸다: `drop` **0.1281** · `tick` **0.4178** (< 0.46).
경고 없음. `tick` 은 여유가 0.042 로 얇지만 넘지 않는다.

**⑥ `timed.json` 진위** — `voice: "ME"` · `engine: "supertonic"` · 7줄 wav 실재.
**`SYNTHETIC-NOT-REAL` 아님.** 합성본이 남아 길이 게이트를 속이는 사고는 없다.

**⑦ 파생 시각도 전부 내 계산과 검수 표가 일치한다**:
`TOTAL` **27,073ms** · 카드 **24,473ms** · 페이오프(`pass=1`) **21,413ms** → **여유 3,060ms** ·
예고 자막 카드 전 노출 **449ms**. `S4` 시작 19,549ms.

## 7. 🔴 넘긴 채 통과시킨 항목 — **다음 회차가 선례로 인용할 수 없다**

전부 **기록**이고 화면·음성에 나가는 것은 하나도 없다. 그래서 반려하지 않았다.
그러나 다음 회차가 이 파일을 베끼므로 여기 박제한다.

**a. `notes` 5칸이 2·3차 산정치인 채로 남았다** (검수 🟡 1~4 + 나의 확인).
- `notes.페이오프와 아웃트로 카드` = 21.36 / 24.38 / 3.0초, 그리고 *"깎은 것은 예고 줄(23→19자)"*
  → 실측 **21.41 / 24.47 / 3.06초**이고 3차본은 **줄인 게 아니라 통째 교체(20자)** 다. `writer.md` 에도 같은 한 벌.
- `notes.정적 구간` = *"3차본에서 예고가 1자 늘어 약 0.59초"* → 실측 **0.449초**.
- `notes.길이` = 3차 **산정치**(27.2 / 2.84 / 21.8) → 실측 **27.1 / 2.7 / 21.8**.
- `notes.말투` = 「~요 **4**」 → 7줄이므로 **~요 5**.

**b. `sfx` 전수 표기의 규약이 안 적혀 있다.** 작성팀 「71건」·「drop 7」·「tick 18」은
**이 편 2건을 뺀 수**이고, 실제 전수는 **73 / 8 / 19** 다. 값 자체는 살아남았지만
「71」만 읽고 다음 회차가 세면 어긋난다. 🔑 이 리포에서 **세 라운드 연속** sfx 대조표의
수치가 흔들렸다(ep10s-2 · ep10s-3 · ep11s). **다음부터 sfx 전수는 이 편 포함 여부를 표에 적는다.**

**c. `S4` `tick` `why` 의 *"이 회차에서 가장 짧고 가장 높은 tick"* 중 「가장 짧고」가 틀렸다.**
`ep00i` 가 **0.04** 로 이 편의 0.044 보다 짧다. 「가장 높은 freq」(2540 > 2320)는 참이다.
파형 상관 0.268 로 갈림은 증명됐으므로 소리는 문제없다 — **문구만 틀렸다.**

**d. `excluded` 6번째 항목이 옛 자막을 인용한다.** *"S2 의 「안 됐어요」가 이미…"* →
3차본 자막은 **「안 되더라고요」**다.

🔴 **위 넷 중 어느 것도 「전례가 있으니 괜찮다」로 인용할 수 없다.** 다음 회차에서
같은 종류(실측 뒤 낡은 칸 · 전수 규약 누락)가 또 나오면 그때는 **기록만이라도 반려**한다.
이번에 넘긴 이유는 단 하나 — **누적 반려 2회이고, 영상에 나가는 결함이 0이며,
영상은 글과 달리 되돌리는 비용이 크기 때문**이다. 기록 위생을 이유로 정지선을 밟지 않는다.

**e. 기획 브리프 `planner.md` 272행에 폐기된 예고 문구 예시가 그대로 남아 있다.**
이 편에는 무해하지만 **그 줄이 이번 사고의 발원지**다. 다음 회차 브리프를 쓸 때
「예고 문구 예시」는 **다음 편 원문 대조 뒤에만** 적는다(§1 마지막 줄).

## 8. `excluded` 재검토 — 되살릴 것 없음

7건을 읽고 **되살려야 할 것이 있는지** 봤다.

- **경로탐색 확장 경계(IPathfinder)** — 원문을 직접 확인했다: *"잘 돌아가고 있고, 저는 이걸
  건드릴 생각이 없습니다"*(20행) · *"알고리즘을 바꾸지는 않되"*(21행). **어긋난 상태가 실제로 없다.**
  절 제목도 「질문」이다. 편으로 세우지 않은 것이 맞고, 27.1초에 자리도 없다. **되살리지 않는다.**
- **ADR 경고문 / 말풍선 3초 여운** — 위 절에 딸렸거나 한 문단뿐. 사유 타당.
- **2단계 「게시판을 안 골랐다」** — 이 편에서 유일하게 아까운 재료지만, 어긋남의 종류가
  다르고(범위 결정) 넣으면 뒤집힘이 둘이 된다. **상한 28초에 0.9초 남은 상태**라 물리적으로도 못 넣는다.
- **「조각 Y」** — 시청자에게 뜻이 0. 화면에 올린 이름을 원문 낱말 **DEBT(빚)** 로 잡은 것이 옳다.
- **3단계 되돌림 / AI 협업 규칙** — 화면에 세울 것이 없거나 HUD 와 중복. blurb 에 남겼다.
