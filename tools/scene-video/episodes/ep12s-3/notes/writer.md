## 0. 4단 전환에서 무엇을 했나 (2026-08-08)

### 0-1. 붙인 것 셋

| 샷 | kind | 한 줄 |
|---|---|---|
| **S0 인트로** | `intro` | 고정 문안 그대로. `export { default } from '../../../engine/intro-brand.js';` **한 줄**이 파일 전부다(ADR-V25-11). 이 회차의 축(밭 칸)을 인트로에 밀어 넣고 싶었지만 **브랜딩은 매회 같아야 브랜딩**이라 손대지 않았다. |
| **SH 훅** | `zero` **(신규)** | 「오늘 개발 일지 내용은, 작물 0개 태운 홍수예요.」 인트로가 매회 같으니 **체류를 만드는 자리가 여기**다. |
| **SO 아웃트로** | `nextpeek` **(신규)** | 예고 한 문장 + 소개 마무리 + **0.5초 미리보기 루프**. |

### 0-2. 훅 `zero` — 본문 S1 의 재방송이 되지 않게 세 축을 갈랐다

같은 사건을 두 번 그리면 훅이 아니라 예고편 없는 재탕이 된다. 그래서:

| 축 | 훅 `zero` | 본문 `flood` |
|---|---|---|
| 홍수의 **방향** | 물마루가 **왼쪽→오른쪽으로 지나가 화면 밖으로 빠진다** | 물띠가 **위에서 내려와 칸 위에 앉는다** |
| 0 을 담는 **그릇** | 계수기 **하나** (`CROPS LOST` + 큰 0) | 로그 카드 **두 줄** (`RUN 1` / `RUN 2`) |
| **순서** | **0 이 먼저 꽂히고** 그 뒤에 홍수가 지나간다 | 홍수가 먼저 오고 0 이 나중이다 |

순서가 갈린 건 우연이 아니라 **자막 어순** 때문이다 — 「작물 **0개** 태운 **홍수**」라
0 이 먼저 나온다. 계약 2대로 물리면 그림 순서가 자동으로 뒤집힌다.
🔑 훅은 「0이었다」만 약속하고 **「한 번이 아니라 두 번이었다」는 S1 이 진다.**
훅이 다 말해 버리면 3초 뒤에 볼 이유가 없어진다.

### 0-3. 아웃트로 `nextpeek` — 밀스톤 층위로만 그렸다

🔴 **다음 편 `ep13s` 는 작성 시점에 아직 분할 전이다**(`state/schedule.json` 의 `order` 에
`ep13s` 한 줄 · `episodes/ep13s` 폴더 없음). 그래서 사건 단위 그림을 그리면 안 된다 —
그 글의 1단계는 늑대가 아니라 **부상**이라, 13-1편이 부상 편이 되는 순간 어긋난다.

**0.5초 루프**: 오른쪽 밖에서 강조색 `THREAT` 쐐기가 **지면 아래 길로** 들어와 왼쪽으로
지나가고, 마을 가장자리 주민의 x 에 닿는 순간 그 **흰 표식이 꺼지고 같은 자리에서 강조색
무덤이 솟는다.** 나머지 표식은 반대쪽으로 물러났다 돌아온다.

- 🔑 **이 회차의 문법만 물려주고 도형은 안 물려줬다.** 물려준 문장은 하나 —
  **「흰 것이 꺼진 자리에 강조색 자국이 남는다」**(본문 S3 에서 밭 칸이 주저앉고 강조색
  점선 윤곽만 남던 그 문장). 다음 편에서는 그 흰 것이 밭이 아니라 **사람**이다.
- 🔴 **흰색/강조색을 두 겹으로 갈랐다.** ⓐ좌표 — 표식은 지면선 **위**(186~202), 쐐기는
  **아래**(216~236)로만 다닌다(14px). ⓑ시간 — 무덤은 표식이 있던 **바로 그 x** 에 서므로
  표식 알파가 위상 0.34 에 0 이 된 뒤 0.38 에야 무덤이 시작하고, 되감을 때도 무덤이
  0.95 에 꺼진 **뒤** 0.955 부터 표식이 돌아온다.
- 🔴 **화면에 숫자를 한 개도 안 올렸다.** 그 시점의 주민 수가 원문에 없다. 표식 개수는
  `spec.marks` 로만 있고 **세는 라벨이 없으며**, 왼쪽 끝만 흐리게 그려 「이어진다」로 읽힌다
  (오른쪽 끝은 흐리게 안 했다 — 위협이 들어오는 **마을의 가장자리**라 거기가 실제로 끝이다).
- 🔴 **수치는 전부 `spec` 경유다**(`marks`·`hitIndex`·`loopSec`). 직전 편이 같은 자리에서
  개수를 kind 파일 상수로 박았는데, 그러면 **그 수가 원문의 어느 문장에서 왔는지
  `scene.json` 만 보고는 알 수 없다.** 화면에 안 적는 수라도 근거는 대본에 있어야 한다.

### 0-4. 🔴 인덱스가 조용히 접히는 자리 둘 — 이게 이번 전환의 진짜 함정이었다

예고 줄이 S4 를 떠나면서 **없는 줄을 가리키는 `cue` 가 둘** 생겼다.
`cue` 는 `Math.min(i, rel.length−1)` 로 마지막 줄에 눌러앉으므로(engine.js:293)
**에러가 안 나고 조용히 두 움직임이 한꺼번에 터진다.**

| 파일 | 접힌 것 | 어떻게 풀었나 |
|---|---|---|
| `hunt.js` | S2 두 줄 → 한 줄이 되며 `lockCue`(1) 가 `checkCue`(0) 에 겹침 | **하나의 `c0` 를 어절 순서로 쪼갰다** — 0.34 「아니라」 체크 완성 / 0.44 「밭을」 화살표 / 0.58 패널 / 0.68 빈 칸 / 0.86 「재파종 잠금」 이름 |
| `between.js` | 예고 줄이 나가며 `teaseCue`(1) 가 `bugCue`(0) 에 겹침 | **같은 줄을 두 번, 다른 창으로 불렀다** — `cue(0, 0.15, 0.35)` 는 페이오프용(좁다), `cue(0, 0.15, 0.95)` 는 벌어짐용(넓다) |

🔑 **`cue` 가 순수 함수라 같은 줄을 다른 `span` 으로 두 번 불러도 된다.** 이게
「예고 자막을 지우면 마지막 샷이 멈춘다」는 옛 문제의 답이다 — 페이오프는 자막 앞쪽
1/3(+1.14초)에서 끝내고, 벌어짐이 +1.42~+3.35초를 이어받아 샷 꼬리가 안 빈다.

### 0-5. 어디를 조였나 — 본문 가운데 한 곳뿐

세 샷이 붙어 길이가 늘었으므로 ADR-V25-4 대로 **편을 더 쪼개지 않고 곁가지를 덜었다.**

| 줄 | 개정 전 | 개정 후 |
|---|---|---|
| S2[0] | 재해 코드는 다 맞았어요. 원인은 딴 데 있었죠. | (아래 한 줄로 합침) |
| S2[1] | 앞에서 건 재파종 잠금 탓에 밭이 비어 있었어요. | **원인은 재해가 아니라, 밭을 비운 재파종 잠금이었어요.** |

- 🔑 **뜻은 하나도 안 버렸다.** 「재해 코드는 다 맞았다」는 **화면이 진다** — `hunt` 의 세
  항목(`TARGETS`·`RESIST`·`AMOUNT`)에 흰 체크가 셋 다 그어지고, 자막이 「재해가 아니라」를
  말하는 **그 순간에** 마지막 체크가 완성된다. 「앞에서 건」은 S4 의 「두 전제 사이에
  있었죠」가 이어받는다(둘 다 내가 만든 것이라는 뜻).
- 🔑 합치면서 **어미도 갈랐다** — 개정 전 S2 는 「~있었죠」로 끝나 S4 의 「~있었죠」와 두 줄
  연속이었다. 지금은 「~이었어요」다.

### 0-6. 안 건드린 것

- **sfx 두 개 전부.** 근거 줄(S1[0] · S3[0])의 `text`·`say`·`pauseAfter` 를 안 만졌으므로
  두 `rel`(3,783 · 3,490ms)이 그대로다. `cue` 창은 **그 줄 자기 `rel` 만** 쓰므로
  (engine.js:169) 앞에 샷이 둘 붙어도 `delayMs` 가 안 움직인다.
- **S1[1]**(제목이 약속한 반전 0개) · **S4[0]**(남는 한 줄이자 페이오프의 `cue` 창).
- **`hook`(카드 맨 위) · `outro.next` · `outro.siblings`** — 지시대로 손대지 않았다.

## 1. 이 편이 든 사건과 안 든 것

세 조각으로 세워 보면 이렇다.

| 조각 | 내용 | 어느 샷 |
|---|---|---|
| ①어긋난 상태 | 코드 0줄로 새 재해 「홍수」를 넣었는데 로그가 **작물 0개 소실**, 다시 돌려도 0개 | S1 |
| ②뒤집힘 | 재해 코드는 다 맞았고 진짜 원인은 **앞 단계의 재파종 잠금**(밭이 비어 있었다) → 홍수를 **밭 시설을 부수는 재해**로 전환 | S2 · S3 |
| ③남는 한 줄 | 「코드에는 버그가 한 줄도 없었습니다. 버그는 **두 설계의 전제 사이**에 있었습니다.」 | S4 |

버린 것은 `scene.json` 의 `excluded` 8건에 사유와 함께 적었다. 요약하면 셋이다.

1. **형제 편의 사건**(구역 / 재해 선반 / 겨울 잔량 40 / FoodDaysLeft) — 한 편은 사건 하나만
   다룬다. 그래서 **30·40·20개·10명·4명·3일치 같은 수치를 이 편 화면에 한 번도 안 올렸다.**
2. **뒤집힘이 아닌 것**(관개수로 목표를 꺼둔 판단 = 보류) — 사건이 아니다.
3. **결론이 겹치는 것**(이탈 오탐) — 곁가지로 배분됐지만 **한 조각도 안 넣었다.**
   둘 다 「증상 쪽을 뒤지면 못 찾는다」이고, 게다가 결말이 「버그가 없었다」라 이 편의 마지막
   줄과 글자까지 겹친다. 페이오프가 두 번 오면 두 번째는 김이 빠진다.

🟢 **브리프 오염 없음.** 기획팀이 원본 HTML 에 `<table>` 0건 · `<pre>` 0건 · `<svg>` 0건임을
확인했고, 내가 받은 전문에도 `|` 구분 줄 · CSS 조각 · 문장이 아닌 단어 나열이 한 줄도 없었다.
표가 지워진 빈 자리(수치가 통째로 사라진 문단)도 없다. 보고할 오염 조각이 없다.

## 2. 제목 — 「0줄」이 아니라 「0개」로 잡은 이유

🔴 **2026-08-08 도치형으로 다시 썼다(0-A).**
**「작물이 왜 0개 사라졌을까요? 마을에 홍수를 제대로 내렸거든요.」**

- **사실은 그대로다.** 옛 제목(「마을에 홍수를 내렸는데 작물은 0개 사라졌어요」)과 같은 사건이고
  낱말도 같다 — 어순과 어미만 바뀌었다. 질문이 0번째 글자에서 궁금증을 열고, 사건 꼬리가
  「~거든요」로 맥락을 댄다.
- 🟢 **「제대로 내렸거든요」의 근거**: 「재해는 분명히 시간 맞춰 발동하는데, 정작 태울 게
  아무것도 없었습니다.」 — **재해가 안 온 게 아니라 제대로 왔는데 헛쳤다.** 이 편의 아이러니가
  제목 한 문장에 다 들어간다.
- 🟡 숫자 `0` 은 그대로 남겼다. 0-B 는 이제 보조 훅이고 게이트도 정보 표시일 뿐이지만,
  **모순 쌍**(재해가 제대로 왔는데 잃은 것이 0)이 도치형 문장에 억지 없이 들어가므로 뺄 이유가 없다.
- 🔴 **코디네이터에게**: 이 제목이 바뀌었으므로 `outro.siblings` 안의 **내 자신의 라벨**이
  새 제목과 어긋난다. `check.mjs` 의 「형제 라벨 = 그 편의 youtube.title」 은 **자기 자신도
  검사**하므로 세 편 제목이 확정된 뒤 셋을 한꺼번에 다시 파생해야 한다. 지시대로 나는 손대지 않았다.

<details><summary>아래는 3단 승인본 시절의 제목 노트 — 「0줄이 아니라 0개」 판단은 지금도 유효하다</summary>

**「마을에 홍수를 내렸는데 작물은 0개 사라졌어요」**

- **모순 쌍이 그 자체로 선다.** 재해가 왔는데 잃은 게 0. "그게 어떻게 되지"가 클릭이다.
- **아라비아 숫자 `0` 이 있다** → `제목 후킹 (수치)` 통과.
- 🔴 **「코드 0줄」을 안 쓴 것은 전수를 세고 내린 판단이다.** ep05s-3 과 ep10s-2 가 이미
  「코드는 0줄이에요」 계열을 **두 번** 썼다. 훅의 *모양*은 반복해도 되지만 **같은 수치가 같은
  뜻으로 세 번** 나오면 그건 돌려막기다. 「작물 0개」는 이 편 고유다.
- 🔑 대신 **0줄을 버리지 않고 화면으로 옮겼다** — S1 물띠 옆 라벨 `NEW ASSET / .CS DIFF 0`.
  그러면 한 화면에 0 이 둘 선다: **위 0 은 자랑(코드 0줄로 넣었다), 아래 0 은 사고(0개 소실).**
  나레이션은 아래 0 만 부르고 위 0 은 화면이 조용히 쥔다. 자막 한 줄(약 3.7초)을 안 쓰고
  아이러니를 완성한 자리다.

### 첫 두 줄 — 숫자가 첫 줄을 잡아먹지 않게 잘랐다

```
마을에 홍수를 내렸어요. / 작물 쓸어가라고요.      ← 시청자가 이미 아는 것
근데 로그는 작물 0개 소실. / 다시 돌려도 0개.      ← 그것을 깨는 자리(숫자·반전)
```

제목 핵심어 [마을 · 홍수 · 내렸는데 · 작물 · 0개 · 사라졌어요] 중 **넷**이 첫 두 줄에 그대로 있다.
첫 줄을 수치 스펙으로 여는 것이 채널 체류 꼴찌(17.35%)였다는 실측이 이 배치의 근거다.

### 첫 두 줄 — 4단 구조에서는 **훅 줄 + S1[0]** 이다

`check.mjs` 의 `postIntroLines` 가 인트로를 건너뛰고 센다.

```
오늘 개발 일지 내용은, / 작물 0개 태운 홍수예요.     ← SH  (체류를 만드는 자리)
마을에 홍수를 내렸어요. / 작물 쓸어가라고요.          ← S1[0] (그 앞 장면)
```

새 제목 핵심어 [작물 · 0개 · 사라졌을까요 · 마을 · 홍수 · 제대로 · 내렸거든요] 중
**넷(작물 · 0개 · 마을 · 홍수)** 이 어절 그대로 있다. 나머지 셋은 도치형 제목의 의문·회상
어미와 부사라 활용형이 안 맞는데, **맞추려면 제목을 낭독해야 하고 그건 금지**다.

🔴 **숫자가 첫 줄을 잡아먹는 형태는 아니다.** 「작물 0개 태운 홍수」는 수치 스펙이 아니라
**사건**이다. 우리 프로젝트를 몰라도, 앞 편을 안 봤어도 그 자리에서 이해된다.

## 3. 그림 설계 — 축 한 문장에서 네 개를 냈다

🔴 **샷마다 그림을 고르지 않았다.** 먼저 축을 한 문장으로 정했다.

> **「밭 칸 한 줄 — 그 안에 무엇이 있고, 칸 자체는 어떻게 되는가」**

이 글의 사건이 정확히 그 둘 사이의 착오이기 때문이다. 재해는 칸 **안**(작물)을 때리려 했고
칸 안은 비어 있었고, 해결은 칸 **자체**(시설)를 때리게 바꾼 것이다.

| 샷 | kind | 같은 칸이 여기서 하는 일 |
|---|---|---|
| S1 | `flood` | 칸 위에 무언가가 **내려앉는다** — 그런데 칸 안은 처음부터 점선 빈 자리뿐이다 |
| S2 | `hunt` | 칸이 조연으로 아래로 내려가, 「왜 비었는지」를 쥔 **규칙 아래**에 깔린다 |
| S3 | `flip` | 같은 폭·같은 칸 수의 줄이 다시 서고, 이번엔 **칸 자체가 주저앉는다** |
| S4 | `between` | 칸이 둘로 커져 **두 설계**가 되고, 담긴 것이 아니라 **그릇 사이의 틈**이 주인공이 된다 |

- **막대 그래프도 표도 안 썼다.** 이 글에는 비교할 두 값이 없고 「거기 있느냐 없느냐」 하나만 있다.
- 다른 회차의 kind 를 연 것은 파일 구조(`{ build, draw }` · `fit` 헬퍼 · 주석 쓰는 법)를 보기
  위해서지 그림을 가져오기 위해서가 아니다. 직전 회차 `ep11s` 의 축은 「두 표식 사이의 간격」이라
  여기와 겹치는 도형이 하나도 없다. **좌표·움직임·라벨은 전부 이 글에서 새로 냈다.**

### 샷별로 한 줄씩

- **`flood`** — 강조색 물띠가 크게 일렁이며 내려와 칸 줄 바로 위에 **착지**하고 칸들이 한 번
  눌렸다 되돌아온다(홍수는 분명히 왔다). 로그 카드에 같은 줄이 `RUN 1` · `RUN 2` 로 두 번
  찍히고 두 번 다 오른쪽 숫자가 `0` 이다 — 원문의 「다시 돌려도 0개」를 라벨 없이 말한다.
- **`hunt`** — 이 샷만 세로 이동이 전부다. 세 항목(TARGETS · RESIST · AMOUNT)에 **흰** 체크가
  하나씩 그어지고(🔴 여기서 강조색을 쓰면 「이게 답이다」가 되는데 이 셋은 **답이 아니라서**
  이야기가 되는 자리다), 셋이 다 찬 뒤에야 아래로 강조색 화살표가 뻗어 `REPLANT LOCK` 이 켜진다.
- **`flip`** — SOW 화살표는 오른쪽으로, FLOOD 화살표는 왼쪽으로. 점선이 **서로 반대 방향으로**
  흐르고 둘은 끝내 닿지 않는다. TARGET 값이 `CROP` → `FIELD` 로 갈리자 칸 위에 타격 자국이
  서고 가운데 두 칸이 주저앉는다.
- **`between`** — 판 둘 다 흰 `OK` 를 받는데 강조색은 판 안이 아니라 **판 사이 검은 틈**에서
  켜진다. 이 편의 결론이 그 배치 하나로 읽힌다.

### 🔴 흰색과 강조색을 안 겹쳤다 (좌표 + 시간 양쪽)

팔레트 게이트는 두 색의 혼합을 hue 150~152 로 읽어 **어느 순서든 통과**시킨다.
게이트 통과가 근거가 못 되는 자리라 설계 단계에서 막았다.

- **좌표로**: S1 물띠 y ≤ 146 · 격자 y ≥ 150 · 로그 카드 y ≥ 214. S3 타격 자국은 칸 **위**
  검은 틈(y 126~146)에만. S4 빗금 띠는 판 테두리에서 5px 안쪽(stroke 3px = 경로 ±1.5px → 여백 3.5px).
- **시간으로**: 같은 자리에서 색이 바뀌는 두 곳은 **알파 구간을 붙여 놓지 않았다.**
  S3 값 `CROP` 은 c0 0.48 에 0 이 되고 `FIELD` 는 0.54 에야 시작한다(칸 테두리도 brk 0.42 / 0.52).
  S4 빗금은 흰 계열이 c0 0.56 에 꺼진 **뒤** 0.58 부터 강조색이 들어온다.
  🔑 문턱에서 색만 갈아 끼우면 그 한 프레임에 두 색이 섞이는데, 그건 게이트가 못 본다.
- **강조색 빗금이 강조색 글자를 훑지 않는다** — S2 빗금은 글자 없는 패널 바닥 띠, S4 빗금은
  글자 없는 검은 틈. `BUG` 글자는 판보다 위(y ≤ 56)에 따로 세웠다.

### 🔴 반려 수정 (2026-08-08) — `hunt`(S2)가 캔버스 아래로 870px 넘어갔다

**870 은 「몇 px 넘어갔나」가 아니라 캔버스 마지막 행에 잉크가 있는 픽셀의 개수다**
(`check.mjs` 가 `getImageData(0, H−1, W, 1)` 의 알파 > 10 을 센다). 바닥 한 줄이 가로로
**288 CSS px × dpr 3.02 ≈ 870** 통째로 칠해져 있었다.

**원인은 슬라이드 오프셋 하나.** 아래 패널이 밑에서 밀려 올라오는 연출이라
`top = 198 + lerp(22, 0, rise)` 였는데, **쉬는 자리는 292 로 307 안이지만 등장 첫 프레임의
top 은 220 이라 바닥이 314** 였다. 그 패널 바닥의 **빗금 띠**(x 32 ~ w−32, 폭 288)가

**잘라서 맞추지 않고 층을 다시 쟀다.**

🔑 **남길 규칙 한 줄: 움직이는 요소는 「쉬는 자리」가 아니라 「가장 밖으로 나가는 순간」으로
여백을 잰다.** 나는 정지 좌표만 검산하고 292 < 307 을 보고 통과라고 적었다.

🔴 **2026-08-08 두 번째 정정 — 나머지 셋의 최저를 셀 때 또 틀렸다.** `flood` 를 「격자 196 +

## 5. 효과음 — 두 마디

> **헛되이 닿는다(S1 `thud`) → 이번엔 진짜로 무너진다(S3 `drop`).**

4샷 중 **2샷이 무음**이다. 재해 코드 수색(S2)과 「전제 사이」(S4)는 나레이션이 부르는 사건이지
소리가 나는 사건이 아니다.

- 직전 편 `ep11s` 의 문장은 「떨어진 것 하나(drop), 앉은 것 하나(tick)」였다. 순서도 뜻도 다르다 —
  저기서는 **잃는 소리**가 먼저였고, 여기서는 **아무 일도 안 일어나는 소리**가 먼저다.
- 🔴 **`sweep` 과 `latch` 를 일부러 안 썼다.** 그 둘은 잡음이 `rng(seed)` 라 seed 가 같으면
  `dur` 을 바꿔도 파형이 안 갈리는데(한 회차가 실측 상관 0.977 로 반려됐다), 나는 이 환경에서
  node 를 못 돌려 **파형 상관을 직접 잴 수 없다.** 재지 못하는 근거를 적는 대신
  **잴 필요가 없는 kind** 를 골랐다 — `KIT.thud` 도 `KIT.drop` 도 `rng` 를 아예 안 부르므로
  `(dur, freq)` · `(dur, from, to)` 가 파형을 완전히 결정하고, **파라미터 대조가 곧 파형 대조**다.
- 전수는 작성 시점에 `_archive` 를 포함해 **scene.json 24개**를 필드 이름으로 훑어 다시 셌다
  (thud 14건 · drop 8건). 명령과 목록은 각 `sfx[].why` 에 통째로 적어 뒀다.
  선택값 **thud (0.25, 198)** · **drop (0.44, 700→130)** 은 어느 것도 기존 목록에 없다.
- 🟡 **형제 편 대조(2026-08-08 · 세 편이 다 나온 뒤 채웠다).**

  | 편 | 소리 짝 | 이 편과의 거리 |
  |---|---|---|
  | `ep12s-1` | `thud`(0.19/264) + `drop`(0.36/430→150) | 🔴 **kind 쌍이 완전히 같다** |
  | `ep12s-2` | `tick`(0.10/760) + `riser`(0.50/240→610) | 겹치는 kind 0 |
  | **ep12s-3** | `thud`(0.25/198) + `drop`(0.44/700→130) | — |

  파라미터는 갈렸다 — `thud` 의 기음은 `g = f×(1−0.3·t/dur)` 로 활강하므로 활강 속도가
  **417Hz/s vs 238Hz/s(1.75배)**, 시작 기음 비 **1.333(완전4도)**, 길이 +31.6%.
  `drop` 은 시작 주파수 **1.63배**, 스윕 범위 **2.87배 vs 5.38배**, 길이 +22%.
  부르는 사건도 다르다 — ep12s-1 은 「숫자가 못 박힌다」·「일수가 반으로 떨어진다」,
  여기는 「닿았는데 아무것도 안 걸린다」·「밭 시설이 주저앉는다」.
  🔴 **그래도 형제 두 편이 같은 짝으로 열리고 닫히는 것은 검수팀 판정 자리다.** 내가 지금
  안 바꾸는 이유: 이 편의 두 사건이 「무겁게 닿는다」와 「위에서 아래로 무너진다」라
  다른 kind 로는 뜻이 안 맞고(riser·tick 은 반대 방향, sweep 은 쓸고 지나감),
  `latch`·`sweep` 은 `rng(seed)` 라 이 환경에서 파형 상관을 못 잰다.
  바꾸라는 판정이 오면 **S1 을 무음으로 돌리는 쪽**이 억지 kind 를 얹는 것보다 낫다.
- 🟢 **`delayMs` 두 값을 실측 `rel` 로 다시 풀었다: thud 2,700 → **2,690** · drop 2,390 → **2,160**.**
  `kind`·`gain`·`dur`·`freq`·`from`·`to` 는 하나도 안 바꿨다.
  🔑 두 줄의 실측 말 속도가 **202.9 vs 182.8ms/자**로 10% 흔들려 같은 가정을 쓴 두 값이 각각
  4ms 와 **230ms(6.9프레임)** 어긋났다 — **회차 단위 보정치로는 못 잡는 폭**이다.
  drop 이 산정 그대로 나갔으면 소리가 「했어요」 쪽으로 밀려 **칸이 이미 다 주저앉은 뒤에**
  났을 것이다.
