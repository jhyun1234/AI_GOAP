## 1. 🔴 반려 사유 — S3 「최소 비용」이 8 이 되지 않는다

### 지적

`scene.json` S3 `spec`:

```json
"panelLabel": "경우의 수",
"minLabel": "최소 비용",
"minFrom": "1",
"minTo": "8",
```

`kinds/overrun.js:68` 주석도 같다 — `/* ── 최소 비용 : 1 이 8 로 올라간다 ─── */`.
스틸 `build/stills/24.85s.png` · `26.6s.png` 에 **「최소 비용   8」** 이 강조색으로 떠 있다.

### 원문 대조

원문에서 `5` 와 `8` 이 각각 무엇의 값인지 두 문장이 직접 말한다(태그 제거본, `finditer` 문맥):

> "그런데 **카탈로그 전체에서 가장 싼 액션이 5였다가** 갑자기 1짜리가 등장하면서, 그
> 어림값이 5분의 1로 쪼그라들었습니다."

> "고치는 것 자체는 **간호 비용을 1에서 8로 올리는** 한 줄이었습니다."

즉 `5` = **카탈로그 최소 비용**(다른 액션의 값), `8` = **간호 액션의 비용**.
간호를 8 로 올리면 8 > 5 이므로 **카탈로그 최소 비용은 다시 `5` 로 돌아간다.**
원문 어디에도 최소 비용이 8 이 됐다는 말이 없고, 원문이 준 수만으로 산수가 반대로 나온다.

같은 사건을 이미 그린 롱폼 `lf02` 의 `kinds/costfloor.js` 주석이 이 해석을 리포 안에서
그대로 뒷받침한다:

```
   MineStone 12 · HarvestCrop 8 · BuildCampfire 20 · EatCookedFood 5 ·
   BuildHouse 15 · CookMeal 6, 그리고 TendInjured 8(1→8 로 고친 그 값).
   기준선 5 와 끼어든 1 은 M10 글 50행.
```

`lf02`(승인·완주)는 **기준선을 5 로, 8 을 간호(TendInjured) 자신의 값으로** 그렸다.

### 이 회차 안에서도 어긋난다

- S2(`notch`)의 같은 슬롯은 **「최소 비용」 5 → 1** 로 옳다(간호 1 이 최저를 갈아 끼운다).
  S3 가 같은 라벨을 이어받아 1 → 8 로 올리므로, 슬롯의 뜻이 「카탈로그 최소」로 고정된 채
  틀린 값을 받는다.
- **영어 자막은 오히려 옳다** — S3 둘째 줄 `en` 이 `"I bumped **nursing** to 8"` 이다.
  즉 자막(en)과 화면 라벨이 서로 다른 주어를 말하고 있다.
- `hud.title` 도 「간호 비용 1이 부른 계획 실패」로 **간호 비용**이라 적는다.
- 작성팀 스스로 `notes.수치 정직성` 에 **"`8`(고친 값)"** 이라고 분류해 두고, 화면에서는
  「최소 비용」 라벨에 붙였다. 문자열 대조는 했는데 **값↔라벨 결합**을 대조하지 않은 것이다
  (`notes.문자열 정직성` 이 「최소 비용」 낱말의 실재만 확인한다).

### 그림도 같은 방향으로 어긋난다

`overrun.js:108` 이 걸음 폭을 `pitchFrom 6 → pitchTo 26` 으로 넓힌다. S2 의 척도로 보면
폭 6 ↔ 최소 비용 1, 폭 30 ↔ 최소 비용 5 였으므로 **26 은 「최소 비용 ≈ 4.3」에 해당**한다.
그림은 5 쪽으로 돌아가는데 글자만 8 이라, 값과 폭이 서로 다른 말을 한다.

### 고치는 길 (둘 중 하나 — 선택은 작성팀 몫)

1. **라벨을 바꾼다.** `minLabel` 을 「간호 비용」으로. 원문에 그 문자열이 있다
   (*"간호 비용을 1에서 8로 올리는"*). 그러면 `1 → 8` 이 그대로 옳아지고 자막
   「값을 8로 올리고」·`en` 「I bumped nursing to 8」과도 주어가 맞는다.
   걸음 폭은 `pitchTo` 를 30(= 최소 비용 5) 으로 두면 「최저가 5 로 돌아왔다」가 되고,
   그때 화면에 5 라는 수를 새로 적지 않아도 폭만으로 읽힌다.
2. **값을 바꾼다.** 「최소 비용」을 유지하고 `1 → 5` 로. 대신 8 을 별도 칩
   (「간호 8」)으로 세워야 자막의 8 과 화면이 이어진다. 요소가 하나 늘어난다.

🔑 어느 쪽이든 **S1·S2 는 손댈 필요가 없다.** 어긋난 곳은 S3 한 샷의 값 슬롯 하나다.

## 2. 🔴 정정 요구 — 반려본을 고칠 때 같이 처리할 것

### 2-A. `source.title` 이 아직 옛 이름이라 **유튜브 설명란에 두 번째 이름이 찍힌다**

코디네이터가 `outro.source` 를 세 편 모두 「M10 야생 위협과 방랑자」로 통일했고 그건
실물에서 확인했다(§7-1). 그런데 같은 `scene.json` 의

```json
"source": { "title": "M10 야생 위협과 부상", ... }
```

는 그대로다. 이 필드는 화면에는 안 나오지만 **`publish.mjs` 가 설명란에 두 번 찍는다**:

```
tools/scene-video/publish.mjs:706  `이 편은 「${scene.source?.title ?? '원문'}」 에서 나온 …`
tools/scene-video/publish.mjs:710  scene.source?.title ? `원문: ${scene.source.title}` : '',
```

결과 = 아웃트로 카드는 「M10 야생 위협과 **방랑자**」, 설명란은 「M10 야생 위협과 **부상**」.
작성팀이 `notes.outro.source 표기` 에서 걱정한 *"형제 셋이 같은 글을 두 이름으로 부르면
시청자가 못 잇는다"* 가 **편 사이가 아니라 한 편 안에서** 일어난다.
세 편 다 같은 상태이므로 **`ep13s-1`·`ep13s-3` 도 함께** 고쳐야 한다.

### 2-B. `S2` 효과음 `delayMs` — 실측으로 다시 풀면 **1,940 → 1,820** (오차 +120ms)

작성팀이 산정치임을 밝혀 두었으므로 실측 `timed.json` 으로 다시 풀었다.
식은 `cue(i, lead, span)` 역산이다(`engine/engine.js:396-401`):
`a = rel[i].t − lead` · `b = rel[i].t + rel[i].dur×span` · `W = b − a` ·
`진행도 c 인 시각(줄 시작 기준) = a + c×W − rel[i].t`.
`rel.dur` = **`timed.dur` + `pauseAfter`** (`engine.js:156`).

| 항목 | S2 `drop` | S3 `latch` |
|---|---|---|
| 붙은 줄 | `at 0` (rel[0]) | `at 1` (rel[1]) |
| `timed.dur` + `pause` | 4,100 + 180 = **4.280s** | 3,702 + 200 = **3.902s** |
| 작성팀 산정 `rel` | 4.548s | 3.886s |
| `cue` 인자 | `(0, 0.15, 0.85)` (`notch.js:43`) | `(1, 0.15, 0.80)` (`overrun.js:60`) |
| 창 `W` | 0.15 + 4.280×0.85 = **3.788s** | 0.15 + 3.902×0.80 = **3.272s** |
| 리빌 시작 문턱 | `shr` = `(c0−0.52)/0.34` → c0 0.52 | `gate` = `(c1−0.52)/0.28` → c1 0.52 |
| **실측 delayMs** | **1,820** | **1,551** |
| 대본 값 | 1,940 | 1,550 |
| 오차 | **+120ms (늦다)** | **+1ms** |

- **S3 는 사실상 정확하다**(1ms). 산정치가 우연히 맞은 게 아니라 `rel` 추정이 16ms 밖에
  안 틀렸기 때문이다.
- **S2 는 120ms 늦다.** 가이드 한도(±20프레임 = 0.667초) 안이라 이것만으로는 반려가 아니다.
  다만 **말 축을 재 보면 1,820 이 확실히 더 좋은 자리**다. 줄 wav
  (`build/audio/04-0nai7ay.wav`, 20ms 창 RMS)에서:

  | 시각(줄 시작 기준) | 단기 RMS | 무엇 |
  |---|---|---|
  | 1.55s | 0.0482 | 유성 |
  | **1.82s** | **0.0010** | **쉼(「되니,」 뒤 골)** |
  | 1.94s | 0.0899 | 「어림」 첫 음절 — 이 줄에서 가장 센 축 |
  | 2.34s | 0.0013 | 쉼 |

  현재 값 1,940 은 **그 줄에서 가장 큰 소리 위**에 떨어지고, 실측 값 1,820 은 **쉼의 골**에
  떨어진다. 마스킹 0 인 자리이고, 작성팀이 `why` 에 적은 의도(*"「어림값」이라는 낱말이
  나오는 그 위"*)와도 오히려 더 맞는다 — 낱말 **직전**에 떨어져야 낱말이 안 가려진다.
- 스틸로도 확인했다. `build/stills/16.94s.png`(= 1,941ms) 는 **띠가 아직 98% · 값이 아직
  「5」** 다. 즉 지금 소리는 리빌이 눈에 보이기 전에 나고, 동시에 말은 가장 크다.

## 5. 🔊 효과음 — 파형으로 다시 쟀다

### 5-1. 재는 방법 (재현 명령)

`sfx.mjs` 의 `synth()` 를 **씬의 실제 인자 그대로** 불러 `gain: 1` 로 정규화한 뒤
**절대 표본 정렬**로 상관을 낸다. 짧은 쪽을 0으로 채워 길이를 맞추고, **정규화 위치로
리샘플하지 않는다** — 리샘플하면 같은 seed 쌍이 상쇄돼 검출이 안 된다.

```js
const corr = (a, b) => {           // a, b = synth(kind, {...opt, gain:1}, 44100)
  const n = Math.max(a.length, b.length);
  let sa=0, sb=0, sab=0;
  for (let i=0;i<n;i++){ const x=i<a.length?a[i]:0, y=i<b.length?b[i]:0;
                         sa+=x*x; sb+=y*y; sab+=x*y; }
  return sab / Math.sqrt(sa*sb);
};
```

대조 모집단 = `episodes/**/scene.json`(`_archive`·`lf01`·`lf02` 포함) 전수 **113건**.

### 5-2. 코디네이터가 지목한 쌍 — 충돌 없음

| ep13s-2 `latch`(191) ↔ ep13s-1 `latch`(157, dur 0.135) | 0.7445 | latch 계열 바닥값 — 아래 5-4 |

통제군을 같이 재서 **척도가 살아 있음**을 확인했다(0 이 나온 게 「측정이 안 된 것」이
아님을 보이는 절차):

| 통제 | r | 뜻 |
|---|---|---|
| `latch` 191/dur 0.17 ↔ `latch` 191/dur 0.135 | **0.9931** | 같은 seed 면 dur 을 바꿔도 안 갈린다(작성팀 주장 ✔) |

전체에 쓴다(`sfx.mjs:73-84`, `:105-116`). 같은 난수열이라도 쓰이는 자리가 달라 상관이 0 이다.
**「seed 191 이 겹친다」는 걱정은 실측으로 해소된다.**

### 5-4. 🟡 관찰 — `latch` 는 seed 를 갈아도 0.77 아래로 안 내려간다

이 회차 `latch` 와 리포 안 다른 `latch` 들의 상관: `ep08s-3` **0.825** · `ep09s-1` 0.796 ·
`ep05s-2` 0.794 · `ep04s-3` 0.788 · `ep08s-1` 0.787 · `lf01` 0.785 · `lf02` 0.777·0.771 ·
`ep13s-1` **0.744**. 340/680Hz 고정 몸통이 지배하기 때문이고, **latch 를 쓰는 한 피할 수
없는 바닥**이다. 이 회차 값은 그 분포의 **가장 낮은 쪽**이다.

다만 **성격**으로 보면 형제 둘이 닿아 있다:

| 편 | 자리 | kind | 붙은 사건 |
|---|---|---|---|
| `ep13s-1` | S3 · cue 1 | `latch` seed 157 | 무덤이 **그 자리에 걸려 앉는다**(되돌릴 수 없음) |
| `ep13s-2` | S3 · cue 1 | `latch` seed 191 | 기준선이 그어져 **규칙이 걸린다**(확정) |

같은 샷 번호 · 같은 cue · 같은 「확정」 계열이다. 셋이 병렬로 작성돼 서로를 못 봤으니
사고가 아니라 수렴이다. **반려도 정정 요구도 아니고 의견으로 올린다** — 지시서 표의
`latch` 정의(*"철컥 · 잠긴다 · 커밋 · **규칙이 걸림** · 확정"*)에 문자 그대로 맞는 쪽은
**이 편**이고, 은유로 확장한 쪽이 13-1(무덤)이다. 굳이 하나를 갈아야 한다면 옮길 쪽은
13-2 가 아니다. 세 편을 이어 볼 마스터가 판단할 자리라 여기 남긴다.

### 8-1. 🟡 `"if any cost goes that low"` — `that low` 의 지시 대상

바로 앞이 `bumped nursing to **8**` 이라 `that low` 가 **8** 을 가리키게 읽힌다.
그런데 8 은 게이트가 막는 값이 아니라 **허용된 값**이다(원문: *"카탈로그의 최소 비용이
기준선 밑으로 내려가면"*). 한국어 「더 낮아지면」은 기준선 아래를 뜻해 옳다.
`… if any cost ever drops below that baseline` 처럼 지시 대상을 기준선으로 되돌리면 깨끗하다.
**반려 사유로 세우지 않는다**(사실을 뒤집는 정도가 아니라 지시어가 흐린 정도다).
🔴 §1 을 고치면서 S3 를 다시 만질 때 같이 보면 된다.

### 8-2. 🟡 `en.blurb` 의 형제 소개에서 조건절이 사라졌다

한국어: 「간호가 죽음의 시계를 **되감으면** 아무도 안 죽게 되던 이야기는 13-3편」(조건)
영어: `nursing **rewinding** the death clock is part 3` (조건 표지 없음)
소재를 가리키는 명사구라 완료형 주장까지는 아니지만, 같은 문단 본문이 `almost rewound` 로
쓰고 있으니 `nursing almost rewinding the death clock` 으로 맞추는 편이 낫다. 의견.
