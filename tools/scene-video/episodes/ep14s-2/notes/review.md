## §2. 🔴 반려 사유 — S3 「지금 내 손이 비어 있나」가 화면에 안 뜬다

### 무엇이 문제인가

이 편의 뒤집힘은 **묻는 조건 두 개 중 하나를 뺀 것**이고, S3 은 그 두 문장을 카드 두 장으로
세워 아래 것을 접어 없애는 그림이다. `oneask.js` 머리 주석과 `notes.쉬운 말` 이 그렇게 적었다:

> 🔴 어려운 낱말을 화면에서 뺐다 — 「선불 판정」·「수령 공간 조건」 대신 원문이 따옴표로
> 직접 써 준 두 문장(「값을 치를 능력이 있나」·「지금 내 손이 비어 있나」)을 그대로 올렸다.
> — `episodes/ep14s-2/kinds/oneask.js:18-19`

그런데 **빠지는 쪽 문장이 화면에 실질적으로 안 나온다.**

### cue 산수 (엔진 정의로 풀었다)

`engine/engine.js:396-400` — `a = l.t − lead`, `b = l.t + dur×span`, `k = (ts − a)/(b − a)`.
S3 자막 0 은 `dur = 2.246s`, `oneask.js:77` 이 `cue(0, 0.15, 0.55)` 이므로

```
W = 0.15 + 2.246 × 0.55 = 1.3853s
샷 시작(ts=0) 시점에 이미 k = 0.15 / 1.3853 = 0.108
```

`oneask.js:98-99` 의 글자 알파 = `st × (1 − ease(k / 0.30))` 이고, 여기에 엔진의 샷 진입
페이드(`engine.js:388-389`, ENTER 0.26초, 0.12 → 1.0)가 곱해진다. 풀면:

| ts (샷 기준) | k | 「지금 내 손이 비어 있나」 최종 알파 |
|---|---|---|
| 0.00 | 0.108 | **0.073** |
| 0.10 | 0.180 | **0.144** ← 최댓값 |
| 0.15 | 0.217 | 0.125 |
| 0.20 | 0.253 | 0.059 |
| 0.26 | 0.296 | **0.001** |
| 0.30 이후 | — | **0** |

- **최대 알파 0.145**, 읽을 수 있는 창은 **약 0.20~0.25초**.
- 그 0.25초는 **샷 전체가 0.12 → 1.0 으로 페이드인하는 구간과 겹친다.**
- 게다가 **말이 아직 시작도 안 했다** — S3[0] wav(`build/audio/06-0roovz3.wav`)의 발화 개시는
  **0.310초**다(10ms 창 RMS > 0.02 기준). 즉 나레이션 「이제 손이 비었나는 안 물어요」가
  입을 떼는 순간에는 그 카드 글자가 **이미 0** 이다.
- 11글자를 0.2초에 읽을 수는 없다.

### 스틸 (확인 사살)

- `build/stills/23.24s.png` (ts = 0.11 · 알파 최댓값 프레임) — 카드가 흐린 회색으로 보이긴
  하지만 **화면 전체가 진입 페이드 중**(위 카드도 회색, 자막도 회색)이라 이 순간이 읽는
  순간이 될 수 없다.
- `build/stills/23.45s.png` (ts = 0.32) — **글자가 완전히 사라지고 빈 회색 상자만 접히고 있다.**
  이 빈 상자는 그 뒤로도 약 0.3초 더 남는다(`sy = 1 − ease(k/0.55)`, k=0.55 → ts 0.612).
- `build/stills/25.2s.png` (ts = 2.07) — 아래 카드 자리에 강조색 띠만 흐른다.

즉 시청자가 실제로 보는 것은 **「카드 한 장 + 이름 없는 빈 상자가 접힘」**이다.
「어떤 물음이 빠졌는가」는 화면에서 사라졌고, 자막(「손이 비었나」) 혼자 그 짐을 진다.
이 편의 사건이 **묻는 조건 하나를 뺀 것**이라 그 한 장이 이름을 잃으면 S3 의 대비가 성립하지 않는다.

### 고치는 법 (한 줄 · 부수 효과 0)

`oneask.js:98-99`

```js
      ctext(spec.dropAsk, w / 2, cy + 5, 800, 13.5, tone('ink'), CWD - 26,
        st * (1 - ease(clamp(k / 0.30))));          // ← 지금
```

글자가 **상자보다 먼저** 사라져야 할 이유가 없다. 상자와 같은 시간표(`k/0.55`)로 맞추거나,
지연 구간을 주면 된다. 예:

```js
        st * (1 - ease(clamp((k - 0.34) / 0.21))));  // k 0.34 까지 온전 → 0.55 에서 상자와 함께 0
```

- 이러면 온전한 알파 구간이 **ts 0.32초까지**(샷 진입 페이드가 끝난 뒤, 발화 개시 0.31초와 같은
  자리) 이어지고, ts 0.61초에 상자와 함께 사라진다 → **읽을 수 있는 시간 약 0.6초.**
- 🔴 **`sfx.delayMs` 는 안 건드려도 된다** — S3 의 소리는 `since(1)` 위에 있고 여기는 `cue(0)` 다.
- 🔴 **TTS 재생성 없음 · 자막 한 글자도 안 바뀜 · 길이 불변.**
- 고친 뒤 `check.mjs --fps 30` 만 다시 돌려 결정성·정적 구간을 재확인하면 된다.

⚠️ 값은 예시다. 그대로 쓰라는 뜻이 아니라 **「글자가 상자보다 먼저 죽지 않게」** 하면 된다.
고치면 `oneask.js` 머리 주석과 `notes` 의 「두 문장을 그대로 올렸다」가 비로소 사실이 된다.

## §3. 🟡 마스터 판단을 구하는 것 (혼자 반려 사유로 쓰지 않았다)

### 3-1. S3 에서 품삯이 **즉시** 건너간다 — 원문은 「후불로 수락」이다

- 원문: *"그래서 선불 판정에서 수령 공간 조건을 빼냈습니다. **손이 차 있으면 후불로 수락하고**,
  이미 만들어둔 정산 연기 로직이 나중에 처리합니다."*
- 화면(`26.26s.png`): 강조색 알 다섯이 의뢰인 → 목수로 **끝까지 건너가 닿고** 「수락」이 켜진다.
- 이 편은 S1·S2 에서 **목수 주머니가 이미 4개로 차 있다**고 세워 놨으므로, 고친 뒤에도 그
  순간에 품삯이 건너갈 수는 없다(그래서 「후불」이다).

**그래도 반려로 올리지 않은 이유** 셋:
1. **방향과 주어는 원문과 같다** — 품삯은 의뢰인 → 목수이고(원문의 「품삯」 정의 그대로),
   `ep11s` 를 무너뜨린 「주러/받으러」 종류의 역전이 아니다.
2. 작성팀이 **S3 에 벽도 여덟 칸도 안 그렸다**(`oneask.js:15-16`). 즉 화면이 「상한 8이
   사라졌다」를 주장하지 않는다 — 주장하는 것은 「거래가 성립한다」까지다.
3. 원문에서도 **품삯은 결국 건너간다**(정산 연기). 루프 그림은 시각(時刻)의 주장이 아니다.

🟡 그래도 값이 싸게 강해지는 길은 있다 — 「수락」을 **먼저** 켜고 품삯을 **그 뒤에** 건너가게 하면
「수락이 먼저, 값은 나중」이 그림으로 정확해진다. 지금은 두 사건이 같은 루프 위상에서 붙어 있다.
(제안이지 요구가 아니다. 마스터 판단.)

### 3-2. 형제 편과 **효과음 쌍이 겹친다** — 재는 방법과 수치를 남긴다

`ep14s-2` = **thud + latch** / `ep14s-3` = **thud + latch**. 둘이 병렬로 쓰여 서로를 못 봤다.
자리도 겹친다 — **thud = 원인/추적 샷의 막힘 · latch = 해결 샷의 확정**.

**재는 방법**(같은 쌍이 검수 0.851 / 마스터 0.595 로 갈린 전례가 있어 명시한다):
`sfx.mjs` 의 `synth(kind, opt, 44100)` 이 돌려주는 Float32 파형을 **절대 표본 정렬**로
(리샘플·정규화 길이 맞추기 **금지**) 짧은 쪽 길이까지 자른 뒤 피어슨 r. `gain` 은 각 편의 실값.

```
thud  이 편(0.23, 246)  vs  ep14s-3(0.14, 286)      r = -0.055
      비교 통제군 — 이 편 vs ep12s-1(0.19,264)        r =  0.051
                    이 편 vs ep10s-2(0.29,230)        r =  0.017
                    자기 자신                          r =  1.000
latch 이 편(0.21, 233)  vs  ep14s-3(0.21, 223)      r =  0.794
      통제군(리포에서 이미 승인돼 나간 latch 쌍들)
        ep08s-1(0.205,83) vs ep08s-3(0.225,97)        r =  0.815
        lf01(0.15,127)    vs lf01(0.155,131)          r =  0.773
        lf01(0.16,137)    vs lf01(0.175,139)          r =  0.790
        lf02(0.16,157)    vs lf02(0.19,163)           r =  0.779
        lf02(0.14,167)    vs lf02(0.2,179)            r =  0.762
      바닥 확인 — latch(0.21,233) vs sweep(0.21,233)  r = -0.001
```

- **thud 는 완전히 갈린다**(r ≈ −0.06). `KIT.thud` 가 `rng` 를 안 부르므로 (dur, freq) 가
  파형을 다 정한다는 작성팀 주장은 코드(`sfx.mjs:60-70`)로 맞다.
- **latch 0.794 는 「높지만 이 kind 의 정상 범위」**다. `KIT.latch` 는 몸통이 340/680Hz 고정이라
  seed 를 아무리 갈아도 r 이 **0.76~0.83** 을 못 벗어난다 — 위 통제군 다섯 쌍이 그 증거이고,
  그중 넷은 **이미 승인돼 나간 회차들끼리의 값**이다. 즉 **이 수치로는 반려할 수 없다.**
- 🟡 그래서 판단은 파형이 아니라 **연출**의 문제다: 인접한 두 편이 「막힘 thud → 확정 latch」라는
  **같은 소리 문장**을 쓴다. 승인 선례(`ep12s-1`·`ep12s-3` 이 둘 다 thud+drop)가 있어 반려는 아니지만,
  넷을 한 자리에서 보는 코디네이터가 **한쪽을 갈아 주면 좋겠다**. 갈 곳은 `ep14s-3` 이든 이 편이든
  **latch 쪽**이 싸다(seed·kind 만 바뀌고 `delayMs` 는 `since()` 기반이라 재계산 0).

**전수 재검산도 했다** — 작성팀이 `ep13s-3` 노트의 「thud 18건」을 「20건」으로 정정한 것이 맞다.
지금 리포 전수는 `thud 22 · latch 26 · tick 27 · drop 17 · sweep 16 · riser 13` 이고,
22 = 작성 시점 20 + 이 편 + `ep14s-3`, 26 = 23 + 14s-2·3·4 로 정확히 맞는다.
**`seed 233` 은 리포 어디에도 없다** ✓. `dur 0.21` 은 이제 형제 셋이 공유하지만 seed 가 다르다.

**피크 천장** — `synth('latch',{dur:0.21,seed:233,gain:0.064})` · `synth('thud',{dur:0.23,freq:246,gain:0.066})`
둘 다 실행해도 `⚠️ sfx …: 피크 천장에 걸려` 경고가 **안 뜬다**. 작성팀이 못 쟀다고 적은 자리를
대신 쟀고, **gain 을 내릴 필요 없다.**

### 3-3. `notes.길이` 가 실측을 아직 안 담았다 (정정 요구)

`notes.길이` 첫 줄이 *"🔴 아직 인용할 실측이 없다"* 로 남아 있다. 작성팀이 *"실측이 나오면
그 줄을 그대로 인용해 이 칸을 갈아 끼운다"* 고 스스로 적었으니, 위 §1 의

```
총 길이 38초 이하   37.3초 = 자막 35.2 + 꼬리 2.10   / 본문 18~22초   본문 20.3초
```

한 줄을 **그대로** 옮겨 적어 달라. 🔴 **자체 계산식을 쓰지 말 것**(회차 여섯이 각자 다른 식으로
적었고 여섯 다 틀렸다). 같은 김에 `notes.outro.siblings` 도 「빈 배열이다」로 남아 있는데
부모가 이미 채워 게이트가 4개 일치로 통과한다 — 현재 상태에 맞게 한 문장만 고쳐라.

### 3-4. 그 밖에 관찰만 적는 것 (고칠 필요 없다고 본다)

- **S1 에서 목수가 이미 네 알을 들고 있게 그린 것** — 작성팀이 스스로 넘긴 항목이다.
  원문은 「목수가 정확히 4개」라고 특정하지 않지만, 같은 문단이 「모든 주민이 평상시에 4개를
  채우고 다닙니다」 + 「상한 8」 + 「품삯이 다섯 알」을 나란히 놓아 **4 + 5 > 8 을 원문이 직접
  세운다.** 목수도 주민이다. 자막은 개별 사례로 말하지 않고 평상시 상태로만 말한다(S2).
  **통과로 본다.**
- **S2 의 되밀림 진폭이 작다** — `everyrow.js:108-111` 로 풀면 품삯 무리의 x 는
  268 → 258 → 276 → 268(CSS px, 폭 18px = 알 지름 1.8배)이고 띠 오른쪽 끝 250.5 에
  **7.5px 못 미친다.** `reads` 가 「닿지도 못하고」라고 정확히 적었으니 서술은 맞다.
  다만 「되밀린다」로 읽히기엔 약하다 — 스틸에서 실제로 읽히는 것은 움직임이 아니라
  **「빈 칸 4개 vs 알 5개」가 세 줄 모두 똑같다**는 정지 사실이다. 그것으로 뜻은 선다.
- **S3 의 latch 가 「남는 한 줄」의 첫머리에 얹힌다** — 발화 개시 0.480초, 소리 0.750초
  → 문장 시작 0.27초 뒤(「물을」 근처). 0.21초짜리 악센트라 말을 가리진 않지만,
  이 편에서 가장 중요한 문장의 입구다. 관찰만 남긴다.
- **「막힘 → 튕김」 도형이 `ep09s-1/undersurface.js`(값이 표면선에 부딪혀 되돌아온다)와
  뜻이 닮았다** — 다만 도형이 완전히 다르고(세로 값 vs 가로 칸·알), 다섯 회차 전이다.
  **돌려막기 아님으로 판정.**

## §4. 사람이 본 것 — 통과한 항목 (근거 포함)

### 4-1. 사실 대조 — 화면 문자열 전수 + 수치

원본 HTML 을 직접 열어 대조했다. **먼저: 이 원문에는 `<table>` 0개 · `<pre>` 0개 · `<svg>` 0개**
(`re.findall` 로 확인). 즉 **브리프가 지운 표가 애초에 없어서** 「표 안에만 있던 값이 화면에
샜는가」라는 사고 경로 자체가 성립하지 않는다. 산문 전문만이 원장이다.

`spec` 안 문자열 전수(중복 제외 18 = 글자 15 + 표정 3)를 뽑아 원문에 `finditer` 로 대조했다:

| 화면 문자열 | 원문 대조 |
|---|---|
| 집 부탁 | *"집을 부탁했는데"* · *"집 부탁 대사에 품삯도 노출"* ✅ |
| 선불 없이는 안 해 | 따옴표 안 문자열 그대로 ✅ |
| 목수 · 의뢰인 | 원문 낱말 ✅ |
| 의뢰인 곡식 6개 | *"곡식 6개를 지닌 의뢰인이"* ✅ |
| 목수 주머니 여유 공간 | *"목수 자신의 주머니 여유 공간이었습니다"* ✅ (원문 어절 그대로) |
| 품삯 다섯 알 | *"품삯이 다섯 알인데"* ✅ |
| 곡식은 8개까지 | *"(몸에 지닐 수 있는 식량은 8개까지입니다)"* + *"상한 8에 걸려"* ✅ |
| 평상시 곡식 4개 | *"채집 목표가 '곡식 4개 확보'라서 모든 주민이 평상시에 4개를 채우고 다닙니다"* ✅ |
| 항상 거절 | *"선불 성격 목수는 구조적으로 항상 거절하고 있었습니다"* ✅ |
| 선불 목수가 묻는 것 | *"선불을 요구하는 성격이 묻는 건"* ✅ |
| 값을 치를 능력이 있나 | 따옴표 안 문자열(앞의 「저 사람이」만 뗌) ✅ |
| 지금 내 손이 비어 있나 | 따옴표 안 문자열 그대로 ✅ |
| 수락 | *"후불로 수락하고"* ✅ |

🔴 **값↔라벨 결합을 따로 한 번 더 봤다**(`ep13s-2` 의 「최소 비용 8」이 여기서 났다):
**6** 은 의뢰인 주머니에, **8** 은 칸 개수와 상한 라벨에, **다섯** 은 강조색 알 개수와 품삯
라벨에, **4** 는 이미 차 있는 칸에 붙었다 — 네 수가 전부 **원문이 그 수를 붙인 바로 그 자리**에 있다.
어긋난 결합 **0건**.
🔑 「식량 8개까지」를 「곡식 8개까지」로 좁힌 것은 원문 2단계가 합산 상한을 버리고 **슬롯별
상한**으로 갔다고 적고, 6단계가 「곡식이 있으면 상한 8에 걸려」라고 쓰므로 **좁혀도 맞는다.**

**화면에 없는 수** — 주민 수·줄 수(S2 셋)·표식 수(SO 넷)를 글자로 안 적었다.
원문에 없는 수가 화면·자막에 **0건**.

**주어와 방향** (`ep11s` 사고 재발 방지):
- 「곡식 6개를 든 주민이 **거절당했어요**」 — 원문의 거절 주체는 목수, 대상은 의뢰인 ✅
- 「막힌 건 **목수 주머니**」 — 원문 「탈락한 건 … 목수 자신의 주머니 여유 공간」 ✅
- 품삯은 **의뢰인 → 목수**로 흐른다(S1 은 목수 주머니로 들어가려다 튕기고, S3 은 왼쪽
  의뢰인에서 오른쪽 목수로 건너간다) ✅ 방향 역전 없음.
- 「이제 손이 비었나는 안 물어요」 — 묻는 주체는 선불 목수 ✅

### 4-2. 🔴 인과 사슬 — 자막만 읽고 서는가

```
① 곡식 6개를 든 주민이 거절당했어요.            (어긋남)
② 곡식은 충분한데 선불 없인 안 한대요.          (수수께끼 — 낼 수 있는데 왜?)
③ 근데 막힌 건 목수 주머니였어요.               (원인이 엉뚱한 데 있다)
④ 곡식은 8개까지인데 품삯이 다섯 알이죠.        (받을 자리 산수)
⑤ 다들 4개씩 들고 다니니 늘 거절이었죠.         (4+5>8 → 구조)
⑥ 이제 손이 비었나는 안 물어요.                 (뒤집힘)
⑦ 물을 건 값을 낼 능력이지, 내 손이 아니거든요. (남는 한 줄)
```

**빈 칸 없음.** ④와 ⑤ 사이의 산수(4 + 5 = 9 > 8)만 말로 안 하는데, 그 자리를 **그림이 정확히
메운다** — `16.607s.png` 에서 여덟 칸이 흰 넷 + 강조색 넷으로 꽉 차고 **다섯 번째 알 하나가
칸 밖에서 벽에 부딪혀 있다.** 세는 도형이라 라벨 없이도 읽힌다.
🔑 「품삯은 목수가 **받는** 것」이라는 전제가 자막에 명시되진 않지만, 「품삯」이 일상어이고
S1 의 알이 목수 주머니 **안으로** 날아가므로 오해 여지가 없다.

### 4-3. 🧑‍🌾 새 규격 — `ADR-V25-13`~`15`

**① 낱말 전수 — 내가 다시 뽑았다.** 작성팀 목록을 믿지 않고 `spec` 문자열 전수 + `lines[].text`
+ `lines[].say` + `hud` 3칸을 한 덩어리로 합쳐, 브리프 §7 의 「쓰면 안 되는 것에 가까운 낱말」
21개 + 「판정·상한·수령·축 분리·테스트·정산·인벤토리·선반·플래너·증상 봉합·고집쟁이」를
전부 검색했다.

> 남은 것: **`GOAP` 한 개**. 그것도 `hud.aiHook`(「Claude Code로 만든 유니티 GOAP AI」)이라
> **시리즈 공용 브랜드 줄**이고, 개정 `ADR-V-10` §3 이 「옮기면 뜻이 무너지는 고유 기술명」으로
> 허용한 것이다. 본문 자막·`spec` 에는 **0건**.

즉 **미배정 낱말 0** 이라는 작성팀 주장은 검산으로 사실이다. 「판정」·「상한」·「수령 공간」·
「슬롯」·「로직」·「테스트」·「축 분리」가 화면과 자막 어디에도 없다.

⚠️ **①풀어쓰기의 재료가 원문 안에 있는지도 확인했다** — 「목수 주머니 여유 공간」·「곡식은
8개까지」·「지금 내 손이 비어 있나」·「평상시에 4개」가 **전부 원문 문장**이다(§4-1 표).
원문 밖에서 끌어온 말이 없으므로 **비유 계약을 받아야 할 것이 없다.**

⚠️ 「의뢰인」·「품삯」·「선불」은 브리프 §7 이 「어려운 낱말이 아니다」로 분류했고 나도 동의한다
(게임을 안 만들어 본 사람도 아는 일상어이고, 고유명사·게임 안 사물은 애초에 대상이 아니다).

**② 비유 — 자막에 비유가 0건인 것을 확인했다.** 열 줄을 한 줄씩 읽었다. 「~같은 거예요」·
「~라고 보면 돼요」·「말하자면」 형태가 없고, **원문에 없는 대상을 끌어와 빗댄 문장도 없다.**
「막혔다」는 비유가 아니라 상태 서술이다. `notes.비유` 칸은 「없음」 + 사유 3줄로 채워져 있다
(계약 4 충족 · 빈 칸 아님).

🔴 **브리프가 짚은 유일한 후보(「구조적으로 항상 거절」)를 그림으로 푼 것이 실제로 되는가** —
스틸로 봤다(`21.5s.png`). **세 줄이 똑같은 배치**(흰 알 4 + 빈 칸 4 + 밖에서 대기하는 강조색 알 5)로
복제돼 있고 되밀리는 x 가 셋 다 같다. 「한 사람의 사고가 아니라 판이 그렇다」가 **글자 없이
읽힌다** — 화면의 「항상 거절」을 지워도 남는다. **통과.** 비유를 안 만든 판단이 옳았다.

**③ 라벨을 가려도 읽히나 (`ADR-V25-15`)** — `reads` 산문을 믿지 않고 스틸 여덟 장으로 봤다.

### 4-4. 🔤 화면 글자는 한국어인가 (개정 `ADR-V-10`)

`spec` 을 거치는 문자열 **전부 한국어**다. 영어는 `hud.aiHook`·`hud.outro` 의 브랜드 줄
(`Claude Code` · `GOAP` · `AI`)뿐이고 셋 다 §3(고유 기술명·브랜드)에 든다.
표정 문자 `·_·` · `ㅡ_ㅡ` · `^-^` 는 언어가 아니다(§2 기호).
`ep06s`~`ep12s-3` 을 선례로 인용한 자리 없음 — `notes.한국어 라벨` 이 명시적으로 그렇게 적었다.
🔴 자막 `lines[].en` 이 영어인 것은 **의도한 상태**이므로 섞어 보지 않았다.

### 4-5. 제목 · 첫 줄

**제목** = 「곡식 6개를 들고 갔는데 왜 거절당했을까요? 목수 주머니에 빈자리가 없었거든요.」

- **도치형** ✅ — 질문 문장이 앞, 사건 꼬리가 뒤(`ADR-V25-12` 문형).
- **드라마 서술** ✅ — 주어가 주민이고 「거절당했다」는 감정·사건이다. 기능 서술("~보이게 했어요") 아님.
- **답을 미리 주지 않는가** ✅ — 꼬리가 답처럼 보이지만 **새 질문을 연다**(「돈은 의뢰인이 내는데
  왜 목수 주머니가 문제야?」). 이 편의 힘이 정확히 그 역설이다.
- 🔴 **자극이 사실을 넘지 않는가** ✅ — 두 마디 다 원문 실물이다.
  *"곡식 6개를 지닌 의뢰인이 … 집을 부탁했는데 … 거절당했습니다"* / *"탈락한 건 엉뚱하게도
  목수 자신의 주머니 여유 공간이었습니다."* 지어낸 사건 0.
- 숫자 6 은 원문 수치 ✅(브리프 §6 원장에 있음). 숫자 부재를 지적하지 않았고, 숫자 때문에
  첫 줄이 수치 설명이 되지도 않았다(아래).

**첫 줄**(= 훅 줄) = 「오늘 개발 일지 내용은, 곡식 6개를 든 주민이 거절당했어요.」

1. 🔴 수치 스펙으로 시작하지 않았다 ✅ — 「포만감 소비 3, 요리하면 2」 형태가 아니라
   **주어(주민) + 사건(거절당했다)** 이다. 6개는 스펙이 아니라 그 주민이 쥔 것이다.
2. 🔴 우리 프로젝트 진행 상황으로 시작하지 않았다 ✅ — 「재설계가 끝난 그 자리에서」류 없음.
3. 🔴 앞 편을 봐야 이해되지 않는다 ✅ — 14-1(공용 창고)을 안 봐도 혼자 선다.
4. 🟡 (미검증 항목 · 의견) 주민이 무언가를 하고 있고 어긋나 있는가 — **어긋나 있다.**
   다만 상위 3편은 주민이 **거스르는** 쪽(거절함)이었고 여기는 **거절당하는** 쪽이다.
   등급은 섞지 않고 의견으로만 남긴다.

**제목 이행** — 게이트는 「곡식·6개」 두 어절로 통과했다. 뜻으로도 제목이 약속한 장면
(값을 낼 수 있는 사람이 거절당함)이 **첫 두 줄 안에 통째로** 들어간다. `ep02s` 의 34.3초 같은
지연 없음.

### 4-9. 버린 것 · 그림 · 말투 · 그 밖

- **`excluded` 9건** 전부 사유가 납득된다. 특히 브리프가 「배경 한 줄」로 허용한 후보 13
  (보상 경제가 죽어 있었다)을 **안 쓴 판단이 옳다** — 원문에 「선불 목수가 항상 거절한 이유」가
  창고 고장과 주머니 상한 **둘 다** 적혀 있어서, 20초 본문에 둘을 넣으면 시청자가 어느 쪽이
  이 편의 답인지 못 고른다. blurb 에는 통째로 남겼다.
- **원문이 이름 붙인 개념이 버려졌는가** — 「고집쟁이」(성격 이름)를 안 썼다. 사유가
  *"이 편의 원인은 성격이 아니라는 것인데 이름을 세우면 그 오해를 화면이 먼저 심는다"* 이고,
  원문 자신이 「엉뚱하게도」라고 쓰므로 **동의한다.** 「증상 봉합」·「축 분리」는 ③버리기가 맞다.
- **그림이 뜻을 나르는가** — `reads` 다섯 개가 전부 사건을 적었고(빈말 0), 스틸로 확인했다.
  🔑 **벽을 두 번 그린 것**(SH·S1)은 작성팀이 스스로 짚은 자리인데, **반복이 아니라 폭로가 맞다** —
  「목수 앞의 벽 = 목수 주머니 끝의 벽」이 이 편의 사건 그 자체이고, 두 스틸을 나란히 놓으면
  같은 강조색 세로선이라는 것이 바로 읽힌다. 갈아치우면 편이 무너진다.
- **말과 그림이 같은 순간에 도착하는가** — `cue`/`since` 를 전수로 풀었다.
  🔴 `t` 로 도는 조건은 `doorstep` 의 왕복(1.9초)·`oneask` 의 띠 흐름(1.1초)·`nextpeek` 의
  0.5초 루프뿐이고, **셋 다 자막이 부르는 사건이 아니라 「계속 그러고 있다」는 상태**라
  `ep02s tripwire` 형태가 아니다. 🔴 **다른 cue 에서 파생된 문턱**(`ep00i runmark` 형태)은
  **0건** — 사건은 전부 자기 자막의 `since()` 또는 `cue()` 위에 있다.
- **효과음 배치** — 2개(S1 thud · S3 latch). 본문 20.3초에 2개 = 0.098개/초로
  「30~35초 4단 구조에서 2~3개」 대역 안. 인트로·훅·S2·아웃트로 무음.
  🔑 **S2 에 안 단 것은 설계다**(세 줄이 되풀이되는 자리) — 동의한다.
  `why` 두 개 다 채워져 있고 kind 선택 근거가 표와 맞는다.
  **`delayMs` 를 그림 축으로 실측 검산했다**:
  - S1 thud 1100ms = `HIT 0.50 × loopSec 2.2` — `pocketfull.js:41,114` 로 확인.
    스틸 `16.607s.png` 에서 **다섯 번째 알이 실제로 벽에 붙어 있다** ✅
  - S3 latch 750ms = `ARRIVE 0.50 × loopSec 1.5` — `oneask.js:45,140` 로 확인.
    스틸 `26.26s.png` 에서 **품삯이 목수에 닿아 있다** ✅
  - 작성팀 확인 요청(자막 1 이 접촉 시각보다 긴가)에 답한다: S1[1] = **3.507초** > 1.100 ✅ ·
    S3[1] = **3.633초** > 0.750 ✅. 둘 다 소리가 자막 안에서 난다.
  - **말 축**도 쟀다(TTS 선행 무음): S1[1] 발화 개시 **0.460초** → thud 는 발화 0.640초 뒤,
    23자 3.05초 기준 약 「8개까지」 부근 — **상한을 말할 때 상한 벽에 부딪히는 소리**가 난다 ✅
- **말투** — 어미 배열 `입니다 / 어요 / 대요 / 어요 / 죠 / 죠 / 어요 / 거든요 / 예요 / 아요`,
  **최장 연속 2**(`voice.json` rules.1 「3연속 금지」 충족) · 어미 7종.
  담화표지 「근데」·「이제」 둘(rules.3) · `say` 전부 27자 이하(rules.2) ·
  큰 쉼 0회(rules.6, 게이트도 0회) ✅
- **막(act)** — `4막 · 잃을 수 있는 마을 (연장)`. **「5막」 표기 0건** ✅
  (브리프 §1 이 반려 사유로 못박은 자리 · `schedule.json` 의 `sources.ep14s.note` 와도 일치)
- **그림 돌려막기** — 형제 셋(`ep14s-1` 그릇 / `ep14s-3` 자리 위의 집 / `ep14s-4` 거리)과

  `ep14s-1` 의 `nextpeek` 이 이 편 사건을 예고하는데 **그릇 높이로** 그렸고 본편은
  **여덟 칸 격자**다 — 같은 사건을 다른 그림으로(브리프 §2 규칙) ✅
