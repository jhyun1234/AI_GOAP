## §4. 「닿지 않고 멈춤」 — 통과로 판정한다

**질문: 「닿지 않고 멈춤 + 수락」이 「또 막혔다」로 안 읽히는가.**

검수가 든 신호 넷을 결론이 아니라 **코드와 스틸로** 다시 확인했다.

| 신호 | 내 확인 |
|---|---|
| ① 벽이 없다 | `oneask.js` 전체에 `setShadow(GLOW…)` 호출이 **띠 하나뿐**(147행). 앞 세 그림에서 튕김의 원인이던 강조색 세로 획이 이 kind 에 **0건** — 스틸 `26.26s` 에서도 없다 |
| ② 안 돌아온다 | `m = ease(clamp((u−0.08)/0.42))` 는 u 에 대해 **단조 비감소**이고 음의 항이 없다. `gx = lerp(66,200,m)` 이므로 루프 안에서 왼쪽으로 가는 프레임이 존재하지 않는다 |
| ③ 「수락」이 켜진다 | `ease((s1−0.55)/0.45)` — **`u` 가 아니라 `s1` 이 분모다** |
| ④ 표정 | SH `ㅡ_ㅡ` → S3 `^-^` |

🔑 **내가 하나 더 찾았고, 그게 결정적이다.** 알 무리는 `u` 루프라 자막 1(3.633초) 동안
2.4바퀴 돌지만, `a = wa·ease(u/0.06)·(1−ease((u−0.80)/0.16))` 이라 **u 0.80~0.96 에서 알파가
0 으로 지워진 뒤** 왼쪽에서 다시 떠오른다 — 되돌아가는 **움직임**이 아니라 디졸브다.
그리고 「수락」은 `s1` 축이라 **루프가 재시작해도 안 꺼지고 ≥0.78 로 계속 켜져 있다.**
즉 「멈춤이 풀리고 다시 시도한다」로 읽힐 화면이 구조적으로 안 나온다. **통과.**

### 「후불로 수락」인데 화면이 「안 건넨다」로 끝나는 것 — 사실 왜곡 아님

원문: *"손이 차 있으면 **후불로 수락**하고, 이미 만들어둔 정산 연기 로직이 나중에 처리합니다."*
- 원문이 그 순간에 일어났다고 말하는 것은 **지급이 아니라 수락**이다. 화면이 주장하는 것도
  「되튕기지 않았다 + 수락」까지다. **원문과 시점이 정확히 같다.**
- 「안 건넨다」는 **주장을 빼는 것**이지 「영영 안 준다」를 주장하는 것이 아니다. 후불 정산은
  ③버리기로 통째로 뺐으므로(`excluded` 4번) 그림이 「나중에 준다」를 주장할 근거가 없고,
  주장하면 오히려 규격 위반이다. 작성팀 논거가 맞다.
- 🔑 그리고 이 수정은 **원문 위반보다 무거운 결함을 먼저 지웠다** — 닿는 그림은 S1·S2 가
  「목수 주머니에 이미 4개」라고 세워 둔 것과 **자기 앞 샷 모순**이었다(4+5>8).
  검수 1차가 🟡 로만 올린 것을 작성팀이 더 정확하게 진단했다.

🟡 관찰(반려 아님): S3 의 라벨 없는 읽기는 **앞 세 그림의 기억에 기댄다.** 정지 화면 한 장만
보면 「왜 저기서 멈췄지」가 남는다. 회차 안에서 SH·S1·S2 가 그 기억을 세 번 깔므로 영상으로는
성립한다. 다음 회차가 **「안 돌아옴」을 첫 등장 도형으로 쓰면 안 된다** — 이 편은 앞에 셋을
깔아서 성립한 것이다.

🟢 **11개 전부 소수 셋째 자리까지 일치.** `ep10s-2`·`ep12s-1` 에서 검수 상관표가 재현 안 됐던
이력이 있는데(내 memory) **이번엔 한 값도 안 틀렸다.**

### 6-2. 🔴 그런데 **형제가 둘이 아니라 셋이다** — 검수 전수가 또 전수가 아니었다

`episodes/*/scene.json` 의 `sfx` 를 내가 전수로 뽑았다:

```
ep14s-2 S3  latch dur=0.21 seed=233
ep14s-3 S3  latch dur=0.21 seed=223
ep14s-4 S3  latch dur=0.21 seed=229   ← 검수가 안 봤다
```

**세 편이 전부 `dur 0.21` latch 를 「해결 샷(S3)의 확정」 자리에 쓴다.** 삼각형 실측:

```
14-2 ↔ 14-3   r = 0.7939
14-2 ↔ 14-4   r = 0.7924
14-3 ↔ 14-4   r = 0.8026
```

**판정은 안 바뀐다**(아래 대역 참조 — 셋 다 정상 대역 안이고 발행분 최댓값보다 낮다).
그러나 「형제 대조를 했다」는 이 회차 세 층의 서술은 **한 편을 빼놓고 한 것**이다.
이 파이프라인에서 「전수」가 전수가 아니었던 **일곱 번째** 사례다.

### 6-3. 🔴 대역을 여기 박는다 (다음 회차는 이 수를 쓴다)

리포의 **latch 전 인스턴스 25개 · 300쌍**을 전수로 쟀다.

| | 값 |
|---|---|
| 전체 대역 | **0.629 ~ 0.998** |
| **기본 seed(7) 쌍 제외 대역** | **0.628 ~ 0.845** · 중앙 **0.765** |
| 최댓값 0.9976 | `(0.14, 기본7)` ↔ `(0.16, 기본7)` = **seed 미지정 두 편**(둘 다 발행됨) |
| 발행분 중 이 편 쌍보다 높은 쌍 | **26 / 231 (11%)** |

🔴 **세 층이 전부 대역을 좁게 적었다** — 작성팀 「0.68~0.79 가 하한」 · 검수 「0.76~0.83 을
못 벗어난다」·「0.713~0.815」. **셋 다 실측이 아니다.**

> **정본 잣대 (이 판정서가 세운다)**
> - `latch` 파형 상관 **0.85 이하 = 이 합성기의 정상 대역. 그 수만으로는 반려할 수 없다.**
>   몸통이 340/680Hz 고정이라 seed 를 아무리 갈아도 이 아래로 못 내려간다.
> - **0.99 대는 seed 미지정 신호다** — 파형이 안 갈린 것이지 대역이 넓은 것이 아니다.
> - 🔴 **`thud` 는 `seed` 로 못 가른다**(`rng` 미호출). `(dur, freq)` 가 파형을 결정하므로
>   `freq` 를 반드시 명시한다. 이 편은 `246` 을 박았고 r −0.055 로 완전히 갈렸다. **옳다.**

### 6-4. 🟡 코디네이터 몫 (반려 아님)

파형은 갈렸지만 **연출은 세 편이 같은 소리 문장**이다 — 14-2·14-3 이 「막힘 thud → 확정
latch」로 완전히 같고, 14-4 도 확정 자리에 latch 를 쓴다. 승인 선례(`ep12s-1`·`ep12s-3`
둘 다 thud+drop)가 있어 **이 편의 반려 사유가 아니고**, 병렬 집필이라 작성팀 과실도 아니다.
넷을 한자리에서 보는 코디네이터가 한쪽을 갈고 싶다면 **`ep14s-4` 를 갈아라** — 그 편은
`latch + sweep` 이라 latch 를 다른 kind 로 바꿔도 소리 문장이 안 무너지고, `delayMs` 가
`since()` 축이면 재계산 0 이다. **`ep14s-2` 는 손대지 마라**(길이 여유 0.7초 · §8).

🟢 피크 천장 — `synth('latch',{dur:0.21,seed:233,gain:0.064})`·`synth('thud',{dur:0.23,freq:246,gain:0.066})`
둘 다 경고 0. gain 인하 불필요.
