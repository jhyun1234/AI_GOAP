## 🔴 A. S4 페이오프 — 화덕이 「마을 경계」 밖에 있다

### 증거

`kinds/spread.js`

```js
const R_IN = 50, R_OUT = 96;
const HEARTH_OFF = 46;
...
dashRing(R_OUT, 9, 8, -t * 10, ...);              // 「마을 경계」 = 반지름 96
...
const r  = lerp(R_IN, rOf(s.ratio), move);        // 집
const hr = r + HEARTH_OFF;                        // 곁불 = 집보다 46px 바깥
```

`rOf` 로 푼 최종 반지름:

| 자리(deg·비율) | 집 r | 화덕 r | 경계(96) 기준 |
|---|---|---|---|
| 221 · 0.10 (순둥이) | 50.0 | **96.0** | 경계 위 |
| 125 · 0.25 | 58.1 | **104.1** | 밖 |
| 269 · 0.50 | 71.7 | **117.7** | 밖 |
| 5 · 0.50 | 71.7 | **117.7** | 밖 |
| 173 · 0.80 | 87.9 | **133.9** | 밖 |
| 317 · 0.95 (떠돌이) | 96.0 | **142.0** | 밖 |

**집 여섯은 전부 경계 안(≤96)인데 화덕 여섯은 전부 경계 위·밖(≥96)이다.** 경계 고리가
집과 자기 화덕 사이를 물리적으로 가른다.

스틸로 확인했다 — `build/stills/25.89s.png`(S4 자막 0, 곁불 다 켜진 시점)과
`build/stills/28.26s.png`(이름 켜진 시점) 둘 다 **점선 원 안에 흰 집 여섯, 원 밖에 초록 삼각 여섯**이다.

### 왜 반려인가

1. **자막과 그림이 서로 다른 말을 한다.** 같은 순간의 자막은 「각자 **집 옆에** 화덕을 놨더니」다.
   화면은 「화덕은 마을 밖에 있다」로 읽힌다. (사람 몫 5 — *나레이션이 A 를 부르는데 화면이 B 를 켜면 반려*)
2. **원문에 없는 배치다.** 원문은 *"자기 집 곁에 짓게 했습니다"* 이고, 경계는 정착의 상한이다
   (*"맵이 100칸이면 실효 반경이 40칸이 되고, 집들이 4칸에서 38칸 사이에 흩어집니다"*).
   원문 어디에도 화덕이 마을 경계 밖에 선다는 말이 없다.
3. **작성팀이 자기 그림을 틀리게 서술했다.** `shots[S4].reads` = *"**바깥에는** 마을 경계 고리가 돌고"*.
   실제로는 고리가 화덕보다 **안쪽**이다. `spread.js` 머리 주석의 좌표 예산(35~38행)도 라벨·글로우만
   따졌고 **고리와 곁불의 안팎 순서를 한 번도 안 봤다.** = 이 프레임을 실제로 확인하지 않았다는 뜻이다.
4. 🟡 (`ADR-V25-15` · 마스터 판단 요청) 라벨을 다 지우고 보면 이 그림은 *"여섯 집이 원 안에 있고
   원 밖에 삼각형 여섯이 있다"* 로 읽힌다. 작성팀이 `notes.라벨을 가려도 읽히는가` 에 적은
   *"그 점이 여섯으로 나뉘어 **각자에게 하나씩 붙는다** ✅"* 는 스틸에서 확인되지 않는다.
   **첫 적용 회차라 이 4번만은 단독 반려 사유로 쓰지 않고 🟡 로 올린다** — 1~3번으로 반려한다.

### 고칠 방향 (자막 0자)

한 가지 예시일 뿐 선택은 작성팀 몫이다 — **화덕이 전부 경계 안에 들어오면 된다.**
예: `R_OUT` 을 **집의 최대 반지름**과 **고리 반지름**으로 분리해서, 집을 `R_IN 50 ~ 74`,
화덕 오프셋을 `46 → 22`, 고리는 96 에 그대로 두면 화덕 반지름이 72~96 이 되어 전부 안쪽이다.
떠돌이 집은 74, 그 화덕이 96(경계 위)이라 **원문의 「마을 경계 **근처**」와 오히려 더 맞는다.**
🔴 바꾼 뒤 흰색/강조색 분리(현 규약 = 반지름 오프셋)와 가장자리 예산을 다시 풀고 게이트를 다시 돌릴 것.

## 🔴 B. 실제 렌더 fps 에서 정적 3.0초 초과

### 증거 ① — 같은 게이트, 실제 렌더 fps

`render.mjs:32` 가 `const FPS = Number(flag('fps', 30))` 이므로 **납품되는 mp4 는 30fps** 다.
그 fps 로 같은 게이트를 돌리면:

```
ep14s-4  ⚠  정적 구간 3초 이하   S3 3.2s, S4 5.2s
```

### 증거 ② — 통제군 (승인·완주 회차 셋, 같은 명령)

| 회차 | `--fps 30` 정적 최대 |
|---|---|
| `ep13s-3` | 1.2s |
| `ep13s-1` | 1.7s |
| `ep12s-3` | 1.1s |
| **`ep14s-4`** | **S3 3.2s · S4 5.2s** |

즉 **fps 를 올리면 아무 회차나 걸리는 표집 아티팩트가 아니다.** 이 회차만 바닥 아래다.
(기본 5fps 는 표본 간격이 200ms 라 같은 움직임이 6배로 잡혀 0.6s 로 통과한다 — 게이트가
무른 게 아니라 이 편의 움직임이 렌더 눈금에서 사라진다.)

### 증거 ③ — 판정식을 직접 복제해 프레임간 m 을 쟀다

30fps 인접 프레임을 스틸로 뽑아, 게이트와 같은 식(휘도 `(r*77+g*151+b*28)>>8` · 3픽셀마다 ·
평균 |Δ|/255)으로 비주얼 영역을 쟀다. 게이트 문턱은 `m < 0.0008` 이면 정지다.

| 구간 | 프레임 쌍 | m | 문턱 대비 |
|---|---|---|---|
| S4 꼬리 | 28.2000s ↔ 28.2333s | **0.000105** | 7.6배 아래 |
| S4 꼬리 | 28.2333s ↔ 28.2667s | **0.000117** | 6.8배 아래 |
| S3 꼬리 | 17.4000s ↔ 17.4333s | **0.000413** | 1.9배 아래 |

원인은 `notes.정적 구간 대책` 이 「면적이 있는 움직임」이라고 적은 것들이 **30fps 한 프레임 단위로는
면적이 없다**는 데 있다:

- `spread` — 「마을 경계 고리(둘레 603px)의 점선」은 `-t * 10`(°/s)이라 한 프레임에 **0.33° = 호 0.56px**
  움직이고, 색이 `track`(흰색 12%)이라 휘도 기여가 거의 0 이다. 곁불 맥동은
  높이 `13+3·hp`, 각속도 3.4rad/s → 한 프레임 **최대 0.34px**.
- `tether` — 자막 1 구간의 「여섯이 함께 숨 쉬는」 폭이 `4·(1+sin(4.2·s))`, 한 프레임 **약 0.56px**.

### 고칠 방향 (자막 0자)

각속도/진폭을 올리거나 면적이 큰 요소를 하나 더 돌리면 된다. 예: `spread` 의
`dashRing(..., -t * 10, ...)` 를 `-t * 40` 대로, 곁불 맥동 진폭 3 → 6;
`tether` 의 숨 각속도 4.2 → 8 대. **바꾼 뒤 `--fps 30` 으로 다시 재서 3.0초 아래를 보이고,
같은 명령으로 결정성 1,126프레임 불일치 0 도 다시 확인할 것.**

## 5. 🟡 남는 정정 5건 — 전부 **주석의 수**이고 그림은 안 고쳐도 된다

작성팀의 좌표 산수에 **일관된 누락 하나**가 있다: `lineWidth 3` 의 **절반(1.5px)** 을 안 더한다.
모든 여유가 실제보다 1.5~3px 넉넉하게 적혀 있다. **다섯 곳 전부 실측값이 여전히 양수라
지금 그림을 고칠 이유는 없지만**, 다음 사람이 이 수를 믿고 값을 조정하면 그때 뚫린다.

| # | 주석 | 적힌 값 | 실측 |
|---|---|---|---|
| ① | `spread` 269° 곁불 ↔ 경계 윗선 | 5.8px | **4.37px** |
| ② | `spread` 집↔곁불 최악 자리 | 317° 3.8px · 221° 4.7px | 최악은 **125° 1.95px** (불투명끼리 8.95). 키 큰 불꽃(h 20)+글로우 7 을 `x±10 · y−13~+11` 로 과소 모델했다 |
| ③ | `tether` 불 글로우 반경 | r ≤ 29.5 | **31.0** (stroke 1.5). 다만 삼각형 실측 최소 여유는 **5.97px** 로 원 근사보다 넉넉하다 |
| ④ | `tether` 당김줄 끝 = 「글립 가장자리 4px 앞」 | 4px | 317°·125° 처럼 **모서리로 마주보는 자리**는 글립 모서리가 중심에서 18.4px 라 불투명끼리 **약 1.9px**. 🔑 **1차본과 같은 값이라 이번 수정의 회귀가 아니다**(내가 1차에서 안 쟀다) |
| ⑤ | `tether` 통로 vs 125° 집 오른쪽 끝 | x 161.2 (13px) | **x 162.75 (11.75px)** |

**처방**: 위 다섯 수만 주석에서 고치고, **각 kind 머리에 「모든 여유는 `lineWidth/2 = 1.5` 를
포함한 값」이라고 한 줄 박아 둘 것.** 그림·자막·게이트에 영향 0.
