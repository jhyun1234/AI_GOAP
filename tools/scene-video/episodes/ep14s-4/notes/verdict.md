## 3. 🔴 검수 처방 판정 — **방향은 맞고, ④ 한 줄에서는 처방이 틀렸다**

검수의 진단(「`lineWidth/2 = 1.5px` 를 안 더한다」)은 **참이고 중요하다.** 다섯 중 ①②③⑤ 는
내 재계산과 일치한다(269° **4.4px** / 125° **1.95px** / 불 글로우 **31.0** / 통로 **x 162.75 · 11.75px**).

🔴 **그러나 ④ 는 재현되지 않는다.** 검수는 「불투명끼리 약 1.9px」이라 적었다.

```
당김줄 끝 = 집 중심에서 18px  ·  집 글립(box+지붕, 획 3) 과의 최소거리
  125° path 4.25 → 불투명 1.25      173° 5.43 → 2.43      269° 6.00 → 3.00
  317° path 3.12 → 불투명 **0.12**   5°  5.92 → 2.92
```

그리고 **렌더가 그 계산을 뒷받침한다** — `20.9s` 프레임에서 317° 집의 왼아래 모서리에서
흰 픽셀과 강조색 픽셀이 **1 디바이스px(0.36 CSS px) 거리로 맞닿고, 혼합 픽셀이 4~7개 생긴다.**
(같은 잣대로 형제 셋의 본문 샷은 전부 혼합 0 · 최소 3.27 CSS px 이상이다.)

**판정 셋:**

1. 🟢 **반려 사유가 아니다.** ⓐ `check.mjs` 실패 0 이고, 3색 팔레트 게이트는 **허용된 두 색의
   안티에일리어싱 혼합을 위반이 아니라고 스스로 선언**한다(`check.mjs:605`). ⓑ 5배 확대해 보면
   「강조색 줄이 집에 걸린다」로 읽혀 **자막 「모닥불이 중력이었죠」의 뜻을 오히려 돕는다.**
   ⓒ `git diff 4a70dd48` 로 확인 — `rEnd = p.r − 18` 도 집 글립도 **1차본과 한 글자도 안 바뀌었다.**
   **검수의 「회귀가 아니다」라는 분류는 옳다.**
2. 🔴 **검수의 처방(「수만 고치고 kind 머리에 한 줄 박기」)은 ④ 에서는 안 통한다.** 수만 고치면
   「0.12px 뜬다」가 되는데, **0.12px 은 「뜬다」가 아니라 「닿는다」다.** 이 자리는 **의도임을
   밝히는 문장**으로 바꿔 써야 한다 — 다음 사람이 「0.12px 여유」를 읽고 1px 을 조정하면 뚫린다.
3. 🔑 **진짜 병은 「1.5 를 빼먹은 것」이 아니라 「그 수가 경로 좌표인지 획 바깥인지 안 적힌 것」이다.**
   ⑤ 처럼 획을 포함한 자리와 ②④ 처럼 안 한 자리가 **같은 문법으로 나란히 적혀 있어서** 검수도
   작성팀도 어느 쪽인지 몰랐다.

**형제 셋에도 있는가 → 있다. 트랙 규칙으로 승격한다.**
`ep14s-2/kinds/everyrow.js:22` 의 「칸 테두리 최대 x = 250.5」는 `cellL(7)+CW = 250.5` 로
**경로 좌표**인데 그 칸은 `lineWidth 3` 으로 그어진다(획 바깥 252.0) → 적힌 여유 7.5px 의 실제는
**6.0px**. 같은 파일의 「표식 x 23~45」도 같다(실제 21.5~46.5).
반면 `ep14s-3/kinds/scan.js:25` 는 **포함해서 적었다**(54 높이 상자를 `y 95.5~152.5` = 57 로).
→ **누락이 아니라 관행이 없다.** 그래서 규칙으로 만들 자리다.
🟢 다만 **형제 셋에 실해는 없다** — 렌더 스틸 23장 전수에서 본문 샷의 흰↔강조색 최소거리가

## 5. 🔴 `ADR-V25-15` ③-b — 표본 재현 완료

**나레이션 발화 개시를 열 줄 전부 내가 다시 쟀다**(10ms 창 RMS, 피크 10% 문턱).

```
00 0.480  01 0.540  02 0.460  03 0.370  04 0.390
05 0.470  06 0.340  07 0.430  08 0.510  09 0.280
```

검수가 적은 「이 편 온셋 0.28~0.54초」와 **열 줄 전부 일치**한다.

`ㅠ_ㅠ` 알파 시간표도 손으로 풀었다.
`α = st · ease((sf−1.5)/0.4) · (1−ease((s1−0.90)/0.35))`, `ease` = smoothstep,
샷 진입 `ENTER 0.26s` 는 `sf 1.9` 시점에 이미 1.0 이므로 곱해도 안 깎인다.

- **α = 1.0 도달 = `sf 1.90` = 절대 18.671s**
- **α 이탈 시작 = `s1 0.90` = 절대 20.865s** → **α 1.0 유지 2.194초** ✅ (검수 2.19)
- 「멀리 살면 굶어요」 줄의 실측 발화 개시 = 19.965 + 0.470 = **20.435s**

⚠️ 검수의 「**1.72초** 앞질러」는 재현되지 않는다. **1.76초**다(20.435 − 18.671). 0.04초 차이라
판정은 안 바뀌지만 **표에 적힌 수는 정정한다.**
🔑 `ep14s-2` 를 반려시킨 형태(최대 α 0.145 · 0.2초 · 말보다 먼저 소멸)는 **이 편에 없다.**

⚠️ 화면 글자 수 — 검수 표는 **11행**, 작성팀 `notes["한국어 라벨"]` 은 **13종**이다.
**둘 다 맞다**(검수가 「안쪽·바깥쪽」과 「순둥이·떠돌이」를 각각 한 행으로 묶었다).
🔴 그래도 **전수 표에는 행 수가 아니라 종 수를 적어라** — 이 파이프라인에서 「전수」가 전수가
아니었던 사고가 일곱 번이고, 그때마다 첫 신호가 **두 층의 개수가 안 맞는 것**이었다.

## 7. 🔴 효과음 — 작성팀이 「예약」이라 적은 것을 내가 대신 갚았다

작성팀은 node 를 못 돌리는 환경이라 **「전수 N건」이라 적지 않고** 파형 결정값만 근거로 남겼다.
🟢 **정직한 처리이고, 그 예약은 지금 갚을 때다**(형제 넷이 다 나왔다). 내가 기계로 셌다.

```
리포 전수 sfx 114건 / 33회차 — tick 25 · latch 25 · thud 20 · drop 16 · sweep 15 · riser 13
```

**절대 표본 정렬 상관**(48kHz, `synth()` 원본 파형, 정규화 위치 리샘플 아님):

| kind | ep14s-4 의 최댓값 | 상대 | 전수 순위 |
|---|---|---|---|
| `sweep` (dur 0.56 · seed 239) | **0.0223** | ep04s-2/S3 | 사실상 무상관 ✅ |
| `latch` (dur 0.21 · seed 229) | **0.8309** | lf02/S19 | 300쌍 중 **5위** |

- 🟢 **형제 넷의 kind 쌍은 안 겹친다** — 14-1 `tick+drop` / 14-2 `thud+latch` / 14-3 `thud+latch` /
  **14-4 `latch+sweep`**. (14-2 와 14-3 이 같은 쌍인 것은 그 두 편의 문제이고 이 편은 아니다.)
- 🔴 **그런데 `latch` 자체가 최근 6편 중 5편에 있다**(13-1 · 13-2 · 14-2 · 14-3 · 14-4).
- 🔴 **그리고 `latch` 는 `seed` 로 거의 안 갈린다.** `sfx.mjs:73-84` 에서 몸통은
  **340/680Hz 고정 + `dur` 이 정하는 포락선**이고, `seed` 가 만지는 `click` 은 `exp(−260t)` 라
  **210ms 중 앞 15ms** 뿐이다. 세 형제가 **`dur` 을 0.21 로 똑같이** 썼다 → 갈림은 seed 뿐:
  14-3↔14-4 **0.8001** · 14-2↔14-4 **0.7943**.
  전수 latch 쌍의 분포는 **0.637~0.841**(공지된 돌려막기 `ep02s↔ep03s` 0.9976 제외)이라
  **0.83 은 그 가족의 천장 근처지만 이상치가 아니다** — 2·3·4위가 각각 0.8408·0.8378·0.8346 이고
  그중 둘이 **이미 승인된 14-2·14-3** 이다.

**판정: 통과.** 사유 = ⓐ `ep13s-3` 선례와 같은 형태다(그 편 `thud` 0.873 을 「8위라 통과」로 냈고,
진짜 원인은 개별 회차가 아니라 **`freq` 기본 150 관행**이었다). ⓑ 여기서도 원인은 회차가 아니라
**`latch` 의 몸통이 결정론적이라는 kind 설계**다. ⓒ 이 편만 반려하면 값이 더 나쁜 형제 둘이
이미 나간 상태에서의 불일치가 된다.
🔴 **다음 회차 이행 조건으로 올린다 → §9-3.**

`delayMs` 는 둘 다 `since()` 원점이라 **TTS 재생성에 면역**이다(`render.mjs:114` 가
`line.t + delayMs`). 실측 재계산 필요 0 — 이 편의 설계 성과이고, 그대로 다음 편에 물려라.
