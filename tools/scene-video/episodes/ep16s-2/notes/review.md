## 1. 🔴 반려 ① — 「진동 수」 척도는 틀렸다 (이 편 특수 판정 의무 1)

작성팀이 `tick` 을 고르며 **새 척도**를 세웠다:

> `notes` (S3 `why`) : *"포락선 `atk × exp(−22·t/dur)` 는 dur 로 정규화돼 있어 **정규화 위치로
> 리샘플하면 모양을 정하는 것은 `freq × dur` = 진동 수 하나**다. 그래서 이 축으로 골랐다."*
> *"1차 후보였던 `dur 0.078 · freq 1580` 을 버린 이유가 이것이다 — 진동 수가 123.2 회라
> `ep10s-2`(0.068 · 1830 = 124.4회)와 **1.2회** 차이였다."*

### 실측 — 척도가 상관을 설명하지 못한다

`synth('tick', …, 48000)` 로 리포의 서로 다른 호출 **29종**을 만들어 **절대 표본 정렬** 피어슨
상관을 전 쌍(406쌍) 계산했다.

| 설명 변수 | r 과의 상관 |
|---|---:|
| **\|Δ진동수(freq×dur)\|** | **−0.032** ← 작성팀 척도 |
| \|Δfreq\| | −0.145 |
| \|Δdur\| | −0.067 |

**−0.032 는 「아무 설명도 못 한다」는 뜻이다.** 반례가 양방향으로 다 나온다.

```
진동수가 가장 가까운 쌍들 (척도대로면 가장 위험한 자리)
  Δ진동수=0.4  r=-0.1944  ep05s-2/S3(0.07/1080) ↔ ep12s-2/S1(0.1/760)
  Δ진동수=0.5  r= 0.0117  ep02s/S10(0.09/1050) ↔ ep03s/S9(0.05/1900)
  Δ진동수=0.5  r=-0.1595  ep08s-2/S1(0.062/960) ↔ lf01/S28(0.05/1180)

r 이 가장 높은 쌍들 (실제로 같은 소리인 자리)
  r=0.9998  Δ진동수= 2.4  ep09s-1/S3(0.052/1180) ↔ lf01/S28(0.05/1180)
  r=0.9748  Δ진동수=38.3  ep09s-2/S3(0.075/1420) ↔ lf02/S23(0.048/1420)
  r=0.9875  Δ진동수=12.7  ep07s-2/S4(0.058/1650) ↔ eptest-m11/S9(0.05/1660)
```

**작성팀이 버린 1차 후보를 직접 재 봤다** — 척도가 「1.2회 차이라 위험」이라던 그 쌍이다.

```
tick 0.078/1580 ↔ ep10s-2 0.068/1830  :  r = -0.1940   ← 전혀 안 닮았다. 버릴 이유가 없었다
tick 0.078/1580 ↔ ep05s-1 0.042/1510  :  r =  0.5942   ← 척도가 59.8회 떨어졌다고 안심시킨 쪽이 훨씬 가깝다
```

즉 **척도는 위험을 반대로 가리켰다.** 원인은 전제다 — 「정규화 위치로 리샘플하면」이라고 썼는데
**판정 절차는 정규화 리샘플이 아니라 절대 표본 정렬**이다(`scene-master` 의
`procedure_sfx_waveform_correlation`). 절대 정렬에서 파형의 실시간 주기를 정하는 것은 `freq`
하나이고 `dur` 은 포락선의 감쇠 속도만 바꾼다. 실제로 r 상위 쌍은 **전부 Δfreq ≤ 40** 이다.

### 그래도 값 자체는 통과다 (판정선 0.85)

| 대상 | 최근접 | r | 판정 |
|---|---|---:|---|
| **`tick` 0.095 / 1560** | `ep05s-1/S1` (0.042/1510) | **0.7030** | 🟢 통과 |
| | `lf01/S31` (0.05/1480) | 0.4321 | |
| | `ep07s-2/S4` (0.058/1650) | 0.3167 | |
| **`latch` 0.105 / seed 251** | `ep08s-1/S4` (0.205/83) | **0.7207** | 🟢 통과 |
| | `lf02/S19` (0.2/179) | 0.7181 | |
| | `ep13s-1/S3` (0.135/211) | 0.7127 | |

- `latch` 는 **통제군 중앙(0.7602)보다도 낮다** — 리포에서 가장 개성 있는 latch 다. seed 251 이
  실제로 축을 갈랐다(작성팀 주장 확인).
- `tick` 은 통제군 95%(0.5638)를 넘지만 판정선 0.85 아래다. **다만 「진동 수 17.5회 차이라
  안전하다」는 서술은 우연히 맞은 것**이고, 실제 안전 마진을 만든 것은 freq 1560 이 기존
  1480·1510·1650 과 **50~90Hz** 떨어져 있었던 것이다.
- `gain` 무경고 상한도 실측했다(`0.46 / (peak/gain)`, `synth()` 반환 파형에서 피크):
  **latch 0.0667**(쓴 값 0.056) · **tick 0.0754**(쓴 값 0.060). 둘 다 여유가 있고
  `synth()` 호출에서 **피크 천장 경고가 안 뜬다**(실제 피크 0.3861 · 0.3662 < 0.46).

### 🔴 통제군 정리 — 「같은 호출」을 걸러냈다

기본값을 채운 뒤 인자가 같은 것을 하나로 접었다(잣대 = 「인자를 적었나」가 아니라 「기본값을
채운 뒤 인자가 같나」).
- `latch` 30건 → **29종** (`ep02s/S8`·`_archive/eptest-m11/S10` 이 둘 다 기본 `0.14/seed 7`)
- `tick` 30건 → **29종** (`ep05s-3/S3`·`S4` 가 같은 `0.048/1380`)

**뺀 사실을 적어 둔다** — 안 빼면 `latch` 통제군 최댓값이 그 자기쌍으로 1.0000 이 된다.
접은 뒤의 통제군 최댓값도 여전히 높다(**latch 0.9976** = `ep02s/S8`(0.14/7) ↔ `ep03s/S5`(0.16/**seed 미지정 = 7**) ·
**tick 0.9998** = `ep09s-1/S3`(0.052/1180) ↔ `lf01/S28`(0.05/1180)). **이미 나간 편이라 되돌리지
않는다**(`ADR-V-15`) — 다만 다음 회차가 이 상단을 「안전 근거」로 인용하면 안 된다.

「결정적」·「밀스톤」·「콘솔」·「로그」·「코드 실사」가 **자막·화면에 한 번도 안 나온다.**
「개입」조차 「손을 쓴다」로 바뀌었고 그 표현이 **원문에 실재**한다(「언제까지 손쓸 수 있는가」).
고유명사·게임 안 사물(주민·식량·알림·카메라·마을·지도)은 잣대 대상이 아니다.
🔑 **①풀어쓰기의 재료가 전부 원문 안에 있다** — 지어낸 풀이 0건.

### ② 비유 — `notes.비유` = 「없음」, 실제로도 없다

자막 10줄에 표지(「~같은 거예요」류)가 필요한 문장이 **0건**이다. 「줄을 얹었다」·「걸린다」·
「붙잡는다」는 **화면에서 실제로 일어나는 일의 서술**이고 다른 영역에 빗댄 것이 아니다.
칸이 비어 있지 않고 「없음」이라고 적혀 있다 ✅ → 자막 전 줄을 **사실 대조 대상**으로 다뤘고
(위 §4) 전건 통과.

### 🔤 화면 글자 언어 (`ADR-V-10` 2026-08-10 개정)

**번인 글자 전부 한국어** ✅ 남은 비한글은 기호·수치뿐(`—`·`?`·`0`·`14`) = 예외 ②.
🔑 인용 예외 ①을 잘못 쓰지 않았다 — 원문의 게임 문자열이 **애초에 한국어**라 영어로 옮기면
그게 인용이 아니게 된다. 자막(`lines[].en`)이 영어인 것은 의도한 상태다.

  0.7602 · gain 상한 0.0667)도 §1 과 일치 ✅
- **census 갱신** — 「작성 시점 27건 / 형제 넷이 생긴 뒤 30건 · 서로 다른 호출 29종」으로
  시점을 못박았고, **seed 미사용 목록을 「지금도 미사용」의 근거로 인용하지 말라**는 경고를

  갈아 풀린 실제 사고). ✅ 다음 회차가 쓸 수 있는 형태다.
- `writer.md` §3 에 「🔴 내가 틀린 것」 절이 신설됐고 결론이 **「파라미터 거리로 「안전하다」를
  주장하지 마라 · 못 쟀으면 못 쟀다고 적고 검수에 넘겨라 · 지어낸 수치만 위험한 게 아니라

### 13-4. ④ blurb 형제 경로 — 🔴 **부분 이행 (2차의 유일한 반려 사유)**

🔴 **잣대(2026-08-11 추가 · `ep16s-4` 검수의 형제 전수 발) = 「그 문단만 읽고 시청자가
검색창에 칠 것이 나오는가」.** 이 채널 제목은 전부
`· 유니티 GOAP 개발일지 16-N편 #shorts` / `· Unity GOAP Devlog #16-N #shorts` 로 끝난다 —
**검색 키는 편 번호**이고, 서술만으로는 그 영상에 못 닿는다.

**기계 계수**(정규식 `1\d-[1-5]편` · `#?1\d-[1-5]` · `[Pp]art \d`):

```
ep15s-5  ko ["15-1편","15-2편","15-3편","15-4편"]   4/4
         en ["part 1","part 2","part 3","part 4"]   4/4
ep16s-1  ko ["16-2편","16-3편","16-4편","16-5편"]   4/4
         en ["#16-2","#16-3","#16-4","#16-5"]       4/4
ep16s-2  ko ["16-1편"]                              1/4   ← 뒤 셋이 「뒤에 이어집니다」로만 끝난다
         en []                                      0/4   ← 앞 편조차 번호가 없다
```

- **ko** — *"…이야기가 16-1편이고, 마을 명부를 만들었더니 …이야기, 죽으면 …이야기, 그리고 같은
  판을 …이야기가 **뒤에 이어집니다**."* → 16-3·16-4·16-5 에 검색 키가 없다.
- **en** — *"Before this: … / Still to come: …"* 로만 나눠 **번호가 0개**다.
  `Part 2 of 5` 는 **자기 자신의 번호**라 형제 경로가 아니다. 형제 넷 어느 쪽으로도 못 간다.
- 🔑 **문안을 새로 지을 필요가 없다** — `ep16s-1` 이 이미 같은 사건을 같은 말로 부르며 번호를
  달아 뒀다(`… 이야기는 16-3편, … 16-4편, … 16-5편` / `… is #16-3, #16-4, #16-5`).
  **그 형식으로 통일하면 끝난다.**
- 🔑 이건 「형제 문구를 안 썼다」가 아니라 **「썼는데 검색 키를 뺐다」**이다. 아래 §13-4-B 의
  대조·수치 검사는 **전부 통과**이므로 **번호만 끼워 넣으면 된다.**

**everyone else**` 는 앞 문장 `graves` 와 이웃해 「묻었다 = 죽였다」로 읽힐 여지가 있었는데,
`buried **under his own record**` 로 바뀌어 **「기록을 덮었다」가 명확해졌다.** 원문
(「한 사람이 명부를 통째로 덮었다」)과도 더 가깝다.

### 14-3. 수치 누출 재검사 ✅ · 남기는 배치 관찰 둘

- 🔴 **형제 소유 수치 누출 0건** — ko+en 꼬리 전체에서 `Day 45`·`일곱`·`7개`·`Seven`/`seven`·
  `아홉`·`9번`·`nine`·`×9`·`×11`·`서른`/`thirty` **전부 0회**.
  🔑 특히 16-1 을 부르면서 그 편 제목의 `Seven` 을 **안 가져왔다** — §3-C 계약을 지킨 것이다 ✅
- 🟡 **(배치 · 이 편 사유 아님) `ep16s-1` 만 en 형식이 다르다.** 다섯 편 중 넷이 발행 정본
  `… is part N` 인데 `ep16s-1` 만 `… is #16-2/#16-3/#16-4/#16-5` 다. 어느 쪽이든 계수는
  4/4 로 통과하지만 **한 배치 안에서 두 형식이 섞인다.** 코디네이터 판단 사항.
- 🟡 **(배치) 같은 편을 부르는 영어 문구가 두 갈래다.** 16-3 = `buried under his own record`
  (`ep16s-2`·`ep16s-5`) vs `buried all by himself`(`ep16s-1`) vs `buried single-handedly`
  (`ep16s-4`). 16-1 = `graves with no names on them`(`-2`·`-3`·`-5`) vs `graves that had no
  names on them`(`-4`). **이 편은 다수파(`-3`·`-5`)와 축자로 같으므로 사유가 아니다.**
