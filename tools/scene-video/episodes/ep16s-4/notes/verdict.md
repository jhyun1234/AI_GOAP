## 3. 🔴 길이 천장 0.14초 — **재합성 오차는 0이다** (직접 검증)

이 편의 유일한 실질 위험이라 코드 경로까지 따라갔다.

**⒜ 실측 재검산 (내가 다시 합산)**
`build/timed.json` 10줄의 `dur + pause` 합 = **35,758ms** → check 의 「자막 35.8」과 일치.
`+ 꼬리 2,100ms` = **37,858ms**. → **fail 38,000 까지 여유 142ms.**

**⒝ `timed.json` 이 `scene.json` 보다 오래된 것(12:45:51 vs 13:21:33)이 위험인가 → 아니다**
`say` 10줄 · `pauseAfter` 10개를 `timed.json` 과 한 줄씩 대조: **불일치 0건.**
2차 편집은 발화에 안 닿는 칸(`outro.siblings`·`notes`·`blurb`)이었다.

**⒞ `publish --prepare` 가 TTS 를 다시 돌리는가 → 돌린다. 그런데 재합성은 0줄이다**

```
publish.mjs:625-626   needTts = timed.json.mtime < scene.json.mtime   → true (재실행된다)
tts.mjs:64-69         키 = FNV-1a(`${voice}|${speed}|${steps}|${say}`)  ← 인덱스가 아니라 내용 해시
tts.mjs:86-93         같은 해시 파일이 있으면 재사용(reused), dur 은 그 파일에서 다시 읽는다
```

→ `say` 가 한 글자도 안 바뀌었고 **wav 10개가 전부 디스크에 있다**(전수 확인).
**10줄 전부 캐시 재사용 → `dur` 이 바이트 단위로 동일 → 37.858초가 그대로 재현된다.**
🔑 **즉 0.14초 여유는 「운 좋게 남은 값」이 아니라 「고정된 값」이다.** 이 상태로 내보내도 된다.

**⒟ 🔴 판정서에 박는 것 — 이 편은 어떤 후속 수정도 재실측 필수**

> **`ep16s-4` 는 fail 38 까지 142ms 뿐이다. 아래 셋 중 하나라도 일어나면 그 순간 37.9초는

> ⓒ 🔴 **`voice.json` 의 `voice`·`speed`·`steps` 변경** — 캐시 키가 통째로 바뀌어 **10줄 전부 재합성**된다.
>   이 편은 형제 편 수정이나 전역 음성 조정에 **가장 먼저 깨질 회차**다.
> ⓓ `build/audio/*.wav` 삭제 (캐시 소실 → 재합성)
>
> 🔑 **자막을 안 건드리는 수정(`blurb`·`notes`·`source`·`why`·`outro.siblings`)은 안전하다** —
