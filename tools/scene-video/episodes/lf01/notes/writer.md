## 2. 아크를 어떻게 잡았나

브리프 §1 의 권장 묶음(콜드오픈=① / 챕터1=②③ / 챕터2=④ / 챕터3=⑤ / 챕터4=⑥ /
챕터5=⑦ / 마무리=⑧)에서 **⑥만 둘로 쪼갰다.**
⑥은 표현층(M13)과 위협 축(M10)과 화폐(M19)를 한꺼번에 안고 있어 그대로 두면
10샷 3분짜리 챕터가 되는데, 문법 §1 이 챕터를 「각 1~2분」으로 못 박았다.
그래서 「화면」(표현층)과 「늑대」(위협 축 + 화폐 두 줄)로 갈랐고, 결과가 챕터 6개다.

챕터 칩에 뜨는 이름은 전부 **그 챕터 안에서 벌어지는 일**로 잡았다 —
습격 / 재설계 / 정적 / 역설 / 화면 / 늑대 / 지금 / 기록.
「콜드 오픈」·「마무리」처럼 제작 용어를 칩에 띄우지 않았다(시청자의 말이 아니다).

### 열린 고리 4개

1. **무덤.** 콜드 오픈의 클립(`strike-farm-...-139`) 왼쪽에 무덤 `C · Day 9` 가 있는데
   대본은 그걸 부르지 않는다. S20 에서 「맨 처음 늑대 장면에서 화면 왼쪽에 있던 그
   무덤이 이겁니다」로 회수한다. 브리프 §2① 이 짚어 준 고리를 그대로 썼다.
2. **답 없는 질문.** S13 에서 질문 두 개를 세우고 하나에만 답을 붙인다. 남은 질문
   (「림월드는 뭐가 다른가」)은 카드 위 검토 밴드가 계속 훑고 있고, S15 가 답한다.
3. **가려진 사슬.** S16 이 「가장 안 보이는 상태」로 닫히고, S17 이 그 가리개를 걷는
   것으로 챕터4가 열린다.
4. **세우자마자 뒤집기.** S28 이 방어 건설을 세우고, S29 가 바로 그 전제를 무너뜨린다
   (「울타리를 세우면 킬박스가 아니라 완전 무적」).

## 3. 그림 — 이 회차의 기본 도형은 「하나의 축 위에 두 값」

샷마다 그림을 따로 고르면 남의 회차 어휘가 섞인다. 그래서 **축을 먼저 정하고**
챕터마다 축만 갈아 끼웠다.

| 축 | kind | 얹힌 두 값 |
|---|---|---|
| 코드 총량 | `shrink` | 24,800 / 5,977 |
| 겨울 비축 | `stock` | 562 / 1,110 |
| AI 유능함 | `paradox` | 재미 / 플레이어가 할 일 |
| 마을 규모 | `threatladder` | 티어1(밭) / 티어2(사람) |
| 시간 | `northstar` | 마을 규모 / 위협 티어 |
| 수리 시간 | `repairrate` | 주민 1 / 목수 5 |

축을 고정한 덕에 대비가 **색이 아니라 길이**로 읽힌다 — 3색 팔레트에서 대비를
색으로 만들려는 유혹이 애초에 안 생긴다.

### 되받기는 딱 두 번, 그리고 둘 다 뒤집는 자리

- `planchain` : phase 0(챕터1, 사슬이 선다) → phase 1(챕터3, 같은 사슬을 가리개가 덮는다)
- `logscreen` : phase 0(챕터2, 콘솔에만 쌓인다) → phase 1(챕터4, 그 줄이 화면으로 건너간다)

같은 kind 를 두 번 쓰는 이유는 **같은 그림이어야 뒤집힘이 보이기 때문**이다.
나머지 22샷은 전부 다른 그림이고, 다른 회차에서 파일을 가져온 것은 하나도 없다.

### 정적 대책 — 계속 도는 것을 뜻으로 골랐다

wide 무대의 캔버스는 약 **649 × 246 CSS px** 로 세로 회차보다 넓다. 작은 표식만
움직이면 픽셀 변화량이 정적 검사 문턱(프레임 평균 0.0008) 아래로 떨어진다.
그래서 kind 마다 자막과 무관하게 도는 것을 하나씩 뒀는데, **장식이 아니라 그 마디의
대사**로 골랐다:

- `refusal` 되돌아오는 명령 토큰 — 거부는 한 번 일어난 사건이 아니라 규칙이다
- `logscreen` 멈추지 않는 콘솔 스크롤 — 로그는 언제나 쌓이고 있었다
- `stock` 평평한 긴장 계기 — 아무 일도 안 일어나는 상태가 계속된다
- `twoq` 답 없는 질문만 훑는 검토 밴드 — 열린 고리를 화면에 남긴다
- `gravemark` 퍼지는 흔적 링 — 주석이 약속한 「영구 흔적」이 실제로는 이 원 하나뿐이었다
- `notifystack` 칸 하나를 번갈아 차지하는 사건들 — 덮어쓰기는 그때 계속 돌던 구조다
- `siege` 반복되는 출몰 시도 — 어떤 국면에서는 스폰 자리에서 그대로 취소된다
- `motion5` 계속 휘둘러지는 도구 — 「정지 그림의 끝」을 말하는 샷이 멈추면 자기모순이다
- `closing` 기준선을 넘나드는 비축 — 「아슬아슬해야 한다」가 목표치다

🔴 **초안에서 다섯 군데를 고쳤다.** 처음엔 연속 모션을 전부 cue 뒤에 걸었는데,
첫 자막 구간이나 중간 자막 구간이 통째로 멈추는 곳이 생겼다:

| 샷 | 증상(추정) | 고친 것 |
|---|---|---|
| S4·S16 `planchain` | 첫 자막 약 2.7초 정지 | 흐름 표식을 cue 게이트에서 빼 항상 돌게 |
| S14 `paradox` | 첫 자막에 3px 축선만 자람 = 문턱 바로 아래 | 유능도 표식을 항상 돌게(곡선 전엔 축 위에) |
| S15 `seats` | 첫 자막 정지 + 둘째 자막 정지 | 판 등장을 cue(0)으로 당기고 흐름을 판 등장에 묶음 |
| S19 `notifystack` | 둘째 자막 약 3.5초 정지 | 칸 순환 시작을 cue(2) → cue(1) 로 |
| S31 `motion5` | 셋째 자막 약 4.2초 정지 | 칸 등장을 `(cue(2)+cue(3))/2` 로 두 자막에 걸침 |

산수로 잡은 것이라 **픽셀 실측은 검수/렌더 때 다시 봐야 한다.**

### 가장자리·팔레트

- 모든 요소를 안쪽 10px 이상에 뒀다. 특히 반경이 자라는 링 둘은 상한을 계산해서 박았다 —
  `nearest` 의 거리 링은 반지름 108(중심 y 120 · 캔버스 246), `gravemark` 의 흔적 링은
  R+52. 이 값을 안 박으면 링이 아래 가장자리에 닿아 잘림 검사가 red 를 낸다.
- 반투명 흰 막으로 덮는 방식을 한 번 썼다가 **불투명 검정 + 빗금**으로 바꿨다
  (`planchain` 가리개). 흰색과 강조색이 같은 픽셀에서 섞이면 팔레트 검사가 통과시켜 버려
  게이트가 못 잡는 자리가 된다.
- 캔버스 글자는 전부 폭을 재서 넣거나(`record`·`closing` 은 `measureText` 로 폰트를 줄인다)
  고정 폭 안에 클립했다.

## 5. 사실 정직성

- **모든 수치·인용은 브리프 §2·§3 의 원문 문장에서만 가져왔다.** 각 샷 `source` 에
  파일 경로와 행 번호를 적어 뒀다(문법 §5-3 「출처가 안 달린 단언은 반려」).
- 브리프 오염은 **없었다.** 표 조각(`|` 구분)·CSS 조각·문장이 아닌 단어 나열을 찾지
  못했다. 브리프 §0-4 가 밝힌 대로 발췌가 전부 산문 문장이다.
- **원문에 없는 값은 그리지 않았다:**
  - `gravemark` 의 좌표는 값(`(41, 17)`)이 아니라 **형식**(`( x , y )`)으로 그린다.
    원문은 「남은 건 좌표뿐이었습니다」라고만 한다.
  - `nearest` 는 거리 순위 규칙 이름(`RANDOM` → `NEAREST FIRST`)만 바꾸고 거리 숫자를
    안 적는다.
  - `threshold` 아래의 두 시간 막대에는 **눈금을 넣지 않았다.** 원문이 말한 것은
    「어느 쪽이 더 길었나」뿐이고 비율은 원문에 없다.
  - `notifystack` 의 알림 칸에는 번호(`#1`~`#7`)만 띄운다. 그때 무슨 문장이 떠 있었는지는
    원문에 없다.
  - `bondcut` 은 정리 함수 이름을 안 쓰고 `CLEANUP()` 으로 뒀다. 원문은 「주민이 사라질 때
    호출되는 정리 함수」라고만 부른다.
- **울타리·문·계획 고스트를 「화면에서 보고 있다」고 쓰지 않았다.** 그 클립이 이번
  수확에 0개이기 때문이다(브리프 §0-1). S28·S31 은 캔버스로만 그렸고, 캔버스 샷에는
  「지금 빌드 화면」 배지가 붙지 않으므로 화면이 스스로 사실관계를 지킨다.
- **화폐(S26)는 전부 과거 완결형이다** — 「지었다가 허물었습니다」·「같았거든요」.
  ADR-LF-7 · 브리프 §0-3. 두 줄로 묶은 것도 브리프의 🔴 지시(「한두 문장, 더 늘리지 말 것」)다.
- **쇼츠 유도는 회차 전체에서 한 번**, 마지막 줄에서만 한다(브리프 §5). 거기서
  재설계·늑대·화폐를 이름으로 부르는데, 화폐(M16~M18)가 `BLOG_COVERAGE.md` 대기열에
  있으므로 ADR-LF-7 의 「궤도 위에 있는 소재에만 약속」 조건을 만족한다.

### 화면 라벨의 언어

판정 잣대(「코드나 인스펙터에 그대로 있을 법한 말인가」)를 그대로 적용했다.

- **영어**: `Goal_P0_Hunger` · `HarvestCrop` · `CookMeal` · `EatCookedFood` ·
  `MineStone.asset` · `Threat_Tier1_Wolf` · `Threat_Tier2_Pack` · `DURABILITY` ·
  `ALERT SLOT` · `NEAREST FIRST` 등. 앞의 일곱은 **실제 파일·카탈로그에서 확인한 이름**이다
  (`Assets/M0Config/Goals`·`Actions` · 클립 카탈로그 `detail`).
- **한국어**: 자막 전부, 판정 서술(「완전 무적」·「성장이 위협을 부른다」·「가장 안 보이는
  상태」), 그리고 고유명사(`고집쟁이`) — 이 이름은 소스에 한국어 문자열로 실재한다.
- `motion5` 의 다섯 칸(도끼질·곡괭이질·괭이질·망치질·맨손)은 **명세서 원문 서술 그대로**라
  한국어로 뒀다. 셋째 칸에 정정(괭이 → 물뿌리개)이 붙는 것도 devlog 원문 그대로다.

## B-9. R6 — S23 자막 1 「무덤 두 기 / 왼쪽」 (반려)

**틀린 것이 둘이었다.**

| | 내가 쓴 것 | 화면 실측 |
|---|---|---|
| 개수 | 두 기 | **네 기** (회색 비석 픽셀 군집 4) |
| 방향 | 「그(경보줄) **왼쪽**」 | x = 1066·1391·1498·1715 → **전부 오른쪽 절반** (경보줄은 x<320 좌상단이므로 정확히 반대) |

고친 줄:

> ~~그리고 그 왼쪽에는 / 무덤 두 기가 서 있고요.~~
> → **그리고 화면 오른쪽에는 / 무덤이 서 있고요.**

**개수를 안 세는 쪽(review.md 의 (b)안)을 골랐다.** 이유가 둘이다.

1. 🟡 검수가 같은 문서에서 짚었듯, HUD 가 우측으로 옮겨 가면서 무덤 한 기
   (x≈1715, y≈106)가 제목 `왜 GOAP로 만드는가` 뒤에 부분적으로 잠긴다.
   화면에 넷이 있어도 **시청자가 셀 수 있는 것은 셋**이라, (a)안(「네 기」)을 쓰면
   "화면과 맞다"와 "보는 사람이 세면 맞다"가 갈린다. 방향만 말하면 어느 쪽으로도 안 틀린다.
2. 자막 길이를 그대로 두려면 세지 않는 쪽이 맞았다 — 새 줄은 구두점·공백을 뺀 글자 수가
   **17자로 옛 줄과 정확히 같다.** 그래서 아래 「길이」 정정값(485.0초)이 이 수정 뒤에도
   유효하다. 줄을 늘렸다면 방금 받은 실측이 또 낡았을 것이다.

`source` 에 실측 흔적을 남겼다 — 스틸 파일명(`546s.png`·`552s.png`), 네 기의 x 좌표,
회색이 무덤이라는 코드 근거(`SimulationLoop.cs:668`), 그리고 **왜 개수를 안 쓰는지**까지.
`reads` 도 「그 옆에는」 → 「화면 오른쪽 절반에는」으로 고쳤다.

### 🔴 같은 자리에서 두 번 났다 — 다음 회차가 가져갈 것

1차 R2 는 「브리프의 *사용자 확인* 표시를 스틸 확인으로 갈음」한 것이었고,
2차 R6 은 「스틸을 봤다고 적었는데 프레임과 다르게 적은」 것이다. 형태는 다르지만 뿌리가 같다 —
**화면에서 읽어 낸 것을 대본에 옮길 때 검산을 안 했다.**

원문 인용은 `grep` 이 검산해 주지만 **화면에서 읽은 것은 검산해 줄 도구가 없다.**
그래서 규칙을 하나 만든다:

> **화면에서 읽어 세거나 방향을 말하는 문장은, 셀 수 있으면 세고 셀 수 없으면 말하지 않는다.**
> 「N개」·「왼쪽/오른쪽」·「~옆에」는 전부 이 규칙의 대상이다. 원문에서 온 문장과 달리
> 이런 문장은 **출처가 프레임**이므로, 그 프레임을 다시 열어 좌표로 확인하기 전에는
> 수와 방향을 쓰지 않는다.
