## R-1. 🔴 기계 실패가 새로 났다 — `아래 가장자리 잘림` S5 1673px (ledger)

```
🔴 아래 가장자리 잘림 없음        S5 1673px
```

1차 실행에서는 **`OK … 없음`** 이었다. 2차 개정이 만든 것이다.

원인은 산술로 확정된다 — C6 로 새로 넣은 **판독 띠**가 캔버스 밖으로 나간다
(`kinds/ledger.js:44~49`):

```
const PR = 4.6, k = (t % PR) / PR;
const by = lerp(y0 - 10, h - 22, k);
ctx.fillRect(bx - 10, by, bw + 10, rowH - 6);
```

`rowH = (h - y0 - 22)/5 = (246 - 46 - 22)/5 = 35.6`.
`k → 1` 이면 `by = h - 22 = 224`, 띠 바닥 = `224 + 35.6 - 6 = 253.6` → **캔버스 h(246)를 7.6px 넘는다.**
4.6초 주기마다 반드시 한 번 넘으므로 상시 재현이다.

- 증거 스틸: `build/stills/100.8s.png` — 마지막 칸 아래의 띠가 **바닥에서 잘려 반만 남아 있다.**
- 처방: `fillRect` 의 `by` 상한을 `h - 22 - (rowH - 6)` 로 물리거나 높이를 `Math.min(rowH - 6, h - by)` 로 클램프.
  🔑 다른 kind 의 띠도 같이 보라 — `decay`(`fillRect(X(headD)-22, py, 44, ph)`)는 x 만 움직이고
  y 가 고정이라 안전했고, **세로로 움직이는 것은 `ledger` 하나뿐**이다.

## 8. 검수가 남기는 말

3차본은 **지시받은 일곱 자리를 전부 닫았고, 그 과정에서 새 회귀를 하나도 만들지 않았다.**
특히 작성팀이 스스로 「이건 산술로만 쟀다」고 표시한 여덟 자리를 내가 실스틸로 덮어썼는데
**전부 계산대로였다** — 셸 없는 환경에서 스케일을 역산해 좌표를 미리 푼 §L 은 이 트랙에서
처음 보는 작업이고, 다음 회차가 그대로 쓸 만하다.

남은 둘은 성격이 다르다. **C14 는 검수 셋이 다 놓치고 있던 자리**다(2차 스틸과 바이트가
같으니 이번 개정 탓이 아니다) — 「글자 위에 글자」만 찾다가 **「가로선이 글자 위쪽 획을
먹는 자리」**를 못 본 것이고, 그건 라벨 baseline 과 선 y 의 차를 글자 높이와 비교하는
산수 한 줄로 훑을 수 있었다. **C13 은 반대로 작성팀 쪽 자기보고**다 — 같은 표에서 다섯 칸은

## 3. S17 정적 6.6초 — 원인 판정 (재슬라이스 불필요)

**결론: 창(window) 클램프로 인한 「얼어붙음」이 아니라 클립 원본 자체가 고요한 컷이다.**
lf01 이 허용한 전례와 같은 종류이므로 **경고를 그대로 두고 통과**를 권고한다.

**근거 ① — 창은 남았다(클램프 없음).** 엔진의 클립 시각은
`want = min(out - 1/120, in + (t - shot.t)/1000 + 1/60)`(`engine.js:356`)이다.
S17 은 `in 0 / out 7`, 실측 샷 길이 **6.712초**(자막 6.362 + SHOT_TAIL 0.35)이므로
샷 마지막 프레임의 `want` = 6.729초 < 클램프 지점 6.9917초 → **한 프레임도 클램프되지 않는다.**
(발화 기준 여유 +0.64초 · **엔진 클램프 기준 여유 +0.288초**.)

**근거 ② — 원본 클립을 직접 재 봤다.** `check.mjs` 의 클립 정적 판정식을 그대로 복제해
(160×90 축소 · 3픽셀마다 · 평균 절대 휘도차 `m < 0.0008`) 다섯 클립 원본을 같은 조건으로 쟀다:

| 클립 (구간) | 최대 m | 최장 정적 | 판정 |
|---|---:|---:|---|
| `built-…-08` (0–7) | 0.00891 | 0.2s | 활발 |
| `disaster-…-65` (0–7) | 0.00655 | 0.8s | 활발 |

원본이 고요하다는 사실은 안 바뀐다(18초본을 떠도 같은 장면이다). 마스터 §3-5 는 닫는다.

### 정정 C18 — S3 `tick` 이 **피크 천장에 걸린다** (다음 렌더에 함께)

`synth()` 를 이 회차의 실제 인자로 호출해 확인했다:

```
S3 tick {gain:0.060, dur:0.05, freq:1240}
  ⚠️ sfx tick: 피크 천장(0.46)에 걸려 목표 RMS 0.060 → 실효 0.0578 (-0.3dB).
```

나머지 10개 + 앵비언트 7개는 전부 통과(latch 0.337~0.370 · drop 0.126~0.136 ·
S23 tick 0.4452 — 천장 코앞이지만 안 걸림 · pad 0.0412).
🔑 **「tick 은 0.065 까지 안전」이라는 표는 이 인자에서 틀린다** — `dur 0.05 · freq 1240`
조합이 피크/RMS 비를 올려 **0.057 부터 걸린다**(0.056 = peak 0.4454 로 첫 안전값).

**재렌더 사유로 올리지 않는 이유(실측)**: 규칙대로 고쳐 `gain 0.056` 으로 내리면
실효는 0.0578 → **0.0560**, 즉 **지금보다 0.27dB 더 조용해진다.** 「그 소리만 조용해진다」는
이 규칙의 취지가 겨냥하는 불균형이 여기서는 0.3dB 이고, 고친 결과와 지금이 음향적으로
구분되지 않는다. → **값만 `0.056` 으로 고쳐 두고, 다른 사유로 재렌더할 때 함께 반영.**
