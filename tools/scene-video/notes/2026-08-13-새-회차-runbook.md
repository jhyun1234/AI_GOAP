# 새 회차를 3D 로 만드는 법 — ep15s-2~5

**ep15s-1 이 첫 편이고 끝났다**(`build/video.mp4` 48.4초 · 게이트 33종 통과).
이 문서는 **그다음 편을 만드는 사람**을 위한 것이다. 왜 그렇게 하는지는
[3D 네이티브 설계](./2026-08-12-3d-native-design.md)와 [진행 계획](./2026-08-12-3d-native-plan.md)에 있다.

## 0. 먼저 알아야 할 것 — 「만들기」가 아니라 「다시 만들기」다

| 편 | 지금 | 대본 |
|---|---|---|
| ep15s-1 | ✅ 3D 완성 | 3D 전제로 다시 씀 |
| **ep15s-2~5** | 2D 판 `video.mp4` 가 **이미 있다** | 🔴 **2D 도형을 전제하고 쓰여 있다** |

`ep15s-2` 의 kind 이름이 `ceiling` · `frozen` · `over` 다. 그 그림들은 이제 없다.
그래서 회차마다 **대본 재작성이 먼저**다 — ep15s-1 의 작업 7 이 한 그 일이다
(`episodes/ep15s-1/notes/3d-rewrite.md` 가 그 판단 기록이고, 표 형식을 그대로 쓰면 된다).

🔴 **사건은 안 바꾼다.** 형제편 경계와 앞 편이 이미 내보낸 예고가 사건에 걸려 있다.
바꾸는 것은 **도형을 전제한 낱말**뿐이다(「칸」·「줄」·「말풍선」 → 장면에 있는 것).

## 1. 손대지 않아도 되는 것 — 일곱 파일이 회차 무관이다

```
blender3d/  stage.py  village.py  unison.py  instrument.py  motions.py  probe.py  palette.py
```

마을·주민·소품·동작 아홉·계기층·측정·색표. **좌표만 주면 어디서나 다시 선다.**
🔴 소품을 다시 만들지 마라 — [`PROPS.md`](../blender3d/PROPS.md) 가 어휘집이고,
「무엇이 그것처럼 보이게 하는가」를 판정 네 판으로 뽑아 규칙 여섯으로 적어 뒀다.

엔진 쪽도 그대로다: `engine.js` 의 대기 채널(`drawWaits`) · `serve.js` 의 `/3d` 라우트 ·
`check.mjs` 의 팔레트 3층 게이트 · `render.mjs` · `tts.mjs`.

**새로 쓰는 것은 둘뿐이다: 대본과 샷 렌더 스크립트.**
🔑 샷 스크립트가 회차마다 새로 필요한 것은 결함이 아니라 설계다 — 엔진 규약이
「그림은 회차가 소유한다」이고, 그걸 어겼을 때 **회차마다 같은 그림이 돌아왔다.**

## 2. 🔴 작업 0 — 먼저 막아야 할 구멍 둘

ep15s-1 은 첫 편이라 이 둘이 안 드러났다. 두 번째 편에서 바로 터진다.

### 0-A. 인트로가 사실은 공유가 안 된다

`render_intro.py` 에 `DUR = 5.143` 이 박혀 있는데 그건 **ep15s-1 의 S0 길이**다.

| 편 | S0 대사 | pauseAfter |
|---|---|---|
| ep15s-1 | 클로드 코드로만 만든 에이아이 마을이에요. | **1800** |
| ep15s-2 | (같은 대사) | 200 |
| ep15s-3~5 | 클로드 코드로만 **만드는, 에이아이 마을 개발일지입니다.** | 200 |

그대로 쓰면 그림 5.14초에 소리 3.5초라 어긋나고, 컷 없이 이어지던 인트로→훅 이음새가 깨진다.

**할 일**
1. `DUR = stage.shot_seconds(EP, 'S0')` 로 바꾸고 `EP` 를 환경변수로 받는다
2. 🔴 **비트 시각도 같이 줄인다.** 집 0.75 · 나무 2.20 · 주민 3.20 · 고개 4.25 · 착지 4.70 은
   5.143 초에 맞춰 놓은 값이다. `DUR/5.143` 을 곱하되 **착지가 끝에 붙는지 확인**해라 —
   착지가 일찍 끝나면 훅 시작 카메라와 어긋난다
3. 출력을 `_intro/frames` 대신 **길이별**로 가른다(예: `_intro/<밀리초>/frames`).
   길이가 같은 편끼리는 그대로 재사용된다 — 45편이 공유한다는 말이 그때 사실이 된다

### 0-B. `scene3d.js` 가 회차 폴더에 있다

엔진이 kind 를 `episodes/<ep>/kinds/` 에서만 읽으므로 회차마다 복사해야 한다.
**합성기는 그림이 아니라 붓이다**(`lib.js` 와 같은 층). 지금 구조면 버그 하나에 45벌을 고친다.

**할 일** — `engine/scene3d.js` 로 옮기고, 회차 kind 다섯은 한 줄로 재수출한다.
```js
export { default } from '../../../engine/scene3d.js';
```
🔴 `kind` **이름은 바꾸지 마라.** `check.mjs` 가 `kind === 'intro'` 로 인트로 유무·
제목 이행 시작점·4단 구조를 센다. 이름은 **역할**이고 파일 내용이 **그림**이다.

## 3. 회차 하나 만드는 순서

### ① 대본을 3D 전제로 다시 쓴다
`episodes/<ep>/notes/3d-rewrite.md` 에 세 열 표(`지금 문장` · `도형을 전제하는가` · `새 문장`).
🔴 「도형을 전제하는가」가 **아니오면 새 문장 칸을 비운다** — 안 건드리는 것이 기본값이다.
각 샷의 `reads` 도 같이 고친다. 그림이 통째로 바뀌었으므로 지금 값은 전부 거짓이다.

### ② TTS → 길이가 나온다
```bash
node tools/scene-video/tts.mjs ep15s-2
```
🔑 **길이는 대본이 정한다.** 렌더 스크립트에 초를 손으로 적지 마라 —
`stage.shot_seconds(EP, 샷id)` 가 `timed.json` 에서 읽는다.

### ③ 비트 시트를 쓴다 — 여기가 진짜 작업이다
샷마다 사건 **셋 이상**, 비트당 **1.5초 이하**. 길이 ÷ 비트 수가 그 값을 넘으면 비트를 늘린다.
🔴 **길이를 늘려 홀드를 채우지 마라.** 상한이 1분대로 열린 것이지 길게 만들라는 것이 아니다.

### ④ 샷 렌더 스크립트를 쓴다
`render_hook.py` 를 본으로 삼아라 — 길이 읽기·비트 단언·궤적 검사·카메라·불이 다 들어 있다.

🔴 **매번 밟은 함정들** (전부 겪고 적은 것이다)
- 걷게 하려면 `arm.location` 을 밀어라. 다리만 저으면 제자리걸음이다(`unison.march`)
- 나아가는 거리는 `motions.WALK_SPEED` — 눈대중으로 올리면 발이 미끄러진다
- 동작을 갈아탈 땐 `motions.sequence`/`blend`. 그냥 바꾸면 관절이 순간이동한다
- 카메라를 옮기면 `stage.key_from_view` 를 같이 불러라. 안 부르면 인물이 역광이 된다
- 궤적이 소품을 뚫는지 `village.obstacles` 로 재라. **가로 대열은 이 마을에 못 들어간다**
- 정지 비트를 나란히 두지 마라 — 둘 다 그림이 안 변해서 홀드가 된다

### ⑤ 3D 배선 — `scene.json` 에 세 가지
```json
"kind": "(이름 그대로)", "enter": "cut",
"spec":   { "frames": "/3d/<ep>/<shot>/frames", ... },
"checks": { "edge": "3D 전면 그림 — 상자를 끝까지 채우는 것이 설계다" }
```
🔴 `enter: "cut"` 을 빠뜨리지 마라. 기본값 `up` 은 2D 판의 것이고, 3D 는 카메라가 이음새를
진다 — 엔진이 또 밀어 넣으면 이어 놓은 카메라가 샷 경계마다 튄다.

### ⑥ 재고 → 판정 → 굽는다
```bash
cd tools/scene-video/blender3d && for t in probe palette stage village motions unison instrument intro; do python test_$t.py; done
node tools/scene-video/check.mjs ep15s-2      # 게이트 33종
node tools/scene-video/render.mjs ep15s-2     # build/video.mp4
```
샷을 렌더한 뒤 **사람에게 보이기 전에** 프레임 그리드와 수치를 먼저 뽑아라:
프레임당 뜻층 ≤2 · 최장 정적 ≤3.0초 · 클리핑 0(peak <250) · 궤적 여유 >0.

## 4. 🔴 판정을 받는 자리

이 프로젝트는 **연출을 고치기 전에 피사체를 의심하는** 것이 규칙이다(여덟 판을 돌린 전례).
그래서 다음 자리에서 멈추고 보여 준다.

1. **대본 재작성 뒤** — 사건 셋이 그대로인가
2. **훅 렌더 뒤** — 자막 없이 처음 0.3초에 그 편의 사건이 읽히는가
3. **여섯 샷 통짜 그림 뒤** — 소리·자막 붙이기 전에
4. **완성본**

「밋밋하다」를 들으면 **자막을 가린 프레임 그리드부터 뽑아라.** 안 읽히면 카메라를 만지지 마라.
