## 2. 왜 흩어지나 — 오일러가 범인이다

새 리그는 **T 포즈**라 팔뼈가 **±Y** 를 향한다. 그 축에서 `Quaternion.to_euler('XYZ')` 는
**짐벌 특이점 근처**다 — 프레임마다 분해가 튀고, 그 값을 선형 보간하면 폭발한다.

근거 셋:
- 레스트(포즈 0)는 **정상**이다 → 메시·결합·뼈 배치는 맞다
- `@root` 는 최대 0.076 m 다 → 이동으로는 그만큼 못 흩어진다. **회전이다**
- 옛 모델(팔이 아래를 향함)에서는 같은 코드가 멀쩡했다 → 축이 바뀐 것이 방아쇠다

옛 `rig.py` 가 roll 을 `GLOBAL_POS_X` 로 **고정**해 둔 것도 같은 문제를 오일러로 피해 간
장치였다(주석: *"X = 앞뒤 · Z = 좌우 · Y = 비틀림"*). 새 리그는 `roll = 0` 이다.

🔴 **roll 을 맞추는 것은 임시 처방이다.** 근본은 오일러를 안 쓰는 것 — T 포즈 리그를 쓰는 한
이 문제는 다른 동작에서 또 나온다.

## 3. 다음 수 — 쿼터니언 전환 (파일 셋)

### ① `mocap2pose.py` — 표를 쿼터니언으로 굽는다

```python
# 지금
e = basis.to_euler('XYZ')
for i in range(3): raw[n][i].append(e[i])
...
raw[n] = [unwrap(ch) for ch in raw[n]]     # ← 폐기

# 바꿀 것
q = basis.normalized()
if prev[n] and q.dot(prev[n]) < 0.0:       # 🔴 반구 정렬 — unwrap 의 쿼터니언 판
    q = -q                                  #    안 하면 보간이 먼 길로 돈다(360°)
prev[n] = q
raw[n].append((q.w, q.x, q.y, q.z))
```

- JSON 에 **`"mode": "quat"`** 을 넣는다. 옛 표(3성분)와 섞이면 조용히 틀린다.
- `unwrap()` 은 지운다 (`ADR-M0-4` 정신 — 폐기 = 삭제). 특이점이 없으니 필요가 없다.
- `ARM_CHAIN` / `BASE_MODE` 도 **지울 수 있는지 확인**하라 — T 포즈 리그면 기준면 A 가
  그대로 맞아야 한다. 그게 새 모델을 만든 값이다. 안 맞으면 그건 다른 버그다.

### ② `mocap.py` — nlerp 로 보간하고 4성분을 그대로 넘긴다

```python
qa, qb = a[nm], b[nm]
if qa[0]*qb[0] + qa[1]*qb[1] + qa[2]*qb[2] + qa[3]*qb[3] < 0:
    qb = tuple(-v for v in qb)             # 프레임 쌍마다 다시 확인(표가 정렬돼 있어도 싸다)
q = tuple(qa[c] + (qb[c] - qa[c]) * k for c in range(4))
n = math.sqrt(sum(v*v for v in q)) or 1.0
out[nm] = tuple(v / n for v in q)          # nlerp — 30fps 라 slerp 와 눈으로 구분 안 된다
```

- `gain`(과장 손잡이)은 **항등에서의 slerp** 로 바꾼다: `slerp(identity, q, gain)`.
  성분에 곱하면 회전이 아니라 쓰레기가 된다.
- `demo()` 자체 점검을 갱신: 노름이 1 인지(±1e-6), 4성분인지, 연속 프레임 dot 이 양수인지.

### ③ `stage.py` — `pose()` 가 두 형식을 다 받게 (성분 수로 가른다)

```python
for pb in arm.pose.bones:                  # 리셋도 두 모드 다
    pb.rotation_euler = (0, 0, 0)
    pb.rotation_quaternion = (1, 0, 0, 0)
    pb.location = (0, 0, 0)
...
for name, rot in spec.items():
    if name in (ROOT, SQUASH): continue
    pb = arm.pose.bones[name]
    if len(rot) == 4:                      # 모캡
        pb.rotation_mode = 'QUATERNION'
        pb.rotation_quaternion = rot
    else:                                  # 손으로 짠 22종 — 무변경
        pb.rotation_mode = 'XYZ'
        pb.rotation_euler = rot
```

🔑 성분 수로 가르면 **기존 22종은 한 글자도 안 바뀐다.** 새 형식을 위해 옛 것을 고치지 않는다.

## 4. 먼저 정할 것 하나 (코드보다 앞)

**손으로 짠 22종을 새 모델에서 쓸 것인가?**

- 쓰려면 → 새 리그의 roll 을 `GLOBAL_POS_X` 로 맞추고, **팔 각도 상수를 전부 다시 잡아야
  한다**(레스트가 팔 내림 → T 포즈로 바뀌어 팔 관련 값이 ~80° 어긋난다). 다리·척추는 무사하다.
- 안 쓰려면 → 사용자 방침이 *"모션도 Mixamo 에서 가져오면 될 것 같다"* 이므로 **그게 기본**이다.
  그 경우 22종은 **옛 모델 전용**으로 남기고(ep15s·ep16s 재현용) 새 모델은 모캡만 쓴다.

🔴 이 판단을 먼저 하라. 코드부터 손대면 안 쓸 22종을 재조정하는 데 시간을 버린다.

## 7. 밟은 지뢰 여덟 — 다시 밟지 말 것

| # | 증상 | 원인 |
|---|---|---|
| 1 | 사람이 90° 누움 | Mixamo FBX 는 아마추어에 −90° X 를 달고 온다. 델타를 **월드 축으로 켤레** 취해야 한다 |
| 2 | 「쏜다」가 안 읽힘 | 궁수는 표적에 **옆으로 선다** — 클립의 상수 요각이 `hips` 를 174° 흔들었다. 첫 프레임 골반 델타를 전 뼈에서 뺀다 |
| 3 | 몸이 앞으로 고꾸라짐 | `@root` 를 안 옮겼다. 모캡 다리 회전은 **골반이 같이 이동하는 것을 전제**한다 |
| 4 | 걷기가 무대와 싸움 | 걷는 클립은 수평 드리프트를 뺀다(`INPLACE`). 단 `flinch` 의 밀림은 **사건이라 빼면 안 된다** |
| 5 | 화살 뽑는 구간이 섞임 | 모캡은 한 동작이 아니라 **한 연기**다. `TRIM` 으로 자른다 |
| 6 | 팔이 43° 모자람 | 레스트 차이(T 포즈 vs 팔 내림). 방향 벡터로 흉내 내면(`rotation_difference`) **roll 이 임의로 남아 걷기가 망가진다** |
| 7 | 활이 안 섬 | `stage.hold` 은 `rot_x` 만 받는다. 활채를 Z 에 두면 팔 평면에서만 돈다 — **로컬 X** 에 실어야 선다 |
| 8 | 조각이 흩어짐 | **오일러 짐벌**(§2). 그리고 그 전에 자동 웨이트가 터졌다 — 저폴리는 **마디마다 뼈 하나 100%** |
