# AI_GOAP 영상 대본 파이프라인 (루틴 프롬프트)

블로그 파이프라인(`tools/blog-automation/routine-prompt.md`)과 같은 모양이다. 다른 점은
**산출물이 글이 아니라 씬 JSON 이고, 마지막에 사람이 유튜브에 올린다**는 것이다.

## 이 파이프라인이 하는 일과 안 하는 일

- **한다**: 다음 회차 선정 → 대본(씬 JSON) 작성 → 검수 → 승인 → 음성·렌더·점검 →
  붙여넣을 메타데이터 생성. 🔴 **2026-08-06부터 사람이 세션을 열 때만 돈다** — 크론은
  폐기됐다(「주기」 절). 한 번에 그 글의 사건 수만큼 만든다.
- **재료가 없으면 안 한다.** 순서표를 다 만들었고 아직 영상이 안 된 발행 글도 없으면
  아무것도 만들지 않고 조용히 끝낸다. 블로그가 새 글을 내면 저절로 재개된다 — 「주기」 절.
- **안 한다**: 유튜브 업로드. 감사를 통과하지 않은 API 프로젝트로 올린 영상은 YouTube 가
  비공개로 **잠그고** 스튜디오에서도 못 푼다. 사람이 스튜디오에 끌어다 놓는다.

## 🔊 효과음도 회차가 소유한다

사용자 확정(2026-07-30). 소리는 **받아 쓰지 않고 합성**한다(`sfx.mjs`, 6종, 결정적·의존성 0).
작성팀이 씬의 `shot.sfx` 에 달고, 검수팀이 배치와 절제와 **돌려막기**를 본다.
🔑 **그림과 같은 규칙이다** — 회차마다 같은 자리에 같은 소리를 쓰면 안 된다.
🔑 **나레이션이 부르는 사건에만. 23초에 1~2개.** 정적을 메우려고 깔지 않는다.
🟡 **2026-08-06 두 번째 개정** — 「90초에 5~8개」 → 「40초에 2~4개」 → 지금 값이다.
편당 길이가 **20~25초**로 바뀌었다(`Docs/영상_25초_전환_실행명세서.md` W1).
같은 밀도(초당 0.06~0.09개)를 지금 길이로 환산했다.

## 🔴 마지막은 다음 편 예고로 끝난다

사용자 요청(2026-07-30) — **다음 편에 무슨 이야기가 오는지 구체적으로 알려주고 끝낸다.**
기획팀이 브리프 끝에 **「다음 편 예고 재료」**(막 · 원본 회차 · 주제)를 넣고, 작성팀이 그걸로
마지막 샷을 만들고, 검수팀이 **사실인지 대조**한다.

🔴 **2026-08-06 전환 — 형태가 둘이고 둘 다 허용된다**(`Docs/영상_25초_전환_실행명세서.md`
ADR-V25-2). 편이 25초가 되면 3초 예고는 12% 라 그대로 둘 수 없다.
**예고를 없애는 것이 아니라 형태를 바꾸는 것이다** — 2026-07-30 사용자 요청은 유효하다.

- **①쇼트 훅 (1초 이하 음성).** 찰나에 다음 편의 가장 자극적인 것 하나만 던진다.
  설명이 아니라 미끼다. 1초는 말로 **6~7자**다.
- **②음성 0 + 아웃트로 글자.** `scene.json` 의 **`outro.next`** 에 다음 편 이름을 적으면
  마지막 2.6초 아웃트로 카드가 그것을 글자로 진다.

`check.mjs` 가 「다음 편 예고 있음」(fail — 둘 다 비면 red)과 「예고 1.0초 이하」(warn)로 잰다.
🔑 옛 값(3초)의 유래: 1차본 예고가 10~14초여서 페이오프 뒤가 늘어졌다
(ep04s S12 14.0초 · ep05s S11 12.7초).

🔑 **편을 나눈 회차는 예고가 오히려 안전하다.** 2편이 이미 리포에 있으므로 아직 안 쓴 글을
넘겨짚을 일이 없다 — 아래 ep02s·ep04s 사고가 구조적으로 불가능해진다.

⚠️ **정본은 `Docs/영상_시리즈_구성안.md` 표와 `state/schedule.json` 의 `order` 뿐이다.**
**원문의 "다음 글에서는…" 문장을 옮기면 틀린다** — 구성안이 순서를 바꿔 놓은 자리가 있다.
실제로 ep02s 가 그렇게 *"다음 편은 성격이 자리 잡는 이야기"* 라고 했는데 ep03s 는
**M0 재설계 회고(2막 · 리셋)** 였다.

## 🔴 나누는 단위는 **사건**이고, 편당 20~25초다

🔑 정본은 `Docs/영상_이탈률_개선_실행명세서.md` 다. 아래는 요약이니 갈리면 명세서를 따른다.

- **편당 목표 20~25초 · 상한 25초**(2026-08-06 전환, 옛 값 30~45/50초). `check.mjs` 의
  「총 길이 25초 이하」가 red 를 내고 「본문 21초 이상」이 예고·아웃트로를 뺀 알맹이를 잰다.
- **나누는 단위는 "사건"이지 챕터가 아니다**(ADR-V-1). 한 편 = ①어긋난 상태나 결정이 하나 있고
  ②그게 뒤집히거나 해결되고 ③남는 한 줄이 있는 것. 챕터(사건/추적/해결/증명/결과) 경계로
  자르면 뒷편에 훅이 없어져 **고치려는 병이 악화된다.**
- **글당 최대 3편, 하한 없음**(ADR-V-2). 사건이 하나면 안 쪼갠다.
- id 는 `order` 만 편 단위로 치환한다 — `ep05s-1`·`ep05s-2`. `sources` 는 글 단위(`ep05s`)로
  남긴다(§1). 그래야 `nextId()` 가 번호를 정확히 내고 기존 로직 수정이 거의 없다.

## 🔴 이 채널 최대의 이탈 원인은 **제목 이행 시각**이다

실측(§관측①②): 절대 시청 시간이 길이와 무관하게 **16~27초에 갇혀 있다.** 79.9초짜리와
122.5초짜리의 시청 시간이 같다. **길이는 원인이 아니었다.**

순위를 가른 것은 `youtube.title` 이 약속한 것이 화면·내레이션에 처음 나오는 시각이다 —
이행이 30초를 넘는 두 편(ep02s 34.3초 · ep03s 50초+)이 4·5위다. 시청자 대다수가 제목이
약속한 장면을 **한 번도 못 보고 나간다.**

→ `check.mjs` 의 「제목 이행 (첫 두 줄)」이 **red** 다(ADR-V-4). 과거 5편 중 3편을 잡을 만큼
세고, 그게 의도다. 오탐이 나면 게이트를 무르게 하지 말고 **제목이나 첫 줄을 고쳐라.**

⚠️ **길이를 이유로 자막을 지우지 마라.** ep02s 1차본(83.6초)이 리포 밖 상식("쇼츠 60초 상한")
으로 반려돼 36초가 잘렸다. 상한을 넘으면 할 일은 **편을 나누는 것**이다.
🔑 그리고 짧게만 만드는 것도 답이 아니다 — 명세서 S2 가 "평균 절대 시청 15초 아래로
내려가지 않을 것"을 안전장치로 둔다. 조회율만 오르고 실제로 덜 본 것은 개선이 아니다.

🔑 **판정 근거는 리포 안의 문서에서만 가져온다.** 바깥 지식으로 반려하려거든 출처를 리포에서
먼저 찾고, 못 찾으면 반려하지 않는다. (2026-08-03~04 에 이 규칙이 두 번 값을 했다 —
근거 없이 들어온 "꼬리 예고 금지"와 "편당 75/90초"를 각각 검수팀과 이 명세서가 잡아냈다.)

## 🔴 그림은 회차가 소유한다

`episodes/<ep>/kinds/` 는 그 회차의 소유물이고, 작성팀이 **그 글만을 위해 새로 설계**한다.
공용 그림 라이브러리(`engine/kinds/`)는 **일부러 없앴다** — 있을 때 두 회차가 같은
그림으로 채워졌고, 사용자 판정이 "돌려막기는 내가 원하는 방향이 아니다" 였다.
공유하는 것은 `engine/lib.js`(팔레트·이징·캔버스 헬퍼)뿐 — 그림이 아니라 붓이다.

## 🌍 영어 자막은 한국어 대본 **안에** 산다 (ep06s부터)

정본 = `Docs/영상_영어권_확장_실행명세서.md`.

**영상은 하나다.** 더빙도 번인 자막도 한국어로 나가고, 영어권 시청자는 **CC 를 켜서** 본다.
그래서 영어 대본 파일(`scene.en.json`)을 **만들지 않는다**(ADR-V-9 폐기).
영어는 `scene.json` 안의 두 자리에 산다 — 줄마다 `lines[].en`, 그리고 `youtube.en`.

**왜 파일을 안 나누나** — ①검수팀이 원문 옆에서 한 줄씩 대조해야 지어낸 내용을 잡는다
②파일 개수가 안 늘어 `backlog.mjs` 와 클라우드 루틴이 **아무 영향을 안 받는다**
③줄이 늘거나 합쳐질 때 번역이 자동으로 따라 움직인다(인덱스로 짝을 맞추면 어긋난다).

작성팀이 한국어와 **함께** 쓰고, 검수팀이 한 줄씩 대조한다. 게이트 2종(`영어 자막 전 줄 존재`·
`영어 자막 2줄 상한`)이 `check.mjs` 에 있고 파일만 보므로 크로미움 없이도 돈다.
⚠️ **`en` 이 0줄이면 게이트가 통째로 건너뛴다**(옛 회차용) — 그러니 **번역 누락은 사람과
검수팀이 잡아야 한다.** `srt.mjs` 는 렌더가 되는 로컬에서만 돌고 산출물은 `build/` 다.

🔤 함께: **그림 안의 짧은 라벨은 언어 중립(영어)** 이다(ADR-V-10). 잣대 한 줄 —
*"이게 코드나 인스펙터에 그대로 있을 법한 말인가?"* → 그렇다면 영어, 서술이면 한국어.
🔴 **고유명사(`순둥이`·`농부`)는 한국어다** — C# 소스에 한국어 리터럴로 실재한다.
자막에서는 반대로 **뜻으로 옮긴다**(`the easygoing one`, ADR-V-19). 갈리는 것이 의도다.

## 스테이징 파일 규칙

각 서브에이전트는 **별도 무상태 세션**이다. 앞 단계의 결과를 대화로 물려받을 수 없으므로
반드시 `tools/scene-video/episodes/<ep>/notes/` 에 파일로 남기고 다음 단계에 경로를 알려준다.
(블로그 파이프라인이 이 규칙을 어겨 사고가 났던 자리와 같다.)

## 승인 이후 — 기계가 하는 부분

```
node tools/scene-video/publish.mjs <ep> --prepare
```
음성(캐시 재사용) → mp4 렌더 → `check.mjs` 점검 13종 → `episodes/<ep>/build/upload.txt` 생성.
**점검이 실패하면 여기서 멈춘다.** 그 경우 검수팀 단계로 되돌아간다.

🔴 **루틴에서는 이 문서를 사람이 읽지 않는다.** `publish.mjs --routine` 이 대본이 없으면
`claude -p` 로 이 절차를 그대로 물려 4개 부서를 돌리고, 이어서 음성·렌더·점검까지 한다.
즉 이 문서는 **사람용 안내이자 무인 실행의 지시서**다 — 고칠 때 둘 다 바뀐다고 생각하고 고쳐라.
무인 실행에는 **CLI 로그인이 유효해야 한다**(OAuth 토큰은 만료된다). 만료되면 대본 단계가
매번 죽고 `state/routine.log` 에 401 이 남는다.

## 멈춰야 하는 조건

- `backlog.mjs` 가 `IDLE` 을 냈다 (재료 없음 — 가장 흔한 정상 종료)
- 기획팀이 `SKIP` 을 냈다 (원본 글 미발행)
- 검수 반려 3회
- 마스터 반려 3회
- `check.mjs` 실패가 두 번 연속 같은 항목

멈출 때는 `episodes/<ep>/notes/` 에 사유를 남긴다. **애매하면 통과시키지 말고 멈춘다** —
영상은 글과 달리 되돌리는 비용이 크다.

## 사람이 이어받는 지점

1. `episodes/<ep>/build/video.mp4` 를 스튜디오(<https://studio.youtube.com>)에 끌어다 놓는다
2. `episodes/<ep>/build/upload.txt` 의 제목·설명·태그를 붙여넣는다
3. 공개로 전환한다

  **0.5일**이 지났는지를 **git 이력**으로 재고(파일 mtime 은 새 clone 에서 전부 체크아웃 시각이라 못 쓴다),
  `order` 안의 회차만 센다 — 손으로 만든 특별편이 본편 박자를 먹으면 안 된다.
  0.5일인 이유: 크론이 하루 한 번이므로 막을 것은 "이틀째"가 아니라 **같은 날 두 번 도는 것**뿐이다.
  1일로 잡으면 크론이 몇 분만 늦어도 그날을 통째로 건너뛴다.
  로컬은 간격 게이트를 **아예 보지 않는다**. 규칙이 하나뿐이다 — *아직 아무도 렌더 안 한 대본이 있으면 렌더한다.*
- `scriptBy: "local"` — 이 PC 가 대본까지 만들고, 간격 게이트(`everyDays`)도 여기서 본다.

### 재료가 떨어지면 — 멈추는 게 정상이다

`order` 는 손으로 적어 둔 목록이었다. 격일일 때는 한 달치라 안 보였는데 **하루 한 편이면
열흘 남짓 뒤에 바닥난다.** 그래서 `backlog.mjs` 가 그 자리를 맡는다.

```
node tools/scene-video/backlog.mjs            # 판정만
node tools/scene-video/backlog.mjs --extend   # 재료가 있으면 순서표에 한 칸 편입
```

| 상태 | 뜻 |
|---|---|
| `PENDING` | 순서표에 아직 대본 없는 회차가 있다 → 그걸 만든다 |
| `EXTENDED` | 순서표를 다 만들어서 **아직 영상이 안 된 발행 글 한 편**을 회차로 편입했다 |
| `IDLE` | 재료 없음 → **아무것도 안 한다** |

🔴 **`IDLE` 은 사고가 아니다.** 블로그가 다음 글을 발행하면 그다음 실행이 `EXTENDED` 로
저절로 재개된다. 억지로 소재를 찾지 않는다 — 미발행 밀스톤을 앞질러 만들거나 이미 만든
회차를 다시 쓰는 것이 여기서 나올 수 있는 최악이다.

- **한 번에 한 칸만** 늘린다. 밀린 글이 셋이어도 사흘에 나눠 간다("하루 한 편"이 규칙).
- 정본은 `tools/blog-automation/published/` 디렉터리다. `BLOG_COVERAGE.md` 표가 아니다 —
  그 표는 사람이 사후에 갱신해서 **실제로 늦는다**(M11·M12 발행분이 표에 늦게 들어간 전례).
- **번외(방법론 편)는 자동으로 편입하지 않는다.** 구성안이 "시즌 마지막이나 중간 쉬어가는
  자리"라고 자리를 지정해 둔 편이라, 발행일 순서로 끼우면 그 결정을 덮는다. 넣을 때가 되면
  사람이 `order` 에 한 줄 적는다.
- 편입은 **대본을 만드는 쪽**이 한다. 클라우드 모드에서 로컬이 늘리면 커밋 안 된
  `schedule.json` 변경이 남아 다음 `git pull --ff-only` 를 막는다.

🔑 **매일이라고 매일 나오는 건 아니다.** 순서표를 소진한 뒤로는 산출이 **블로그 발행 속도**를
따라간다(지금 격일). 그건 이 설계의 결론이지 고장이 아니다.

로컬 작업 스케줄러 `AI_GOAP scene-video` 는 **매일 15:00 + 로그온**에 돈다.
등록·재등록은 **`tools/scene-video/register-task.cmd` 를 실행**하면 된다 — `%~dp0` 로 제 경로를
스스로 채우므로 손으로 고칠 것이 없다(경로를 손으로 박아 넣는 자리가 가장 자주 틀렸다).

🔴 **왜 로컬에서 주기를 또 잠그지 않는가.** 박자는 이미 클라우드가 쥐고 있으므로 여기서 또 잠그면
박자가 두 군데가 된다. 실제로 그래서 사고가 났다 — 옛 등록이 `DAILY /mo 2 /st 09:00` 이었는데
클라우드 루틴이 **09:09 에 시작해 11:04 에 push** 했다. 로컬이 **9분 먼저** 돌고 가서
"대본 대기"로 끝났고, 그날 만든 대본은 이틀 뒤에나 렌더됐다. 매 회차가 하루씩 밀린 것이다.
15:00 은 클라우드가 끝난 뒤이고 블로그(짝수일 13:03)와도 안 겹친다. PC 가 그 시각에 꺼져 있으면
로그온 트리거가 받는다.

할 일이 없는 날 도는 비용은 `git pull` 한 번이다 — 대본이 없으면 `publish.mjs` 가
"대본 대기"만 찍고 exit 0 으로 끝난다(TTS·크로미움을 건드리지 않는다).
트리거가 둘이 됐으므로 `routine.cmd` 가 락으로 겹침을 막는다(6시간 지난 락은 죽은 것으로 보고 지운다).

```
routine.cmd (매일 15:00 + 로그온, 락으로 겹침 방지)
  └ publish.mjs --routine
      ├ git pull            ← 클라우드가 push 한 대본을 먼저 받는다
      ├ scriptBy=cloud 면 간격 게이트를 보지 않는다 (박자는 클라우드가 쥔다)
      │   scriptBy=local 이면 여기서 backlog.mjs --extend 로 순서표를 늘린다
      ├ schedule.json 의 order 에서 아직 안 만든 첫 회차 선택
      │   없으면 → "만들 회차가 없다" · exit 0        ← 재료 고갈, 사고가 아니다
      ├ scene.json 이 없으면 → "대본 대기" · exit 0   ← 사고가 아니다
      │   (scriptBy=local 이면 여기서 claude -p 로 4개 부서를 돌린다)
      ├ 음성(Supertonic) → mp4(크로미움 CDP) → check.mjs 13종
      └ build/upload.txt  ← 사람은 여기서 이어받는다
```
🔑 **로컬이어야 한다** — TTS 모델 645MB · 크롬 · ffmpeg · 폰트가 전부 이 PC 에 있다.
블로그처럼 원격 routine 으로는 못 돌린다.
🔑 기획팀 SKIP 이나 반려 한도 초과로 대본이 안 나오면 `scene.json` 이 없으므로 렌더가
**exit 0 으로 조용히 건너뛴다**. 사고가 아니라 설계된 결말이고 사유는 `notes/` 에 있다.
